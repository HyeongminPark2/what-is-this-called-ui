간격 체계

Spacing scale · spacing system

간격 체계는 여백 값을 정해 둔 배수 가운데서만 고르도록 한 규칙입니다. 보통 4px이나 8px의 배수를 씁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

8px 격자 보기를 켜면 8px마다 가로줄이 그어집니다. 여백이 모두 8의 배수라서 테두리와 글줄이 격자선에 딱 맞습니다.
눈대중 값으로를 켜면 7, 13, 19 같은 값이 섞이는데, 어디가 틀렸는지 한눈에 짚기는 어렵지만 화면 전체가 어수선해 보입니다. 간격 체계는 이렇게 값이 조금씩 어긋나서 생기는 어수선함을 막으려고 씁니다.

2 이름같은 것을 부르는 여러 이름

한국어간격 체계, 여백 체계, 스페이싱 스케일, 8포인트 그리드
영어spacing scale, spacing system, 8-point grid
같이 쓰는 말안쪽 여백은 패딩, 바깥 여백은 마진, 플렉스나 그리드에서 항목 사이를 띄우는 간격은 갭입니다. 열과 열 사이의 간격은 거터(gutter)라고 하고, 화면 양옆의 여백은 팀에 따라 마진이라고도 하고 거터라고도 부릅니다. 4px 단위로 잡는 방식은 4포인트 그리드라고 합니다.
자주 잘못 부르는 이름그리드 — 화면을 열로 나누는 레이아웃 그리드와 여백 단위를 정하는 간격 그리드는 서로 다른 것입니다.
여백 — 디자인에서 말하는 여백(white space)은 '비워 둔 공간' 전체를 가리키는 더 넓은 뜻입니다.
패딩 — 패딩은 여백이 들어가는 자리를 가리키고, 간격 체계는 그 자리에 넣을 값을 정한 것입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지 × 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

간격 체계를 한 줄로 정리하면 — 간격 체계는 쓸 수 있는 여백 값의 개수를 줄이는 일입니다. 고를 수 있는 여백이 여섯 개뿐이면 값을 고르는 고민이 줄고, 화면마다 여백이 조금씩 어긋나는 일도 없어집니다.

묶음 사이보다 넓으면 묶음이 안 보입니다.
  1. 바깥 여백 padding · 안쪽 여백카드 테두리와 내용 사이의 여백입니다. 네 방향이 같아야 안정돼 보입니다
  2. 묶음 안 간격 gap · 8px제목과 부제처럼 한 덩어리인 요소 사이의 간격이라 좁게 둡니다
  3. 묶음 사이 gap · 16~24px덩어리와 덩어리 사이의 간격입니다. 묶음 안 간격보다 반드시 넓게 두어야 어디까지가 한 묶음인지 보입니다
  4. 버튼 사이 gap · 8px나란히 놓인 버튼은 가깝게 둡니다. 사이가 멀어지면 서로 관계없는 버튼처럼 보입니다
  5. 글줄 사이 line-height행간도 간격의 하나입니다. 행간이 묶음 사이 간격보다 넓으면 어디까지가 한 묶음인지 알아보기 어렵습니다

간격이 하는 일은 화면을 보기 좋게 꾸미는 것보다 무엇이 한 묶음인지 보여 주는 것입니다(근접성). 사람은 가까이 있는 것끼리 한 덩어리로 보기 때문에, 라벨을 윗 칸보다 자기 입력창에 더 가깝게 두면 따로 설명하지 않아도 어느 입력창의 라벨인지 알 수 있습니다. 반대로 묶음 안 간격이 묶음 사이 간격보다 넓으면 줄을 잘 맞춰 두어도 읽는 사람은 어디까지가 한 묶음인지 찾지 못합니다.

6 쓸 때 / 안 쓸 때

간격 체계를 쓰는 경우

  • 여러 사람이 화면을 만들 때. 같은 카드를 누가 만들어도 여백이 같아집니다
  • 목록이나 표처럼 같은 모양이 반복되는 화면일 때
  • 폰과 PC 화면을 함께 만들 때. 새 값을 만들 필요 없이 쓰는 단만 바꾸면 됩니다

간격 체계를 쓰지 않는 경우

  • 글자 사이처럼 타이포그래피 안쪽을 미세하게 조정할 때. 눈으로 보고 맞추는 시각 보정이 필요해서 배수에 맞지 않을 수 있습니다
  • 사진이나 아이콘의 시각 중심을 맞출 때. 이때는 숫자로 잰 가운데보다 눈으로 본 가운데가 더 정확합니다
  • 단을 2·4·6·8·10·12…처럼 너무 촘촘히 둘 때. 고를 수 있는 값이 너무 많아져서 아무 값이나 쓰는 것과 다르지 않게 됩니다

간격 체계 대신 다른 것을 써야 하는 경우 — 글줄 사이 간격은 타입 스케일에서 글자 크기와 함께 정하고, 화면을 열로 나누는 일은 레이아웃 그리드(1부)에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙간격을 코드로 옮기는 법

코드에서는 단을 숫자 대신 이름으로 부릅니다. 16px 대신 --space-4를 써 두면 나중에 여백 전체를 한 번에 좁히거나 넓힐 수 있습니다.

:root {
  --space-1: 4px;    --space-2: 8px;
  --space-3: 12px;   --space-4: 16px;
  --space-6: 24px;   --space-10: 40px;
}

.card {
  padding: var(--space-4);
  display: grid;
  gap: var(--space-2);   /* 묶음 안 */
}
.card + .card { margin-top: var(--space-4); } /* 묶음 사이 */

/* 폰에서는 한 단씩 줄인다 */
@media (max-width: 600px) {
  .card { padding: var(--space-3); }
}
규칙지켜야 하는 것
8의 배수를 기본으로4px은 아이콘과 글자 사이처럼 작은 간격에만 쓰고, 나머지는 8·16·24·40을 씁니다
묶음 안 < 묶음 사이묶음 안 간격은 늘 묶음 사이 간격보다 좁아야 합니다. 간격 규칙에서 가장 중요한 조건으로, 이 관계가 뒤집히면 묶음이 한 칸씩 밀려 읽힙니다
한 방향으로만 민다마진을 위아래 양쪽에 주면 두 마진이 겹쳐 하나가 되거나(마진 겹침) 두 배로 벌어집니다. 그래서 gap을 먼저 씁니다
폰에서는 한 단 줄인다PC에서 40px이던 간격은 폰에서 24px로 줄입니다. 이때 새 값을 만들지 않고 정해 둔 단 가운데서 바꿔 고릅니다
터치 자리는 간격이 아니다버튼끼리 떼어 두는 간격과 별개로, 버튼마다 44px 이상의 누를 자리가 있어야 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

간격 토큰 = 열거형아무 정수나 받지 않고 정해진 값만 받도록 하는 열거형과 같습니다. 타입으로 막아 두면 23px 같은 값이 끼어들 수 없습니다.
디자인 도구와 맞추기피그마의 오토 레이아웃에도 같은 단을 씁니다. 디자이너와 개발자가 같은 이름으로 이야기하면 "여기 조금만 띄워 주세요" 대신 "space-4로 해 주세요"처럼 정확하게 요청할 수 있습니다.
목록 성능줄마다 여백이 다르면 줄 높이를 미리 알 수 없어서 가상 스크롤을 쓸 수 없습니다. 모든 줄이 같은 단을 쓰면 줄 높이가 고정되므로 수만 줄도 그릴 수 있습니다.
빈 값 처리데이터가 없어 요소가 빠지면 gap은 그 자리만큼 저절로 줄어들지만 margin은 그대로 남습니다. 목록 화면에 생기는 이상한 빈칸은 대부분 이렇게 남은 마진 때문입니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 단위는 다르지만, 여백을 배수로 정해 둔다는 생각은 같습니다.

웹CSS · px · rem
--space-2: 8px
gap: var(--space-2)
gap 속성이 생기면서 마진 겹침 문제는 거의 사라졌습니다. 그래서 새로 짜는 화면에서는 gap을 먼저 씁니다.
iOSpoints (pt)
.padding(16)
spacing: 8
단위는 포인트(pt)입니다. 1pt가 화면에 따라 1~3픽셀이므로, 디자이너가 적은 '16'은 px이 아니라 pt일 수 있습니다.
안드로이드dp
16.dp
Arrangement
.spacedBy(8.dp)
단위는 dp이고, Material은 8dp 그리드를 권합니다. 아이콘 자리에만 4dp 단위를 씁니다.

플랫폼 차이 때문에 자주 생기는 문제 — px과 pt, dp는 서로 다른 단위입니다. 그래서 시안에 '16'이라고만 적혀 있으면 어느 단위인지 반드시 확인하세요. 같은 16이라도 iOS의 16pt는 고해상도 기기에서 실제 픽셀 32~48개에 해당합니다. 앱 쪽에 웹 시안을 그대로 넘기면 여백이 세 배로 벌어진 화면이 나올 수 있습니다.
