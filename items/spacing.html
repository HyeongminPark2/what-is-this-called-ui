Spacing scale · spacing system

여백을 정해 둔 배수에서만 고르는 약속. 보통 4px 또는 8px 의 배수를 씁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

8px 격자 보기를 켜면 줄이 8px 마다 그어집니다. 여백이 모두 8의 배수라 테두리와 글줄이 줄에 떨어집니다.
눈대중 값으로를 켜면 7·13·19가 섞입니다. 한눈에 틀린 데를 짚기는 어려운데 전체가 어수선해집니다 — 간격 체계가 막으려는 것이 정확히 이 느낌입니다.

2 이름부르는 말이 여러 개다

한국어간격 체계, 여백 체계, 스페이싱 스케일, 8포인트 그리드
영어spacing scale, spacing system, 8-point grid
같이 쓰는 말안쪽 여백은 패딩, 바깥 여백은 마진, 플렉스·그리드에서 사이를 띄우는 것은 갭입니다. 열 사이의 홈은 거터(gutter), 화면 양옆의 여백은 마진 또는 거터라고 부르는데 팀마다 다릅니다. 4px 단위로 잡는 것을 4포인트 그리드라고 합니다.
자주 잘못 부름그리드 — 레이아웃 그리드(열을 나누는 것)와 간격 그리드(여백 단위)는 다른 것입니다.
여백 — 디자인에서 여백(white space)은 '비워 둔 공간'이라는 더 넓은 뜻입니다.
패딩 — 패딩은 자리를 가리키고 간격 체계는 값을 가리킵니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다

한 줄로 — 간격 체계는 값을 줄이는 일입니다. 쓸 수 있는 여백이 여섯 개뿐이면 고민도 줄고 어긋남도 사라집니다.

행간도 간격입니다. 글줄 사이가
묶음 사이보다 넓으면 묶음이 안 보입니다.
  1. 바깥 여백 padding · 안쪽 여백카드 테두리와 내용 사이. 사방이 같아야 안정돼 보인다
  2. 묶음 안 간격 gap · 8px제목과 부제처럼 한 덩어리인 것들. 좁게 둔다
  3. 묶음 사이 gap · 16~24px덩어리와 덩어리. 안쪽보다 반드시 넓게 — 이 비율이 묶음을 만든다
  4. 버튼 사이 gap · 8px나란한 버튼은 붙여 둔다. 멀어지면 관계없는 것으로 보인다
  5. 글줄 사이 line-height행간도 간격이다. 행간이 묶음 간격보다 넓으면 묶음이 흩어진다

간격의 진짜 일은 '예쁘게'가 아니라 무엇이 한 묶음인지 말하는 것입니다(근접성). 사람은 가까운 것끼리 한 덩어리로 봅니다. 그래서 라벨을 자기 입력창보다 윗 칸에 더 가깝게 두면 누구의 라벨인지 설명하지 않아도 알게 됩니다. 반대로 안쪽이 바깥쪽보다 넓으면 아무리 줄을 맞춰도 읽는 사람은 묶음을 못 찾습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 화면을 여럿이 만들 때 — 같은 카드가 사람마다 달라지지 않습니다
  • 목록·표처럼 같은 모양이 반복되는 화면
  • 폰과 PC 를 같이 만들 때 — 단만 바꿔 끼우면 됩니다

이럴 때는 안 쓴다

  • 타이포그래피 안쪽 미세 조정 — 글자 사이는 시각 보정이 필요해 배수에 안 맞을 수 있습니다
  • 사진·아이콘의 시각 중심 맞추기 — 숫자보다 눈이 맞습니다
  • 단을 너무 촘촘히 두는 것(2·4·6·8·10·12…) — 결국 아무 값이나 쓰는 것과 같아집니다

대신 이걸 — 글줄 사이는 타입 스케일에 딸려 있고, 화면을 열로 나누는 일은 레이아웃 그리드(1부)가 맡습니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 체계의 계약서

단은 숫자가 아니라 이름으로 부릅니다. 16px이 아니라 --space-4를 쓰면 나중에 전부 한 번에 조일 수 있습니다.

:root {
  --space-1: 4px;    --space-2: 8px;
  --space-3: 12px;   --space-4: 16px;
  --space-6: 24px;   --space-10: 40px;
}

.card {
  padding: var(--space-4);
  display: grid;
  gap: var(--space-2);   /* 묶음 안 */
}
.card + .card { margin-top: var(--space-4); } /* 묶음 사이 */

/* 폰에서는 한 단씩 줄인다 */
@media (max-width: 600px) {
  .card { padding: var(--space-3); }
}
규칙지켜야 하는 것
8의 배수를 기본으로4px 은 작은 것(아이콘·글자 사이)에만. 나머지는 8·16·24·40
묶음 안 < 묶음 사이이 한 줄이 간격 규칙의 전부입니다. 어긋나면 묶음이 밀려 읽힙니다
한 방향으로만 민다마진을 위·아래 양쪽에 주면 겹치거나(마진 겹침) 두 배가 된다. gap을 먼저 쓴다
폰에서는 한 단 줄인다PC 의 40px 이 폰에서는 24px. 단을 바꿔 끼우지 새 값을 만들지 않는다
터치 자리는 간격이 아니다버튼은 서로 떼는 것과 별개로 44px 이상의 누를 자리가 있어야 한다

9 서버 쪽으로 치면백엔드 감각으로 번역

간격 토큰 = 열거형자유로운 정수 대신 정해진 값만 받게 하는 것과 같습니다. 타입으로 막아 두면 23px 이 끼어들 수 없습니다.
디자인 도구와 맞추기피그마의 오토 레이아웃도 같은 단을 씁니다. 디자이너와 개발자가 같은 이름으로 말하면 "여기 조금만 띄워 주세요"가 "space-4 로"가 됩니다.
목록 성능줄마다 여백이 다르면 높이를 미리 알 수 없어 가상 스크롤을 못 씁니다. 같은 단을 쓰면 줄 높이가 고정돼 수만 줄도 그릴 수 있습니다.
빈 값 처리데이터가 없어 요소가 빠지면 gap은 알아서 줄어들지만 margin은 남습니다. 목록 화면에서 생기는 이상한 빈칸의 대부분이 이것입니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

단위는 다르지만 '배수로 정해 둔다'는 생각은 같습니다.

웹CSS · px · rem
--space-2: 8px
gap: var(--space-2)
gap이 들어오면서 마진 겹침 문제가 거의 사라졌습니다. 새로 짜는 화면은 gap 을 먼저 씁니다.

.padding(16)
spacing: 8
단위가 포인트입니다. 1pt 가 화면에 따라 1~3픽셀이라, 디자이너의 '16'은 px 이 아니라 pt 일 수 있습니다.

16.dp
Arrangement

단위가 dp이고 Material 은 8dp 그리드를 권합니다. 아이콘 자리만 4dp 단위로 씁니다.

자주 생기는 사고 — px · pt · dp 가 서로 다릅니다. 시안에 '16'이라고만 적혀 있으면 어느 단위인지 반드시 확인하세요. 같은 16이라도 iOS 의 16pt 는 고해상도 기기에서 32~48 실제 픽셀입니다. 앱 쪽에 웹 시안을 그대로 넘기면 여백이 세 배로 벌어진 화면이 나올 수 있습니다.
