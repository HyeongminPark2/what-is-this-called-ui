제스처

Gesture

제스처는 손가락을 따라가는 움직임입니다. 보여 주기 위한 연출이 아니라 사용자가 직접 하는 조작이어서 지켜야 할 규칙이 더 엄격합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

시트를 아래로 끌어 보세요. 조금 끌었다 놓으면 제자리로 돌아오고, 절반을 넘기거나 빠르게 튕기면 닫힙니다.
내리는 속도도 함께 보기를 끄면 짧게 탁 튕겨 닫는 동작이 듣지 않습니다. 손가락을 따라 움직이기를 끄면 규칙은 같은데도 내가 조작하고 있다는 느낌이 사라지는데, 이것으로 제스처에서 따라가기가 왜 중요한지 알 수 있습니다.

2 이름같은 것을 부르는 여러 이름

한국어제스처, 끌기, 쓸어넘기기, 당겨서 새로고침
영어gesture, drag, swipe, pan, fling, pull-to-refresh
같이 쓰는 말천천히 끄는 것을 팬·드래그, 빠르게 튕기는 것을 스와이프·플링이라고 합니다. 닫을지 말지 판단하는 기준 거리는 스레시홀드(threshold), 손을 놓은 뒤에도 미끄러지듯 이어지는 움직임은 관성(momentum)이라고 부릅니다. 손을 뗐을 때 가까운 자리에 맞춰 멈추는 것은 스냅이라고 합니다.
자주 잘못 부르는 이름애니메이션 — 제스처는 애니메이션이 아니라 입력입니다. 애니메이션은 손을 뗀 뒤에만 나옵니다.
스크롤 — 제스처가 브라우저 기본 스크롤과 같은 입력을 두고 겹치면 제스처와 스크롤이 모두 제대로 동작하지 않습니다.
터치 이벤트 — touchstart는 손가락 입력만 받지만, 포인터 이벤트는 마우스·펜·손가락을 한 코드로 받습니다.

3 끌어 닫는 동안의 단계손을 떼기 전과 뗀 뒤의 모습

4 해부도부분마다 붙은 이름

pointerdown에서 잡음 (setPointerCapture)
끄는 동안 손가락을 그대로 따라감
문턱은 절반을 넘겼는지
속도는 빠르게 튕겼는지 (0.5px/ms)
touch-action을 안 적으면 브라우저가 먼저 가져감
  1. 잡기 pointerdownsetPointerCapture를 걸면 손가락이 요소 밖으로 나가도 이벤트를 계속 받습니다
  2. 따라가기 1:1끄는 동안 손가락과 똑같이 움직입니다. 따라가지 않으면 사용자는 조작하고 있다고 느끼지 못합니다
  3. 놓기 pointerup손을 놓은 이 시점에 처음으로 애니메이션이 나옵니다
  4. 문턱 절반끈 거리로 판단합니다. 문턱이 너무 작으면 실수로 닫힙니다
  5. 속도 0.5px/ms짧게 튕겨도 닫히게 합니다. 거리만 보면 답답합니다
  6. 브라우저 스크롤과 겹치는 입력 touch-action이 속성을 적지 않으면 브라우저 스크롤이 먼저 입력을 가져갑니다

제스처는 화면에 보이지 않습니다. 예를 들어 쓸어넘겨 지우기는 화면 어디에도 표시가 없고, 마우스나 키보드로는 할 수 없습니다. 그래서 제스처로 할 수 있는 일은 반드시 버튼으로도 할 수 있어야 합니다. 시트에는 닫기 버튼과 Esc를, 쓸어넘겨 지우기에는 메뉴 안의 '삭제'를 함께 둡니다. 제스처는 자주 하는 일을 빨리 하는 방법일 뿐, 그 일을 하는 유일한 방법이 되어서는 안 됩니다.

5 쓸 때 / 안 쓸 때

제스처를 쓰는 경우

  • 시트, 카드 넘기기, 당겨서 새로고침처럼 손으로 다루는 느낌이 필요할 때
  • 자주 하는 동작을 빨리 하는 방법을 줄 때
  • 폰에서 엄지가 닿기 어려운 버튼을 대신할 때

제스처를 쓰지 않는 경우

  • 제스처로만 할 수 있는 일을 만들 때. 같은 일을 하는 버튼도 함께 둡니다
  • 되돌릴 수 없는 일을 한 번 쓸어서 처리할 때. 실수로 지워집니다
  • 브라우저 스크롤과 같은 방향으로 끄는 제스처를 만들 때
  • PC에서 끌어야만 할 수 있는 일을 만들 때. 마우스로 끌기는 불편합니다

제스처와 함께 볼 것 — 손을 놓은 뒤에 이어지는 움직임은 스프링에서, 들어오고 나가는 움직임을 짝짓는 방법은 진입과 퇴장에서 다룹니다. 같은 일을 버튼으로 하는 방법은 바텀시트와 다이얼로그 항목에 있습니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙구현할 때 지킬 최소 규칙

포인터 이벤트 하나로 마우스·펜·손가락 입력을 모두 받고, touch-action을 반드시 적습니다.

.sheet { touch-action: none; }   /* 브라우저 스크롤에 안 뺏긴다 */

sheet.addEventListener('pointerdown', e => {
  sheet.setPointerCapture(e.pointerId);      // 밖으로 나가도 계속 받는다
  start = e.clientY - y; lastY = e.clientY; lastT = performance.now();
});

sheet.addEventListener('pointermove', e => {
  const dt = performance.now() - lastT;
  v = (e.clientY - lastY) / Math.max(dt, 1);   // px/ms
  lastY = e.clientY; lastT = performance.now();
  move(e.clientY - start);                   // 1:1 로 따라간다
});

sheet.addEventListener('pointerup', () => {
  (y > H / 2 || v > 0.5) ? close() : snapBack();   // 거리 또는 속도
});
알아 둘 규칙자세한 내용
touch-actionnone이나 pan-y를 적습니다. 적지 않으면 브라우저가 먼저 입력을 가져갑니다
setPointerCapture손가락이 상자 밖으로 나가도 이벤트가 계속 옵니다. 걸지 않으면 중간에 끊깁니다
pointercancel전화가 오거나 브라우저가 입력을 가로채면 이 이벤트가 옵니다. 이때는 제자리로 되돌려야 합니다
키보드로 닫는 방법 꼭 두기Esc로 닫기와 닫기 버튼을 둡니다. 제스처는 키보드로 대신할 수 없습니다
user-select: none끄는 동안 글자가 선택되어 파랗게 칠해지는 것을 막습니다
모션 줄이기를 켰을 때따라가기는 그대로 둡니다. 사용자의 손가락이 만든 움직임이라 멀미를 일으키지 않기 때문입니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

쓸어서 지운 것을 되돌릴 수 있게 하기실수가 잦은 조작이라 바로 지우지 않고 되돌릴 시간을 둡니다. 보통 5초쯤 기다렸다가 실제 삭제 요청을 보냅니다.
당겨서 새로고침을 여러 번 했을 때몇 번을 당겨도 요청은 하나만 나가게 막습니다. 그러지 않으면 같은 요청이 여러 번 연달아 갑니다.
끄는 도중에는 요청하지 않기손을 떼기 전까지는 아무것도 확정되지 않았기 때문에, 끄는 도중의 값으로 서버에 요청하지 않습니다.
제스처가 중간에 끊겼을 때앱이 배경으로 가면 pointercancel만 오고 pointerup은 오지 않습니다. 그래서 제스처가 끊겼을 때는 되돌리는 쪽을 기본으로 둡니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

폰에서는 제스처가 기본 조작이지만, PC에서는 보조 수단입니다.

웹Pointer Events
마우스·펜·손가락 입력을 한 코드로 받습니다. 구현할 때는 브라우저 기본 동작과 입력이 겹치지 않게 하는 일이 가장 큽니다.
iOSUIGestureRecognizer
제스처마다 전용 인식기가 있고, 인식기끼리 어느 쪽이 먼저 입력을 받을지 정하는 규칙까지 있습니다. 화면 가장자리에서 쓸면 뒤로 갑니다.
안드로이드GestureDetector
양쪽 가장자리에서 쓸면 모두 뒤로 가기 때문에, 가장자리에서 끄는 제스처를 만들면 시스템 뒤로가기와 겹칩니다.

플랫폼 차이 때문에 자주 생기는 문제 — "카톡처럼 쓸어서 답장" 같은 요청은 제스처 자체를 만드는 일보다 함께 챙겨야 할 일이 더 많습니다. 되돌리기, 키보드로 하는 방법, 스크롤과 입력이 겹치는 문제, 가장자리 뒤로가기와의 충돌까지 모두 처리해야 합니다. 제스처를 넣기로 했다면 같은 일을 하는 버튼을 먼저 만들고 그 위에 제스처를 더하는 순서가 안전합니다.
