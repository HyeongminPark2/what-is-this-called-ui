제스처

Gesture

손가락을 따라가는 움직임. 연출이 아니라 조작이라 규칙이 더 엄격합니다.

속도도 본다를 끄면 짧게 탁 튕겨 닫는 동작이 안 먹힙니다. 손가락을 따라간다를 끄면 같은 규칙인데도 내가 조작하고 있다는 느낌이 사라집니다 — 제스처에서 따라가기가 왜 핵심인지 알 수 있습니다.

2 이름부르는 말이 여러 개다

한국어제스처, 끌기, 쓸어넘기기, 당겨서 새로고침
영어gesture, drag, swipe, pan, fling, pull-to-refresh
같이 쓰는 말천천히 끄는 것이 팬·드래그, 빠르게 튕기는 것이 스와이프·플링입니다. 판단 기준이 되는 거리가 스레시홀드(threshold), 놓은 뒤 미끄러지는 것이 관성(momentum)입니다. 손을 뗐을 때 가까운 자리로 붙는 것을 스냅이라 합니다.
자주 잘못 부름애니메이션 — 제스처는 입력입니다. 애니메이션은 손을 뗀 뒤에만 나옵니다.
스크롤 — 브라우저가 이미 하는 스크롤과 싸우면 둘 다 망가집니다.
터치 이벤트 — touchstart는 손가락만, 포인터 이벤트는 마우스·펜·손가락을 한 코드로 받습니다.

움직임은 장식이 아니라 말입니다. 이 네 가지만 물어보면 갈립니다.

이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다

한 줄로 — 끄는 동안 따라가지 않으면 제스처가 아닙니다. 그리고 거리만 보면 '끝까지 끌어야 하는' 조작이 됩니다 — 속도도 봅니다.

4 끄는 네 토막손을 떼기 전과 뒤

5 해부도부분 이름이 제일 안 알려진 지식

pointerdown — 잡는다 (setPointerCapture)
끄는 동안 손가락을 그대로 따라간다
문턱 — 절반을 넘겼나
속도 — 빠르게 튕겼나 (0.5px/ms)
touch-action 을 안 적으면 브라우저가 먼저 가져간다
  1. 잡기 pointerdownsetPointerCapture로 밖으로 나가도 계속 받는다
  2. 따라가기 1:1끄는 동안 그대로 움직인다. 안 따라가면 조작이 아니다
  3. 놓기 pointerup여기서 처음으로 애니메이션이 나온다
  4. 문턱 절반거리로 판단. 너무 작으면 실수로 닫힌다
  5. 속도 0.5px/ms짧게 튕겨도 닫히게. 거리만 보면 답답하다
  6. 브라우저와의 자리 다툼 touch-action안 적으면 스크롤이 먼저 가져간다

제스처는 숨어 있습니다. 쓸어넘겨 지우기는 보이지 않고, 마우스로도 키보드로도 할 수 없습니다. 그래서 제스처로 되는 일은 반드시 버튼으로도 되어야 합니다 — 시트에는 닫기 버튼과 Esc, 쓸어넘겨 지우기에는 메뉴 안의 '삭제'가 함께 있어야 합니다. 제스처는 빠른 길이지 유일한 길이 아닙니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 손으로 다루는 느낌이 필요한 것 — 시트, 카드 넘기기, 당겨서 새로고침
  • 자주 하는 동작의 빠른 길
  • 폰에서 엄지로 닿기 어려운 버튼을 대신할 때

이럴 때는 안 쓴다

  • 제스처로만 되는 일 — 버튼도 함께 둔다
  • 되돌릴 수 없는 일을 한 번 쓸어서 — 실수로 지워진다
  • 브라우저 스크롤과 같은 방향으로 다투기
  • PC 에서 끌기만으로 되는 일 — 마우스로는 불편하다

대신 이걸 — 놓은 뒤의 움직임은 스프링, 들고 나는 짝은 진입과 퇴장, 버튼으로 되는 길은 바텀시트·다이얼로그.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 제스처의 계약서

포인터 이벤트 하나로 마우스·펜·손가락을 다 받고, touch-action을 반드시 적습니다.

.sheet { touch-action: none; }   /* 브라우저 스크롤에 안 뺏긴다 */

sheet.addEventListener('pointerdown', e => {
  sheet.setPointerCapture(e.pointerId);      // 밖으로 나가도 계속 받는다
  start = e.clientY - y; lastY = e.clientY; lastT = performance.now();
});

sheet.addEventListener('pointermove', e => {
  const dt = performance.now() - lastT;
  v = (e.clientY - lastY) / Math.max(dt, 1);   // px/ms
  lastY = e.clientY; lastT = performance.now();
  move(e.clientY - start);                   // 1:1 로 따라간다
});

sheet.addEventListener('pointerup', () => {
  (y > H / 2 || v > 0.5) ? close() : snapBack();   // 거리 또는 속도
});
키일어나야 하는 일
touch-actionnone·pan-y. 안 적으면 브라우저가 먼저 가져간다
setPointerCapture손가락이 상자 밖으로 나가도 이벤트가 계속 온다. 없으면 중간에 끊긴다
pointercancel전화가 오거나 브라우저가 가로채면 온다. 제자리로 되돌려야 한다
키보드 길을 반드시Esc로 닫기, 닫기 버튼. 제스처는 키보드로 흉내 낼 수 없다
user-select: none끄는 동안 글자가 잡혀 파랗게 되는 것을 막는다
모션 줄이기따라가기는 그대로 둔다 — 내 손가락이 만든 움직임이라 멀미를 일으키지 않는다

9 서버 쪽으로 치면백엔드 감각으로 번역

쓸어서 지우기는 되돌릴 수 있어야실수가 잦은 조작이라 바로 지우지 말고 되돌릴 틈을 둡니다. 보통 5초쯤 뒤에 진짜로 보냅니다.
당겨서 새로고침이 연타된다몇 번을 당겨도 요청은 하나만 나가게 막습니다. 안 그러면 같은 요청이 줄줄이 갑니다.
끄는 중에는 요청하지 않는다손을 떼기 전까지는 아무 일도 확정되지 않았습니다. 중간 값으로 서버를 부르지 않습니다.
끊긴 제스처앱이 배경으로 가면 pointercancel만 오고 pointerup은 안 옵니다. 되돌리는 쪽이 기본값이어야 합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

폰에서는 당연한 것이고, PC 에서는 보조입니다.

웹Pointer Events
마우스·펜·손가락을 한 코드로 받습니다. 브라우저 기본 동작과의 자리 다툼이 가장 큰 일거리입니다.
iOSUIGestureRecognizer
제스처마다 전용 인식기가 있고 서로 양보하는 규칙까지 정해져 있습니다. 가장자리에서 쓸면 뒤로가기입니다.
안드로이드GestureDetector
양쪽 가장자리가 전부 뒤로가기라, 가장자리에서 끄는 제스처를 만들면 부딪힙니다.

자주 생기는 사고 — "카톡처럼 쓸어서 답장"류 요청은 만드는 품보다 뒤처리가 많습니다 — 되돌리기, 키보드 길, 스크롤과의 다툼, 가장자리 뒤로가기와의 충돌까지가 한 벌입니다. 제스처를 넣기로 했으면 같은 일을 하는 버튼을 먼저 만들고 제스처를 얹는 순서가 안전합니다.
