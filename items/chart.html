차트 고르기

Choosing a chart

차트는 질문이 먼저입니다. 무엇을 묻느냐가 정해지면 그릴 그림은 거의 자동으로 정해집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

묻고 싶은 것을 골라 보세요. 맞는 그림과 흔히 잘못 고르는 그림이 나란히 나옵니다.
축을 0에서 자르기를 켜 보면 같은 숫자가 어떻게 세 배쯤 달라 보이는지 알 수 있습니다 — 보고서에서 가장 자주 나오는 거짓말입니다.

2 이름부르는 말이 여러 개다

한국어차트, 그래프, 도표, 시각화
영어chart, graph, plot, data visualization
같이 쓰는 말막대그래프가 바 차트, 눕히면 가로 막대(horizontal bar), 선이 라인 차트, 밑을 칠하면 에어리어, 점이 산점도(scatter), 원이 파이·도넛입니다. 작게 줄여 글 속에 넣은 선을 스파크라인이라 합니다.
자주 잘못 부름그래프 — 일상에서는 같은 말이지만 전산에서 '그래프'는 점과 선의 연결 구조를 뜻하기도 합니다.
대시보드 — 차트 여럿을 모아 둔 화면이지 차트 자체가 아닙니다.
인포그래픽 — 데이터보다 설명이 주인입니다. 정확도 기준이 다릅니다.

3 가르는 기준형제들과 비교하는 네 축

데이터를 다루는 화면은 '건수가 늘면 어떻게 되나'가 설계의 전부입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 다루나건수가 늘면주소에 담나서버가 할 일
데이터 테이블여러 열의 행들쪽을 나눈다담는다(정렬·쪽)페이징 · 정렬
필터와 패싯거르는 조건조건이 늘어난다담는다조건별 개수 세기
검색질의어결과가 늘어난다담는다색인 · 순위
폼 설계입력 묶음단계를 나눈다안 담는다저장 · 임시 저장
입력 검증틀린 값해당 없음안 담는다서버가 다시 검사
일괄 선택고른 것들'전체'가 모호해진다안 담는다묶음 처리 · 되돌리기
가상 스크롤긴 목록이게 그 답이다안 담는다커서 페이징
차트 고르기숫자들의 관계점이 뭉친다담기도 한다집계 · 구간 나누기

한 줄로 — 차트를 고르기 전에 한 문장으로 물음을 적으세요. '누가 제일 큰가'와 '언제부터 늘었나'는 다른 그림입니다.

4 질문별로 고르기그림이 아니라 물음이 먼저다

5 해부도부분 이름이 제일 안 알려진 지식

11월 가맹점별 매출
막대의 밑은 0에서 시작한다 — 잘라내면 거짓말이 된다
눈금에 단위를 적는다 — 만 원? 건?
색은 뜻이 있을 때만. 네 색 쓰면 넷을 외워야 한다
<table> 를 같이 둔다 — 눈으로 안 보는 사람의 길
  1. 제목 무엇의 무엇인가'매출'이 아니라 '11월 가맹점별 매출'
  2. 그림 막대·선·점물음에 맞는 모양 하나
  3. 0 기준선 막대는 필수자르면 작은 차이가 세 배로 보인다
  4. 눈금과 단위 원? 만 원? 건?숫자만 있으면 크기를 못 읽는다
  5. 색 뜻이 있을 때만강조할 하나만 진하게. 나머지는 회색으로
  6. 표도 함께 <table>그림은 눈으로만 읽힌다. 숫자 표를 같이 둔다

막대의 밑은 0 이어야 합니다. 길이로 크기를 읽는 그림이라 밑을 잘라내면 눈이 읽는 비율 자체가 거짓이 됩니다. 100·102·104 를 98 부터 그리면 두 배 차이처럼 보입니다. 선 그래프는 '변화'를 읽는 그림이라 잘라도 되지만, 이때는 축에 잘랐다고 적어 둡니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 숫자들의 관계를 한눈에 보여야 할 때
  • 흐름·크기 차이가 표로는 안 보일 때
  • 볼 사람이 정확한 값이 아니라 경향을 원할 때

이럴 때는 안 쓴다

  • 값이 서넛일 때 — 그냥 숫자로 적는 게 빠르다
  • 정확한 값이 필요할 때 → 데이터 테이블
  • 조각이 다섯을 넘는 파이 — 막대로 바꾼다
  • 3차원·기울인 그림 — 보기에만 좋고 크기를 왜곡한다

대신 이걸 — 정확한 값이면 데이터 테이블, 값 하나면 스탯, 비율 하나면 프로그레스.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 접근이 차트의 계약서

차트는 그림이므로 이름을 붙이고, 숫자는 표로 한 벌 더 둡니다.

<figure>
  <figcaption>11월 가맹점별 매출 (단위: 만 원)</figcaption>

  <svg role="img"
       aria-label="막대그래프. 새벽상사가 80으로 가장 높다">…</svg>

  <table class="sr-only">      <!-- 숫자를 읽을 길 -->
    <tr><th>모란상회</th><td>62</td></tr>
  </table>
</figure>

/* 그림은 칸을 따르되 찌그러지지 않게 */
svg { width: 100%; height: auto; }   /* viewBox + xMidYMid meet */
키일어나야 하는 일
role="img" + aria-label무엇을 말하는 그림인지 한 문장. '차트'라고만 적으면 쓸모없다
<figcaption>제목과 단위. 눈으로 보는 사람에게도 필요하다
숨은 <table>정확한 값을 읽을 유일한 길. sr-only로 둬도 된다
색만으로 구분하지 않는다선은 모양(점선·실선)이나 직접 라벨로도 가른다
preserveAspectRatio기본은 xMidYMid meet. none으로 두면 원이 타원이 된다
움직임그리며 자라는 연출은 prefers-reduced-motion에서 끈다

9 서버 쪽으로 치면백엔드 감각으로 번역

집계는 서버에서10만 건을 보내 브라우저가 더하게 하면 느립니다. 이미 더한 값을 보냅니다.
구간을 정해 보낸다일별인지 주별인지는 서버가 결정해 보내야 눈금이 흔들리지 않습니다. 기간이 길면 자동으로 묶습니다.
빈 구간을 채운다거래가 없는 날은 행이 아예 없습니다. 그대로 그리면 날짜가 건너뛴 선이 됩니다. 0 을 채워 보냅니다.
시간대'11월 1일'이 서버 기준인지 보는 사람 기준인지에 따라 숫자가 달라집니다. 기준을 적어 보냅니다.
점이 너무 많을 때1년치 분당 데이터는 50만 점입니다. 서버에서 솎아(downsample) 보내고, 확대하면 그 구간만 다시 받습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

표준 부품이 없어 어디서나 라이브러리를 씁니다.

웹SVG / Canvas
점이 수천 개를 넘으면 SVG 가 느려집니다. 그때 캔버스로 바꿉니다.
iOSSwift Charts
2022년부터 OS 기본 차트가 생겼습니다. 다크 모드와 글자 크기를 알아서 따릅니다.
안드로이드라이브러리
OS 기본 차트가 없어 외부 라이브러리를 씁니다. Compose 로 직접 그리는 경우도 많습니다.

자주 생기는 사고 — "차트 하나 넣어 주세요"를 받으면 무엇을 묻는 그림인지를 먼저 물으세요. '매출 차트'는 요구사항이 아닙니다 — '지난달 대비 어느 가맹점이 늘었나'여야 막대인지 선인지가 정해지고, 그래야 서버가 어떤 모양으로 집계해 보낼지도 정해집니다.
