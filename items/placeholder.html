자리글과 헬퍼 텍스트

Placeholder & helper text

레이블 · 자리글 · 헬퍼는 서로 다른 일을 합니다. 하나로 때우면 다른 둘이 사라집니다.

① 실물② 이름③ 가르는 기준④ 상태⑤ 해부도⑥ 쓸 때⑦ 사례⑧ 마크업⑨ 백엔드 메모⑩ 플랫폼

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

레이블을 자리글로 쓰기를 켜고 세 칸 채우기를 눌러 보세요 — 글자를 치는 순간 그 칸이 무슨 칸이었는지가 사라집니다.
자리글의 일은 형식의 보기를 드는 것입니다. 칸 이름은 레이블이, 규칙은 헬퍼 텍스트가 맡습니다.

2 이름부르는 말이 여러 개다

한국어자리글, 플레이스홀더, 힌트, 헬퍼 텍스트, 보조 설명
영어placeholder, hint text, helper text, supporting text
같이 쓰는 말placeholder 속성으로 넣는 흐린 글자가 자리글이고, 칸 밑에 늘 보이는 설명이 헬퍼 텍스트·서포팅 텍스트입니다. 칸 이름이 칸 안에 있다가 치면 위로 올라가는 것을 플로팅 레이블이라 합니다.
자주 잘못 부름레이블 — 자리글은 레이블이 아닙니다. 치면 사라지기 때문입니다.
툴팁 — 툴팁은 올려야 보입니다. 폰에서는 못 봅니다.
오류 문구 — 오류는 틀린 뒤, 헬퍼는 틀리기 전입니다.

3 가르는 기준형제들과 비교하는 네 축

화면의 말은 꾸미는 것이 아니라 일하는 것입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 알려야 하나흔한 실수고치는 기준한국어에서 더 조심할 것
버튼 문구누르면 무슨 일이 나나‘확인’ · ‘제출’동사 + 두세 어절조사 없이 끝낸다
오류 문구무엇이 · 왜 · 어떻게코드만 보여 주기다음 수가 있나사과보다 다음 수
빈 상태 문구왜 비었고 뭘 하면 되나‘데이터가 없습니다’네 경우를 가른다명사로 끝내지 않는다
자리글과 헬퍼 텍스트형식의 보기레이블을 자리글로셋을 따로 둔다보기를 진짜처럼
한국어 UI같은 말을 한국어로번역투소리 내어 읽어 본다조사 · 주어 생략
날짜와 시간 쓰기언제인지기계 꼴 그대로얼마나 지났나로 가른다오전 · 오후와 요일
숫자와 단위 쓰기얼마인지단위 없는 숫자자리에 따라 끊는다만 · 억으로 읽는다
말투와 높임우리가 누구인지화면마다 다른 말투하나로 정한다해요체인가 합쇼체인가

한 줄로 — 자리글은 보기, 헬퍼는 규칙, 레이블은 이름. 셋 다 필요하고 서로 대신하지 못합니다.

4 셋을 가르면무엇이 사라지나

5 해부도부분 이름이 제일 안 알려진 지식

레이블 — 칸의 이름. 늘 보인다
사업자번호
1248100998
- 없이 10자리
자리글 — 형식의 보기. 치면 사라진다
헬퍼 — 규칙. 틀리기 전에 미리 알려 준다
오류 — 틀린 뒤. 헬퍼 자리에 들어간다
자리글을 레이블로 쓰면 치는 순간 이름이 사라진다
  1. 레이블 칸의 이름늘 보인다. 치든 안 치든 사라지지 않는다
  2. 자리글 형식의 보기1248100998처럼 진짜 같은 값을
  3. 헬퍼 규칙'- 없이 10자리'. 틀리기 전에 알려 준다
  4. 오류 헬퍼 자리에틀린 뒤 같은 자리에 들어온다. 칸이 안 움직인다
  5. 자리글 색 흐리게, 그러나너무 흐리면 대비비에 걸린다
  6. 자리글을 이름으로 치면 사라진다가장 흔한 실수. 고치러 돌아오면 못 읽는다

'비어 있을 때는 멀쩡해 보인다'는 것이 이 실수가 오래 사는 이유입니다. 시안은 대개 빈 칸으로 그려지고, 거기서는 자리글이 레이블 노릇을 잘합니다. 문제는 값이 들어간 뒤에만 나타납니다 — 고치러 돌아온 화면, 자동완성이 채운 칸, 오류를 고치는 중. 전부 처음 쓸 때가 아니라 두 번째부터라, 시안 검토에서는 거의 안 걸립니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 셋을 따로 두기 — 이름 · 보기 · 규칙
  • 자리글에는 진짜 같은 값을 넣기
  • 규칙은 틀리기 전에 보여 주기

이럴 때는 안 쓴다

  • 자리글을 레이블로 — 치면 사라진다
  • 자리글에 ‘입력하세요’ — 아무 정보가 없다
  • 설명을 툴팁에만 — 폰에서 못 본다
  • 자리글을 너무 흐리게 — 대비비가 모자란다

대신 이걸 — 칸 자체는 입력 필드, 틀린 뒤 문구는 입력 검증, 칸이 많으면 폼 설계.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 글자들의 계약서

레이블은 <label>, 헬퍼는 aria-describedby로 묶습니다.

<label for="no">사업자번호</label>
<input id="no" name="no"
       placeholder="1248100998"
       inputmode="numeric"
       aria-describedby="no-help">
<p id="no-help" class="help">- 없이 10자리</p>

/* 자리글은 흐리되 읽을 수는 있게 */
input::placeholder { color: var(--fg-muted); }   /* 4.5:1 을 지킨다 */
키일어나야 하는 일
<label for>자리글은 이름이 못 된다. 보조기기가 읽는 것은 레이블이다
aria-describedby헬퍼를 칸에 묶는다. 안 묶으면 그냥 옆에 있는 글이다
오류와 헬퍼를 같은 자리에칸이 위아래로 안 움직인다. 글이 덜컥거리지 않는다
::placeholder 대비비브라우저 기본값은 4.5:1 에 못 미친다. 직접 정한다
자리글에 단위를 넣지 않는다'원'을 자리글에 두면 치는 순간 사라진다. 칸 밖에 적는다
title 속성호버로만 뜬다. 폰에서는 못 본다 — 헬퍼로 뺀다

9 서버 쪽으로 치면백엔드 감각으로 번역

형식을 한곳에 적어 둔다자리글·헬퍼·검증·서버 검사가 따로 놀면 서로 다른 규칙을 말하게 됩니다.
서버 오류도 같은 자리에서버가 돌려준 문구를 헬퍼 자리에 넣으면 화면이 안 흔들립니다.
보기 값을 진짜로 쓰지 않는다자리글에 넣은 번호가 실제 사업자번호면 곤란합니다. 만든 값을 씁니다.

자주 생기는 사고 — 시안이 깔끔해 보이려고 레이블을 지우고 자리글만 남기는 일이 흔합니다. 이건 취향 문제가 아니라 두 번째 사용부터 깨지는 설계라, 시안을 받을 때 값이 채워진 상태를 한 장 더 달라고 하면 그 자리에서 드러납니다.
