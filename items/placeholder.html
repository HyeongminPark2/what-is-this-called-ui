자리글과 헬퍼 텍스트

Placeholder & helper text

레이블은 칸 이름을, 자리글은 형식의 보기를, 헬퍼 텍스트는 입력 규칙을 알려 주기 때문에 셋은 서로 다른 일을 합니다. 하나로 셋을 대신하면 나머지 두 정보가 화면에서 빠집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

레이블을 자리글로 쓰기를 켜고 세 칸 채우기를 눌러 보세요. 글자가 들어가는 순간 자리글이 사라지면서 그 칸이 무슨 칸이었는지도 알 수 없게 됩니다.
자리글에는 입력할 값의 형식을 보기로 보여 주고, 칸 이름은 레이블에, 규칙은 헬퍼 텍스트에 적습니다.

2 이름같은 것을 부르는 여러 이름

한국어자리글, 플레이스홀더, 힌트, 헬퍼 텍스트, 보조 설명
영어placeholder, hint text, helper text, supporting text
같이 쓰는 말placeholder 속성으로 넣는 흐린 글자가 자리글이고, 칸 밑에 늘 보이는 설명이 헬퍼 텍스트·서포팅 텍스트입니다. 칸 이름이 칸 안에 있다가 글자를 치면 위로 올라가는 것은 플로팅 레이블이라고 합니다.
자주 잘못 부르는 이름레이블 — 자리글은 글자를 치면 사라지기 때문에 레이블이 될 수 없습니다.
툴팁 — 툴팁은 마우스를 올려야 보이기 때문에 폰에서는 볼 수 없습니다.
오류 문구 — 오류 문구는 값이 틀린 뒤에 보여 주고, 헬퍼 텍스트는 틀리기 전에 미리 보여 줍니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

화면 문구는 사용자가 무엇을 하면 되는지 알려 줍니다. 아래 네 가지로 문구마다 다른 점을 봅니다.

사용자에게 무엇을 알려야 하는가흔한 실수고치는 기준한국어에서 더 조심할 것
버튼 문구누르면 무슨 일이 일어나는지‘확인’ · ‘제출’동사로 두세 어절 안에조사 없이 끝내기
오류 문구무엇이 · 왜 · 어떻게코드만 보여 주기다음에 할 일을 알려 주는지사과보다 다음에 할 일 먼저
빈 상태 문구왜 비었고 무엇을 하면 되는지‘데이터가 없습니다’네 경우를 가르기명사로 끝내지 않기
자리글과 헬퍼 텍스트형식의 보기레이블을 자리글로 대신하기셋을 따로 두기보기를 실제 값처럼 쓰기
한국어 UI같은 뜻을 한국어답게번역투소리 내어 읽어 보기조사 · 주어 생략
날짜와 시간 쓰기언제인지기계용 형식을 그대로 보여 주기얼마나 지났는지로 가르기오전 · 오후와 요일
숫자와 단위 쓰기얼마인지단위 없는 숫자자리에 따라 끊어 적기만 · 억 단위로 끊어 읽기
말투와 높임우리가 누구인지화면마다 다른 말투하나로 정하기해요체와 합쇼체 가운데 고르기

자리글과 헬퍼 텍스트를 한 줄로 정리하면 — 자리글은 보기를, 헬퍼는 규칙을, 레이블은 이름을 알려 줍니다. 셋 다 필요하고, 어느 하나가 다른 것을 대신할 수 없습니다.

4 레이블·자리글·헬퍼를 나눠 둔 모습하나를 빼면 사라지는 정보

5 해부도부분마다 붙은 이름

레이블은 칸의 이름이라 늘 보임
사업자번호
1248100998
- 없이 10자리
자리글은 형식의 보기로, 치면 사라짐
헬퍼는 규칙을 틀리기 전에 미리 알려 줌
오류는 틀린 뒤에 헬퍼 자리로 들어옴
자리글을 레이블로 쓰면 치는 순간 이름이 사라짐
  1. 레이블 칸의 이름늘 보입니다. 값을 쳐도 사라지지 않습니다
  2. 자리글 형식의 보기1248100998처럼 진짜 같은 값을 보기로 넣습니다
  3. 헬퍼 규칙'- 없이 10자리'처럼 지켜야 할 규칙을 틀리기 전에 알려 줍니다
  4. 오류 헬퍼 자리에값이 틀리면 헬퍼 자리에 오류 문구가 들어오므로 칸이 위아래로 움직이지 않습니다
  5. 자리글 색 흐리되 읽을 수 있게흐리게 쓰되, 너무 흐리면 대비비 기준을 지키지 못합니다
  6. 자리글을 이름으로 치면 사라짐가장 흔한 실수입니다. 값을 고치러 돌아왔을 때 칸 이름을 읽을 수 없습니다

이 실수가 오래 고쳐지지 않는 까닭은 칸이 비어 있을 때는 멀쩡해 보이기 때문입니다. 시안은 대개 빈 칸으로 그리는데, 빈 칸에서는 자리글이 레이블 역할을 충분히 합니다. 문제는 값을 고치러 돌아온 화면, 자동완성이 채운 칸, 오류를 고치는 중처럼 값이 들어간 뒤에만 나타납니다. 모두 처음 입력할 때가 아니라 두 번째부터 겪는 상황이라서 시안 검토에서는 거의 드러나지 않습니다.

6 쓸 때 / 안 쓸 때

자리글과 헬퍼 텍스트를 쓸 때 지킬 것

  • 이름 · 보기 · 규칙을 따로 두기
  • 자리글에는 진짜 같은 값을 넣기
  • 규칙은 틀리기 전에 보여 주기

자리글과 헬퍼 텍스트에서 피할 것

  • 자리글을 레이블 대신 쓸 때. 값을 치면 사라집니다
  • 자리글에 ‘입력하세요’라고 적을 때. 아무 정보도 주지 않습니다
  • 설명을 툴팁에만 넣을 때. 폰에서는 볼 수 없습니다
  • 자리글을 너무 흐리게 쓸 때. 대비비가 모자랍니다

자리글과 헬퍼 텍스트와 함께 보면 좋은 항목 — 입력 칸 자체는 입력 필드에서, 값이 틀린 뒤에 보여 주는 문구는 입력 검증에서 다룹니다. 칸이 여럿인 화면을 짤 때는 폼 설계를 함께 봅니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드코드로 옮길 때 지킬 것

레이블은 <label>로 칸에 연결하고, 헬퍼는 aria-describedby로 칸에 묶습니다.

<label for="no">사업자번호</label>
<input id="no" name="no"
       placeholder="1248100998"
       inputmode="numeric"
       aria-describedby="no-help">
<p id="no-help" class="help">- 없이 10자리</p>

/* 자리글은 흐리되 읽을 수는 있게 */
input::placeholder { color: var(--fg-muted); }   /* 4.5:1 을 지킨다 */
지킬 규칙과 마크업지키는 방법과 이유
<label for>보조기기는 레이블을 칸 이름으로 읽으므로 자리글로는 이름을 대신할 수 없습니다
aria-describedby헬퍼 텍스트를 칸에 연결합니다. 연결하지 않으면 보조기기에게는 칸과 상관없는 그냥 옆에 있는 글이 됩니다
오류를 헬퍼와 같은 자리에 두기오류 문구가 헬퍼 자리에 들어가므로 칸이 위아래로 움직이지 않고, 글이 밀려 흔들리지도 않습니다
::placeholder의 대비비 맞추기브라우저 기본 자리글 색은 대비비가 4.5:1에 못 미치므로 색을 직접 정합니다
자리글에 단위를 넣지 않기'원' 같은 단위를 자리글에 두면 값을 치는 순간 사라지므로 칸 밖에 적습니다
title 속성에 설명 두지 않기마우스를 올려야만 뜨기 때문에 폰에서는 볼 수 없습니다. 설명은 헬퍼 텍스트로 옮깁니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

형식을 한곳에 적어 두기자리글, 헬퍼, 검증, 서버 검사가 형식을 각자 따로 정해 두면 서로 다른 규칙을 말하게 됩니다.
서버 오류도 헬퍼 자리에 넣기서버가 돌려준 오류 문구도 헬퍼 자리에 넣으면 칸이 밀리지 않아 화면이 흔들리지 않습니다.
보기에 실제 값을 쓰지 않기자리글에 넣은 번호가 누군가의 실제 사업자번호이면 곤란하므로, 형식만 맞춘 지어낸 값을 씁니다.

값을 치면 칸 이름이 칸 안에서 위로 올라갑니다. 이름이 사라지지 않으므로 자리글을 레이블로 쓸 때의 문제가 생기지 않습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 시안을 깔끔하게 보이려고 레이블을 지우고 자리글만 남기는 일이 흔합니다. 이런 설계에서는 두 번째 사용부터 칸 이름을 읽을 수 없으므로 취향으로 넘길 문제가 아닙니다. 시안을 받을 때 값이 채워진 상태의 화면을 한 장 더 달라고 하면 이 문제가 그 자리에서 드러납니다.
