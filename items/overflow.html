넘침

Overflow

넘침은 상자보다 내용이 클 때 넘친 부분을 어떻게 처리할지 고르는 일입니다. 아무것도 고르지 않으면 기본값인 visible이 적용되어 내용이 상자 밖으로 삐져나옵니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 글을 네 가지 overflow 값으로 나란히 두었습니다. scroll은 글이 넘치지 않아도 스크롤바 자리를 잡는다는 점을 눈여겨보세요.
아래는 가로 스크롤의 원인을 찾는 실험입니다. 체크를 켜고 끄면서 scrollWidth - clientWidth 값이 어떻게 바뀌는지 보세요. 가로 스크롤은 거의 항상 줄어들지 못하는 칸 하나 때문에 생깁니다.

2 이름같은 것을 부르는 여러 이름

한국어넘침, 오버플로, 말줄임
영어overflow, clipping, scroll container, text-overflow
같이 쓰는 말스크롤이 생긴 상자는 스크롤 컨테이너(scroll container), 넘친 부분을 잘라 내는 것은 클리핑(clipping), 글 끝을 …으로 줄이는 것은 말줄임(ellipsis · truncation)이라고 부릅니다. 가로만 따로 정할 때는 overflow-x, 세로만 정할 때는 overflow-y를 씁니다.
자주 잘못 부르는 이름hidden과 말줄임 — hidden은 넘친 부분을 그냥 잘라 낼 뿐이라서, …이 나오려면 text-overflow: ellipsis와 white-space: nowrap이 함께 있어야 합니다.
auto와 scroll — auto는 넘칠 때만 스크롤바 자리를 잡고, scroll은 항상 잡습니다.
'가로 스크롤이 생겼다' — overflow 설정 문제가 아니라 안쪽에 줄어들지 않는 요소가 있다는 뜻입니다.

3 넘친 내용을 처리하는 방법값마다 달라지는 넘친 내용의 모습

4 해부도부분마다 붙은 이름

상자보다 글이 길어지면 무엇을 할지는 고르는 것이지 저절로 정해지지 않습니다. 네 가지 중 하나를 골라야 합니다.
overflow: visible 기본값, 밖으로 삐져나옴
overflow: hidden 잘려서 읽을 방법이 없음
overflow: auto 넘칠 때만 스크롤
text-overflow: ellipsis 한 줄 끝을 …으로 줄임
min-width: 0 빠지면 가로 스크롤이 생김
  1. 스크롤 컨테이너 scroll containeroverflow가 visible이 아닌 상자입니다. 이 상자 안쪽은 바깥과 따로 스크롤됩니다
  2. visible overflow: visible기본값이며, 자르지도 스크롤하지도 않습니다. 다만 부모가 대신 잘라 낼 수는 있습니다
  3. hidden overflow: hidden넘친 부분을 자릅니다. 쓰기는 쉽지만 잘린 내용을 읽을 방법이 사라집니다
  4. auto overflow: auto넘칠 때만 스크롤됩니다. 내용 길이를 모를 때 기본으로 고르는 값입니다
  5. 말줄임 text-overflow: ellipsis이 속성 하나만으로는 말줄임이 되지 않고, overflow·white-space와 함께 세 개를 써야 합니다
  6. 안 줄어드는 칸 min-width: 0가로 스크롤을 만드는 실제 원인입니다. overflow를 고쳐서는 해결되지 않습니다

overflow를 visible이 아닌 값으로 바꾸면 다른 동작도 함께 바뀝니다. 그 안의 position: sticky는 이 상자를 기준으로 붙게 되는데, '스티키가 안 먹어요'라는 문제가 흔히 여기서 생깁니다. 또 상자 밖으로 나간 그림자·배지·드롭다운도 잘립니다. 그래서 "일단 hidden으로 막자"고 넘어가면 다른 자리에서 새 버그가 생기는 일이 잦습니다.

5 쓸 때 / 안 쓸 때

넘침 처리를 정해 둬야 하는 경우

  • 길이를 알 수 없는 내용을 담을 때. auto를 씁니다
  • 목록의 제목처럼 한 줄로 맞춰야 할 때. 말줄임 세 줄을 씁니다
  • 칩 줄이나 탭 줄처럼 옆으로 밀어 보는 편이 맞을 때. overflow-x: auto를 씁니다

넘침을 다룰 때 피할 것

  • 원인을 모른 채 hidden으로 가릴 때. 가로 스크롤은 대개 안쪽의 줄어들지 않는 요소 때문에 생깁니다
  • 말줄임만 쓰고 전체를 볼 방법을 주지 않을 때. 툴팁이나 상세 화면에서 전체 글을 볼 수 있게 합니다
  • scroll을 기본으로 쓸 때. 넘치지 않아도 스크롤바 자리가 남습니다
  • body에 overflow: hidden을 줄 때. 페이지 스크롤이 통째로 막힙니다

overflow 값 말고 다른 방법이 필요한 경우 — 글을 한 줄로 줄이고 싶다면 말줄임을 쓰고, 줄어들지 않는 칸 때문에 넘친다면 플렉스·그리드 자식에 min-width: 0을 줍니다. 스크롤하는 동안 요소를 한자리에 붙여 두려면 스티키를 씁니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙넘침을 다룰 때 지킬 것

말줄임은 세 줄을 함께 적어야 하고, 하나라도 빠지면 말줄임표가 나오지 않습니다.

/* 한 줄 말줄임. 세 줄을 함께 쓴다 */
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  min-width: 0;        /* 플렉스·그리드 자식이면 이것도 */
}

/* 여러 줄 말줄임 */
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

// 가로 스크롤 원인 찾기. 콘솔에 붙여 넣는다
[...document.querySelectorAll('*')].filter(el =>
  el.scrollWidth > document.documentElement.clientWidth);
지킬 규칙지키는 방법
말줄임은 세 속성을 함께 쓰기overflow + text-overflow + white-space를 함께 써야 하고, 하나만 써서는 말줄임이 되지 않습니다
min-width: 0 빠뜨리지 않기플렉스·그리드 자식은 이 줄이 없으면 말줄임이 걸리지 않습니다
hidden으로 가리기 전에 원인 찾기가로 스크롤은 대개 줄어들지 않는 칸 때문에 생깁니다. 원인을 그대로 둔 채 가리면 다른 곳에서 문제가 다시 생깁니다
잘린 글 전체를 볼 방법 마련하기title 속성이나 상세 화면으로 전체 글을 보여 줍니다. 잘린 채로 두면 사용자는 나머지 내용을 볼 수 없습니다
스크롤 상자에 높이 주기overflow: auto만으로는 스크롤이 생기지 않고, 높이나 최대 높이를 함께 줘야 합니다
hidden의 부작용 알아 두기안쪽 sticky가 그 상자를 기준으로 붙게 되고, 상자 밖으로 나간 배지·그림자가 잘립니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

자료는 그대로 보내고 화면에서 자르기서버가 글을 미리 잘라 보내면 툴팁에도 전체 글을 보여 줄 수 없습니다. 그래서 전체를 보내고 화면에서 줄이는 편이 낫고, 서버에서 자르는 것은 양이 아주 많을 때뿐입니다.
가장 긴 값으로 한 번 확인하기말줄임이 제대로 걸리는지는 실제로 긴 데이터를 넣어 봐야 알 수 있습니다. 개발 중에 쓰는 짧은 더미 데이터로는 문제가 드러나지 않습니다.
스크롤 상자 안에 무한 스크롤을 붙일 때상자 안에서 스크롤하면 window에는 스크롤 이벤트가 오지 않기 때문에, 무한 스크롤을 붙이려면 그 상자를 기준으로 잡아야 합니다.
가로 스크롤을 자동으로 검사하기scrollWidth > clientWidth 한 줄로 검사할 수 있습니다. 이 검사를 CI에 넣어 두면 사람이 일일이 보지 않아도 좁은 화면에서 레이아웃이 깨지는 것을 잡아냅니다.

넘친 내용을 처리하는 방법은 세 플랫폼 모두 있지만, 기본값이 서로 다릅니다.

기본값이 삐져나오기(visible)라서, 자르거나 스크롤하게 하려면 직접 적어야 합니다.

기본 동작이 자르기에 가깝습니다. .lineLimit(1) 한 줄로 말줄임이 되기 때문에 웹처럼 세 속성을 묶을 필요가 없습니다.
안드로이드Compose

maxLines와 overflow 두 값만 주면 말줄임이 됩니다. 스크롤이 필요하면 verticalScroll을 붙입니다.

플랫폼 차이 때문에 자주 생기는 문제 — 앱에서는 말줄임이 코드 한 줄이라서, 앱 개발자에게는 웹에서 세 속성을 맞춰야 하는 사정이 낯섭니다. 또 "일단 hidden으로 막았더니 다른 게 잘렸다"는 일은 웹에서만 생기는데, overflow 속성 하나가 자르기·스크롤·쌓임 맥락에 모두 영향을 주기 때문입니다.
