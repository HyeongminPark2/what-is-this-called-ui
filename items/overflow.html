Overflow

상자보다 내용이 클 때 무엇을 할지 고르는 것. 안 고르면 기본값(삐져나오기)이 고른 셈이 됩니다.

2 이름부르는 말이 여러 개다

한국어넘침, 오버플로, 말줄임
영어overflow, clipping, scroll container, text-overflow
같이 쓰는 말스크롤이 생긴 상자를 스크롤 컨테이너(scroll container), 잘라 내는 것을 클리핑(clipping), 끝을 …으로 줄이는 것을 말줄임(ellipsis · truncation)이라 합니다. 가로만 따로 정하려면 overflow-x, 세로만은 overflow-y입니다.
자주 잘못 부름hidden과 말줄임 — hidden은 그냥 자릅니다. …이 나오려면 text-overflow: ellipsis와 white-space: nowrap이 같이 있어야 합니다.
auto와 scroll — auto 는 넘칠 때만, scroll 은 늘 스크롤바 자리를 잡습니다.
'가로 스크롤이 생겼다' — overflow 설정 문제가 아니라 안에 안 줄어드는 것이 있다는 뜻입니다.

3 가르는 기준형제들과 비교하는 네 축

뼈대를 다루는 것들은 '눈에 안 보이는데 자리를 정한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나방향넘치면누가 값을 정하나
박스 모델상자 한 개의 크기해당 없음밖으로 삐져나온다내가

가운데 맞추기자식의 자리두 방향해당 없음나

4 갈래네 값이 다 다르게 동작한다

5 해부도부분 이름이 제일 안 알려진 지식

상자보다 글이 길어지면 무엇을 할지는 고르는 것이지 저절로 정해지지 않습니다. 네 가지 중 하나를 골라야 합니다.
overflow: visible — 기본값. 삐져나온다
overflow: hidden — 잘린다. 읽을 방법이 없다
overflow: auto — 넘칠 때만 스크롤
text-overflow: ellipsis — 한 줄을 … 으로
min-width: 0 — 가로 스크롤의 진짜 원인
  1. 스크롤 컨테이너 scroll containeroverflow가 visible 이 아닌 상자. 여기서부터 안쪽이 따로 굴러간다
  2. visible overflow: visible기본값. 자르지도 굴리지도 않는다 — 부모가 대신 가릴 수는 있다
  3. hidden overflow: hidden자른다. 쉬워 보이지만 읽을 방법을 없애는 선택이다
  4. auto overflow: auto넘칠 때만 스크롤. 길이를 모를 때의 기본 선택
  5. 말줄임 text-overflow: ellipsis혼자서는 안 된다. overflow·white-space 와 세 개가 한 세트
  6. 안 줄어드는 칸 min-width: 0가로 스크롤의 진짜 원인. overflow 를 고쳐도 안 낫는다

overflow를 visible 이 아닌 값으로 바꾸면 다른 일들도 같이 바뀝니다. 그 안의 position: sticky가 그 상자 기준으로 바뀌고(그래서 '스티키가 안 먹어요'), 밖으로 나간 그림자·배지·드롭다운이 잘립니다. 그래서 "일단 hidden 으로 막자"가 다른 자리에서 새 버그로 돌아오는 일이 잦습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 길이를 모르는 내용을 담을 때 — auto
  • 목록의 제목처럼 한 줄로 맞춰야 할 때 — 말줄임 세 줄
  • 칩 줄·탭 줄처럼 옆으로 미는 것이 맞는 때 — overflow-x: auto

이럴 때는 안 쓴다

  • 원인을 모른 채 hidden으로 덮는 것 — 가로 스크롤은 대개 안쪽에 범인이 있습니다
  • 말줄임만 쓰고 전체를 볼 방법을 안 주는 것 — 툴팁이나 상세로 이어 줍니다
  • scroll을 기본으로 쓰는 것 — 안 넘쳐도 스크롤바 자리가 남습니다
  • body에 overflow: hidden — 스크롤이 통째로 막힙니다

대신 이걸 — 한 줄로 줄이려면 말줄임, 안 줄어드는 칸은 플렉스·그리드의 min-width: 0, 굴리면서 붙여 두려면 스티키.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 상자의 계약서

말줄임은 세 줄이 한 세트입니다. 하나라도 빠지면 아무 일도 안 일어납니다.

/* 한 줄 말줄임 — 세 줄이 한 세트 */
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  min-width: 0;        /* 플렉스·그리드 자식이면 이것도 */
}

/* 여러 줄 말줄임 */
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

// 범인 찾기 — 콘솔에 붙여 넣는다
[...document.querySelectorAll('*')].filter(el =>
  el.scrollWidth > document.documentElement.clientWidth);
규칙지켜야 하는 것
말줄임은 세 줄overflow + text-overflow + white-space. 하나만 써도 안 된다
min-width: 0을 잊지 않는다플렉스·그리드 자식이면 이 줄이 없을 때 말줄임이 영영 안 걸린다
hidden 전에 원인을 본다가로 스크롤은 대개 안 줄어드는 칸 때문이다. 덮으면 다른 데서 터진다
자른 글은 볼 길을 준다title 속성이나 상세 화면으로. 잘린 채 끝나면 정보가 사라진다
스크롤 상자에는 높이가 있어야overflow: auto만으로는 안 굴러간다. 높이나 최대 높이가 필요하다
hidden은 부작용이 있다안쪽 sticky가 그 상자 기준이 되고, 밖으로 나간 배지·그림자가 잘린다

9 서버 쪽으로 치면백엔드 감각으로 번역

자르기는 화면에서, 자료는 그대로서버가 미리 잘라 보내면 툴팁에도 전체가 없습니다. 전체를 보내고 화면에서 줄이는 편이 낫습니다 — 양이 아주 많을 때만 서버에서 자릅니다.
가장 긴 값으로 한 번말줄임이 걸리는지는 실제로 긴 데이터로만 알 수 있습니다. 개발 중의 짧은 더미 데이터로는 평생 안 드러납니다.
스크롤 상자와 무한 스크롤상자 안에서 굴리면 window의 스크롤 이벤트가 안 옵니다. 무한 스크롤을 붙이려면 그 상자를 기준으로 잡아야 합니다.
가로 스크롤 자동 검사scrollWidth > clientWidth 한 줄이면 됩니다. CI 에 넣어 두면 좁은 화면이 깨지는 것을 사람이 안 봐도 잡힙니다.
