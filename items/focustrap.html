포커스 트랩

Focus trap

포커스 트랩은 모달이 열려 있는 동안 키보드 포커스가 모달 안에서만 움직이게 하는 동작입니다. 포커스를 가두지 않으면 가림막에 가려 보이지 않는 배경 버튼으로 포커스가 넘어갑니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

모달을 열고 Tab을 여러 번 눌러 보세요. 기록에 '모달 밖'이 찍히면 포커스가 모달 밖으로 빠져나간 것입니다.
가두지 않고 열기를 켜면 모달이 show()로 열리기 때문에 포커스가 모달 밖으로 빠져나갑니다. 반면 showModal()로 열면 브라우저가 포커스를 알아서 가두므로, 이제는 포커스 트랩을 직접 만들 일이 거의 없습니다.
모달을 닫을 때 모달을 연 버튼으로 포커스가 돌아가는 것도 기록에 찍힙니다.

2 이름같은 것을 부르는 여러 이름

한국어포커스 트랩, 포커스 가두기
영어focus trap, focus containment, inert
같이 쓰는 말모달 밖의 요소를 한꺼번에 포커스도 클릭도 받지 않게 만드는 속성은 inert이고, 브라우저가 모달을 그리는 맨 위 층은 최상위 레이어(top layer)라고 부릅니다. 모달을 닫은 뒤 포커스를 원래 자리로 돌려주는 것은 포커스 복원(focus restoration)이라고 합니다.
자주 잘못 부르는 이름모달 — 모달은 부품이고, 포커스 트랩은 모달이 해야 하는 동작 가운데 하나입니다.
스크롤 잠금 — 배경이 스크롤되지 않게 막는 것은 포커스 트랩과 다른 문제이고, 모달에는 둘 다 필요합니다.
aria-modal — 이름은 비슷하지만 이 속성은 포커스를 가두지 않습니다. 지금 모달이 열려 있다고 스크린 리더에게 알리는 표시입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

접근성은 눈으로는 보이지 않는 부분까지 챙기는 일입니다. 아래 네 가지를 물어보면 이 부의 항목들이 서로 어떻게 다른지 가를 수 있습니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람직접 들어 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다
대체 텍스트그림의 뜻안 보인다눈으로 안 보는 사람이미지를 끄고 읽어 본다
확대와 글자 크기키웠을 때도 쓰이나안 보인다저시력 사용자200%로 키워 본다

포커스 트랩을 한 줄로 정리하면 — 포커스 트랩은 세 가지 규칙을 함께 지켜야 합니다. 모달을 열 때 포커스를 모달 안으로 옮기고, 열려 있는 동안에는 모달 안에서만 돌게 하고, 닫을 때는 모달을 연 버튼으로 돌려줍니다.

4 상태열고 돌고 닫는 세 순간

5 해부도부분마다 붙은 이름

배경 버튼
정산을 확정할까요? 취소 확정
showModal( ) — 브라우저가 가둔다
열 때 안으로 — 첫 요소에 focus( )
닫을 때 — 부른 버튼으로 돌려준다
Esc 로 닫힌다
show( ) · 직접 만든 모달 — 밖으로 샌다
  1. 모달과 배경 dialog + backdrop가림막 뒤의 배경은 보이지도 눌리지도 않아야 합니다
  2. 가두기 showModal()브라우저가 알아서 포커스를 가두고 배경을 inert 상태로 만듭니다
  3. 열 때 focus()포커스를 모달 안의 첫 요소로 보냅니다. 보내지 않으면 포커스가 body에 남습니다
  4. 닫을 때 복원포커스를 모달을 연 버튼으로 돌려줍니다. 돌려주지 않으면 포커스가 화면 맨 위로 가 버립니다
  5. Esc cancel모달을 닫을 방법이 반드시 있어야 합니다. <dialog>는 따로 코드를 쓰지 않아도 Esc로 닫힙니다
  6. 직접 만든 모달 div + position:fixed포커스가 모달 밖으로 빠져나가는 일은 대부분 직접 만든 모달에서 생깁니다. 가능하면 직접 만들지 않습니다

<dialog>를 showModal()로 열면 포커스 가두기, 배경 끄기, Esc로 닫기, 최상위 레이어를 브라우저가 모두 처리합니다. 모달을 직접 만들면 이 네 가지를 모두 코드로 짜야 하는데, 그중에서도 배경을 inert로 만드는 일을 빠뜨리기 쉽습니다. 배경을 끄지 않으면 가림막에 가려 보이지 않는 배경 버튼을 스크린 리더는 계속 읽습니다. 이 도감의 모달 항목에서도 같은 내용을 다룹니다.

6 쓸 때 / 안 쓸 때

포커스 트랩을 쓰는 경우

  • 모달 다이얼로그처럼 뒤의 화면을 막는 부품을 띄울 때
  • 바텀시트나 드로어가 뒤의 화면을 막을 때
  • 전체 화면을 덮는 메뉴를 띄울 때

포커스 트랩을 쓰지 않는 경우

  • 뒤의 화면을 막지 않는 부품을 띄울 때. 팝오버, 툴팁, 토스트에서는 포커스를 가두지 않습니다
  • 포커스를 가두기만 하고 Esc로 닫을 수 없게 만들 때. 빠져나갈 방법이 없으면 가두지 않은 것보다 더 나쁩니다
  • 모달을 닫은 뒤 포커스를 돌려주지 않을 때
  • 모달을 직접 만들면서 inert를 빠뜨릴 때

포커스 트랩 대신 다른 것을 써야 하는 경우 — 뒤를 안 막으면 팝오버·다이얼로그, 부품 자체는 모달, 테두리는 포커스.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

포커스를 직접 가두지 말고 브라우저에 맡깁니다. 그러면 직접 적을 코드는 포커스를 옮기는 두 줄뿐입니다.

<dialog id="dlg" aria-labelledby="t">
  <h2 id="t">정산을 확정할까요?</h2>
  <button id="cancel">취소</button>
  <button id="ok">확정</button>
</dialog>

// 열 때는 가두기를 브라우저에 맡기고, 포커스 이동만 직접 한다
dlg.showModal();
cancel.focus();

// 닫을 때는 모달을 연 버튼으로 포커스를 돌려준다
dlg.addEventListener('close', () => openBtn.focus());

/* 직접 만든다면 배경을 꺼야 한다 */
<div id="app" inert>…</div>
키와 동작그때 일어나야 하는 일
Tab포커스가 모달 안에서만 돕니다. 마지막 요소 다음에는 첫 번째 요소로 갑니다
Shift+Tab거꾸로 돕니다. 첫 번째 요소 앞에서는 마지막 요소로 갑니다
Esc모달이 반드시 닫혀야 합니다. <dialog>는 기본으로 닫힙니다
열 때모달 안의 첫 요소에 .focus()를 호출합니다. 제목에 tabindex="-1"을 주고 제목으로 포커스를 보내기도 합니다
닫을 때포커스를 모달을 연 버튼으로 돌려줍니다. 그 버튼이 사라졌다면 가장 가까운 요소로 보냅니다
inert모달을 직접 만들 때는 배경에 inert를 걸어야 배경이 스크린 리더에도 읽히지 않습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

모달을 라우팅으로 열 때주소가 바뀌면서 모달이 열린다면 뒤로가기를 눌렀을 때 모달이 닫히는지까지 정해야 합니다. 모달이 닫힌 뒤 포커스를 어디로 돌려줄지도 함께 정합니다.
모달 안에서 화면이 바뀌면모달 안에서 다음 단계로 넘어가면 이전 단계의 요소와 함께 포커스가 사라지므로, 포커스를 새 단계의 제목으로 옮겨 줘야 합니다.
여러 겹의 모달모달 위에 모달을 열면 포커스 가두기가 겹칩니다. <dialog>는 최상위 레이어에 차례로 쌓이므로 브라우저가 알아서 처리하지만, 모달을 직접 만들었다면 겹친 순서를 직접 관리해야 합니다.
자동 검사모달을 열고 Tab을 20번 눌러 보면서 모달 밖 요소에 포커스가 가는지 확인하면 됩니다. 이 검사는 CI에서도 돌릴 수 있습니다.
