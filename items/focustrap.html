포커스 트랩

Focus trap

모달이 열린 동안 키보드를 그 안에만 두는 것. 안 가두면 보이지도 않는 배경 버튼에 포커스가 가 있게 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

모달을 열고 Tab을 여러 번 눌러 보세요. 기록에 '모달 밖'이 찍히면 그게 사고입니다.
가두지 않고 열기를 켜면 show()로 열려 포커스가 샙니다. showModal()로 열면 브라우저가 알아서 가둡니다 — 직접 만들 일이 거의 없어졌습니다.
닫을 때 부른 버튼으로 포커스가 돌아가는 것도 기록에 찍힙니다.

2 이름부르는 말이 여러 개다

한국어포커스 트랩, 포커스 가두기
영어focus trap, focus containment, inert
같이 쓰는 말모달 밖을 통째로 끄는 속성이 inert이고, 브라우저가 모달을 그리는 맨 위 층을 최상위 레이어(top layer)라 합니다. 닫은 뒤 포커스를 돌려주는 것을 포커스 복원(focus restoration)이라 합니다.
자주 잘못 부름모달 — 모달은 부품이고 포커스 트랩은 그 안의 동작입니다.
스크롤 잠금 — 배경 스크롤을 막는 것은 다른 문제입니다. 둘 다 필요합니다.
aria-modal — 이름이 비슷하지만 가두지 않습니다. 스크린 리더에게 알리는 표시일 뿐입니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다

한 줄로 — 포커스 트랩은 세 가지가 한 세트입니다 — 열 때 안으로, 도는 동안 안에서, 닫을 때 부른 버튼으로.

4 상태열고 돌고 닫는 세 순간

5 해부도부분 이름이 제일 안 알려진 지식

배경 버튼
정산을 확정할까요? 취소 확정
showModal( ) — 브라우저가 가둔다
열 때 안으로 — 첫 요소에 focus( )
닫을 때 — 부른 버튼으로 돌려준다
Esc 로 닫힌다
show( ) · 직접 만든 모달 — 밖으로 샌다
  1. 모달과 배경 dialog + backdrop가림막 뒤의 배경은 보이지도 눌리지도 않아야 한다
  2. 가두기 showModal()브라우저가 알아서 가두고 배경을 inert 로 만든다
  3. 열 때 focus()모달 안 첫 요소로 보낸다. 안 보내면 포커스가 body 에 남는다
  4. 닫을 때 복원부른 버튼으로 돌려준다. 안 돌려주면 화면 맨 위로 튕긴다
  5. Esc cancel닫을 길이 반드시 있어야 한다. <dialog>는 공짜로 해 준다
  6. 직접 만든 모달 div + position:fixed여기서 전부 새는 일이 생긴다. 가능하면 안 만든다

<dialog>를 showModal()로 열면 가두기·배경 끄기·Esc·최상위 레이어가 전부 따라옵니다. 직접 만들면 그 넷을 다 짜야 하고, 특히 배경을 inert로 만드는 것을 빠뜨리기 쉽습니다 — 그러면 눈에 안 보이는 배경 버튼이 스크린 리더에는 계속 읽힙니다. 이 도감의 모달 항목과 같은 이야기입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 모달 다이얼로그 — 뒤를 막는 모든 것
  • 바텀시트·드로어가 뒤를 막을 때
  • 전체 화면을 덮는 메뉴

이럴 때는 안 쓴다

  • 뒤를 안 막는 것에 거는 것 — 팝오버·툴팁·토스트는 가두지 않습니다
  • 가두기만 하고 Esc 를 안 주는 것 — 못 나가면 더 나쁩니다
  • 닫은 뒤 포커스를 안 돌려주는 것
  • 직접 만들면서 inert를 빠뜨리는 것

대신 이걸 — 뒤를 안 막으면 팝오버·다이얼로그, 부품 자체는 모달, 테두리는 포커스.

8 최소 마크업과 키보드이 동작의 계약서

직접 가두지 말고 브라우저에 맡깁니다. 적을 것은 포커스를 옮기는 두 줄뿐입니다.

<dialog id="dlg" aria-labelledby="t">
  <h2 id="t">정산을 확정할까요?</h2>
  <button id="cancel">취소</button>
  <button id="ok">확정</button>
</dialog>

// 열 때 — 가두기는 브라우저가, 포커스만 내가
dlg.showModal();
cancel.focus();

// 닫을 때 — 부른 버튼으로 돌려준다
dlg.addEventListener('close', () => openBtn.focus());

/* 직접 만든다면 배경을 꺼야 한다 */

9 서버 쪽으로 치면백엔드 감각으로 번역

모달을 라우팅으로 열 때주소가 바뀌며 열리면 뒤로가기로 닫히는지까지 정해야 합니다. 닫힌 뒤 포커스를 어디로 돌려줄지도 같이 정합니다.
모달 안에서 화면이 바뀌면단계가 넘어가면 포커스가 사라집니다. 새 단계의 제목으로 옮겨 줘야 합니다.
여러 겹의 모달모달 위에 모달을 열면 가두기가 겹칩니다. <dialog>는 최상위 레이어에 쌓여 알아서 되지만, 직접 만들면 직접 관리해야 합니다.
자동 검사모달을 열고 Tab을 20번 눌러 모달 밖 요소에 포커스가 가는지 보면 됩니다. CI 에서 돌릴 수 있습니다.
