포커스

Focus · focus indicator

키보드가 지금 가리키는 곳. 마우스를 못 쓰는 사람에게는 이것이 곧 커서입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

Tab을 눌러 보세요. 어디에 포커스가 갔는지, 테두리가 보이는지를 기록합니다.
테두리를 아예 없애기로 바꾸면 포커스는 움직이는데 화면에서는 아무것도 안 보입니다 — outline: none 한 줄이 하는 일입니다.
맨 앞의 건너뛰기 링크는 평소엔 숨어 있다가 첫 Tab 에만 나타납니다.

2 이름부르는 말이 여러 개다

한국어포커스, 초점, 포커스 링, 포커스 표시
영어focus, focus ring, focus indicator, focus order
같이 쓰는 말포커스를 둘러싼 테두리를 포커스 링(focus ring · indicator), Tab 으로 도는 순서를 포커스 순서(focus order · tab order)라 합니다. 맨 앞의 숨은 링크는 건너뛰기 링크(skip link), 포커스를 받을 수 있는 요소는 포커서블(focusable)입니다.
자주 잘못 부름호버 — 호버는 마우스를 올린 것, 포커스는 키보드가 가리키는 것입니다. 같은 모양으로 만들면 어느 쪽인지 알 수 없습니다.
선택 — 글을 드래그한 것은 selection 입니다.
:focus와 :focus-visible — 앞은 마우스로 눌러도 걸리고, 뒤는 키보드로 왔을 때만입니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다

한 줄로 — 포커스 테두리는 지워도 되는 장식이 아닙니다. 지우면 키보드만 쓰는 사람에게 화면이 통째로 안 보이게 됩니다.

5 해부도부분 이름이 제일 안 알려진 지식

저장하기
:focus-visible — 키보드로 왔을 때만
outline-offset — 글자에 안 붙게 띄운다
outline: none — 지우면 키보드로 못 쓴다
tabindex="0" / "-1" — 순서에 넣기 / 빼기
본문으로 건너뛰기
  1. 포커스된 것 focused element키보드가 지금 가리키는 하나. 화면에 꼭 하나만 있다
  2. 테두리 조건 :focus-visible키보드로 왔을 때만 그린다. 마우스 클릭에는 안 그려 지저분해지지 않는다
  3. 띄우기 outline-offset글자에 바싹 붙으면 안 보인다. 2px 쯤 띄운다
  4. 지우기 outline: none이 한 줄이 가장 흔한 접근성 사고다
  5. 순서에 넣기·빼기 tabindex0은 순서에 넣고, -1은 빼되 코드로는 보낼 수 있게 한다
  6. 건너뛰기 링크 skip link평소엔 숨고 첫 Tab 에만 나타난다. 메뉴 서른 개를 건너뛴다

outline: none을 쓰고 싶어지는 이유는 대개 기본 테두리가 투박해서입니다. 답은 지우는 것이 아니라 갈아 끼우는 것입니다 — :focus-visible로 조건을 좁히고, 색과 두께를 브랜드에 맞추면 됩니다. 지운 채로 두면 '예뻐 보이는 대신 못 쓰는 화면'이 됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 누를 수 있는 모든 것 — 버튼, 링크, 입력칸, 탭
  • 키보드로 간 곳이 화면 밖이면 스크롤해서 보여 줍니다
  • 붙박이 머리말이 가릴 수 있으면 scroll-margin-top으로 띄웁니다
  • 긴 메뉴가 있으면 건너뛰기 링크를 맨 앞에

이럴 때는 안 쓴다

  • outline: none — 대신 갈아 끼웁니다
  • 호버와 똑같이 그리는 것 — 어느 쪽인지 알 수 없습니다
  • tabindex에 1 이상을 주는 것 — 순서가 뒤엉킵니다
  • 비활성에 포커스를 주는 것 — 왜 안 눌리는지 알 수 없습니다

대신 이걸 — 모달 안에 가두는 일은 포커스 트랩, 키로 눌리는지는 키보드 조작, 이름은 이름 붙이기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 키보드이 화면의 계약서

기본 테두리를 지우지 말고 갈아 끼웁니다. 조건은 :focus-visible로 좁힙니다.

/* 지우지 말고 갈아 끼운다 */
:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

/* 목록의 줄은 안쪽에 — 옆 줄을 덮지 않게 */
.row:focus-visible { outline-offset: -2px; }

/* 붙박이 머리말에 가리지 않게 */
:target, [tabindex] { scroll-margin-top: 72px; }

9 서버 쪽으로 치면백엔드 감각으로 번역

순서는 DOM 순서다order나 grid-area로 보이는 자리를 바꿔도 Tab 순서는 안 바뀝니다. 서버가 내려주는 순서를 그대로 그리는 쪽이 안전합니다.
화면이 바뀐 뒤목록을 다시 그리거나 라우팅으로 화면을 바꾸면 포커스가 body 로 떨어집니다. 새 화면의 제목으로 옮겨 줘야 '어디로 왔는지'가 전달됩니다.
지운 줄의 포커스항목을 지우면 그 자리의 포커스가 사라집니다. 다음 줄이나 목록 자체로 옮깁니다 — 칩에서 다룬 것과 같은 문제입니다.
자동 검사Playwright 로 Tab을 눌러 가며 document.activeElement를 기록하면 순서와 테두리를 CI 에서 확인할 수 있습니다.
