포커스

Focus · focus indicator

포커스는 키보드가 지금 가리키고 있는 요소입니다. 마우스를 쓰지 못하는 사람은 포커스 표시를 보고 화면의 어디에서 작업하고 있는지 알기 때문에, 포커스 표시가 마우스 커서 역할을 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

Tab을 눌러 보세요. 포커스가 어디로 갔는지, 그리고 테두리가 보이는지가 기록에 남습니다.
테두리를 아예 없애기로 바꾸면 포커스는 그대로 옮겨 가는데도 화면에는 아무 표시가 나타나지 않습니다. CSS에 outline: none 한 줄을 넣으면 이렇게 됩니다.
맨 앞의 건너뛰기 링크는 평소에는 숨어 있다가 처음 Tab을 눌렀을 때만 나타납니다.

2 이름같은 것을 부르는 여러 이름

한국어포커스, 초점, 포커스 링, 포커스 표시
영어focus, focus ring, focus indicator, focus order
같이 쓰는 말포커스를 받은 요소를 둘러싼 테두리는 포커스 링(focus ring · indicator), Tab을 누를 때 포커스가 옮겨 가는 순서는 포커스 순서(focus order · tab order)라고 부릅니다. 페이지 맨 앞에 숨겨 둔 링크는 건너뛰기 링크(skip link), 포커스를 받을 수 있는 요소는 포커서블(focusable) 요소라고 합니다.
자주 잘못 부르는 이름호버 — 호버는 마우스를 올려 둔 상태이고, 포커스는 키보드가 가리키는 상태입니다. 두 상태를 같은 모양으로 그리면 사용자는 지금 어느 쪽인지 알 수 없습니다.
선택 — 마우스로 글자를 끌어서 칠한 것은 포커스가 아니라 선택(selection)입니다.
:focus와 :focus-visible — :focus는 마우스로 눌렀을 때도 적용되고, :focus-visible은 키보드로 포커스가 왔을 때만 적용됩니다.

포커스를 한 줄로 정리하면 — 포커스 테두리는 키보드로 화면을 쓰는 사람에게 지금 어느 요소에 있는지 알려 주는 표시입니다. 이 테두리를 지우면 키보드만 쓰는 사람은 어느 요소를 누르게 될지 모르는 채로 화면을 다뤄야 합니다.

5 해부도부분마다 붙은 이름

저장하기
:focus-visible — 키보드로 왔을 때만 그림
outline-offset — 글자에 붙지 않게 띄움
outline: none — 지우면 키보드로 쓸 수 없음
tabindex="0" / "-1" — 순서에 넣기 / 순서에서 빼기
본문으로 건너뛰기
  1. 포커스된 것 focused element키보드가 지금 가리키는 요소입니다. 포커스된 요소는 화면에 한 번에 하나만 있습니다
  2. 테두리 조건 :focus-visible키보드로 포커스가 왔을 때만 테두리를 그립니다. 마우스로 클릭할 때는 그리지 않으므로 화면이 지저분해지지 않습니다
  3. 띄우기 outline-offset테두리가 요소 가장자리에 바싹 붙으면 잘 보이지 않기 때문에 2px쯤 띄웁니다
  4. 지우기 outline: none포커스 테두리를 지우는 이 한 줄이 가장 흔한 접근성 사고입니다
  5. 순서에 넣기·빼기 tabindex0은 요소를 포커스 순서에 넣고, -1은 순서에서 빼되 코드로는 포커스를 보낼 수 있게 합니다
  6. 건너뛰기 링크 skip link평소에는 숨어 있다가 처음 Tab을 누를 때 나타납니다. 이 링크를 누르면 메뉴가 서른 개라도 한 번에 건너뛰고 본문으로 갑니다

outline: none을 쓰고 싶어지는 이유는 대개 브라우저의 기본 테두리가 투박해 보여서입니다. 이럴 때는 테두리를 지우지 말고 다른 테두리로 바꿔 그리면 됩니다. :focus-visible로 키보드 포커스일 때만 그리도록 조건을 좁히고, 색과 두께를 브랜드에 맞추는 방식입니다. 테두리를 지운 채로 두면 화면은 깔끔해 보여도 키보드로는 쓸 수 없게 됩니다.

6 쓸 때 / 안 쓸 때

포커스를 챙겨야 하는 경우

  • 버튼, 링크, 입력칸, 탭처럼 누를 수 있는 모든 요소에 포커스 테두리를 그릴 때
  • 키보드로 옮겨 간 요소가 화면 밖에 있어서 스크롤해 보여 줘야 할 때
  • 화면 위에 고정된 머리말이 포커스된 요소를 가릴 수 있을 때. scroll-margin-top으로 그만큼 띄웁니다
  • 본문 앞에 긴 메뉴가 있을 때. 페이지 맨 앞에 건너뛰기 링크를 둡니다

포커스를 다룰 때 하지 말아야 할 것

  • outline: none으로 테두리를 지울 때. 지우지 말고 다른 테두리로 바꿔 그립니다
  • 포커스를 호버와 똑같이 그릴 때. 사용자가 둘 중 어느 쪽인지 알 수 없습니다
  • tabindex에 1 이상의 값을 줄 때. 화면에 보이는 순서와 포커스 순서가 어긋납니다
  • 비활성 요소에 포커스를 줄 때. 사용자는 그 요소가 왜 눌리지 않는지 알 수 없습니다

포커스와 이어지는 주제는 다른 항목에서 다룹니다 — 모달 안에 포커스를 가두는 방법은 포커스 트랩에서, 요소를 키보드로 누를 수 있는지는 키보드 조작에서 다룹니다. 요소에 붙이는 이름은 이름 붙이기를 보세요.

8 최소 코드와 키보드구현할 때 지킬 최소 규칙

브라우저의 기본 테두리는 지우지 말고 원하는 모양으로 바꿔 그립니다. 그리고 :focus-visible로 키보드 포커스일 때만 그리도록 조건을 좁힙니다.

/* 지우지 말고 바꿔 그린다 */
:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

/* 목록의 줄은 안쪽에 그려서 옆 줄을 덮지 않게 한다 */
.row:focus-visible { outline-offset: -2px; }

/* 붙박이 머리말에 가리지 않게 */
:target, [tabindex] { scroll-margin-top: 72px; }

Shift+Tab이전 요소로 돌아갑니다

tabindex="0"원래 포커스를 받지 못하던 요소를 포커스 순서에 넣습니다. 1 이상의 값은 쓰지 않습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

Tab 순서는 DOM 순서를 따름Tab 순서는 DOM 순서를 따르기 때문에 order나 grid-area로 보이는 자리를 바꿔도 Tab 순서는 바뀌지 않습니다. 그래서 서버가 내려주는 순서대로 DOM을 그리는 쪽이 안전합니다.
화면이 바뀐 뒤 포커스 옮기기목록을 다시 그리거나 라우팅으로 화면을 바꾸면 포커스가 body로 돌아갑니다. 이때 포커스를 새 화면의 제목으로 옮겨 줘야 사용자가 어느 화면으로 왔는지 알 수 있습니다.
포커스가 있던 줄을 지웠을 때포커스가 있던 항목을 지우면 포커스도 함께 사라지므로, 포커스를 다음 줄이나 목록 자체로 옮깁니다. 칩에서 다룬 것과 같은 문제입니다.
포커스 순서 자동 검사Playwright로 Tab을 눌러 가며 document.activeElement를 기록하면 포커스 순서와 테두리를 CI에서 확인할 수 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 웹에서 "포커스"는 보통 키보드 포커스 하나를 뜻하지만, 앱에서는 스크린 리더 커서와 키보드 포커스가 따로 움직입니다. 그래서 "포커스를 여기로 옮겨 주세요"라는 요청을 받으면 둘 중 어느 쪽을 말하는지 확인해야 합니다.
