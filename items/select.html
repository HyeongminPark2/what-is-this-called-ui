셀렉트

Select · Dropdown

셀렉트는 정해진 선택지 가운데 하나를 고르는 칸입니다. 평소에는 접혀 있어 자리를 적게 차지하고, 펼쳐야 선택지가 보입니다.

2 이름같은 것을 부르는 여러 이름

한국어셀렉트, 선택 상자, 드롭다운
영어select, dropdown, picker
같이 쓰는 말선택지 묶음은 옵션 그룹(optgroup), 펼쳐진 목록은 리스트박스, 오른쪽의 화살표는 셰브런이라고 부릅니다.
자주 잘못 부르는 이름드롭다운 메뉴 — 메뉴는 이름 바꾸기나 삭제 같은 동작을 고르고, 셀렉트는 값을 고릅니다. 생김새가 닮아서 특히 자주 섞어 부릅니다.
콤보박스 — 글자를 입력해 선택지를 걸러 낼 수 있으면 셀렉트가 아니라 콤보박스입니다.
스피너 — 안드로이드에서는 셀렉트를 Spinner라고 부르는데, 웹에서 스피너라고 하는 로딩 표시와는 전혀 다른 부품입니다.

펼친 목록은 브라우저나 운영체제가 그립니다. 그래서 폰에서는 휠이나 전체 화면 목록이 뜹니다. 모양을 꾸미려고 목록을 직접 만들면 첫 글자로 건너뛰기, 폰의 큰 목록, 화면 밖으로 나가지 않게 잡아 주는 위치 계산까지 모두 새로 구현해야 합니다.

6 쓸 때 / 안 쓸 때

셀렉트를 쓰는 경우

  • 선택지가 5~15개쯤일 때
  • 은행, 국가, 통화처럼 선택지가 잘 바뀌지 않고 이름이 분명할 때
  • 폼이 길고 칸이 많아서 자리를 아껴야 할 때

셀렉트를 쓰지 않는 경우

  • 선택지가 2~4개일 때. 라디오나 세그먼티드 컨트롤을 쓰면 펼치지 않아도 선택지가 다 보입니다
  • 선택지가 수십 개를 넘을 때. 글자를 입력해 좁혀 갈 수 있는 콤보박스를 씁니다
  • 값이 아니라 동작을 고를 때. 이때는 드롭다운 메뉴를 씁니다
  • 모양을 바꾸려고 직접 만들 때. 키보드 조작과 폰 목록을 모두 다시 만들어야 합니다

셀렉트 대신 다른 것을 써야 하는 경우 — 둘셋이면 라디오나 세그먼티드, 많으면 콤보박스, 여럿 고르면 체크박스.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

브라우저가 제공하는 <select>를 쓰면 키보드 조작과 폰 목록이 따로 구현하지 않아도 동작합니다. 반면 셀렉트를 직접 만들면 이 기능을 모두 다시 만들어야 합니다.

<label for="bank">입금 은행</label>
<select id="bank" name="bank" required>
  <option value="">고르세요</option>
  <optgroup label="시중은행">
    <option>신한</option>
    <option>하나</option>
  </optgroup>
</select>

/* 모양은 테두리까지만 바꾼다. 펼친 목록은 못 바꾼다 */
select { appearance: none; background-image: url(chevron.svg); }

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

값과 라벨은 다른 것value에는 SHINHAN 같은 코드를 넣고, 화면에 보이는 글자는 사람이 읽는 이름으로 둡니다. 보이는 글자를 그대로 서버에 보내면 은행 이름이 바뀔 때 기존 데이터와 맞지 않게 됩니다.
빈 값 = 안 고름value=""인 첫 옵션으로 '아직 고르지 않음'을 나타냅니다. 기본값을 임의로 넣어 두면 사용자가 확인하지 않고 보낸 값이 저장됩니다.
선택지 출처선택지를 코드에 하드코딩하면 선택지가 바뀔 때마다 다시 배포해야 합니다. 서버에서 받아 오면 다시 배포할 필요는 없지만, 캐시를 관리하고 '저장된 값이 지금 목록에는 없는' 경우를 처리해야 합니다.
묶인 셀렉트 = 의존 질의앞 칸의 값이 정해져야 뒤 칸의 선택지를 가져올 수 있습니다. 앞 칸을 바꾸면 뒤 칸의 값을 비워야 하는데, 비우지 않으면 서로 맞지 않는 값 한 쌍이 저장됩니다.
