토스트 · 스낵바

Toast · Snackbar

화면 구석에 잠깐 떴다가 저절로 사라지는 알림. 하던 일을 막지 않고, 못 읽어도 큰일이 나지 않아야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

여러 개를 빠르게 지워 보세요. 토스트는 쌓입니다(스택). 마우스를 올리면 타이머가 멈추고, 되돌리기를 누르면 지운 항목이 제자리로 돌아옵니다 — 되돌리기가 되면 "정말 지울까요?" 확인 모달은 없어도 됩니다.

지금 보는 기기에는 호버가 없습니다. 타이머를 멈출 방법이 없으니, 손으로 쓰는 화면에서는 토스트를 더 오래 띄우거나 되돌리기를 다른 자리에도 남겨 둬야 합니다.

2 이름부르는 말이 여러 개다

한국어토스트, 토스트 메시지, 스낵바
영어toast, snackbar
같이 쓰는 말액션(되돌리기)이 붙은 것을 스낵바, 글만 있는 것을 토스트로 가르기도 합니다. Material 기준이고 웹에서는 섞어 씁니다.
자주 잘못 부름팝업 — 뒤를 막지 않고 저절로 사라지니 팝업과는 전혀 다른 것입니다.
알림 — 운영체제가 띄우는 푸시 알림(notification)과 헷갈립니다. 토스트는 앱 화면 안에만 있습니다.
얼럿 — 얼럿은 답을 받으려고 막는 것이고, 토스트는 알려만 줍니다.

3 가르는 기준형제들과 비교하는 네 축

겹쳐 뜨는 부품들은 모양으로는 구별이 안 됩니다. 이 네 가지만 물어보면 갈립니다.

한 줄로 — 토스트인지 아닌지는 저절로 사라지느냐로 정해집니다. 사용자가 닫지 않아도 없어지므로, 못 읽어도 되는 말만 담을 수 있습니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

먼저 띄운 토스트
✓ “회고 문서 초안 쓰기”를 지웠습니다
되돌리기 ×
  1. 스택 stack · container토스트가 쌓이는 자리. 여기에 aria-live를 걸어 둔다
  2. 토스트 몸통 toast · snackbar한 건. 보통 화면 폭의 절반을 넘기지 않는다
  3. 메시지 message한 줄. 무엇이 끝났는지만 적는다. 앞의 아이콘은 상태 아이콘 — 색만으로 알리지 않으려고 모양을 같이 쓴다
  4. 액션 action하나만. 되돌리기가 가장 흔하다
  5. 닫기 dismiss저절로 사라지더라도 먼저 치울 수 있게 둔다
  6. 타이머 바 timer · progress얼마나 남았는지 보여 준다. 올려 두면 멈춘다

여기 안 보이는 것이 하나 더 있습니다 — 라이브 리전(aria-live). 눈에는 안 보이지만 스크린 리더에게 "지금 이 글이 새로 생겼다"를 알려 주는 표시입니다. 12부 접근성에서 따로 다룹니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 이미 끝난 일을 알릴 때 — 저장했습니다, 보냈습니다, 지웠습니다
  • 되돌릴 수 있는 일 — 되돌리기를 붙이면 확인 모달이 필요 없어집니다
  • 못 읽고 지나가도 괜찮은 짧은 소식

이럴 때는 안 쓴다

  • 사용자가 꼭 읽어야 하는 에러 → 인라인 얼럿이나 배너
  • 답을 받아야 할 때 → 모달. 토스트에는 선택지를 넣지 않습니다
  • 긴 글, 링크 여러 개 — 읽기 전에 사라집니다
  • 중요한 정보를 토스트에만 담기 — 사라지면 다시 볼 방법이 없습니다

대신 이걸 — 꼭 읽어야 하면 인라인 얼럿·배너, 답을 받아야 하면 모달, 누른 것 옆에 붙어야 하면 팝오버. (링크 없는 것은 아직 안 쓴 항목)

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

토스트는 포커스를 뺏지 않습니다. 하던 입력이 끊기기 때문입니다. 대신 스크린 리더에게는 라이브 리전으로 알립니다.

<!-- 토스트가 쌓이는 자리. 페이지에 하나만 둔다 -->
<div id="toasts" role="status" aria-live="polite"></div>

// 한 건을 넣는다. 포커스는 건드리지 않는다
toasts.append(el);

// 올려 두면 타이머를 멈춘다 — 읽을 시간을 주는 최소한의 배려
el.addEventListener('mouseenter', pause);
el.addEventListener('focusin', pause);

// 되돌리기는 '아직 지우지 않은' 상태여야 한다 (아래 ⑨칸)
undoBtn.addEventListener('click', () => cancelPendingDelete(id));
키일어나야 하는 일
Tab토스트로 곧바로 끌려가지 않는다. 포커스를 뺏으면 하던 입력이 끊긴다
Esc포커스가 토스트 안에 있을 때 닫는다
마우스 올림타이머가 멈춘다. 치우면 남은 시간부터 다시 간다
스크린 리더aria-live="polite" — 읽던 말을 끊지 않고 뒤에 읽는다. assertive는 끊으니 에러에만
표시 시간글자 수에 맞춰 늘린다. 액션이 붙으면 최소 5초, 짧은 글도 4초 아래로 내리지 않는다

9 서버 쪽으로 치면백엔드 감각으로 번역

토스트 = fire-and-forget보내고 잊는 이벤트입니다. 받았는지 확인하지 않습니다. 그래서 꼭 전달돼야 하는 것은 담으면 안 됩니다.
되돌리기 = 지연 커밋'지웠습니다'라고 말하고 실제 삭제는 5초 미룹니다. soft delete + 보류 큐. 되돌리기를 누르면 큐에서 빼고, 안 누르면 그때 커밋합니다.
쌓임 = 큐짧은 시간에 여러 건이 들어오면 포개집니다. 상한(보통 3)과 밀어내기 정책이 필요합니다. 로그 레이트 리밋과 같은 문제입니다.
at-most-once토스트는 '최대 한 번' 전달입니다. 못 읽어도 다시 오지 않습니다. 반드시 읽혀야 하면 화면에 남는 통로(배너·목록)를 따로 둡니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

이 부품은 이름이 플랫폼마다 가장 많이 엇갈립니다. 특히 안드로이드에서는 '토스트'가 다른 것을 뜻합니다.
