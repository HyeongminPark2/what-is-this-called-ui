토스트 · 스낵바

Toast · Snackbar

토스트는 화면 구석에 잠깐 떴다가 저절로 사라지는 알림입니다. 사용자가 하던 일을 막지 않는 대신 금방 사라지기 때문에, 사용자가 못 읽고 지나가도 문제가 없는 내용만 담아야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

항목 여러 개를 빠르게 지워 보세요. 지울 때마다 토스트가 하나씩 떠서 위로 쌓입니다(스택). 토스트에 마우스를 올리면 타이머가 멈추고, 되돌리기를 누르면 지운 항목이 원래 자리로 돌아옵니다. 이렇게 되돌릴 수 있으면 지우기 전에 "정말 지울까요?"라고 묻는 확인 모달을 띄우지 않아도 됩니다.

지금 보는 기기는 호버를 지원하지 않습니다. 마우스를 올려 타이머를 멈출 수 없으므로, 터치 화면에서는 토스트를 더 오래 띄우거나 되돌리기 버튼을 토스트 밖의 다른 자리에도 남겨 둬야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어토스트, 토스트 메시지, 스낵바
영어toast, snackbar
같이 쓰는 말되돌리기 같은 액션이 붙은 것을 스낵바, 글만 있는 것을 토스트로 나눠 부르기도 합니다. 이 구분은 Material 기준이고, 웹에서는 두 이름을 섞어 씁니다.
자주 잘못 부르는 이름팝업 — 토스트는 뒤 화면을 막지 않고 저절로 사라지기 때문에 팝업과는 전혀 다른 부품입니다.
알림 — 이렇게 부르면 운영체제가 띄우는 푸시 알림(notification)과 헷갈립니다. 토스트는 앱 화면 안에서만 뜹니다.
얼럿 — 얼럿은 사용자의 답을 받으려고 화면을 막는 것이고, 토스트는 알리기만 합니다.

5 해부도부분마다 붙은 이름

먼저 띄운 토스트
✓ “회고 문서 초안 쓰기”를 지웠습니다
되돌리기 ×
  1. 스택 stack · container토스트가 쌓이는 자리입니다. 여기에 aria-live를 걸어 둡니다
  2. 토스트 몸통 toast · snackbar알림 한 건을 담는 상자입니다. 보통 화면 폭의 절반을 넘기지 않습니다
  3. 메시지 message무엇이 끝났는지만 한 줄로 적습니다. 앞의 아이콘은 상태 아이콘인데, 색만으로 상태를 알리지 않으려고 모양을 함께 씁니다
  4. 액션 action하나만 둡니다. 되돌리기를 가장 많이 씁니다
  5. 닫기 dismiss토스트가 저절로 사라지더라도 사용자가 먼저 치울 수 있게 둡니다
  6. 타이머 바 timer · progress사라지기까지 얼마나 남았는지 보여 주고, 마우스를 올려 두면 멈춥니다

그림에는 보이지 않는 부분이 하나 더 있는데, 라이브 리전(aria-live)입니다. 화면에는 나타나지 않지만 스크린 리더에게 글이 새로 생겼다는 사실을 알려 주는 표시입니다. 12부 접근성에서 따로 다룹니다.

6 쓸 때 / 안 쓸 때

토스트 · 스낵바를 쓰는 경우

  • '저장했습니다', '보냈습니다', '지웠습니다'처럼 이미 끝난 일을 알릴 때
  • 되돌릴 수 있는 일을 알릴 때. 되돌리기를 붙이면 확인 모달을 띄우지 않아도 됩니다
  • 못 읽고 지나가도 괜찮은 짧은 소식을 전할 때

토스트 · 스낵바를 쓰지 않는 경우

  • 사용자가 꼭 읽어야 하는 에러를 알릴 때. 인라인 얼럿이나 배너를 씁니다
  • 사용자의 답을 받아야 할 때. 토스트에는 선택지를 넣지 않고 모달을 씁니다
  • 긴 글이나 링크 여러 개를 담을 때. 다 읽기 전에 사라집니다
  • 중요한 정보를 토스트에만 담을 때. 토스트가 사라지면 다시 볼 방법이 없습니다

토스트 · 스낵바 대신 다른 것을 써야 하는 경우 — 꼭 읽어야 하면 인라인 얼럿·배너, 답을 받아야 하면 모달, 누른 것 옆에 붙어야 하면 팝오버. (링크 없는 것은 아직 안 쓴 항목)

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

토스트는 포커스를 가져가지 않습니다. 포커스가 옮겨 가면 사용자가 하던 입력이 끊기기 때문입니다. 그 대신 스크린 리더에게는 라이브 리전으로 새 토스트를 알립니다.

<!-- 토스트가 쌓이는 자리는 페이지에 하나만 둔다 -->
<div id="toasts" role="status" aria-live="polite"></div>

// 한 건을 넣되 포커스는 건드리지 않는다
toasts.append(el);

// 마우스를 올리거나 포커스가 들어오면 타이머를 멈춰 읽을 시간을 준다
el.addEventListener('mouseenter', pause);
el.addEventListener('focusin', pause);

// 되돌리기를 누를 때는 아직 실제로 지우지 않은 상태여야 한다 (아래 ⑨칸)
undoBtn.addEventListener('click', () => cancelPendingDelete(id));
키와 동작그때 일어나야 하는 일
Tab토스트가 떠도 포커스가 토스트로 곧바로 옮겨 가지 않습니다. 포커스를 가져가면 하던 입력이 끊기기 때문입니다
Esc포커스가 토스트 안에 있을 때 토스트를 닫습니다
마우스 올림타이머가 멈추고, 마우스를 치우면 남은 시간부터 다시 줄어듭니다
스크린 리더aria-live="polite"로 두면 읽던 말을 끊지 않고 이어서 읽습니다. assertive는 읽던 말을 끊기 때문에 에러에만 씁니다
표시 시간글자 수가 많을수록 길게 띄웁니다. 액션이 붙으면 최소 5초, 짧은 글도 4초 아래로는 내리지 않습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

토스트 = fire-and-forget토스트는 보내고 나면 잊는 이벤트처럼 사용자가 받았는지 확인하지 않습니다. 그래서 꼭 전달돼야 하는 내용은 토스트에 담으면 안 됩니다.
되돌리기 = 지연 커밋화면에는 '지웠습니다'라고 띄우지만 실제 삭제는 5초 미룹니다. soft delete와 보류 큐를 함께 쓰는 방식으로, 되돌리기를 누르면 큐에서 빼고 누르지 않으면 5초 뒤에 커밋합니다.
쌓임 = 큐짧은 시간에 여러 건이 들어오면 토스트가 포개지기 때문에 상한(보통 3개)과 오래된 것을 밀어내는 정책이 필요합니다. 로그에 레이트 리밋을 거는 것과 같은 문제입니다.
at-most-once토스트는 '최대 한 번' 전달하는 방식이라서 사용자가 못 읽어도 다시 띄우지 않습니다. 반드시 읽혀야 하는 내용이라면 배너나 목록처럼 화면에 남는 통로를 따로 둡니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

토스트는 플랫폼마다 부르는 이름이 특히 많이 엇갈리는 부품입니다. 안드로이드에서는 '토스트'가 아예 다른 것을 가리킵니다.

플랫폼 차이 때문에 자주 생기는 문제 — 안드로이드에는 Toast라는 다른 API가 따로 있는데, 액션을 붙일 수 없고 포커스도 받지 못하는 더 단순한 시스템 알림입니다. 그래서 안드로이드 개발자에게 "토스트에 되돌리기 붙여 주세요"라고 하면 "그건 스낵바"라는 답이 돌아옵니다.
