컴포넌트와 인스턴스

Component & instance

컴포넌트는 원본 하나이고, 인스턴스는 그 원본에서 만든 복제본입니다. 원본을 고치면 연결된 복제본이 모두 같이 바뀐다는 점이 핵심입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

맨 왼쪽이 마스터(원본), 나머지가 인스턴스(복제본)입니다. 마스터의 글자나 모서리를 바꿔 보면 인스턴스가 모두 같이 바뀝니다.
인스턴스에서 떼어내기를 누르면 그 하나만 마스터와의 연결이 끊기기 때문에, 그 뒤에 마스터를 고치면 떼어낸 것만 옛 모습으로 남습니다.

2 이름같은 것을 부르는 여러 이름

한국어컴포넌트, 마스터, 인스턴스, 복제본, 떼어내기
영어component, main component, instance, override, detach
같이 쓰는 말원본을 마스터 컴포넌트 또는 메인 컴포넌트라고 하고, 복제본을 인스턴스라고 합니다. 인스턴스에서 글자나 아이콘만 바꾸는 것을 오버라이드(덮어쓰기), 마스터와의 연결을 끊는 것을 디태치(떼어내기)라고 부릅니다. 여러 마스터를 모아 하나로 만든 것은 컴포넌트 세트이고, 그 안의 칸들이 배리언트입니다.
자주 잘못 부르는 이름컴포넌트 — 개발 쪽의 리액트 컴포넌트와 개념은 같지만 같은 물건은 아닙니다. 시안의 컴포넌트는 코드가 아니라 그림입니다.
심볼 — 다른 도구에서 쓰던 옛 이름이고, 뜻은 컴포넌트와 같습니다.
복사·붙여넣기 — 그냥 복사해 붙인 것은 마스터와 연결이 없으므로 인스턴스가 아닙니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

15부에서 다루는 현장 용어는 화면 부품의 이름 대신 디자인과 개발이 함께 일하는 단계를 가리킵니다. 아래 네 가지를 물어보면 이 용어들을 서로 구별할 수 있습니다.

무엇을 가리키나언제 나오나개발 쪽 대응물잘못 알아들으면
와이어프레임과 목업과 시안얼마나 진짜 같은 그림인가기획 ~ 디자인마크업 구조 ~ 완성 화면엉뚱한 리뷰가 돌아온다
디자인 시스템규칙 + 부품 + 문서프로젝트 내내토큰 + 컴포넌트 라이브러리스타일 가이드와 섞인다
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀐다
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞인다
오토 레이아웃자동 배치시안 작업flexbox‘여백이 자동’을 못 알아듣는다
프로토타입눌리는 시안리뷰 · 사용자 시험아직 코드가 아니다다 된 줄 안다
핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받는다
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배만 받아 뭉갠다
디자인 리뷰고칠 거리를 만드는 말단계마다코드 리뷰너무 이르거나 너무 늦다
버전 관리어느 것이 지금 것인가프로젝트 내내커밋 메시지final 사슬이 생긴다

컴포넌트와 인스턴스를 한 줄로 정리하면 — 떼어낸 인스턴스는 떼어냈다는 표시가 남지 않습니다. 그래서 급할 때 떼어낸 하나가 몇 달 뒤 마스터를 고쳤을 때 혼자 옛 모습으로 남아 있게 됩니다.

4 연결 상태마스터를 따라오나

5 해부도부분마다 붙은 이름

마스터 — 원본 하나. 여기만 고친다
인스턴스 — 복제본. 마스터를 따라간다
덮어쓰기 — 글자·아이콘만 바꾼다. 연결은 남는다
떼어내기(디태치) — 연결이 끊긴다. 되돌리기 어렵다
코드로는 컴포넌트 정의와 사용
떼어낸 것은 눈으로 찾아야 한다
  1. 마스터 원본 하나고칠 때는 마스터만 고칩니다. 마스터 자체는 화면에 쓰지 않기도 합니다
  2. 인스턴스 복제본마스터가 바뀌면 같이 바뀝니다
  3. 덮어쓰기 글자 · 아이콘글자나 아이콘만 바꾸고 연결은 남겨 둡니다. 인스턴스를 고칠 때는 이렇게 쓰는 것이 정상입니다
  4. 떼어내기 연결 끊기급할 때 쓰지만, 떼어냈다는 표시가 남지 않습니다
  5. 코드로는 정의와 사용function Button()이 마스터, <Button />이 인스턴스에 해당합니다
  6. 찾기 눈으로떼어낸 인스턴스를 목록으로 뽑기 어렵습니다

인스턴스를 떼어내고 싶어진다면 대개 마스터에 필요한 자리가 없는 것입니다. '이 버튼에만 아이콘을 넣고 싶은데 마스터에 아이콘 자리가 없다' 같은 때에 떼어내게 되는데, 그럴 때 필요한 일은 떼어내기가 아니라 마스터에 아이콘 자리를 추가하는 것입니다. 코드에서도 마찬가지로, 컴포넌트를 복사해 조금 고친 버전을 만드는 것보다 props를 하나 추가하는 쪽이 거의 늘 낫습니다. 이런 판단을 모아 마스터에 변형을 미리 정해 두는 것이 배리언트 설계입니다.

6 쓸 때 / 안 쓸 때

컴포넌트와 인스턴스를 쓰는 경우

  • 같은 모양이 여러 번 나올 때
  • 나중에 한꺼번에 고칠 일이 있을 때
  • 덮어쓰기로 되는 범위까지만 바꿀 때

컴포넌트와 인스턴스를 쓰지 않는 경우

  • 급하다고 떼어낼 때. 떼어냈다는 표시가 남지 않습니다
  • 복사·붙여넣기로 개수를 늘릴 때. 복사본은 마스터와 연결이 없습니다
  • 한 번만 쓰는 것을 컴포넌트로 만들 때. 쓰는 곳에 비해 일이 과합니다
  • 마스터를 화면 안에 그대로 쓸 때. 화면을 고치다가 마스터까지 실수로 고치게 됩니다

컴포넌트와 인스턴스 대신 다른 것을 써야 하는 경우 — 변형이 여럿이면 배리언트, 값이 흩어지면 디자인 시스템의 토큰, 배치는 오토 레이아웃.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 코드와 맞춰 보기시안과 코드의 짝

시안의 마스터와 인스턴스는 코드에서 컴포넌트를 정의하는 곳과 쓰는 곳에 해당합니다.

// 마스터 = 컴포넌트 정의 — 한 곳에만 있다
function Button({ label, tone = 'primary', size = 'md' }) {
  return <button className={`btn btn--${tone} btn--${size}`}>{label}</button>;
}

// 인스턴스 = 쓰는 곳 — 덮어쓰기는 props 로
<Button label="내보내기" />
<Button label="삭제" tone="danger" />

// ✕ 떼어내기에 해당하는 코드 — 복사해서 조금 고친 것
function ButtonWithIcon({ label }) {     // 마스터와 멀어진다
  return <button className="btn btn--primary">◆ {label}</button>;
}
키와 동작그때 일어나야 하는 일
마스터는 한 곳에화면 안에 두면 화면을 고치다 마스터까지 고치기 쉬우므로 따로 모아 둡니다
덮어쓰기는 props글자와 아이콘, 상태는 props로 바꿉니다. 모양 자체를 바꾸려면 마스터를 고칩니다
접근성도 마스터에role·aria-*·키보드 동작을 마스터에 넣어 두면 인스턴스를 쓰는 쪽은 따로 손대지 않아도 접근성을 갖추게 됩니다
떼어내면 그것도 끊긴다떼어낸 때의 접근성 속성이 그대로 남아서, 마스터에서 고친 접근성이 반영되지 않습니다
이름을 쓰임으로Button/Primary보다 Button/주동작처럼 언제 쓰는지가 드러나게 짓습니다
찾기코드에서는 검색으로 쓰인 곳을 모두 찾을 수 있지만, 시안에서는 찾기 어렵습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

부품 묶음에 버전마스터를 고치면 그 부품을 쓰는 화면이 모두 바뀌므로, 배포할 때 무엇이 바뀌는지 적어 함께 내보냅니다.
쓰인 곳 세기코드에서는 부품이 쓰인 곳을 검색으로 셀 수 있으니, 세어 보고 쓰이지 않는 부품은 지웁니다.
복사된 부품 찾기btn-primary-2처럼 비슷한 클래스 이름을 찾아보면 부품을 복사해 고친 곳, 곧 시안의 떼어낸 자리에 해당하는 곳이 드러납니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 부르는 이름은 다르지만 원본 하나를 정의해 여러 곳에서 쓰는 개념은 같습니다.

웹컴포넌트
저장정의 / 사용
function Button()으로 정의하고 <Button />으로 씁니다. 시안의 마스터, 인스턴스와 그대로 짝이 맞습니다.
iOSSwiftUI View
struct PrimaryButton: View
View 하나가 컴포넌트 하나이고, 쓰는 쪽에서는 값만 넘깁니다.
안드로이드Composable
@Composable fun PrimaryButton()
@Composable 함수가 컴포넌트 역할을 합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 시안에서 떼어낸 부품과 코드에서 복사해 고친 컴포넌트는 같은 문제를 일으킵니다. 둘 다 그때는 가장 빨리 끝나는 방법이지만, 몇 달 뒤 원본을 고칠 때 그것만 바뀌지 않고 남습니다. "이거 떼어낸 건가요"와 "이거 복사한 건가요"는 같은 질문이고, 둘 다 원본에 자리를 하나 더 만들어 두면 하지 않아도 되는 일입니다.
