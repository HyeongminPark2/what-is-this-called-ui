플렉스

Flexbox · flex layout

플렉스는 자식 요소들을 한 줄(또는 한 열)에 늘어놓는 방법입니다. 화면에서 요소를 가로로 늘어놓는 배치는 대부분 플렉스로 만듭니다.

방향을 column으로 바꿔 보세요. justify-content와 align-items가 맡는 방향이 서로 뒤바뀝니다. 두 속성은 가로·세로가 아니라 주축·교차축을 기준으로 하기 때문입니다.
flex: 1을 켜면 가운데 칸이 남은 자리를 모두 차지합니다. 여기에 긴 글까지 켜 보세요. min-width: 0이 없으면 가운데 칸이 글 길이만큼 넓어지면서 '뒤' 칸을 밀어내는데, 이때 아래 코드에 min-width: 0 줄이 함께 붙습니다.

2 이름같은 것을 부르는 여러 이름

한국어플렉스, 플렉스박스, 플렉스 레이아웃
영어flexbox, flex layout, flex container / flex item
같이 쓰는 말자식을 늘어놓는 방향은 주축(main axis), 주축을 가로지르는 방향은 교차축(cross axis)이라고 부릅니다. display: flex를 준 부모는 플렉스 컨테이너, 그 자식은 플렉스 아이템입니다. flex는 grow·shrink·basis 세 값을 한 번에 적는 단축 속성이고, 자리가 모자랄 때 다음 줄로 넘기는 것은 랩(wrap)이라고 합니다.
자주 잘못 부르는 이름그리드 — 플렉스는 한 방향으로 늘어놓고, 그리드는 두 방향으로 칸을 나눕니다. 플렉스도 줄을 넘길 수는 있지만, 줄을 넘기는 것과 판을 짜는 것은 다릅니다.
가로 정렬 — justify-content는 방향에 따라 세로 정렬이 되기도 하므로, 주축 정렬이라고 불러야 헷갈리지 않습니다.
flex: 1 — '너비 100%'가 아니라 남은 자리를 한 몫 나눠 받으라는 뜻입니다.

4 갈래같은 속성도 방향에 따라 다르게 적용된다

5 해부도부분마다 붙은 이름

앞 가운데 뒤
flex-direction: row ←→
justify-content ←→ (주축)
align-items ↑↓ (교차축)
flex: 1 — 남은 자리를 먹는다
min-width: 0 — 이게 없으면 안 줄어든다
  1. 플렉스 컨테이너 flex containerdisplay: flex를 준 부모입니다. 그 자식들은 자동으로 플렉스 아이템이 됩니다
  2. 주축 main axis자식을 늘어놓는 방향이며, flex-direction으로 정합니다
  3. 주축 정렬 justify-content주축에서 자식을 어느 쪽으로 모을지 정합니다. 방향을 바꾸면 세로 정렬이 됩니다
  4. 교차축 정렬 align-items주축을 가로지르는 방향의 정렬입니다. 기본값이 stretch라서 자식 높이가 저절로 같아집니다
  5. 늘어나기 flex: 1남은 자리를 한 몫씩 나눠 받습니다. '앞·가운데·뒤' 짜임에서 가운데 칸을 늘리는 데 씁니다
  6. 줄어들기 min-width: 0플렉스 자식의 최소 너비는 기본값이 내용만큼이라서, 이 줄이 없으면 내용보다 좁게 줄어들지 않습니다

min-width: 0은 이 도감에서 가장 자주 나오는 코드 한 줄입니다. 플렉스·그리드 자식의 자동 최소 크기는 '내용만큼'이라서, 긴 글이 들어오면 칸이 내용보다 좁아지지 않고 옆 칸을 밀어냅니다. 말줄임이 걸리지 않거나, 가로 스크롤이 생기거나, 레이아웃이 판 밖으로 넘치는 문제는 대개 이 한 줄이 빠져서 생깁니다.

6 쓸 때 / 안 쓸 때

플렉스를 쓰는 경우

  • 상단 바, 리스트 아이템, 버튼 줄처럼 요소를 한 줄에 늘어놓을 때
  • '앞·가운데·뒤' 짜임에서 가운데 칸만 늘어나야 할 때
  • 개수가 정해지지 않은 것들을 나란히 둘 때
  • 한 줄 안에서 세로 가운데를 맞출 때. align-items: center 한 줄이면 됩니다

플렉스를 쓰지 않는 경우

  • 줄과 열이 서로 맞아야 할 때. 플렉스는 줄마다 따로 배치해서 위아래 줄의 칸을 맞추지 못하므로 그리드를 씁니다
  • 사이드바, 본문, 꼬리말로 판 전체를 짤 때. 그리드로 짜는 편이 구조가 더 분명합니다
  • 한 칸만 가운데 놓으면 될 때. 그리드의 place-items: center 한 줄이 더 짧습니다

플렉스 대신 다른 것을 써야 하는 경우 — 두 방향이면 그리드, 가운데만 놓으면 가운데 맞추기, 넘친 뒤 처리는 넘침.

8 최소 코드와 규칙플렉스를 쓸 때 지킬 것

플렉스는 대개 부모에 한 줄, 자식에 한 줄만 적으면 원하는 배치가 나옵니다.

.bar {
  display: flex;
  align-items: center;   /* 교차축(세로) 가운데 */
  gap: 12px;
}

.bar__title {
  flex: 1;          /* 남은 자리를 차지한다 */
  min-width: 0;     /* 이게 없으면 긴 글에 밀려 안 줄어든다 */
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* 빈 칸을 넣지 않고 이 한 줄로 오른쪽 끝에 붙인다 */
.bar__end { margin-left: auto; }
규칙지켜야 하는 것
gap을 쓴다자식에 마진을 주면 첫 칸과 끝 칸의 바깥 여백을 따로 처리해야 하지만, gap은 칸 사이에만 들어갑니다
min-width: 0줄어들어야 하는 칸에는 거의 항상 필요합니다. 이 도감에서 가장 자주 나오는 한 줄입니다
margin-left: auto한 칸만 오른쪽 끝으로 밀 때 씁니다. 자리를 채우려고 빈 <div>를 넣지 않습니다
flex-wrap을 생각한다기본값이 nowrap이라서 화면이 좁아지면 모든 칸이 찌그러집니다
순서를 바꾸지 않는다order나 row-reverse를 쓰면 보이는 순서와 탭 순서가 어긋납니다
align-items: stretch가 기본자식 높이가 저절로 같아지기 때문에, 아이콘이 세로로 늘어나 보이면 대개 이 기본값이 원인입니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

플렉스 = 남은 자리 나누기flex: 1은 남은 폭을 비율대로 나누라는 뜻입니다. 고정 칸의 폭을 먼저 빼고 나머지를 나눠 주기 때문에, 총량이 정해진 자원을 배분하는 계산과 같습니다.
내용 길이가 배치를 바꾼다이름이 길면 옆 칸이 밀려납니다. 그래서 가장 긴 값과 빈 값을 하나씩 넣고 화면을 그려 보는 것이 최소한의 테스트입니다.
개수가 바뀌는 경우서버가 버튼을 3개 보낼지 7개 보낼지 미리 알 수 없다면 flex-wrap: wrap을 켜 둡니다. 켜지 않으면 좁은 화면에서 버튼이 모두 찌그러집니다.
순서와 접근성order로 눈에 보이는 순서를 바꿔도 키보드 순서는 바뀌지 않습니다. 그래서 화면에서 순서를 바꾸기보다 서버가 내려 주는 순서를 그대로 쓰는 편이 안전합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 세 플랫폼의 방식이 같아서 "가운데만 늘어나게 해 주세요"라는 요청은 어디서나 그대로 통합니다. 다만 min-width: 0 문제는 웹에만 있어서, 앱 개발자는 "글이 길어도 안 줄어들어요"라는 증상을 낯설어합니다. 이때는 '칸이 내용보다 작아지지 못한다'고 풀어 말하는 편이 빨리 통합니다.
