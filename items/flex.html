Flexbox · flex layout

방향을 column으로 바꿔 보세요. justify-content와 align-items의 역할이 통째로 뒤집힙니다 — 둘은 가로·세로가 아니라 주축·교차축을 가리키기 때문입니다.
flex: 1을 켜면 가운데 칸이 남은 자리를 다 먹습니다. 거기에 긴 글까지 켜 보세요 — min-width: 0이 없으면 칸이 글에 밀려 '뒤'를 쫓아냅니다. 아래 코드에 그 줄이 같이 붙습니다.

2 이름부르는 말이 여러 개다

한국어플렉스, 플렉스박스, 플렉스 레이아웃
영어flexbox, flex layout, flex container / flex item
같이 쓰는 말늘어놓는 방향을 주축(main axis), 가로지르는 방향을 교차축(cross axis)이라 합니다. 부모가 플렉스 컨테이너, 자식이 플렉스 아이템입니다. flex는 grow·shrink·basis 세 값을 한 번에 적은 것이고, 줄을 넘기는 것은 랩(wrap)입니다.
자주 잘못 부름그리드 — 플렉스는 한 방향, 그리드는 두 방향입니다. 줄바꿈이 되는 것과 판을 짜는 것은 다릅니다.
가로 정렬 — justify-content는 방향에 따라 세로가 되기도 합니다. 주축이라고 불러야 안 헷갈립니다.
flex: 1 — '너비 100%'가 아니라 '남은 자리를 한 몫'입니다.

4 갈래같은 속성이 방향 따라 다르게 먹는다

5 해부도부분 이름이 제일 안 알려진 지식

앞 가운데 뒤
flex-direction: row ←→
justify-content ←→ (주축)
align-items ↑↓ (교차축)
flex: 1 — 남은 자리를 먹는다
min-width: 0 — 이게 없으면 안 줄어든다
  1. 플렉스 컨테이너 flex containerdisplay: flex를 준 부모. 자식들이 자동으로 아이템이 된다
  2. 주축 main axisflex-direction이 정한다. 늘어놓는 방향
  3. 주축 정렬 justify-content주축에서 어디로 모을지. 방향을 바꾸면 세로가 된다
  4. 교차축 정렬 align-items가로지르는 방향. 기본값 stretch라 자식 높이가 저절로 같아진다
  5. 늘어나기 flex: 1남은 자리를 한 몫씩. '앞·가운데·뒤' 짜임의 핵심
  6. 줄어들기 min-width: 0플렉스 자식의 최소 너비는 내용만큼이다. 이 줄이 없으면 영영 안 줄어든다

min-width: 0은 이 도감에서 가장 자주 나오는 한 줄입니다. 플렉스·그리드 자식의 자동 최소 크기가 '내용만큼'이라, 긴 글이 들어오면 칸이 줄어들기를 거부하고 옆 칸을 밀어냅니다. 말줄임이 안 걸리는 것도, 가로 스크롤이 생기는 것도, 판이 터지는 것도 대개 이 한 줄이 빠져서입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 한 줄에 늘어놓을 때 — 상단 바, 리스트 아이템, 버튼 줄
  • '앞·가운데·뒤' 짜임 — 가운데만 늘어나야 할 때
  • 개수가 정해지지 않은 것들을 나란히 둘 때
  • 세로 가운데 맞추기 — align-items: center 한 줄

이럴 때는 안 쓴다

  • 줄과 열이 서로 맞아야 할 때 → 그리드. 플렉스는 줄끼리 모릅니다
  • 판 전체의 짜임(사이드바 + 본문 + 꼬리말) → 그리드가 더 또렷합니다
  • 한 칸만 가운데 놓으면 될 때 — place-items: center 한 줄이 더 짧습니다

대신 이걸 — 두 방향이면 그리드, 가운데만 놓으면 가운데 맞추기, 넘친 뒤 처리는 넘침.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 부품의 계약서

플렉스는 부모에 한 줄, 자식에 한 줄이면 거의 끝납니다.

.bar {
  display: flex;
  align-items: center;   /* 교차축 — 세로 가운데 */
  gap: 12px;
}

.bar__title {
  flex: 1;          /* 남은 자리를 먹는다 */
  min-width: 0;     /* 이게 없으면 긴 글에 밀려 안 줄어든다 */
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* 오른쪽 끝으로 밀기 — 빈 칸 대신 이 한 줄 */
.bar__end { margin-left: auto; }
규칙지켜야 하는 것
gap을 쓴다자식에 마진을 주면 첫 칸·끝 칸을 따로 챙겨야 한다. gap 은 사이에만 들어간다
min-width: 0줄어들어야 하는 칸에는 거의 늘 필요하다. 이 도감에서 가장 자주 나오는 한 줄
margin-left: auto한 칸만 오른쪽 끝으로 밀 때. 빈 <div>를 넣지 않는다
flex-wrap을 생각한다기본값은 nowrap이라 좁아지면 다 찌그러진다
순서를 바꾸지 않는다order나 row-reverse는 보이는 순서와 탭 순서를 어긋나게 한다
align-items: stretch가 기본자식 높이가 저절로 같아진다. 아이콘이 늘어나 보이면 이것 때문이다

9 서버 쪽으로 치면백엔드 감각으로 번역

플렉스 = 남은 자리 나누기flex: 1은 '남은 폭을 비율대로 나눠라'입니다. 고정 칸을 먼저 빼고 나머지를 분배하는 것이라, 합이 정해진 자원 배분과 같은 계산입니다.
내용 길이가 배치를 바꾼다이름이 길면 칸이 밀립니다. 가장 긴 값과 빈 값 둘로 한 번씩 그려 보는 것이 최소 테스트입니다.
개수가 바뀌는 경우서버가 버튼을 3개 줄지 7개 줄지 모르면 flex-wrap: wrap을 켜 둡니다. 안 켜면 좁은 화면에서 전부 찌그러집니다.
순서와 접근성order로 눈에 보이는 순서를 바꿔도 키보드 순서는 안 바뀝니다. 서버가 내려주는 순서를 그대로 쓰는 편이 안전합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

세 플랫폼 모두 거의 같은 생각이고, 이름만 다릅니다.

HStack · VStack 이 플렉스와 같습니다. flex: 1 자리에 Spacer()나 .frame(maxWidth: .infinity)를 씁니다.
안드로이드Compose

Modifier.weight(1f)
Row · Column 이고, flex: 1 은 Modifier.weight(1f) 입니다. 개념이 거의 1대1로 옮겨집니다.

자주 생기는 사고 — 세 쪽이 생각은 같아서 "가운데만 늘어나게"가 그대로 통합니다. 다만 min-width: 0 문제는 웹에만 있습니다. 앱 개발자에게 "글이 길어도 안 줄어들어요"는 낯선 증상이니, '칸이 내용보다 작아지지 못한다'로 풀어 말하는 편이 빠릅니다.
