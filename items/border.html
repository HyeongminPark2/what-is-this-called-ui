테두리와 구분선

Border · divider

선은 칸을 가르는 가장 센 수단입니다. 그래서 적게 쓸수록 화면이 조용해집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

가르는 법 넷을 바꿔 보세요. 줄마다 테두리를 두르면 맞닿은 자리에서 선이 두 겹이 되어 2px 이음선이 생깁니다 — 데모가 두 테두리를 더해 잽니다.
줄은 width: 100% 입니다. box-sizing을 끄면 그 100%에 테두리가 더 붙어 2px 넘칩니다. 격자가 어긋나는 흔한 원인이라 넘친 줄에 빨간 테를 둘러 표시합니다.

2 이름부르는 말이 여러 개다

한국어테두리, 구분선, 선, 괘선
영어border, divider, separator, rule, hairline
같이 쓰는 말상자를 둘러싸는 선이 테두리, 둘 사이를 가르는 선이 구분선입니다. 아주 얇은 선은 헤어라인(hairline)이라 부릅니다. HTML 의 <hr>은 내용이 바뀐다는 뜻을 가진 태그라, 그냥 선을 긋고 싶을 때는 border-top이 맞습니다.
자주 잘못 부름아웃라인 — outline은 자리를 안 차지해 포커스 테에 씁니다. 꾸미는 선이 아닙니다.
그림자 — 고도는 높이를, 선은 경계를 말합니다.
모서리 — 모서리는 모양이고 이건 선입니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보인다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선하다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 안 읽히고 z-index 가 안 먹는다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 안 맞는다
상태 색성공 · 주의 · 오류 · 정보4가지 × 3자리알림 · 배지 · 입력 오류색을 못 보면 상태를 못 읽는다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 아무도 못 고친다

한 줄로 — 선을 긋기 전에 여백으로 되는지 보세요. 선은 여백으로 안 될 때만 씁니다.

4 가르는 법센 것부터 약한 것까지

5 해부도부분 이름이 제일 안 알려진 지식

--line: 테두리와 구분선의 한 가지 색
1px ← 거의 늘 이 굵기다
맞닿으면 1 + 1 = 2px 이음선
border-box ← 선이 폭 안에 들어간다
outline ← 자리를 안 차지한다
바탕색 차이 ← 선 없이 가르는 법
  1. 색 한 가지--line 하나면 거의 충분하다
  2. 굵기 1px2px 은 선택됨 같은 뜻이 된다
  3. 이음선 1 + 1 = 2px맞닿은 테두리는 두 겹이 된다
  4. border-box 폭 안에선을 켜도 치수가 안 변한다
  5. outline 자리 없음포커스 테 전용
  6. 바탕색 선 없이줄이 많을 때 가장 조용하다

선을 쓰는 순서가 있습니다 — 여백 → 바탕색 → 구분선 → 테두리 순으로 세집니다. 화면이 어수선하다는 말을 들으면 대개 한 단계 센 것을 쓰고 있습니다. 카드마다 테두리를 두르는 대신 바탕색만 바꿔도 구역은 충분히 나뉩니다.
색은 한 가지면 됩니다. 진한 선과 흐린 선을 섞으면 '왜 여기만 진하지'라는 질문이 생기고, 그 질문에 답이 없으면 실수입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 선 색을 --line 하나로 두기
  • 목록은 구분선, 떨어진 덩어리는 테두리
  • box-sizing: border-box를 전역으로 깔기

이럴 때는 안 쓴다

  • 맞닿은 줄마다 테두리 두르기 — 2px 이음선이 생긴다
  • 선 굵기를 2px 로 올리기 — 선택됨이라는 뜻이 생겨 버린다
  • <hr>로 그냥 선 긋기 — 내용이 바뀐다는 뜻이 읽힌다
  • outline을 꾸미는 데 쓰기 — 포커스 테와 헷갈린다

대신 이걸 — 모양은 모서리, 높이는 고도, 포커스 테는 초점, 선 대신 쓰는 여백은 간격 체계.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 선의 계약서

전역에 border-box를 깔고, 선은 색 하나로 통일합니다.

/* 이 한 줄이 치수 사고를 통째로 없앤다 */
*, *::before, *::after { box-sizing: border-box; }

:root { --line: #e4e6eb; }

/* 목록 — 구분선 하나. 첫 줄 위에는 안 붙는다 */
.row + .row { border-top: 1px solid var(--line); }

/* 떨어진 덩어리 — 테두리를 쓰되 서로 붙이지 않는다 */
.card { border: 1px solid var(--line); border-radius: var(--radius-3); }

/* ✕ 맞닿은 테두리 — 이음선이 2px 이 된다 */
.row { border: 1px solid var(--line); }
키일어나야 하는 일
* + *첫 줄 위에는 선이 안 붙는다 — 구분선의 기본 꼴
border-collapse표에서는 이 값으로 이음선을 한 겹으로 만든다
outline-offset포커스 테를 바깥으로 띄운다. 테두리와 겹치지 않게
0.5px레티나에서만 그려진다. 안 되는 기기에서는 0px 로 사라진다
border-box폭·높이에 선과 안쪽 여백이 포함된다
확인하는 법줄을 두 개 겹쳐 두고 이음선 자리를 확대해 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버와는 상관없다선은 전부 화면의 일입니다. 다만 줄 수에 따라 알맞은 가르기가 달라집니다.
줄이 많을 때수십 줄이 오면 테두리보다 줄무늬가 읽기 편합니다 — 어느 쪽이 올지 미리 물어보면 좋습니다.
빈 목록줄이 없으면 구분선만 남아 이상한 금이 보입니다. 빈 상태로 갈아 끼웁니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

얇은 선을 그리는 방식이 플랫폼마다 다릅니다.

웹1px solid
모란상회한빛아웃도어CSS px
CSS 픽셀 1px 입니다. 화면 밀도가 높으면 실제로는 2~3 화소로 그려집니다.
iOSseparator
구분선이 왼쪽에서 들여쓰여 시작합니다. 글머리와 선이 맞아 떨어져 보입니다.
안드로이드Divider
Material 3 은 선을 줄이는 쪽입니다. 목록에서는 아예 안 쓰고 여백으로 가르기를 권합니다.

자주 생기는 사고 — iOS 의 들여쓴 구분선은 웹에서도 그대로 쓸 만합니다 — 아이콘이나 아바타가 있는 목록에서 선을 글머리에 맞추면 줄이 한 덩어리로 읽힙니다. 반대로 안드로이드가 선을 줄이는 쪽으로 간 것도 참고할 만합니다. 선을 지우고 여백만 늘려 보면, 생각보다 많은 경우 선이 없어도 됩니다.
