테두리와 구분선

Border · divider

선은 칸을 가르는 방법 가운데 눈에 가장 강하게 띄는 방법입니다. 그래서 선을 적게 쓸수록 화면이 덜 어수선해집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

가르는 법 네 가지를 바꿔 보세요. 줄마다 테두리를 두르면 맞닿은 자리에서 선이 두 겹이 되어 2px 이음선이 생기는데, 데모는 맞닿은 두 테두리의 두께를 실제로 더해 보여 줍니다.
각 줄의 폭은 width: 100%입니다. box-sizing을 끄면 그 100%에 테두리 두께가 더해져 줄이 2px 넘칩니다. 격자가 어긋나는 흔한 원인이라서 넘친 줄에는 빨간 테를 둘러 표시합니다.

2 이름같은 것을 부르는 여러 이름

한국어테두리, 구분선, 선, 괘선
영어border, divider, separator, rule, hairline
같이 쓰는 말상자를 둘러싸는 선은 테두리, 두 요소 사이를 가르는 선은 구분선입니다. 아주 얇은 선은 헤어라인(hairline)이라고 부릅니다. HTML의 <hr>은 내용이 바뀐다는 뜻을 담은 태그라서, 모양으로만 선을 긋고 싶을 때는 border-top을 쓰는 것이 맞습니다.
자주 잘못 부르는 이름아웃라인 — outline은 자리를 차지하지 않기 때문에 포커스 테에 씁니다. 꾸미려고 긋는 선이 아닙니다.
그림자 — 그림자로 나타내는 고도는 높이를 보여 주고, 선은 경계를 보여 줍니다.
모서리 — 모서리는 상자의 모양이고, 테두리와 구분선은 선입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하는가몇 단으로 두면 좋은가값을 바꾸면 어디가 바뀌는가잘못 정했을 때 나타나는 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌, 고대비까지 두면 3벌화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지, 색마다 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

테두리와 구분선을 한 줄로 정리하면 — 선을 긋기 전에 여백만으로 나눌 수 있는지 먼저 보세요. 선은 여백만으로 구역이 나뉘지 않을 때만 씁니다.

4 칸을 가르는 방법눈에 강하게 띄는 것부터 약한 것까지

5 해부도부분마다 붙은 이름

--line: 테두리와 구분선의 한 가지 색
1px ← 거의 늘 이 굵기
맞닿으면 1 + 1 = 2px 이음선
border-box ← 선이 폭 안에 들어감
outline ← 자리를 차지하지 않음
바탕색 차이 ← 선 없이 가르는 방법
  1. 색 한 가지--line 하나면 거의 충분합니다
  2. 굵기 1px2px로 올리면 선택됨 같은 다른 뜻으로 읽힙니다
  3. 이음선 1 + 1 = 2px맞닿은 두 테두리가 두 겹으로 겹쳐 2px이 됩니다
  4. border-box 폭 안에테두리를 넣어도 치수가 변하지 않습니다
  5. outline 자리 없음포커스 테에만 씁니다
  6. 바탕색 선 없이줄이 많을 때 가장 깔끔해 보입니다

칸을 가르는 방법에는 순서가 있습니다. 여백, 바탕색, 구분선, 테두리 순으로 갈수록 눈에 강하게 띕니다. 화면이 어수선하다는 말을 들었다면 대개 필요한 것보다 한 단계 강한 방법을 쓰고 있는 것입니다. 예를 들어 카드마다 테두리를 두르는 대신 바탕색만 바꿔도 구역은 충분히 나뉩니다.
선 색은 한 가지면 됩니다. 진한 선과 흐린 선을 섞으면 보는 사람에게 '왜 여기만 진하지' 하는 의문이 생기는데, 그 차이에 정해 둔 이유가 없다면 실수로 들어간 것입니다.

6 쓸 때 / 안 쓸 때

테두리와 구분선을 쓸 때 지킬 것

  • 선 색을 --line 하나로 두기
  • 목록은 구분선으로, 떨어진 덩어리는 테두리로 나누기
  • box-sizing: border-box를 전역에 적용하기

테두리와 구분선을 쓸 때 피할 것

  • 맞닿은 줄마다 테두리 두르기. 맞닿은 자리에 2px 이음선이 생깁니다
  • 선 굵기를 2px로 올리기. 선택됨이라는 뜻으로 읽힐 수 있습니다
  • 모양만 내려고 <hr>로 선 긋기. 내용이 바뀐다는 뜻이 함께 전달됩니다
  • outline을 꾸미는 데 쓰기. 포커스 테와 헷갈립니다

함께 보면 좋은 항목 — 상자의 모양은 모서리 항목에서, 높이는 고도 항목에서 다룹니다. 포커스 테는 초점 항목에서, 선 대신 여백으로 나누는 방법은 간격 체계 항목에서 설명합니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 지킬 규칙선을 코드로 옮기는 방법

전역에 border-box를 적용하고, 선 색은 하나로 통일합니다.

/* 이 한 줄로 테두리 때문에 치수가 넘치는 문제를 막는다 */
*, *::before, *::after { box-sizing: border-box; }

:root { --line: #e4e6eb; }

/* 목록은 구분선 하나. 첫 줄 위에는 붙지 않는다 */
.row + .row { border-top: 1px solid var(--line); }

/* 떨어진 덩어리는 테두리를 쓰되 서로 붙이지 않는다 */
.card { border: 1px solid var(--line); border-radius: var(--radius-3); }

/* ✕ 맞닿은 테두리는 이음선이 2px이 된다 */
.row { border: 1px solid var(--line); }
값과 속성쓰면 일어나는 일
* + *첫 줄 위에는 선이 붙지 않습니다. 구분선을 넣는 기본 방식입니다
border-collapse표에서는 이 값으로 이음선을 한 겹으로 만듭니다
outline-offset포커스 테를 바깥으로 띄워 테두리와 겹치지 않게 합니다
0.5px레티나 화면에서만 그려지고, 지원하지 않는 기기에서는 0px로 처리되어 사라집니다
border-box폭과 높이에 테두리와 안쪽 여백이 포함됩니다
확인하는 방법줄 두 개를 맞붙여 두고 이음선 자리를 확대해 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버와 관계없는 화면 쪽 값선은 전부 화면 쪽에서 정합니다. 다만 데이터의 줄 수에 따라 알맞은 가르는 법이 달라집니다.
줄이 많을 때 가르는 방법수십 줄이 오면 테두리보다 줄무늬가 읽기 편합니다. 그래서 데이터가 몇 줄쯤 올지 미리 물어 두면 좋습니다.
목록이 비었을 때 남는 선줄이 하나도 없으면 구분선만 남아 이상한 금이 보입니다. 이때는 목록 대신 빈 상태 화면을 보여 줍니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

얇은 선을 그리는 방식이 플랫폼마다 다릅니다.

웹1px solid
모란상회한빛아웃도어CSS px
CSS 픽셀로 1px입니다. 화면 밀도가 높으면 실제로는 2~3 화소 두께로 그려집니다.
iOSseparator
구분선이 왼쪽에서 들여쓴 자리부터 시작해서, 줄의 글머리와 선의 시작점이 맞춰져 보입니다.
안드로이드Divider
Material 3는 선을 줄이는 쪽을 택했습니다. 목록에서는 선을 아예 쓰지 않고 여백으로 가르기를 권합니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS의 들여쓴 구분선은 웹에서도 그대로 쓸 만합니다. 아이콘이나 아바타가 있는 목록에서 선의 시작점을 글머리에 맞추면 줄 하나가 한 덩어리로 읽힙니다. 안드로이드가 선을 줄이는 쪽을 택한 것도 참고할 만합니다. 선을 지우고 여백만 늘려 보면, 생각보다 많은 경우에 선 없이도 구역이 나뉩니다.
