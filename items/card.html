카드

Card

한 대상에 딸린 것들을 테두리 하나로 묶은 상자. 묶는 것이 일이라서, 안에 누를 것이 여럿이면 바로 문제가 생깁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

'장바구니'를 눌러 보고, 그다음 카드의 빈 데를 눌러 보세요. 둘이 따로 동작합니다 — 카드 전체가 링크인데도 안의 버튼이 카드를 열지 않습니다(stopPropagation). 이걸 안 막으면 장바구니를 누를 때마다 상세 화면으로 끌려갑니다.
제목이 긴 상품 섞기를 켜면 카드 높이가 제각각이 됩니다. 데이터가 길이를 정하기 때문입니다.

2 이름부르는 말이 여러 개다

한국어카드, 카드 뷰, 상품 카드
영어card, tile, media object
같이 쓰는 말위의 사진 자리를 미디어(media · thumbnail), 글이 있는 부분을 본문(body · content), 맨 아래 버튼 줄을 액션 영역(actions · footer)이라 합니다. 카드를 격자로 깐 것을 카드 그리드, 가로로 미는 것을 캐러셀이라 합니다.
자주 잘못 부름타일 — 보통 같은 뜻이지만, 윈도우·대시보드 쪽에서는 정사각형에 가까운 칸을 가리킵니다.
패널 — 패널은 화면을 나눈 구역이고 카드는 한 건입니다. 패널 안에 카드가 여럿 들어갑니다.
모달 — 떠서 뒤를 막으면 모달입니다. 카드는 흐름 안에 놓입니다.

3 가르는 기준형제들과 비교하는 네 축

표시 부품은 '보여 주기만 한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다

배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+

스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)

접히는 글제목과 본문제목이 눌린다세로로 포갠다접어 둔다
태그한 낱말안 눌린다가로로 줄바꿈말줄임하거나 +N

한 줄로 — 카드는 하나로 셀 수 있는 것을 묶습니다. '이 안의 것이 다 같은 한 건인가'에 아니라고 답하면 카드가 아니라 구역입니다.

5 해부도부분 이름이 제일 안 알려진 지식

장바구니
  1. 카드 card · container테두리와 모서리와 그림자. 이 셋이 '한 덩어리'를 만든다
  2. 미디어 media · thumbnail사진 자리. 비율을 못 박아 둬야 사진마다 카드 높이가 달라지지 않는다
  3. 제목 title무엇인지. 카드 안에서 가장 진하고 큰 글
  4. 메타 meta · supporting text값·날짜·만든 이. 제목보다 작고 흐리게
  5. 보조 동작 actions카드 전체가 링크일 때 여기서 사고가 난다 — 눌림이 위로 번지지 않게 막는다

카드 전체를 누르게 만드는 방법은 두 가지인데 결과가 다릅니다. 카드 전체를 <a>로 감싸면 안의 버튼이 링크 안에 들어가 버려 HTML 이 어긋나고 눌림이 겹칩니다. 그래서 보통은 제목만 링크로 두고 그 링크를 투명하게 카드 전체로 늘립니다(::after { inset: 0 }). 이러면 스크린 리더에는 링크가 하나만 읽히고, 버튼은 그 위에 따로 올려 둘 수 있습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 한 대상에 딸린 것이 서너 가지라 한 줄에 안 들어갈 때
  • 사진이 고르는 데 도움이 될 때 — 상품, 숙소, 영상
  • 건마다 길이가 들쭉날쭉할 때 — 카드는 높이가 늘어나도 괜찮습니다

이럴 때는 안 쓴다

  • 세로로 훑어 비교해야 할 때 → 리스트 아이템이나 표가 낫습니다
  • 보여 줄 것이 제목 하나뿐일 때 — 테두리만 늘어납니다
  • 건수가 아주 많을 때 — 카드는 자리를 많이 먹어 한 화면에 몇 개 안 들어갑니다
  • 모든 것을 카드에 넣는 것 — 다 묶으면 아무것도 안 묶인 것과 같습니다

대신 이걸 — 줄 세워 비교하려면 리스트 아이템, 숫자 하나면 스탯 타일, 표로 다룰 양이면 데이터 테이블(10부).

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

카드 자체에는 정해진 역할(role)이 없습니다. 무엇으로 감싸느냐가 전부입니다 — 목록이면 <li>, 기사면 <article>.

<article class="card">
  <img src="…" alt="">          <!-- 장식이면 alt 를 비운다 -->
  <h3>
    <a href="/p/128" class="stretch">무선 이어폰 2세대</a>
  </h3>
  <p>모란상회 · ₩129,000</p>
  <button class="over">장바구니</button>
</article>

/* 링크 하나를 카드 전체로 늘린다 — 읽히는 링크는 그대로 하나 */
.card { position: relative; }
.stretch::after { content: ""; position: absolute; inset: 0; }
.over { position: relative; z-index: 1; } /* 버튼은 그 위로 */

9 서버 쪽으로 치면백엔드 감각으로 번역

카드 하나 = 응답 한 건목록 API 가 돌려주는 한 줄이 카드 하나입니다. 카드에 보이는 값은 전부 그 한 줄 안에 있어야 합니다 — 카드마다 따로 부르면 20장이면 요청이 20번입니다.
사진 비율올라오는 사진은 비율이 제각각입니다. 서버에서 미리 잘라 두거나 object-fit: cover로 맞춥니다. 안 맞추면 카드 높이가 흔들립니다.
글 길이제목 길이는 데이터가 정합니다. 가장 긴 값으로 한 번 그려 보지 않으면 운영에서 깨집니다. 길이를 서버에서 자를지 화면에서 자를지도 정해 둡니다.
카드 수한 화면에 카드 20장이면 사진도 20장입니다. 지연 로딩(loading="lazy")과 작은 썸네일이 첫 화면 속도를 좌우합니다.
