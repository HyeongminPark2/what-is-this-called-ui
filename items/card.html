카드

Card

카드는 한 대상에 딸린 사진, 제목, 값 같은 정보를 테두리 하나로 묶은 상자입니다. 여러 정보를 한 덩어리로 묶는 것이 카드의 역할이라서, 카드 전체를 누를 수 있게 만들었는데 안에 누를 것이 또 있으면 어느 쪽이 눌렸는지를 두고 문제가 생깁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

'장바구니'를 먼저 눌러 보고, 그다음 카드의 빈 곳을 눌러 보세요. 두 곳이 서로 따로 동작합니다. 카드 전체가 링크인데도 안쪽 버튼을 누를 때 카드가 열리지 않는 것은, 버튼의 눌림이 카드까지 전달되지 않게 막아 두었기 때문입니다(stopPropagation). 이렇게 막지 않으면 장바구니를 누를 때마다 상세 화면으로 넘어가 버립니다.
제목이 긴 상품 섞기를 켜면 카드마다 높이가 달라집니다. 카드 높이는 그 안에 든 데이터의 길이에 따라 정해지기 때문입니다.

2 이름같은 것을 부르는 여러 이름

한국어카드, 카드 뷰, 상품 카드
영어card, tile, media object
같이 쓰는 말카드 위쪽의 사진 자리는 미디어(media · thumbnail), 글이 들어가는 부분은 본문(body · content), 맨 아래 버튼 줄은 액션 영역(actions · footer)이라고 부릅니다. 카드를 격자로 늘어놓은 것은 카드 그리드, 가로로 밀어 넘기며 보게 만든 것은 캐러셀이라고 합니다.
자주 잘못 부르는 이름타일 — 보통은 카드와 같은 뜻으로 쓰지만, 윈도우나 대시보드에서는 정사각형에 가까운 칸을 가리킵니다.
패널 — 패널은 화면을 나눈 구역이고, 카드는 그 안에 놓이는 한 건입니다. 그래서 패널 하나 안에 카드가 여러 장 들어갑니다.
모달 — 화면 위에 떠서 뒤쪽 화면을 막으면 카드가 아니라 모달입니다. 카드는 다른 내용과 함께 페이지 흐름 안에 놓입니다.

카드를 한 줄로 정리하면 — 카드는 상품 하나, 글 하나처럼 하나로 셀 수 있는 것을 묶습니다. 상자 안에 든 것이 모두 같은 한 건에 딸린 것이 아니라면, 그 상자는 카드가 아니라 화면을 나눈 구역입니다.

4 상태상태마다 달라지는 카드 모습

5 해부도부분마다 붙은 이름

무선 이어폰 2세대
모란상회 · ₩129,000
장바구니
  1. 카드 card · container테두리와 둥근 모서리, 그림자로 이루어집니다. 이 세 가지 덕분에 안의 내용이 한 덩어리로 보입니다
  2. 미디어 media · thumbnail사진이 들어가는 자리입니다. 가로세로 비율을 고정해 두어야 사진마다 카드 높이가 달라지지 않습니다
  3. 제목 title카드가 무엇에 대한 것인지 알려 줍니다. 카드 안에서 가장 진하고 큰 글자로 씁니다
  4. 메타 meta · supporting text값, 날짜, 만든 사람 같은 정보입니다. 제목보다 작고 흐리게 씁니다
  5. 보조 동작 actions카드 전체가 링크이면 이 버튼을 누를 때 카드까지 같이 눌리는 문제가 생기므로, 버튼의 눌림이 카드로 전달되지 않게 막습니다

카드 전체를 누를 수 있게 만드는 방법은 두 가지이고, 결과가 서로 다릅니다. 카드 전체를 <a>로 감싸면 안의 버튼이 링크 안에 들어가게 되는데, 링크 안에 버튼을 넣는 것은 HTML 규칙에 어긋나고 두 곳의 눌림도 겹칩니다. 그래서 보통은 제목만 링크로 두고, 그 링크의 누르는 영역을 투명하게 카드 전체로 넓힙니다(::after { inset: 0 }). 이렇게 하면 스크린 리더에는 링크가 하나만 읽히고, 버튼은 넓힌 링크 영역 위에 따로 올려 둘 수 있습니다.

6 쓸 때 / 안 쓸 때

카드를 쓰는 경우

  • 한 대상에 딸린 정보가 서너 가지라서 한 줄에 다 들어가지 않을 때
  • 상품, 숙소, 영상처럼 사진이 고르는 데 도움이 될 때
  • 건마다 내용 길이가 들쭉날쭉할 때. 카드는 높이가 늘어나도 보기에 문제가 없습니다

카드를 쓰지 않는 경우

  • 여러 건을 세로로 훑으며 비교해야 할 때. 리스트 아이템이나 표가 더 낫습니다
  • 보여 줄 것이 제목 하나뿐일 때. 묶을 것이 없으니 테두리만 늘어납니다
  • 건수가 아주 많을 때. 카드는 자리를 많이 차지해서 한 화면에 몇 장밖에 들어가지 않습니다
  • 화면의 모든 것을 카드에 넣을 때. 모든 것을 카드로 묶으면 무엇끼리 묶였는지 구별되지 않습니다

카드 대신 다른 것을 써야 하는 경우 — 여러 건을 줄 세워 비교해야 하면 리스트 아이템을 쓰고, 보여 줄 것이 숫자 하나뿐이면 스탯 타일이 맞습니다. 표로 다뤄야 할 만큼 양이 많으면 데이터 테이블(10부)을 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

카드에는 따로 정해진 역할(role)이 없어서 어떤 태그로 감싸느냐로 의미가 정해집니다. 목록 안의 한 건이면 <li>, 기사처럼 혼자 완결된 글이면 <article>으로 감쌉니다.

<article class="card">
  <img src="…" alt="">          <!-- 장식용 사진이면 alt 를 비운다 -->
  <h3>
    <a href="/p/128" class="stretch">무선 이어폰 2세대</a>
  </h3>
  <p>모란상회 · ₩129,000</p>
  <button class="over">장바구니</button>
</article>

/* 링크 하나의 누르는 영역을 카드 전체로 넓힌다. 읽히는 링크는 그대로 하나 */
.card { position: relative; }
.stretch::after { content: ""; position: absolute; inset: 0; }
.over { position: relative; z-index: 1; } /* 버튼은 넓힌 링크 위에 올린다 */
키와 마크업그때 일어나야 하는 일
Tab포커스가 카드마다 한 번만 멈추는 것이 좋습니다. 카드 안에 링크가 셋이면 세 번 멈춥니다
Enter카드가 가리키는 주된 화면으로 이동합니다
카드 안의 버튼을 누를 때event.stopPropagation()을 쓰거나 링크 영역을 넓히는 방식으로 버튼과 카드의 눌림이 겹치지 않게 합니다
카드 제목을 적을 때h2~h4 제목 태그로 두면 스크린 리더 사용자가 제목만 골라 들으며 목록을 넘길 수 있습니다
카드 사진의 대체 텍스트사진에 전할 뜻이 있으면 alt를 쓰고, 제목이 이미 같은 내용을 알려 주면 비워 둡니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

카드 한 장은 응답 한 건목록 API가 돌려주는 한 줄이 카드 한 장이 됩니다. 카드에 보이는 값은 모두 그 한 줄 안에 들어 있어야 하는데, 카드마다 값을 따로 요청하면 카드가 20장일 때 요청도 20번 나가기 때문입니다.
사진 비율 맞추기사용자가 올리는 사진은 가로세로 비율이 제각각이라서, 서버에서 미리 잘라 두거나 화면에서 object-fit: cover로 비율을 맞춥니다. 비율을 맞추지 않으면 사진마다 카드 높이가 달라집니다.
가장 긴 제목에 대비하기제목 길이는 데이터에 따라 정해집니다. 그래서 실제 데이터 중 가장 긴 값으로 카드를 한 번 그려 보아야 하고, 그러지 않으면 운영 중에 레이아웃이 깨집니다. 긴 제목을 서버에서 자를지 화면에서 자를지도 미리 정해 둡니다.
카드 수만큼 늘어나는 사진 요청한 화면에 카드가 20장이면 사진도 20장을 받아야 합니다. 그래서 화면에 보일 때 사진을 받는 지연 로딩(loading="lazy")을 쓰는지, 작은 썸네일을 쓰는지에 따라 첫 화면이 뜨는 속도가 크게 달라집니다.
