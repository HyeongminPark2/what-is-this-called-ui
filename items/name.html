이름 붙이기

Accessible name

화면을 보지 못하는 사람은 버튼을 이름으로만 구별합니다. 버튼에 이름이 없으면 스크린 리더는 그냥 '버튼'이라고만 읽습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

각 줄의 오른쪽에 적힌 것이 스크린 리더가 읽는 말입니다. 빨간 줄은 이름이 아예 없는 요소입니다.
그중 아이콘만 있는 버튼과 label 없는 입력칸이 가장 흔한 사고입니다. 눈으로 보면 쓰레기통 그림과 자리글이 있지만, 스크린 리더는 그 요소가 무엇인지 읽어 주지 못합니다.

2 이름같은 것을 부르는 여러 이름

한국어이름, 접근 이름, 레이블
영어accessible name, label, labelling
같이 쓰는 말브라우저가 계산해 낸 요소의 이름은 접근 이름(accessible name), 이름 뒤에 덧붙는 설명은 접근 설명(accessible description · aria-describedby)이라고 합니다. 이름을 정하는 규칙은 이름 계산(accname)이라는 표준에 정해져 있습니다.
자주 잘못 부르는 이름자리글(placeholder) — 자리글은 이름이 아닙니다. 입력을 시작하면 사라지고, 스크린 리더마다 읽는 방식도 다릅니다.
title — 다른 방법이 없을 때 마지막으로 쓰는 수단입니다. 마우스를 올려야 보이고 터치 화면에서는 보이지 않습니다.
alt — 그림에만 쓰는 속성입니다. 버튼의 이름은 aria-label로 줍니다.

이름 붙이기를 한 줄로 정리하면 — 이름은 정해진 순서대로 찾습니다. aria-labelledby를 먼저 보고, 없으면 aria-label, <label>, 요소 안의 글자, title 순서로 내려가며 처음 찾은 것을 이름으로 씁니다.

4 무엇이 이름이 되는가요소에 따라 이름이 정해지는 모습

5 해부도부분마다 붙은 이름

🗑
aria-label="정산 #4821 지우기"
<label for> — 입력칸에 이름 붙이기
aria-labelledby — 이미 있는 글을 이름으로 씀
placeholder — 이름이 될 수 없음
aria-hidden="true" — 아이콘을 이름에서 뺌
  1. 이름이 필요한 것 button · link · input누를 수 있는 모든 요소와 입력칸에는 이름이 있어야 합니다
  2. 직접 적기 aria-label화면에 보이는 글이 없을 때 씁니다. 이름에 무엇을 하는지까지 넣습니다
  3. 입력칸의 이름 <label for>label을 누르면 입력칸으로 포커스도 옮겨 가기 때문에 aria-label보다 낫습니다
  4. 이미 있는 글 가리키기 aria-labelledby화면에 제목이 이미 있으면 그 제목을 가리켜 이름으로 씁니다. 이름을 정할 때 가장 먼저 봅니다
  5. 자리글 placeholder자리글은 이름이 아닙니다. 입력을 시작하면 사라집니다
  6. 아이콘 숨기기 aria-hidden="true"장식용 아이콘은 이름 계산에서 뺍니다. 빼지 않으면 아이콘 이름이 섞여 '쓰레기통 버튼'처럼 읽힙니다

이름은 위의 순서에서 처음 찾은 하나만 쓰입니다. 예를 들어 aria-label을 주면 버튼 안의 글자는 전부 무시됩니다. 그래서 <button aria-label="삭제">저장</button> 같은 실수는 화면만 봐서는 눈에 띄지 않습니다. 이렇게 보이는 글과 읽히는 이름이 다르면 음성으로 화면을 조작하는 사람이 "저장 눌러"라고 말해도 버튼이 눌리지 않습니다.

6 쓸 때 / 안 쓸 때

이름을 꼭 챙겨야 하는 경우

  • 아이콘만 있는 버튼을 만들 때. 이름을 가장 자주 빠뜨리는 자리입니다
  • 같은 글자의 링크가 여러 개일 때. '더 보기'에 무엇을 더 보는지 붙입니다
  • 입력칸을 만들 때. 모든 입력칸에 <label>을 붙입니다
  • 요소 여러 개를 한 묶음으로 보여 줄 때. role="group"과 aria-label로 묶음에도 이름을 붙입니다

이름을 붙일 때 피할 것

  • label 대신 자리글만 둘 때
  • 화면에 보이는 글과 다른 이름을 붙일 때. 음성으로 조작할 수 없게 됩니다
  • 이름을 title에만 맡길 때. 터치 화면에서는 보이지 않습니다
  • '버튼'이나 '링크'라는 말을 이름에 넣을 때. 역할은 스크린 리더가 따로 읽기 때문에 '저장 버튼 버튼'처럼 겹쳐 읽힙니다

이름 붙이기와 이어지는 주제는 다른 항목에서 다룹니다 — 이름과 함께 역할·상태까지 어떻게 읽히는지는 스크린 리더가 읽는 것에서, 어떤 태그를 고를지는 시맨틱 태그에서 다룹니다. 화면이 저절로 바뀐 것을 알리는 방법은 라이브 리전을 보세요.

8 최소 마크업과 규칙이름이 정해지는 순서

이름이 정해지는 순서를 알면 디버깅이 쉬워집니다. 순서상 위의 것이 있으면 아래의 것은 무시되기 때문입니다.

<!-- 1. aria-labelledby는 이미 있는 글을 가리킨다 -->
<h2 id="t">정산 요청 #4821</h2>
<section aria-labelledby="t">…</section>

<!-- 2. aria-label은 보이는 글이 없을 때 쓴다 -->
<button aria-label="정산 #4821 지우기">
  <svg aria-hidden="true">…</svg>
</button>

<!-- 3. 입력칸에는 label이 가장 좋다 -->
<label for="acc">계좌번호</label>
<input id="acc" aria-describedby="hint">
<p id="hint">숫자만 입력하세요</p>   <!-- 설명은 따로 -->
지킬 규칙지키는 방법
이름을 찾는 순서 알기labelledby, label(aria), <label>, 안의 글자, title 순서로 찾습니다
입력칸에는 <label> 쓰기label을 누르면 입력칸으로 포커스가 옮겨 가는 이점까지 있습니다
아이콘은 이름에서 숨기기aria-hidden="true"로 숨깁니다. 숨기지 않으면 아이콘 그림의 이름이 버튼 이름에 섞입니다
이름을 보이는 글과 맞추기보이는 글과 이름이 다르면 음성으로 조작할 수 없습니다
이름에 역할을 적지 않기이름을 '저장 버튼'이라고 쓰면 '저장 버튼 버튼'으로 읽힙니다
설명은 describedby로 따로 연결하기이름은 짧게 두고, 긴 도움말은 설명으로 따로 연결합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

이름에 데이터 넣기'지우기'보다 '정산 #4821 지우기'가 낫습니다. 목록에 같은 버튼이 열 개 있어도 서로 구별할 수 있기 때문입니다. 이름에는 서버가 내려주는 ID를 끼워 넣습니다.
aria-label도 번역하기aria-label도 번역 대상입니다. 코드에 한국어 문구를 직접 적어 두면 번역할 때 빠지기 쉽습니다.
이름 없는 버튼 자동 검사axe-core 같은 도구를 돌리면 '이름 없는 버튼'을 바로 찾아 줍니다. 접근성 검사 가운데 CI에 넣기 가장 쉬운 검사입니다.
접근성 트리에서 이름 확인하기개발자 도구의 Accessibility 패널을 열면 브라우저가 계산한 이름을 직접 볼 수 있으니, 이름이 무엇으로 정해졌는지 추측할 필요가 없습니다.

이름을 붙이는 방식은 웹, iOS, 안드로이드가 거의 같습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 세 플랫폼 모두 이름과 설명을 따로 두고 같은 용도로 씁니다. 그래서 "아이콘 버튼에 이름 붙여 주세요"라는 요청이 웹 개발자와 앱 개발자에게 같은 뜻으로 전달되고, 접근성 항목 가운데 소통하기가 가장 쉽습니다.
