이름 붙이기

Accessible name

화면을 못 보는 사람에게 버튼은 이름 하나로만 존재합니다. 이름이 없으면 그냥 '버튼'입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

각 줄의 오른쪽이 스크린 리더가 읽는 말입니다. 빨간 줄은 이름이 아예 없는 것입니다.
아이콘만 있는 버튼과 label 없는 입력칸이 가장 흔한 사고입니다 — 눈으로는 쓰레기통 그림과 자리글이 보이지만, 소리로는 아무것도 아닙니다.

2 이름부르는 말이 여러 개다

한국어이름, 접근 이름, 레이블
영어accessible name, label, labelling
같이 쓰는 말계산된 이름을 접근 이름(accessible name), 덧붙는 설명을 접근 설명(accessible description · aria-describedby)이라 합니다. 이름을 정하는 규칙은 이름 계산(accname) 이라는 표준으로 정해져 있습니다.
자주 잘못 부름자리글(placeholder) — 이름이 아닙니다. 입력을 시작하면 사라지고, 기기마다 읽는 방식이 다릅니다.
title — 마지막 수단입니다. 마우스를 올려야 보이고 터치에서는 안 보입니다.
alt — 그림 전용입니다. 버튼의 이름은 aria-label로 줍니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다
대체 텍스트그림의 뜻안 보인다눈으로 안 보는 사람이미지를 끄고 읽어 본다
확대와 글자 크기키웠을 때도 쓰이나안 보인다저시력 사용자200%로 키워 본다

한 줄로 — 이름은 순서대로 정해집니다 — aria-labelledby → aria-label → <label> → 안의 글자 → title.

4 갈래무엇이 이름이 되나

5 해부도부분 이름이 제일 안 알려진 지식

🗑
aria-label="정산 #4821 지우기"
<label for> — 입력칸의 이름
aria-labelledby — 이미 있는 글을 가리킨다
placeholder — 이름이 아니다
aria-hidden="true" — 아이콘은 이름에서 뺀다
  1. 이름이 필요한 것 button · link · input누를 수 있는 모든 것과 입력칸
  2. 직접 적기 aria-label보이는 글이 없을 때. 무엇을까지 넣는다
  3. 입력칸의 이름 <label for>눌러서 포커스도 간다 — aria-label 보다 낫다
  4. 이미 있는 글 가리키기 aria-labelledby제목이 이미 있으면 그걸 가리킨다. 가장 우선한다
  5. 자리글 placeholder이름이 아니다. 입력하면 사라진다
  6. 아이콘 숨기기 aria-hidden="true"장식 아이콘은 이름 계산에서 뺀다 — 안 빼면 '쓰레기통 버튼'이 된다

이름은 위에서부터 하나만 쓰입니다. aria-label을 주면 안의 글자는 통째로 무시됩니다 — 그래서 <button aria-label="삭제">저장</button> 같은 실수가 눈에 안 띄게 숨습니다. 보이는 글과 읽히는 이름이 다르면 음성으로 조작하는 사람이 "저장 눌러"라고 말해도 안 눌립니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 아이콘만 있는 버튼 — 거의 늘 빠뜨리는 자리
  • 같은 글자가 여럿인 링크 — '더 보기'에 무엇을 더 보는지 붙입니다
  • 모든 입력칸에 <label>
  • 묶음에 이름 붙이기 — role="group" + aria-label

이럴 때는 안 쓴다

  • 자리글로 label 을 대신하는 것
  • 보이는 글과 다른 이름을 붙이는 것 — 음성 조작이 안 됩니다
  • title에만 의지하는 것 — 터치에서는 안 보입니다
  • '버튼'·'링크'를 이름에 넣는 것 — 역할은 따로 읽히므로 '저장 버튼 버튼'이 됩니다

대신 이걸 — 역할·상태까지 보려면 스크린 리더가 읽는 것, 태그 고르기는 시맨틱 태그, 저절로 바뀐 것은 라이브 리전.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙이름이 정해지는 순서

순서를 알면 디버깅이 쉬워집니다 — 위의 것이 있으면 아래는 무시됩니다.

<!-- 1. aria-labelledby — 이미 있는 글을 가리킨다 -->
<h2 id="t">정산 요청 #4821</h2>
<section aria-labelledby="t">…</section>

<!-- 2. aria-label — 보이는 글이 없을 때 -->
<button aria-label="정산 #4821 지우기">
  <svg aria-hidden="true">…</svg>
</button>

<!-- 3. label — 입력칸은 이게 가장 좋다 -->
<label for="acc">계좌번호</label>
<input id="acc" aria-describedby="hint">
<p id="hint">숫자만 입력하세요</p>   <!-- 설명은 따로 -->
규칙지켜야 하는 것
순서를 안다labelledby → label(aria) → <label> → 안의 글자 → title
입력칸은 <label>눌러서 포커스가 가는 이점까지 있다
아이콘은 숨긴다aria-hidden="true". 안 숨기면 그림 이름이 섞인다
보이는 글과 맞춘다다르면 음성 조작이 안 된다
역할은 안 적는다'저장 버튼'이라고 쓰면 '저장 버튼 버튼'으로 읽힌다
설명은 describedby이름은 짧게, 긴 도움말은 설명으로 따로

9 서버 쪽으로 치면백엔드 감각으로 번역

이름에 데이터를 넣는다'지우기'보다 '정산 #4821 지우기'가 낫습니다. 목록에서 같은 버튼이 열 개일 때 구별이 됩니다 — 서버가 주는 ID 를 이름에 끼워 넣습니다.
다국어aria-label도 번역 대상입니다. 코드에 한국어를 박아 두면 번역에서 빠집니다.
자동 검사axe-core 같은 도구가 '이름 없는 버튼'을 바로 잡아 줍니다. CI 에 넣기 가장 쉬운 접근성 검사입니다.
접근성 트리개발자 도구의 Accessibility 패널에서 계산된 이름을 볼 수 있습니다. 추측하지 말고 보면 됩니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

이름을 붙이는 일은 세 플랫폼이 거의 같습니다.

웹aria-label · label
🗑"지우기, 버튼"
속성으로 붙입니다. 순서가 정해져 있어 위의 것이 아래를 덮습니다.
iOSSwiftUI
.accessibilityLabel( )
.accessibilityHint( )
Label 과 Hint 로 나뉩니다. 웹의 이름·설명과 거의 1대1입니다.
안드로이드Compose

semantics { }
contentDescription 하나로 붙입니다. 장식은 null 로 두어 뺍니다.

자주 생기는 사고 — 세 쪽 다 이름·설명 두 층이 있고 쓰임이 같습니다. 그래서 "아이콘 버튼에 이름 붙여 주세요"가 그대로 통합니다 — 접근성 항목 중 소통이 가장 쉬운 축입니다.
