여러 줄 입력

Textarea

줄바꿈이 들어가는 순간 다른 부품이 됩니다 — 높이가 변하고, 한도가 생기고, Enter 의 뜻이 달라집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

'160자짜리 글 붙여넣기'를 눌러 보세요 — '아예 못 치게'를 켜면 붙여넣은 글이 소리 없이 잘립니다. 데모가 잘려 나간 글자 수를 세서 적습니다. 넘치더라도 치게 두고 빨갛게 알리는 쪽이 고치기 쉽습니다.
내용만큼 늘어나기를 켜면 줄이 늘 때 칸도 같이 커집니다. Enter 로 보내기를 메모 칸에 켜면 줄바꿈을 못 하게 됩니다 — 둘은 같이 쓸 수 없습니다.

2 이름부르는 말이 여러 개다

한국어여러 줄 입력, 텍스트 영역, 메모 칸
영어textarea, multi-line input, text area
같이 쓰는 말내용만큼 높이가 늘어나는 것을 오토그로(auto-grow), 모서리를 끌어 크기를 바꾸는 손잡이를 리사이저라 합니다. 서식(굵게·목록)이 들어가면 리치 텍스트 편집기로, 전혀 다른 부품이 됩니다.
자주 잘못 부름텍스트 필드 — 텍스트 필드는 한 줄입니다.
에디터 — 굵게·목록이 들어가면 리치 텍스트라 다른 것입니다.
코드 칸 — 들여쓰기·Tab 처리가 달라 따로 만듭니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

rows — 처음 보이는 줄 수
내용만큼 늘어나기 — 작은 창에서 안 굴린다
남은 글자 수 — 넘치기 전에 보인다
maxlength — 붙여넣은 글이 소리 없이 잘린다
resize — 세로만 열어 두는 편이 안전하다
Enter 로 보내기와 줄바꿈은 같이 못 쓴다
  1. rows 처음 줄 수두세 줄로 시작
  2. 자동 높이 안 굴림내용만큼 커진다
  3. 글자 수 미리 보임넘치기 전에
  4. maxlength 소리 없이 잘림붙여넣기에서 특히
  5. resize 세로만가로로 늘면 칸이 깨진다
  6. Enter 둘 중 하나보내기 또는 줄바꿈

maxlength 는 쉬워 보이지만 붙여넣기에서 가장 나쁩니다 — 길게 써 둔 글을 붙여넣으면 한도까지만 들어가고 나머지는 아무 말 없이 사라집니다. 사용자는 다 들어간 줄 알고 보냅니다.
그래서 한도는 막는 것이 아니라 알리는 것으로 두는 편이 낫습니다 — 넘치면 빨갛게 하고 보내기를 막되, 글은 그대로 두는 것입니다. 그래야 사용자가 보면서 줄일 수 있습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 남은 글자 수를 미리 보이기
  • 넘치면 치게 두고 보내기를 막기
  • resize: vertical 로 세로만 열어 두기

이럴 때는 안 쓴다

  • maxlength 로 잘라 버리기
  • 메모 칸에 Enter 로 보내기 켜기 — 줄바꿈을 못 한다
  • 높이를 한 줄로 두기 — 쓰면서 아무것도 안 보인다
  • 글자 수를 보낸 뒤에 알리기

대신 이걸 — 한 줄이면 텍스트 필드, 서식이 들어가면 리치 텍스트, 검사 규칙은 입력 검증, 문구는 자리글과 헬퍼 텍스트.

8 최소 마크업과 키보드이 부품의 계약서

자동 높이는 field-sizing 한 줄, 안 되면 scrollHeight 로 맞춥니다.

<label for="memo">정산 메모</label>
<textarea id="memo" rows="3" aria-describedby="memo-cnt"></textarea>
<p id="memo-cnt" role="status">118자 남음</p>

textarea { resize: vertical; field-sizing: content; max-height: 14em; }

// field-sizing 을 못 쓰는 곳에서는 — 높이를 재서 맞춘다
el.addEventListener('input', () => {
  el.style.height = 'auto';
  el.style.height = Math.min(240, el.scrollHeight) + 'px';
});

9 서버 쪽으로 치면백엔드 감각으로 번역

한도는 서버에도화면의 한도는 친절이고, 서버 검사가 진짜입니다.
줄바꿈 보존저장할 때 줄바꿈이 사라지면 쓴 모양이 달라집니다 — 보여 줄 때 white-space: pre-wrap 이 필요합니다.
글자 수 세는 법이모지·한글은 코드 단위로 세면 어긋납니다 — 서버와 화면이 같은 방식으로 세야 합니다.

자주 생기는 사고 — 앱 쪽은 자동 높이가 기본이라 따로 챙길 것이 없는데, 웹에서는 오래도록 자바스크립트로 높이를 재야 했습니다. field-sizing: content 가 그 수고를 없애 주지만 아직 모든 브라우저에 있지는 않아, 한동안은 둘 다 써야 합니다. 최대 높이를 두는 것은 어느 쪽이든 필요합니다 — 안 두면 긴 글에서 칸이 화면을 다 먹습니다.
