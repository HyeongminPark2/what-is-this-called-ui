폼 설계

Form design

폼 설계는 칸 하나하나의 모양보다 여러 칸을 어떻게 묶고 얼마나 줄일지를 정하는 일입니다. 칸이 적을수록 사용자가 끝까지 채울 가능성이 높아지므로 짧은 폼을 목표로 합니다.

선택 칸 숨기기를 켜면 꼭 채울 칸만 남습니다. 폼 설계에서 가장 효과가 큰 일이 이렇게 칸 수를 줄이는 것입니다. 아래에는 지금 몇 칸을 채워야 하는지가 표시됩니다.

2 이름같은 것을 부르는 여러 이름

한국어폼, 입력 양식, 서식, 등록 화면
영어form, form design, input form
같이 쓰는 말입력 칸 하나는 필드(field), 칸 이름은 레이블, 칸 밑에 붙는 설명은 헬프 텍스트·힌트라고 부릅니다. 여러 칸을 한데 묶은 것은 필드셋(fieldset)·섹션이라고 하고, 폼을 여러 화면으로 나눈 것은 위저드(wizard)·스텝 폼이라고 합니다.
자주 잘못 부르는 이름필드 — 입력 필드는 칸 하나를 가리키고, 폼은 여러 칸을 묶은 전체를 가리킵니다.
모달 — 모달은 화면을 띄우는 방식이고, 폼은 그 모달 안에 들어가는 내용입니다.
검증 — 입력 검증은 폼을 이루는 한 부분입니다.

저장취소
  1. 폼 <form>칸들을 <form>으로 감싸야 엔터로 제출되고 브라우저 자동 채움도 잘 동작합니다
  2. 묶음 fieldset / legend성격이 같은 칸들을 묶습니다. 칸 수가 같아도 묶어 두면 짧아 보입니다
  3. 한 줄에 한 칸 single column한 줄에 한 칸씩 두면 시선이 위에서 아래로 한 줄기로 내려갑니다. 두 열로 놓으면 사용자가 건너뛰는 칸이 생깁니다
  4. 레이블은 위 label top레이블을 칸 위에 두면 좁은 폰 화면에서도 배치가 무너지지 않고, 레이블 글자가 길어져도 들어갑니다
  5. 선택 칸 표시 (선택)필수 칸에 별표를 다는 것보다 선택 칸에 '(선택)'을 적는 편이 읽기 쉽습니다
  6. 버튼 주 동작 하나저장은 오른쪽에 진한 색으로, 취소는 눈에 덜 띄게 둡니다. 두 버튼을 같은 강조로 두지 않습니다

칸을 두 열로 놓지 않습니다. 두 열로 놓으면 시선이 Z 자로 오가야 해서, 사용자가 오른쪽 열을 통째로 보지 못하고 지나치는 일이 생깁니다. 예외는 따로 떼어 놓으면 오히려 어색한 값뿐입니다. 시·도와 시·군·구, 시작일과 종료일, 카드 유효기간의 월과 연도처럼 한 덩어리로 읽히는 값은 나란히 둡니다.

6 쓸 때 / 안 쓸 때

폼 설계를 쓰는 경우

  • 받을 값이 여러 개이고 한 번에 보내야 할 때
  • 이미 있는 값을 고치는 화면일 때. 칸마다 기존 값이 들어 있어야 합니다
  • 단계가 있는 등록 화면일 때. 단계를 나눠야 사용자가 끝까지 채웁니다

폼 설계를 쓰지 않는 경우

  • 칸이 하나일 때. 입력 필드와 버튼만 두면 됩니다
  • '나중에 쓸지도 몰라서' 칸을 넣을 때. 지금 쓰지 않는 칸은 지웁니다
  • 열 칸을 한 화면에 늘어놓을 때. 세 묶음 정도로 나누거나 단계로 쪼갭니다
  • <form> 없이 <div>로 감쌀 때. 엔터로 제출할 수 없고 자동 채움도 제대로 동작하지 않습니다

폼 설계 대신 다른 것을 써야 하는 경우 — 칸이 하나면 입력 필드, 고르기만 하면 셀렉트, 확인만 받으면 다이얼로그를 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드폼이 꼭 갖출 것

칸 전체를 <form>으로 감싸고, 묶음은 <fieldset>으로, 칸 이름은 <label for>로 답니다.

<form method="post">
  <fieldset>
    <legend>가맹점</legend>
    <label for="biz">상호</label>
    <input id="biz" name="biz" autocomplete="organization" required>

    <label for="no">사업자번호</label>
    <input id="no" name="no" inputmode="numeric"
           aria-describedby="no-hint">
    <p id="no-hint">- 없이 10자리</p>
  </fieldset>

  <button>저장</button>
</form>
키와 동작그때 일어나야 하는 일
Enter칸이 <form> 안에 있으면 엔터로 제출됩니다. div로 감싸면 제출되지 않습니다
<label for>칸마다 답니다. 레이블을 눌러도 칸에 포커스가 가서 누를 수 있는 영역이 넓어집니다
autocomplete이름·전화·주소·카드 칸에 적어 두면 브라우저가 값을 채워 줍니다. 폼에 넣을 수 있는 효과가 가장 큰 한 줄입니다
inputmode폰 키보드 종류를 바꿉니다. 숫자 칸에 글자 키보드가 뜨면 사용자가 숫자 키보드로 직접 바꿔야 합니다
<fieldset><legend>스크린 리더가 '가맹점 묶음, 상호 입력'처럼 묶음 이름과 함께 읽습니다
aria-describedby힌트를 칸에 연결합니다. 칸 밑에 적기만 하면 칸에 포커스가 왔을 때 힌트를 읽어 주지 않습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버가 다시 검사한다브라우저에서 하는 검사는 사용자가 빨리 고치도록 돕는 장치이고 방어 수단은 아닙니다. 요청은 폼을 거치지 않고도 보낼 수 있기 때문입니다.
두 번 눌러 두 건저장 버튼을 두 번 눌러 같은 건이 둘 생기는 일이 흔합니다. 그래서 요청마다 고유 키(idempotency key)를 받아, 같은 키로 온 요청은 한 번만 처리합니다.
임시 저장긴 폼은 사용자가 중간에 자리를 뜨거나 창을 닫아 끊기기 쉽습니다. 초안을 따로 저장해 두면 다시 돌아왔을 때 이어서 쓸 수 있습니다.
오류를 칸별로 돌려준다{"errors":{"no":"10자리여야 합니다"}}처럼 오류가 어느 칸의 것인지 함께 보내야 화면에서 오류 문구를 그 칸에 붙일 수 있습니다.
칸이 늘면 버전이 생긴다칸을 새로 추가하면 이미 저장된 옛 데이터에는 그 칸의 값이 없습니다. 새 칸은 빈 값을 허용하거나 기본값을 정해 둡니다.
