1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

체크를 끄면 그림만 받은 상태입니다. ✕ 가 붙은 것들이 개발 중에 하나씩 물어보게 되는 것들이고, 그 왕복이 일정의 상당 부분을 먹습니다.
그림에서 재서 알 수 있는 것은 둘뿐이고, 나머지 여덟은 말로 넘겨야 합니다.

2 이름부르는 말이 여러 개다

한국어핸드오프, 전달, 개발 전달, 스펙
영어handoff, design handoff, spec, redline
같이 쓰는 말치수를 적어 넣은 그림을 레드라인(redline)·스펙이라 하고, 시안 도구가 자동으로 보여 주는 값이 인스펙트(inspect) 화면입니다. 그림과 코드 부품을 짝지어 두는 것을 코드 커넥트라 부르기도 합니다. 넘기고 끝나는 게 아니라 계속 오간다는 뜻으로 지속적 핸드오프라는 말도 씁니다.
자주 잘못 부름스펙 — 기능 명세서를 뜻하기도 합니다. 여기서는 화면의 치수와 규칙입니다.
QA — 만든 뒤 확인하는 일입니다. 핸드오프는 만들기 전입니다.
리뷰 — 의견을 주고받는 일이고, 핸드오프는 넘기는 일입니다.

3 가르는 기준형제들과 비교하는 네 축

현장 용어는 말이 아니라 일하는 단계를 가리킵니다. 이 네 가지만 물어보면 갈립니다.

무엇을 가리키나언제 나오나개발 쪽 대응물잘못 알아들으면
와이어프레임과 목업과 시안얼마나 진짜 같은 그림인가기획 ~ 디자인마크업 구조 ~ 완성 화면엉뚱한 리뷰가 돌아온다
디자인 시스템규칙 + 부품 + 문서프로젝트 내내토큰 + 컴포넌트 라이브러리스타일 가이드와 섞인다
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀐다
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞인다
오토 레이아웃자동 배치시안 작업flexbox‘여백이 자동’을 못 알아듣는다
프로토타입눌리는 시안리뷰 · 사용자 시험아직 코드가 아니다다 된 줄 안다
핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받는다
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배만 받아 뭉갠다
디자인 리뷰고칠 거리를 만드는 말단계마다코드 리뷰너무 이르거나 너무 늦다
버전 관리어느 것이 지금 것인가프로젝트 내내커밋 메시지final 사슬이 생긴다

한 줄로 — 그림에서 잴 수 있는 것은 둘뿐입니다. 나머지 여덟은 적어 주지 않으면 물어보게 됩니다.

4 무엇이 넘어오나재는 것과 묻는 것

5 해부도부분 이름이 제일 안 알려진 지식

그림에서 잴 수 있는 것 — 간격 · 색 · 크기
토큰 이름 — accent 인가 brand 인가
상태 — 호버 · 누름 · 비활성 · 로딩
글이 길어지면 · 폰에서는 · 비어 있으면
문구 — 버튼 글자와 오류 문장
그림만 받으면 여덟 가지를 물어보게 된다
  1. 잴 수 있는 것 간격 · 색 · 크기도구가 자동으로 보여 준다
  2. 토큰 이름 값이 아니라 이름#2f6df6 이 무엇인지를 적는다
  3. 상태 호버 · 누름 · 비활성시안에는 기본 하나뿐이다
  4. 경계 길어지면 · 좁아지면말줄임인가 두 줄인가
  5. 없는 화면 빈 · 로딩 · 오류데이터가 가득한 시안에는 안 보인다
  6. 문구 · 에셋 글자와 파일버튼 글자, 아이콘 파일 꼴

스펙은 긴 문서가 아니어도 됩니다. 시안 옆에 적은 메모 열 줄이면 대개 충분합니다 — '이 파랑은 --accent', '글이 길면 두 줄까지', '560px 아래에서 한 단', '목록이 비면 가맹점 등록 버튼'. 중요한 것은 분량이 아니라 그림에서 알 수 없는 것만 골라 적는 것입니다. 그리고 이 목록은 거의 매번 같기 때문에, 한 번 만들어 둔 점검표를 돌려 쓰면 됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 그림에서 알 수 없는 것만 골라 적기
  • 같은 점검표를 매번 돌려 쓰기
  • 토큰 이름으로 적기 — 값이 아니라

이럴 때는 안 쓴다

  • 그림만 넘기고 '보면 알죠' — 여덟 번 물어보게 된다
  • 값을 박아 적기 — #2f6df6 대신 이름을
  • 상태·빈 화면을 안 그리기 — 개발 중에 즉흥으로 정해진다
  • 넘기고 끝내기 — 계속 오간다

대신 이걸 — 그림 단계는 와이어프레임과 목업과 시안, 부품 규칙은 디자인 시스템, 파일은 에셋 내보내기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 점검표이 전달의 계약서

매번 같은 열 줄을 적습니다.

# 핸드오프 점검표 — 그림에서 알 수 없는 것만

1. 토큰 이름  : 이 파랑은 --accent, 간격은 --space-3
2. 상태       : 기본 / 호버 / 누름 / 비활성 / 로딩
3. 글이 길면  : 두 줄까지, 넘으면 말줄임
4. 좁아지면   : 560px 아래에서 한 단, 메뉴는 접기
5. 비어 있으면: "아직 등록한 가맹점이 없어요" + [가맹점 등록]
6. 불러오는 중: 스켈레톤 세 줄
7. 실패하면   : "불러오지 못했습니다" + [다시 시도]
8. 문구       : 버튼은 "내보내기" (확인 아님)
9. 움직임     : 240ms ease-out, 모션 줄이기에서는 0
10. 에셋      : 아이콘 SVG, 사진 WebP 2x
키일어나야 하는 일
상태에 초점도 넣는다호버만 그리면 키보드 초점이 빠진다
대비비를 적는다흐린 회색 글씨는 시안에서 예뻐 보이고 기준에 걸린다
아이콘의 이름아이콘만 있는 버튼은 뭐라고 읽힐지를 적어 준다
눌리는 넓이보이는 크기와 따로다. 시안에서는 안 보인다
모션 줄이기움직임을 적을 때 줄이기에서 어떻게 되는지도 함께
읽는 순서눈에 보이는 차례와 Tab 순서가 다르면 적어 둔다

9 서버 쪽으로 치면백엔드 감각으로 번역

데이터 모양을 함께화면에 필요한 값이 정해지면 API 설계가 앞당겨집니다.
없는 화면이 일정을 늘린다빈·로딩·오류는 화면 수가 세 배가 되는 일입니다. 핸드오프에서 드러나야 일정에 들어갑니다.
문구를 한곳에버튼 글자·오류 문장을 표로 받으면 그대로 문구 파일이 됩니다 — 말투와 높임.
토큰을 코드로 내보내기시안 도구의 변수를 CSS 변수로 뽑아 쓰면 옮겨 적다 틀릴 일이 없습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

도구가 거드는 범위가 다릅니다 — 잴 수 있는 것까지입니다.

웹인스펙트 + 메모
padding: 12px
color: --accent
도구가 CSS 를 보여 줍니다. 다만 이름·상태·경계는 사람이 적어야 합니다.
iOS같은 문제
spacing: 12pt
color: Accent
pt 로 보여 줍니다. 다이내믹 타입에서 어떻게 되는지는 따로 물어야 합니다.
안드로이드같은 문제
padding: 12dp
color: colorPrimary
dp 로 보여 줍니다. 기기 폭이 다양해 경계 질문이 더 많습니다.

자주 생기는 사고 — "시안 다 나왔으니 개발만 하면 됩니다"가 자주 틀리는 이유가 이것입니다. 시안에 있는 것은 기본 상태 한 장이고, 만들어야 하는 것은 상태 다섯에 경계 셋입니다. 핸드오프 점검표를 한 번 만들어 두면 이 차이가 일정 잡을 때 드러나고, 개발 중 왕복이 크게 줄어듭니다.
