사이드바 내비게이션

Sidebar navigation

사이드바 내비게이션은 화면 옆에 늘 붙어 있는 메뉴입니다. 지금 어디인지와 갈 수 있는 곳이 한눈에 보이고, 세로로 늘어놓기 때문에 항목이 열 개를 넘어도 모두 담을 수 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

사이드바는 늘 화면에 보입니다. 같은 메뉴가 좁은 화면에서 숨어 있다가 버튼을 눌러야 나오면 그건 사이드바가 아니라 드로어입니다.
아이콘만 보기를 눌러 보세요. 이름을 숨기고 아이콘만 남겨 폭을 줄인 레일(rail)로 바뀌는데, 아이콘만으로는 어느 화면인지 알기 어려우므로 툴팁이나 글자를 함께 둬야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어사이드바, 측면 내비게이션, 좌측 메뉴
영어sidebar navigation, side nav, navigation rail
같이 쓰는 말아이콘만 남겨 폭을 좁힌 것은 레일(rail), 하위 항목을 펼치고 접을 수 있는 것은 접이식(collapsible), 항목 묶음의 제목은 섹션 헤더라고 부릅니다.
자주 잘못 부르는 이름드로어 — 늘 보이면 사이드바이고, 숨어 있다가 옆에서 밀려 나오면 드로어입니다. 같은 메뉴가 화면 폭에 따라 사이드바가 되기도 하고 드로어가 되기도 합니다.
메뉴 — 메뉴는 실행할 동작을 고르는 부품이고, 사이드바는 다른 화면으로 옮겨 가는 부품입니다.
패널 — 패널은 보조 내용을 담는 칸이고, 사이드바는 다른 화면으로 가는 링크를 담습니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품들은 모양만 보고는 구별하기 어렵지만, 아래 네 가지를 따져 보면 어느 부품인지 가려낼 수 있습니다.

화면에 놓이는 자리누르면 데려가는 곳지금 위치를 알리는 방법담을 수 있는 항목 수
앱바 · 헤더화면 위전역 또는 상위 화면제목으로해당 없음
사이드바 내비게이션화면 옆전역항목 강조로10~20
바텀 탭바화면 아래전역아이콘 강조로3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위 단계계층 전체를 보여 줌3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록의 다음 묶음보여 주지 않음제한 없음
스테퍼내용 위 · 옆같은 흐름의 다음 단계번호와 완료 표시로3~5단계
트리뷰화면 옆계층 아래로펼친 가지로깊이 3단까지
앵커 내비내용 옆같은 문서 안보는 절을 강조해5~12
뒤로가기화면 왼쪽 위바로 앞 화면보여 주지 않음하나
메가 메뉴앱바 아래전역, 여러 분류열린 분류로20~60

사이드바 내비게이션을 한 줄로 정리하면 — 사이드바는 늘 보이는 내비게이션입니다. 화면 폭 일부를 차지하는 대신 '지금 어디인지'와 '어디로 갈 수 있는지'를 계속 보여 줍니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

운영
거래 내역 584
정산
  1. 사이드바 sidebar화면 높이 전체를 씁니다. 폭은 보통 200~260px입니다
  2. 섹션 헤더 section header항목이 일곱 개를 넘으면 묶음으로 나누고 묶음마다 제목을 붙입니다. 항목보다 작고 흐린 글자로 씁니다
  3. 현재 항목 current item배경과 글자색으로 현재 위치를 알리고, aria-current="page"도 함께 답니다
  4. 아이콘 icon항목을 눈으로 빨리 찾게 해 줍니다. 레일에서는 아이콘만 남습니다
  5. 이름 label짧게 씁니다. 이름이 한 줄을 넘기면 묶음을 다시 나눌 때가 된 것입니다
  6. 숫자 count · badge항목의 개수나 처리할 건수를 보여 줍니다. 보여 줄 숫자가 없으면 두지 않습니다
  7. 다른 항목 item누르는 영역은 40px 이상으로 잡습니다. 글자만이 아니라 줄 전체가 눌려야 합니다

사이드바는 모든 화면에 함께 나옵니다. 그래서 사이드바에 항목 하나를 더하면 그 항목이 모든 화면에 보이게 되므로, 화면 하나를 새로 만드는 것보다 더 신중하게 정해야 합니다. 항목이 열 개를 넘기면 새 항목을 더하기 전에 묶음부터 다시 나눕니다.

6 쓸 때 / 안 쓸 때

사이드바 내비게이션을 쓰는 경우

  • 갈 곳이 다섯 개를 넘을 때. 탭바로는 다 담을 수 없습니다
  • 넓은 화면에서 내비게이션을 늘 보여 주고 싶을 때
  • 묶음과 항목, 두 단으로 된 내비게이션을 둘 때

사이드바 내비게이션을 쓰지 않는 경우

  • 좁은 화면에서도 그대로 둘 때. 사이드바가 자리를 차지해 내용을 볼 자리가 없어지므로 드로어로 바꿉니다
  • 항목을 스무 개 넘게 늘어놓을 때. 묶음으로 나누거나 검색을 붙입니다
  • 저장·삭제 같은 동작을 섞어 넣을 때. 사이드바에는 다른 화면으로 가는 링크만 담습니다
  • 깊이가 세 단 이상일 때. 묶음을 여러 번 접었다 펴다 보면 지금 어디에 있는지 놓칩니다

사이드바 내비게이션 대신 다른 것을 써야 하는 경우 — 화면이 좁으면 같은 메뉴를 드로어로 바꾸고, 폰에서는 바텀 탭바를 씁니다. 같은 화면의 다른 면을 보여 주려면 탭이 맞고, 다른 화면으로 가는 대신 동작을 고르게 하려면 드롭다운 메뉴를 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

핵심은 <nav>와 aria-current 두 가지입니다. 색을 구별하기 어려운 사용자나 스크린 리더 사용자도 알 수 있도록, 지금 어디인지를 색 말고도 알려야 합니다.

<nav aria-label="주 메뉴">
  <a href="/tx" aria-current="page">거래 내역</a>
  <a href="/settle">정산</a>
</nav>

/* 좁아지면 드로어로 바꾼다. 마크업은 같고 모양만 다르다 */
@media (max-width: 860px) {
  .nav-side { position: fixed; transform: translateX(-100%); }
}

/* 레일에서는 이름을 숨기되 title 로 남긴다 */
.nav-side.is-rail .tx { display: none; }
키와 마크업그때 일어나야 하는 일
Tab항목마다 포커스가 한 번씩 거쳐 갑니다. 본문에 닿기까지 오래 걸리므로 '본문으로 건너뛰기' 링크가 꼭 필요합니다
aria-current"page" 값으로 지금 위치를 알립니다. 색만으로는 스크린 리더에 전해지지 않습니다
<nav aria-label>내비게이션이 여러 개이면 '주 메뉴', '보조 메뉴'처럼 이름을 붙여 구별합니다
레일로 좁혔을 때아이콘만 남으면 aria-label이나 툴팁이 반드시 있어야 합니다
묶음을 펼치고 접을 때묶음이 펼쳐졌는지를 aria-expanded로 알립니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

라우팅 표를 그대로 보여 주는 메뉴사이드바는 앱의 화면 구조를 그대로 보여 줍니다. 항목과 주소가 1대1로 대응하기 때문에 사이드바를 고치는 일은 라우팅을 고치는 일이 됩니다.
숫자를 보여 주는 데 드는 추가 질의'거래 584'처럼 개수를 보여 주려면 개수를 따로 세는 질의가 필요합니다. 이 값은 모든 화면에 뜨는데 정확한 COUNT는 비용이 크기 때문에 캐시하거나 근사치로 보여 줍니다.
권한에 따라 메뉴 항목 거르기사용자가 볼 수 없는 화면은 서버가 메뉴 목록에서 빼고 내려 주거나, 권한 플래그를 함께 내려 줍니다. 화면에서 항목만 숨기면 사용자가 주소를 직접 입력해 그 화면에 들어올 수 있습니다.
주소로 현재 위치를 찾는 방법/tx/8812 같은 상세 화면에서도 '거래 내역' 항목이 켜져 있어야 합니다. 그래서 현재 주소와 항목 주소가 정확히 같은지가 아니라 접두사가 같은지로 비교합니다.
