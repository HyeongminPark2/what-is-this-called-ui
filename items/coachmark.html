코치마크

Coach mark · product tour

코치마크는 처음 쓰는 사람에게 화면의 한 곳을 짚어 그 기능을 설명하는 말풍선입니다. 한 번에 여러 곳을 짚으면 읽을 말풍선이 한꺼번에 늘어나서 어느 것도 제대로 읽히지 않습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

한 번에 짚는 수를 늘려 보세요. 한꺼번에 읽어야 하는 말풍선 수를 데모가 세어 적습니다. 말풍선이 둘을 넘으면 사람들은 어느 것도 제대로 읽지 않습니다.
건너뛸 길을 끄고 다시 보면 '다음'만 누를 수 있어서, 안내가 끝날 때까지 빠져나갈 수 없습니다. 데모는 빠져나갈 수 있는 길의 수도 셉니다.
코치마크는 한 번만 보여 줘야 합니다. 한 번 본 사람에게는 다시 띄우지 않고, 다시 봐야 할 때를 대비해 도움말 안에 같은 설명을 남겨 둡니다.

2 이름같은 것을 부르는 여러 이름

한국어코치마크, 안내 말풍선, 기능 투어, 스포트라이트
영어coach mark, product tour, onboarding tooltip, spotlight
같이 쓰는 말코치마크 여러 개를 차례로 이어 붙인 것은 프로덕트 투어(product tour), 짚는 곳만 밝게 남기는 효과는 스포트라이트라고 합니다. 새 기능 하나만 알리는 작은 점은 뉴 뱃지나 힌트 점이라고 부릅니다.
자주 잘못 부르는 이름툴팁 — 사용자가 대상을 가리켜야 뜨고 설명만 담으면 코치마크가 아니라 툴팁입니다.
온보딩 — 온보딩은 처음 쓰는 사람을 안내하는 흐름 전체를 가리키고, 코치마크는 그 흐름에 쓰는 방법 가운데 하나입니다.
모달 — 처음 들어왔을 때 한 장 띄우는 설명 화면은 코치마크가 아니라 모달입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품들은 모양만 보고는 구별하기 어렵지만, 아래 네 가지를 따져 보면 어느 부품인지 가려낼 수 있습니다.

뒤쪽 화면을 막는가포커스를 안에 가두는가뒤쪽 화면의 스크롤은화면 어디에서 뜨는가
모달막는다가둔다잠긴다가운데
다이얼로그(비모달)안 막는다안 가둔다그대로 움직인다가운데에 띄워 둔 채
바텀시트막을 때도 있다뒤를 막을 때만뒤를 막을 때만아래에서 올라옴
드로어보통 막는다가둔다잠긴다옆에서 밀려 나옴
팝오버안 막는다가두기도 한다그대로 움직인다누른 것 옆
툴팁안 막는다안 가둔다그대로 움직인다가리킨 것 옆
토스트안 막는다안 가둔다그대로 움직인다구석에 떴다 저절로 사라짐

코치마크를 한 줄로 정리하면 — 코치마크는 한 번에 하나씩, 모두 합쳐 셋까지만 띄웁니다. 그보다 많으면 사람들이 끝까지 읽지 않습니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

한 번에 하나만 짚음
구멍을 뚫어 짚는 곳만 밝게 남김
몇 번째인지 1 / 4로 보여 줌
건너뛰기가 없으면 못 빠져나감
한 번 본 사람에게는 다시 띄우지 않음
같은 설명을 도움말에도 남김
  1. 하나씩 한 번에 하나말풍선이 한꺼번에 둘만 떠도 사람들이 읽지 않습니다
  2. 구멍 짚는 것만 밝게짚는 곳만 밝게 남기면 어디를 설명하는지 분명해집니다
  3. 몇 번째 1 / 4전체 가운데 몇 번째인지 보여 주면 얼마나 남았는지 알 수 있습니다
  4. 건너뛰기 늘 둠건너뛰기가 없으면 안내가 끝날 때까지 빠져나갈 수 없습니다
  5. 한 번만 본 뒤에는 띄우지 않음본 적이 있는지 기억해 두고 다시 띄우지 않습니다
  6. 도움말 같은 설명을 남김나중에 다시 찾을 수 있게 도움말에도 같은 설명을 둡니다

코치마크는 만드는 쪽은 편하지만 쓰는 쪽은 불편한 대표적인 부품입니다. 화면을 고치지 않고도 설명을 덧붙일 수 있어서 만드는 쪽은 자꾸 코치마크를 쓰게 되는데, 사용자는 빨리 시작하고 싶어서 대부분 건너뜁니다.
그래서 코치마크를 붙이고 싶어지면, 먼저 그 기능이 화면만으로는 알기 어려운 이유를 찾아보는 것이 좋습니다. 단추 이름이 모호하거나, 단추가 엉뚱한 자리에 있거나, 빈 상태 화면에 아무 안내가 없는 경우가 많습니다. 이런 원인을 고치면 코치마크로 설명을 덧붙일 필요가 없어집니다.

6 쓸 때 / 안 쓸 때

코치마크를 만들 때 지킬 것

  • 한 번에 하나씩, 모두 합쳐 셋까지만 띄우기
  • 건너뛸 길을 늘 두기
  • 같은 설명을 도움말에도 남기기

코치마크를 만들 때 피할 것

  • 처음 들어오자마자 다섯 단계 띄우기
  • 건너뛰기 없이 다음으로만 가게 하기
  • 이미 본 사람에게 또 띄우기
  • 화면을 고치는 대신 설명을 덧붙이기

코치마크 대신 다른 것을 써야 하는 경우 — 사용자가 가리켰을 때만 설명을 띄우려면 툴팁을 쓰고, 처음 쓰는 흐름 전체를 안내하려면 온보딩이 맞습니다. 아무것도 없는 빈 화면에서 할 일을 알려 주려면 빈 상태를 쓰고, 기능이 많아 찾기 어렵다면 커맨드 팔레트를 둡니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

말풍선에는 role="dialog"를 붙이고, 사용자가 투어를 본 적이 있는지 꼭 저장해 둡니다.

<div class="coach" role="dialog" aria-label="여기서 내보내요">
  <b>여기서 내보내요</b>
  <p>정산 내역을 엑셀로 받을 수 있습니다.</p>
  <p>1 / 4</p>
  <button data-skip>건너뛰기</button>
  <button data-next>다음</button>
</div>

/* 짚는 곳만 밝게 남긴다. 바깥은 큰 그림자 한 줄로 어둡게 덮는다 */
.coach-hole { box-shadow: 0 0 0 9999px rgba(20, 22, 26, .5); }

// 한 번만 띄운다. 본 뒤에는 다시 띄우지 않는다
if (!localStorage.getItem('tour:v2')) startTour();
function endTour() { localStorage.setItem('tour:v2', 'done'); }
키와 마크업그때 일어나야 하는 일
Esc건너뛰기를 누른 것과 같이 투어를 끝냅니다
Tab초점이 말풍선 안에서만 돌아서 건너뛰기와 다음 두 단추 사이를 오갑니다
투어를 열고 닫을 때의 초점투어를 열면 초점을 말풍선으로 옮기고, 끝나면 짚던 요소로 돌려놓습니다
aria-describedby짚는 요소와 말풍선을 이 속성으로 연결해 둘 수도 있습니다
모션 줄이기를 켰을 때모션 줄이기를 켠 사람에게는 움직임을 끕니다
확인하는 방법Esc 키만으로 빠져나갈 수 있는지 확인합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

본 적이 있다는 기록을 두는 곳본 적이 있다는 기록을 계정에 저장하면 다른 기기에서도 다시 뜨지 않습니다. 반면 브라우저 저장소에만 저장하면 기기를 바꿀 때마다 또 뜹니다.
저장하는 이름에 투어 버전 붙이기tour:v2처럼 저장하는 이름에 버전을 붙여 두면, 기능이 바뀌었을 때 바뀐 기능만 다시 안내할 수 있습니다.
누구에게 띄울지 정하기이미 그 기능을 써 본 사람에게는 안 띄우는 것이 맞습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

코치마크는 대개 정식 부품이 없어서 직접 만듭니다.

웹직접 만듦
내보내기필터 ▾도움말여기서 내보내요1 / 4건너뛰기다음
투어를 만드는 라이브러리는 많지만, 한 번만 띄우기는 직접 챙겨야 합니다.
iOSTipKit
팁을 언제, 몇 번 띄울지까지 OS가 규칙으로 관리해 줍니다(iOS 17 이상).
안드로이드Tooltip 또는 직접 만듦
정식 부품이 드물어서 대개 직접 만들고, 짚는 곳만 밝게 남기는 효과도 직접 그립니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS의 TipKit에서 눈여겨볼 점은 팁을 '어떻게 그릴지'보다 '언제, 몇 번 띄울지'를 OS가 관리해 준다는 것입니다. 같은 팁은 세 번까지만 띄우고 다른 팁과 겹치지 않게 하는 식의 규칙을 모든 앱이 똑같이 따릅니다. 웹에는 이런 장치가 없기 때문에 우리가 직접 그 규칙을 만들어야 합니다. 적어도 한 번만 띄우기와 겹쳐 띄우지 않기, 이 두 가지는 정해 두는 편이 좋습니다.
