드로어

Drawer · Side panel

드로어는 화면 옆에서 밀려 나오는 판입니다. 넓은 화면에서는 사이드바로 늘 보여 주던 내용을, 화면이 좁아 자리가 모자랄 때 숨겨 두었다가 필요할 때 꺼내 쓰는 방식입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

☰를 눌러 보세요. 드로어가 왼쪽에서 밀려 나오고 뒤쪽 화면은 막힙니다. Esc를 누르거나 오른쪽 빈 곳을 누르면 닫히고, 포커스가 ☰로 돌아갑니다. ☰ 버튼은 햄버거 버튼이라고 부르는데, 이 이름은 드로어를 여는 버튼의 이름이지 드로어의 이름이 아닙니다.

2 이름같은 것을 부르는 여러 이름

한국어드로어, 서랍, 사이드 패널
영어drawer, side panel, off-canvas
같이 쓰는 말뒤쪽 화면을 막고 떠 있는 것은 임시 드로어(temporary), 넓은 화면에서 늘 붙어 있는 것은 고정(permanent) 드로어, 아이콘만 남기고 폭을 좁힌 것은 레일(rail)이라고 부릅니다.
자주 잘못 부르는 이름사이드바 — 늘 보이면 사이드바이고, 숨어 있다가 밀려 나오면 드로어입니다. 같은 내용이 화면 폭에 따라 사이드바가 되기도 하고 드로어가 되기도 합니다.
햄버거 메뉴 — ☰는 드로어를 여는 버튼의 별명이고, 그 버튼을 눌러 나온 판이 드로어입니다.
슬라이드 메뉴 — 말은 통하지만 문서에는 드로어로 적어야 오해가 없습니다.

설정
  1. 스크림 scrim · backdrop임시 드로어에만 있고 고정 드로어에는 없습니다
  2. 패널 panel · drawer surface화면 한쪽 변에 붙고 화면 높이를 다 씁니다. 높이를 다 쓴다는 점이 시트와 다릅니다
  3. 헤더 · 닫기 header무엇을 하는 판인지 알려 주고, 닫기 버튼을 눈에 띄게 둡니다
  4. 내비 목록 nav list링크를 누르면 드로어가 닫힙니다. 닫지 않으면 드로어가 이동한 화면을 가립니다
  5. 현재 위치 표시 current · selected지금 보고 있는 화면을 표시합니다. 스크린 리더에는 aria-current="page"로 알립니다
  6. 구분선 divider항목 묶음을 나눕니다. 묶음마다 제목을 다는 것보다 선 하나가 덜 눈에 띕니다

드로어가 열릴 때 뒤쪽 화면을 덮을지(overlay), 옆으로 밀어낼지(push)도 정해야 합니다. 보통 좁은 화면에서는 덮고, 넓은 화면에서는 밀어냅니다.

5 쓸 때 / 안 쓸 때

드로어를 쓰는 경우

  • 좁은 화면에서 보조 내비게이션으로 쓰던 사이드바를 접어 둘 때
  • 필터 묶음이 길어서 목록을 보면서 조건을 바꾸게 할 때. 오른쪽 드로어를 씁니다
  • 목록 옆에서 한 건을 자세히 보거나 고칠 때

드로어를 쓰지 않는 경우

  • 이 화면의 주요 동작을 담을 때. 드로어에 숨겨 두면 사용자가 찾지 못해 쓰지 않게 됩니다
  • 짧게 한 번 확인받을 때. 이때는 모달을 씁니다
  • 넓은 화면에서 늘 필요한 내용일 때. 접어 두지 말고 사이드바로 고정합니다
  • iOS에서 왼쪽 드로어를 쓸 때. 화면 왼쪽 가장자리에서 밀어 뒤로 가는 시스템 동작과 부딪칩니다

드로어 대신 다른 것을 써야 하는 경우 — 짧게 한 번 확인받는 일이라면 모달을 쓰고, 손가락으로 선택지를 고르게 할 때는 바텀시트가 맞습니다. 누른 요소 바로 옆에 붙어 떠야 하면 팝오버를 씁니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

드로어도 바텀시트와 같은 <dialog> 요소로 만들고, margin과 높이만 다르게 줍니다. 화면 옆에 붙이고 높이를 꽉 채우면 드로어가 됩니다.

<button aria-expanded="false" aria-controls="drawer">☰</button>

<dialog class="drw" id="drawer" aria-labelledby="t">
  <h2 id="t">메일</h2>
  <nav>…</nav>
</dialog>

/* 왼쪽 변에 붙이고 높이를 꽉 채운다. 시트와 다른 부분 */
dialog.drw { margin: 0 auto 0 0; height: 100%; max-height: 100%; }

// 여는 버튼의 상태를 같이 알린다
btn.setAttribute('aria-expanded', 'true');
키와 마크업그때 일어나야 하는 일
Esc드로어가 닫힙니다
Tab임시 드로어에서는 포커스가 드로어 안에서만 돌고, 고정 드로어에서는 포커스를 가두지 않습니다
안의 링크를 눌렀을 때드로어가 닫힙니다. 닫지 않으면 드로어가 이동한 화면을 가립니다
여는 버튼의 상태드로어가 열리고 닫힐 때마다 aria-expanded 값도 함께 바꿉니다
드로어가 닫힐 때포커스가 ☰ 버튼으로 돌아갑니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

열림 상태를 URL에 담기열림 상태를 ?panel=filters처럼 주소에 담으면 뒤로가기로 드로어를 닫을 수 있고, 열린 상태 그대로 링크로 공유할 수도 있습니다. 상태를 어디에 둘지 고르는 문제라서 세션과 토큰 가운데 무엇을 쓸지 정하는 것과 비슷합니다.
주 화면과 따로 불러오는 보조 리소스드로어 내용은 주 화면과 다른 리소스인 경우가 많습니다. 그래서 주 화면 응답에 함께 넣지 말고 드로어를 열 때 따로 가져오면 첫 화면이 빨리 뜹니다.
임시와 고정은 데이터가 같고 표시만 다름임시 드로어와 고정 드로어는 화면 폭에 따라 모양만 바뀔 뿐 데이터는 같습니다. 그러므로 서버 응답을 두 가지로 나눌 필요가 없습니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

드로어는 안드로이드에서 자리 잡은 이름이라 iOS에는 이에 대응하는 표준 부품이 없습니다.

대응하는 표준 부품이 없어서 같은 일을 시트나 화면 전환으로 처리합니다. 왼쪽 드로어는 화면 가장자리에서 밀어 뒤로 가는 가장자리 스와이프와 부딪치기 때문에 권하지 않습니다.
안드로이드Material 3
메일받은 메일보낸 메일
내비게이션 드로어(Navigation drawer) · 드로어라는 이름이 처음 자리 잡은 곳입니다. Modal, Standard, Dismissible로 나누고, 폭을 좁힌 것은 내비게이션 레일이라고 부릅니다.

플랫폼 차이 때문에 자주 생기는 문제 — "드로어 넣어 주세요"라는 말은 안드로이드 개발자에게는 바로 통하지만, iOS에는 드로어라는 부품이 없어서 통하지 않습니다. 그래서 보조 내비게이션처럼 역할로 말하고, iOS에서는 탭 바나 시트 가운데 무엇으로 바꿀지 함께 정해야 합니다.
