드로어

Drawer · Side panel

화면 옆에서 밀려 나오는 판. 넓은 화면에서 늘 보이는 사이드바와 같은 내용을, 자리가 모자랄 때 숨겼다 꺼내 쓰는 것입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

☰ 를 눌러 보세요. 왼쪽에서 밀려 나오고 뒤가 막힙니다. Esc나 오른쪽 빈 곳을 누르면 닫히고, 포커스가 ☰로 돌아갑니다. ☰ 자체는 햄버거 버튼이라 부르는데, 그건 여는 버튼의 이름이지 드로어의 이름이 아닙니다.

2 이름부르는 말이 여러 개다

한국어드로어, 서랍, 사이드 패널
영어drawer, side panel, off-canvas
같이 쓰는 말뒤를 막고 떠 있으면 임시 드로어(temporary), 넓은 화면에서 늘 붙어 있으면 고정(permanent), 아이콘만 남겨 좁힌 것은 레일(rail).
자주 잘못 부름사이드바 — 늘 보이면 사이드바, 숨었다 밀려 나오면 드로어입니다. 같은 내용이 폭에 따라 둘 사이를 오갑니다.
햄버거 메뉴 — ☰ 는 여는 버튼의 별명입니다. 열려 나온 판이 드로어입니다.
슬라이드 메뉴 — 통하기는 하지만 문서에는 드로어로 적는 편이 안전합니다.

한 줄로 — 드로어인지는 옆에서 밀려 나오느냐로 정해집니다. 늘 보이면 사이드바이고, 숨었다 나오면 드로어입니다.

5 해부도부분 이름이 제일 안 알려진 지식

메일 ×

임시 보관
설정
  1. 스크림 scrim · backdrop임시 드로어에만 있다. 고정 드로어에는 없다
  2. 패널 panel · drawer surface한쪽 변에 붙고 화면 높이를 다 쓴다. 이 점이 시트와 다르다
  3. 헤더 · 닫기 header어디로 가는 판인지. 닫기를 눈에 보이게 둔다
  4. 내비 목록 nav list링크를 누르면 드로어는 닫힌다. 안 닫으면 어디로 갔는지 가린다
  5. 현재 위치 표시 current · selected지금 보고 있는 곳. aria-current="page" 로도 알린다
  6. 구분선 divider묶음을 가른다. 선 하나가 제목 하나보다 조용하다

드로어가 열릴 때 뒤쪽 화면을 덮는지(overlay) 옆으로 미는지(push)도 고르는 축입니다. 좁은 화면은 덮기, 넓은 화면은 밀기가 보통입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 보조 내비게이션 — 좁은 화면에서 사이드바를 접어 둘 때
  • 긴 필터 묶음 — 목록을 보면서 조건을 바꾸게 (오른쪽 드로어)
  • 목록 옆에서 한 건을 자세히 보거나 고칠 때

이럴 때는 안 쓴다

  • 이 화면의 주요 동작 — 숨겨 두면 안 쓰게 됩니다
  • 짧은 확인 한 번 → 모달
  • 넓은 화면에서 늘 필요한 것 → 접지 말고 사이드바로 고정합니다
  • 왼쪽 드로어 + iOS — 시스템의 가장자리 스와이프 뒤로가기와 부딪칩니다

대신 이걸 — 짧은 확인이면 모달, 손가락으로 고르는 것이면 바텀시트, 누른 것 옆에 붙어야 하면 팝오버.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

바텀시트와 같은 <dialog>인데 margin과 높이만 다릅니다. 옆에 붙이고 높이를 꽉 채우면 드로어입니다.

<button aria-expanded="false" aria-controls="drawer">☰</button>

<dialog class="drw" id="drawer" aria-labelledby="t">
  <h2 id="t">메일</h2>
  <nav>…</nav>
</dialog>

/* 왼쪽 변에 붙이고 높이를 꽉 채운다 — 시트와 갈리는 곳 */
dialog.drw { margin: 0 auto 0 0; height: 100%; max-height: 100%; }

// 여는 버튼의 상태를 같이 알린다
btn.setAttribute('aria-expanded', 'true');
키일어나야 하는 일
Esc닫힌다
Tab임시 드로어 안에서만 돈다. 고정 드로어는 안 가둔다
링크 누름드로어가 닫힌다. 안 닫으면 이동한 화면을 자기가 가린다
여는 버튼aria-expanded 가 열림/닫힘을 따라간다
닫힐 때포커스가 ☰ 로 돌아간다

9 서버 쪽으로 치면백엔드 감각으로 번역

열림 상태를 URL 에?panel=filters 처럼 주소에 담으면 뒤로가기로 닫히고 링크로 공유됩니다. 상태를 어디에 둘지의 문제라, 세션 vs 토큰과 같은 결정입니다.
보조 리소스드로어 내용은 주 화면과 다른 리소스인 경우가 많습니다. 주 화면 응답에 끼워 넣지 말고 열 때 따로 가져오면 첫 화면이 빨라집니다.
임시 vs 고정 = 같은 데이터, 다른 표시폭에 따라 모양만 바뀌고 데이터는 같습니다. 응답을 둘로 나누지 않습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

드로어는 안드로이드에서 굳은 말이라 iOS 에는 대응하는 표준 부품이 없습니다.

내비게이션 드로어(Navigation drawer) · 이 부품의 원산지입니다. Modal / Standard / Dismissible 로 나누고, 좁힌 것은 내비게이션 레일이라 부릅니다.

자주 생기는 사고 — "드로어 넣어 주세요"는 안드로이드 개발자에게는 바로 통하지만 iOS 쪽에는 그런 부품이 없습니다. 역할(보조 내비게이션)로 말하고, iOS 에서는 탭 바나 시트로 어떻게 바꿀지 같이 정해야 합니다.
