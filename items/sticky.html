스티키

Sticky positioning

스티키는 평소에는 문서 흐름을 따라 움직이다가, 스크롤되어 정해진 선에 닿으면 그 자리에 붙어 있는 요소입니다. 붙박이 머리말과 묶음 머리글은 모두 스티키로 만듭니다.

스티키가 작동하지 않게 만들어 보기를 켜면 머리말이 붙지 않고 그냥 올라갑니다. 실무에서 '스티키가 안 먹어요'라는 문제는 거의 항상 top을 적지 않았거나, 조상에 overflow가 걸렸거나, 부모 높이가 내용과 같은 경우 셋 가운데 하나입니다.

2 이름같은 것을 부르는 여러 이름

한국어스티키, 붙박이, 고정 머리말
영어sticky, sticky header, stuck state
같이 쓰는 말붙은 상태는 스턱(stuck), 붙는 기준선은 오프셋(top·bottom)이라고 부릅니다. 화면에 아예 고정하는 것은 fixed이고, 묶음마다 머리글이 번갈아 붙는 것은 스티키 섹션 헤더라고 합니다.
자주 잘못 부르는 이름fixed — fixed는 화면에 붙어서 스크롤해도 움직이지 않지만, sticky는 부모가 화면을 벗어나면 함께 사라집니다.
float — 스티키와는 전혀 다른 속성으로, 요소 옆으로 글이 흐르게 하는 옛 방식입니다.
스크롤 스파이 — 지금 보고 있는 구역을 메뉴에 표시하는 기능으로, 스티키와는 다른 것입니다.

'스티키가 안 먹어요'의 세 가지 원인 가운데 가장 찾기 어려운 것은 조상의 overflow입니다. 대여섯 단계 위의 래퍼에 overflow: hidden 한 줄이 있으면 스티키는 그 상자를 기준으로 붙으려 하는데, 그 상자는 스크롤되지 않으므로 아무 일도 일어나지 않습니다. 이럴 때는 개발자 도구에서 부모를 거슬러 올라가며 overflow를 찾는 것이 가장 빠릅니다.

6 쓸 때 / 안 쓸 때

스티키를 쓰는 경우

  • 긴 목록의 머리말을 붙여 둘 때. 스크롤해도 무슨 열인지 알 수 있습니다
  • 지금 보는 항목이 몇 월 것인지 알려 주는 묶음 머리글을 둘 때
  • 표의 합계 줄이나 폼의 저장 버튼을 아래에 붙일 때. bottom: 0을 씁니다
  • 긴 글의 목차를 붙여 둘 때

스티키를 쓰지 않는 경우

  • 화면을 반쯤 덮을 만큼 큰 요소를 붙일 때. 내용을 볼 자리가 없어집니다
  • 폰에서 머리말과 꼬리말을 둘 다 붙일 때. 가운데 내용 영역이 너무 좁아집니다
  • 스크롤할 때마다 모양이 크게 바뀌는 머리말을 만들 때. 화면이 덜컥거려 보입니다
  • fixed로 해도 되는 것을 굳이 sticky로 만들 때. 부모를 벗어나면 함께 사라집니다

스티키 대신 다른 것을 써야 하는 경우 — 부모와 상관없이 화면에 완전히 고정하려면 position: fixed를 씁니다. 화면 맨 위 머리말을 어떻게 꾸밀지는 앱바에서, 상자 안쪽만 스크롤하게 만드는 방법은 넘침에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙스티키가 작동하지 않을 때 확인할 것

스티키는 두 줄이면 됩니다. 그런데도 작동하지 않는다면 그 두 줄이 아니라 조상 요소를 살펴봐야 합니다.

.table-head {
  position: sticky;
  top: 0;          /* 이 줄이 없으면 아무 일도 안 일어난다 */
  z-index: 2;       /* 없으면 목록 줄이 머리말 위로 지나간다 */
  background: var(--surface); /* 없으면 뒤가 비쳐 보인다 */
}

/* 머리말 아래에 한 겹 더 쌓기 */
.section-head { position: sticky; top: 36px; z-index: 1; }

/* 붙었을 때만 그림자 — 브라우저가 알려 준다 */
.table-head { top: -1px; }
.table-head:is(.is-stuck) { box-shadow: 0 2px 6px rgba(20,22,26,.1); }
지킬 규칙지키는 방법
top(또는 bottom) 적기적지 않으면 아무 일도 일어나지 않습니다. 작동하지 않는 원인 가운데 가장 흔합니다
조상의 overflow 확인하기스크롤되는 조상에 걸려 있으면 그 상자를 기준으로 붙습니다. 세 원인 가운데 가장 찾기 어렵습니다
부모 높이 확인하기부모 높이가 내용과 같으면 붙어 있을 구간이 없습니다
z-index와 배경 함께 주기둘 다 없으면 목록 줄이 머리말 위로 지나가고, 머리말 뒤가 비쳐 보입니다
키보드 포커스가 가려지지 않게 하기붙박이 머리말이 Tab으로 옮겨 간 요소를 가릴 수 있으므로, scroll-margin-top으로 그만큼 띄웁니다
머리말 높이 고정하기머리말 높이가 바뀌면 아래 겹의 top 값도 어긋나기 때문입니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

JS 없이 CSS만으로 동작함예전에는 스크롤 이벤트로 스티키를 흉내 냈지만, 지금은 JS가 전혀 필요 없어서 스크롤이 훨씬 부드럽습니다.
붙은 상태를 알아야 할 때붙었을 때만 그림자를 넣으려면 IntersectionObserver로 붙었는지 감시합니다. 스크롤 이벤트마다 위치를 재면 화면이 느려지기 때문입니다.
가상 스크롤과 함께 쓸 때화면 밖으로 나간 줄을 지웠다가 다시 그리는 목록에서는 머리말이 그 안에 들어가면 줄과 함께 사라집니다. 그래서 머리말은 가상 스크롤 영역 밖에 둡니다.
표 열 이름에 걸 때sticky는 <thead> 자체가 아니라 <th>에 걸어야 합니다. 브라우저마다 다르게 동작하던 예전 사정 때문입니다.
