Sticky positioning

평소엔 흐름에 있다가 정해진 선에 닿으면 거기 붙는 것. 붙박이 머리말과 묶음 머리글이 다 이것입니다.

목록을 굴려 보세요. 머리말은 맨 위에 붙어 있고, '11월 1주' 같은 묶음 머리글은 하나씩 교대합니다 — 스티키는 자기 부모 안에서만 붙어 있기 때문입니다.
안 먹게 만들어 보기를 켜면 그냥 올라가 버립니다. 실무에서 '스티키가 안 먹어요'는 거의 늘 아래 셋 중 하나입니다 — top을 안 적었거나, 조상에 overflow가 걸렸거나, 부모 높이가 내용과 같거나.

2 이름부르는 말이 여러 개다

한국어스티키, 붙박이, 고정 머리말
영어sticky, sticky header, stuck state
같이 쓰는 말붙은 상태를 스턱(stuck), 붙는 기준선을 오프셋(top·bottom)이라 합니다. 화면에 아예 못 박는 것은 fixed, 묶음마다 머리글이 교대하는 것은 스티키 섹션 헤더입니다.
자주 잘못 부름fixed — fixed 는 화면에 붙어 끝까지 안 움직입니다. sticky 는 부모를 벗어나면 같이 사라집니다.
float — 전혀 다른 것입니다. float 는 글이 옆으로 흐르게 하는 옛 방식입니다.
스크롤 스파이 — 지금 보는 구역을 메뉴에 표시하는 것은 다른 기능입니다.

'스티키가 안 먹어요'의 원인 셋 중 가장 찾기 어려운 것이 조상의 overflow입니다. 대여섯 단계 위의 래퍼에 overflow: hidden 한 줄이 있으면, 스티키는 그 상자를 기준으로 붙으려 하고 그 상자는 안 굴러가므로 아무 일도 안 일어납니다. 개발자 도구에서 부모를 거슬러 올라가며 overflow를 찾는 것이 가장 빠릅니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 긴 목록의 머리말 — 무슨 열인지 잊지 않게
  • 묶음 머리글 — '지금 보는 게 몇 월 것인지'
  • 표의 합계 줄이나 폼의 저장 버튼 — bottom: 0
  • 긴 글의 목차

이럴 때는 안 쓴다

  • 화면을 반쯤 덮을 만큼 큰 것 — 볼 자리가 없어집니다
  • 폰에서 머리말·꼬리말을 둘 다 붙이는 것 — 가운데가 너무 좁아집니다
  • 스크롤 때마다 모양이 크게 바뀌는 머리말 — 덜컥거려 보입니다
  • fixed로 해도 되는 것을 굳이 sticky 로 — 부모를 벗어나면 사라집니다

대신 이걸 — 화면에 완전히 못 박으려면 position: fixed, 머리말 자체는 앱바, 안쪽만 굴리려면 넘침.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙안 먹을 때 볼 목록

두 줄이면 됩니다. 안 먹는다면 그 두 줄이 아니라 조상을 봐야 합니다.

.table-head {
  position: sticky;
  top: 0;          /* 이 줄이 없으면 아무 일도 안 일어난다 */
  z-index: 2;       /* 없으면 지나가는 줄이 위로 지나간다 */
  background: var(--surface); /* 없으면 뒤가 비쳐 보인다 */
}

/* 머리말 아래에 한 겹 더 쌓기 */
.section-head { position: sticky; top: 36px; z-index: 1; }

/* 붙었을 때만 그림자 — 브라우저가 알려 준다 */
.table-head { top: -1px; }
.table-head:is(.is-stuck) { box-shadow: 0 2px 6px rgba(20,22,26,.1); }
규칙지켜야 하는 것
top(또는 bottom)을 적는다없으면 아무 일도 안 일어난다. 원인 1위
조상의 overflow를 의심한다스크롤되는 조상에 걸려 있으면 그 상자 기준이 된다. 가장 찾기 어렵다
부모 높이를 본다부모 높이가 내용과 같으면 붙어 있을 구간이 없다

키보드도 생각한다붙박이 머리말이 Tab으로 간 요소를 가릴 수 있다. scroll-margin-top으로 띄운다

9 서버 쪽으로 치면백엔드 감각으로 번역

스티키는 순수 CSS 다예전에는 스크롤 이벤트로 흉내 냈습니다. 지금은 JS 가 전혀 필요 없고, 그래서 스크롤이 훨씬 부드럽습니다.
붙은 상태를 알아야 할 때그림자를 붙었을 때만 넣으려면 IntersectionObserver로 감시합니다 — 스크롤 이벤트로 매번 재면 느려집니다.
가상 스크롤과 함께줄을 지웠다 그렸다 하는 목록에서는 머리말이 그 안에 들어가면 같이 사라집니다. 머리말은 가상 영역 밖에 둡니다.
표 열 이름<thead> 자체가 아니라 <th>에 걸어야 합니다. 브라우저마다 다르게 동작하던 오래된 사정입니다.
