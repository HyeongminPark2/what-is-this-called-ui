메가 메뉴

Mega menu

메가 메뉴는 분류가 수십 개인 사이트에서 여러 단의 항목을 한 번에 펼쳐 보여 주는 큰 메뉴입니다. 설계할 때는 항목 배치만큼 마우스가 지나가는 경로를 신경 써야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

메가 메뉴에서 가장 자주 생기는 문제는 대각선 이동입니다. 머리글자에서 패널 오른쪽 아래 항목으로 마우스를 곧장 옮기면 마우스가 옆 머리글자 위를 지나가면서 메뉴가 바뀌고, 가려던 항목이 사라집니다. 데모는 이 경로를 따라 마우스를 움직여 보고 가는 동안 메뉴가 몇 번 바뀌거나 닫혔는지 셉니다.
열기를 100ms, 닫기를 300ms 늦추면 머리글자 위를 잠깐 지나가는 마우스로는 메뉴가 바뀌지 않고, 머리글자와 패널 사이 빈틈을 잠깐 지나도 메뉴가 열린 채로 유지됩니다. 눌러야 열림으로 두면 마우스 이동과는 아예 상관이 없어지고, 키보드와 터치에서도 똑같이 동작합니다.

2 이름같은 것을 부르는 여러 이름

한국어메가 메뉴, 대형 드롭다운, 전체 분류 메뉴
영어mega menu, mega dropdown, flyout menu
같이 쓰는 말마우스가 지나갈 만한 삼각형 영역을 미리 열어 두는 기법은 의도 삼각형(intent triangle), 열고 닫기를 잠깐 늦추는 기법은 호버 인텐트(hover intent)라고 부릅니다. 작고 항목이 한 줄로 늘어선 메뉴는 그냥 드롭다운, 옆으로 펼쳐지는 메뉴는 플라이아웃이라고 합니다.
자주 잘못 부르는 이름팝오버 — 팝오버는 특정 요소 옆에 붙어 뜨는 작은 판이고, 메가 메뉴는 화면 폭에 가깝게 펼쳐지는 큰 판입니다.
셀렉트 — 셀렉트는 값을 고르는 입력 부품이고, 다른 화면으로 가는 길 안내 부품이 아닙니다.
사이드바 — 사이드바는 화면 옆에 늘 보이는 메뉴이고, 메가 메뉴는 필요할 때만 펼쳐집니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

길 안내 부품은 모두 누르면 다른 곳으로 옮겨 간다는 점이 같습니다. 그래서 아래 네 가지를 물어보면 서로 구별할 수 있습니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음
스테퍼내용 위 · 옆같은 흐름의 다음 단계번호와 완료 표시로3~5단계
트리뷰화면 옆계층 아래로펼친 가지로깊이 3단까지
앵커 내비내용 옆같은 문서 안보는 절을 밝혀5~12
뒤로가기화면 왼쪽 위바로 앞 화면안 보여 준다하나
메가 메뉴앱바 아래전역 · 여러 갈래열린 갈래로20~60

메가 메뉴를 한 줄로 정리하면 — 대각선 문제는 열기 100ms, 닫기 300ms 두 가지 지연만으로 대부분 해결됩니다. 그래도 해결되지 않으면 눌러야 열리게 하세요.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

머리글자 — 갈래 대여섯 개
패널 — 여러 단을 한 번에 펼친다
열기 100ms · 닫기 300ms 늦추기
대각선 — 옆 머리글자를 스치면 바뀐다
aria-expanded — 열렸는지 알린다
Esc 로 닫고 머리글자로 초점이 돌아온다
  1. 머리글자 대여섯 개이보다 많으면 머리글자 줄부터 한 줄에 다 들어가지 않습니다
  2. 패널 여러 단한 분류 안의 항목을 한 번에 보여 줍니다
  3. 지연 100 / 300ms대각선 문제를 가장 적은 품으로 고치는 방법입니다
  4. 대각선 스치면 바뀜마우스가 목표 항목까지 직선으로 움직이는 것이 원인입니다
  5. aria-expanded 열렸는지메뉴가 열렸는지를 스크린 리더에도 알립니다
  6. Esc 닫고 돌아오기메뉴를 닫고 포커스를 머리글자로 되돌립니다

호버로 여는 메뉴는 따로 챙겨야 할 것이 생깁니다. 터치 화면과 키보드에는 호버가 없기 때문입니다. 그래서 호버로 열더라도 누르면 열리는 방법을 반드시 함께 둬야 하는데, 누르면 열리는 방법이 있으면 호버는 사실상 보조 수단이 됩니다.
호버가 없는 환경에서는 머리글자를 처음 탭하면 메뉴가 열리고 두 번째 탭에서야 그 분류 화면으로 들어가는데, 이렇게 하면 머리글자가 가리키는 분류 화면으로 바로 갈 방법이 없어집니다. 패널 안에 '의류 전체 보기' 같은 줄을 하나 두면 그 화면으로 갈 수 있습니다.

6 쓸 때 / 안 쓸 때

메가 메뉴를 쓰는 경우

  • 열기는 100ms, 닫기는 300ms 늦출 때
  • 패널 안에 '○○ 전체 보기' 줄을 둘 때
  • 폰에서는 드로어나 한 단씩 들어가는 화면으로 바꿀 때

메가 메뉴를 쓰지 않는 경우

  • 마우스가 닿자마자 열고 벗어나자마자 닫을 때. 대각선으로 움직이면 메뉴가 바뀌거나 닫힙니다
  • 호버로만 열 때. 터치 화면과 키보드에서는 메뉴를 열 수 없습니다
  • 머리글자를 여덟 개 넘게 둘 때
  • 패널이 화면 밖까지 넘어갈 때. 오른쪽 끝 분류가 잘립니다

메가 메뉴 대신 다른 것을 써야 하는 경우 — 작게 뜨면 팝오버, 늘 보이면 사이드바, 폰에서는 드로어, 찾기가 목적이면 검색.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

호버로 열더라도 누르면 열리는 방법을 함께 둡니다. 그래서 머리글자는 <button>으로 만듭니다.

<nav aria-label="전체 분류">
  <button aria-expanded="false" aria-controls="m-wear">의류</button>
  <div id="m-wear" hidden>
    <a href="/wear">의류 전체 보기</a>
    …
  </div>
</nav>

// 잠깐 지나가는 마우스로는 열지 않고, 잠깐 벗어나도 닫지 않는다
let openT, closeT;
bar.addEventListener('pointerover', e => {
  clearTimeout(closeT);
  clearTimeout(openT);                       // 머리글자를 벗어나면 예약 취소
  const b = e.target.closest('button');
  if (b) openT = setTimeout(() => open(b), 100);
});
nav.addEventListener('pointerleave', () => {
  closeT = setTimeout(closeAll, 300);
});
키와 동작그때 일어나야 하는 일
Tab머리글자를 하나씩 지나가고, 메뉴가 열려 있으면 패널 안으로 들어갑니다
Enter · Space눌러서 메뉴를 엽니다. 호버 없이도 메뉴를 여는 방법입니다
← →머리글자 사이를 옮겨 다닙니다(role="menubar"를 쓸 때)
Esc메뉴를 닫고 포커스를 머리글자로 되돌립니다
aria-expanded메뉴가 열렸는지 알리며, 머리글자 쪽에 붙입니다
확인하는 법마우스를 쓰지 않고 Tab만으로 셋째 분류의 넷째 항목까지 가 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

분류는 한 번에메뉴에 쓰는 분류는 거의 바뀌지 않으므로 한 번 받아서 캐시해 둡니다. 머리글자에 마우스를 올릴 때마다 요청하면 메뉴가 늦게 열립니다.
깊이를 미리 줄여메가 메뉴는 보통 두 단까지만 펼칩니다. 서버가 세 단까지 내려 주면 화면에서 셋째 단을 따로 접어야 하므로, 서버에서 미리 두 단으로 줄여 보냅니다.
인기 갈래분류별 클릭 수 데이터가 있으면 많이 찾는 분류를 맨 앞 칸에 올릴 수 있습니다. 데이터가 없으면 미리 정해 둔 순서대로 보여 줍니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

메가 메뉴는 데스크톱 웹에서 쓰는 부품이라서 모바일 지침에서는 다루지 않습니다.

웹직접 만듦
의류생활용품식품아우터패딩상의티셔츠
정해진 부품이 없어서 지연과 키보드 동작을 모두 직접 구현합니다.
iOS없다 — 드릴다운
›
한 단씩 새 화면으로 넘어가며 들어갑니다. 앞 화면으로는 ‹ 버튼으로 돌아옵니다.
안드로이드없다 — 드로어
내비게이션 드로어가 같은 역할을 합니다. 하위 분류는 접었다 펼 수 있게 둡니다.

플랫폼 차이 때문에 자주 생기는 문제 — 폰에서 메가 메뉴를 쓰지 않는 것은 호버가 없고 화면이 좁기 때문입니다. 이런 조건에서 같은 정보를 보여 주려면 한 단씩 들어가는 방법밖에 없어서 iOS와 안드로이드 모두 이 방식을 씁니다. 웹에서도 폰 폭에서는 메가 메뉴 전체를 접고 드로어로 바꾸는 것이 맞습니다. 메가 메뉴를 작게 줄여 폰 화면에 넣으려 하면 메가 메뉴로도 드로어로도 제대로 쓸 수 없게 됩니다.
