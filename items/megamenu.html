메가 메뉴

Mega menu

갈래가 수십 개인 사이트에서 한 번에 펼쳐 보여 주는 큰 메뉴입니다. 손이 지나가는 길이 설계의 절반입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

메가 메뉴의 고질병은 대각선입니다 — 머리글자에서 패널 오른쪽 아래 항목으로 곧장 가면 손이 옆 머리글자 위를 스쳐 메뉴가 바뀌고, 가려던 항목이 사라집니다. 데모가 그 경로를 흉내 내 가는 길에 몇 번 끊겼는지 셉니다.
열기를 100ms 늦추고 닫기를 300ms 늦추면 스쳐 지나가는 손은 메뉴를 못 바꾸고, 잠깐 빈틈을 지나도 열린 채로 버팁니다. 눌러야 열림으로 두면 지나가는 손과 아예 상관이 없고 키보드·터치에서도 같게 동작합니다.

2 이름부르는 말이 여러 개다

한국어메가 메뉴, 대형 드롭다운, 전체 분류 메뉴
영어mega menu, mega dropdown, flyout menu
같이 쓰는 말손이 지나갈 만한 세모 모양을 미리 열어 두는 기법을 의도 삼각형(intent triangle), 열고 닫기를 늦추는 것을 호버 인텐트(hover intent)라 부릅니다. 작고 한 줄짜리는 그냥 드롭다운, 옆으로 펼쳐지는 것은 플라이아웃입니다.
자주 잘못 부름팝오버 — 팝오버는 어딘가에 붙어 뜨는 작은 판입니다.
셀렉트 — 셀렉트는 값을 고르는 것이지 길 안내가 아닙니다.
사이드바 — 사이드바는 늘 보이는 자리입니다.

3 가르는 기준형제들과 비교하는 네 축

길 안내 부품은 모두 '누르면 어디론가 간다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음
스테퍼내용 위 · 옆같은 흐름의 다음 단계번호와 완료 표시로3~5단계
트리뷰화면 옆계층 아래로펼친 가지로깊이 3단까지
앵커 내비내용 옆같은 문서 안보는 절을 밝혀5~12
뒤로가기화면 왼쪽 위바로 앞 화면안 보여 준다하나
메가 메뉴앱바 아래전역 · 여러 갈래열린 갈래로20~60

한 줄로 — 지연 두 개로 거의 다 고쳐집니다 — 열기 100ms, 닫기 300ms. 안 되면 눌러야 열리게 하세요.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

머리글자 — 갈래 대여섯 개
패널 — 여러 단을 한 번에 펼친다
열기 100ms · 닫기 300ms 늦추기
대각선 — 옆 머리글자를 스치면 바뀐다
aria-expanded — 열렸는지 알린다
Esc 로 닫고 머리글자로 초점이 돌아온다
  1. 머리글자 대여섯 개더 늘면 머리줄이 먼저 무너진다
  2. 패널 여러 단갈래 안을 한 번에 보인다
  3. 지연 100 / 300ms가장 싼 수리
  4. 대각선 스치면 바뀜손의 직선 경로가 원인
  5. aria-expanded 열렸는지소리로도 알린다
  6. Esc 닫고 돌아오기초점이 머리글자로

호버로 여는 메뉴에는 공짜가 없습니다 — 터치에는 호버가 없고, 키보드에도 없습니다. 그래서 호버로 열더라도 누르면 열리는 길을 반드시 같이 둬야 하고, 그 길이 있으면 사실 호버는 덤입니다.
호버가 없는 세계에서는 첫 탭이 '열기'가 되고 두 번째 탭이 '들어가기'가 되는데, 그러면 머리글자 자체로 가는 길이 막힙니다. 패널 안에 '의류 전체 보기' 같은 줄을 하나 두면 그 길이 살아납니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 열기 100ms · 닫기 300ms 늦추기
  • 패널 안에 '○○ 전체 보기' 줄 두기
  • 폰에서는 드로어나 한 단씩 들어가는 화면으로 바꾸기

이럴 때는 안 쓴다

  • 닿자마자 열고 떠나자마자 닫기 — 대각선에서 끊긴다
  • 호버로만 열기 — 터치·키보드에서 못 쓴다
  • 머리글자를 여덟 개 넘게 두기
  • 패널을 화면 밖까지 늘리기 — 오른쪽 끝 갈래가 잘린다

대신 이걸 — 작게 뜨면 팝오버, 늘 보이면 사이드바, 폰에서는 드로어, 찾기가 목적이면 검색.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

호버로 열더라도 누르면 열리는 길을 같이 둡니다.

<nav aria-label="전체 분류">
  <button aria-expanded="false" aria-controls="m-wear">의류</button>
  <div id="m-wear" hidden>
    <a href="/wear">의류 전체 보기</a>
    …
  </div>
</nav>

// 스쳐 가는 손은 열지 않고, 잠깐 벗어나도 안 닫는다
let openT, closeT;
bar.addEventListener('pointerover', e => {
  clearTimeout(closeT);
  clearTimeout(openT);                       // 머리글자를 벗어나면 예약 취소
  const b = e.target.closest('button');
  if (b) openT = setTimeout(() => open(b), 100);
});
nav.addEventListener('pointerleave', () => {
  closeT = setTimeout(closeAll, 300);
});
키일어나야 하는 일
Tab머리글자를 하나씩 지나간다. 열려 있으면 패널 안으로 들어간다
Enter · Space눌러서 연다 — 호버 없이도 되는 길
← →머리글자 사이를 옮긴다 (role="menubar" 를 쓸 때)
Esc닫고 초점을 머리글자로 되돌린다
aria-expanded열렸는지. 머리글자 쪽에 붙인다
확인하는 법마우스를 안 쓰고 Tab 만으로 셋째 갈래의 넷째 항목까지 가 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

분류는 한 번에메뉴에 쓰는 분류는 거의 안 바뀌니 한 번 받아 캐시합니다. 머리글자마다 요청하면 지연이 커집니다.
깊이를 미리 줄여메가 메뉴는 보통 두 단까지만 폅니다 — 서버가 세 단을 주면 화면이 접어야 합니다.
인기 갈래클릭 수가 있으면 맨 앞 칸에 올릴 수 있습니다 — 없으면 정해 둔 차례대로입니다.

안드로이드없다 — 드로어
내비게이션 드로어가 같은 자리입니다. 하위 갈래는 접었다 펴는 꼴로 둡니다.

자주 생기는 사고 — 메가 메뉴가 폰에 없는 것은 호버가 없고 화면이 좁아서입니다. 둘 다 없는 조건에서 같은 정보를 보이려면 한 단씩 들어가는 수밖에 없고, 그래서 iOS·안드로이드 모두 그 길을 씁니다. 웹에서도 폰 폭에서는 메가 메뉴를 통째로 접고 드로어로 바꾸는 것이 맞습니다 — 작게 줄여 넣으려 하면 둘 다 못 쓰게 됩니다.
