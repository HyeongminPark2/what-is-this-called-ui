칩

Chip · tag · pill

칩은 한 낱말을 담은 작은 알약 모양의 부품입니다. 생김새는 하나인데 필터 칩, 입력 칩, 표시 칩 세 가지가 서로 다른 일을 하기 때문에 특히 많이 헷갈립니다.

새 탭에서 열기 ↗

위는 눌러서 목록을 거르는 필터 칩, 가운데는 사용자가 넣은 값이라 뗄 수 있는 입력 칩, 아래는 라벨일 뿐이라 눌리지 않는 표시 칩입니다.
칩을 ×로 지워 보세요. 포커스가 사라지지 않고 다음 칩으로 넘어갑니다. 지운 칩에 있던 포커스를 그대로 두면 포커스가 갈 곳을 잃고 화면 맨 위로 돌아가 버리는데, 지울 수 있는 칩에서 특히 흔한 오류입니다.

2 이름같은 것을 부르는 여러 이름

한국어칩, 태그, 필터 칩, 알약
영어chip, tag, pill, token, filter chip
같이 쓰는 말Material은 칩을 어시스트(assist) · 필터(filter) · 인풋(input) · 서제스천(suggestion) 네 가지로 나눕니다. 입력칸 안에 들어간 칩은 토큰(token)이라고도 하고, 칩을 떼는 ×는 딜리트 아이콘이라고 부릅니다.
자주 잘못 부르는 이름배지 — 칩과 가장 자주 헷갈리는 부품입니다. 배지는 다른 요소에 붙어서 알리기만 하고, 칩은 누르거나 뗄 수 있습니다.
버튼 — 칩도 누를 수 있지만, 칩을 누르면 값이 켜지거나 꺼질 뿐 저장이나 전송 같은 동작이 일어나지는 않습니다.
세그먼티드 컨트롤 — 세그먼티드 컨트롤은 칸이 서로 붙어 있고 하나만 고를 수 있는 반면, 필터 칩은 여럿을 함께 고를 수 있습니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

표시 부품은 모두 무언가를 보여 주기만 한다는 점이 같아서, 아래 네 가지를 물어봐야 서로 구별됩니다.

무엇을 담는가부품 전체를 누를 수 있는가여러 개가 어떻게 모이는가내용이 길어지면 어떻게 하는가
카드한 덩어리보통 눌린다그리드로 늘어선다높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로 쌓인다말줄임한다
아바타사람·조직 하나눌리지 않는다겹쳐 쌓는다크기는 고정하고 넘치면 +N으로 줄인다
배지숫자나 한 낱말눌리지 않는다혼자 놓이지 않고 다른 요소에 붙는다크기는 고정하고 넘치면 99+로 줄인다
칩한 낱말눌린다가로로 늘어서다 줄을 바꾼다말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로 늘어선다단위를 줄인다(1.2만)
타임라인사건들의 순서항목만 눌린다세로 선으로 잇는다아래로 길어진다
별점점수 하나읽기용은 눌리지 않는다줄 안에 들어간다별 다섯 개로 고정된다
아이콘뜻 하나혼자서는 눌리지 않는다글자 옆에 붙는다아이콘은 그대로 두고 옆 글자가 길어진다
썸네일그림 하나보통 눌린다격자로 늘어선다칸은 고정하고 사진을 자르거나 여백을 남긴다
테이블 행한 건의 여러 값행 전체나 주 열만 눌린다세로로 쌓인다말줄임한다
키-값 목록이름과 값의 짝눌리지 않는다세로로 쌓인다값이 먼저 잘린다
미디어 오브젝트그림과 글보통 눌린다세로 목록으로 쌓인다글 쪽만 늘어난다
접히는 글제목과 본문제목이 눌린다세로로 쌓는다접어 둔다
태그한 낱말눌리지 않는다가로로 늘어서다 줄을 바꾼다말줄임하거나 +N으로 접는다

칩을 한 줄로 정리하면 — 칩은 누르거나 뗄 수 있습니다. 누를 수도 뗄 수도 없다면 그건 칩이 아니라 배지이거나 그냥 글자입니다.

5 해부도부분마다 붙은 이름

검토 중 ×
켜진 칩은 바탕과 테두리가 함께 바뀜. 색만 바꾸면 알아보기 어려움
전체검토 중승인됨거절됨
  1. 칩 chip알약 모양의 한 덩어리입니다. 높이가 32px 안팎이라서 버튼보다 작습니다
  2. 라벨 label한 낱말을 담습니다. 글이 길어지면 칩도 길어지므로 글자 수 상한을 정해 둡니다
  3. 지우기 delete icon입력 칩에만 붙습니다. 칩 본체와는 별도로 누르는 곳이라서 스크린 리더가 읽을 이름을 따로 붙여야 합니다
  4. 켜짐 표시 selected칩이 켜지면 바탕, 테두리, 글자색이 함께 바뀝니다. 체크 아이콘을 넣기도 합니다
  5. 무리 chip group칩들이 모인 줄입니다. role="group"으로 묶고 이름을 붙입니다

입력 칩에는 칩 본체와 × 두 가지, 즉 누를 것이 둘 있습니다. 그래서 키보드 포커스는 칩마다 두 번 멈추고, 스크린 리더는 '홍길동', '홍길동 빼기'처럼 두 번 읽습니다. 이때 ×의 이름을 그냥 '삭제'로 두면 칩이 열 개일 때 '삭제'를 열 번 읽어서 무엇을 지우는지 알 수 없습니다.

6 쓸 때 / 안 쓸 때

칩을 쓰는 경우

  • 상태, 기간, 분류로 목록을 빠르게 거를 때
  • 받는 사람이나 태그처럼 사용자가 넣은 값을 여러 개 쌓아 보여 줄 때
  • 고를 것이 미리 정해져 있고 개수가 적을 때

칩을 쓰지 않는 경우

  • 누르면 동작이 일어나야 할 때. 동작은 버튼으로 만들고, 칩은 값을 다룰 때만 씁니다
  • 선택지가 열 개를 넘을 때. 콤보박스나 필터 패널을 씁니다
  • 하나만 골라야 하고 선택지가 2~4개일 때. 세그먼티드 컨트롤을 씁니다
  • 누를 수 없는 칩에 테두리와 호버 효과를 줄 때. 사용자가 누를 수 있는 줄 알고 눌러 봅니다

칩 대신 다른 것을 써야 하는 경우 — 다른 요소에 붙어서 알리기만 하면 배지를 쓰고, 몇 안 되는 선택지 가운데 하나만 골라야 하면 세그먼티드 컨트롤을 씁니다. 선택지가 많다면 콤보박스가 맞습니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

필터 칩은 켜고 끄는 버튼이므로 aria-pressed로 상태를 알립니다. 입력 칩의 ×에는 무엇을 지우는지까지 이름에 적습니다.

<!-- 필터 칩: 켜고 끄는 버튼 -->
<div role="group" aria-label="상태로 거르기">
  <button class="chip" aria-pressed="true">검토 중</button>
  <button class="chip" aria-pressed="false">승인됨</button>
</div>

<!-- 입력 칩: 본체와 × 를 따로 누른다 -->
<span class="chip">홍길동
  <button aria-label="홍길동 빼기">×</button>
</span>

// 지운 뒤 포커스를 옮긴다. 안 옮기면 포커스가 화면 맨 위로 돌아간다
chips.splice(i, 1); render();
(next ?? input).focus();
키와 마크업그때 일어나야 하는 일
Tab포커스가 칩마다 한 번 멈춥니다. 입력 칩에서는 두 번(본체와 ×) 멈춥니다
Enter · Space필터 칩을 켜고 끕니다
Backspace입력칸이 비어 있을 때 누르면 마지막 칩을 뺍니다. 메일 앱에서 굳어진 관례입니다
칩을 지운 뒤의 포커스포커스를 다음 칩으로, 다음 칩이 없으면 입력칸으로 옮깁니다. 지운 칩에 두면 포커스가 사라집니다
× 버튼의 이름aria-label="홍길동 빼기" 처럼 이름을 붙입니다. 그냥 '삭제'라고 하면 칩 열 개의 ×가 모두 같은 이름이 됩니다
칩 무리의 이름role="group" + aria-label로 무엇을 기준으로 거르는 칩인지 알립니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

필터 칩은 질의 조건켜진 칩은 질의의 WHERE 조건이 됩니다. 칩이 여럿 켜질 수 있으므로 조건을 AND로 묶을지 OR로 묶을지 먼저 정해야 하는데, 보통 같은 갈래의 칩끼리는 OR, 갈래가 다른 칩끼리는 AND로 묶습니다.
필터를 주소에 담기?status=wait,ok&period=week처럼 필터를 주소에 담아 두면 주소 공유와 뒤로가기로도 같은 필터가 유지됩니다. 주소에 담지 않으면 새로고침할 때 필터가 풀립니다.
칩에 건수를 붙일 때칩에 '검토 중 7'처럼 건수를 붙이려면 거르기 전의 전체 목록에서 세어야 합니다. 이미 거른 결과에서 세면 지금 켜진 칩에 해당하는 건수만 나옵니다.
입력 칩이 서버로 보내는 값화면에는 이름이 보이지만 서버로 보내는 값은 ID입니다. 칩마다 ID를 함께 들고 있어야 이름이 같은 사람끼리 섞이지 않습니다.

칩은 안드로이드에서는 규격이 또렷하게 정해진 부품이지만, iOS에는 같은 이름의 부품이 없습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "칩으로 해 주세요"라는 요청을 받으면 안드로이드에서는 네 가지 종류 가운데 어느 것인지까지 정해야 하고, iOS에는 그런 부품이 없어서 세그먼티드 컨트롤이나 메뉴로 다시 설계해야 합니다. 웹, iOS, 안드로이드가 같은 화면을 만든다면, 그 칩이 목록을 거르는 칩인지 사용자가 넣은 값을 보여 주는 칩인지부터 합의하세요.
