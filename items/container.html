컨테이너와 최대 폭

Container · max-width

컨테이너는 화면에서 내용이 들어가는 가운데 칸입니다. 대부분의 사이트가 폭에 상한을 걸고 가운데에 두는 같은 두 줄로 이 칸을 만듭니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 움직이면 한 줄에 실제로 몇 글자가 들어가는지 재서 알려 줍니다. 읽는 글은 한 줄에 45~75자일 때 읽기 편합니다.
상한 없애기를 켜 보세요. 넓은 화면에서 글줄이 끝까지 늘어나면 한 줄을 다 읽고 돌아올 때 다음 줄의 첫 글자를 찾기 어려워집니다. 긴 글이 읽기 힘든 이유는 글꼴보다 줄 길이에 있을 때가 많습니다.

2 이름같은 것을 부르는 여러 이름

한국어컨테이너, 최대 폭, 가운데 칸, 래퍼
영어container, wrapper, max-width, measure, line length
같이 쓰는 말한 줄의 글자 수는 글줄 길이(measure · line length)라고 하고, 폭을 재는 단위 ch는 그 글꼴에서 '0' 한 글자의 너비입니다. 화면 양옆에 남기는 여백은 거터나 페이지 마진이라고 부르고, 폭에 따라 짜임을 바꾸는 기능은 컨테이너 쿼리(container query)라고 합니다.
자주 잘못 부르는 이름width와 max-width — width: 1200px은 좁은 화면에서도 1200px을 유지해서 가로 스크롤이 생깁니다. 반면 max-width는 이 값보다 커지지만 않게 막습니다.
컨테이너 쿼리 — 부모 폭에 따라 스타일을 바꾸는 기능으로, 이름만 비슷하고 컨테이너와는 다른 것입니다.
컨테이너(도커) — 서버에서 쓰는 도커 컨테이너는 이름만 같고 전혀 다른 개념입니다.

3 화면 폭에 따른 모습화면 폭과 상한에 따라 달라지는 칸의 너비

4 해부도부분마다 붙은 이름

글줄이 너무 길면 다음 줄의 첫 글자를 찾기 어렵습니다.
max-width: 65ch
margin-inline: auto
padding-inline: 16px 좁은 화면의 양옆 여백
width: 1200px 좁은 화면에서 가로 스크롤이 생김
  1. 바깥 칸 page화면 전체입니다. 여기에는 폭 제한을 두지 않습니다
  2. 컨테이너 container · wrapper내용이 들어가는 가운데 칸으로, 사이트 레이아웃의 뼈대가 됩니다
  3. 최대 폭 max-width칸이 이 값보다 넓어지지 않게 막습니다. 읽는 글은 65ch 정도로 잡습니다
  4. 가운데 두기 margin-inline: auto남은 자리를 양옆에 똑같이 나눕니다. 가로 방향에만 작동합니다
  5. 양옆 패딩 padding-inline좁은 화면에서 글이 가장자리에 붙지 않게 합니다. 빠뜨리기 쉬운 줄입니다
  6. 고정된 폭 width (쓰지 않음)width: 1200px은 좁은 화면에서 가로 스크롤을 만듭니다

상한은 하나일 필요가 없습니다. 읽는 글은 65ch 정도로 좁게, 카드 그리드나 표는 1200px 정도로 넓게 잡아서 같은 페이지 안에서 상한을 두세 겹 쓰는 것이 보통입니다. 컨테이너 하나에 모든 내용을 담으면 글이 너무 넓어지거나 표가 너무 좁아집니다.

5 쓸 때 / 안 쓸 때

컨테이너와 최대 폭을 쓰는 경우

  • 기사, 설명, 약관처럼 읽는 글이 있는 화면을 만들 때
  • 넓은 모니터에서 내용이 끝까지 늘어나면 안 될 때
  • 화면마다 양옆 여백을 똑같이 맞추고 싶을 때

컨테이너와 최대 폭을 쓰지 않는 경우

  • width로 폭을 고정할 때. 좁은 화면에서 가로 스크롤이 생깁니다
  • 배경색이나 배경 이미지까지 컨테이너에 가둘 때. 배경은 화면 끝까지 채우고 내용만 가둡니다
  • 표나 그리드까지 좁은 상한에 넣을 때. 열이 다닥다닥 붙습니다
  • 양옆 패딩을 빠뜨릴 때. 폰에서 글이 화면 가장자리에 닿습니다

컨테이너와 함께 보면 좋은 항목 — 글줄 길이 자체는 타입 스케일과 함께 보고, 칸을 나누는 일은 그리드에서 다룹니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙사이트 뼈대를 만드는 두 줄과 지킬 규칙

대부분의 사이트 스타일시트에는 이 네 줄이 들어 있습니다.

.container {
  max-width: 1200px;        /* width가 아니다 */
  margin-inline: auto;      /* 가운데로 */
  padding-inline: 16px;    /* 좁은 화면의 양옆 */
}

/* 읽는 글은 한 줄 45~75자로 더 좁게 */
.prose { max-width: 65ch; }

/* 요즘 방식. 한 줄로 적는다 */
.container { width: min(100% - 32px, 1200px); margin-inline: auto; }

/* 안에서 하나만 끝까지 내보내기 */
.full-bleed { margin-inline: calc(50% - 50vw); }
지킬 규칙지키는 방법
폭은 max-width로 제한하기width로 폭을 고정하면 좁은 화면에서 가로 스크롤이 생깁니다
양옆 패딩 빠뜨리지 않기패딩이 없으면 폰에서 글이 화면 가장자리에 닿습니다
읽는 글의 상한은 ch로 적기ch로 적으면 글꼴 크기가 바뀔 때 상한도 함께 바뀌지만, px로 적으면 따라 바뀌지 않습니다
내용에 따라 상한을 여러 겹 두기글은 좁게, 표와 그리드는 넓게 잡고 상한을 하나로 통일하지 않습니다
배경은 컨테이너에 가두지 않기배경색과 배경 이미지는 화면 전체에 깔고, 내용만 컨테이너 안에 둡니다
가운데 두기는 margin-inline으로margin: 0 auto보다 뜻이 분명하고, 글 방향이 바뀌어도 맞게 동작합니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

모든 화면에 함께 쓰는 값 하나컨테이너 폭 값 하나가 모든 화면에 적용됩니다. 그래서 이 값을 --container 같은 토큰으로 빼 두면 나중에 한 번에 바꿀 수 있습니다.
글줄 길이와 읽기 편한 정도한 줄 45~75자는 조판에서 오래 써 온 경험칙입니다. 한글은 한 글자가 영문보다 넓어서 영문 기준보다 조금 짧게 잡습니다.
이메일과 PDF의 폭메일은 폭을 600px로 고정하는 것이 관례라서, 웹의 컨테이너 값을 그대로 쓰면 내용이 잘립니다.
내려 줄 사진 크기 정하기컨테이너 폭이 1200px이면 2400px짜리를 보낼 필요가 없습니다. 상한을 알면 내려줄 크기도 정해집니다.

앱은 화면 폭이 크게 달라지지 않아서 상한을 덜 쓰고, 태블릿에서만 필요해집니다.

화면을 윈도 크기 클래스로 나눠 다룹니다. 폭이 넓어지면 내용을 가운데로 모으거나 두 칸으로 나누라고 권합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 폰 화면만 생각하고 만든 앱을 태블릿이나 폴더블에서 실행하면 이 문제가 갑자기 생깁니다. "넓은 화면에서 어떻게 보일지"를 정해 두지 않으면 글이 화면 끝까지 늘어난 채로 출시됩니다. 웹에서는 늘 하던 고민을 앱에서는 뒤늦게 하게 되는 셈입니다.
