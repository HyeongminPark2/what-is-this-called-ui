컨테이너와 최대 폭

Container · max-width

내용이 들어가는 가운데 칸. 거의 모든 사이트가 같은 두 줄로 만듭니다 — 상한을 걸고 가운데에 둡니다.

상한 없애기를 켜 보세요. 넓은 화면에서 글줄이 끝까지 늘어나 다음 줄의 첫 글자를 눈이 못 찾게 됩니다 — 긴 글을 읽기 힘든 이유가 글꼴이 아니라 줄 길이일 때가 많습니다.

2 이름부르는 말이 여러 개다

한국어컨테이너, 최대 폭, 가운데 칸, 래퍼
영어container, wrapper, max-width, measure, line length
같이 쓰는 말한 줄의 글자 수를 글줄 길이(measure · line length)라 하고, 폭을 재는 단위 ch는 글꼴의 '0' 한 글자 너비입니다. 화면 양옆에 남기는 여백은 거터나 페이지 마진, 폭에 따라 짜임을 바꾸는 것은 컨테이너 쿼리(container query)입니다.
자주 잘못 부름width와 max-width — width: 1200px은 좁은 화면에서도 1200px이라 가로 스크롤이 생깁니다. max-width는 '이보다 커지지만 마라'입니다.
컨테이너 쿼리 — 부모 폭에 반응하는 다른 기능입니다. 이름만 비슷합니다.
컨테이너(도커) — 완전히 다른 말입니다.

3 가르는 기준형제들과 비교하는 네 축

뼈대를 다루는 것들은 '눈에 안 보이는데 자리를 정한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나방향넘치면누가 값을 정하나

4 상태화면 폭이 바뀌면 달라진다

5 해부도부분 이름이 제일 안 알려진 지식

글줄이 너무 길면 눈이 다음 줄의 첫 글자를 못 찾습니다.
max-width: 65ch
margin-inline: auto
padding-inline: 16px — 좁은 화면의 양옆
width: 1200px — 좁은 화면에서 가로 스크롤
  1. 바깥 칸 page화면 전체. 여기엔 폭 제한을 두지 않는다
  2. 컨테이너 container · wrapper내용이 들어가는 가운데 칸. 이것 하나가 사이트의 뼈대다
  3. 최대 폭 max-width'이보다 넓어지지 마라'. 읽는 글은 65ch쯤
  4. 가운데 두기 margin-inline: auto남은 자리를 양옆에 똑같이 나눈다. 가로 전용
  5. 양옆 패딩 padding-inline좁은 화면에서 글이 가장자리에 붙지 않게. 빠뜨리기 쉽다
  6. 못 박힌 폭 width (쓰지 않는다)width: 1200px은 좁은 화면에서 가로 스크롤을 만든다

상한은 하나일 필요가 없습니다. 읽는 글은 65ch 쯤으로 좁게, 카드 그리드나 표는 1200px 쯤으로 넓게 — 같은 페이지에서 두세 겹을 쓰는 것이 보통입니다. '컨테이너 하나로 전부'라고 정해 두면 글이 너무 넓거나 표가 너무 좁아집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 읽는 글이 있는 모든 화면 — 기사, 설명, 약관
  • 넓은 모니터에서 내용이 끝까지 늘어나면 안 될 때
  • 화면마다 양옆 여백을 똑같이 맞추고 싶을 때

이럴 때는 안 쓴다

  • width로 못 박는 것 — 좁은 화면에서 가로 스크롤이 생깁니다
  • 배경색·배경 이미지까지 가두는 것 — 배경은 끝까지 가고 내용만 가둡니다
  • 표·그리드까지 좁은 상한에 넣는 것 — 열이 다닥다닥 붙습니다
  • 양옆 패딩을 빠뜨리는 것 — 폰에서 글이 가장자리에 닿습니다

대신 이걸 — 글줄 길이 자체는 타입 스케일과 함께 보고, 칸을 나누는 일은 그리드가 맡습니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙사이트의 뼈대 두 줄

거의 모든 사이트가 이 네 줄을 갖고 있습니다.

.container {
  max-width: 1200px;        /* width 가 아니다 */
  margin-inline: auto;      /* 가운데로 */
  padding-inline: 16px;    /* 좁은 화면의 양옆 */
}

/* 읽는 글은 더 좁게 — 한 줄 45~75자 */
.prose { max-width: 65ch; }

/* 요즘 방식 — 한 줄로 */
.container { width: min(100% - 32px, 1200px); margin-inline: auto; }

/* 안에서 하나만 끝까지 내보내기 */
.full-bleed { margin-inline: calc(50% - 50vw); }
규칙지켜야 하는 것
max-width를 쓴다width로 못 박으면 좁은 화면에서 가로 스크롤이 생긴다
양옆 패딩을 잊지 않는다없으면 폰에서 글이 가장자리에 닿는다
읽는 글은 ch로글꼴 크기가 바뀌면 상한도 같이 바뀐다. px 로 적으면 안 따라온다
상한은 여러 겹글은 좁게, 표·그리드는 넓게. 하나로 통일하지 않는다
배경은 가두지 않는다배경색·배경 이미지는 화면 전체, 내용만 컨테이너 안에
margin-inlinemargin: 0 auto보다 또렷하고, 글 방향이 바뀌어도 맞는다

9 서버 쪽으로 치면백엔드 감각으로 번역

컨테이너 = 레이아웃의 상수폭 값 하나가 모든 화면에 걸립니다. 토큰으로 빼 두면(--container) 나중에 한 번에 조일 수 있습니다.
글 길이와 읽기한 줄 45~75자는 오래된 조판 경험칙입니다. 한글은 한 글자가 넓어 영문 기준보다 조금 짧게 잡습니다.
이메일·PDF메일은 보통 600px 고정이 관례입니다. 웹의 컨테이너 값을 그대로 쓰면 잘립니다.
사진 크기컨테이너 폭이 1200px 이면 2400px 짜리를 보낼 필요가 없습니다. 상한을 알면 내려줄 크기도 정해집니다.
