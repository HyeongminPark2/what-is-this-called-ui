대비비

Color contrast

글자색과 바탕색의 밝기 차이를 1~21로 잰 값. 이 부에서 유일하게 눈으로 보이는 항목입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

색을 바꾸면 세 크기가 각각 통과인지 바로 나옵니다. 같은 색인데 큰 글자는 통과하고 본문은 미달하는 것을 보세요 — 기준이 하나가 아니라서 "이 회색 써도 되나요"의 답은 "어디에 쓰는데요"입니다.
아래 네 칸은 이 도감이 실제로 쓰는 색입니다. 자리글이 유독 아슬아슬합니다.

2 이름부르는 말이 여러 개다

한국어대비비, 명도 대비, 색 대비
영어contrast ratio, color contrast, WCAG AA / AAA
같이 쓰는 말기준을 정한 문서가 WCAG이고 수준이 AA(4.5:1)와 AAA(7:1)로 나뉩니다. 글자 아닌 것(테두리·아이콘)의 기준은 비텍스트 대비(non-text contrast, 3:1)입니다. 큰 글자는 18.66px 굵게 또는 24px 부터입니다.
자주 잘못 부름밝기 — 대비비는 두 색의 관계이지 한 색의 성질이 아닙니다.
AA 와 AAA — AAA 는 더 엄격한 선택 기준입니다. 보통 AA 를 목표로 합니다.
'보기에 충분한' — 모니터·밝기·나이에 따라 다릅니다. 재야 알 수 있습니다.

4 기준같은 색이 크기 따라 갈린다

5 해부도부분 이름이 제일 안 알려진 지식

큰 글자 본문 — 정산이 확정되었습니다 보조 글
본문 4.5 : 1
큰 글자(18.66px 굵게 · 24px) 3 : 1
테두리 · 아이콘 3 : 1
자리글 · 비활성 — 가장 자주 넘긴다
눈으로 판단하지 않는다 — 재면 숫자가 나온다
  1. 한 덩어리 color + background대비비는 두 색의 관계다. 한 색만 보고는 알 수 없다
  2. 본문 기준 4.5 : 1대부분의 글이 여기 해당한다
  3. 큰 글자 기준 3 : 118.66px 굵게 또는 24px 부터. 획이 굵어 덜 흐려 보인다
  4. 글자 아닌 것 3 : 1입력칸 테두리·아이콘·그래프 — 잊기 쉬운 자리
  5. 자주 넘기는 자리 자리글 · 비활성흐릴수록 예뻐 보여서 기준을 넘기기 쉽다
  6. 재는 법 개발자 도구 · 대비비 계산기눈으로 판단하지 않는다. 숫자가 바로 나온다

비활성(disabled)은 기준에서 빠집니다. WCAG 가 비활성 요소를 예외로 두기 때문입니다 — 하지만 '규칙에 안 걸린다'와 '읽을 수 있다'는 다릅니다. 비활성 버튼이 무슨 버튼인지 아예 안 보이면 왜 못 누르는지도 알 수 없습니다. 규칙을 핑계로 지나치게 흐리게 두지 않는 편이 낫습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 모든 글자 — 본문 4.5:1, 큰 글자 3:1
  • 입력칸 테두리와 아이콘 — 3:1. 가장 자주 잊는 자리
  • 다크 모드 — 두 벌을 각각 재야 합니다
  • 색 위에 얹은 흰 글자 — 브랜드 색이 밝으면 자주 미달합니다

이럴 때는 안 쓴다

  • 눈으로 판단하는 것 — 모니터·밝기·나이에 따라 다릅니다
  • 자리글에 중요한 정보를 담는 것 — 거의 늘 미달입니다
  • 색만으로 상태를 말하는 것 — 대비를 맞춰도 색맹에게는 같습니다
  • AAA(7:1)를 모든 곳에 요구하는 것 — 보통 AA 가 목표입니다

대신 이걸 — 색을 쓰임으로 정리하는 것은 색 토큰, 두 벌 관리는 다크 모드, 글자 크기 기준은 타입 스케일.

8 최소 코드와 규칙재는 법과 기준

브라우저 개발자 도구에서 색을 누르면 바로 나옵니다. 코드로 재야 할 때는 공식이 짧습니다.

// 상대 밝기 → 대비비. WCAG 공식 그대로다
const lum = (hex) => {
  const n = parseInt(hex.slice(1), 16);
  const c = [(n >> 16) & 255, (n >> 8) & 255, n & 255]
    .map(v => (v /= 255) <= .03928 ? v / 12.92
                                 : ((v + .055) / 1.055) ** 2.4);
  return .2126 * c[0] + .7152 * c[1] + .0722 * c[2];
};
const ratio = (a, b) => {
  const [x, y] = [lum(a), lum(b)];
  return (Math.max(x, y) + .05) / (Math.min(x, y) + .05);
};

ratio('#697180', '#ffffff');   // 4.91 → 본문 통과

9 서버 쪽으로 치면백엔드 감각으로 번역

토큰에서 한 번색을 토큰으로 정리해 두면 토큰 수만큼만 재면 됩니다. 화면마다 재는 것과 일이 열 배 차이 납니다.
CI 에서 검사axe-core·Lighthouse 가 대비비를 자동으로 잽니다. 접근성 항목 중 자동화가 가장 잘 되는 쪽입니다.
그림 위의 글자사진 위에 글을 얹으면 사진마다 대비가 다릅니다. 반투명 막을 깔거나 글자에 그림자를 넣습니다.
브랜드 색과 충돌브랜드 색이 밝으면 흰 글자가 미달합니다. 흰 글자용으로 한 단 어두운 색을 토큰에 따로 두는 것이 흔한 해법입니다.
