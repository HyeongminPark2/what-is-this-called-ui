대비비

Color contrast

대비비는 글자색과 바탕색의 밝기 차이를 1에서 21 사이의 값으로 잰 것입니다. 이 부의 항목 가운데 눈으로 보고 확인할 수 있는 것은 대비비 하나뿐입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

색을 바꾸면 세 가지 크기의 글자가 각각 기준을 통과하는지 바로 나옵니다. 같은 색인데도 큰 글자는 통과하고 본문 글자는 미달하는 경우를 살펴보세요. 글자 크기에 따라 기준이 다르기 때문에 "이 회색 써도 되나요"라는 질문에는 "어디에 쓰는데요"라고 되물어야 답할 수 있습니다.
아래 네 칸은 이 도감에서 실제로 쓰는 색입니다. 그중 자리글 색이 기준에 가장 가깝게 걸쳐 있습니다.

2 이름같은 것을 부르는 여러 이름

한국어대비비, 명도 대비, 색 대비
영어contrast ratio, color contrast, WCAG AA / AAA
같이 쓰는 말대비비 기준을 정한 문서는 WCAG이고, 기준 수준은 AA(4.5:1)와 AAA(7:1)로 나뉩니다. 테두리나 아이콘처럼 글자가 아닌 요소에 적용하는 기준은 비텍스트 대비(non-text contrast, 3:1)라고 합니다. WCAG에서 큰 글자는 굵은 글씨 18.66px 이상이거나 24px 이상인 글자를 말합니다.
자주 잘못 부르는 이름밝기 — 밝기는 한 색의 성질이지만, 대비비는 글자색과 바탕색 두 색 사이의 관계입니다.
AA와 AAA — AAA는 AA보다 엄격한 기준으로, 필요할 때 골라서 적용합니다. 보통은 AA를 목표로 합니다.
'보기에 충분한' — 보기에 충분한지는 모니터와 화면 밝기, 보는 사람의 나이에 따라 달라지므로 직접 재야 알 수 있습니다.

3 글자 크기와 쓰임별 판정같은 색이라도 글자 크기에 따라 판정이 달라지는 모습

4 해부도부분마다 붙은 이름

큰 글자 본문 — 정산이 확정되었습니다 보조 글
본문 4.5 : 1
큰 글자(18.66px 굵게 · 24px) 3 : 1
테두리 · 아이콘 3 : 1
자리글 · 비활성 — 기준을 가장 자주 어김
눈으로 판단하지 말고 도구로 재서 숫자로 확인
  1. 두 색의 조합 color + background대비비는 두 색 사이의 관계이므로 한 색만 보고는 알 수 없습니다
  2. 본문 기준 4.5 : 1화면의 글 대부분이 이 기준에 해당합니다
  3. 큰 글자 기준 3 : 1굵은 글씨 18.66px 이상이거나 24px 이상인 글자에 적용합니다. 획이 굵어서 같은 색이라도 덜 흐려 보이기 때문입니다
  4. 글자가 아닌 요소 3 : 1입력칸 테두리, 아이콘, 그래프에 적용합니다. 글자가 아니어서 기준을 잊기 쉬운 자리입니다
  5. 기준을 자주 어기는 자리 자리글 · 비활성색이 흐릴수록 깔끔해 보여서 기준에 미달하기 쉽습니다
  6. 재는 방법 개발자 도구 · 대비비 계산기눈으로 판단하지 않고 도구로 잽니다. 재면 숫자가 바로 나옵니다

비활성(disabled) 요소는 대비 기준에서 빠집니다. WCAG가 비활성 요소를 예외로 두기 때문입니다. 하지만 규칙에 걸리지 않는다고 해서 읽을 수 있다는 뜻은 아닙니다. 비활성 버튼이 무슨 버튼인지 아예 보이지 않으면 사용자는 그 버튼을 왜 누를 수 없는지도 알 수 없습니다. 그러니 예외 규정이 있더라도 비활성 요소를 지나치게 흐리게 두지 않는 편이 낫습니다.

5 쓸 때 / 안 쓸 때

대비비를 재야 하는 경우

  • 모든 글자의 색을 정할 때. 본문은 4.5:1, 큰 글자는 3:1을 넘겨야 합니다
  • 입력칸 테두리와 아이콘의 색을 정할 때. 3:1을 넘겨야 하는데, 가장 자주 잊는 자리입니다
  • 다크 모드를 만들 때. 밝은 색과 어두운 색 두 벌을 각각 재야 합니다
  • 색 바탕 위에 흰 글자를 얹을 때. 브랜드 색이 밝으면 기준에 미달하는 경우가 많습니다

대비비를 다룰 때 피할 것

  • 대비를 눈으로 판단할 때. 보이는 정도는 모니터와 화면 밝기, 보는 사람의 나이에 따라 다릅니다
  • 자리글에 중요한 정보를 담을 때. 자리글은 거의 언제나 대비 기준에 미달합니다
  • 색만으로 상태를 구별할 때. 대비를 맞춰도 색을 구별하지 못하는 사람에게는 똑같이 보입니다
  • AAA(7:1)를 모든 곳에 요구할 때. 보통은 AA를 목표로 합니다

대비비와 이어지는 주제는 다른 항목에서 다룹니다 — 색을 쓰임별로 정리하는 방법은 색 토큰에서, 밝은 색과 어두운 색 두 벌을 관리하는 방법은 다크 모드에서 다룹니다. 글자 크기를 정하는 기준은 타입 스케일을 보세요.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙대비비를 재는 방법과 기준

대비비는 브라우저 개발자 도구에서 색을 누르면 바로 나옵니다. 코드로 재야 할 때도 아래처럼 짧은 공식으로 계산할 수 있습니다.

// 상대 밝기를 구한 뒤 대비비를 계산한다. WCAG 공식 그대로다
const lum = (hex) => {
  const n = parseInt(hex.slice(1), 16);
  const c = [(n >> 16) & 255, (n >> 8) & 255, n & 255]
    .map(v => (v /= 255) <= .03928 ? v / 12.92
                                 : ((v + .055) / 1.055) ** 2.4);
  return .2126 * c[0] + .7152 * c[1] + .0722 * c[2];
};
const ratio = (a, b) => {
  const [x, y] = [lum(a), lum(b)];
  return (Math.max(x, y) + .05) / (Math.min(x, y) + .05);
};

ratio('#697180', '#ffffff');   // 4.91 → 본문 통과
지킬 규칙지키는 방법
본문은 4.5:1 이상화면의 글 대부분에 적용하는 기본 기준입니다
큰 글자는 3:1 이상굵은 글씨 18.66px 이상이거나 24px 이상인 글자에 적용합니다
테두리와 아이콘은 3:1 이상이 기준 가운데 입력칸 테두리를 가장 자주 잊습니다
다크 모드는 따로 재기밝은 모드에서 통과했다고 다크 모드에서도 통과한다는 보장이 없습니다
색만으로 상태를 구별하지 않기대비를 맞춰도 색을 구별하지 못하는 사람에게는 같은 회색으로 보입니다
토큰을 만들 때 한 번 재기색을 쓸 때마다 재지 말고 토큰을 만들 때 미리 재 둡니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

토큰 단위로 한 번만 재기색을 토큰으로 정리해 두면 토큰 개수만큼만 재면 되므로, 화면마다 재는 것보다 일이 훨씬 적습니다.
CI에서 자동으로 검사하기axe-core나 Lighthouse가 대비비를 자동으로 재 줍니다. 접근성 항목 가운데 자동 검사가 가장 잘 되는 편입니다.
사진 위에 얹은 글자사진 위에 글을 얹으면 사진마다 대비가 달라지기 때문에, 사진과 글자 사이에 반투명 막을 깔거나 글자에 그림자를 넣습니다.
브랜드 색이 기준에 미달할 때브랜드 색이 밝으면 그 위에 얹은 흰 글자가 기준에 미달합니다. 이럴 때는 흰 글자 바탕용으로 한 단계 어두운 색을 토큰에 따로 두는 방법을 흔히 씁니다.
