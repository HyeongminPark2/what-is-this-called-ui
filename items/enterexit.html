진입과 퇴장

Enter / Exit

진입과 퇴장은 요소가 들어올 때와 나갈 때의 움직임을 따로 정하는 일입니다. 두 값을 같게 맞추면 닫을 때마다 사용자가 필요 없이 더 기다리게 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

열고 닫기를 되풀이해 보세요. 기본값은 들어올 때 260ms ease-out, 나갈 때 180ms ease-in입니다.
같게 맞추기를 켜면 닫을 때도 260ms가 걸립니다. 이미 다 본 패널이 사라지기를 기다리는 것이 어떤 느낌인지 바로 알 수 있습니다.

2 이름같은 것을 부르는 여러 이름

한국어진입과 퇴장, 들고 남, 등장과 사라짐
영어enter / exit, entrance / exit transition, in / out
같이 쓰는 말리액트 쪽에서는 enter·enter-active·exit 같은 클래스 이름으로 나타나고, Vue에서는 v-enter-from·v-leave-to를 씁니다. 요즘 CSS에서는 @starting-style과 transition-behavior: allow-discrete를 쓰면 자바스크립트 없이도 들어오고 나가는 움직임을 만들 수 있습니다.
자주 잘못 부르는 이름트랜지션 — CSS transition은 움직임을 구현하는 수단이고, 진입과 퇴장은 그 움직임을 어떻게 줄지 정하는 설계입니다.
페이드 — 투명도를 바꾸는 것은 여러 방법 가운데 하나일 뿐이고, 보통은 자리와 크기도 함께 움직입니다.
모달 — 모달은 부품 이름이고, 진입과 퇴장은 그 부품이 어떻게 들어오고 나가는지를 가리킵니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

움직임은 화면에서 무엇이 바뀌었는지 사용자에게 알려 주는 역할을 합니다. 아래 네 가지를 따져 보면 움직임을 다루는 항목들을 서로 구별할 수 있습니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다
지속 시간얼마나 걸리나거리와 크기기다리게 된다짧게 하거나 0
진입과 퇴장들고 나는 방식어디서 왔나닫는 데 붙잡힌다퇴장은 거의 0
무엇을 움직이나어떤 속성을 바꾸나매끄러움 그 자체버벅인다해당 없음
스프링지나쳤다 돌아오는 정도손으로 민 느낌어지럽다튕김을 0으로
차례로 들어오기줄 사이 지연순서와 묶음마지막이 늦는다한꺼번에 띄운다
제스처손가락을 따라가는 규칙내가 조작한다실수로 닫힌다그대로 둔다
모션 줄이기무엇을 끄나배려받고 있다다 꺼서 변화를 못 읽는다이게 그 기준이다
공유 요소 전환두 화면의 같은 것어디서 왔나자리가 어긋나면 더 헷갈린다자리 이동 없이
스크롤 연동굴림에 맞춰 움직이기내가 어디쯤인가멀미를 부른다연출만 끈다

진입과 퇴장을 한 줄로 정리하면 — 나가는 움직임을 더 짧게 줍니다. 들어오는 것은 어디서 왔는지 보여 줘야 하지만, 나가는 것은 사용자가 이미 다 본 것이기 때문입니다.

4 들고 나는 네 토막같은 부품, 다른 시간

5 해부도부분마다 붙은 이름

들어옴 — 260ms ease-out
나감 — 180ms ease-in (더 짧다)
나온 자리로 돌아간다 — 버튼 쪽으로
가림막은 투명도만 — linear
나간 뒤에 display:none — 먼저 지우면 연출이 없다
초점은 연출을 기다리지 않는다
  1. 들어오는 길이 260ms ease-out요소가 어디서 왔는지 보여 줄 시간입니다
  2. 나가는 길이 180ms ease-in들어올 때보다 더 짧게 줍니다. 이미 다 본 것이 사라지기를 기다리게 하지 않기 위해서입니다
  3. 돌아갈 자리 나온 쪽누른 버튼 쪽으로 돌아가면 패널이 어디로 갔는지 알 수 있습니다
  4. 가림막 투명도만자리는 움직이지 않고 투명도만 바뀌므로 linear로 충분합니다
  5. 지우는 때 연출 뒤transitionend나 setTimeout으로 연출이 끝난 때를 잡아 지웁니다. 먼저 지우면 연출이 보이지 않습니다
  6. 초점 기다리지 않는다열릴 때는 바로 패널 안으로, 닫힐 때는 바로 패널을 연 버튼으로 옮깁니다

초점은 연출이 끝나기를 기다리지 않고 옮깁니다. '애니메이션이 끝나면 초점을 옮기자'로 짜면 키보드 사용자는 그동안 아무 데도 갈 수 없고, Tab을 눌러도 초점이 배경으로 빠집니다. 그래서 자리는 천천히 옮기고 초점은 바로 옮기는 것이 맞습니다. 포커스 트랩도 같은 이유로 열자마자 걸어 둡니다.

6 쓸 때 / 안 쓸 때

진입과 퇴장을 쓰는 경우

  • 모달·시트·토스트·드롭다운처럼 떴다 사라지는 것을 만들 때
  • 목록에서 줄이 지워질 때. 그냥 사라지면 무엇이 지워졌는지 알 수 없습니다
  • 화면이 통째로 바뀔 때

진입과 퇴장을 쓰지 않는 경우

  • 들어오는 움직임과 나가는 움직임을 같게 맞출 때. 닫을 때마다 필요 없이 기다리게 됩니다
  • 나가는 연출이 끝나기를 기다렸다가 초점을 옮길 때
  • display:none을 먼저 걸 때. 나가는 연출이 통째로 보이지 않습니다
  • 들어올 때만 움직임을 만들고 나갈 때는 툭 사라지게 둘 때. 진입과 퇴장 가운데 절반만 만든 것입니다

진입과 퇴장 대신 다른 것을 써야 하는 경우 — 곡선 자체는 이징, 길이는 지속 시간, 여러 줄이 차례로 들어오게 하려면 차례로 들어오기.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙구현할 때 지킬 최소 규칙

들어온 상태와 나간 상태를 따로 적고, 요소는 다 나간 뒤에 지웁니다.

.sheet {                      /* 나갈 때 */
  transition: transform 180ms var(--ease-in), opacity 140ms linear;
  transform: translateY(100%); opacity: 0;
}
.sheet[data-open] {           /* 들어올 때 */
  transition: transform 260ms var(--ease-out), opacity 180ms linear;
  transform: none; opacity: 1;
}

// 초점은 기다리지 않는다
sheet.dataset.open = ''; firstField.focus();

// 지우는 것은 연출이 끝난 뒤
function close() {
  opener.focus();                        // 먼저
  delete sheet.dataset.open;
  sheet.addEventListener('transitionend', () => { sheet.hidden = true; }, { once: true });
}
키와 동작그때 일어나야 하는 일
초점을 먼저 옮긴다열 때는 패널 안으로, 닫을 때는 패널을 연 버튼으로 옮깁니다. 연출이 끝나기를 기다리지 않습니다
transitionend는 안 올 수 있다값이 바뀌지 않았거나 길이가 0이면 이벤트가 오지 않습니다. 그래서 setTimeout을 예비로 같이 걸어 둡니다
@starting-style요즘 CSS에 들어온 규칙입니다. display:none이던 요소가 나타나는 움직임도 자바스크립트 없이 만들 수 있습니다
<dialog>.close()부르면 바로 사라집니다. 퇴장 연출을 보여 주려면 연출이 끝난 뒤에 부릅니다
Esc닫는 연출 중에도 동작해야 합니다. 연출 중에는 입력을 막고 싶어지지만, 막으면 사용자가 그 화면에서 빠져나갈 수 없습니다
aria-hidden나가는 중에도 켜 둡니다. 화면에는 보이지만 스크린 리더가 읽지 않는 구간이 잠깐 생기는 편이 낫습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

닫히는 중에 다시 열리면닫는 연출이 끝날 때 hidden을 거는 타이머가 남아 있으면 새로 연 패널까지 숨겨 버립니다. 그래서 열 때 그 타이머를 취소합니다.
저장하고 닫는 순서저장하고 응답을 받은 뒤에 닫으면 느립니다. 보통은 낙관적 UI로 먼저 닫고, 저장에 실패하면 되돌리는 편이 낫습니다.
닫힘을 서버가 모른다사용자가 연출 도중에 페이지를 떠나면 요청이 끊깁니다. 그래서 중요한 저장은 keepalive나 sendBeacon으로 보냅니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

세 플랫폼 모두 나가는 움직임을 더 짧게 두고, 부르는 이름만 다릅니다.

웹transition · @starting-style
내보내기
두 상태를 적어 두고 클래스로 오갑니다. 웹에서는 요소를 지우는 때를 개발자가 직접 챙겨야 합니다.
iOSpresent / dismiss
present와 dismiss를 짝으로 씁니다. 시트에는 끌어서 닫기가 기본으로 들어 있습니다.
안드로이드Material motion
규격에 enter는 길게, exit는 짧게 하라고 정해 두었습니다. 공유 축 전환(shared axis)도 표준으로 들어 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "모달 띄울 때 스르륵"이라는 요청에는 닫는 움직임이 빠져 있기 쉽습니다. 들어오는 움직임만 만들면 닫을 때 툭 사라져서 절반만 만든 것처럼 보이고, 둘을 같은 값으로 맞추면 닫을 때마다 필요 없이 기다리게 됩니다. 처음부터 들어옴 260 · 나감 180을 기본값으로 적어 두면 이런 요청을 주고받는 일이 줄어듭니다.
