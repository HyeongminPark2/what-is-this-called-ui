진입과 퇴장

Enter / Exit

들어올 때와 나갈 때를 따로 정하는 일. 같게 맞추면 닫을 때마다 한 박자 붙잡힙니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

열고 닫기를 되풀이해 보세요. 기본값은 들어올 때 260ms ease-out, 나갈 때 180ms ease-in입니다.
같게 맞추기를 켜면 닫는 데도 260ms 가 걸립니다 — 볼 일이 끝난 것을 기다리는 느낌이 어떤지 바로 알 수 있습니다.

2 이름부르는 말이 여러 개다

한국어진입과 퇴장, 들고 남, 등장과 사라짐
영어enter / exit, entrance / exit transition, in / out
같이 쓰는 말리액트 쪽에서는 enter·enter-active·exit 같은 클래스 이름으로 나타납니다. Vue 는 v-enter-from·v-leave-to입니다. 요즘 CSS 는 @starting-style과 transition-behavior: allow-discrete로 자바스크립트 없이도 들고 남을 그릴 수 있습니다.
자주 잘못 부름트랜지션 — CSS transition은 수단이고, 진입·퇴장은 설계입니다.
페이드 — 투명도는 여러 방법 중 하나입니다. 자리·크기도 함께 움직입니다.
모달 — 모달은 부품, 이쪽은 그 부품이 어떻게 들고 나는지입니다.

3 가르는 기준형제들과 비교하는 네 축

움직임은 장식이 아니라 말입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다
지속 시간얼마나 걸리나거리와 크기기다리게 된다짧게 하거나 0
진입과 퇴장들고 나는 방식어디서 왔나닫는 데 붙잡힌다퇴장은 거의 0
무엇을 움직이나어떤 속성을 바꾸나매끄러움 그 자체버벅인다해당 없음
스프링지나쳤다 돌아오는 정도손으로 민 느낌어지럽다튕김을 0으로
차례로 들어오기줄 사이 지연순서와 묶음마지막이 늦는다한꺼번에 띄운다
제스처손가락을 따라가는 규칙내가 조작한다실수로 닫힌다그대로 둔다
모션 줄이기무엇을 끄나배려받고 있다다 꺼서 변화를 못 읽는다이게 그 기준이다
공유 요소 전환두 화면의 같은 것어디서 왔나자리가 어긋나면 더 헷갈린다자리 이동 없이
스크롤 연동굴림에 맞춰 움직이기내가 어디쯤인가멀미를 부른다연출만 끈다

한 줄로 — 나가는 쪽을 더 짧게. 들어오는 것은 어디서 왔는지 보여 줘야 하지만, 나가는 것은 이미 볼 일이 끝났습니다.

4 들고 나는 네 토막같은 부품, 다른 시간

5 해부도부분 이름이 제일 안 알려진 지식

들어옴 — 260ms ease-out
나감 — 180ms ease-in (더 짧다)
나온 자리로 돌아간다 — 버튼 쪽으로
가림막은 투명도만 — linear
나간 뒤에 display:none — 먼저 지우면 연출이 없다
초점은 연출을 기다리지 않는다
  1. 들어오는 길이 260ms ease-out어디서 왔는지를 보여 줄 시간
  2. 나가는 길이 180ms ease-in더 짧게. 볼 일이 끝난 것을 기다리게 하지 않는다
  3. 돌아갈 자리 나온 쪽누른 버튼 쪽으로 돌아가면 어디로 갔는지 알 수 있다
  4. 가림막 투명도만자리는 안 움직인다. linear로 충분하다
  5. 지우는 때 연출 뒤transitionend나 setTimeout. 먼저 지우면 안 보인다
  6. 초점 기다리지 않는다열릴 때는 바로 안으로, 닫힐 때는 바로 부른 버튼으로

초점은 연출을 기다리지 않습니다. '애니메이션이 끝나면 초점을 옮기자'로 짜면 키보드 사용자는 그 시간 동안 아무 데도 못 갑니다 — Tab 을 눌러도 배경으로 빠집니다. 자리는 천천히, 초점은 즉시가 맞습니다. 포커스 트랩도 같은 이유로 열자마자 걸어 둡니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 떴다 사라지는 모든 것 — 모달·시트·토스트·드롭다운
  • 목록에서 줄이 지워질 때 — 그냥 사라지면 뭐가 지워졌는지 모른다
  • 화면이 통째로 바뀔 때

이럴 때는 안 쓴다

  • 들어오는 것과 나가는 것을 같게 — 닫을 때 붙잡힌다
  • 나가는 연출이 끝나기를 기다렸다 초점 옮기기
  • display:none을 먼저 걸기 — 연출이 통째로 안 보인다
  • 들어올 때만 만들고 나갈 때는 툭 사라지게 두기 — 절반만 한 것이다

대신 이걸 — 곡선 자체는 이징, 길이는 지속 시간, 여러 줄이 차례로면 차례로 들어오기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 전환의 계약서

두 상태를 따로 적고, 나간 뒤에 지웁니다.

.sheet {                      /* 나갈 때 */
  transition: transform 180ms var(--ease-in), opacity 140ms linear;
  transform: translateY(100%); opacity: 0;
}
.sheet[data-open] {           /* 들어올 때 */
  transition: transform 260ms var(--ease-out), opacity 180ms linear;
  transform: none; opacity: 1;
}

// 초점은 기다리지 않는다
sheet.dataset.open = ''; firstField.focus();

// 지우는 것은 연출이 끝난 뒤
function close() {
  opener.focus();                        // 먼저
  delete sheet.dataset.open;
  sheet.addEventListener('transitionend', () => { sheet.hidden = true; }, { once: true });
}
키일어나야 하는 일
초점을 먼저 옮긴다열 때는 안으로, 닫을 때는 부른 버튼으로. 연출을 기다리지 않는다
transitionend는 안 올 수 있다값이 안 바뀌거나 길이가 0 이면 안 온다. setTimeout 보험을 같이 건다
@starting-style요즘 CSS. display:none에서 나타나는 것도 자바스크립트 없이 그릴 수 있다
<dialog>.close()바로 사라진다. 퇴장 연출을 보려면 끝난 뒤에 부른다
Esc닫는 연출 중에도 먹어야 한다. 연출 중엔 잠그고 싶겠지만 잠그면 갇힌다
aria-hidden나가는 중에도 켜 둔다. 보이지만 읽히지 않는 구간이 짧게 있는 편이 낫다

9 서버 쪽으로 치면백엔드 감각으로 번역

닫히는 중에 다시 열리면연출이 끝나며 hidden을 거는 타이머가 새로 연 것까지 숨깁니다. 열 때 타이머를 취소합니다.
저장하고 닫는 순서'저장 → 응답 → 닫기'면 느립니다. 낙관적 UI로 먼저 닫고 실패하면 되돌리는 쪽이 보통 낫습니다.
닫힘을 서버가 모른다사용자가 연출 도중 떠나면 요청이 끊깁니다. 중요한 저장은 keepalive나 sendBeacon으로 보냅니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

세 곳 모두 나가는 쪽이 더 짧습니다. 이름만 다릅니다.

웹transition · @starting-style
내보내기
상태를 둘 적고 클래스로 오갑니다. 지우는 때를 직접 챙겨야 하는 것이 웹의 숙제입니다.
iOSpresent / dismiss
present·dismiss가 짝입니다. 시트는 끌어서 닫기가 기본으로 붙습니다.
안드로이드Material motion
enter 는 길게, exit 는 짧게를 규격에 못 박았습니다. 공유 축 전환(shared axis)도 표준으로 있습니다.

자주 생기는 사고 — "모달 띄울 때 스르륵"이라는 요청에는 닫는 쪽이 빠져 있기 쉽습니다. 들어오는 것만 만들면 닫을 때 툭 사라져 절반만 한 모양이 되고, 둘을 같은 값으로 맞추면 닫을 때마다 붙잡힙니다. 들어옴 260 · 나감 180을 기본으로 적어 두면 이 대화가 짧아집니다.
