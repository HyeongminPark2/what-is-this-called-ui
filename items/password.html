비밀번호 칸

Password field

비밀번호 칸의 핵심은 무엇을 막지 않느냐입니다 — 붙여넣기를 막으면 오히려 약해집니다.

붙여넣기를 막으면 비밀번호 관리자를 못 쓰게 되어 오히려 약한 비밀번호를 쓰게 됩니다 — 체크를 끄고 붙여넣어 보면 데모가 막힌 횟수를 셉니다.
갈래 강제(대문자·숫자·기호)는 Passw0rd! 같은 짧고 뻔한 것을 통과시키고, 길고 센 한국어 문장을 막습니다 — 데모가 두 규칙으로 각각 매겨 보여 줍니다.
보기 단추는 눈으로 확인할 유일한 길입니다.

2 이름부르는 말이 여러 개다

한국어비밀번호 칸, 암호 입력, 패스워드 필드
영어password field, password input, masked input
같이 쓰는 말글자를 점으로 가리는 것을 마스킹, 눌러서 드러내는 것을 보기 토글(reveal)이라 합니다. 세기를 막대로 보여 주는 것은 스트렝스 미터, 여러 낱말을 이어 만든 긴 것은 패스프레이즈입니다.
자주 잘못 부름텍스트 필드 — 텍스트 필드와 같은 태그지만 type 이 다릅니다.
PIN — 네 자리 숫자는 다른 부품으로 만드는 편이 낫습니다.
OTP — 일회용 번호는 autocomplete="one-time-code" 를 씁니다.

  4. autocomplete 관리자가 알아봄new-password
  5. 갈래 강제 역효과짧고 뻔한 것이 통과

대문자·숫자·기호를 꼭 넣으라는 규칙은 오래 쓰였지만, 지금은 권하지 않습니다 — 사람들이 그 규칙을 가장 적게 만족하는 방식으로 만들기 때문입니다 (Password1!, Qwer1234!). 대신 길이를 보고, 이미 털린 비밀번호 목록과 맞춰 보는 쪽이 실제로 셉니다.
붙여넣기를 막는 것은 보안을 위해 하는 일처럼 보이지만, 관리자가 만들어 주는 20자짜리 무작위 비밀번호를 못 쓰게 만들어 오히려 사람이 외울 수 있는 약한 것을 쓰게 합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 길이를 기준으로 삼기
  • 보기 단추 두고 aria-pressed 로 상태 알리기
  • autocomplete="new-password" 로 관리자가 알아보게 하기

이럴 때는 안 쓴다

  • 붙여넣기 막기 — 관리자를 못 쓰게 된다
  • 갈래를 강제하기 — 짧고 뻔한 것만 늘어난다
  • 규칙을 틀린 뒤에 알리기
  • 최대 길이를 짧게 두기 — 20자도 못 넣는 칸이 많다

대신 이걸 — 한 줄 글이면 텍스트 필드, 검사 규칙은 입력 검증, 로그인 화면 전체는 로그인, 오류 문구는 오류 문구.

8 최소 마크업과 키보드이 부품의 계약서

autocomplete 를 제대로 적는 것이 가장 큰 차이를 냅니다.

<label for="pw">새 비밀번호</label>
<input id="pw" type="password"
       autocomplete="new-password"      <!-- 로그인이면 current-password -->
       minlength="12" aria-describedby="pw-rule">
<button type="button" aria-pressed="false"
        aria-label="비밀번호 보기">보기</button>
<p id="pw-rule">12자 이상이면 됩니다 — 길수록 셉니다</p>

// ✕ 이렇게 막지 않는다
input.addEventListener('paste', e => e.preventDefault());

9 서버 쪽으로 치면백엔드 감각으로 번역

규칙은 서버가 정한다화면이 아는 규칙과 서버의 규칙이 다르면 통과했는데 거절당합니다.
털린 목록널리 털린 비밀번호 목록과 맞춰 보면 갈래 규칙보다 훨씬 효과가 큽니다.
최대 길이짧게 두지 않습니다 — 64자 이상을 받는 편이 안전합니다.
실패 메시지'아이디 또는 비밀번호가 다릅니다'로 어느 쪽인지 숨깁니다 — 로그인 참고.
