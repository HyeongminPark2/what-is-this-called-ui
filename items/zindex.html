z-index

z-index · stacking order

z-index는 겹친 요소들의 앞뒤 순서를 정하는 값입니다. 아무 숫자나 적는 칸이 아니라, 미리 정해 둔 층 목록에서 골라 쓰는 값입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

100, 300, 500처럼 층 사이를 띄워 두면 나중에 층을 하나 끼워 넣을 자리가 남습니다.
아무 값이나 쓰기를 켜면 토스트가 9999가 됩니다. 당장은 맨 위로 올라오지만, 다음 사람은 그보다 큰 99999를 쓰게 되고, 이런 일이 쌓이면 왜 이 순서인지 아무도 설명할 수 없게 됩니다. 이 데모에서는 그 결과로 모달이 가림막에 덮여 글자를 읽을 수 없게 됩니다.

2 이름같은 것을 부르는 여러 이름

한국어z-인덱스, 쌓임 순서, 층 순서
영어z-index, stacking order, stacking context, layer
같이 쓰는 말z-index 값끼리 앞뒤를 비교하는 범위를 쌓임 맥락(stacking context)이라고 합니다. 같은 맥락 안에서 z-index 번호 없이 정해지는 순서는 그리는 순서(painting order)이고, 미리 정해 둔 층 목록은 보통 레이어 스케일 또는 z 스케일이라고 부릅니다.
자주 잘못 부르는 이름고도 — 고도는 그림자로 나타내는 보이는 높이이고, z-index는 그리는 순서입니다. 그래서 그림자가 커도 그리는 순서가 뒤로 밀리면 다른 요소 아래에 깔립니다.
레이어 — 디자인 도구의 레이어 패널과는 다릅니다. 브라우저에서는 순서를 같은 맥락 안에서만 비교합니다.
position — position이 static이면 z-index는 아예 적용되지 않습니다.

3 층 목록과 층마다 놓이는 부품숫자 대신 이름으로 부르는 층

4 해부도부분마다 붙은 이름

부모에 transform이 걸려 있으면 여기서 새 맥락이 시작됩니다
transform: translateZ(0)
자식 · z-index: 9999
형제 · z-index: 1, 이쪽이 위에 그려짐
  1. 맥락 밖 outer contextz-index 번호는 같은 쌓임 맥락 안에 있는 요소끼리만 비교됩니다
  2. 쌓임 맥락 stacking context이 맥락 안의 자식은 z-index가 얼마나 크든 맥락 바깥의 요소와는 순서를 비교하지 않습니다
  3. 맥락을 만드는 속성 transform · opacity · filtertransform, 1 미만의 opacity, filter, will-change, position: fixed 등을 주면 새 쌓임 맥락이 생깁니다
  4. 갇힌 자식 z-index: 9999z-index가 9999라도 그 값은 부모가 만든 맥락 안에서만 의미가 있습니다
  5. 바깥 형제 z-index: 1맥락 바깥에 있는 z-index 1인 요소가 안쪽의 9999보다 위에 그려집니다. 'z-index가 안 먹어요'라는 문제는 대부분 이 때문에 생깁니다

드롭다운이 카드에 가려 보이지 않는 문제는 거의 모두 부모 어딘가에 transform이나 opacity: .99가 걸려 있어서 생깁니다. 이때는 z-index 숫자를 올려도 고쳐지지 않습니다. 해결 방법은 두 가지로, 맥락을 만드는 속성을 없애거나 그 부품을 <body> 바로 밑으로 옮기는 것입니다(포털 · popover 속성).

5 쓸 때 / 안 쓸 때

z-index를 쓰는 경우

  • 모달과 토스트가 함께 있는 화면처럼 겹쳐 뜨는 부품이 둘 이상 있을 때
  • 붙박이 머리말이 다른 것에 가릴 때
  • 층 목록을 한 파일에 모아 둘 때

z-index를 쓰지 않는 경우

  • 본문 요소에 번호를 줄 때. 대부분은 번호 없이 그리는 순서만으로 충분합니다
  • 급하다고 숫자만 올릴 때. 다음 사람이 그보다 더 큰 숫자를 쓰게 되어 같은 문제가 되풀이됩니다
  • 999나 9999 같은 값을 쓸 때. 정해 둔 층 목록이 쓸모없어집니다
  • 쌓임 맥락이 달라서 생긴 문제를 숫자로 맞추려 할 때. 원인이 숫자가 아니라 맥락에 있어서 고쳐지지 않습니다

z-index와 함께 보면 좋은 항목 — 요소가 떠 보이게 하는 방법은 고도 항목에서 다루고, 어떤 부품이 뒤 화면을 막는지는 모달 항목과 토스트 항목에 정리돼 있습니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 지킬 규칙층 목록을 코드로 옮기는 방법

층을 이름으로 정해 두고 코드에서는 그 이름만 씁니다. 숫자를 직접 적는 곳이 한 군데라도 생기면 층 목록과 실제 값이 어긋나기 시작합니다.

:root {
  --z-sticky: 100;
  --z-dropdown: 300;
  --z-scrim: 500;
  --z-modal: 600;
  --z-toast: 800;
}

/* position 이 static 이면 z-index 는 아무 일도 하지 않는다 */
.site-header { position: sticky; z-index: var(--z-sticky); }
.toast-area  { position: fixed;  z-index: var(--z-toast); }

// 맥락에 갇히지 않으려면 body 밑으로 옮긴다(포털)
document.body.appendChild(toastEl);

/* 또는 브라우저에 맡겨 최상위 레이어로 올린다 */
<dialog>, [popover]
지킬 규칙지키는 방법과 이유
층 목록부터 정하기다섯~여섯 층이면 충분합니다. 층 사이를 100씩 띄워 나중에 끼워 넣을 자리를 남깁니다
코드에 숫자를 직접 쓰지 않기var(--z-modal)처럼 이름만 씁니다. 코드에 숫자가 보이면 리뷰에서 막습니다
position을 함께 지정하기position이 static이면 z-index가 무시됩니다. 'z-index가 안 먹어요'라는 문제의 두 번째로 흔한 원인입니다
쌓임 맥락부터 확인하기z-index가 적용되지 않으면 숫자를 올리지 말고 부모에 걸린 transform · opacity · filter부터 찾습니다
가림막과 모달은 한 칸 차이로 두기500과 600처럼 바로 이웃한 층에 둡니다. 둘 사이에 다른 층이 끼면 그 층의 요소가 가림막 위로 드러납니다
<dialog>와 popover를 먼저 쓰기브라우저가 최상위 레이어에 그려 주기 때문에 쌓임 맥락 문제가 아예 생기지 않습니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

우선순위 상수와 같은 구조미들웨어 순서나 이벤트 핸들러 우선순위와 같은 구조입니다. 값 사이를 비워 두는 이유도 나중에 끼워 넣기 위해서라는 점에서 같습니다.
9999 같은 값이 생기는 이유급할 때 가장 손쉽게 쓸 수 있는 해결책이기 때문입니다. 코드 리뷰에서 숫자 리터럴을 막는 규칙 하나만 두어도 이 문제는 대부분 사라집니다.
외부 위젯이 쓰는 큰 값채팅 상담이나 결제창 같은 외부 스크립트는 미리 알 수 없는 큰 값을 씁니다. 그래서 우리 층 목록의 맨 위층을 그보다 높게 잡거나, 해당 구역을 따로 감싸 둡니다.
쌓임 맥락을 확인하는 방법브라우저 개발자 도구의 Layers 패널에서 쌓임 맥락을 볼 수 있습니다. 숫자를 바꿔 보기 전에 이 패널부터 열어 보면 원인을 더 빨리 찾을 수 있습니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

쌓임 맥락 문제는 웹에만 있습니다. 앱은 화면을 쌓는 방식 자체가 달라서 이런 문제가 거의 생기지 않습니다.

웹CSS z-index
z-index: 600
position: fixed
쌓임 맥락 때문에 z-index가 뜻대로 적용되지 않는 일이 생깁니다. <dialog>와 popover 속성을 쓰면 맥락과 상관없이 최상위 레이어에 그려집니다.
iOS뷰 계층
zPosition
.zIndex(1)
.sheet / .alert
새 화면을 기존 화면 위에 쌓아 올리는 구조(present)라서 순서가 엉킬 일이 적습니다. 같은 층 안의 순서만 zIndex로 조정합니다.
안드로이드Compose · elevation
Modifier.zIndex(1f)
Dialog { }
기본적으로 그리는 순서를 따르고, 다이얼로그는 별도 윈도로 떠서 아예 다른 층에 그려집니다.

플랫폼 차이 때문에 자주 생기는 문제 — "z-index가 안 먹어요"는 웹 개발자끼리만 통하는 말입니다. 앱 개발자는 같은 증상을 겪지 않기 때문에, 문제를 설명할 때는 "부모 때문에 이 요소가 바깥 요소보다 위로 못 올라간다"처럼 맥락을 풀어서 말해야 합니다.
