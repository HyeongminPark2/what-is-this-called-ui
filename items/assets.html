에셋 내보내기

Exporting assets

무엇을 내보내느냐에 따라 고를 것이 달라집니다. 선은 SVG, 사진은 배율별 비트맵입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

무엇을 내보낼지 골라 보세요 — 선으로 된 아이콘·로고는 SVG 하나면 어느 배율에서나 선명하고 파일도 작습니다. 사진은 SVG 로 만들 수 없으니 배율별 비트맵이 필요합니다.
크기는 어림한 값입니다 — 요점은 숫자가 아니라 어느 쪽이 몇 배 차이나는지입니다.

2 이름부르는 말이 여러 개다

한국어에셋, 내보내기, 익스포트, 이미지 추출
영어assets, export, asset export, slicing
같이 쓰는 말넘기는 그림 파일을 통틀어 에셋이라 하고, 꺼내는 일이 익스포트입니다. 배율별로 뽑는 것을 1x · 2x · 3x, 여러 아이콘을 한 파일에 모은 것을 스프라이트·아이콘 폰트라 합니다. SVG 를 HTML 안에 직접 적어 넣는 것은 인라인 SVG입니다.
자주 잘못 부름이미지 — SVG 는 그림이 아니라 그리는 명령이라 성격이 다릅니다.
해상도 — 배율과 섞입니다. 화면 밀도를 참고합니다.
슬라이스 — 옛 방식(큰 그림을 잘라 쓰기)의 이름이 남은 말입니다.

3 가르는 기준형제들과 비교하는 네 축

현장 용어는 말이 아니라 일하는 단계를 가리킵니다. 이 네 가지만 물어보면 갈립니다.

무엇을 가리키나언제 나오나개발 쪽 대응물잘못 알아들으면
와이어프레임과 목업과 시안얼마나 진짜 같은 그림인가기획 ~ 디자인마크업 구조 ~ 완성 화면엉뚱한 리뷰가 돌아온다
디자인 시스템규칙 + 부품 + 문서프로젝트 내내토큰 + 컴포넌트 라이브러리스타일 가이드와 섞인다
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀐다
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞인다
오토 레이아웃자동 배치시안 작업flexbox‘여백이 자동’을 못 알아듣는다
프로토타입눌리는 시안리뷰 · 사용자 시험아직 코드가 아니다다 된 줄 안다
핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받는다
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배만 받아 뭉갠다

한 줄로 — 선이면 SVG, 사진이면 배율별 비트맵. 그리고 포맷을 바꾸는 쪽이 배율보다 효과가 큽니다.

4 무엇을 내보내나고를 것이 달라진다

5 해부도부분 이름이 제일 안 알려진 지식

선 · 글자 → SVG. 어느 배율에서나 선명하다
사진 → WebP · AVIF. SVG 로는 못 만든다
비트맵은 배율별로 — 1x · 2x · 3x
srcset 으로 브라우저가 고르게 한다
글꼴은 윤곽선으로 — 없는 곳에서 깨진다
SVG 가 늘 작은 것은 아니다 — 점이 많으면 커진다
  1. 선 · 글자 SVG어느 배율에서나 선명하고 대개 가장 작다
  2. 사진 WebP · AVIFSVG 로는 못 만든다. 포맷이 먼저
  3. 배율별 1x · 2x · 3x비트맵은 배율만큼 필요하다
  4. 고르게 하기 srcset브라우저가 자기 배율에 맞는 것만 받는다
  5. 글꼴 윤곽선으로안 바꾸면 그 글꼴이 없는 곳에서 깨진다
  6. SVG 의 한계 점이 많으면 커진다그라데이션·패턴이 많으면 비트맵이 낫다

SVG 는 코드라서 다룰 수 있는 것이 많습니다. fill="currentColor"로 두면 CSS 의 글자색을 따라가 다크 모드에서 색을 따로 안 만들어도 되고, aria-hidden·<title>로 읽히는 방식도 정할 수 있습니다. 다만 그만큼 남이 만든 SVG 를 그대로 붙이면 엉뚱한 id·style이 따라 들어와 다른 그림과 부딪히기도 합니다 — 받으면 한 번 훑어보는 편이 좋습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 아이콘·로고는 SVG로 받기
  • 사진은 포맷부터 바꾸기 — WebP·AVIF
  • 비트맵은 배율별로 받고 srcset 으로 고르게 하기

이럴 때는 안 쓴다

  • 1배짜리만 받기 — 3배 화면에서 뭉갠다
  • 모든 그림을 3배로만 — 1배 기기가 손해를 본다
  • 글꼴을 윤곽선으로 안 바꾸기 — 깨진다
  • 아이콘을 PNG 로 — 색을 못 바꾸고 더 크다

대신 이걸 — 배율 이야기는 화면 밀도, 넘기는 일 전체는 핸드오프, 글꼴 파일은 웹폰트.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙이 파일의 계약서

SVG 는 코드로 넣고, 비트맵은 srcset 으로 고르게 합니다.

<!-- 아이콘: 색을 CSS 가 정하고, 장식이면 숨긴다 -->
<svg width="24" height="24" fill="currentColor" aria-hidden="true">
  <path d="…"/>
</svg>

<!-- 뜻이 있는 그림이면 이름을 준다 -->
<svg role="img" aria-label="이름표 로고">…</svg>

<!-- 사진: 폭과 배율을 브라우저가 고르게 -->
<img src="c-800.webp"
     srcset="c-400.webp 400w, c-800.webp 800w, c-1200.webp 1200w"
     sizes="(min-width: 900px) 33vw, 100vw"
     width="800" height="450" alt="모란상회 매장 사진">
키일어나야 하는 일
fill="currentColor"글자색을 따라간다. 다크 모드에서 색을 또 안 만들어도 된다
장식이면 aria-hidden아이콘 옆에 글자가 있으면 두 번 읽히지 않게
뜻이 있으면 이름로고·상태 아이콘은 role="img" + aria-label — 이름 붙이기
width·height미리 적으면 자리가 안 덜컥거린다
alt사진의 뜻. 장식이면 alt=""로 비운다
받은 SVG 를 훑는다엉뚱한 id·style이 따라와 다른 그림과 부딪힌다

9 서버 쪽으로 치면백엔드 감각으로 번역

변환은 서버에서원본 하나를 올려 두고 필요한 크기·포맷으로 내려주는 쪽이 파일을 따로 관리하는 것보다 쌉니다.
포맷이 더 큰 몫WebP·AVIF 로 바꾸면 절반 아래로 떨어집니다 — 배율보다 먼저 볼 일입니다.
캐시주소를 크기·포맷마다 따로 두면 CDN 이 안 어긋납니다.
업로드한 사진폰 사진은 4000px 이 넘습니다. 받자마자 쓸 크기로 줄여 저장합니다.
SVG 를 그대로 올리지 않는다사용자가 올린 SVG 에는 스크립트가 들어갈 수 있습니다. 걸러 내거나 비트맵으로 바꿉니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

벡터 한 벌 vs 배율별 비트맵이라는 선택은 어디나 같습니다.

웹SVG · srcset
icon.svg
photo@2x.webp
SVG 를 코드로 넣을 수 있는 것이 큰 이점입니다. 색·접근성을 CSS 로 다룹니다.
iOS@2x @3x · SF Symbols
icon@2x.png
icon@3x.png
파일 이름에 배율을 붙입니다. 시스템 아이콘(SF Symbols)은 내보낼 필요가 없습니다.
안드로이드벡터 드로어블
drawable/ic_store.xml
벡터 드로어블이 SVG 자리입니다. 쓰면 배율별 폴더가 필요 없습니다.

자주 생기는 사고 — "아이콘 파일 주세요"로 끝나면 나중에 색을 못 바꾸는 PNG가 쌓입니다. 받을 때 SVG 로, 색은 currentColor 로를 한 번 말해 두면 다크 모드·상태 색이 전부 공짜로 해결되고, 사진은 원본 한 장만 받아 서버에서 줄이는 쪽이 파일 관리보다 훨씬 쌉니다.
