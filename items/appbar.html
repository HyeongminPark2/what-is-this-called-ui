앱바 · 헤더

App bar · Header · Top bar

화면 꼭대기에 붙어 있는 띠. 지금 어디인지(제목), 어디서 왔는지(뒤로), 여기서 뭘 할 수 있는지(동작)를 한 줄에 담습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

목록을 스크롤해 보세요. 큰 제목이 올라가 사라지면 앱바가 얇아지면서 제목을 받아 갑니다 — 접히는 앱바(collapsing·large title)라 부릅니다. 꼭대기에 붙어 있어서(스티키) 어디까지 내려가도 돌아갈 길이 남습니다.

2 이름부르는 말이 여러 개다

한국어앱바, 헤더, 상단바, 툴바
영어app bar, header, top bar, navigation bar, toolbar
같이 쓰는 말스크롤해도 붙어 있으면 스티키 헤더, 내용 위에 투명하게 떠 있으면 오버레이 헤더, 큰 제목이 접히는 것을 접히는 앱바라 합니다.
자주 잘못 부름내비게이션 바 — iOS 에서는 이게 앱바를 뜻하지만, 웹에서는 메뉴 줄로 알아듣기 쉽습니다.
툴바 — 툴바는 동작 버튼만 모은 줄입니다. 제목과 뒤로가기가 있으면 앱바입니다.
탭 — 탭은 같은 화면 안의 전환이고, 앱바는 화면의 틀입니다.

3 가르는 기준형제들과 비교하는 네 축

길 안내 부품은 모두 '누르면 어디론가 간다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음

한 줄로 — 앱바는 화면의 틀입니다. 지금 어디인지와 나가는 길을 담되, 여기서 가장 자주 하는 일 한둘만 올립니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

‹ 거래 내역 ⌕ ⋯
아래 내용은 이 띠 밑으로 지나갑니다
  1. 앱바 app bar화면 폭을 다 쓰는 띠. 보통 44~64px 높이
  2. 뒤로 back왼쪽 첫 자리. 하위 화면이면 거의 언제나 여기 있다
  3. 제목 title지금 어디인지. 길면 말줄임하되 앞쪽을 남긴다
  4. 동작 actions여기서 가장 자주 하는 일. 둘까지가 적당하다
  5. 더 보기 overflow menu나머지는 ⋯ 안으로. 자주 안 쓰는 것을 넣는다
  6. 아래 내용 content앱바 밑으로 지나간다. 그래서 스크롤해도 앱바가 남는다

그림에 없는 것이 세이프 에어리어입니다. 폰에서는 앱바 위에 상태바(시계·배터리)가 겹치므로 그만큼 위쪽 여백을 더 둬야 합니다 — 안 두면 제목이 시계에 가립니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 화면마다 지금 어디인지를 알려야 할 때
  • 뒤로 갈 길이 필요할 때 — 하위 화면에서는 거의 언제나
  • 이 화면에서 가장 자주 하는 동작 한둘을 둘 때

이럴 때는 안 쓴다

  • 버튼을 넷 이상 올리기 — 좁은 화면에서 먼저 무너집니다
  • 제목 없이 아이콘만 두기 — 어디인지 알 수 없습니다
  • 스크롤하면 사라지게 두기 — 돌아갈 길까지 같이 사라집니다
  • 앱바에 주 내비게이션을 전부 넣기 → 사이드바나 탭바가 할 일입니다

대신 이걸 — 화면 사이를 오가면 사이드바나 바텀 탭바, 같은 화면의 다른 면이면 탭, 어디 있는지만 알리면 브레드크럼.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

position: sticky 한 줄이 앱바의 절반입니다. 나머지 절반은 무엇을 올리지 않을지입니다.

<header class="nav-app">
  <button aria-label="뒤로">‹</button>
  <h1>거래 내역</h1>
  <button aria-label="검색">⌕</button>
</header>

/* 꼭대기에 붙인다. 아래 내용이 밑으로 지나간다 */
.nav-app { position: sticky; top: 0; z-index: 20; }

/* 폰에서는 상태바만큼 위 여백을 더 둔다 */
padding-top: calc(12px + env(safe-area-inset-top));
키일어나야 하는 일
Tab페이지의 첫 칸들이다. 그래서 '본문으로 건너뛰기' 링크를 앞에 둔다
제목<h1>으로 두면 스크린 리더의 제목 목록에 잡힌다
아이콘 버튼글자가 없으면 aria-label이 꼭 필요하다. 툴팁도 같이 두면 좋다
Esc선택 모드·검색 모드에서는 Esc 로 빠져나갈 수 있게 한다
스티키스크롤해도 포커스가 앱바에 닿을 수 있어야 한다. 화면 밖으로 밀어내지 않는다

9 서버 쪽으로 치면백엔드 감각으로 번역

앱바 = 요청 컨텍스트제목·뒤로·동작이 전부 지금 보고 있는 리소스에서 나옵니다. 그 리소스가 없으면 앱바도 채울 수 없으니, 로딩 중에는 뼈대로 둡니다.
뒤로가기 = 계층 vs 이력앱바의 뒤로는 상위 리소스로, 브라우저 뒤로는 이전 화면으로 갑니다. 둘이 다를 수 있다는 걸 모르면 길을 잃는 사용자가 생깁니다.
동작 개수 = 권한권한에 따라 버튼이 줄어듭니다. 숨길지 비활성할지를 정해야 하고, 서버가 무엇을 내려 줄지와 묶입니다.
선택 모드 = 일괄 작업고른 것들에 한꺼번에 명령합니다. '전부 선택'이 조건인지 ID 목록인지에 따라 요청 모양이 달라집니다.
