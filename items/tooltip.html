툴팁

Tooltip

툴팁은 마우스를 올린 대상 옆에 짧은 설명 한 줄을 띄우는 작은 상자입니다. 안에는 누를 수 있는 것이 없고, 마우스를 올려야 뜨기 때문에 손가락으로 쓰는 터치 화면에서는 뜨지 않습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

버튼에 마우스를 올리고 잠깐 기다려 보세요. 마우스가 0.4초 동안 머물러야 툴팁이 뜨는데, 화면을 가로질러 지나가는 마우스에까지 툴팁이 뜨지 않도록 일부러 둔 지연입니다. 반면 Tab으로 포커스를 옮기면 기다리지 않고 바로 뜹니다. 키보드 포커스는 우연히 지나가는 일이 없으니 지연을 둘 이유가 없기 때문입니다.

지금 보는 기기는 호버를 지원하지 않습니다. 터치 화면에는 마우스를 올려 둔 상태가 없어서 툴팁이 뜰 계기가 생기지 않습니다. 따라서 툴팁에만 적어 둔 내용은 모바일 사용자에게 전혀 보이지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어툴팁, 말풍선, 도움말 풍선
영어tooltip
같이 쓰는 말툴팁이 뜨기까지 기다리는 시간은 지연(delay), 대상을 가리키는 뾰족한 부분은 꼬리(tail·arrow)라고 부릅니다.
자주 잘못 부르는 이름팝오버 — 안에 버튼이나 링크처럼 누를 것이 들어 있으면 툴팁이 아니라 팝오버입니다. 툴팁 안에 버튼을 넣으면 마우스를 버튼 쪽으로 옮기는 사이에 툴팁이 사라지기 때문에 그 버튼은 누를 수 없습니다.
팝업 — 화면 위에 뜨는 것을 모두 팝업이라고 부르면 툴팁과 팝오버, 모달을 서로 구별할 수 없게 됩니다.
title 속성 — title="…" 속성을 달면 브라우저가 기본 툴팁을 띄워 주지만, 지연 시간과 모양을 바꿀 수 없고 모바일에서는 뜨지 않습니다.

3 상태상태마다 달라지는 모습

4 해부도부분마다 붙은 이름

되돌리기 · Ctrl+Z
↺
  1. 상자 tooltip · bubble한두 줄에 맞춥니다. 두 줄을 넘기는 내용은 툴팁에 담기에 너무 깁니다
  2. 글 label대상의 이름이나 단축키를 적습니다. 설명이 길어지면 화면에 직접 적는 편이 낫습니다
  3. 꼬리 tail · arrow툴팁이 어느 대상을 설명하는지 가리킵니다
  4. 간격 offset트리거와 툴팁 사이의 거리입니다. 너무 가까우면 마우스 포인터가 툴팁 글자를 가립니다
  5. 트리거 trigger툴팁이 설명하는 대상입니다. aria-describedby로 트리거와 툴팁을 연결합니다

그림에는 보이지 않지만 툴팁에서 특히 중요한 요소가 지연(delay)입니다. 마우스가 대상 위에 머문 시간을 재서 0.3~0.5초가 지난 뒤에 툴팁을 띄웁니다. 이 값이 너무 짧으면 마우스가 지나갈 때마다 툴팁이 떴다 사라져 화면이 산만해집니다. 반대로 너무 길면 사용자가 기다리지 않고 마우스를 옮겨 버려서, 툴팁이 있다는 것조차 모르고 지나가게 됩니다.

5 쓸 때 / 안 쓸 때

툴팁을 쓰는 경우

  • 아이콘만 있는 버튼의 이름을 알려 줄 때
  • 말줄임으로 잘린 글자의 전체를 보여 줄 때
  • 비활성 버튼이 왜 못 눌리는지 알려 줄 때
  • 단축키처럼 알면 편하지만 몰라도 쓰는 데 지장이 없는 정보를 덧붙일 때

툴팁을 쓰지 않는 경우

  • 꼭 알아야 하는 정보를 담을 때. 모바일에서는 툴팁이 뜨지 않아서 볼 방법이 없습니다
  • 설명이 길거나 여러 줄일 때. 화면에 직접 적거나 팝오버를 씁니다
  • 안에 링크나 버튼을 넣을 때. 마우스를 옮기는 사이에 툴팁이 사라져 누를 수 없으니 팝오버를 씁니다
  • 버튼에 이미 적힌 글자를 툴팁으로 한 번 더 보여 줄 때

툴팁 대신 다른 것을 써야 하는 경우 — 안에 누를 것이 들어가야 하면 팝오버를 쓰고, 꼭 읽혀야 하는 내용이면 화면에 직접 적거나 헬퍼 텍스트로 보여 줍니다. 작업 결과를 알리는 용도라면 토스트가 맞습니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

title 속성을 쓰면 간단하지만 지연 시간과 모양을 바꿀 수 없고 모바일에서는 뜨지 않습니다. 그래서 툴팁을 직접 만들 때는 aria-describedby로 트리거와 툴팁을 연결해 스크린 리더도 설명을 읽을 수 있게 합니다.

<button aria-describedby="t1">↺</button>
<span id="t1" role="tooltip" hidden>되돌리기 · Ctrl+Z</span>

/* 툴팁은 누를 수 없게 한다. 팝오버와 구현이 갈리는 부분 */
.tip { pointer-events: none; }

// 마우스는 지연을 두고, 키보드는 바로
el.addEventListener('mouseenter', () => timer = setTimeout(show, 400));
btn.addEventListener('focus', show);

// 비활성 버튼은 포커스를 못 받으니 감싼 요소에 건다
<span tabindex="0" aria-describedby="t5"><button disabled>게시</button></span>
키와 마크업그때 일어나야 하는 일
Tab포커스가 오면 지연 없이 바로 뜹니다
Esc툴팁을 닫습니다. 툴팁이 읽으려는 글자를 가릴 때 씁니다
마우스를 올렸을 때0.3~0.5초 머물러야 뜨고, 마우스를 치우면 바로 사라집니다
터치 화면에서뜨지 않습니다. 길게 눌러 띄우게 만들 수는 있지만, 사용자 대부분이 그 동작을 모릅니다
스크린 리더로 읽을 때aria-describedby로 연결해 두면 버튼 이름을 읽은 뒤 툴팁 내용을 설명으로 읽어 줍니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

코드 주석과 같은 역할코드 주석이 프로그램 동작에 영향을 주지 않듯, 툴팁도 화면 동작에는 영향을 주지 않고 읽는 사람에게 정보만 줍니다. 그래서 툴팁이 없어도 화면을 쓰는 데 문제가 없어야 합니다. 중요한 전제 조건을 주석에만 적어 두면 놓치기 쉬운 것처럼, 지켜야 할 규칙을 툴팁에만 적어 두면 사용자가 놓칩니다.
지연은 디바운스와 같은 원리툴팁의 지연은 마우스가 지나가는 경우와 머무는 경우를 가르는 디바운스(debounce)입니다. 값이 너무 짧으면 툴팁이 자꾸 떠서 성가시고, 너무 길면 사용자가 툴팁이 뜨기 전에 마우스를 옮겨 버립니다.
툴팁 때문에 서버에 요청하지 않기툴팁을 띄우려고 서버에 요청을 보내야 한다면 대개 설계가 잘못된 것입니다. 툴팁 내용은 화면을 그릴 때 이미 받아 둔 데이터로 채울 수 있어야 합니다.
