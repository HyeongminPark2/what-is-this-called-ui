툴팁

Tooltip

가리킨 것을 한 줄로 설명만 하는 작은 말풍선. 안에 누를 것이 없고, 손가락으로 쓰는 화면에서는 뜨지 않습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

마우스를 올리고 잠깐 기다려 보세요. 0.4초 머물러야 뜹니다 — 지나가기만 할 때 안 뜨게 하는 지연입니다. Tab으로 옮기면 바로 뜹니다. 키보드는 '지나가기'가 없기 때문입니다.

지금 보는 기기에는 호버가 없습니다. 손가락은 '올려놓기'를 못 하니 툴팁이 뜰 일이 없습니다. 그래서 툴팁에만 담아 둔 말은 모바일에서 아무도 못 봅니다.

2 이름부르는 말이 여러 개다

한국어툴팁, 말풍선, 도움말 풍선
영어tooltip
같이 쓰는 말뜨기까지 기다리는 시간을 지연(delay), 가리키는 뾰족한 부분을 꼬리(tail·arrow)라 합니다.
자주 잘못 부름팝오버 — 안에 누를 것이 있으면 팝오버입니다. 툴팁에 버튼을 넣는 순간 그건 팝오버이고, 손이 닿기 전에 사라져서 못 누릅니다.
팝업 — 뜨는 것은 다 팝업이라 부르면 구별이 사라집니다.
title 속성 — title="…" 은 브라우저가 띄워 주는 원시 툴팁입니다. 지연도 모양도 못 바꾸고 모바일에서는 안 뜹니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

되돌리기 · Ctrl+Z
↺
  1. 상자 tooltip · bubble짧게. 두 줄을 넘기면 툴팁에 담을 내용이 아니다
  2. 글 label이름이나 단축키를 적는다. 설명문이 길어지면 화면에 적어야 할 말이다
  3. 꼬리 tail · arrow무엇에 대한 말인지 가리킨다
  4. 간격 offset트리거와 떨어진 거리. 너무 붙으면 손이 가릴 때 같이 가린다
  5. 트리거 trigger툴팁이 붙는 대상. aria-describedby 로 둘을 잇는다

그림에 없는 가장 중요한 부분이 지연(delay)입니다. 마우스가 머문 시간을 재서 0.3~0.5초가 지나야 띄웁니다. 이 숫자 하나가 '성가신 툴팁'과 '있는 줄도 몰랐던 툴팁'을 가릅니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 아이콘만 있는 버튼의 이름을 알려 줄 때
  • 말줄임으로 잘린 글자의 전체를 보여 줄 때
  • 비활성 버튼이 왜 못 눌리는지 알려 줄 때
  • 단축키처럼 있으면 좋고 없어도 되는 정보

이럴 때는 안 쓴다

  • 꼭 필요한 정보 — 모바일에서는 아무도 못 봅니다
  • 긴 설명이나 여러 줄 → 화면에 적거나 팝오버로
  • 안에 링크나 버튼 넣기 → 그 순간 팝오버이고, 손이 닿기 전에 사라집니다
  • 이미 글자가 있는 버튼에 같은 말 반복하기

대신 이걸 — 누를 것이 들어가면 팝오버, 꼭 읽혀야 하면 화면에 적거나 헬퍼 텍스트, 결과 알림이면 토스트.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

title 속성은 쉽지만 지연도 모양도 못 바꾸고 모바일에서 안 뜹니다. 직접 만들 때는 aria-describedby 로 트리거와 이어 줍니다.

<button aria-describedby="t1">↺</button>
<span id="t1" role="tooltip" hidden>되돌리기 · Ctrl+Z</span>

/* 툴팁은 못 누른다 — 이 한 줄이 팝오버와 갈리는 곳 */
.tip { pointer-events: none; }

// 마우스는 지연을 두고, 키보드는 바로
el.addEventListener('mouseenter', () => timer = setTimeout(show, 400));
btn.addEventListener('focus', show);

// 비활성 버튼은 포커스를 못 받으니 감싼 요소에 건다
<span tabindex="0" aria-describedby="t5"><button disabled>게시</button></span>
키일어나야 하는 일
Tab포커스가 닿으면 지연 없이 바로 뜬다
Esc닫는다. 툴팁이 읽으려는 글자를 가릴 때가 있다
마우스 올림0.3~0.5초 머물러야 뜬다. 치우면 바로 사라진다
터치뜨지 않는다. 길게 누르기로 띄우는 방법도 있지만 아무도 모른다
스크린 리더aria-describedby 로 이어 두면 버튼 이름 뒤에 설명으로 읽힌다

9 서버 쪽으로 치면백엔드 감각으로 번역

툴팁 = 코드 주석동작에는 아무 영향이 없고 읽는 사람만 돕습니다. 없어도 돌아가야 합니다. 주석에만 적힌 전제 조건이 위험하듯, 툴팁에만 적힌 규칙도 위험합니다.
지연 = 디바운스마우스가 지나가는 것과 머무는 것을 가르는 디바운스입니다. 숫자를 잘못 잡으면 성가시거나 없는 것이 됩니다.
서버 왕복 없음툴팁 때문에 요청을 보내면 거의 설계가 잘못된 것입니다. 내용은 이미 화면에 있어야 합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

툴팁은 마우스가 있는 화면의 부품입니다. 모바일 지침에는 사실상 자리가 없습니다.
