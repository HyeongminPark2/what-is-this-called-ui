스테퍼

Stepper · wizard

스테퍼는 긴 입력 과정을 몇 단계로 나누고, 지금 몇 번째 단계인지와 얼마나 남았는지를 함께 보여 줍니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

단계 이름은 잘리면 안 됩니다. 데모는 칸마다 이름 글자 전체의 폭과 실제로 보이는 폭을 비교해서 이름이 잘린 단계가 몇 개인지 셉니다. 가로 배치 그대로 폭을 줄이면 단계 이름부터 잘리고, '좁으면 세로로'를 켜면 같은 폭에서도 이름이 잘리지 않습니다.
끝낸 단계는 눌러서 되돌아갈 수 있어야 합니다. 이 기능을 끄면 끝낸 단계를 눌러도 이동하지 않는데, 그러면 배송지를 잘못 적은 사용자가 처음부터 다시 해야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어스테퍼, 단계 표시, 진행 단계, 위저드
영어stepper, wizard, progress steps, multi-step form
같이 쓰는 말앞 단계를 끝내야만 다음 단계로 갈 수 있는 것은 선형(linear), 아무 단계나 오갈 수 있는 것은 비선형(non-linear)이라고 합니다. 한 화면에 한 단계씩 보여 주는 긴 흐름은 위저드라고 부릅니다. Material에는 Stepper라는 부품이 있고, iOS에는 정해진 부품이 없어서 페이지 컨트롤이나 화면 전환으로 단계를 보여 줍니다.
자주 잘못 부르는 이름프로그레스 바 — 프로그레스 바는 기계가 하는 일이 얼마나 진행됐는지 보여 주고, 스테퍼는 사람이 해야 할 일의 차례를 보여 줍니다.
탭 — 탭은 순서 없이 내용 묶음을 바꿔 보여 주는 부품이고, 스테퍼는 정해진 순서대로 나아갑니다.
브레드크럼 — 브레드크럼은 계층을 보여 주고, 스테퍼는 차례를 보여 줍니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

길 안내 부품은 모두 누르면 다른 곳으로 옮겨 간다는 점이 같습니다. 그래서 아래 네 가지를 물어보면 서로 구별할 수 있습니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

번호 또는 ✓ — 끝났는지 한눈에
지금 단계 — 색 + aria-current="step"
단계 이름 — 잘리면 안 된다
적은 값 요약 — '모란상회'
끝낸 단계는 눌러서 되돌아간다
좁으면 가로가 먼저 무너진다 — 세로로
  1. 번호 · ✓ 끝났는지단계 번호를 보면 몇 단계가 남았는지 알 수 있습니다
  2. 지금 단계 색 + aria-current스크린 리더 사용자도 알 수 있도록 소리로도 전해져야 합니다
  3. 단계 이름 잘리면 안 됨자리가 모자라면 이름을 짧게 고칩니다
  4. 적은 값 요약앞 단계에서 적은 값을 보여 줘서 되돌아갈지 판단할 수 있게 합니다
  5. 되돌아가기 끝낸 단계만아직 안 간 뒤 단계로는 건너뛰지 못하게 막습니다
  6. 좁은 화면 세로로가로 스테퍼는 390px 폭에서 이름이 잘리고 배치가 깨집니다

스테퍼를 붙이기 전에 먼저 정말 단계를 나눠야 하는지 따져 봐야 합니다. 입력 칸이 여덟 개인 폼을 네 단계로 나누면 화면은 깔끔해지지만 끝까지 마치는 사람은 줄어듭니다. 단계를 넘어갈 때마다 사용자가 그만둘 기회가 한 번씩 더 생기기 때문입니다.
나눠야 한다면 하는 일의 성격에 따라 나눕니다. 예를 들어 '배송지'와 '결제 수단'은 서로 다른 일이라 나눌 만하지만, '이름'과 '전화번호'를 다른 단계로 나누면 단계 수만 늘어납니다.

6 쓸 때 / 안 쓸 때

스테퍼를 쓰는 경우

  • 단계를 세 개에서 다섯 개 사이로 둘 때
  • 끝낸 단계는 눌러서 되돌아갈 수 있게 할 때
  • 폰에서는 세로로 바꾸거나 '2/4' 같은 글로 줄일 때

스테퍼를 쓰지 않는 경우

  • 아직 안 간 단계로 건너뛰게 둘 때. 뒤 단계는 앞 단계에서 적은 값을 바탕으로 진행됩니다
  • 되돌아갈 때 이미 적은 값을 지울 때. 사용자가 같은 내용을 다시 적어야 해서 가장 크게 불만을 느끼는 부분입니다
  • 단계 이름을 '1단계 · 2단계'로 둘 때. 이름에는 그 단계에서 무엇을 하는지를 적습니다
  • 지금 단계를 색으로만 알릴 때

스테퍼 대신 다른 것을 써야 하는 경우 — 기계가 하는 일의 진척은 프로그레스 바, 순서 없는 묶음은 탭, 계층은 브레드크럼, 흐름 전체 설계는 결제 흐름.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

단계는 순서가 있는 목록이므로 <ol>로 적고, 지금 단계에만 aria-current를 달아 알립니다.

<ol class="stepper">
  <li><a href="#cart"><span aria-hidden="true">✓</span> 장바구니 확인</a></li>
  <li aria-current="step">배송지 입력</li>
  <li>결제 수단</li>
  <li>주문 확인</li>
</ol>

/* 이름이 잘리는 것보다 세로로 늘어놓는 편이 낫다 */
@media (max-width: 480px) {
  .stepper { display: grid; gap: 6px; }
}
키와 동작그때 일어나야 하는 일
Tab끝낸 단계의 링크만 포커스를 받고, 아직 안 간 단계는 포커스를 받지 않습니다
Enter포커스가 있는 단계로 돌아갑니다
aria-current="step"지금 단계에 답니다. 한 페이지에 하나만 있어야 합니다
<ol>단계에 순서가 있다는 정보가 스크린 리더에서 소리로 전해집니다
aria-disabled아직 갈 수 없는 단계에 붙입니다. 포커스는 받지만 눌러도 이동하지 않습니다
확인하는 법Tab으로 단계를 돌면서 아직 안 간 단계가 포커스를 받는지 확인합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

단계마다 저장입력 내용을 마지막 단계에서 한 번에 보내면 중간에 연결이 끊기거나 창을 닫았을 때 적은 내용이 모두 사라집니다. 단계마다 임시 저장해 두면 사용자가 나중에 돌아와 이어서 할 수 있습니다.
초안 id첫 단계에서 draft_id를 받아 두고, 이후 단계에서는 그 초안에 값을 채워 넣습니다.
검증은 단계마다단계마다 그 단계의 입력 칸만 검사해서 결과를 돌려줍니다. 마지막에 모든 오류를 한꺼번에 돌려주면 사용자는 어느 단계로 돌아가야 하는지 알 수 없습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

웹과 안드로이드에서는 스테퍼를 쓰지만, iOS에는 스테퍼 부품이 없습니다.

웹직접 만듦
✓장바구니●배송지·결제
정해진 부품이 없어서 <ol>에 aria-current를 붙여 직접 만듭니다.
iOS없다 — 화면 전환
2 / 4
스테퍼 부품이 없습니다. HIG에 맞는 방식은 단계마다 화면을 넘기고 제목에 '2/4'처럼 적는 것입니다.
안드로이드Stepper
Material에는 가로 스테퍼와 세로 스테퍼가 정식 부품으로 있습니다. 세로 스테퍼는 단계 아래에 그 단계의 내용까지 펼쳐 보여 줍니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS에 스테퍼가 없는 것은 빠뜨려서가 아니라 일부러 그렇게 정했기 때문입니다. 단계 띠에 화면 자리를 쓰는 대신 화면을 넘기고 제목 한 줄로 단계를 알리는 방식인데, 좁은 화면에서는 이 방식이 대체로 낫습니다. 그래서 웹에서도 폰 폭에서는 단계 띠를 접고 '2 / 4 단계' 한 줄로 줄이는 것이 안전합니다. 안드로이드의 세로 스테퍼는 단계 아래에 그 단계의 내용까지 펼쳐 두는 형태라서 긴 서식에 쓰기 좋습니다.
