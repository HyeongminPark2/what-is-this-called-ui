오래된 데이터

Stale data

다시 받는 동안 화면을 비우면 그동안 아무것도 못 읽습니다. 옛 값을 두되 언제 숫자인지를 적습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

비우면 그동안 아무것도 못 읽습니다 — 데모가 숫자가 사라져 있던 시간(ms)을 재서 적습니다. 옛 값을 두면 그 시간이 0입니다.
대신 옛 값에는 언제 숫자인지를 붙여야 합니다 — '3분 전 기준'이 없으면 방금 받은 값인 줄 압니다. 체크를 끄고 보면 숫자만 덩그러니 남습니다.
다시 받는 동안에는 숫자를 흐리게 해 지금 바뀌는 중임을 알립니다.

2 이름부르는 말이 여러 개다

한국어오래된 데이터, 묵은 값, 캐시된 값
영어stale data, stale-while-revalidate, cached value
같이 쓰는 말옛 값을 보여 주면서 뒤에서 새로 받아 오는 방식을 stale-while-revalidate 라 부릅니다. 값이 만들어진 시각을 as of(기준 시각), 얼마나 묵었는지를 나이(age)라 하고, '3분 전 기준' 같은 표시를 신선도 표시라 합니다.
자주 잘못 부름캐시 — 캐시는 저장하는 장치이고, 이건 보여 주는 방식입니다.
낙관적 UI — 낙관적 UI는 앞으로 될 값을 미리 보입니다. 이건 지난 값입니다.
오프라인 — 오프라인은 연결이 없을 때입니다.

3 가르는 기준형제들과 비교하는 네 축

다시 받는 동안 보여 주는 방법들입니다. 이 네 가지만 물어보면 갈립니다.

다시 받는 동안언제 숫자인지틀린 값을 보일 위험쓸 만한 자리
옛 값을 보임읽을 수 있다적어야 한다있다 — 그래서 적는다목록 · 대시보드
비우고 스피너아무것도 못 읽는다필요 없다없다처음 들어올 때
스켈레톤자리만 보인다필요 없다없다처음 들어올 때
옛 값 + 흐리게읽을 수 있다적어야 한다작다 — 바뀌는 중이 보인다거의 늘 이쪽

한 줄로 — 옛 값이라도 보여 주세요. 대신 언제 숫자인지를 반드시 적습니다.

4 상태빈 화면을 만드는가

5 해부도부분 이름이 제일 안 알려진 지식

옛 값을 그대로 둔다 — 빈 화면을 안 만든다
언제 숫자인지 — '3분 전 기준'
다시 받는 중에는 흐리게
적지 않으면 방금 값인 줄 안다
새로 고침 단추 — 사람이 직접 부를 길
돈 · 재고처럼 틀리면 안 되는 값은 예외
  1. 옛 값 그대로 둠빈 화면을 안 만든다
  2. 기준 시각 '3분 전'반드시 적는다
  3. 흐리게 다시 받는 중바뀌는 중임을 알린다
  4. 안 적으면 거짓말방금 값인 줄 안다
  5. 새로 고침 사람이 부를 길기다리기 싫을 때
  6. 예외 돈 · 재고틀리면 안 되는 값

이 방식에는 분명한 예외가 있습니다 — 틀린 값을 보이면 안 되는 자리입니다. 남은 재고, 계좌 잔액, 경매 남은 시간 같은 것은 3분 전 값을 보이면 사람이 잘못된 판단을 합니다. 그런 자리에서는 차라리 비우고 기다리게 하거나, '확인 중'이라고 적고 동작을 막습니다.
반대로 목록·대시보드처럼 대충 맞으면 되는 값은 옛 값을 보이는 쪽이 늘 낫습니다 — 화면이 깜빡이지 않고, 굴린 자리도 안 튑니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 다시 받는 동안 옛 값을 그대로 두기
  • '○분 전 기준'을 숫자 옆에 적기
  • 너무 묵으면 새로 고침을 권하기

이럴 때는 안 쓴다

  • 다시 받을 때마다 화면 비우기 — 깜빡이고 자리가 튄다
  • 기준 시각을 안 적기 — 방금 값인 줄 안다
  • 재고·잔액 같은 값에 옛 값 쓰기
  • '마지막 업데이트' 를 절대 시각으로만 적기 — '3분 전'이 더 읽기 쉽다

대신 이걸 — 처음 그릴 때는 스켈레톤, 앞으로 될 값은 낙관적 UI, 연결이 없으면 오프라인, 바뀌는 자리만 고치려면 부분 로딩.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 값의 계약서

옛 값을 지우지 않고, 기준 시각을 <time> 으로 적습니다.

<p class="big" aria-busy="true">1,284만원</p>
<p class="asof">
  <time datetime="2026-11-14T09:00">3분 전</time> 기준
  <button>새로 고침</button>
</p>

// 다시 받는 동안 옛 값을 지우지 않는다
state.loading = true;              // data 는 그대로 둔다
state.data = await api.get();      // 온 뒤에만 바꾼다
state.asOf = Date.now();
state.loading = false;

/* 바뀌는 중에는 흐리게 */
[aria-busy="true"] { opacity: .55; transition: opacity .15s; }
키일어나야 하는 일
aria-busy다시 받는 중임을 그 자리에 붙인다
<time datetime>기준 시각을 기계도 읽게 적는다
aria-live숫자가 저절로 바뀌면 조심한다 — 계속 읽어 댄다
새로 고침 단추자동만 믿지 말고 사람이 부를 길을 둔다
초점다시 받아도 초점이 날아가지 않게
확인하는 법네트워크를 느리게 걸고 빈 화면이 생기는지 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

기준 시각을 같이as_of 가 응답에 있어야 화면이 '3분 전'을 적을 수 있습니다.
얼마나 묵어도 되나max-age 를 정해 주면 화면이 언제 새로 받을지 압니다.
ETag안 바뀌었으면 304 로 답해 통신을 아낍니다.
정확해야 하는 값재고·잔액은 캐시하지 말라고 응답에 적어 주는 편이 안전합니다.

당겨서 새로 고침이 표준이라 '사람이 부르는 길'이 늘 있습니다.
안드로이드SwipeRefresh
같은 꼴입니다. 옛 값을 보이면서 위에 고리가 돕니다.

자주 생기는 사고 — 폰의 당겨서 새로 고침은 '옛 값을 보이다가 사람이 부르면 새로 받는다'를 한 몸짓으로 만든 것입니다 — 그래서 앱에서는 이 방식이 기본처럼 자리 잡았습니다. 웹에는 그 몸짓이 없으니 새로 고침 단추를 눈에 띄게 두는 편이 낫고, 기준 시각 옆에 두면 '묵었구나 → 눌러야겠다'가 한 줄에서 이어집니다.
