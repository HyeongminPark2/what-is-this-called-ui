배지

Badge · notification badge

배지는 아이콘이나 목록 줄 같은 다른 요소에 붙어서 정보를 하나 더 알려 주는 작은 표시입니다. 배지만 따로 떨어져 놓이는 일은 없습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 끝까지 밀어 보세요. 숫자가 세 자리가 되면 99+로 줄어드는데, 줄이지 않으면 배지가 길어져서 붙어 있던 아이콘을 밀어내기 때문입니다. 반대로 0으로 내리면 배지가 아예 사라집니다. 알릴 것이 없을 때 '0건'을 굳이 보여 줄 이유가 없기 때문입니다.
화면 아래의 스크린 리더가 읽는 말도 함께 바뀝니다. 빨간 동그라미만으로는 스크린 리더가 아무것도 읽어 줄 수 없으므로, 배지가 붙은 요소에 뜻을 글로 적어 두어야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어배지, 알림 배지, 뱃지, 상태 라벨, 태그
영어badge, notification badge, dot badge, status label, pill
같이 쓰는 말숫자 없이 점만 찍은 것은 점 배지(dot badge), 숫자가 든 것은 카운트 배지(count badge), 글자가 든 알약 모양은 라벨 배지 또는 필(pill)이라고 부릅니다. 배지가 붙는 아이콘이나 줄은 앵커(anchor)라고 합니다.
자주 잘못 부르는 이름칩 — 배지와 가장 자주 헷갈리는 부품입니다. 칩은 눌러서 목록을 거르거나 뗄 수 있고, 배지는 다른 요소에 붙어서 알리기만 합니다.
태그 — 태그는 사용자가 직접 붙인 분류이고, 배지는 시스템이 알려 주는 상태입니다.
토스트 — 토스트는 화면에 잠깐 떠서 알린 뒤 사라지고, 배지는 요소에 붙은 채로 남아 있습니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

표시 부품은 모두 보여 주기만 합니다. 아래 네 가지로 서로 가릅니다.

무엇을 담는가부품 전체를 누를 수 있는가여러 개가 어떻게 모이는가내용이 길어지면 어떻게 하는가
카드한 덩어리보통 눌림그리드로 늘어섬높이가 늘어남
리스트 아이템한 건보통 눌림세로 목록으로 쌓임말줄임함
아바타사람·조직 하나눌리지 않음겹쳐 쌓음크기는 고정하고 넘치면 +N으로 줄임
배지숫자나 한 낱말눌리지 않음혼자 놓이지 않고 다른 요소에 붙음크기는 고정하고 넘치면 99+로 줄임
칩한 낱말눌림가로로 늘어서다 줄을 바꿈말줄임하거나 줄을 넘김
스탯 타일숫자 하나가끔 눌림가로 한 줄로 늘어섬단위를 줄인다(1.2만)
타임라인사건들의 순서항목만 눌림세로 선으로 이음아래로 길어짐
별점점수 하나읽기용은 눌리지 않음줄 안에 들어감별 다섯 개로 고정됨
아이콘뜻 하나혼자서는 눌리지 않음글자 옆에 붙음아이콘은 그대로 두고 옆 글자가 길어짐
썸네일그림 하나보통 눌림격자로 늘어섬칸은 고정하고 사진을 자르거나 여백을 남김
테이블 행한 건의 여러 값행 전체나 주 열만 눌림세로로 쌓임말줄임함
키-값 목록이름과 값의 짝눌리지 않음세로로 쌓임값이 먼저 잘림
미디어 오브젝트그림과 글보통 눌림세로 목록으로 쌓임글 쪽만 늘어남
접히는 글제목과 본문제목이 눌림세로로 쌓음접어 둠
태그한 낱말눌리지 않음가로로 늘어서다 줄을 바꿈말줄임하거나 +N으로 접음

배지를 한 줄로 정리하면 — 배지는 늘 다른 요소에 붙어 있습니다. 따로 떨어져 놓여 있고 누를 수도 있다면 그건 배지가 아니라 칩입니다.

4 배지의 종류종류마다 알리는 내용

5 해부도부분마다 붙은 이름

✉ 3 배지는 혼자 놓이지 않고 늘 무언가에 붙음
top: -6px; right: -8px
99+세 자리가 되면 이렇게 줄임
승인됨한 낱말짜리 라벨 배지
aria-label="읽지 않음 3건"
  1. 앵커 anchor배지가 붙는 아이콘, 줄, 탭입니다. 배지는 앵커 없이 혼자 쓰지 않습니다
  2. 자리 position보통 앵커의 오른쪽 위 모서리에 붙습니다. 앵커에 position: relative 한 줄이 빠지면 배지가 화면 구석으로 가서 붙습니다
  3. 넘침 규칙 overflow · 99+두 자리까지만 그대로 보여 주고 그보다 크면 99+로 줄입니다. 숫자가 몇이든 같은 규칙이 적용되도록 규칙부터 정해 둡니다
  4. 라벨 배지 status label숫자 대신 한 낱말을 담습니다. 목록 줄의 뒤쪽 자리에 자주 놓입니다
  5. 읽히는 말 aria-label빨간 점은 스크린 리더가 읽어 줄 내용이 없습니다. 그래서 앵커에 뜻을 글로 적어 둡니다

배지를 붙일 때 특히 자주 생기는 오류가 두 가지 있습니다. ① 앵커에 position: relative를 주지 않아서 배지가 화면 구석에 가서 붙습니다. ② 앵커나 그 바깥 상자에 overflow: hidden이 걸려 있어서 모서리 밖으로 나간 배지가 잘립니다. 두 오류 모두 '배지가 안 보여요'라는 제보로 들어오지만 원인은 서로 다릅니다.

6 쓸 때 / 안 쓸 때

배지를 쓰는 경우

  • 안 읽은 것이나 처리할 것이 몇 건인지 알릴 때
  • 목록에서 승인됨, 검토 중, 거절됨처럼 상태를 한 낱말로 보여 줄 때
  • 탭이나 메뉴에 새로 들어온 것이 있다고 표시할 때

배지를 쓰지 않는 경우

  • 배지를 늘 켜 둘 때. 꺼지지 않는 빨간 점에는 사용자가 금세 익숙해져서 더는 눈여겨보지 않습니다
  • 배지를 누를 수 있게 만들 때. 누르는 것이라면 배지가 아니라 칩이나 버튼입니다
  • 0건을 '0'으로 보여 줄 때. 알릴 것이 없으면 배지를 없애야 합니다
  • 색만으로 뜻을 전할 때. 빨강과 초록은 색맹인 사람에게 같은 회색으로 보입니다

배지 대신 다른 것을 써야 하는 경우 — 눌러서 목록을 걸러야 하면 칩을 쓰고, 잠깐 떠서 알린 뒤 사라져야 하면 토스트를 씁니다. 일이 얼마나 진행됐는지 보여 주려면 프로그레스 바가 맞습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 규칙구현할 때 지킬 최소 규칙

배지에는 따로 정해진 역할(role)이 없습니다. 그래서 스크린 리더가 읽을 말은 배지가 아니라 배지가 붙는 앵커에 적어 두는 것이 중요합니다.

<a href="/inbox" class="anchor"
   aria-label="메일 — 읽지 않음 3건">
  <svg aria-hidden="true">…</svg>
  <span class="bdg" aria-hidden="true">3</span>
</a>

.anchor { position: relative; }   /* 이 줄이 없으면 배지가 화면 구석으로 간다 */
.bdg { position: absolute; top: -6px; right: -8px; }
.bdg[hidden] { display: none; } /* 이 줄이 없으면 inline-flex 가 hidden 보다 우선한다 */

// 숫자는 화면용으로만 줄이고, 읽히는 말에는 원래 수를 둔다
badge.textContent = n > 99 ? '99+' : n;
badge.hidden = (n === 0);
지킬 규칙지키는 방법
앵커에 position: relative 주기빠지면 배지가 화면 구석에 가서 붙습니다. 배지 관련 제보 가운데 가장 많습니다
overflow: hidden에 잘리지 않게 하기모서리 밖으로 나간 배지가 잘립니다. 앵커 대신 안쪽 요소가 모서리를 깎도록 바꿉니다
0건이면 배지 없애기hidden을 주되, display 값이 hidden보다 우선해서 배지가 그대로 보이지 않는지 확인합니다
세 자리 숫자는 99+로 줄이기배지가 길어지면 앵커를 밀어냅니다. 글자 수보다 배지 폭이 늘어나는 것이 문제입니다
읽힐 말은 앵커에 적기배지 자체는 aria-hidden으로 숨기고, 읽힐 말은 앵커의 aria-label에 적습니다
숫자가 저절로 바뀌면 aria-live 쓰기숫자가 저절로 바뀌는 자리라면 polite로 알립니다. 다만 너무 자주 바뀌면 스크린 리더가 계속 읽어서 번거롭습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

배지 숫자를 받아 오는 곳배지 숫자는 보통 개수만 따로 세는 API에서 받습니다. 목록을 모두 받아 화면에서 세면 느리고, 목록이 100건을 넘으면 받은 만큼만 세게 되어 숫자가 틀립니다. 그래서 unread_count 값 하나를 돌려주는 쪽이 낫습니다.
99+로 줄이면 가벼워지는 세기화면에 99+까지만 보여 준다면 정확한 수가 필요 없으므로 세는 비용도 줄일 수 있습니다. 'COUNT(*) LIMIT 100' 처럼 100까지만 세고 멈추는 질의가 전체를 세는 질의보다 훨씬 가볍습니다.
읽은 뒤 숫자가 줄어드는 시점읽음 처리와 배지 숫자가 줄어드는 시점 사이에 시차가 생기면 '읽었는데 배지가 안 없어져요'라는 문의가 들어옵니다. 그래서 화면에서 먼저 숫자를 줄이고(낙관적 UI) 서버 응답이 오면 그 값으로 맞춥니다.
서버가 숫자를 밀어 줄 때웹소켓이나 푸시로 서버가 숫자를 보내 주면 새로고침하지 않아도 배지가 바뀝니다. 다만 변경을 짧은 사이에 연달아 보내면 숫자가 깜빡이는 것처럼 보이므로, 여러 변경을 묶어서 보냅니다.
