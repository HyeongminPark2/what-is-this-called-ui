새 탭에서 열기 ↗

막대를 끝까지 밀어 보세요. 세 자리가 되면 99+로 줄어듭니다 — 안 줄이면 배지가 길어져 붙어 있던 아이콘을 밀어냅니다. 0으로 내리면 배지가 아예 사라집니다. '0건'을 보여 줄 이유가 없습니다.
화면 아래에 스크린 리더가 읽는 말이 같이 바뀝니다. 빨간 동그라미는 그 자체로 아무 뜻이 아니라서, 붙은 쪽에 말로 적어 둬야 합니다.

2 이름부르는 말이 여러 개다

한국어배지, 알림 배지, 뱃지, 상태 라벨, 태그
영어badge, notification badge, dot badge, status label, pill
같이 쓰는 말숫자 없이 점만 찍은 것을 점 배지(dot badge), 숫자가 든 것을 카운트 배지(count badge), 글자가 든 알약 모양을 라벨 배지 또는 필(pill)이라 합니다. 배지가 붙는 쪽(아이콘·줄)은 앵커(anchor)입니다.
자주 잘못 부름칩 — 가장 잦은 혼동입니다. 칩은 눌러서 거르거나 뗄 수 있고, 배지는 붙어서 알리기만 합니다.
태그 — 태그는 내가 붙인 분류입니다. 배지는 시스템이 말해 주는 상태입니다.
토스트 — 토스트는 떠서 알리고 사라집니다. 배지는 붙어서 남습니다.

3 가르는 기준형제들과 비교하는 네 축

표시 부품은 '보여 주기만 한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로말줄임한다
아바타사람·조직 하나안 눌린다겹쳐 쌓는다고정 — 넘치면 +N
배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+
칩한 낱말눌린다가로로 줄바꿈말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)
타임라인사건들의 순서항목만세로로 꿴다아래로 길어진다
별점점수 하나읽기용은 안 눌린다줄 안에 들어간다고정 — 별 다섯

한 줄로 — 배지는 붙어 있어야 배지입니다. 혼자 서 있고 누를 수 있으면 그건 칩입니다.

5 해부도부분 이름이 제일 안 알려진 지식

✉ 3 배지는 혼자 서지 않는다 — 늘 무엇에 붙는다
top: -6px; right: -8px
99+세 자리가 되면 이렇게 줄인다
승인됨한 낱말짜리 라벨 배지
aria-label="읽지 않음 3건"
  1. 앵커 anchor배지가 붙는 쪽. 아이콘·줄·탭. 이것 없이는 배지가 없다
  2. 자리 position보통 오른쪽 위 모서리. 앵커에 position: relative 한 줄이 빠지면 화면 구석으로 날아간다
  3. 넘침 규칙 overflow · 99+두 자리까지만 보이고 그 위는 99+. 숫자가 아니라 규칙을 먼저 정한다
  4. 라벨 배지 status label숫자가 아니라 한 낱말. 목록의 뒤쪽 자리에 자주 온다
  5. 읽히는 말 aria-label빨간 점은 소리로는 아무것도 아니다. 앵커에 말로 적어 둔다

배지를 붙일 때 가장 자주 나는 사고 둘입니다. ① 앵커에 position: relative를 안 줘서 배지가 화면 구석으로 날아갑니다. ② 앵커나 그 위 상자에 overflow: hidden이 걸려 있어 모서리 밖으로 나간 배지가 잘립니다. 둘 다 '배지가 안 보여요'로 제보되는데 원인이 다릅니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 안 읽은 것·처리할 것이 몇 건인지 알릴 때
  • 목록에서 상태를 한 낱말로 보여 줄 때 — 승인됨·검토 중·거절됨
  • 탭이나 메뉴에 '여기 새것이 있다'를 표시할 때

이럴 때는 안 쓴다

  • 늘 켜 두는 것 — 안 꺼지는 빨간 점은 금세 안 보이게 됩니다
  • 누르게 만드는 것 → 그건 칩이나 버튼입니다
  • 0건을 '0'으로 보여 주는 것 — 없으면 없애야 합니다
  • 색만으로 뜻을 말하는 것 — 빨강/초록은 색맹에게 같은 회색입니다

대신 이걸 — 눌러서 거르면 칩, 떠서 알리고 사라지면 토스트, 진행 정도면 프로그레스 바.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙이 부품의 계약서

배지에는 정해진 역할이 없습니다. 중요한 것은 붙는 쪽이 말을 갖는 것입니다.

<a href="/inbox" class="anchor"
   aria-label="메일 — 읽지 않음 3건">
  <svg aria-hidden="true">…</svg>
  <span class="bdg" aria-hidden="true">3</span>
</a>

.anchor { position: relative; }   /* 이게 없으면 배지가 날아간다 */
.bdg { position: absolute; top: -6px; right: -8px; }
.bdg[hidden] { display: none; } /* inline-flex 가 hidden 을 이긴다 */

// 숫자는 화면용으로만 줄이고, 읽히는 말에는 원래 수를 둔다
badge.textContent = n > 99 ? '99+' : n;
badge.hidden = (n === 0);
규칙지켜야 하는 것
앵커에 position: relative빠지면 배지가 화면 구석에 가서 붙는다. 제보 1위
overflow: hidden을 조심모서리 밖으로 나간 배지가 잘린다. 안쪽 요소가 모서리를 깎게 바꾼다
0이면 없앤다hidden을 주되 display가 이기지 않는지 확인한다
99+ 로 줄인다길어지면 앵커를 밀어낸다. 글자 수가 아니라 폭이 문제다
말은 앵커가 갖는다배지 자체는 aria-hidden으로 숨기고, 앵커의 aria-label에 적는다
실시간이면 aria-live숫자가 저절로 바뀌는 자리면 polite로 알린다 — 다만 자주 바뀌면 시끄럽다

9 서버 쪽으로 치면백엔드 감각으로 번역

개수는 어디서 오나배지 숫자는 보통 따로 세는 API입니다. 목록을 다 받아 세면 느리고, 목록이 100건을 넘으면 틀립니다. unread_count 하나를 돌려주는 쪽이 낫습니다.
99+ 로 줄이는 이유정확한 수가 필요 없으면 세는 비용도 줄일 수 있습니다. 'COUNT(*) LIMIT 100' 처럼 100까지만 세고 멈추는 질의가 훨씬 쌉니다.
언제 줄어드나읽음 처리와 배지 감소 사이에 시차가 생기면 '읽었는데 안 없어져요'가 됩니다. 화면에서 먼저 줄이고(낙관적 UI) 서버 응답으로 맞춥니다.
밀어 주기웹소켓이나 푸시로 수를 밀어 주면 새로고침 없이 바뀝니다. 다만 한 번에 몰아 보내면 숫자가 깜빡여 보이니 묶어서 보냅니다.
