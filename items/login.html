2 이름같은 것을 부르는 여러 이름

한국어로그인, 사인인, 인증
영어sign in, log in, authentication
같이 쓰는 말누구인지 확인하는 일을 인증(authentication), 무엇을 할 수 있는지 정하는 일을 인가(authorization)라고 합니다. 둘 다 auth로 줄여 쓰기 때문에 자주 섞입니다. 로그인한 상태를 이어 가는 것을 세션이라 하고, 그 상태를 증명하는 값으로 쿠키나 토큰을 씁니다. 아이디만 먼저 받는 방식은 단계 로그인(identifier-first)이라고 부릅니다.
자주 잘못 부르는 이름가입 — 계정을 만드는 화면과 이미 있는 계정으로 들어오는 화면은 서로 다른 화면입니다. 한 화면에 섞어 두면 어느 쪽 목적도 분명하게 드러나지 않습니다.
인증 — 휴대폰 인증 같은 본인 확인은 로그인과 다른 절차입니다.
로그인 유지 — '자동 로그인'과 '로그인 상태 유지'가 섞여 쓰이기 때문에, 무엇을 얼마나 오래 유지하는지 적어 두는 편이 낫습니다.

4 로그인 화면의 상태여섯 가지 모두 만들어야 하는 상태

5 해부도부분마다 붙은 이름

autocomplete="username" · "current-password"
비밀번호
••••••
'아이디 또는 비밀번호'로 묶어 어느 쪽이 틀렸는지 숨김
'비밀번호를 잊으셨나요?'는 늘 같은 자리에 둠
로그인 상태 유지는 오래 가는 쿠키로 처리
자동완성을 끄면 더 쉬운 비밀번호를 쓰게 됨
  1. 자동완성 힌트 autocompleteusername·current-password를 적습니다. 비밀번호 관리자는 이 값을 보고 칸을 채웁니다
  2. 비밀번호 칸 type="password"보기 버튼을 함께 둡니다. 입력한 글자를 눈으로 확인하면 오타가 줄어듭니다
  3. 오류 문구 어느 쪽이 틀렸는지 밝히지 않음'아이디 또는 비밀번호'로 묶어 말해서 계정이 있는지도 드러내지 않습니다
  4. 비밀번호 찾기 링크 늘 같은 자리에 둠틀린 뒤에야 나타나면 늦기 때문에 처음부터 보이게 둡니다
  5. 로그인 상태 유지 오래 가는 쿠키끄면 브라우저를 닫을 때 로그인이 풀립니다. 공용 PC에서는 끌 수 있도록 사용자가 고르게 합니다
  6. 자동완성 끄기 하지 말아야 할 일자동완성을 막으면 사용자가 외우기 쉬운 비밀번호를 쓰게 됩니다

어떤 계정이 가입되어 있는지 밖에서 알아내는 일을 계정 열거(account enumeration)라고 하는데, 오류 문구 하나만으로도 가능해집니다. '없는 아이디입니다'를 보여 주면 아이디 목록을 차례로 넣어 보는 것만으로 어떤 계정이 있는지 가려낼 수 있기 때문입니다. 비밀번호 찾기 화면도 같은 이유로 '메일을 보냈습니다'라는 문구를 계정이 없어도 똑같이 보여 주어야 합니다. 아이디를 먼저 받는 단계 로그인은 편하지만 같은 약점이 있으므로, 이 방식을 쓰려면 계정이 없어도 다음 단계로 똑같이 넘어가게 만들어야 합니다.

6 쓸 때 / 안 쓸 때

로그인 화면을 만들 때 지킬 것

  • 자동완성 힌트를 적습니다. 한 줄만 적어도 효과가 가장 큽니다
  • 오류는 한 문장으로 묶어서 보여 줍니다
  • 비밀번호 찾기 화면과 가입 화면으로 가는 링크를 늘 둡니다

로그인 화면을 이렇게 만들면 안 되는 경우

  • autocomplete="off"를 적을 때. 비밀번호 관리자를 막아 오히려 보안이 약해집니다
  • 붙여넣기를 막을 때. 비밀번호 관리자를 쓸 수 없게 됩니다
  • 비밀번호 글자 수나 기호 규칙을 로그인 화면에서 따질 때. 그 검사는 가입 화면에서 할 일입니다
  • '없는 아이디입니다'라고 알릴 때. 공격자가 계정 목록을 만들 수 있게 됩니다

로그인 화면에서 다루지 않는 일 — 계정을 새로 만드는 일은 가입 화면이 맡습니다. 입력한 값을 검사하는 방법은 입력 검증에서, 입력 칸을 묶어 배치하는 방법은 폼 설계에서 다룹니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

입력 칸을 <form>으로 감싸고, 각 칸에 자동완성 힌트를 적습니다.

<form method="post" action="/login">
  <label for="id">아이디</label>
  <input id="id" name="username" autocomplete="username" required>

  <label for="pw">비밀번호</label>
  <input id="pw" name="password" type="password"
         autocomplete="current-password" required>
  <button type="button" aria-pressed="false">보기</button>

  <p role="alert">아이디 또는 비밀번호가 올바르지 않습니다</p>

  <button>로그인</button>
  <a href="/forgot">비밀번호를 잊으셨나요?</a>
</form>

autocomplete로그인 화면에는 username·current-password를, 가입 화면에는 new-password를 씁니다

보기 버튼에 aria-pressed 달기비밀번호가 지금 보이는 상태인지 알립니다. 버튼 이름만으로는 알 수 없기 때문입니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

응답 시간 맞추기없는 아이디에는 빨리, 있는 아이디에는 느리게 답하면 응답 시간만으로도 계정이 있는지 알 수 있게 됩니다. 그래서 두 경우의 응답 시간을 비슷하게 맞춥니다.
비밀번호는 해시로 저장하기비밀번호는 원래 값으로 되돌릴 수 없는 해시(bcrypt·argon2)로 저장합니다. 복호화할 수 있는 암호화가 아니라 해시입니다.
비밀번호를 틀린 횟수 제한하기한 계정에 비밀번호를 계속 넣어 보지 못하게 막되, IP 기준도 함께 봅니다. 한쪽 기준만 보면 다른 쪽을 바꿔 가며 피해 갈 수 있습니다.
로그인하면 세션을 새로 발급하기로그인에 성공하면 세션 ID를 새로 바꿉니다. 바꾸지 않으면 공격자가 미리 심어 둔 세션 ID가 로그인 뒤에도 그대로 쓰이는데, 이를 세션 고정이라고 합니다.
세션 쿠키에 붙일 속성HttpOnly·Secure·SameSite를 붙입니다. 자바스크립트로 토큰을 읽을 수 있으면 페이지에 끼어든 스크립트도 토큰을 가져갈 수 있어서 토큰으로 지키는 의미가 없어집니다.
비밀번호 찾기에서도 똑같이 답하기비밀번호 찾기에서도 계정이 없을 때 '메일을 보냈습니다'로 똑같이 답합니다.
