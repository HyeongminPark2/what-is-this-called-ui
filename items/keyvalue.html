키-값 목록

Key-value list · description list

키-값 목록은 줄마다 이름 하나와 값 하나를 짝으로 보여 주는 부품으로, 여러 건을 열로 세우는 표와는 다릅니다. 상세 화면의 절반쯤이 이 부품으로 채워집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

라벨 폭을 고정하면 값이 세로로 가지런히 줄을 맞춥니다. 대신 칸이 좁아지면 값이 먼저 잘리는데, 데모는 잘린 줄 수를 세어 적습니다.
'좁으면 위아래로'를 켜면 라벨을 값 위에 올립니다. 값의 시작 위치가 가지런하지는 않지만 아무것도 잘리지 않아서, 폰 화면에서 흔히 씁니다.
태그는 <dl>·<dt>·<dd>를 씁니다. 그래서 스크린 리더로 읽을 때도 이름과 값이 짝으로 전해집니다.

2 이름같은 것을 부르는 여러 이름

한국어키-값 목록, 정의 목록, 속성 목록, 상세 정보
영어key-value list, description list, definition list, detail list
같이 쓰는 말HTML 태그 이름을 따서 정의 목록(description list)이라고 부르고, 이름 쪽은 라벨이나 키, 값 쪽은 값이라고 합니다. 한 줄에 여러 짝을 넣는 방식은 인라인 KV, 값을 그 자리에서 고칠 수 있게 한 것은 인라인 편집이라고 부릅니다.
자주 잘못 부르는 이름테이블 — 표는 여러 건을 줄로 세우고, 키-값 목록은 한 건의 속성을 보여 줍니다.
폼 — 폼은 값을 고치는 화면이고, 키-값 목록은 값을 읽는 화면입니다.
리스트 아이템 — 리스트 아이템은 한 건 전체를 한 줄에 담고, 키-값 목록은 한 건의 속성 하나를 한 줄에 담습니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

표시 부품은 모두 무언가를 보여 주기만 한다는 점이 같아서, 아래 네 가지를 물어봐야 서로 구별됩니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로말줄임한다
아바타사람·조직 하나안 눌린다겹쳐 쌓는다고정 — 넘치면 +N
배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+
칩한 낱말눌린다가로로 줄바꿈말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)
타임라인사건들의 순서항목만세로로 꿴다아래로 길어진다
별점점수 하나읽기용은 안 눌린다줄 안에 들어간다고정 — 별 다섯
아이콘뜻 하나혼자서는 안 눌린다글자 옆에 붙는다고정 — 글자가 대신 길어진다
썸네일그림 하나보통 눌린다격자로고정 — 잘리거나 여백이 남는다
테이블 행한 건의 여러 값전체 또는 주 열만세로로 쌓인다말줄임한다
키-값 목록이름과 값의 짝안 눌린다세로로 쌓인다값이 먼저 잘린다
미디어 오브젝트그림 + 글보통 눌린다세로 목록으로글 쪽만 늘어난다
접히는 글제목과 본문제목이 눌린다세로로 포갠다접어 둔다
태그한 낱말안 눌린다가로로 줄바꿈말줄임하거나 +N

키-값 목록을 한 줄로 정리하면 — 키-값 목록은 한 건의 속성을 읽는 자리입니다. 값을 고칠 수 있게 만들어야 한다면 키-값 목록이 아니라 폼을 씁니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

<dl> — 이름과 값의 짝
<dt> 이름 · <dd> 값 — 둘을 묶는다
라벨 폭 고정 — 값이 한 줄로 선다
좁아지면 값이 먼저 잘린다
좁으면 라벨을 위로 — 가지런함은 잃는다
값이 없으면 '—' 가 아니라 왜 없는지
  1. <dl> 짝의 목록표가 아니라 이름과 값의 짝을 담습니다
  2. <dt>·<dd> 이름과 값스크린 리더로 읽을 때도 짝으로 전해집니다
  3. 라벨 폭 고정값이 세로로 가지런히 맞춰집니다
  4. 좁을 때 값이 잘림말줄임으로 줄 높이를 지킵니다
  5. 세로 전환 라벨을 위로폰 화면에서 흔히 씁니다
  6. 빈 값 이유까지'—' 하나만 두지 않습니다

가장 먼저 정할 것은 라벨 폭을 고정할지 내용에 맞출지입니다. 고정하면 값이 가지런해지는 대신 긴 라벨이 잘리고, 내용에 맞추면 줄마다 값의 시작 위치가 달라져서 시선이 좌우로 오가며 읽게 됩니다. 그래서 줄이 다섯 개를 넘으면 폭을 고정하는 쪽이 읽기 편합니다.
값이 비었을 때 '—' 하나만 두는 경우도 흔한데, 그러면 아직 정해지지 않은 것인지 해당 사항이 없는 것인지 알 수 없습니다. 짧게라도 값이 왜 없는지를 적어 두면 문의가 줄어듭니다.

6 쓸 때 / 안 쓸 때

키-값 목록을 쓰는 경우

  • <dl>·<dt>·<dd>로 적기
  • 줄이 다섯 개를 넘으면 라벨 폭을 고정하기
  • 폰에서는 라벨을 값 위로 올리기

키-값 목록을 쓰지 않는 경우

  • 표 태그로 적기. 한 건의 속성인데 스크린 리더가 열 이름까지 읽습니다
  • 값이 없을 때 '—' 하나만 두기
  • 값을 고칠 수 있는 칸을 섞어 두기. 고치는 화면은 폼으로 만듭니다
  • 줄을 열다섯 개씩 늘어놓기. 관련된 줄끼리 묶어서 접어 둡니다

키-값 목록 대신 다른 것을 써야 하는 경우 — 여러 건을 줄로 세우면 데이터 테이블, 고치는 화면은 폼 설계, 묶어서 접으면 접히는 글, 한 건 전체가 한 줄이면 리스트 아이템.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

<dl> 안에서 <div>로 이름과 값을 한 짝씩 묶으면 CSS 격자로 배치하기 쉽습니다.

<dl class="kv">
  <div><dt>주문번호</dt><dd>2411-0042-88231</dd></div>
  <div><dt>가게</dt><dd>모란상회</dd></div>
</dl>

.kv > div { display: grid; grid-template-columns: 90px 1fr; gap: 10px; }
.kv dt, .kv dd { min-width: 0; white-space: nowrap;
  overflow: hidden; text-overflow: ellipsis; }
.kv dd { margin: 0; }

@media (max-width: 480px) {
  .kv > div { grid-template-columns: 1fr; }   /* 라벨을 값 위로 */
}
키와 동작그때 일어나야 하는 일
<dl>스크린 리더로 읽을 때 이름과 값이 짝으로 전해집니다
<div>로 묶기HTML 규칙에서 허용하는 방식이고, CSS 격자로 배치하기 쉽습니다
Tab읽기용이라 포커스가 멈추지 않고, 값에 링크가 있을 때만 멈춥니다
말줄임잘린 값은 title로 전체 값을 띄워 줍니다
복사user-select를 막지 않습니다. 주문번호 같은 값은 사용자가 복사해서 쓰는 경우가 많습니다
확인하는 법화면을 390px로 줄여 값이 몇 줄 잘리는지 셉니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

온전한 값을 준다서버가 값을 미리 잘라 보내면 잘린 부분은 복사도 검색도 할 수 없습니다. 값을 줄여 보이는 일은 화면에서 합니다.
빈 값의 뜻null(아직 모름)과 ""(없음)을 구별해서 보내 주면 화면에서 두 경우에 다른 문구를 쓸 수 있습니다.
차례응답에 담긴 키 순서는 보장되지 않을 수 있으므로 화면에서 차례를 정합니다. 중요한 값이 위에 오도록 화면이 순서를 정해 둡니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

이름과 값을 짝으로 보여 준다는 점은 세 플랫폼이 모두 같습니다.

웹<dl>
주문번호2411-0042
전용 태그가 있는 것이 웹의 장점입니다. 덕분에 스크린 리더로 읽을 때도 짝이 유지됩니다.
iOSForm · LabeledContent
왼쪽에 라벨, 오른쪽에 값을 두는 것이 iOS의 기본 배치로, 이 항목에서 말하는 좌우 배치와 같습니다.
안드로이드ListItem
라벨을 값 위에 올리는 배치를 많이 쓰고, 이 항목에서 말하는 세로 배치와 같습니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS와 안드로이드는 각각 좌우와 세로 배치를 기본으로 골랐습니다. 좌우 배치는 값이 가지런하고 세로 배치는 값이 잘리지 않아서 어느 쪽이 틀렸다고 할 수는 없고, 값의 길이가 고르면 좌우가, 들쭉날쭉하면 세로가 낫습니다. 웹에서는 미디어 쿼리 한 줄로 두 배치를 모두 쓸 수 있으므로, 화면 폭에 따라 바꾸는 것이 가장 쉬운 방법입니다.
