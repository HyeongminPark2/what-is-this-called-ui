키-값 목록

Key-value list · description list

표가 아니라 짝입니다 — 줄마다 이름 하나와 값 하나. 상세 화면의 절반이 이걸로 차 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

라벨 폭을 고정하면 값이 한 줄로 가지런히 섭니다. 대신 칸이 좁아지면 값이 먼저 잘립니다 — 데모가 잘린 줄 수를 세서 적습니다.
'좁으면 위아래로'를 켜면 라벨을 값 위에 올립니다. 가지런함은 잃지만 아무것도 안 잘립니다 — 폰에서 쓰는 꼴입니다.
태그는 <dl>·<dt>·<dd> 입니다. 소리로 읽을 때도 짝이 유지됩니다.

2 이름부르는 말이 여러 개다

한국어키-값 목록, 정의 목록, 속성 목록, 상세 정보
영어key-value list, description list, definition list, detail list
같이 쓰는 말HTML 태그 이름을 따서 정의 목록(description list)이라 부르고, 이름 쪽을 라벨·키, 값 쪽을 값이라 합니다. 한 줄에 여러 짝을 넣는 꼴은 인라인 KV, 값을 그 자리에서 고칠 수 있게 한 것은 인라인 편집입니다.
자주 잘못 부름테이블 — 표는 여러 건을 줄로 세웁니다. 이건 한 건입니다.
폼 — 폼은 고치는 화면입니다. 이건 읽는 화면입니다.
리스트 아이템 — 리스트 아이템은 한 건 전체가 한 줄입니다.

3 가르는 기준형제들과 비교하는 네 축

표시 부품은 '보여 주기만 한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로말줄임한다
아바타사람·조직 하나안 눌린다겹쳐 쌓는다고정 — 넘치면 +N
배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+
칩한 낱말눌린다가로로 줄바꿈말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)
타임라인사건들의 순서항목만세로로 꿴다아래로 길어진다
별점점수 하나읽기용은 안 눌린다줄 안에 들어간다고정 — 별 다섯
아이콘뜻 하나혼자서는 안 눌린다글자 옆에 붙는다고정 — 글자가 대신 길어진다
썸네일그림 하나보통 눌린다격자로고정 — 잘리거나 여백이 남는다
테이블 행한 건의 여러 값전체 또는 주 열만세로로 쌓인다말줄임한다
키-값 목록이름과 값의 짝안 눌린다세로로 쌓인다값이 먼저 잘린다
미디어 오브젝트그림 + 글보통 눌린다세로 목록으로글 쪽만 늘어난다
접히는 글제목과 본문제목이 눌린다세로로 포갠다접어 둔다
태그한 낱말안 눌린다가로로 줄바꿈말줄임하거나 +N

한 줄로 — 한 건의 속성을 읽는 자리입니다. 고칠 수 있게 하려면 그건 폼이지 이게 아닙니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

<dl> — 이름과 값의 짝
<dt> 이름 · <dd> 값 — 둘을 묶는다
라벨 폭 고정 — 값이 한 줄로 선다
좁아지면 값이 먼저 잘린다
좁으면 라벨을 위로 — 가지런함은 잃는다
값이 없으면 '—' 가 아니라 왜 없는지
  1. <dl> 짝의 목록표가 아니라 짝이다
  2. <dt>·<dd> 이름과 값소리로도 짝이 유지된다
  3. 라벨 폭 고정값이 한 줄로 선다
  4. 좁을 때 값이 잘림말줄임으로 줄 높이를 지킨다
  5. 세로 전환 라벨을 위로폰에서 쓰는 꼴
  6. 빈 값 이유까지'—' 하나만 두지 않는다

라벨 폭을 고정할지 내용에 맞출지가 첫 결정입니다. 고정하면 값이 가지런한 대신 긴 라벨이 잘리고, 내용에 맞추면 라벨마다 값의 시작 위치가 달라져 눈이 지그재그로 움직입니다. 줄이 다섯을 넘으면 고정하는 쪽이 읽기 편합니다.
값이 비었을 때 '—' 하나만 두는 것도 흔한데, 그러면 '아직 안 정해진 것'인지 '해당 없음'인지 모릅니다. 한 줄이라도 왜 없는지를 적어 두면 문의가 줄어듭니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • <dl>·<dt>·<dd> 로 적기
  • 줄이 다섯을 넘으면 라벨 폭을 고정하기
  • 폰에서는 라벨을 값 위로 올리기

이럴 때는 안 쓴다

  • 표 태그로 적기 — 한 건인데 열 이름이 읽힌다
  • 값이 없을 때 '—' 하나만 두기
  • 값을 고칠 수 있게 섞어 두기 — 그건 폼이다
  • 줄을 열다섯씩 늘어놓기 — 묶어서 접는다

대신 이걸 — 여러 건을 줄로 세우면 데이터 테이블, 고치는 화면은 폼 설계, 묶어서 접으면 접히는 글, 한 건 전체가 한 줄이면 리스트 아이템.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

<dl> 안에서 <div> 로 한 짝씩 묶으면 격자로 세우기 쉽습니다.

<dl class="kv">
  <div><dt>주문번호</dt><dd>2411-0042-88231</dd></div>
  <div><dt>가게</dt><dd>모란상회</dd></div>
</dl>

.kv > div { display: grid; grid-template-columns: 90px 1fr; gap: 10px; }
.kv dt, .kv dd { min-width: 0; white-space: nowrap;
  overflow: hidden; text-overflow: ellipsis; }
.kv dd { margin: 0; }

@media (max-width: 480px) {
  .kv > div { grid-template-columns: 1fr; }   /* 라벨을 값 위로 */
}
키일어나야 하는 일
<dl>소리로 읽을 때 이름과 값이 짝으로 전해진다
<div> 로 묶기HTML 에서 허용된 방식이다 — 격자를 세우기 쉽다
Tab읽기용이라 멈추지 않는다 — 값에 링크가 있을 때만 멈춘다
말줄임잘린 값은 title 로 전체를 띄워 준다
복사user-select 를 막지 않는다 — 주문번호는 복사하라고 있는 값이다
확인하는 법390px 로 줄여 값이 몇 줄 잘리는지 센다

9 서버 쪽으로 치면백엔드 감각으로 번역

온전한 값을 준다서버가 미리 자르면 복사도 검색도 안 됩니다 — 줄이는 것은 화면의 일입니다.
빈 값의 뜻null(아직 모름)과 ""(없음)을 가려 주면 화면이 다른 문구를 쓸 수 있습니다.
차례응답의 키 순서를 믿지 말고 화면이 차례를 정합니다 — 중요한 것이 위로 가야 합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

이름-값 짝이라는 생각은 어디서나 같습니다.

웹<dl>
주문번호2411-0042
전용 태그가 있는 것이 웹의 장점입니다 — 소리로도 짝이 유지됩니다.
iOSForm · LabeledContent
왼쪽에 라벨, 오른쪽에 값이 iOS 의 기본 꼴입니다 — 우리 쪽 '좌우' 와 같습니다.
안드로이드ListItem
라벨을 값 위에 올리는 꼴이 많습니다 — 우리 쪽 '세로'와 같습니다.

자주 생기는 사고 — 두 플랫폼이 좌우와 세로를 각각 기본으로 고른 것이 재미있습니다. 좌우는 가지런하고 세로는 안 잘립니다 — 어느 쪽도 틀리지 않고, 값의 길이가 고르면 좌우가, 들쭉날쭉하면 세로가 낫습니다. 웹에서는 한 줄의 미디어 쿼리로 둘 다 쓸 수 있으니, 폭에 따라 바꾸는 것이 가장 쉬운 답입니다.
