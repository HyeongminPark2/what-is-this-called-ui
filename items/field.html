텍스트 필드

Text field · Input

글자를 직접 넣는 칸. 칸 자체보다 둘레에 붙는 것들(라벨·헬퍼·에러)이 더 중요하고, 더 자주 틀립니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

빈칸으로 등록하기를 눌러 보세요. 첫 번째 틀린 칸으로 포커스가 갑니다. 고치기 시작하면 보내기 전에 에러가 풀립니다.
위의 체크를 켜면 라벨이 사라지고 자리글만 남습니다 — 입력을 시작하는 순간 무슨 칸이었는지 사라집니다. 자리글은 라벨을 대신할 수 없습니다.

2 이름부르는 말이 여러 개다

한국어텍스트 필드, 입력칸, 인풋
영어text field, text input, input
같이 쓰는 말위에 붙는 이름이 라벨, 칸 안의 흐린 안내가 자리글(placeholder), 아래 설명이 헬퍼 텍스트, 여러 줄짜리는 텍스트에어리어. 앞뒤에 붙는 단위(₩·@)는 어픽스(affix).
자주 잘못 부름자리글을 라벨이라 부르기 — 가장 잦고 가장 해로운 혼동입니다. 자리글은 입력하면 사라집니다.
힌트 — 헬퍼 텍스트는 '힌트'가 아니라 늘 보이는 설명입니다.
폼 — 폼은 칸들을 모은 전체이고, 필드는 그중 하나입니다.

한 줄로 — 텍스트 필드의 설계는 칸 바깥에 있습니다 — 라벨이 늘 보이는가, 설명이 입력 전에 보이는가, 에러가 고칠 곳 옆에 붙는가.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

업무용 메일 *
name@company.com
메일 주소 형태가 아닙니다.
정산 안내를 이 주소로 보냅니다.
  1. 라벨 label늘 보인다. <label for>로 칸과 이어 두면 글자를 눌러도 포커스가 간다
  2. 필수 표시 required marker별표만 두지 말고 어느 쪽이 적은지로 고른다 — 대부분 필수면 '선택'을 적는 게 낫다
  3. 입력칸 input높이를 44px 이상으로. 손가락이 닿아야 한다
  4. 자리글 placeholder예시를 적는 자리다. 설명을 여기 넣으면 입력하는 순간 사라진다
  5. 에러 메시지 error무엇이 틀렸고 어떻게 고치는지까지. 칸 바로 아래
  6. 헬퍼 텍스트 helper text입력 전에 알아야 하는 것. 에러가 떠도 안 사라진다

라벨을 칸 안에 띄워 두는 방식(플로팅 라벨)도 있습니다. 자리를 아끼지만 값이 들어오면 라벨이 작아져 읽기 어려워지고, 자리글을 같이 쓸 수 없습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 자유롭게 적어야 하는 값 — 이름, 주소, 메모
  • 선택지가 너무 많아 늘어놓을 수 없을 때
  • 형식이 정해진 값 — inputmode로 폰 키보드를 맞춰 줄 때

이럴 때는 안 쓴다

  • 선택지가 정해져 있을 때 → 셀렉트·라디오·콤보박스
  • 자리글로 라벨을 대신하기 — 입력하면 사라집니다
  • 형식을 안 알려 주고 틀렸다고만 하기 — 헬퍼 텍스트로 미리 알립니다
  • 입력 중에 글자를 마음대로 바꾸기 — 커서가 튀어 고치기 어려워집니다

대신 이걸 — 정해진 것 중 하나면 셀렉트, 많아서 걸러야 하면 콤보박스, 범위에서 고르면 슬라이더, 켜고 끄면 스위치.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

<label for>와 aria-describedby 두 줄이 이 부품의 접근성 거의 전부입니다.

<label for="em">업무용 메일 <span aria-hidden="true">*</span></label>
<input id="em" type="email" required
       inputmode="email" autocomplete="email"
       aria-describedby="em-h" placeholder="name@company.com">
<p id="em-h">정산 안내를 이 주소로 보냅니다.</p>

// 틀렸을 때 — 설명을 잇고 invalid 를 켠다
el.setAttribute('aria-invalid', 'true');
el.setAttribute('aria-describedby', 'em-h em-e');

// 보내기를 기다리지 말고 고쳐지는 즉시 풀어 준다
el.addEventListener('input', () => { if (ok(el)) clearError(el); });
키일어나야 하는 일
라벨 누름for로 이어 뒀으면 칸으로 포커스가 간다. 손가락 과녁이 몇 배 커진다
Tab칸을 차례로 지난다. 순서는 화면에 보이는 순서와 같아야 한다
보낼 때첫 번째 틀린 칸으로 포커스를 옮긴다
autocomplete브라우저가 저장해 둔 값을 채워 준다. 안 적으면 그 편의가 통째로 사라진다
inputmode폰에서 뜨는 키보드를 고른다. 숫자 칸에 글자 키보드가 뜨면 바로 성가시다

9 서버 쪽으로 치면백엔드 감각으로 번역

화면 검증 = 빠른 실패서버 검증을 대신하지 않습니다. 왕복을 아끼는 캐시일 뿐이라 서버에서 또 검증해야 합니다.
maxlength = 스키마칸의 상한은 DB 컬럼 길이와 맞아야 합니다. 어긋나면 서버에서 잘리거나 터집니다.
정규화 시점공백 제거·대소문자 통일은 보낼 때 하지 입력 중에 하지 않습니다. 입력 중에 바꾸면 커서가 튑니다.
autocomplete = 표준 필드 이름브라우저와 합의된 이름입니다. 폼 필드 이름을 멋대로 지으면 자동 채움이 안 먹습니다.
