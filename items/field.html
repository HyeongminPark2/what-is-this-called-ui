텍스트 필드

Text field · Input

텍스트 필드는 사용자가 글자를 직접 입력하는 칸입니다. 칸 자체보다 칸 둘레에 붙는 요소(라벨·헬퍼 텍스트·에러 메시지)가 쓰기 편한지를 더 크게 좌우하고, 잘못 만드는 경우도 이쪽이 더 많습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

칸을 비운 채 등록하기를 눌러 보세요. 포커스가 첫 번째로 틀린 칸으로 옮겨 갑니다. 그 칸을 고치기 시작하면 등록하기를 다시 누르지 않아도 에러 표시가 바로 풀립니다.
위의 체크를 켜면 라벨이 사라지고 자리글만 남는데, 이 상태에서 글자를 입력하기 시작하면 자리글마저 사라져서 무엇을 적는 칸이었는지 알 수 없게 됩니다. 그래서 자리글은 라벨을 대신할 수 없습니다.

2 이름같은 것을 부르는 여러 이름

한국어텍스트 필드, 입력칸, 인풋
영어text field, text input, input
같이 쓰는 말칸 위에 붙는 이름은 라벨, 칸 안에 흐리게 적힌 안내는 자리글(placeholder), 칸 아래 설명은 헬퍼 텍스트라고 부릅니다. 여러 줄을 입력하는 칸은 텍스트에어리어, 칸 앞뒤에 붙는 단위(₩·@)는 어픽스(affix)라고 합니다.
자주 잘못 부르는 이름자리글을 라벨이라 부르기 — 특히 자주 일어나고 문제도 큰 혼동입니다. 자리글은 입력을 시작하면 사라지기 때문에 라벨 역할을 할 수 없습니다.
힌트 — 헬퍼 텍스트는 '힌트'가 아니라 칸 아래에 늘 보이는 설명입니다.
폼 — 폼은 여러 칸을 모은 입력 양식 전체이고, 필드는 그 안의 칸 하나입니다.

5 해부도부분마다 붙은 이름

업무용 메일 *
name@company.com
메일 주소 형태가 아닙니다.
정산 안내를 이 주소로 보냅니다.
  1. 라벨 label늘 보이게 둡니다. <label for>로 칸과 연결해 두면 라벨 글자를 눌러도 칸으로 포커스가 갑니다
  2. 필수 표시 required marker필수 칸마다 별표를 다는 방식만 고집하지 말고, 필수와 선택 중 어느 쪽이 적은지 보고 적은 쪽에 표시합니다. 대부분이 필수라면 선택 칸에 '선택'이라고 적는 편이 낫습니다
  3. 입력칸 input손가락으로도 정확히 누를 수 있도록 높이를 44px 이상으로 잡습니다
  4. 자리글 placeholder입력값의 예시를 적는 자리입니다. 설명을 여기에 넣으면 입력을 시작하는 순간 사라집니다
  5. 에러 메시지 error무엇이 틀렸는지와 어떻게 고치면 되는지까지 적어 칸 바로 아래에 둡니다
  6. 헬퍼 텍스트 helper text입력하기 전에 알아야 할 내용을 적습니다. 에러 메시지가 떠도 사라지지 않습니다

라벨을 칸 안에 두었다가 입력을 시작하면 칸 위쪽으로 올리는 방식(플로팅 라벨)도 있습니다. 세로 공간을 아낄 수 있지만, 값이 들어오면 라벨이 작아져 읽기 어렵고, 빈 칸에서는 라벨이 자리글 자리에 들어가 있으므로 자리글을 함께 쓸 수 없습니다.

6 쓸 때 / 안 쓸 때

텍스트 필드를 쓰는 경우

  • 이름, 주소, 메모처럼 자유롭게 적어야 하는 값을 받을 때
  • 선택지가 너무 많아 늘어놓을 수 없을 때
  • 형식이 정해진 값을 받으면서 inputmode로 폰 키보드 종류를 맞춰 줄 때

텍스트 필드를 쓰지 않는 경우

  • 선택지가 정해져 있을 때. 셀렉트나 라디오, 콤보박스를 씁니다
  • 자리글로 라벨을 대신할 때. 자리글은 입력을 시작하면 사라집니다
  • 형식을 알려 주지 않고 틀렸다고만 할 때. 헬퍼 텍스트로 형식을 미리 알립니다
  • 입력하는 도중에 글자를 마음대로 바꿀 때. 커서 위치가 갑자기 바뀌어 고치기 어려워집니다

텍스트 필드 대신 다른 것을 써야 하는 경우 — 정해진 선택지 가운데 하나를 고르는 값이면 셀렉트를 쓰고, 선택지가 많아 글자로 걸러야 하면 콤보박스를 씁니다. 범위 안에서 값을 고르게 하려면 슬라이더, 켜고 끄는 값이면 스위치가 맞습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

텍스트 필드의 접근성은 대부분 두 가지로 해결됩니다. <label for>로 라벨을 칸에 연결하고, aria-describedby로 헬퍼 텍스트와 에러 메시지를 칸에 연결합니다.

<label for="em">업무용 메일 <span aria-hidden="true">*</span></label>
<input id="em" type="email" required
       inputmode="email" autocomplete="email"
       aria-describedby="em-h" placeholder="name@company.com">
<p id="em-h">정산 안내를 이 주소로 보냅니다.</p>

// 틀렸을 때는 에러 설명을 잇고 invalid 를 켠다
el.setAttribute('aria-invalid', 'true');
el.setAttribute('aria-describedby', 'em-h em-e');

// 보내기를 기다리지 말고 고쳐지는 즉시 풀어 준다
el.addEventListener('input', () => { if (ok(el)) clearError(el); });
키와 마크업그때 일어나야 하는 일
라벨을 눌렀을 때for로 연결해 두었다면 칸으로 포커스가 갑니다. 라벨까지 누를 수 있는 영역이 되므로 손가락으로 누를 곳이 넓어집니다
Tab칸을 차례로 옮겨 갑니다. 이 순서는 화면에 보이는 순서와 같아야 합니다
폼을 보낼 때첫 번째로 틀린 칸에 포커스를 옮깁니다
autocomplete브라우저가 저장해 둔 값을 채워 줍니다. 이 속성을 적지 않으면 자동 채움이 제대로 동작하지 않습니다
inputmode폰에서 뜨는 키보드 종류를 고릅니다. 숫자를 넣는 칸에 글자 키보드가 뜨면 사용자가 키보드를 직접 바꿔야 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

화면 검증은 틀린 값을 일찍 거르는 장치화면에서 하는 검증은 서버 검증을 대신하지 않습니다. 서버까지 갔다 오지 않고 틀린 값을 일찍 걸러 내려는 장치이므로, 같은 값을 서버에서 다시 검증해야 합니다.
maxlength를 DB 컬럼 길이와 맞추기입력칸의 글자 수 상한은 DB 컬럼 길이와 맞아야 합니다. 둘이 어긋나면 서버에서 값이 잘리거나 저장 오류가 납니다.
값을 정리하는 시점공백을 지우거나 대소문자를 통일하는 처리는 입력하는 도중이 아니라 보낼 때 합니다. 입력 중에 글자를 바꾸면 커서 위치가 갑자기 바뀌기 때문입니다.
autocomplete에는 표준 이름 쓰기autocomplete 값은 브라우저가 알아듣도록 표준으로 정해 둔 이름입니다. 표준 이름 대신 필드 이름을 임의로 지어 쓰면 자동 채움이 동작하지 않습니다.
