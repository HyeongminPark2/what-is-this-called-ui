시스템 백

System back

폰에는 앱과 상관없이 OS가 제공하는 뒤로가기가 있고, 사용자는 이 뒤로가기로 모달도 닫으려고 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

기록에 넣기를 끄고 시트를 연 뒤 ← 뒤로를 눌러 보세요. 시트는 그대로 남고 그 아래 화면이 사라지며, 한 번 더 누르면 앱을 나갑니다.
기록에 넣기를 켜 두면 뒤로가기가 시트만 닫습니다. 기록 줄에서는 무엇이 쌓이고 빠지는지 함께 볼 수 있습니다.

2 이름같은 것을 부르는 여러 이름

한국어시스템 백, 뒤로가기, 뒤로 제스처
영어system back, back navigation, predictive back
같이 쓰는 말브라우저가 방문한 화면을 쌓아 두는 목록을 히스토리(history)라고 합니다. 이 목록에 한 칸을 쌓는 함수가 history.pushState이고, 뒤로가기가 눌린 것을 알려 주는 이벤트가 popstate입니다. 안드로이드 14부터는 뒤로 제스처를 하는 도중에 돌아갈 화면을 미리 보여 주는 프레딕티브 백(predictive back)이 들어왔습니다.
자주 잘못 부르는 이름브레드크럼 — 브레드크럼은 지금 '어디에 있는지'를 보여 주고, 뒤로가기는 '어떻게 왔는지'를 따라 되돌아갑니다.
닫기 — 닫기는 그 부품만 화면에서 치우고, 뒤로가기는 기록을 하나 되돌립니다. 화면에 보이는 결과가 같아도 기록에 남는 상태가 다릅니다.
취소 — 취소는 하던 일을 무르는 것이라 뒤로가기보다 뜻이 셉니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

PC와 폰의 차이는 기계 자체보다 화면을 쓰는 전제에 있습니다. 아래 네 가지를 물어보면 두 환경이 어디서 갈리는지 알 수 있습니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px의 실제 화소 수2~3배1~2배그림이 뭉개진다
뷰포트 단위100vh가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다

시스템 백을 한 줄로 정리하면 — 화면을 덮는 것은 기록에 넣으세요. 모달이나 시트, 전체 화면 사진 보기 같은 것을 사용자는 모두 뒤로가기로 닫으려 하기 때문입니다.

4 기록과 화면둘이 어긋나면 사고가 난다

5 해부도부분마다 붙은 이름

목록상세시트
열 때 history.pushState — 기록을 하나 쌓는다
popstate — 뒤로가 눌렸다
✕ 로 닫을 때는 history.back() — 기록을 되돌린다
<dialog> 는 Esc 만 — 뒤로가기는 직접 잇는다
기록에 안 넣으면 뒤로가 앱을 나간다
  1. 기록 history stackOS와 브라우저가 쌓아 둡니다. 뒤로가기는 화면이 아니라 이 기록을 되돌립니다
  2. 쌓기 pushState화면을 덮는 것을 열 때 기록을 하나 쌓습니다. 주소는 바꾸지 않아도 됩니다
  3. 받기 popstate뒤로가기가 눌렸다는 신호입니다. 이 이벤트에서 시트를 닫습니다
  4. ✕ 로 닫을 때 history.back()시트를 직접 닫지 않고 기록을 되돌립니다. 직접 닫으면 쌓아 둔 기록이 그대로 남습니다
  5. <dialog> Esc 만 준다Esc로 닫히는 기능만 있고 뒤로가기와는 연결되어 있지 않습니다. 뒤로가기로 닫히게 하려면 직접 연결해야 합니다
  6. 안 넣으면 앱을 나간다사용자가 쓰던 화면을 잃어버리는, 사용자가 가장 싫어하는 실수입니다

기록을 너무 많이 쌓아도 문제가 생깁니다. 예를 들어 필터를 누를 때마다 기록을 쌓으면, 조건을 열 번 바꾼 사용자는 뒤로가기를 열 번 눌러야 전 화면으로 돌아갈 수 있습니다. 쌓을지 말지는 '화면을 덮었는가'로 가릅니다. 화면을 덮는 것(모달·시트·사진 보기)은 기록을 쌓고, 같은 화면 안에서 값만 바뀌는 것(정렬·필터)은 replaceState로 지금 기록을 바꿔 씁니다.

6 쓸 때 / 안 쓸 때

시스템 백을 쓰는 경우

  • 모달, 바텀시트, 전체 화면 사진처럼 화면을 덮는 것을 열 때
  • 여러 단계로 된 폼을 만들 때. 단계마다 기록을 쌓으면 뒤로가기가 전 단계로 돌아갑니다
  • 드로어로 메뉴를 열 때

시스템 백을 쓰지 않는 경우

  • 조건이나 정렬이 바뀔 때마다 기록을 쌓을 때. 이때는 replaceState를 씁니다
  • 뒤로가기를 막을 때. 사용자가 가장 싫어하는 동작입니다
  • ✕로 닫을 때 시트를 직접 닫을 때. 기록이 남아서 다음 뒤로가기가 한 번 아무 일도 하지 않습니다
  • 확인 없이 저장하지 않은 내용을 버릴 때

시스템 백 대신 다른 것을 써야 하는 경우 — 같은 화면 안에서 값만 바뀌면 replaceState를 쓰고, 어디에 있는지 보여 주려면 브레드크럼, 방금 한 일을 무르게 하려면 되돌리기를 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙빠뜨리기 쉬운 설정까지

열 때 기록을 쌓고 popstate에서 닫으며, ✕ 버튼도 back()을 불러 같은 경로로 닫습니다.

function openSheet() {
  history.pushState({ sheet: true }, '');   // 기록을 하나 쌓는다
  dialog.showModal();
}

window.addEventListener('popstate', () => {
  if (dialog.open) dialog.close();      // 뒤로 = 닫기
});

closeBtn.addEventListener('click', () => history.back());  // 닫는 경로를 하나로 모은다

// Esc 로 닫혔을 때도 기록을 맞춰 준다
dialog.addEventListener('cancel', e => { e.preventDefault(); history.back(); });

// 조건이 바뀔 뿐이면 쌓지 말고 갈아끼운다
history.replaceState(null, '', '?status=ok&page=2');
키와 동작그때 일어나야 하는 일
Esc와 뒤로를 한 길로cancel 이벤트의 기본 동작을 막고 back()을 부르면, Esc와 뒤로가기가 같은 경로로 닫혀서 기록이 어긋나지 않습니다
pushState는 주소를 안 바꿔도 된다두 번째 인자만 주고 세 번째 인자를 빼면 주소는 그대로 남습니다
replaceState와 가른다화면을 덮는 것은 push, 값만 바뀌는 것은 replace로 처리합니다
저장 안 한 내용beforeunload는 뒤로가기에는 작동하지 않을 수 있으므로 확인 다이얼로그를 직접 띄웁니다
<dialog>Esc로 닫히는 기능은 따로 만들지 않아도 있지만, 뒤로가기로 닫히게 하려면 직접 만들어야 합니다
초점뒤로가기로 닫혔을 때도 시트를 연 버튼으로 포커스를 되돌립니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

주소에 담긴 것은 되살아난다뒤로가기로 돌아온 화면은 주소를 보고 다시 그립니다. 그래서 조건과 쪽 번호를 주소에 담아 두면 따로 저장하지 않아도 그대로 복원됩니다.
뒤로 캐시브라우저는 떠난 화면을 메모리에 통째로 보관해 두었다가 뒤로가기를 누르면 그대로 다시 보여 줍니다(bfcache). 그런데 unload 핸들러를 달면 이 캐시를 쓰지 않습니다.
되살아난 화면은 낡았다bfcache에서 되살아난 목록은 몇 분 전 데이터를 보여 줍니다. pageshow 이벤트의 persisted 값을 보고 데이터를 다시 받을지 정합니다.
POST 뒤에는폼을 POST로 저장한 뒤 그 화면에 머물면, 뒤로가기를 눌렀을 때 양식을 다시 보낼지 묻는 경고가 뜹니다. 그래서 저장한 뒤에는 다른 주소로 이동시킵니다.

플랫폼 차이 때문에 자주 생기는 문제 — PC 브라우저에서는 모달을 ✕로만 닫아 보기 때문에, 이 문제를 발견할 수 없습니다. 폰에서 모달을 열고 뒤로가기를 한 번 눌러 보는 것이 이 문제를 확인하는 유일한 방법이고, 그 한 번의 확인으로 '모달이 안 닫히고 앱이 꺼진다'는 민원을 대부분 막을 수 있습니다.
