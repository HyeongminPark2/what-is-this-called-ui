시스템 백

System back

폰에는 OS가 주는 뒤로가기가 있습니다. 사용자는 그걸로 모달도 닫습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

기록에 넣기를 끄고 시트를 연 뒤 ← 뒤로를 눌러 보세요 — 시트는 그대로 남고 그 아래 화면이 사라집니다. 한 번 더 누르면 앱을 나갑니다.
켜 두면 뒤로가기가 시트만 닫습니다. 기록 줄에서 무엇이 쌓이고 빠지는지 같이 보입니다.

2 이름부르는 말이 여러 개다

한국어시스템 백, 뒤로가기, 뒤로 제스처
영어system back, back navigation, predictive back
같이 쓰는 말브라우저가 쌓아 두는 것이 히스토리(history)이고, 한 칸 쌓는 것이 history.pushState, 뒤로가 눌린 것을 받는 것이 popstate입니다. 안드로이드 14부터는 뒤로 제스처 도중에 다음 화면을 미리 보여 주는 프레딕티브 백(predictive back)이 들어왔습니다.
자주 잘못 부름브레드크럼 — 브레드크럼은 '어디에 있나', 뒤로가기는 '어떻게 왔나'입니다.
닫기 — 닫기는 그 부품만 치우고, 뒤로가기는 기록을 하나 되돌립니다. 결과가 같아 보여도 다릅니다.
취소 — 취소는 하던 일을 무르는 것이라 뜻이 더 셉니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다
HIG와 Material의 차이OS 의 말투각자 다르다웹 관례어느 쪽에서도 어색하다

한 줄로 — 화면을 덮는 것은 기록에 넣으세요. 모달·시트·전체 화면 사진 보기 — 사용자는 전부 뒤로가기로 닫으려 합니다.

4 기록과 화면둘이 어긋나면 사고가 난다

5 해부도부분 이름이 제일 안 알려진 지식

목록상세시트
열 때 history.pushState — 기록을 하나 쌓는다
popstate — 뒤로가 눌렸다
✕ 로 닫을 때는 history.back() — 기록을 되돌린다
<dialog> 는 Esc 만 — 뒤로가기는 직접 잇는다
기록에 안 넣으면 뒤로가 앱을 나간다
  1. 기록 history stackOS·브라우저가 쌓아 둔다. 화면이 아니라 기록을 되돌린다
  2. 쌓기 pushState덮는 것을 열 때 하나 쌓는다. 주소는 안 바꿔도 된다
  3. 받기 popstate뒤로가 눌렸다. 여기서 닫는다
  4. ✕ 로 닫을 때 history.back()직접 닫지 말고 기록을 되돌린다. 안 그러면 기록이 쌓인 채 남는다
  5. <dialog> Esc 만 준다뒤로가기와는 아무 상관이 없다. 직접 이어 줘야 한다
  6. 안 넣으면 앱을 나간다쓰던 화면을 잃는다. 가장 싫어하는 사고

너무 많이 쌓는 것도 사고입니다. 필터를 누를 때마다 기록을 쌓으면, 조건을 열 번 만진 사람은 뒤로가기를 열 번 눌러야 전 화면으로 갑니다. 기준은 '화면을 덮었나'입니다 — 덮는 것(모달·시트·사진 보기)은 쌓고, 같은 화면 안에서 값만 바뀌는 것(정렬·필터)은 replaceState로 기록을 갈아끼웁니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 화면을 덮는 것 — 모달, 바텀시트, 전체 화면 사진
  • 여러 단계 폼 — 단계마다 쌓으면 뒤로가 전 단계가 된다
  • 드로어로 연 메뉴

이럴 때는 안 쓴다

  • 조건·정렬이 바뀔 때마다 쌓기 → replaceState
  • 뒤로가기를 막기 — 사용자가 가장 싫어한다
  • ✕ 로 닫을 때 직접 닫기 — 기록이 남아 뒤로가 한 번 헛돈다
  • 확인 없이 저장 안 한 내용을 날리기

대신 이걸 — 같은 화면 안에서 값만 바뀌면 replaceState, 어디에 있는지 보여 주려면 브레드크럼, 되돌릴 일이면 되돌리기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 기록의 계약서

열 때 쌓고, popstate에서 닫고, ✕ 는 back()으로 모읍니다.

function openSheet() {
  history.pushState({ sheet: true }, '');   // 기록을 하나 쌓는다
  dialog.showModal();
}

window.addEventListener('popstate', () => {
  if (dialog.open) dialog.close();      // 뒤로 = 닫기
});

closeBtn.addEventListener('click', () => history.back());  // 한 길로 모은다

// Esc 로 닫혔을 때도 기록을 맞춰 준다
dialog.addEventListener('cancel', e => { e.preventDefault(); history.back(); });

// 조건이 바뀔 뿐이면 쌓지 말고 갈아끼운다
history.replaceState(null, '', '?status=ok&page=2');
키일어나야 하는 일
Esc와 뒤로를 한 길로cancel 이벤트를 막고 back()으로 보내면 둘이 어긋나지 않는다
pushState는 주소를 안 바꿔도 된다두 번째 인자만 주고 세 번째를 빼면 주소는 그대로다
replaceState와 가른다덮는 것은 push, 값만 바뀌면 replace
저장 안 한 내용beforeunload는 뒤로가기엔 안 통할 수 있다. 확인 다이얼로그를 직접 띄운다
<dialog>Esc 는 공짜지만 뒤로가기는 공짜가 아니다
초점뒤로로 닫혔을 때도 부른 버튼으로 초점을 되돌린다

9 서버 쪽으로 치면백엔드 감각으로 번역

주소에 담긴 것은 되살아난다뒤로가기로 돌아온 화면은 주소로 다시 그려집니다. 조건·쪽을 주소에 담아 두면 공짜로 복원됩니다.
뒤로 캐시브라우저는 앞 화면을 통째로 얼려 뒀다 되살립니다(bfcache). unload 핸들러를 달면 이 캐시가 꺼집니다.
되살아난 화면은 낡았다뒤로로 돌아온 목록은 몇 분 전 데이터입니다. pageshow의 persisted를 보고 다시 받을지 정합니다.
POST 뒤에는저장 뒤 그 자리에 머물면 뒤로가기에서 재전송 경고가 뜹니다. 저장 뒤에는 다른 주소로 보냅니다.
