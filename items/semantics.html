시맨틱 태그

Semantic HTML · landmarks

태그 이름이 그 자리의 뜻을 말해 주는 것. 역할·키보드 동작·구조를 공짜로 줍니다.

2 이름부르는 말이 여러 개다

한국어시맨틱 태그, 의미 있는 마크업, 구역
영어semantic HTML, landmarks, document structure
같이 쓰는 말<header>·<nav>·<main> 같은 큰 구역을 랜드마크(landmark)라 하고, h1~h6이 만드는 목차를 제목 구조(heading structure)라 합니다. 태그가 기본으로 갖는 역할은 암시적 역할(implicit role)입니다.
자주 잘못 부름SEO 용 — 검색에도 도움이 되지만 본래는 구조를 알리는 것입니다.
role을 붙이면 같다 — 역할만 같아지고 키보드 동작은 안 따라옵니다.
<section> — 이름이 있어야 구역으로 쳐 줍니다. 그냥 쓰면 div 와 같습니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다

한 줄로 — ARIA 의 첫 규칙은 "ARIA 를 쓰지 않는 것"입니다 — 맞는 태그가 있으면 그걸 씁니다.

4 갈래태그 하나가 주는 것

5 해부도부분 이름이 제일 안 알려진 지식

<header>로고와 검색
<nav>홈 · 정산 · 설정
<main>정산 목록 — 화면에 하나만
h1 → h2 → h3 — 건너뛰지 않는다
ul · ol — "항목 12개" 가 읽힌다
div 로만 쌓으면 구역 목록이 빈다
  1. 배너 <header>화면 맨 위. 로고·검색·계정
  2. 내비게이션 <nav>길 안내 묶음. 여럿이면 이름을 붙인다
  3. 메인 <main>그 화면의 본문. 하나만 두고, 건너뛰기 링크가 여기로 온다
  4. 제목 구조 h1 ~ h6건너뛰지 않는다. 보이는 크기는 CSS 가 따로 정한다
  5. 목록 <ul> · <ol>'항목 12개'가 저절로 읽힌다. <div>로 쌓으면 몇 건인지 모른다
  6. div 만 쌓기 <div>구역 목록이 빈다. 처음부터 끝까지 읽는 수밖에 없다

태그 하나가 세 가지를 한꺼번에 줍니다 — 역할(이게 무엇인가) · 동작(키보드로 눌리는가) · 구조(목록·목차에 들어가는가). role로 흉내 내면 역할 하나만 따라오고 나머지 둘은 직접 짜야 합니다. 그래서 태그를 고르는 일이 접근성의 8할이라는 말이 나옵니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 모든 화면 — 틀을 잡을 때 태그부터 고릅니다
  • 누를 것은 <button>, 이동은 <a href>
  • 반복되는 것은 <ul>·<ol>
  • <nav>가 여럿이면 각각 aria-label

이럴 때는 안 쓴다

  • 전부 <div>로 쌓는 것
  • <main>을 여러 개 두는 것
  • h1 다음에 h4로 뛰는 것 — 목차가 엉킵니다
  • 배치 때문에 <table>을 쓰는 것 — '표, 3열 5행'으로 읽힙니다

대신 이걸 — 키보드로 되는지는 키보드 조작, 역할·상태는 스크린 리더가 읽는 것, 보이는 위계는 글자 위계.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙태그부터 고른다

틀을 잡을 때 태그부터 고릅니다. CSS 는 그다음입니다.

<body>
  <a href="#main" class="skip">본문으로 건너뛰기</a>

  <header>…</header>
  <nav aria-label="주 메뉴">…</nav>

  <main id="main">          <!-- 화면에 하나만 -->
    <h1>정산</h1>
    <section aria-labelledby="w">
      <h2 id="w">이번 주</h2>
      <ul><li>…</li></ul>     <!-- "항목 12개" -->
    </section>
  </main>

  <footer>…</footer>
</body>
규칙지켜야 하는 것
태그부터 고른다역할·동작·구조가 한꺼번에 온다
<main>은 하나건너뛰기 링크의 목적지
제목을 건너뛰지 않는다h1 → h2 → h3. 보이는 크기는 CSS 로 따로
<nav>가 여럿이면 이름aria-label로 구별한다
<section>에는 이름이름 없는 section 은 div 와 같다
배치에 <table>을 안 쓴다'표, 3열 5행'으로 읽힌다

9 서버 쪽으로 치면백엔드 감각으로 번역

템플릿에서 한 번레이아웃 컴포넌트에 <header>·<main>을 박아 두면 모든 화면이 공짜로 따라옵니다.
제목 단계는 화면이 정한다같은 컴포넌트가 어떤 화면에서는 h2, 어떤 화면에서는 h3입니다. 단계를 props 로 받는 설계가 흔합니다.
SEO 와 겹친다구조가 또렷하면 검색 엔진도 잘 읽습니다 — 같은 작업으로 두 가지가 해결됩니다.
자동 검사랜드마크 유무, h1 개수, 제목 단계 건너뜀은 전부 자동으로 잡힙니다. CI 에 넣기 쉬운 쪽입니다.
