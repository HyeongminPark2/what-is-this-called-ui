시맨틱 태그

Semantic HTML · landmarks

시맨틱 태그는 태그 이름만 보고도 그 자리가 무슨 내용인지 알 수 있는 태그입니다. 알맞은 태그를 쓰면 역할과 키보드 동작, 문서 구조가 따로 코드를 쓰지 않아도 함께 들어옵니다.

새 탭에서 열기 ↗

아래에 스크린 리더의 구역 목록이 나옵니다. 스크린 리더 사용자는 이 목록을 띄워 놓고 '내비게이션'이나 '메인' 같은 구역으로 바로 건너뜁니다.
전부 div 로 바꾸기를 켜 보세요. 화면은 똑같은데 구역 목록이 모두 비어 버려서, 페이지를 처음부터 끝까지 순서대로 읽는 방법밖에 남지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어시맨틱 태그, 의미 있는 마크업, 구역
영어semantic HTML, landmarks, document structure
같이 쓰는 말<header>·<nav>·<main>처럼 화면을 크게 나누는 구역은 랜드마크(landmark)라고 하고, h1~h6이 만드는 목차는 제목 구조(heading structure)라고 합니다. 태그에 기본으로 들어 있는 역할은 암시적 역할(implicit role)이라고 부릅니다.
자주 잘못 부르는 이름SEO 용 — 시맨틱 태그는 검색에도 도움이 되지만, 본래 목적은 문서 구조를 알리는 것입니다.
role을 붙이면 같다 — role을 붙이면 역할만 같아지고 키보드 동작은 따라오지 않습니다.
<section> — <section>은 이름이 있어야 구역으로 인정되고, 이름 없이 쓰면 div와 같습니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

접근성은 눈으로는 보이지 않는 부분까지 챙기는 일입니다. 아래 네 가지를 물어보면 이 부의 항목들이 서로 어떻게 다른지 가를 수 있습니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람직접 들어 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다
대체 텍스트그림의 뜻안 보인다눈으로 안 보는 사람이미지를 끄고 읽어 본다
확대와 글자 크기키웠을 때도 쓰이나안 보인다저시력 사용자200%로 키워 본다

시맨틱 태그를 한 줄로 정리하면 — ARIA 사용 규칙의 첫 번째는 "ARIA를 쓰지 않는 것"입니다. 알맞은 태그가 있으면 ARIA 속성을 붙이지 말고 그 태그를 씁니다.

4 갈래태그 하나가 주는 것

5 해부도부분마다 붙은 이름

<header>로고와 검색
<nav>홈 · 정산 · 설정
<main>정산 목록 — 화면에 하나만
h1 → h2 → h3 — 건너뛰지 않는다
ul · ol — "항목 12개" 가 읽힌다
div 로만 쌓으면 구역 목록이 빈다
  1. 배너 <header>화면 맨 위 구역으로, 로고와 검색, 계정 메뉴가 들어갑니다
  2. 내비게이션 <nav>다른 페이지로 가는 링크를 모은 구역입니다. 여러 개라면 각각 이름을 붙입니다
  3. 메인 <main>그 화면의 본문입니다. 하나만 두고, 건너뛰기 링크를 누르면 이곳으로 옵니다
  4. 제목 구조 h1 ~ h6제목 단계는 건너뛰지 않습니다. 화면에 보이는 크기는 CSS로 따로 정합니다
  5. 목록 <ul> · <ol>'항목 12개'처럼 개수가 저절로 읽힙니다. <div>로 쌓으면 몇 건인지 알 수 없습니다
  6. div 만 쌓기 <div>구역 목록이 비어 버려서 처음부터 끝까지 순서대로 읽는 수밖에 없습니다

알맞은 태그 하나를 쓰면 요소가 무엇인지 알려 주는 역할, 키보드로 누를 수 있는 동작, 목록과 목차에 들어가는 구조까지 세 가지가 한꺼번에 들어옵니다. 반면 role로 흉내 내면 역할 하나만 생기고, 나머지 둘은 직접 짜야 합니다. 그래서 접근성 작업의 대부분은 알맞은 태그를 고르는 일이라는 말이 나옵니다.

6 쓸 때 / 안 쓸 때

시맨틱 태그를 쓰는 경우

  • 모든 화면의 틀을 잡을 때. 레이아웃보다 태그를 먼저 고릅니다
  • 누르는 요소와 이동하는 요소를 만들 때. 누르는 것은 <button>, 이동하는 것은 <a href>로 만듭니다
  • 같은 모양이 반복되는 항목을 만들 때. <ul>이나 <ol>로 감쌉니다
  • <nav>가 여러 개일 때. 각각 aria-label로 이름을 붙입니다

시맨틱 태그를 쓰지 않는 경우

  • 화면을 전부 <div>로 쌓을 때
  • 한 화면에 <main>을 여러 개 둘 때
  • h1 다음에 바로 h4를 쓸 때. 제목 구조로 만든 목차의 단계가 어긋납니다
  • 표가 아닌 내용을 배치하려고 <table>을 쓸 때. 스크린 리더가 '표, 3열 5행'으로 읽습니다

시맨틱 태그 대신 다른 것을 써야 하는 경우 — 키보드로 되는지는 키보드 조작, 역할·상태는 스크린 리더가 읽는 것, 보이는 위계는 글자 위계.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 규칙태그부터 고른다

화면의 틀을 잡을 때는 태그부터 고르고, CSS는 그다음에 씁니다.

<body>
  <a href="#main" class="skip">본문으로 건너뛰기</a>

  <header>…</header>
  <nav aria-label="주 메뉴">…</nav>

  <main id="main">          <!-- 화면에 하나만 -->
    <h1>정산</h1>
    <section aria-labelledby="w">
      <h2 id="w">이번 주</h2>
      <ul><li>…</li></ul>     <!-- "항목 12개" -->
    </section>
  </main>

  <footer>…</footer>
</body>
규칙지켜야 하는 것
태그부터 고른다알맞은 태그를 쓰면 역할, 동작, 구조가 한꺼번에 들어옵니다
<main>은 하나건너뛰기 링크를 누르면 도착하는 곳이므로 하나만 둡니다
제목을 건너뛰지 않는다h1, h2, h3 순서로 내려갑니다. 화면에 보이는 크기는 CSS로 따로 정합니다
<nav>가 여럿이면 이름aria-label로 이름을 붙여 서로 구별합니다
<section>에는 이름이름이 없는 section은 div와 같습니다
배치에 <table>을 안 쓴다배치용 표도 스크린 리더는 '표, 3열 5행'으로 읽습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

템플릿에서 한 번레이아웃 컴포넌트에 <header>와 <main>을 넣어 두면 그 레이아웃을 쓰는 모든 화면에 구역이 저절로 생깁니다.
제목 단계는 화면이 정한다같은 컴포넌트라도 어떤 화면에서는 h2, 어떤 화면에서는 h3이 되어야 합니다. 그래서 제목 단계를 props로 받도록 설계하는 경우가 많습니다.
SEO 와 겹친다문서 구조가 또렷하면 검색 엔진도 페이지를 잘 읽기 때문에, 한 번의 작업으로 접근성과 검색 노출을 함께 챙길 수 있습니다.
자동 검사랜드마크가 있는지, h1이 몇 개인지, 제목 단계를 건너뛰었는지는 모두 자동 검사로 찾을 수 있어서 CI에 넣기 쉽습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 세 플랫폼 모두 표준 부품을 쓰면 역할이 기본으로 들어오고, 직접 그리면 역할을 직접 짜야 한다는 점이 같습니다. 그래서 "이거 div로 만들었어요"와 "Box로 그렸어요"는 같은 상황을 말하고, 그 뒤에 해야 할 일도 같습니다.
