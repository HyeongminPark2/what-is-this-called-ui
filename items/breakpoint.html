브레이크포인트

Breakpoint

폭이 얼마일 때 배치를 바꿀지 정하는 지점. 기준은 기기 이름이 아니라 내용이 깨지는 폭입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 끌어 폭을 바꿔 보세요. 단 수와 메뉴 모양이 함께 바뀝니다.
잘못 잡은 기준으로를 켜면 흔히 쓰는 기기 폭(375 / 768 / 1024)에 맞춰 끊습니다 — 390px 폰에서 벌써 두 단이 되어 가게 이름이 두 줄로 접힙니다. 아래 숫자는 짐작이 아니라 실제로 접힌 칸을 센 것입니다.

2 이름부르는 말이 여러 개다

한국어브레이크포인트, 분기점, 중단점
영어breakpoint, media query breakpoint
같이 쓰는 말폭에 따라 다른 규칙을 주는 것이 미디어 쿼리(media query)이고, 좁은 쪽부터 쌓아 올리는 방식이 모바일 퍼스트입니다. 창이 아니라 제가 들어앉은 상자의 폭을 보는 것이 컨테이너 쿼리(@container)입니다. 단계마다 이름을 붙이면 sm · md · lg · xl처럼 됩니다.
자주 잘못 부름반응형 — 반응형은 결과이고, 브레이크포인트는 그 안의 한 수단입니다. 안 끊고도 반응형이 됩니다.
중단점 — 디버거의 breakpoint 와 같은 영어 단어라 검색이 섞입니다.
해상도 — 폭은 CSS px이지 기기 화소 수가 아닙니다. 화면 밀도와 섞지 않습니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다

한 줄로 — 끊는 자리는 기기가 정하지 않습니다. 창을 조금씩 줄이다가 글이 깨지는 그 폭이 그 화면의 브레이크포인트입니다.

5 해부도부분 이름이 제일 안 알려진 지식

@media (min-width: 560px) — 작은 쪽부터 쌓는다
가맹점가맹점가맹점가맹점
기준은 기기 이름이 아니라 내용이 깨지는 폭
끊는 자리는 서넛 — 많을수록 어긋난다
@container — 창이 아니라 제 상자를 본다
375 / 768 / 1024 — 기기 폭으로 잡은 흔한 실수
  1. 질의 @media (min-width)좁은 쪽을 기본으로 두고 넓어질 때 덧붙인다
  2. 단 수 1 → 2 → 3폭이 늘면 칸이 늘어난다. 칸이 넓어지기만 하면 안 된다
  3. 기준 내용이 깨지는 폭창을 줄이다가 글이 접히는 그 자리
  4. 개수 서넛다섯을 넘으면 어디가 어떻게 보이는지 아무도 모른다
  5. 컨테이너 쿼리 @container제가 들어앉은 상자를 본다. 부품을 옮겨 심을 수 있다
  6. 흔한 실수 기기 폭375 · 768 · 1024. 그 폭의 기기만 맞는다

모바일 퍼스트로 적는 이유는 취향이 아닙니다. max-width로 적으면 기본값이 '넓은 화면'이라, 새 기기나 작은 창에서 덮어쓰기가 빠진 구멍이 생깁니다. min-width로 쌓으면 기본값이 가장 좁은 화면이고 넓어질 때마다 덧붙이는 꼴이라, 빠뜨려도 좁은 화면의 배치로 떨어집니다. 망가지는 쪽이 안전한 쪽입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 배치가 더는 안 통하는 폭에서 — 재 보고 정한다
  • 메뉴를 접고 펼 때 · 단 수를 바꿀 때
  • 부품 하나가 여러 자리에 들어간다면 컨테이너 쿼리

이럴 때는 안 쓴다

  • 기기 이름으로 끊기 — 기기는 계속 나온다
  • 끊는 자리를 여섯 개 넘게 — 무엇이 어디서 바뀌는지 모르게 된다
  • 세로 높이로 끊기 — 폰 주소창 때문에 계속 흔들린다
  • 폭마다 다른 내용을 보여 주기 — 공유한 주소가 다른 화면이 된다

대신 이걸 — 단을 안 끊고 늘리려면 그리드의 auto-fit, 글줄 길이를 묶으려면 컨테이너, 부품 단위로 바꾸려면 컨테이너 쿼리.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 기준의 계약서

좁은 쪽을 기본으로 두고 min-width로 덧붙입니다.

:root { --bp-sm: 560px; --bp-md: 900px; --bp-lg: 1180px; }

.list { display: grid; gap: 12px; }          /* 기본 = 가장 좁은 화면 */

@media (min-width: 560px) { .list { grid-template-columns: 1fr 1fr; } }
@media (min-width: 900px) { .list { grid-template-columns: repeat(3, 1fr); } }

/* 아예 안 끊고도 된다 */
.cards { grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); }

/* 창이 아니라 제 상자를 본다 */
.slot { container-type: inline-size; }
@container (min-width: 420px) { .card { flex-direction: row; } }
키일어나야 하는 일
<meta name="viewport">이게 없으면 폰이 980px 짜리 창인 척한다. 미디어 쿼리가 통째로 헛돈다
min-width로 쌓는다빠뜨려도 좁은 화면 배치로 떨어진다. 안전한 쪽으로 망가진다
폭 단위는 pxem으로 적으면 글자 크기 설정에 따라 끊는 자리가 움직인다. 그걸 노린 게 아니면 px
@container부모에 container-type: inline-size가 있어야 한다. 없으면 조용히 안 먹는다
폭만 숨기지 않는다display:none으로 지운 내용은 그 폭에서 영영 못 본다
키보드로도 같은 일좁은 폭에서 메뉴를 접었다면 접힌 버튼도 Tab 으로 닿아야 한다

9 서버 쪽으로 치면백엔드 감각으로 번역

폭에 따라 다른 것을 보내지 않는다서버가 기기를 보고 다른 HTML 을 주면 캐시가 갈라지고 공유한 주소가 사람마다 다른 화면이 됩니다.
그림은 폭에 맞춰srcset·sizes로 그 폭에 맞는 크기를 받게 합니다. 한 벌만 주면 폰이 큰 파일을 받습니다.
목록 건수폰에서 한 쪽에 50건은 과합니다. 폭이 아니라 쪽 크기를 조절하는 편이 낫습니다.
User-Agent로 가르지 않는다기기 문자열은 계속 바뀌고 거짓말도 합니다. 폭은 브라우저가 알고 있습니다.

자주 생기는 사고 — "아이폰이랑 아이패드에서 잘 되게"라는 요청을 그대로 받으면 그 두 기기 폭에만 맞는 화면이 됩니다. 폴더블·분할 화면·브라우저 창 반쪽 같은 폭이 계속 나오므로, 기기 이름 대신 '이 화면은 몇 px 부터 두 단'으로 바꿔 적어 두는 편이 오래갑니다.
