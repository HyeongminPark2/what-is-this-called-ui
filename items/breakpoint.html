브레이크포인트

Breakpoint

브레이크포인트는 화면 폭이 얼마일 때 배치를 바꿀지 정하는 지점입니다. 이 지점은 기기 이름이 아니라 내용이 깨지기 시작하는 폭을 기준으로 잡습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 끌어 폭을 바꿔 보세요. 폭에 따라 단 수와 메뉴 모양이 함께 바뀝니다.
기기 폭을 기준으로 끊기를 켜면 흔히 쓰는 기기 폭(375 / 768 / 1024)에서 단을 바꾸는데, 그러면 390px 폰에서부터 두 단이 되어 가게 이름이 두 줄로 접힙니다. 아래 숫자는 어림한 값이 아니라 화면에서 실제로 접힌 칸을 센 결과입니다.

2 이름같은 것을 부르는 여러 이름

한국어브레이크포인트, 분기점, 중단점
영어breakpoint, media query breakpoint
같이 쓰는 말화면 폭에 따라 다른 CSS 규칙을 적용하는 문법을 미디어 쿼리(media query)라고 하고, 가장 좁은 화면을 기본으로 두고 넓은 화면용 규칙을 덧붙여 가는 방식을 모바일 퍼스트라고 합니다. 브라우저 창 대신 요소를 감싼 상자의 폭을 기준으로 삼는 문법은 컨테이너 쿼리(@container)입니다. 단계마다 이름을 붙일 때는 흔히 sm · md · lg · xl처럼 부릅니다.
자주 잘못 부르는 이름반응형 — 반응형은 화면 폭에 맞춰 배치가 바뀌는 결과를 가리키고, 브레이크포인트는 그 결과를 만드는 여러 수단 가운데 하나입니다. 브레이크포인트로 끊지 않고도 반응형 화면을 만들 수 있습니다.
중단점 — 디버거에서 실행을 멈추는 breakpoint와 영어 단어가 같아서, 이 말로 검색하면 디버거 자료가 섞여 나옵니다.
해상도 — 브레이크포인트의 폭은 기기 화소 수가 아니라 CSS px로 잽니다. 기기 화소 수는 화면 밀도에서 다루는 다른 값입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

PC와 폰의 차이는 기계 자체보다 화면을 쓰는 전제에 있습니다. 아래 네 가지를 물어보면 두 환경이 어디서 갈리는지 알 수 있습니다.

두 환경에서 다른 점폰에서는PC에서는챙기지 않으면 생기는 일
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 배치가 깨짐
터치 타깃누를 수 있는 넓이44px 이상24px도 괜찮음옆의 것이 눌림
호버가 없는 세계올려놓기가 되는지안 됨됨끝내 볼 수 없는 정보가 생김
시스템 백뒤로 가는 길OS가 제공함브라우저의 ← 버튼모달 대신 앱이 꺼짐
화면 밀도1px의 실제 화소 수2~3배1~2배그림이 뭉개짐
뷰포트 단위100vh가 가리키는 높이주소창 때문에 달라짐하나로 정해짐바닥 버튼이 잘림
폰 키보드키보드가 올라와 덮는 자리화면의 절반덮지 않음입력칸이 가려짐
HIG와 Material의 차이OS마다 다른 관례OS마다 다름웹 관례를 따름어느 쪽에서도 어색함

브레이크포인트를 한 줄로 정리하면 — 브레이크포인트는 기기 폭에 맞춰 정하지 않습니다. 브라우저 창을 조금씩 줄여 가다가 글이 깨지기 시작하는 폭을 찾으면, 그 폭이 그 화면의 브레이크포인트입니다.

5 해부도부분마다 붙은 이름

@media (min-width: 560px)로 좁은 화면부터 쌓음
가맹점가맹점가맹점가맹점
기준은 기기 이름이 아니라 내용이 깨지는 폭
끊는 자리는 서넛, 많으면 관리가 어려움
@container는 창 대신 감싼 상자의 폭을 봄
375 / 768 / 1024처럼 기기 폭으로 잡는 실수
  1. 질의 @media (min-width)좁은 화면을 기본으로 두고, 넓어질 때 필요한 규칙을 덧붙입니다
  2. 단 수 1 → 2 → 3폭이 늘면 칸 수가 늘어나야 합니다. 칸 수는 그대로 두고 칸만 넓어지게 두면 안 됩니다
  3. 기준 내용이 깨지는 폭창을 줄여 가다가 글이 접히기 시작하는 폭입니다
  4. 개수 서넛다섯 개를 넘기면 폭마다 화면이 어떻게 보이는지 파악하기 어려워집니다
  5. 컨테이너 쿼리 @container요소를 감싼 상자의 폭을 기준으로 삼기 때문에, 부품을 다른 자리로 옮겨도 그 자리 폭에 맞게 배치가 바뀝니다
  6. 기기 폭으로 끊은 자리 기기 폭375 · 768 · 1024처럼 기기 폭으로 끊으면 그 폭의 기기에서만 화면이 맞습니다

미디어 쿼리를 모바일 퍼스트로 적는 데에는 이유가 있습니다. max-width로 적으면 기본 규칙이 넓은 화면용이 되기 때문에, 새 기기나 작은 창에서 좁은 화면용 규칙이 빠진 폭이 생기면 넓은 화면 배치가 덮어써지지 않고 그대로 나옵니다. 반면 min-width로 쌓으면 기본 규칙이 가장 좁은 화면용이고 넓어질 때마다 규칙을 덧붙이는 구조라서, 규칙 하나를 빠뜨려도 좁은 화면의 배치로 보입니다. 좁은 화면 배치는 넓은 창에서도 읽는 데 문제가 없으므로, 실수했을 때 화면이 덜 망가집니다.

6 쓸 때 / 안 쓸 때

브레이크포인트로 배치를 바꾸는 경우

  • 지금 배치가 더는 맞지 않는 폭을 창을 줄여 가며 재 보고 정할 때
  • 메뉴를 접거나 펴고, 단 수를 바꿀 때
  • 부품 하나가 여러 자리에 들어갈 때. 이때는 컨테이너 쿼리를 씁니다

브레이크포인트를 잘못 잡는 경우

  • 기기 이름에 맞춰 끊을 때. 새 기기가 계속 나오기 때문에 금방 맞지 않게 됩니다
  • 끊는 자리를 여섯 개 넘게 둘 때. 무엇이 어느 폭에서 바뀌는지 알 수 없게 됩니다
  • 세로 높이로 끊을 때. 폰에서는 주소창이 나타났다 사라지면서 높이가 계속 바뀝니다
  • 폭마다 다른 내용을 보여 줄 때. 같은 주소를 공유해도 받는 사람의 화면 폭에 따라 다른 내용이 보입니다

브레이크포인트 대신 다른 것을 써야 하는 경우 — 끊는 자리 없이 폭에 따라 칸 수를 늘리려면 그리드의 auto-fit을 쓰고, 글줄 길이를 묶으려면 컨테이너를 씁니다. 부품 하나를 놓인 자리의 폭에 맞춰 바꾸려면 컨테이너 쿼리가 맞습니다.

8 최소 코드와 지킬 규칙빠뜨리기 쉬운 설정까지 담은 규칙

가장 좁은 화면의 규칙을 기본으로 두고, 넓은 화면용 규칙은 min-width 미디어 쿼리로 덧붙입니다.

:root { --bp-sm: 560px; --bp-md: 900px; --bp-lg: 1180px; }

.list { display: grid; gap: 12px; }          /* 기본 = 가장 좁은 화면 */

@media (min-width: 560px) { .list { grid-template-columns: 1fr 1fr; } }
@media (min-width: 900px) { .list { grid-template-columns: repeat(3, 1fr); } }

/* 브레이크포인트 없이도 칸 수가 바뀐다 */
.cards { grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); }

/* 창 대신 감싼 상자의 폭을 본다 */
.slot { container-type: inline-size; }
@container (min-width: 420px) { .card { flex-direction: row; } }
지킬 규칙지키는 방법과 까닭
<meta name="viewport"> 태그 넣기이 태그가 없으면 폰 브라우저가 화면을 폭 980px짜리 창으로 여기고 그립니다. 그러면 좁은 화면용 미디어 쿼리가 하나도 적용되지 않습니다
min-width로 쌓기규칙을 빠뜨려도 좁은 화면 배치로 보이기 때문에 화면이 덜 망가집니다
폭 단위는 px로 적기em으로 적으면 사용자의 글자 크기 설정에 따라 끊는 자리가 움직입니다. 일부러 그렇게 하려는 게 아니라면 px로 적습니다
@container를 쓸 때부모 요소에 container-type: inline-size가 있어야 합니다. 없으면 오류 없이 규칙만 적용되지 않습니다
좁은 폭에서 내용을 숨기지 않기display:none으로 숨긴 내용은 그 폭의 화면에서는 볼 방법이 없습니다
키보드로도 같은 일을 할 수 있게좁은 폭에서 메뉴를 접었다면, 접힌 메뉴를 여는 버튼에도 Tab으로 포커스가 가야 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

폭에 따라 다른 HTML을 보내지 않기서버가 기기를 보고 서로 다른 HTML을 보내면 같은 주소의 캐시를 기기별로 나눠야 하고, 공유한 주소를 연 사람마다 다른 화면을 보게 됩니다.
그림은 화면 폭에 맞는 크기로 보내기srcset과 sizes를 써서 브라우저가 화면 폭에 맞는 크기의 그림을 골라 받게 합니다. 큰 그림 한 벌만 두면 폰도 그 큰 파일을 받아야 합니다.
한 쪽에 담는 목록 건수폰에서 한 쪽에 50건씩 보여 주면 너무 많습니다. 폭에 맞춰 배치만 바꾸기보다 한 쪽에 담는 건수인 쪽 크기를 조절하는 편이 낫습니다.
User-Agent로 기기를 가르지 않기User-Agent 문자열은 브라우저가 바뀔 때마다 달라지고, 실제 기기와 다른 값이 오는 경우도 있습니다. 화면 폭은 브라우저가 미디어 쿼리로 직접 판단하므로 서버가 기기를 짐작할 필요가 없습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 화면 폭을 나누는 방식과 기본값이 조금씩 다릅니다.

웹@media · @container
가맹점가맹점가맹점가맹점
끊는 폭을 CSS에 직접 적습니다. CSS 프레임워크마다 기본값(640·768·1024·1280 등)이 있으니 팀에서 한 가지로 정해 쓰면 됩니다.
iOSSize Class
폭을 숫자로 나누지 않고 compact / regular 두 등급으로 나눕니다. 아이패드의 분할 화면도 같은 등급 규칙으로 다룹니다.
안드로이드Window Size Class
창 폭을 compact(600dp 미만) · medium · expanded 세 등급으로 나눕니다. 접었다 펴는 폴더블 기기가 나오면서 폭을 숫자 대신 등급으로 다루는 방식이 자리를 잡았습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "아이폰이랑 아이패드에서 잘 되게"라는 요청을 그대로 받으면 그 두 기기 폭에만 맞는 화면이 됩니다. 폴더블 기기, 분할 화면, 반으로 줄인 브라우저 창처럼 새로운 폭은 계속 생기므로, 요청을 기기 이름 대신 '이 화면은 몇 px부터 두 단'처럼 폭으로 바꿔 적어 두면 기기가 바뀌어도 그대로 쓸 수 있습니다.
