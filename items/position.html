포지션

Position

포지션의 다섯 값은 요소가 자리를 차지하는가와 무엇을 기준으로 움직이는가, 이 두 가지를 정합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

값을 바꿔 가며 점선 칸을 보세요. absolute와 fixed는 흐름에서 빠지기 때문에 자리를 차지하지 않습니다.
가까운 조상에 relative 걸기를 켜고 끄면 absolute의 기준이 완전히 바뀝니다. 요소가 엉뚱한 곳에 붙는 문제는 거의 다 이 한 줄로 설명됩니다.

2 이름같은 것을 부르는 여러 이름

한국어포지션, 위치 지정, 절대 위치, 고정
영어position, static / relative / absolute / fixed / sticky
같이 쓰는 말static이 아닌 값이 걸린 요소는 positioned라고 하고, absolute는 가장 가까운 positioned 조상을 포함 블록(containing block)으로 삼습니다. top·right·bottom·left를 묶어 오프셋이라고 부르며, 요즘은 inset 한 줄로 적습니다.
자주 잘못 부르는 이름z-index — z-index는 앞뒤 순서를 정하고 포지션은 자리를 정합니다. 다만 z-index는 positioned 요소에서만 적용됩니다.
float — 예전에 쓰던 배치 방법이고, 지금은 플렉스·그리드를 씁니다.
스티키 — 스티키도 포지션 값 가운데 하나지만, 다룰 내용이 많아서 항목을 따로 두었습니다.

3 포지션의 다섯 값값마다 달라지는 차지하는 자리와 기준

4 해부도부분마다 붙은 이름

static 기본값, top·left가 적용되지 않음
relative 자리는 남기고 보이는 위치만 옮김
absolute 흐름에서 빠지고 가까운 positioned 조상이 기준
fixed 화면이 기준이라 스크롤해도 그대로
sticky relative와 fixed의 중간
transform이 걸린 조상이 fixed의 기준이 됨
  1. static 기본값흐름대로 놓이고, 오프셋이 적용되지 않습니다
  2. relative 자리를 남김보이는 위치만 옮깁니다. absolute 자식의 기준점 역할도 합니다
  3. absolute 흐름에서 빠짐가장 가까운 positioned 조상을 기준으로 놓입니다
  4. fixed 화면이 기준스크롤해도 움직이지 않습니다
  5. sticky relative와 fixed의 중간자리를 차지하면서 정해진 선에 붙습니다
  6. 기준을 바꾸는 조상 transformtransform이 걸린 조상이 fixed의 기준이 됩니다

fixed 요소가 화면에 붙지 않는 문제는 거의 항상 조상 어딘가에 transform·filter·will-change가 걸려 있어서 생깁니다. 이 속성들은 새 기준점을 만들기 때문에 fixed 요소가 화면이 아니라 그 상자를 기준으로 놓입니다. 예를 들어 애니메이션을 넣으려고 부모에 transform을 걸면, 그 안의 떠 있는 메뉴가 부모 상자 안에 갇힙니다. 이처럼 원인과 결과가 멀리 떨어져 있어서 찾기 어렵습니다. 같은 원리는 무엇을 움직이나에서도 다룹니다.

5 쓸 때 / 안 쓸 때

포지션을 쓰는 경우

  • 배지, 닫기 버튼, 떠 있는 메뉴처럼 다른 요소 위에 겹쳐 올릴 때
  • absolute의 기준을 만들 때. 부모에 relative를 겁니다
  • 화면에 붙여 둘 요소를 만들 때. 단, transform이 걸린 조상이 없는지 확인합니다

포지션을 쓰지 않는 경우

  • 전체 배치를 absolute로 짤 때. 플렉스·그리드를 먼저 씁니다
  • relative를 아무 데나 걸 때. 기준이 엉뚱한 곳에 생깁니다
  • fixed로 폰 화면 바닥에 붙일 때. 키보드가 덮습니다
  • 오프셋만 주고 position을 주지 않을 때. 아무 일도 일어나지 않습니다

포지션 대신 다른 것을 써야 하는 경우 — 요소를 한 방향으로 늘어놓는 배치는 플렉스로, 가로와 세로 두 방향 배치는 그리드로 짭니다. 평소에는 흐름을 따르다가 스크롤하면 붙는 요소는 스티키를 씁니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙포지션을 쓸 때 지킬 것

기준을 만들 부모에 relative를 걸고, 자식에 오프셋을 줍니다.

.card {
  position: relative;        /* 기준점을 만든다 */
}
.card .badge {
  position: absolute;
  top: -6px; right: -6px;   /* 또는 inset 한 줄로 */
}

/* 바닥 막대. 폰 키보드와 세이프 에어리어를 함께 챙긴다 */
.cta-bar {
  position: fixed;
  inset: auto 0 0 0;
  padding-bottom: env(safe-area-inset-bottom);
}

/* ✕ 조상에 transform이 있으면 fixed가 화면이 아니라 그 상자를 따른다 */
.animated-parent { transform: translateY(0); }
지킬 규칙지키는 방법
오프셋을 줄 때 position도 함께 주기position이 static이면 top·left가 모두 무시됩니다
네 방향 오프셋은 inset으로 적기네 방향 오프셋을 한 줄로 적습니다. inset: 0은 기준 상자를 꽉 채웁니다
z-index는 positioned 요소에만 주기positioned 요소에서만 적용되고, static에는 적용되지 않습니다
자리를 옮겨도 초점 순서는 그대로라는 점 기억하기absolute로 자리를 옮겨도 Tab 순서는 마크업 순서를 따릅니다(보이는 순서와 읽는 순서 참고)
fixed 요소의 조상에 transform이 있는지 보기조상에 transform이 걸려 있으면 fixed의 기준이 그 조상으로 바뀝니다
폰 바닥에 붙인 요소는 키보드 위로 올리기fixed는 키보드가 올라온 것을 반영하지 않으므로 visualViewport로 위치를 올려 줍니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

화면 쪽에서만 처리하는 배치포지션은 모두 화면 쪽에서 처리하는 배치입니다. 다만 떠 있는 요소가 많으면 화면을 그리는 부담이 커집니다(무엇을 움직이나 참고).
인쇄할 때 fixed 요소 처리fixed 요소는 인쇄할 때 매 쪽에 찍히거나 아예 사라지기 때문에 인쇄용 스타일을 따로 둡니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

요소를 흐름에서 빼낸다는 생각은 세 플랫폼 모두 같습니다.

웹position
줄상자
다섯 값이 있고, 요소가 어디를 기준으로 놓이는지 찾는 것이 핵심입니다. 조상의 transform이 fixed의 기준을 바꿔 버리는 것이 함정입니다.
iOSZStack · overlay
ZStack·.overlay()로 겹칩니다. 기준이 항상 감싼 뷰라서 헷갈릴 일이 적습니다.
안드로이드Box · Modifier
Compose의 Box 안에서 align으로 붙이며, 여기서도 기준이 분명합니다.

플랫폼 차이 때문에 자주 생기는 문제 — "배지가 엉뚱한 데 붙어요"와 "고정 메뉴가 화면에 안 붙어요"는 거의 항상 기준 문제입니다. 앞의 경우는 조상에 relative가 없고, 뒤의 경우는 조상에 transform이 있습니다. 이 두 가지만 알아도 포지션 관련 버그는 대부분 몇 분 안에 고칠 수 있습니다.
