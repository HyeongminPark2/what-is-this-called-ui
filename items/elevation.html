고도

Elevation · shadow scale

고도는 화면 요소가 얼마나 위에 떠 있는지를 그림자로 나타내도록 정해 둔 단입니다. 그림자는 꾸미려고 넣는 것이 아니라 높이를 알려 주려고 넣습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

단이 올라갈수록 그림자는 진해지지 않고 더 멀리, 더 흐리게 퍼집니다. 빛이 위에서 비춘다고 가정하고 만들기 때문입니다.
그림자 대신 테두리로를 켜 보세요. 구역은 여전히 나뉘지만 무엇이 위에 있는지는 알 수 없게 됩니다. 그림자가 잘 보이지 않는 어두운 화면에서도 같은 일이 일어납니다.

2 이름같은 것을 부르는 여러 이름

한국어고도, 그림자 단계, 그림자 체계
영어elevation, shadow scale, depth
같이 쓰는 말그림자 자체는 드롭 섀도(drop shadow), 안쪽으로 파인 듯 보이게 하는 그림자는 인너 섀도(inset)라고 합니다. Material에서는 높이를 dp 단위의 고도로 나타내고(elevation 6dp), 웹 디자인 시스템에서는 보통 shadow-sm · md · lg 같은 이름을 붙여 둡니다.
자주 잘못 부르는 이름z-index — z-index는 요소가 쌓이는 순서이고, 고도는 눈에 보이는 높이입니다. 둘을 함께 정해 두기는 하지만 같은 것은 아닙니다.
블러 — 블러는 대상을 흐리게 만드는 효과이고, 번짐은 그림자 가장자리를 흐리게 처리하는 값입니다.
입체 — 요즘 쓰는 고도는 입체감을 내려는 것이 아니라 화면의 층을 구별하려는 것입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지 × 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

고도를 한 줄로 정리하면 — 고도는 "이 요소가 위에 떠 있다"는 것을 알리는 표시입니다. 보기 좋아서 그림자를 넣고 있다면 고도를 쓰임에 맞게 쓰고 있지 않은 것입니다.

4 단단마다 쓰는 부품

5 해부도부분마다 붙은 이름

그림자 하나는 숫자 네 개와 색 하나입니다
0 ← 가로 치우침
10px ← 아래로 내린 거리
24px ← 번짐
0 ← 퍼짐
rgba(20,22,26,.12) ← 색과 진하기
  1. 그림자 한 벌 box-shadow보통 가까이 붙는 짧은 그림자와 멀리 퍼지는 큰 그림자, 두 겹을 겹쳐 씁니다
  2. 가로 치우침 offset-x빛이 바로 위에 있다고 가정하기 때문에 거의 늘 0으로 둡니다
  3. 아래로 내린 거리 offset-y높이를 나타내는 숫자로, 단이 올라갈수록 커집니다
  4. 번짐 blur그림자 가장자리가 흐려지는 정도입니다. 높은 단일수록 크게 잡습니다
  5. 퍼짐 spread그림자 전체를 키우거나 줄입니다. 보통 0으로 두고, 테두리처럼 보이게 할 때만 씁니다
  6. 색과 진하기 color · alpha검정 대신 바탕색 계열의 어두운 색을 쓰면 덜 탁해 보입니다. 진하기는 0.06~0.18 사이로 둡니다

단을 올릴 때는 진하기를 올리지 않고 거리와 번짐을 키웁니다. 바닥에서 멀리 떨어진 물체일수록 그림자가 흐리고 넓게 퍼지기 때문입니다. 진하기만 올리면 물체가 떠 보이지 않고 둘레에 짙은 회색 테두리가 생긴 것처럼 보입니다.

6 쓸 때 / 안 쓸 때

고도를 쓰는 경우

  • 드롭다운, 팝오버, 모달, 토스트처럼 다른 요소 위에 겹쳐 뜨는 부품일 때
  • 끌어서 옮기는 중인 요소일 때. 바닥에서 들어 올렸다는 표시가 필요합니다
  • 밝은 바탕에서 카드를 구별할 때

고도를 쓰지 않는 경우

  • 어두운 화면일 때. 그림자가 잘 보이지 않으므로 면을 밝히는 방식으로 바꿉니다
  • 모든 요소에 그림자를 넣을 때. 전부 떠 있으면 어느 것이 위에 있는지 구별할 수 없습니다
  • 글자와 아이콘에 넣을 때. 높이는 드러나지 않고 읽기만 어려워집니다
  • 인쇄용 화면일 때

고도 대신 다른 것을 써야 하는 경우 — 요소의 앞뒤 순서는 z-index로 정하고, 어두운 화면에서 높이를 나타내는 방법은 다크 모드에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙고도를 코드로 옮기는 법

단마다 그림자를 두 겹으로 둡니다. 가까운 그림자는 가장자리를 또렷하게 하고, 먼 그림자는 높이를 나타냅니다.

:root {
  --e1: 0 1px 2px rgba(20,22,26,.06), 0 1px 1px rgba(20,22,26,.04);
  --e2: 0 4px 12px rgba(20,22,26,.08), 0 1px 3px rgba(20,22,26,.06);
  --e3: 0 10px 24px rgba(20,22,26,.12), 0 3px 8px rgba(20,22,26,.08);
}

.card     { box-shadow: var(--e1); }
.popover  { box-shadow: var(--e2); }
.modal    { box-shadow: var(--e3); }

/* 어두운 모드에서는 그림자가 보이지 않으니 면을 밝혀 높이를 낸다 */
:root[data-theme="dark"] {
  --e1: none; --e2: none; --e3: none;
  --surface-1: #1c2029; --surface-2: #232834;
}
규칙지켜야 하는 것
단은 네댓 개0·1·2·3·4 다섯 단이면 충분합니다. 여섯 단을 넘으면 단끼리 구별되지 않습니다
거리와 번짐을 키운다진하기는 거의 그대로 두고, 높은 단일수록 그림자를 멀리, 흐리게 둡니다
가로 치우침은 0빛이 바로 위에 있다고 정해 두면 화면 전체의 그림자 방향이 일관됩니다
검정 대신 어두운 바탕색rgba(0,0,0,.2) 같은 검정보다 바탕색 계열의 어두운 색이 덜 탁해 보입니다
어두운 모드는 면으로그림자를 none으로 두고 면 색을 한 단 밝힙니다
부품마다 단을 못 박는다'카드는 1단, 팝오버는 2단'처럼 정해 두면 부품을 만들 때마다 단을 고르지 않아도 됩니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

고도 = 로그 레벨 같은 열거형고도는 DEBUG·INFO·WARN처럼 순서가 있는 몇 개의 값입니다. 단과 단 사이에 중간값을 만들고 싶어진다면 단을 잘못 설계했다는 뜻입니다.
성능브라우저는 화면을 그릴 때마다 그림자를 계산하기 때문에, 긴 목록의 줄마다 큰 그림자를 넣으면 스크롤이 눈에 띄게 끊깁니다. 그래서 목록 줄은 테두리로 나눕니다.
캡처·인쇄PDF로 뽑거나 메일에 넣는 화면에서는 그림자가 회색 띠로 찍히는 일이 있으므로, 인쇄용 스타일에서는 그림자를 꺼 둡니다.
고도와 z-index 를 같이 정의눈에 보이는 높이와 실제로 쌓이는 순서가 어긋나면 '위에 있는 것처럼 보이는데 클릭은 아래 요소가 받는' 버그가 생깁니다. 그래서 두 값을 한 표에 함께 적어 둡니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

안드로이드는 고도를 물리적인 높이로 다루는 반면, iOS와 웹에서는 그림자 값을 직접 정합니다.

정해진 규격이 없어서 팀마다 값이 다릅니다. 요즘은 그림자를 두 겹 이상 겹쳐 만드는 방식을 많이 씁니다.
iOSApple HIG

그림자를 아껴서 씁니다. 떠 있는 느낌은 그림자보다 뒤를 반투명하게 흐리는 머티리얼로 내는 일이 많습니다.
안드로이드Material 3
elevation = 6.dp
tonalElevation
고도를 dp 높이로 적으면 그림자는 OS가 계산해서 그립니다. M3는 그림자 대신 면의 색을 밝혀 높이를 나타내는 색조 고도를 권합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 안드로이드에서 고도는 숫자 하나(6dp)이고, 그림자는 그 숫자에 따라 저절로 그려집니다. 그래서 웹에서 쓰던 그림자 값을 그대로 건네면 안드로이드로 옮길 방법이 없습니다. "그림자를 이렇게 해 주세요" 대신 "이건 몇 단인가"로 이야기하면 세 플랫폼이 같은 기준으로 맞출 수 있습니다.
