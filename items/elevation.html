고도

Elevation · shadow scale

2 이름부르는 말이 여러 개다

한국어고도, 그림자 단계, 그림자 체계
영어elevation, shadow scale, depth
같이 쓰는 말그림자 자체는 드롭 섀도(drop shadow), 안쪽으로 파인 것은 인너 섀도(inset)입니다. Material 에서는 높이를 dp 단위의 고도로 말하고(elevation 6dp), 웹 디자인 시스템에서는 보통 shadow-sm · md · lg 같은 이름으로 둡니다.
자주 잘못 부름z-index — z-index 는 쌓이는 순서이고 고도는 보이는 높이입니다. 둘을 같이 정해 두지만 같은 것이 아닙니다.
블러 — 블러는 흐리게 하는 효과, 번짐은 그림자의 가장자리 처리입니다.
입체 — 요즘의 고도는 입체감을 내려는 것이 아니라 층을 구별하려는 것입니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보인다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선하다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 안 읽히고 z-index 가 안 먹는다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 안 맞는다
상태 색성공 · 주의 · 오류 · 정보4가지 × 3자리알림 · 배지 · 입력 오류색을 못 보면 상태를 못 읽는다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 아무도 못 고친다

한 줄로 — 고도는 "이게 위에 떠 있다"는 한마디입니다. 그림자를 예뻐서 넣고 있다면 이미 쓰임이 아닙니다.

4 단단마다 맡은 부품이 있다

5 해부도부분 이름이 제일 안 알려진 지식

그림자 하나는 숫자 네 개와 색 하나입니다
0 ← 가로 치우침
10px ← 아래로 내린 거리
24px ← 번짐
0 ← 퍼짐
rgba(20,22,26,.12) ← 색과 진하기
  1. 그림자 한 벌 box-shadow보통 두 겹을 겹친다 — 가까운 짧은 그림자와 멀리 퍼지는 큰 그림자
  2. 가로 치우침 offset-x거의 늘 0이다. 빛이 바로 위에 있다고 치기 때문
  3. 아래로 내린 거리 offset-y높이를 말하는 숫자. 단이 올라갈수록 커진다
  4. 번짐 blur가장자리가 흐려지는 정도. 높을수록 크게 잡는다
  5. 퍼짐 spread그림자를 통째로 키우거나 줄인다. 보통 0, 테두리를 흉내 낼 때만 쓴다
  6. 색과 진하기 color · alpha검정 대신 바탕색의 어두운 쪽을 쓰면 덜 탁하다. 진하기는 0.06~0.18 사이

단을 올릴 때 진하기를 올리는 것이 아니라 거리와 번짐을 키웁니다. 멀리 있는 물체일수록 그림자가 흐리고 넓게 퍼지기 때문입니다. 진하기만 올리면 물체가 뜬 것이 아니라 검댕이 묻은 것처럼 보입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 겹쳐 뜨는 부품 — 드롭다운, 팝오버, 모달, 토스트
  • 끌어서 옮기는 중인 것 — 떴다는 신호가 필요합니다
  • 밝은 바탕에서 카드를 구별할 때

이럴 때는 안 쓴다

  • 어두운 화면 — 그림자가 안 보입니다. 면을 밝히는 쪽으로 바꿉니다
  • 모든 것에 다 넣는 것 — 다 떠 있으면 아무것도 안 떠 있는 것과 같습니다
  • 글자와 아이콘에 — 읽기만 나빠집니다
  • 인쇄용 화면

대신 이걸 — 앞뒤 순서를 정하는 일은 z-index가 맡고, 어두운 쪽에서 높이를 내는 방법은 다크 모드에 있습니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 단의 계약서

단마다 그림자를 두 겹으로 둡니다 — 가까운 그림자가 테두리를 또렷하게 하고, 먼 그림자가 높이를 말합니다.

:root {
  --e1: 0 1px 2px rgba(20,22,26,.06), 0 1px 1px rgba(20,22,26,.04);
  --e2: 0 4px 12px rgba(20,22,26,.08), 0 1px 3px rgba(20,22,26,.06);
  --e3: 0 10px 24px rgba(20,22,26,.12), 0 3px 8px rgba(20,22,26,.08);
}

.card     { box-shadow: var(--e1); }
.popover  { box-shadow: var(--e2); }
.modal    { box-shadow: var(--e3); }

/* 어두운 모드 — 그림자는 안 보인다. 면을 밝혀 높이를 낸다 */
:root[data-theme="dark"] {
  --e1: none; --e2: none; --e3: none;
  --surface-1: #1c2029; --surface-2: #232834;
}
규칙지켜야 하는 것
단은 네댓 개0·1·2·3·4 면 충분하다. 여섯 단이 넘으면 서로 구별이 안 된다
거리와 번짐을 키운다진하기는 거의 그대로 둔다. 높이 = 멀고 흐리게
가로 치우침은 0빛이 바로 위에 있다고 정해 두면 화면 전체가 일관된다
검정 대신 어두운 바탕색rgba(0,0,0,.2)보다 바탕색 계열이 덜 탁하다
어두운 모드는 면으로그림자를 none으로 두고 면 색을 한 단 밝힌다
부품마다 단을 못 박는다'카드는 1단, 팝오버는 2단'처럼 정해 두면 매번 고르지 않아도 된다

9 서버 쪽으로 치면백엔드 감각으로 번역

고도 = 로그 레벨 같은 열거형DEBUG·INFO·WARN 처럼 순서가 있는 적은 값입니다. 중간값을 만들고 싶어지면 단 설계가 잘못된 것입니다.
성능그림자는 그릴 때마다 계산합니다. 긴 목록의 줄마다 큰 그림자를 넣으면 스크롤이 눈에 띄게 끊깁니다 — 목록 줄은 테두리로 나눕니다.
캡처·인쇄PDF 로 뽑거나 메일에 넣는 화면에서는 그림자가 회색 띠로 찍히는 일이 있습니다. 인쇄용 스타일에서는 꺼 둡니다.
고도와 z-index 를 같이 정의보이는 높이와 쌓이는 순서가 어긋나면 '위에 보이는데 클릭은 아래가 먹는' 버그가 납니다. 한 표에 같이 적어 둡니다.
