뷰포트 단위

Viewport units

100vh 가 가리키는 높이는 하나가 아닙니다. 폰 주소창이 숨었다 나타나기 때문입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 폰이 같은 화면을 100vh·100svh·100dvh로 그린 것입니다. 주소창 보이기를 켜 보세요 — 100vh 짜리만 바닥의 '다음' 버튼이 잘립니다.
아래 표는 이 브라우저에서 네 단위가 실제로 몇 px 인지 잰 것입니다. PC 에서는 숨는 주소창이 없어 넷이 같습니다 — 차이는 폰에서만 드러납니다.

2 이름부르는 말이 여러 개다

한국어뷰포트 단위, 화면 높이 단위
영어viewport units, vh / svh / lvh / dvh
같이 쓰는 말v는 viewport, h는 height 입니다. 앞에 붙는 글자가 small(작은 쪽) · large(큰 쪽) · dynamic(지금) 입니다. 가로는 vw, 짧은 쪽·긴 쪽이 vmin·vmax입니다. 브라우저 창 안쪽에서 실제로 보이는 영역을 비주얼 뷰포트라 하고 window.visualViewport로 읽습니다.
자주 잘못 부름화면 높이 — 기기 화면이 아니라 브라우저 창 안쪽입니다.
100% — 100%는 부모의 높이이고 100vh는 창의 높이입니다. 전혀 다릅니다.
풀스크린 — 전체 화면 API 와는 상관없습니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다
HIG와 Material의 차이OS 의 말투각자 다르다웹 관례어느 쪽에서도 어색하다

한 줄로 — 바닥에 뭔가 붙는 화면이면 100dvh입니다. 100vh는 PC 에서만 맞습니다.

4 주소창에 따라같은 100%가 네 가지

5 해부도부분 이름이 제일 안 알려진 지식

100lvh — 큰 쪽. 주소창이 숨었을 때
100svh — 작은 쪽. 주소창이 보일 때
100dvh — 지금 보이는 만큼. 굴리면 바뀐다
100vh = 100lvh — 주소창이 보이면 삐져나간다
100vw 는 세로 막대 폭을 안 뺀다 — 가로로 넘친다
meta viewport 가 없으면 전부 헛돈다
  1. 큰 쪽 lvh주소창이 숨었을 때의 높이. vh와 같다
  2. 작은 쪽 svh주소창이 보일 때. 늘 안전하지만 아래가 남는다
  3. 지금 dvh보이는 만큼. 굴리면 따라 바뀐다
  4. vh 의 정체 = lvh큰 쪽 고정. 주소창이 보이면 삐져나간다
  5. 가로의 함정 100vw세로 스크롤 막대 폭을 안 뺀다. PC 에서 가로로 넘친다
  6. 전제 meta viewport없으면 폰이 980px 창인 척한다. 전부 헛돈다

100dvh가 늘 정답인 것도 아닙니다. 굴릴 때마다 값이 바뀌므로, 그 높이를 쓰는 상자가 따라 움직이며 흔들립니다. 배경처럼 가만히 있어야 하는 것에는 100lvh가 낫고, 바닥에 버튼이 붙는 화면에는 100dvh가 맞습니다. 둘 다 피하고 싶으면 100svh를 쓰고 아래가 조금 남는 것을 받아들입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 바닥에 버튼이 붙는 한 화면짜리 폼 → 100dvh
  • 화면을 꽉 채우는 모달·시트
  • 히어로 영역 — 다만 흔들림을 보고 lvh 와 고른다

이럴 때는 안 쓴다

  • 100vh를 폰에서 그대로 — 바닥이 잘린다
  • 100vw로 전체 폭 — PC 에서 가로 스크롤이 생긴다
  • <meta name="viewport"> 빠뜨리기
  • 키보드까지 dvh로 해결될 거라 믿기 → 폰 키보드

대신 이걸 — 부모 높이를 꽉 채우려면 100%, 바닥에 붙이려면 스티키나 position:fixed, 글줄 길이를 묶으려면 컨테이너.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 단위의 계약서

meta viewport를 적고, 높이는 두 줄로 겹쳐 적습니다.

<meta name="viewport" content="width=device-width, initial-scale=1">

.screen {
  min-height: 100vh;     /* 옛 브라우저 */
  min-height: 100dvh;    /* 아는 브라우저는 이 줄을 쓴다 */
  display: flex; flex-direction: column;
}
.screen .cta { margin-top: auto; }   /* 바닥에 붙인다 */

/* 가로는 vw 대신 % */
.full { width: 100%; }

/* 키보드까지 따라가려면 직접 재야 한다 */
visualViewport.addEventListener('resize', () => {
  document.documentElement.style.setProperty('--vvh', visualViewport.height + 'px');
});
키일어나야 하는 일
meta viewport없으면 폰이 980px 창인 척한다. 이 한 줄이 반응형의 전제다
user-scalable=no를 쓰지 않는다확대를 막으면 저시력 사용자가 못 읽는다. 접근성 위반이다
maximum-scale도 마찬가지5배까지는 열어 둔다
두 줄로 겹쳐 적기모르는 단위가 나오는 줄은 통째로 무시되므로, 옛 줄을 먼저 적으면 저절로 대비가 된다
svh·dvh 지원2022년 이후 브라우저. 그 전 것에는 vh가 떨어진다
100vw 대신 100%세로 스크롤 막대가 있는 PC 에서 가로 스크롤이 생기는 흔한 원인

9 서버 쪽으로 치면백엔드 감각으로 번역

서버는 높이를 모른다창 높이는 요청에 담겨 오지 않습니다. 서버에서 미리 그려 보낼 때는 CSS 로만 처리합니다.
첫 그림이 흔들린다자바스크립트로 높이를 재서 넣는 방식은 한 번 그린 뒤 바뀌어 덜컥거립니다. CSS 단위로 되면 CSS 로 합니다.
