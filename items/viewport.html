뷰포트 단위

Viewport units

폰 브라우저에서는 주소창이 숨었다 나타나기 때문에, 100vh 같은 뷰포트 단위가 가리키는 높이도 그때그때 달라집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 폰은 같은 화면을 각각 100vh·100svh·100dvh로 그린 것입니다. 주소창 보이기를 켜 보면 100vh로 그린 폰에서만 바닥의 '다음' 버튼이 잘립니다.
아래 표는 지금 보는 브라우저에서 네 단위가 실제로 몇 px인지 잰 결과입니다. PC에는 숨었다 나타나는 주소창이 없어서 네 값이 같고, 차이는 폰에서만 드러납니다.

2 이름같은 것을 부르는 여러 이름

한국어뷰포트 단위, 화면 높이 단위
영어viewport units, vh / svh / lvh / dvh
같이 쓰는 말v는 viewport, h는 height의 머리글자이고, 앞에 붙는 글자는 small(작은 쪽), large(큰 쪽), dynamic(지금 보이는 만큼)을 뜻합니다. 가로 폭은 vw로 적고, 짧은 쪽과 긴 쪽은 각각 vmin과 vmax로 적습니다. 브라우저 창 안쪽에서 실제로 보이는 영역은 비주얼 뷰포트라고 하며 window.visualViewport로 크기를 읽습니다.
자주 잘못 부르는 이름화면 높이 — 뷰포트 단위가 재는 것은 기기 화면이 아니라 브라우저 창 안쪽의 높이입니다.
100% — 100%는 부모 요소의 높이를 기준으로 하고, 100vh는 창의 높이를 기준으로 하므로 서로 다른 값입니다.
풀스크린 — 화면 전체를 쓰게 하는 전체 화면 API와는 상관이 없습니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

PC와 폰은 기계보다 쓰는 전제가 다릅니다. 아래 네 가지로 두 환경을 견줍니다.

두 환경에서 다른 점폰에서는PC에서는챙기지 않으면 생기는 일
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 배치가 깨짐
터치 타깃누를 수 있는 넓이44px 이상24px도 괜찮음옆의 것이 눌림
호버가 없는 세계올려놓기가 되는지안 됨됨끝내 볼 수 없는 정보가 생김
시스템 백뒤로 가는 길OS가 제공함브라우저의 ← 버튼모달 대신 앱이 꺼짐
화면 밀도1px의 실제 화소 수2~3배1~2배그림이 뭉개짐
뷰포트 단위100vh가 가리키는 높이주소창 때문에 달라짐하나로 정해짐바닥 버튼이 잘림
폰 키보드키보드가 올라와 덮는 자리화면의 절반덮지 않음입력칸이 가려짐
HIG와 Material의 차이OS마다 다른 관례OS마다 다름웹 관례를 따름어느 쪽에서도 어색함

뷰포트 단위를 한 줄로 정리하면 — 바닥에 버튼 같은 것이 붙는 화면이라면 100dvh를 씁니다. 100vh는 주소창이 숨지 않는 PC에서만 화면 높이와 맞습니다.

4 주소창에 따라 달라지는 높이같은 100이 가리키는 네 가지 높이

5 해부도부분마다 붙은 이름

100lvh는 주소창이 숨었을 때의 큰 높이
100svh는 주소창이 보일 때의 작은 높이
100dvh는 지금 보이는 높이라 굴리면 바뀜
100vh는 100lvh와 같아 주소창이 보이면 넘침
100vw는 세로 막대 폭을 빼지 않아 가로로 넘침
meta viewport가 없으면 모두 다르게 계산됨
  1. 큰 쪽 높이 lvh주소창이 숨었을 때의 높이로, vh와 같습니다
  2. 작은 쪽 높이 svh주소창이 보일 때의 높이입니다. 화면 밖으로 넘치지 않아 늘 안전하지만, 주소창이 숨으면 아래가 남습니다
  3. 지금 보이는 높이 dvh지금 보이는 만큼의 높이라서 화면을 굴리면 따라 바뀝니다
  4. vh가 가리키는 높이 lvh와 같음큰 쪽 높이로 고정되어 있어서 주소창이 보이면 화면 아래로 넘칩니다
  5. 가로 폭 단위 100vw세로 스크롤 막대 폭을 빼지 않기 때문에 PC에서 가로로 넘칩니다
  6. 먼저 넣을 태그 meta viewport이 태그가 없으면 폰 브라우저가 화면을 폭 980px짜리 창으로 여기고 그려서, 뷰포트 단위와 미디어 쿼리가 모두 의도와 다르게 계산됩니다

100dvh에도 단점이 있습니다. 화면을 굴릴 때마다 값이 바뀌기 때문에, 그 높이를 쓰는 상자가 크기를 따라 바꾸며 흔들립니다. 그래서 배경처럼 가만히 있어야 하는 것에는 100lvh가 낫고, 바닥에 버튼이 붙는 화면에는 100dvh가 맞습니다. 흔들림과 잘림을 둘 다 피하고 싶다면 100svh를 쓰고, 주소창이 숨었을 때 아래가 조금 비는 것은 감수합니다.

6 쓸 때 / 안 쓸 때

뷰포트 단위를 쓰는 경우

  • 바닥에 버튼이 붙는 한 화면짜리 폼을 만들 때. 100dvh를 씁니다
  • 화면을 꽉 채우는 모달이나 시트를 만들 때
  • 첫 화면을 채우는 히어로 영역을 만들 때. 다만 흔들림이 거슬리면 lvh를 고릅니다

뷰포트 단위를 잘못 쓰는 경우

  • 100vh를 폰에서 그대로 쓸 때. 주소창이 보이면 바닥이 잘립니다
  • 100vw로 전체 폭을 잡을 때. PC에서 가로 스크롤이 생깁니다
  • <meta name="viewport">를 빠뜨렸을 때
  • 키보드가 올라오는 문제까지 dvh로 해결될 거라고 여길 때. 폰 키보드 항목을 봅니다

뷰포트 단위 대신 다른 것을 써야 하는 경우 — 부모 요소의 높이를 꽉 채우려면 100%를 쓰고, 바닥에 붙이려면 스티키나 position:fixed를 씁니다. 글줄 길이를 묶을 때는 컨테이너가 맞습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 지킬 규칙빠뜨리기 쉬운 설정까지 담은 규칙

먼저 meta viewport를 적고, 높이는 옛 단위와 새 단위를 두 줄로 겹쳐 적습니다.

<meta name="viewport" content="width=device-width, initial-scale=1">

.screen {
  min-height: 100vh;     /* 옛 브라우저 */
  min-height: 100dvh;    /* 아는 브라우저는 이 줄을 쓴다 */
  display: flex; flex-direction: column;
}
.screen .cta { margin-top: auto; }   /* 바닥에 붙인다 */

/* 가로는 vw 대신 % */
.full { width: 100%; }

/* 키보드까지 따라가려면 직접 재야 한다 */
visualViewport.addEventListener('resize', () => {
  document.documentElement.style.setProperty('--vvh', visualViewport.height + 'px');
});
지킬 규칙지키는 방법과 까닭
meta viewport 넣기이 태그가 없으면 폰 브라우저가 화면을 폭 980px짜리 창으로 여기고 그립니다. 반응형 화면은 이 한 줄이 있어야 작동합니다
user-scalable=no를 쓰지 않기확대를 막으면 저시력 사용자가 글을 읽을 수 없어서 접근성 기준에 어긋납니다
maximum-scale로 확대를 막지 않기확대 배율은 5배까지 허용해 둡니다
두 줄로 겹쳐 적기브라우저는 모르는 단위가 나오는 줄을 통째로 무시하므로, 옛 단위 줄을 먼저 적어 두면 옛 브라우저에서도 그 줄이 적용됩니다
svh·dvh를 지원하는 브라우저2022년 이후에 나온 브라우저가 지원합니다. 그 전 브라우저에서는 vh 줄이 적용됩니다
100vw 대신 100% 쓰기세로 스크롤 막대가 있는 PC에서 가로 스크롤이 생기는 흔한 원인이 100vw입니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버가 알 수 없는 창 높이창 높이는 요청에 담겨 오지 않습니다. 그래서 서버에서 HTML을 미리 그려 보낼 때는 높이 처리를 CSS에 맡깁니다.
자바스크립트로 높이를 잴 때 생기는 흔들림자바스크립트로 높이를 재서 넣으면 화면을 한 번 그린 뒤에 높이가 바뀌어 화면이 덜컥거립니다. CSS 단위로 해결할 수 있으면 CSS로 처리합니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

앱에는 주소창이 없기 때문에, 높이가 흔들리는 것은 웹에만 있는 문제입니다.

웹vh · svh · lvh · dvh
example.com
dvh
svh·lvh·dvh는 브라우저 UI가 숨었다 나타나는 문제 때문에 생긴 단위이고, 2022년에야 표준으로 정리되었습니다.
iOSsafe area · 전체 높이
앱에는 주소창이 없어서 화면 높이가 하나로 정해집니다. 대신 노치와 홈 표시줄이 차지하는 세이프 에어리어를 빼고 배치해야 합니다.
안드로이드insets
상태 표시줄과 내비게이션 바가 차지하는 높이를 인셋(insets)으로 알려 줍니다. 안드로이드 앱도 주소창이 없어서 높이가 흔들리지는 않습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "폰에서 아래 버튼이 안 눌려요"라는 문의는 대개 100vh 때문이거나 폰 키보드 때문입니다. 두 문제 모두 PC 브라우저에서는 재현되지 않아서 고쳤는지 확인하려면 폰에서 열어 봐야 합니다. 그러니 이 부분은 일정에 실제 기기에서 한 번 열어 보는 단계를 넣어 두는 편이 낫습니다.
