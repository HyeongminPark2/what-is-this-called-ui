박스 모델

Box model

화면에 놓이는 요소는 모두 내용, 안쪽 여백, 테두리, 바깥 여백으로 이루어진 네 겹짜리 상자입니다. 레이아웃이 어긋나는 일은 대부분 이 네 겹을 잘못 셈하는 데서 시작합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 움직여 네 겹의 크기가 어떻게 바뀌는지 보세요. 아래 줄에는 CSS에 적은 값과 상자가 실제로 차지하는 자리가 함께 나옵니다.
box-sizing을 끄면 width: 200px이라고 적었는데도 상자가 240px로 커집니다. 기본값에서 width는 내용 칸만의 너비라서 패딩과 테두리가 그 바깥에 더해지기 때문입니다. 대부분의 프로젝트가 스타일시트 맨 위에 * { box-sizing: border-box } 한 줄을 넣어 두는 것도 이 계산을 피하려는 것입니다.

2 이름같은 것을 부르는 여러 이름

한국어박스 모델, 상자 모델
영어box model, content box, border box
같이 쓰는 말안쪽 여백은 패딩(padding), 바깥 여백은 마진(margin), 테두리는 보더(border), 글과 그림이 들어가는 칸은 콘텐츠 박스(content box)입니다. width가 어디까지의 너비를 뜻하는지 정하는 속성은 box-sizing이고, 위아래 마진이 하나로 합쳐지는 현상은 마진 겹침(margin collapsing)이라고 부릅니다.
자주 잘못 부르는 이름패딩과 마진 — 둘 다 '여백'이라서 섞어 부르기 쉽지만, 패딩은 테두리 안쪽, 마진은 테두리 바깥쪽 여백입니다. 배경색이 칠해지는 여백이면 패딩이고, 칠해지지 않으면 마진입니다.
width — width에 적은 값이 곧 상자 너비라고 생각하기 쉽지만, 실제 너비는 box-sizing 값에 따라 달라집니다.
여백 — 디자인에서 말하는 여백(white space)은 패딩·마진보다 넓은 뜻으로 씁니다.

박스 모델을 한 줄로 정리하면 — 박스 모델에서 따질 것은 CSS에 적은 값이 어느 겹까지의 크기인가입니다. 그 답은 box-sizing 한 줄에 따라 달라집니다.

4 상자를 이루는 네 겹겹을 하나씩 더할 때마다 커지는 크기

5 해부도부분마다 붙은 이름

내용
box-sizing: border-box
  1. 마진 margin테두리 바깥 여백입니다. 배경색이 칠해지지 않고, 상자 크기에도 들어가지 않습니다
  2. 테두리 border상자를 두르는 선입니다. 투명하게 칠해도 두께만큼 자리를 차지합니다
  3. 패딩 padding테두리 안쪽 여백입니다. 배경색이 여기까지 칠해지고, 누를 수 있는 범위도 여기까지입니다
  4. 내용 content글과 그림이 들어가는 칸입니다. 기본값에서는 width가 이 칸의 너비를 가리킵니다
  5. box-sizing box-sizingwidth가 내용 칸까지의 너비인지, 테두리까지의 너비인지를 정합니다. 이 값에 따라 상자 크기 계산이 모두 달라집니다

박스 모델에는 마진 겹침이라는 현상도 있습니다. 위아래로 맞닿은 두 상자의 마진은 서로 더해지지 않고 큰 쪽 하나로 합쳐지기 때문에, 24px과 16px이 맞닿으면 간격은 40px이 아니라 24px이 됩니다. 이 현상은 가로 방향에서는 일어나지 않고, 플렉스나 그리드 안에서도 일어나지 않습니다. 간격이 생각보다 좁게 나올 때 원인이 마진 겹침인 경우가 많아서, 요즘은 마진 대신 겹치지 않는 gap을 먼저 씁니다.

6 쓸 때 / 안 쓸 때

박스 모델을 따져 봐야 하는 경우

  • 모든 화면을 만들 때. 어떤 요소든 박스 모델을 따르기 때문에, 이것부터 알아야 나머지 레이아웃이 설명됩니다
  • 간격이 생각과 다를 때. 박스 모델은 가장 먼저 확인할 곳입니다
  • 누를 수 있는 범위를 키우고 싶을 때. 마진이 아니라 패딩을 키워야 누르는 범위가 넓어집니다

박스 모델을 다룰 때 피할 것

  • 마진으로 요소 사이 간격을 만들 때. 마진 겹침이 생길 수 있으니 gap을 먼저 씁니다
  • width와 padding을 둘 다 고정값으로 정할 때. 크기 계산이 어긋나기 쉽습니다
  • box-sizing을 요소마다 다르게 줄 때. 맨 위에서 한 번 정하고 모든 요소에 같은 값을 씁니다

박스 모델과 함께 보면 좋은 항목 — 간격 값 자체는 간격 체계가 정하고, 넘친 내용을 어떻게 처리할지는 넘침에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙상자를 다룰 때 지킬 것

프로젝트 맨 위에 아래 세 줄을 넣어 두면 크기 계산이 대부분 예상대로 맞습니다.

/* 대부분의 프로젝트가 맨 위에 두는 줄 */
*, *::before, *::after { box-sizing: border-box; }

.card {
  width: 100%;        /* border-box라서 패딩을 더해도 넘치지 않는다 */
  padding: 16px;
  border: 1px solid var(--line);
}

/* 마진 대신 gap을 쓰면 겹침이 아예 안 생긴다 */
.list { display: grid; gap: 16px; }

/* 누를 자리를 키울 때는 마진이 아니라 패딩 */
.icon-btn { padding: 10px; }   /* 아이콘 20px + 패딩 = 40px 터치 영역 */
지킬 규칙지키는 방법
border-box를 기본값으로 정하기스타일시트 맨 위에서 한 번만 정하고, 요소마다 다르게 두지 않습니다
마진 대신 gap으로 간격 주기위아래 마진은 맞닿으면 합쳐지지만(마진 겹침), gap은 합쳐지지 않습니다
누를 자리는 패딩으로 넓히기마진으로 간격을 벌리면 그 자리는 눌리지 않는 빈 공간이 됩니다
투명한 테두리로 자리를 미리 잡아 두기호버할 때만 테두리를 주면 그 두께만큼 상자가 커져서 레이아웃이 1px씩 밀립니다. 처음부터 투명한 테두리를 둬서 자리를 잡아 둡니다
width와 padding을 함께 고정하지 않기둘 중 하나는 자동으로 두는 편이 안전합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

API 응답에서 내용과 포장을 나누는 일과 비슷함내용과 그 둘레의 패딩·테두리를 나눠 생각하는 것은 API 응답에서 data와 meta를 나누는 일과 비슷합니다. 두 경우 모두 어디까지가 내용인지를 정하는 일입니다.
글 길이에 따라 달라지는 상자 크기상자 높이는 보통 내용의 양에 따라 정해지기 때문에 데이터가 길어지면 레이아웃도 바뀝니다. 그래서 들어올 수 있는 가장 긴 값을 넣고 화면을 한 번 그려 보는 것이 좋은 테스트가 됩니다.
이미지 크기를 미리 알려 주기이미지에 width·height 속성이 없으면 사진을 다 받은 순간 상자가 갑자기 커지면서 아래 내용이 밀려납니다. 서버가 이미지 크기를 함께 내려 주면 사진을 받기 전에 자리를 미리 잡아 둘 수 있습니다.
메일 HTML을 만들 때메일 클라이언트 가운데에는 box-sizing을 무시하는 곳이 많기 때문에, 메일 템플릿은 지금도 <table>로 레이아웃을 짭니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

박스 모델은 웹에서 쓰는 개념이고, iOS와 안드로이드는 비슷한 개념을 다른 이름으로 부릅니다.

웹CSS box model
내용
네 겹이 분명하게 나뉘고, box-sizing 값에 따라 width가 가리키는 범위가 바뀝니다.
iOSApple HIG · SwiftUI
.padding(16)
.frame(width:)

.padding()으로 패딩을, .frame()으로 크기를 정합니다. 마진이라는 개념이 없어서 바깥 여백도 패딩이나 간격으로 줍니다.
안드로이드Compose · View
Modifier
 .padding(16.dp)
 .size(200.dp)
예전 View에는 padding과 margin이 모두 있었지만, Compose에서는 적은 순서대로 적용되는 Modifier로 바뀌었습니다. 그래서 패딩을 테두리보다 앞에 쓰는지 뒤에 쓰는지에 따라 결과가 달라집니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS와 Compose에는 마진이 없기 때문에, "마진 16 주세요"라는 요청은 앱에서 '부모의 패딩'이나 '간격(spacing)'으로 바꿔 구현해야 합니다. 시안의 바깥 여백이 어느 상자에 속하는지(이 상자의 바깥인지, 부모의 안쪽인지)를 분명히 적어 두면 앱에서도 같은 간격으로 옮길 수 있습니다.
