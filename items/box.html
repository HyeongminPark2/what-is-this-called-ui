박스 모델

Box model

화면의 모든 것은 네 겹짜리 상자입니다 — 내용 · 안쪽 여백 · 테두리 · 바깥 여백. 레이아웃이 어긋나는 거의 모든 일이 여기서 시작합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 움직이며 네 겹이 어떻게 자라는지 보세요. 아래 줄에 적은 값과 실제로 차지하는 자리가 같이 나옵니다.
box-sizing을 꺼 보면 width: 200px이라고 적었는데 상자가 240px이 됩니다 — 기본값에서 width 는 '내용만'의 너비이기 때문입니다. 거의 모든 프로젝트가 맨 위에 * { box-sizing: border-box } 한 줄을 까는 이유입니다.

2 이름부르는 말이 여러 개다

한국어박스 모델, 상자 모델
영어box model, content box, border box
같이 쓰는 말안쪽 여백은 패딩(padding), 바깥 여백은 마진(margin), 테두리는 보더(border), 글과 그림이 들어가는 칸은 콘텐츠 박스(content box)입니다. width 가 어디까지를 뜻하는지 정하는 속성이 box-sizing이고, 위아래 마진이 하나로 합쳐지는 현상을 마진 겹침(margin collapsing)이라 합니다.
자주 잘못 부름패딩과 마진 — 둘 다 '여백'이라 섞어 부르기 쉽지만, 테두리 안인지 밖인지가 다릅니다. 배경색이 칠해지면 패딩, 안 칠해지면 마진입니다.
width — 적은 값이 곧 상자 너비라고 생각하기 쉬운데, box-sizing에 따라 달라집니다.
여백 — 디자인에서 말하는 여백(white space)은 더 넓은 뜻입니다.

4 겹네 겹이 각각 다르게 자란다

5 해부도부분 이름이 제일 안 알려진 지식

내용
box-sizing: border-box
  1. 마진 margin테두리 바깥. 배경색이 안 칠해지고, 상자 크기에도 안 들어간다
  2. 테두리 border선. 투명해도 두께만큼 자리를 먹는다
  3. 패딩 padding테두리 안쪽. 배경색이 여기까지 칠해져서 누를 수 있는 범위도 여기까지다
  4. 내용 content글·그림이 들어가는 칸. width가 기본으로 가리키는 것이 바로 이것
  5. box-sizing box-sizingwidth가 내용까지냐 테두리까지냐를 정한다. 한 줄로 모든 계산이 바뀐다

마진 겹침이라는 함정이 하나 더 있습니다. 위아래로 맞닿은 두 상자의 마진은 더해지지 않고 큰 쪽 하나로 합쳐집니다(24 + 16 = 24). 가로에서는 안 일어나고, 플렉스·그리드 안에서도 안 일어납니다. '왜 간격이 생각보다 좁지'의 절반이 이것이고, 그래서 요즘은 마진 대신 gap을 먼저 씁니다 — gap 은 겹치지 않습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 모든 화면 — 피할 수 없습니다. 이것부터 알아야 나머지가 설명됩니다
  • 간격이 생각과 다를 때 제일 먼저 의심할 곳
  • 누를 수 있는 범위를 키우고 싶을 때 — 마진이 아니라 패딩을 키웁니다

이럴 때는 안 쓴다

  • 마진으로 간격을 만드는 것 — 겹침이 생깁니다. gap을 먼저 씁니다
  • width와 padding을 둘 다 못 박는 것 — 계산이 어긋나기 시작합니다
  • box-sizing을 요소마다 다르게 쓰는 것 — 한 번 깔고 끝냅니다

대신 이걸 — 간격 값 자체는 간격 체계가 정하고, 넘친 내용은 넘침이 맡습니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 상자의 계약서

프로젝트 맨 위의 세 줄이 거의 모든 계산을 정상으로 만듭니다.

/* 거의 모든 프로젝트의 첫 줄 */
*, *::before, *::after { box-sizing: border-box; }

.card {
  width: 100%;        /* border-box 라 패딩을 더해도 안 터진다 */
  padding: 16px;
  border: 1px solid var(--line);
}

/* 마진 대신 gap — 겹침이 아예 안 생긴다 */
.list { display: grid; gap: 16px; }

/* 누를 자리를 키울 때는 마진이 아니라 패딩 */
.icon-btn { padding: 10px; }   /* 아이콘 20px + 패딩 = 40px 터치 영역 */
규칙지켜야 하는 것
border-box를 깐다맨 위에 한 번. 요소마다 다르게 두지 않는다
마진 대신 gap마진은 위아래가 합쳐진다(겹침). gap 은 안 합쳐진다
누를 자리는 패딩으로마진으로 떼면 안 눌리는 빈 공간이 생긴다
테두리는 투명해도 자리를 먹는다호버에만 테두리를 주면 1px 씩 덜컥거린다. 미리 투명 테두리를 둔다
width와 padding을 같이 못 박지 않는다둘 중 하나는 자동으로 두는 편이 안전하다

9 서버 쪽으로 치면백엔드 감각으로 번역

박스 모델 = 데이터의 포장값 자체(내용)와 포장(패딩·테두리)을 나눠 생각하는 것과 같습니다. API 응답의 data와 meta를 나누는 것처럼, 어디까지가 내용인지를 정하는 일입니다.
글 길이가 크기를 정한다상자 높이는 보통 내용이 정합니다. 그래서 데이터가 길어지면 레이아웃이 바뀝니다 — 가장 긴 값으로 한 번 그려 보는 것이 테스트입니다.
이미지 크기를 미리 알려 준다width·height 속성이 없으면 사진이 올 때 상자가 갑자기 커져 화면이 덜컥거립니다. 서버가 크기를 같이 내려주면 미리 자리를 잡을 수 있습니다.
메일 HTML메일 클라이언트는 box-sizing을 무시하는 곳이 많습니다. 그래서 메일 템플릿은 여전히 <table>로 짭니다.
