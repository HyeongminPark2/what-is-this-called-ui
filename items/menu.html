드롭다운 메뉴

Dropdown menu

누르면 무슨 일이 일어나는 목록입니다. 누르면 값이 정해질 뿐인 셀렉트와 생김새가 같아 가장 많이 섞입니다.

2 이름부르는 말이 여러 개다

한국어드롭다운 메뉴, 메뉴, 더 보기 메뉴, 케밥 메뉴
영어dropdown menu, menu, overflow menu, kebab menu
같이 쓰는 말점 세 개로 여는 것을 오버플로 메뉴·케밥 메뉴라 부릅니다. 주 동작 옆에 화살표가 붙은 것은 스플릿 버튼(split button), 메뉴 안에서 또 열리는 것은 서브메뉴입니다. 값을 고르는 쪽은 셀렉트이고 역할 이름도 다릅니다.
자주 잘못 부름셀렉트 — 셀렉트는 값을 고릅니다. 아무 일도 안 일어납니다.
팝오버 — 팝오버는 아무 내용이나 담습니다.
컨텍스트 메뉴 — 컨텍스트 메뉴는 오른쪽 눌러 엽니다.

겹쳐 뜨는 부품들은 모양으로는 구별이 안 됩니다. 이 네 가지만 물어보면 갈립니다.

한 줄로 — 누르면 일이 일어나면 메뉴, 값만 정해지면 셀렉트입니다. 역할 이름부터 다릅니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

단추 — aria-haspopup · aria-expanded
동작 목록이면 menu / menuitem
값 고르기면 listbox / option
단축키는 오른쪽에 적는다
자리가 없으면 위로 뒤집는다
닫으면 초점이 단추로 돌아온다
  1. 단추 aria-haspopup무엇이 열리는지
  2. 동작 목록 menu/menuitem누르면 일이 일어난다
  3. 값 고르기 listbox/option누르면 값이 정해진다
  4. 단축키 오른쪽가르치는 자리
  5. 뒤집기 자리가 없으면잘리지 않게
  6. 닫은 뒤 단추로초점을 돌려준다

둘을 가르는 질문은 하나입니다 — 누르면 무슨 일이 일어나나. '지우기'는 일이 일어나니 메뉴고, '매주 수요일'은 값만 정해지니 셀렉트입니다. 역할 이름이 다르면 소리로 듣는 사람이 듣는 말도 달라집니다 — 메뉴는 '메뉴 항목', 셀렉트는 '목록 상자 · 선택됨'이라고 읽힙니다.
섞어 쓰면 키보드도 어긋납니다. 메뉴는 Enter 로 실행하고 닫히지만, 셀렉트는 고른 값이 표시로 남아야 합니다 — 어느 쪽인지 모르면 어느 쪽 동작도 제대로 못 만듭니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 누르면 일이 일어나면 메뉴, 아니면 셀렉트
  • 자리가 없으면 위로 뒤집기
  • 닫으면 초점을 단추로 돌려주기

이럴 때는 안 쓴다

  • 셀렉트를 role="menu" 로 만들기 — 고른 값이 안 들린다
  • 메뉴를 아래로만 열기 — 화면 끝에서 잘린다
  • 메뉴에 입력칸 넣기 — 그건 팝오버다
  • 항목을 열다섯 개 넘게 두기 — 묶거나 팔레트로

대신 이걸 — 값을 고르면 셀렉트, 아무 내용이나 담으면 팝오버, 오른쪽 눌러 열면 컨텍스트 메뉴, 아래에서 올라오면 액션 시트.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

동작 목록이면 menu, 값 고르기면 listbox — 여기서부터 갈립니다.

<!-- 동작 목록 — 누르면 일이 일어난다 -->
<button aria-haspopup="menu" aria-expanded="false"
        aria-controls="m1">더 보기</button>
<div id="m1" role="menu" hidden>
  <button role="menuitem">이름 바꾸기</button>
  <button role="menuitem" class="danger">지우기</button>
</div>

/* 자리가 없으면 위로 — CSS 만으로도 된다 */
[popover] { position-try-fallbacks: flip-block; }

// 닫으면 초점을 단추로 돌려준다
menu.addEventListener('close', () => trigger.focus());
키일어나야 하는 일
Enter · Space · ↓단추에서 메뉴를 연다
↑ ↓항목 사이를 옮긴다 — Tab 이 아니다
Home · End처음 · 마지막 항목으로
Esc닫고 초점을 단추로
글자 키그 글자로 시작하는 항목으로 — 긴 메뉴에서 쓸모가 크다
확인하는 법Tab 을 눌러 메뉴 밖으로 안 나가는지 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

할 수 있는 일권한에 따라 항목을 지웁니다 — 흐리게 두면 '왜 안 되나'를 묻게 됩니다.
동작의 결과메뉴 항목을 누르면 보통 요청이 나갑니다 — 되돌리기를 붙일지 미리 정합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

이름과 역할이 플랫폼마다 또렷하게 나뉘어 있습니다.

웹role="menu" 또는 <select>
더 보기 ▾이름 바꾸기
popover 속성이 생겨 위치 잡기와 닫기가 쉬워졌습니다.
iOSUIMenu
길게 누르거나 단추로 엽니다. destructive 역할이 따로 있어 빨갛게 나옵니다.
안드로이드DropdownMenu
앱바 오른쪽의 점 세 개가 표준 자리입니다 — 오버플로 메뉴라 부릅니다.

자주 생기는 사고 — 앱 쪽은 점 세 개의 자리가 정해져 있어(iOS 는 오른쪽 위, 안드로이드는 앱바 오른쪽) 사용자가 찾을 줄 압니다. 웹에는 그런 약속이 없어 어디에 두는지를 팀이 정해 두어야 하고, 한 화면에서 자리가 바뀌면 바로 '못 찾겠다'가 됩니다. 줄마다 쓰는 메뉴는 줄 끝에 고정하는 것이 가장 무난합니다.
