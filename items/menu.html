드롭다운 메뉴

Dropdown menu

드롭다운 메뉴는 항목을 누르면 무슨 일이 일어나는 목록입니다. 항목을 눌러도 값이 정해질 뿐인 셀렉트와 생김새가 같아서 가장 많이 헷갈리는 짝입니다.

2 이름같은 것을 부르는 여러 이름

한국어드롭다운 메뉴, 메뉴, 더 보기 메뉴, 케밥 메뉴
영어dropdown menu, menu, overflow menu, kebab menu
같이 쓰는 말점 세 개를 눌러 여는 메뉴는 오버플로 메뉴나 케밥 메뉴라고 부릅니다. 주 동작 옆에 화살표가 붙은 것은 스플릿 버튼(split button), 메뉴 안에서 또 열리는 메뉴는 서브메뉴입니다. 값을 고르는 목록은 셀렉트이고, 역할 이름도 메뉴와 다릅니다.
자주 잘못 부르는 이름셀렉트 — 셀렉트는 값을 고르는 부품이라서, 항목을 눌러도 값만 바뀌고 다른 일은 일어나지 않습니다.
팝오버 — 팝오버는 동작 목록에 한정되지 않고 어떤 내용이든 담습니다.
컨텍스트 메뉴 — 컨텍스트 메뉴는 단추를 누르는 대신 대상을 오른쪽 버튼으로 눌러 엽니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품들은 모양만 보고는 구별하기 어렵지만, 아래 네 가지를 따져 보면 어느 부품인지 가려낼 수 있습니다.

뒤쪽 화면을 막는가포커스를 안에 가두는가뒤쪽 화면의 스크롤은화면 어디에서 뜨는가

드롭다운 메뉴를 한 줄로 정리하면 — 누르면 일이 일어나면 메뉴이고, 값만 정해지면 셀렉트입니다. 두 부품은 마크업에 쓰는 역할 이름부터 다릅니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

단추에 aria-haspopup · aria-expanded
동작 목록이면 menu / menuitem
값 고르기면 listbox / option
단축키는 오른쪽에 적음
자리가 없으면 위로 뒤집음
닫으면 초점이 단추로 돌아옴
  1. 단추 aria-haspopup단추를 누르면 무엇이 열리는지 알립니다
  2. 동작 목록 menu/menuitem누르면 일이 일어나는 목록입니다
  3. 값 고르기 listbox/option누르면 값이 정해지는 목록입니다
  4. 단축키 오른쪽에 적음단축키를 익히게 하는 자리입니다
  5. 뒤집기 자리가 없으면 위로메뉴가 잘리지 않게 위로 엽니다
  6. 닫은 뒤 초점을 단추로초점을 단추로 돌려줍니다

메뉴와 셀렉트를 가르는 질문은 항목을 누르면 무슨 일이 일어나는가 하나입니다. '지우기'는 누르면 일이 일어나니 메뉴이고, '매주 수요일'은 값만 정해지니 셀렉트입니다. 역할 이름이 다르면 스크린 리더 사용자가 듣는 말도 달라져서, 메뉴 항목은 '메뉴 항목'으로, 셀렉트 항목은 '목록 상자 · 선택됨'으로 읽힙니다.
둘을 섞어 쓰면 키보드 동작도 어긋납니다. 메뉴는 Enter로 항목을 실행하고 닫히지만, 셀렉트는 고른 값이 표시로 남아야 합니다. 그래서 어느 쪽인지부터 정하지 않으면 두 동작 중 어느 것도 제대로 만들 수 없습니다.

6 쓸 때 / 안 쓸 때

드롭다운 메뉴를 만들 때 지킬 것

  • 누르면 일이 일어나면 메뉴로, 값만 정해지면 셀렉트로 만들기
  • 자리가 없으면 위로 뒤집기
  • 닫으면 초점을 단추로 돌려주기

드롭다운 메뉴를 만들 때 피할 것

  • 셀렉트를 role="menu"로 만들기. 스크린 리더가 고른 값을 읽어 주지 않습니다
  • 메뉴를 아래로만 열기. 화면 끝에서 메뉴가 잘립니다
  • 메뉴에 입력칸 넣기. 입력칸이 들어가면 메뉴가 아니라 팝오버입니다
  • 항목을 열다섯 개 넘게 두기. 항목을 묶거나 팔레트로 옮깁니다

드롭다운 메뉴 대신 다른 것을 써야 하는 경우 — 항목을 눌러 값만 정하는 목록이면 셀렉트를 쓰고, 동작 목록이 아닌 다른 내용까지 담으려면 팝오버가 맞습니다. 마우스 오른쪽 버튼으로 누른 자리에 띄우려면 컨텍스트 메뉴를, 화면 아래에서 올라오게 하려면 액션 시트를 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

동작 목록이면 menu 역할을, 값 고르기면 listbox 역할을 쓰고, 마크업은 이 역할에 따라 달라집니다.

<!-- 동작 목록 — 누르면 일이 일어난다 -->
<button aria-haspopup="menu" aria-expanded="false"
        aria-controls="m1">더 보기</button>
<div id="m1" role="menu" hidden>
  <button role="menuitem">이름 바꾸기</button>
  <button role="menuitem" class="danger">지우기</button>
</div>

/* 자리가 없으면 위로 — CSS 만으로도 된다 */
[popover] { position-try-fallbacks: flip-block; }

// 닫으면 초점을 단추로 돌려준다
menu.addEventListener('close', () => trigger.focus());
키와 마크업그때 일어나야 하는 일
Enter · Space · ↓단추에서 메뉴를 엽니다
↑ ↓항목 사이를 옮깁니다. 이때는 Tab이 아니라 화살표 키를 씁니다
Home · End처음 항목과 마지막 항목으로 옮깁니다
Esc메뉴를 닫고 초점을 단추로 돌려보냅니다
글자 키를 누를 때그 글자로 시작하는 항목으로 옮깁니다. 항목이 많은 긴 메뉴에서 특히 쓸모가 있습니다
확인하는 방법Tab을 눌러 초점이 메뉴 밖으로 나가지 않는지 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

권한에 따라 빼는 항목사용자 권한으로 할 수 없는 동작은 목록에서 항목을 뺍니다. 흐리게만 두면 사용자가 '왜 안 되나' 하고 묻게 됩니다.
항목을 누른 뒤의 서버 요청메뉴 항목을 누르면 보통 서버로 요청이 나갑니다. 그래서 되돌리기를 붙일지 미리 정해 둡니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 메뉴의 이름과 역할이 또렷하게 나뉘어 있습니다.

웹role="menu" 또는 <select>
더 보기 ▾이름 바꾸기
popover 속성이 생기면서 위치 잡기와 닫기를 만들기가 쉬워졌습니다.
iOSUIMenu
길게 누르거나 단추를 눌러 엽니다. destructive 역할이 따로 있어서 이 역할을 붙인 항목은 빨갛게 나옵니다.
안드로이드DropdownMenu
앱바 오른쪽의 점 세 개가 표준 자리이고, 여기서 여는 메뉴를 오버플로 메뉴라고 부릅니다.

플랫폼 차이 때문에 자주 생기는 문제 — 앱에서는 점 세 개를 두는 자리가 정해져 있어서(iOS는 오른쪽 위, 안드로이드는 앱바 오른쪽) 사용자가 어디서 찾을지 압니다. 웹에는 그런 약속이 없으므로 어디에 둘지 팀이 정해 두어야 하고, 한 화면 안에서 자리가 바뀌면 사용자는 바로 메뉴를 찾지 못합니다. 줄마다 쓰는 메뉴는 줄 끝에 고정하는 것이 가장 무난합니다.
