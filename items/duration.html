2 이름부르는 말이 여러 개다

한국어지속 시간, 길이, 재생 시간
영어duration, transition duration
같이 쓰는 말CSS 로는 transition-duration·animation-duration입니다. 시작을 늦추는 것이 딜레이(delay), 값들을 --duration-fast처럼 이름 붙여 두면 모션 토큰이라 부릅니다.
자주 잘못 부름이징 — 이징은 '어떻게', 길이는 '얼마나'입니다.
딜레이 — 늦게 시작하는 것과 오래 걸리는 것은 다릅니다. 딜레이는 차례로에 씁니다.
FPS — 초당 프레임 수는 매끄러움의 문제라 무엇을 움직이나 쪽입니다.

4 길이별로같은 움직임, 다른 길이

5 해부도부분 이름이 제일 안 알려진 지식

툴팁 · 색 바뀜 — 100ms
드롭다운 · 토글 — 150ms
모달 · 시트 열기 — 250ms
화면 전체 전환 — 350ms
400ms 넘으면 기다리게 된다
100ms 아래는 깜빡인 것처럼 보인다
  1. 아주 짧게 100ms자리가 거의 안 변하는 것 — 색, 테두리, 툴팁
  2. 짧게 150ms토글·드롭다운처럼 손가락 하나 거리
  3. 보통 250ms모달·시트. 어디서 왔는지를 보여 줄 시간이 필요하다
  4. 길게 350ms화면 전체 전환. 이보다 길면 거의 늘 과하다
  5. 상한 400ms넘으면 애니메이션이 일을 막기 시작한다
  6. 하한 100ms아래로 내리면 움직임이 안 읽힌다. 차라리 0 이 낫다

기준표의 숫자보다 중요한 것은 '몇 번 보느냐'입니다. 온보딩처럼 한 번 보는 화면은 400ms 도 괜찮지만, 목록에서 하루에 백 번 여는 메뉴가 300ms 면 하루에 30초를 기다리는 셈입니다. 자주 쓰는 것일수록 짧게 — 이 규칙이 거리·크기보다 앞섭니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 토큰 서넛으로 정해 두고 그것만 쓰기 — fast · base · slow
  • 거리가 멀거나 크면 조금 더 길게
  • 자주 보는 것은 짧게 — 하루에 백 번이면 100ms 도 길다

이럴 때는 안 쓴다

  • 화면마다 숫자를 손으로 적기 — 400, 350, 420이 뒤섞인다
  • 멋있다고 길게 — 두 번째부터는 답답하다
  • 100ms 아래 — 안 보일 바에는 0이 낫다
  • 데이터를 기다리는 시간을 애니메이션으로 때우기 → 스켈레톤

대신 이걸 — 속도를 나눠 쓰는 방식은 이징, 줄마다 늦게 들어오는 것은 차례로, 기다림을 보여 주는 것은 스피너.

8 최소 코드와 규칙이 길이의 계약서

길이도 토큰으로 두고, 모션 줄이기에서는 거의 0 으로 내립니다.

:root {
  --dur-fast: 120ms;   /* 색 · 툴팁 */
  --dur-base: 220ms;   /* 토글 · 드롭다운 */
  --dur-slow: 340ms;   /* 모달 · 화면 전환 */
}

.menu { transition: opacity var(--dur-base) var(--ease-out); }

@media (prefers-reduced-motion: reduce) {
  :root { --dur-fast: 1ms; --dur-base: 1ms; --dur-slow: 1ms; }
}
키일어나야 하는 일
단위를 빼먹지 않는다transition: transform 200은 통째로 무시된다. 200ms나 .2s
0s와 0.01ms완전히 0 이면 transitionend·animationend가 안 온다. 그 이벤트를 기다리는 코드가 멎는다
속성마다 다르게transition: transform 240ms, opacity 140ms — 투명도는 더 짧아도 된다
prefers-reduced-motion길이를 1ms 로 내리는 것이 가장 안전한 대응이다
초점이 옮겨 갈 때애니메이션이 끝나기를 기다려 초점을 옮기면 키보드 사용자가 멈춰 선다. 초점은 먼저 옮긴다
<dialog> 닫기close()는 바로 사라진다. 나가는 연출을 보려면 끝난 뒤에 호출한다

9 서버 쪽으로 치면백엔드 감각으로 번역

응답보다 애니메이션이 길면데이터가 50ms 에 와도 전환이 400ms 면 사용자는 400ms 를 기다립니다. 느린 쪽이 서버가 아닐 수 있습니다.
요청은 먼저 보낸다'애니메이션이 끝나면 부르기'로 짜면 길이만큼 늦어집니다. 요청과 연출은 같이 시작합니다.
지표에 섞인다LCP·INP 같은 숫자에 연출 시간이 들어갑니다. 느리게 나타나는 히어로는 점수를 깎습니다.
최소 표시 시간스피너가 50ms 만 보이고 사라지면 깜빡임이 됩니다. 띄웠으면 300ms 는 유지하는 쪽이 덜 어지럽습니다.
