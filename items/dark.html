다크 모드

Dark mode · dark theme

다크 모드는 같은 화면에 쓸 색 값을 두 벌 정해 두고 바꿔 쓰는 방식입니다. 어두운 쪽 색은 밝은 색을 뒤집어 얻는 것이 아니라, 어두운 바탕에 맞춰 따로 고른 색입니다.

위 카드는 토큰만 쓰고, 아래 카드는 #ffffff를 코드에 직접 적어 두었습니다. 어두운 모드로 바꾸기를 눌러 보면 아래 카드만 하얗게 남는데, 다크 모드가 깨졌다는 제보는 대부분 이렇게 색을 직접 적어 둔 자리에서 나옵니다. 모드를 바꿀 때마다 글자의 대비비도 다시 재서 보여 줍니다.

2 이름같은 것을 부르는 여러 이름

한국어다크 모드, 어두운 테마, 야간 모드
영어dark mode, dark theme, night mode
같이 쓰는 말밝은 쪽은 라이트 모드라고 부릅니다. OS 설정을 따라 바뀌는 것은 시스템 따름(system · auto), 대비를 더 높인 것은 고대비(high contrast)입니다. 바탕을 완전한 검정인 #000으로 칠하는 방식은 OLED 화면용으로 따로 블랙 모드(AMOLED · true black)라고 부릅니다.
자주 잘못 부르는 이름색 반전 — OS의 색 반전은 사진 색까지 모두 뒤집는 접근성 기능이지 다크 모드가 아닙니다.
테마 — 테마는 더 넓은 뜻의 말이고, 다크 모드는 밝은 테마와 어두운 테마 한 쌍을 가리킵니다.
야간 모드 — 이렇게 부르면 색온도를 낮춰 화면을 노랗게 만드는 나이트 시프트와 헷갈리기 쉬운데, 둘은 서로 다른 기능입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하는가몇 단으로 두면 좋은가값을 바꾸면 어디가 바뀌는가잘못 정했을 때 나타나는 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌, 고대비까지 두면 3벌화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지, 색마다 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

다크 모드를 한 줄로 정리하면 — 다크 모드는 색을 뒤집는 일이 아니라 값을 한 벌 더 만드는 일입니다. 그래서 값만 바꿔 끼워 어두운 화면으로 바꿀 수 있는 것은 처음부터 토큰을 쓴 화면뿐입니다.

4 쓰임별로 정한 두 모드의 값쓰임마다 밝은 쪽과 어두운 쪽 값을 고르는 규칙

사진은 살짝 어둡게
  1. 바탕 background가장 아래에 깔리는 색입니다. 순검정을 쓰면 흰 글자와의 대비가 너무 커서 글자가 번져 보이기 때문에 순검정은 쓰지 않습니다
  2. 제목 글 fg흰색을 그대로 쓰지 않고 한 단계 낮춘 색(#e8ebf0)을 씁니다
  3. 보조 글 fg-muted밝은 모드의 회색을 그대로 가져오면 대비가 모자라므로, 어두운 바탕에서 대비비를 다시 재야 합니다
  4. 떠 있는 면 surface · elevated어두운 쪽에서는 위에 놓인 면일수록 밝게 칠합니다. 그림자 대신 밝기 차이로 높이를 나타내는 방식입니다
  5. 강조색 accent채도를 낮추고 밝기를 올립니다. 밝은 모드의 원색을 그대로 쓰면 어두운 바탕에서 지나치게 튀어 눈이 피로합니다
  6. 사진 · 일러스트 media흰 바탕이 들어 있는 그림은 밝기를 살짝(brightness(.9)) 낮춥니다

두 모드 사이에서 방법이 뒤바뀌는 규칙이 하나 있습니다. 밝은 모드에서는 위에 놓인 면일수록 그림자가 짙어지고, 어두운 모드에서는 위에 놓인 면일수록 면 자체가 밝아집니다. 그래서 밝은 모드의 그림자 토큰만 복사해 오면 어두운 화면에서는 그림자가 거의 보이지 않아 높이 차이가 드러나지 않습니다.

6 쓸 때 / 안 쓸 때

다크 모드를 쓰는 경우

  • 읽기 앱이나 코드 편집기, 영상처럼 오래 보는 화면일 때
  • 밤에 보는 폰처럼 어두운 곳에서 쓰는 화면일 때
  • 색 토큰을 이미 쓰고 있을 때. 토큰이 있으면 값만 한 벌 더 만들면 되므로 비용이 적게 듭니다
  • OS 설정을 따라갈 수 있을 때(prefers-color-scheme)

다크 모드를 쓰지 않는 경우

  • 색 값이 화면 곳곳에 직접 적혀 있을 때. 이때는 다크 모드보다 토큰으로 바꾸는 일을 먼저 합니다
  • 사진과 색을 보여 주는 것이 목적인 화면일 때. 예를 들어 쇼핑몰 상품 사진은 흰 바탕에서 더 잘 보입니다
  • 인쇄용 화면이나 문서일 때
  • '요즘 다들 하니까'라는 이유뿐일 때. 두 벌을 계속 관리할 사람이 없으면 한쪽 값이 고쳐지지 않은 채 남아 화면이 어긋납니다

다크 모드와 함께 보면 좋은 항목 — 다크 모드를 만들기 전에 색을 쓰임별로 정리하는 방법은 색 토큰 항목에서 다루고, 어두운 화면에서 높이를 나타내는 방법은 고도 항목에서 이어서 설명합니다.

8 최소 코드와 지킬 규칙두 벌의 값을 바꿔 끼우는 방법

기본으로는 OS 설정을 따르고, 사용자가 직접 고른 값이 있으면 그 값을 우선합니다. 마지막으로 페이지를 처음 그릴 때 흰 화면이 잠깐 보이는 깜빡임을 막아야 합니다.

/* 1) OS 설정을 기본으로 따른다 */
:root { color-scheme: light dark; --bg: #fff; --fg: #14161a; }
@media (prefers-color-scheme: dark) {
  :root { --bg: #15181e; --fg: #e8ebf0; }
}

/* 2) 사용자가 고른 값이 있으면 그 값을 우선한다 */
:root[data-theme="dark"] { --bg: #15181e; --fg: #e8ebf0; }
:root[data-theme="light"] { --bg: #fff; --fg: #14161a; }

// 3) <head> 안에서 먼저 적용한다. 늦으면 흰 화면이 한 번 번쩍인다
document.documentElement.dataset.theme =
  localStorage.getItem('theme') ?? '';
지킬 규칙지키는 방법과 이유
color-scheme 속성 적기스크롤바나 입력창처럼 브라우저가 그리는 부품까지 어두운 색으로 바뀌게 합니다. 이 속성 하나만 적어도 해결되는 제보가 많습니다
OS 설정을 기본으로 따르기prefers-color-scheme을 기본으로 따르고, 사용자가 고른 값이 있으면 그 위에 덮어씁니다
본문을 그리기 전에 모드 적용하기저장된 설정을 <head>에서 읽어 바로 적용합니다. 본문을 그린 뒤에 적용하면 흰 화면이 한 번 번쩍입니다
두 모드에서 대비비를 따로 재기밝은 쪽에서 대비비 기준을 통과한 회색이 어두운 쪽에서도 통과한다는 보장은 없으므로 두 벌 모두 잽니다
사진과 아이콘을 어두운 쪽에 맞추기흰 바탕이 들어 있는 그림이나 로고는 어두운 쪽 전용 그림을 따로 준비하거나 밝기를 낮춥니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

모드 설정을 저장하는 곳모드 설정은 기기마다 다를 수 있어서 기기에 저장하는 것이 기본입니다. 계정에 저장하면 기기를 바꿔도 설정이 따라오지만, 밤에만 어둡게 쓰는 사람에게는 오히려 불편할 수 있습니다.
서버 렌더링에서 생기는 번쩍임서버는 사용자의 OS 설정을 알 수 없기 때문에 첫 HTML은 늘 한쪽 모드의 색으로 만들어집니다. 브라우저는 이 HTML을 받은 뒤 설정에 맞게 한 번 고쳐 그리는데, 고쳐 그리기 전 잠깐 보이는 화면이 번쩍임입니다.
메일과 PDF처럼 밖으로 보내는 문서메일 클라이언트는 다크 모드에서 보낸 쪽이 정한 색을 자기 규칙대로 바꿉니다. 그래서 중요한 내용은 색에만 기대지 않도록 만듭니다.
모드마다 이미지를 따로 보내기로고처럼 모드마다 달라야 하는 그림은 <picture>로 두 벌을 보내거나 SVG 안에서 currentColor를 씁니다.
