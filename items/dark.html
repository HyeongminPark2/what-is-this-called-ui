다크 모드

Dark mode · dark theme

같은 화면을 위한 두 벌의 값. 밝은 색을 뒤집는 것이 아니라, 어두운 바탕에 맞춰 따로 고른 색입니다.

2 이름부르는 말이 여러 개다

한국어다크 모드, 어두운 테마, 야간 모드
영어dark mode, dark theme, night mode
같이 쓰는 말밝은 쪽을 라이트 모드라 부릅니다. OS 설정을 따라가는 것은 시스템 따름(system · auto), 대비를 더 높인 것은 고대비(high contrast)입니다. 검정을 완전한 #000으로 쓰는 것은 OLED 전용인 블랙 모드(AMOLED · true black)로 따로 부릅니다.
자주 잘못 부름색 반전 — OS 의 색 반전은 사진까지 뒤집는 접근성 기능이고 다크 모드가 아닙니다.
테마 — 테마는 더 넓은 말입니다. 다크 모드는 테마 한 쌍을 가리킵니다.
야간 모드 — 화면을 노랗게 만드는 나이트 시프트(색온도)와는 다른 것입니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다

한 줄로 — 다크 모드는 색을 뒤집는 일이 아니라 값을 한 벌 더 만드는 일입니다. 뒤집어서 되는 화면은 처음부터 토큰을 쓴 화면뿐입니다.

  1. 바탕 background가장 아래. 순검정이 아니다 — 흰 글과의 대비가 너무 세서 글자가 번져 보인다
  2. 제목 글 fg흰색을 그대로 쓰지 않고 한 단계 낮춘다(#e8ebf0)
  3. 보조 글 fg-muted밝은 모드의 회색을 그대로 가져오면 대비가 모자란다. 다시 재야 한다
  4. 떠 있는 면 surface · elevated어두운 쪽에서는 위로 올라갈수록 밝아진다. 그림자 대신 밝기가 높이를 말한다
  5. 강조색 accent채도를 낮추고 밝기를 올린다. 밝은 모드의 원색은 어두운 바탕에서 눈을 찌른다
  6. 사진 · 일러스트 media흰 바탕이 든 그림은 밝기를 살짝(brightness(.9)) 낮춘다

방향이 뒤집히는 규칙이 하나 있습니다. 밝은 모드에서는 위로 올라갈수록 그림자가 짙어지고, 어두운 모드에서는 위로 올라갈수록 면이 밝아집니다. 그림자 토큰만 복사해 오면 어두운 화면에서는 아무 일도 일어나지 않습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 오래 보는 화면 — 읽기 앱, 코드 편집기, 영상
  • 어두운 데서 쓰는 화면 — 밤에 보는 폰
  • 토큰을 이미 쓰고 있을 때. 그때만 비용이 싸집니다
  • OS 설정을 따라갈 수 있을 때(prefers-color-scheme)

이럴 때는 안 쓴다

  • 색이 화면 곳곳에 직접 박혀 있을 때 — 먼저 토큰으로 바꾸는 것이 순서입니다
  • 사진과 색이 주인공인 화면 — 쇼핑몰 상품 사진은 흰 바탕에서 더 잘 보입니다
  • 인쇄용 화면 · 문서
  • '요즘 다 하니까' — 두 벌을 끝까지 관리할 사람이 없으면 한쪽이 반드시 썩습니다

대신 이걸 — 색을 쓰임으로 먼저 정리하는 것이 색 토큰이고, 어두운 쪽의 높이 표현은 고도에서 이어집니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙두 벌을 어떻게 갈아 끼우나

OS 설정을 기본으로 따르고, 사용자가 고른 값이 있으면 그것을 우선합니다. 깜빡임을 막는 것이 마지막 한 수입니다.

/* 1) OS 설정을 기본으로 따른다 */
:root { color-scheme: light dark; --bg: #fff; --fg: #14161a; }
@media (prefers-color-scheme: dark) {
  :root { --bg: #15181e; --fg: #e8ebf0; }
}

/* 2) 사용자가 고른 값이 있으면 그것이 이긴다 */
:root[data-theme="dark"] { --bg: #15181e; --fg: #e8ebf0; }
:root[data-theme="light"] { --bg: #fff; --fg: #14161a; }

// 3) <head> 안에서 먼저 칠한다 — 안 그러면 흰 화면이 한 번 번쩍인다
document.documentElement.dataset.theme =
  localStorage.getItem('theme') ?? '';
규칙지켜야 하는 것
color-scheme를 적는다스크롤바·입력창 같은 브라우저가 그리는 부품까지 따라오게 한다. 이거 하나로 해결되는 제보가 많다
OS 를 기본으로prefers-color-scheme이 먼저고, 사용자가 고른 값은 그 위에 덮는다
첫 칠을 먼저저장된 설정을 <head>에서 읽어 적용한다. 나중에 하면 흰 화면이 번쩍인다
대비를 다시 잰다밝은 쪽에서 통과한 회색이 어두운 쪽에서도 통과하지는 않는다. 두 벌 모두 잰다
사진과 아이콘흰 바탕이 든 그림·로고는 어두운 쪽 전용을 따로 준비하거나 밝기를 낮춘다

9 서버 쪽으로 치면백엔드 감각으로 번역

설정은 어디에 두나기기마다 다를 수 있어 로컬에 두는 것이 기본입니다. 계정에 저장하면 기기를 옮겨도 따라오지만, 밤에만 어둡게 쓰는 사람에게는 거슬립니다.
서버 렌더링서버는 사용자의 OS 설정을 모릅니다. 그래서 첫 HTML 은 늘 한쪽으로 칠해져 나오고, 브라우저에서 한 번 고쳐 그립니다 — 이 틈이 번쩍임입니다.
메일 · PDF 처럼 밖으로 나가는 것메일 클라이언트는 다크 모드에서 색을 제멋대로 바꿉니다. 중요한 글자는 색에만 기대지 않게 만듭니다.
이미지 두 벌로고처럼 모드마다 달라야 하는 그림은 <picture>로 두 벌을 보내거나 SVG 안에서 currentColor를 씁니다.
