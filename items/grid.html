그리드

CSS Grid · grid layout

판을 먼저 그리고 거기에 넣는 방법. 플렉스가 '줄 세우기'라면 그리드는 '칸 나누기'입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

칸이 알아서 접히기로 두고 브라우저 폭을 바꿔 보세요(위의 폭 토글). auto-fit + minmax는 미디어 쿼리 없이 열 수를 줄입니다 — 요즘 카드 그리드가 거의 다 이것입니다.
긴 글 넣기를 켜면 고르던 칸이 어긋납니다. 1fr이 사실 minmax(auto, 1fr)이라 그 칸이 글보다 작아지지 못하기 때문입니다. minmax(0, 1fr)로 고치면 그제서야 줄어듭니다.

2 이름부르는 말이 여러 개다

한국어그리드, 격자, 레이아웃 그리드
영어CSS Grid, grid layout, track, gutter
같이 쓰는 말열과 행 하나하나를 트랙(track), 칸 사이의 홈을 거터(gutter · gap)라 합니다. fr은 남은 자리의 몫(fraction), auto-fit/auto-fill은 열 수를 브라우저가 정하게 하는 말입니다. 이름을 붙인 칸 짜임은 그리드 템플릿 영역입니다.
자주 잘못 부름간격 그리드 — 여백 단위(8px 격자)와는 다른 것입니다. 이쪽은 열 나누기입니다.
테이블 — 표는 데이터이고 그리드는 배치입니다. 표를 배치에 쓰면 스크린 리더가 '표'라고 읽습니다.
플렉스 — 플렉스는 한 방향, 그리드는 두 방향. 줄끼리 맞아야 하면 그리드입니다.

한 줄로 — 그리드는 판을 먼저 정하는 것입니다. 자식이 몇 개든 판은 그대로라, 줄과 열이 서로 맞습니다.

4 짜는 법같은 자식, 다른 판

5 해부도부분 이름이 제일 안 알려진 지식

1 2 3
grid-template-columns: 1fr 1fr 1fr
gap: 8px (거터)
repeat(auto-fit, minmax(150px, 1fr))
minmax(0, 1fr) — 1fr 의 함정을 푸는 값
grid-column: span 2 (한 칸이 두 칸을 먹기)
  1. 그리드 컨테이너 grid containerdisplay: grid를 준 부모. 자식은 순서대로 칸에 들어간다
  2. 트랙 track · template열(과 행)의 정의. 1fr은 남은 자리를 한 몫
  3. 거터 gap · gutter칸 사이의 홈. column-gap·row-gap을 따로 줄 수 있다
  4. 알아서 접기 auto-fit + minmax'최소 150px, 안 되면 열 수를 줄여라'. 미디어 쿼리 없이 반응한다
  5. minmax(0, 1fr) minmax1fr의 숨은 최소값(auto)을 0 으로 바꾼다. 칸이 글보다 작아질 수 있게
  6. 칸 합치기 grid-column: span한 자식이 여러 칸을 먹는다. 플렉스로는 못 하는 일

1fr은 '남은 자리를 한 몫'이지만 숨은 조건이 하나 있습니다 — 사실은 minmax(auto, 1fr)이고, auto 는 '내용만큼'입니다. 그래서 긴 글이 든 칸은 줄어들기를 거부하고 옆 칸의 자리를 빼앗습니다. 글이 더 길면 판이 통째로 터지고 가로 스크롤이 생깁니다. minmax(0, 1fr)이 그 숨은 최소값을 0 으로 바꿔 줍니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 줄과 열이 서로 맞아야 할 때 — 카드 그리드, 표 같은 배치
  • 화면 전체의 짜임 — 사이드바 + 본문 + 꼬리말
  • 미디어 쿼리 없이 접히게 하고 싶을 때 — auto-fit minmax
  • 한 칸이 여러 칸을 먹어야 할 때

이럴 때는 안 쓴다

  • 한 줄에 늘어놓기만 하면 될 때 → 플렉스가 짧습니다
  • 데이터 표 → <table>을 씁니다. 그리드로 만들면 행·열이 안 읽힙니다
  • 자식 개수가 매번 달라 판이 무너질 때 — auto-fit으로 바꿉니다

대신 이걸 — 한 방향이면 플렉스, 데이터면 데이터 테이블(10부), 가운데만 놓으면 가운데 맞추기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 판의 계약서

외울 것은 사실상 두 줄입니다 — 카드 그리드 한 줄과 화면 짜임 한 줄.

/* 카드 그리드 — 미디어 쿼리 없이 접힌다 */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}

/* 화면 짜임 — 사이드바 + 본문 */
.app {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
}                       /* ↑ 0 이라야 긴 글에 본문이 터지지 않는다 */

/* 한 칸이 두 칸을 먹기 */
.cards > .featured { grid-column: span 2; }
규칙지켜야 하는 것
minmax(0, 1fr)본문처럼 긴 글이 들어올 칸에는 거의 늘 필요하다
auto-fit vs auto-fillauto-fit 은 빈 트랙을 접고, auto-fill 은 빈 칸을 남긴다. 보통 auto-fit
gap만 쓴다자식 마진으로 간격을 만들면 가장자리에도 생긴다
auto 트랙auto 1fr auto는 '앞뒤는 내용만큼, 가운데만 유동'. 리스트 한 줄의 정석
배치에 <table>을 쓰지 않는다스크린 리더가 '표, 3열 5행'이라고 읽는다
자식 순서 = 읽는 순서grid-area로 눈에 보이는 자리를 바꿔도 키보드 순서는 안 바뀐다

9 서버 쪽으로 치면백엔드 감각으로 번역

그리드 = 판이 먼저자식이 몇 개 오든 판은 그대로입니다. 그래서 응답 개수가 들쭉날쭉해도 레이아웃이 안 무너집니다 — 플렉스와 가장 큰 차이입니다.
빈 칸 처리마지막 줄이 덜 찼을 때 어떻게 보일지 정해 둬야 합니다. auto-fit이면 남은 칸이 늘어나고, auto-fill이면 빈 자리가 남습니다.
페이지 크기한 번에 12개를 주면 3열·4열·6열 어디서도 줄이 딱 맞습니다. 12의 약수로 페이지 크기를 잡는 관례가 여기서 나왔습니다.
이미지 비율칸 크기가 바뀌어도 카드 높이가 흔들리지 않으려면 aspect-ratio를 못 박아야 합니다. 서버가 원본 비율을 내려주면 더 정확해집니다.
