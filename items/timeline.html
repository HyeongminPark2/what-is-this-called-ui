Timeline · activity feed · stepper

사건들을 일어난 순서대로 꿴 줄. 배송 추적, 결재 단계, 활동 기록이 다 같은 모양입니다.

2 이름부르는 말이 여러 개다

한국어타임라인, 진행 단계, 이력, 활동 기록, 배송 추적
영어timeline, activity feed, stepper, progress tracker, audit log
같이 쓰는 말세로로 내려가는 선을 레일(rail · line · connector), 사건마다 찍히는 동그라미를 노드(node · dot · marker)라 합니다. 단계가 정해져 있고 끝이 있으면 스테퍼(stepper), 끝없이 쌓이는 기록이면 활동 피드(activity feed)라 따로 부릅니다.
자주 잘못 부름스테퍼 — 스테퍼는 끝이 정해진 단계이고(결제 1·2·3단계), 타임라인은 끝이 없을 수도 있습니다.
프로그레스 바 — 프로그레스는 얼마나 왔는지를 한 줄로 말하고, 타임라인은 무엇이 있었는지를 말합니다.
리스트 — 리스트는 순서가 바뀌어도 됩니다. 타임라인은 순서가 뜻입니다.

3 가르는 기준형제들과 비교하는 네 축

표시 부품은 '보여 주기만 한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로말줄임한다
아바타사람·조직 하나안 눌린다겹쳐 쌓는다고정 — 넘치면 +N
배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+
칩한 낱말눌린다가로로 줄바꿈말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)
타임라인사건들의 순서항목만세로로 꿴다아래로 길어진다
별점점수 하나읽기용은 안 눌린다줄 안에 들어간다고정 — 별 다섯

한 줄로 — 타임라인은 순서가 내용인 목록입니다. 순서를 바꿔도 말이 되면 그건 그냥 리스트입니다.

담당자 검토
홍길동이 보고 있습니다
  1. 타임라인 timeline사건들을 담는 세로 목록. <ol>이라야 '순서가 있다'가 읽힌다
  2. 시각 timestamp왼쪽에 가지런히. 본문에 섞으면 훑어 내려갈 때 눈이 걸린다
  3. 레일 rail · connector점들을 잇는 선. 첫 점 위와 마지막 점 아래는 잘라 둬야 끝이 또렷하다
  4. 점 node · dot사건 하나. 지금은 테를 둘러 키우고, 멈춘 자리는 빨갛게
  5. 제목 title무슨 일이 있었는지. 한 줄로 끝낸다
  6. 본문 detail누가·왜. 멈춘 이유도 여기에 적는다

레일은 점을 잇는 선이지 테두리가 아닙니다. 그래서 첫 점 위쪽과 마지막 점 아래쪽은 잘라 내야 '여기서 시작해서 여기서 끝난다'가 보입니다. 선을 끝까지 그어 두면 더 있을 것 같은 인상을 줘서, 실제로 "다음 단계가 안 보여요"라는 제보로 돌아옵니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 순서가 곧 뜻일 때 — 배송, 결재, 상태 변화
  • '지금 어디인지'가 가장 궁금할 때
  • 누가 언제 무엇을 했는지 되짚어야 할 때 — 감사 기록

이럴 때는 안 쓴다

  • 순서가 상관없는 목록 → 리스트 아이템
  • 단계가 둘뿐일 때 — 선을 그릴 만한 일이 아닙니다
  • 진행률만 알면 될 때 → 프로그레스 바 한 줄이 낫습니다
  • 수백 건을 한 번에 — 묶어서 접거나 날짜로 나눕니다

대신 이걸 — 끝이 정해진 단계면 스테퍼(7부), 진행률이면 프로그레스 바, 순서가 상관없으면 리스트 아이템.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙이 부품의 계약서

순서가 뜻이므로 <ol>을 씁니다. 지금 단계에는 aria-current="step" 하나면 충분합니다.

<ol class="tl">
  <li>
    <time datetime="2026-11-07T14:02">11월 7일 14:02</time>
    <span class="tl__dot" aria-hidden="true"></span>
    <span><b>정산 요청</b><span>모란상회가 올렸습니다</span></span>
  </li>
  <li aria-current="step">…</li>   <!-- 지금 단계 -->
</ol>

/* 레일은 점을 잇는 선 — 첫 점 위와 마지막 점 아래를 자른다 */
.tl__rail::before { content: ""; position: absolute; top: 0; bottom: 0; width: 2px; }
li:first-child .tl__rail::before { top: 7px; }
li:last-child  .tl__rail::before { bottom: auto; height: 7px; }
규칙지켜야 하는 것
<ol>로 감싼다순서가 뜻이다. <ul>이면 '순서 없는 목록'으로 읽힌다
aria-current="step"지금 단계 하나에만. 둘이면 어디인지 알 수 없다
<time datetime>기계가 읽을 수 있는 시각을 따로 적는다. '방금'만 있으면 언제인지 모른다
점은 숨긴다aria-hidden — 동그라미는 소리로 읽을 것이 없다
멈춘 자리에 이유를맨 아래 따로 적지 말고 그 항목 안에 쓴다
레일 끝을 자른다첫 점 위와 마지막 점 아래를 남기면 더 있을 것처럼 보인다

9 서버 쪽으로 치면백엔드 감각으로 번역

타임라인 = 이벤트 로그상태를 status 한 칸으로 덮어쓰면 지나온 길이 사라집니다. 상태가 바뀔 때마다 한 줄씩 쌓는 표가 따로 있어야 타임라인을 그릴 수 있습니다.
시각은 UTC 로저장은 UTC, 보여 줄 때 사용자 시간대로 바꿉니다. 섞이면 같은 사건이 두 시간 다르게 보입니다.
'방금'은 화면에서서버가 '2시간 전'을 보내면 화면을 오래 켜 둔 사람에게는 틀린 말이 됩니다. 절대 시각을 보내고 화면에서 바꿔 적습니다.
몇 개까지활동 기록은 끝없이 쌓입니다. 최근 20건만 주고 더 보기로 이어 받습니다 — 무한 스크롤과 같은 문제입니다.
누가 했는지시스템이 한 일과 사람이 한 일을 구별해 두면 '자동 검증'과 '담당자 검토'를 다르게 그릴 수 있습니다.
