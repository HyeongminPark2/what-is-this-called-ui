슬라이더

Slider · Range

정해진 범위 안에서 손잡이를 끌어 값을 고르는 막대. 대략 맞추기는 빠르고, 정확히 맞추기는 어렵습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

손잡이를 잡고 ←→를 눌러 보세요. 한 칸씩 움직이고 Home·End로 양 끝까지 갑니다.
첫 칸에 123,456을 적어 보세요. 눈금(step)이 1만 원이라 120,000으로 붙습니다 — 눈금을 정하는 순간 그 사이 값은 고를 수 없게 됩니다.

2 이름부르는 말이 여러 개다

한국어슬라이더, 범위 입력, 레인지
영어slider, range input
같이 쓰는 말잡고 끄는 동그라미가 손잡이(thumb), 바탕이 트랙, 지나온 쪽이 채움(fill), 멈추는 간격이 눈금(step), 양 끝에 적는 글자가 눈금 표시입니다. 손잡이가 둘이면 범위 슬라이더.
자주 잘못 부름프로그레스 바 — 생김새는 닮았지만 프로그레스는 못 만집니다. 읽기 전용입니다.
스위치 — 손잡이가 움직인다고 슬라이더가 아닙니다. 스위치는 켜고 끌 뿐입니다.
캐러셀 — 미는 동작이 닮았지만 캐러셀은 내용을 넘깁니다.

3 가르는 기준형제들과 비교하는 네 축

조작 부품은 모두 '값을 받는다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

고르는 개수선택지가 보이나바로 적용되나타이핑

한 줄로 — 슬라이더는 대략 맞추기에 좋고 정확히 맞추기에 나쁩니다. 정확한 값이 필요하면 숫자 칸을 옆에 같이 둡니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

이 금액을 넘으면 알림 ₩300,000
050만100만
  1. 라벨 label무엇을 정하는 값인지. 단위까지 적는다
  2. 지금 값 value숫자로 보여 준다. 이게 없으면 슬라이더는 쓸 수 없는 부품이 된다
  3. 트랙 track전체 범위. 양 끝이 어디인지 보인다
  4. 채움 fill지나온 쪽. 지금 어디쯤인지 한눈에 알린다
  5. 손잡이 thumb · knob잡는 곳. 손가락이 닿으려면 지름 20px 이상이 필요하다
  6. 눈금 표시 tick labels양 끝과 가운데만 적어도 충분하다. 다 적으면 어지럽다

그림에 안 보이는 것이 눈금(step)입니다. 1만 원 단위로 정하면 123,456은 120,000으로 붙습니다 — 편의이기도 하고 제약이기도 합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 대략 맞추면 되는 값 — 밝기, 소리, 글자 크기
  • 범위가 눈에 보여야 할 때 — 최소와 최대가 얼마인지
  • 값을 바꾸면 결과가 바로 보일 때 — 밝기를 끌면서 화면이 밝아질 때

이럴 때는 안 쓴다

  • 정확한 값이 필요할 때 — 숫자 칸을 옆에 같이 두지 않으면 못 맞춥니다
  • 범위가 아주 넓을 때 (1~10,000) — 한 픽셀이 수십 단위가 됩니다
  • 칸이 둘셋뿐일 때 → 세그먼티드나 라디오
  • 값이 숫자로 안 보일 때 — 지금 얼마인지 모르면 쓸 수 없습니다

대신 이걸 — 정확한 값이면 텍스트 필드(숫자), 칸이 셋이면 세그먼티드, 읽기만 하면 프로그레스 바.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

<input type="range">를 쓰면 키보드 조작과 스크린 리더가 공짜입니다. 직접 그리면 그걸 전부 다시 만들어야 합니다.

<label for="amt">이 금액을 넘으면 알림</label>
<input type="range" id="amt"
       min="0" max="1000000" step="10000" value="300000">
<input inputmode="numeric" aria-label="금액 직접 입력">

// 막대와 숫자 칸을 양쪽으로 잇는다
range.addEventListener('input', () => num.value = fmt(range.value));
num.addEventListener('input', () => range.value = clamp(parse(num.value)));

/* 색만 바꾼다 */
input[type=range] { accent-color: var(--accent); }
키일어나야 하는 일
←→눈금 한 칸씩 움직인다
PageUpPageDown크게 움직인다. 범위가 넓을 때 꼭 필요하다
HomeEnd최소·최대로 바로 간다
스크린 리더aria-valuenow와 함께 aria-valuetext로 사람이 읽을 값을 준다 — '300000'이 아니라 '30만 원'
손가락손잡이는 20px 이상. 트랙만 얇게 그리고 과녁은 크게 둔다

9 서버 쪽으로 치면백엔드 감각으로 번역

눈금 = 양자화step으로 값을 가능한 집합으로 줄입니다. 저장할 값의 정밀도와 맞춰야 합니다 — 화면은 1만 단위인데 DB 가 원 단위면 섞인 값이 들어옵니다.
끄는 동안 보낼 것인가input은 끄는 내내, change는 손을 뗄 때 한 번 납니다. 서버에 보낸다면 change에서 보내거나 디바운스합니다.
범위 슬라이더 = 구간최소·최대 둘을 보내고, 서버는 min ≤ max를 다시 검증해야 합니다. 화면에서 막아도 요청은 조작될 수 있습니다.
기본값이 곧 질의슬라이더 기본값이 첫 화면의 조건을 정합니다. 범위를 넓게 잡아 두면 첫 질의가 가장 무거워집니다.
