터치 타깃

Touch target

누를 수 있는 넓이. 보이는 크기와 같을 필요가 없고, 대개 같으면 안 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

점선 원이 손가락 끝이 닿는 넓이(약 9mm ≈ 44px)입니다. 네모가 원보다 작으면 옆을 누르게 됩니다.
보이는 크기는 두고 누를 넓이만 키우기를 켜 보세요 — 아이콘은 그대로 24px 인데 눌리는 범위만 44px 이 됩니다. 디자인을 안 바꾸고 고치는 방법입니다. 아래쪽에서는 크기만큼 간격도 중요하다는 것을 볼 수 있습니다.

2 이름부르는 말이 여러 개다

한국어터치 타깃, 누를 수 있는 넓이, 터치 영역
영어touch target, hit area, tap target, hit slop
같이 쓰는 말눌리는 범위를 보이는 것보다 넓히는 것을 히트 슬롭(hit slop)·히트 영역 확장이라 합니다. WCAG 에서는 타깃 크기(target size) 기준으로 나오고, iOS 는 44pt, 안드로이드는 48dp를 최소로 적어 두었습니다.
자주 잘못 부름버튼 크기 — 버튼이 커 보일 필요는 없습니다. 눌리는 넓이만 넓으면 됩니다.
패딩 — 패딩은 수단 가운데 하나입니다. ::before로 넓히는 방법도 있습니다.
아이콘 크기 — 아이콘은 보이는 크기입니다. 둘을 같은 값으로 묶으면 화면이 둔해집니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다
HIG와 Material의 차이OS 의 말투각자 다르다웹 관례어느 쪽에서도 어색하다

한 줄로 — 보이는 크기와 눌리는 넓이를 따로 두세요. 아이콘 24px, 눌리는 넓이 44px — 이 한 줄이 거의 모든 경우를 해결합니다.

4 크기별로원 안에 네모가 들어가나

5 해부도부분 이름이 제일 안 알려진 지식

보이는 아이콘 — 24px 여도 된다
눌리는 넓이 — 44 × 44px 이상
가운데 맞춤 — 아이콘은 그대로 두고 여백만 키운다
이웃과의 간격 8px — 원이 안 겹치게
화면 가장자리 16px — 쓸기 제스처와 안 다투게
손가락 끝 약 9mm — 화면에서 44px 남짓
  1. 보이는 것 아이콘 24px작아도 된다. 작아야 화면이 깔끔하다
  2. 눌리는 넓이 44 × 44px투명한 여백으로 넓힌다. 눈에는 안 보인다
  3. 가운데 맞춤 place-items: center아이콘을 키우지 말고 상자를 키운다
  4. 이웃과의 간격 8px 이상붙여 두면 가운데를 누를 때 어느 쪽인지 모른다
  5. 가장자리 16px 안쪽너무 붙으면 OS 의 쓸기 제스처와 다툰다
  6. 기준 약 9mm손가락 끝의 평균. 화면에서 44~48px 남짓이다

WCAG 2.2 의 기준(24 × 24px)과 OS 기준(44~48px)이 다릅니다. 24px 은 '법적 최소'이고 48px 은 '쓸 만한 크기'입니다. 게다가 WCAG 쪽은 간격으로 대신할 수 있다고 적어 두었습니다 — 24px 짜리라도 둘레에 충분한 빈틈이 있으면 통과입니다. 실무에서는 44px 을 기본으로 잡고 빽빽한 표 안의 아이콘만 예외로 두는 쪽이 간단합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 손가락으로 누르는 모든 것 — 아이콘 버튼, 닫기 ✕, 체크박스
  • 표나 목록 안의 작은 버튼 — 가장 자주 빠진다
  • 줄 전체를 누르게 할 수 있으면 줄을 통째로

이럴 때는 안 쓴다

  • 아이콘을 키워서 해결하기 — 화면이 둔해진다
  • 44px 짜리를 딱 붙여 늘어놓기
  • 화면 맨 가장자리에 붙이기 — 쓸기 제스처와 다툰다
  • PC 에서만 재 보기 — 마우스는 1px 도 정확히 누른다

대신 이걸 — 누를 것이 많으면 리스트 아이템처럼 줄 전체를 누르게, 숨겨도 되면 메뉴로 모으기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 넓이의 계약서

보이는 크기는 두고 상자만 키웁니다.

.icon-btn {
  min-width: 44px; min-height: 44px;   /* 눌리는 넓이 */
  display: grid; place-items: center;
  padding: 0; border: 0; background: none;
}
.icon-btn svg { width: 24px; height: 24px; }   /* 보이는 크기 */

/* 배치를 못 건드릴 때 — 범위만 넓힌다 */
.tight-btn { position: relative; }
.tight-btn::before { content: ""; position: absolute; inset: -10px; }

/* 손가락 기기에서만 키우고 싶다면 */
@media (pointer: coarse) { .icon-btn { min-width: 48px; min-height: 48px; } }
키일어나야 하는 일
min-width·min-heightwidth로 박으면 글자가 길어질 때 넘친다
<button>에 aria-label아이콘만 있으면 이름이 없다. 이름 붙이기로
초점 테두리도 같이 커진다상자를 키우면 포커스 테두리가 아이콘에서 멀어진다. outline-offset으로 당긴다
@media (pointer: coarse)손가락 기기에서만 키울 수 있다. PC 는 작게 둬도 된다
::before로 넓힐 때부모에 position: relative가 있어야 하고, overflow:hidden이 걸리면 잘린다
Tab 순서범위를 넓혀도 순서는 그대로다. 눈에 보이는 차례와 맞는지 따로 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

잘못 눌린 요청작은 버튼은 옆 것이 눌립니다. '지우려다 보냈다' 같은 민원은 서버 로그로는 정상 요청으로 보입니다.
되돌릴 길실수로 눌리기 쉬운 동작일수록 되돌리기가 필요합니다.
두 번 눌림손가락은 미끄러져 두 번 눌리기 쉽습니다. 같은 요청을 한 번만 처리하는 장치가 필요합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

숫자만 다릅니다 — 44 · 48 · 24.

웹WCAG 2.2
✕
24 보이고 44 눌린다
최소 24 × 24px이고 간격으로 대신할 수 있습니다. 실무 기준으로는 느슨해 44px 을 쓰는 편이 많습니다.
iOS44 × 44pt
HIG 에 44 × 44pt로 못 박혀 있습니다. 시스템 부품은 처음부터 그 크기입니다.
안드로이드48 × 48dp
48 × 48dp. 아이콘은 24dp 로 두고 둘레에 12dp 씩 여백을 주라고 그림까지 그려 두었습니다.

자주 생기는 사고 — "폰에서 버튼이 잘 안 눌려요"의 거의 전부가 이것입니다. 그런데 디자인 시안에서는 안 보입니다 — 눌리는 넓이는 투명하기 때문입니다. 시안을 받을 때 '이 아이콘의 눌리는 넓이는 몇 px 입니까'를 한 번 묻고, 44px 을 기본값으로 적어 두면 나중에 다시 안 돌아옵니다.
