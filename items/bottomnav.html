바텀 탭바

Tab bar · Bottom navigation

폰 화면 아래에 늘 붙어 있는 메뉴. 앱 전체를 서너 갈래로 나누고, 엄지가 닿는 자리에 둡니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

거래를 여러 번 눌러 보세요. 처음 누르면 그 화면으로 가고, 이미 그 화면이면 맨 위로 올라갑니다 — 탭바의 숨은 약속입니다. 탭마다 스크롤 위치를 따로 기억하는 것도 확인해 보세요.
칸은 3~5개까지입니다. 그 이상은 손가락이 닿기 어렵고 글자가 잘립니다.

2 이름부르는 말이 여러 개다

한국어바텀 탭바, 하단 탭, 탭바, 하단 내비게이션
영어tab bar (iOS), bottom navigation (Android), bottom nav
같이 쓰는 말칸 하나가 탭, 빨간 숫자가 배지, 넓은 화면에서 옆으로 서는 것을 레일이라 합니다.
자주 잘못 부름탭 — 이름이 같지만 화면 안의 탭은 한 화면의 다른 면이고, 탭바는 앱 전체를 오갑니다.
푸터 — 푸터는 스크롤 끝에 나오는 정보 영역입니다. 탭바는 늘 떠 있습니다.
툴바 — 툴바는 동작을 모읍니다. 탭바는 길을 나눕니다.

3 가르는 기준형제들과 비교하는 네 축

길 안내 부품은 모두 '누르면 어디론가 간다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음

한 줄로 — 바텀 탭바는 앱을 서너 갈래로 나눕니다. 갈래가 여섯을 넘으면 더 쪼갤 게 아니라 구조를 다시 짤 때입니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

3 거래 정산
  1. 탭바 tab bar화면 아래에 고정. 스크롤해도 남는다
  2. 탭 하나 tab과녁은 48px 이상. 칸을 균등하게 나눈다
  3. 아이콘 icon골랐을 때 채운 모양, 아닐 때 선 모양으로 가르는 것이 관례
  4. 배지 badge처리할 것이 몇 건인지. 아이콘 오른쪽 위
  5. 이름 label아이콘만 두지 않는다. 아이콘만으로는 뜻이 안 전해진다
  6. 세이프 에어리어 safe area inset홈 인디케이터에 가리지 않게 아래에 더 두는 빈 자리

탭바의 숨은 규칙 두 가지 — 탭마다 자기 화면 스택과 스크롤 위치를 기억하고, 같은 탭을 다시 누르면 맨 위로 갑니다. 둘 다 그림에는 안 보이지만 없으면 바로 불편합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 앱의 주 갈래가 3~5개일 때
  • 갈래 사이를 자주 오갈 때 — 한 번에 닿습니다
  • 폰에서 엄지로 쓰는 화면

이럴 때는 안 쓴다

  • 갈래가 여섯을 넘을 때 — 글자가 잘립니다. 구조를 다시 짭니다
  • '더 보기' 칸으로 나머지를 몰아넣기 — 거기 든 것은 거의 안 쓰입니다
  • 동작(글쓰기·저장)을 탭으로 넣기 — 탭은 길입니다. 그건 FAB 가 할 일입니다
  • 아이콘만 두기 — 뜻이 안 전해집니다

대신 이걸 — 넓은 화면이면 사이드바, 한 화면 안이면 탭, 주 동작이면 FAB(5부), 숨겨도 되는 길이면 드로어.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

<nav>와 aria-current면 됩니다. 어려운 건 탭마다 상태를 따로 기억하는 일입니다.

<nav aria-label="주 메뉴">
  <a href="/tx" aria-current="page">
    <span aria-hidden="true"></span>거래
  </a>
</nav>

// 탭마다 스크롤 위치를 따로 기억한다
pos[current] = body.scrollTop;
body.scrollTop = pos[next] || 0;

// 같은 탭을 다시 누르면 맨 위로
if (next === current) body.scrollTo({ top: 0, behavior: 'smooth' });

/* 홈 인디케이터에 가리지 않게 */
padding-bottom: calc(10px + env(safe-area-inset-bottom));
키일어나야 하는 일
aria-current지금 탭에 "page". 색만으로는 안 전해진다
아이콘aria-hidden으로 숨기고 글자를 읽히게 한다
과녁48px 이상. 아래 끝에 붙어 있어 더 누르기 쉬운 자리이기도 하다
배지'읽지 않음 3건'처럼 뜻까지 읽히게 라벨을 붙인다
Tab칸마다 한 번씩. 보통 서너 번이라 부담이 적다

9 서버 쪽으로 치면백엔드 감각으로 번역

탭 = 독립된 스택탭마다 자기 화면 기록과 스크롤 위치를 들고 있습니다. 하나의 전역 스택으로 다루면 탭을 옮길 때마다 처음으로 돌아가 불편해집니다.
배지 = 폴링 또는 푸시모든 화면에 떠 있는 숫자라 자주 갱신해야 합니다. 폴링이면 주기를, 푸시면 연결을 관리해야 합니다 — 가장 자주 부르는 API가 되기 쉽습니다.
첫 탭 = 첫 질의앱을 열면 첫 탭의 데이터가 곧바로 필요합니다. 나머지 탭은 열 때 부르되, 자주 오가면 캐시를 둡니다.
갈래 수 = 제품 구조탭이 여섯 개가 되는 건 보통 화면 문제가 아니라 제품이 뭘 하는 것인지가 흐려진 신호입니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

iOS 와 안드로이드가 각각 다른 이름으로 가장 강하게 규정한 부품입니다.

웹표준 부품 없음
거래정산
모바일 웹에서 앱처럼 보이려고 씁니다. 브라우저 주소창과 겹치지 않게 env(safe-area-inset-bottom)이 필요합니다.
iOSApple HIG
거래정산
탭 바(Tab bar) · 2~5개를 권하고, 같은 탭 다시 누르기·탭별 스택이 시스템 관례로 굳어 있습니다. iOS 에서 "탭"은 이것을 뜻합니다.
안드로이드Material 3
거래정산
내비게이션 바(Navigation bar) · 3~5개. 고른 칸의 아이콘 뒤에 알약 모양 배경이 깔리는 것이 M3 의 표시 방식입니다.

자주 생기는 사고 — 안드로이드에서 "내비게이션 바"는 이 하단 메뉴를 뜻하고, iOS 에서 같은 말은 화면 위 앱바를 뜻합니다. 위아래가 정반대라, 플랫폼이 섞인 자리에서 가장 크게 어긋나는 이름입니다 — '아래 탭바'처럼 자리를 붙여 말하는 편이 안전합니다.
