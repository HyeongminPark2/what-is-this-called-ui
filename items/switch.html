스위치

Switch · Toggle

켜고 끄는 손잡이. 체크박스와 생김새만 다른 게 아니라, 누르는 즉시 적용된다는 약속이 다릅니다.

같은 설정을 두 방식으로 뒀습니다. 위는 누르는 즉시 적용되고 저장 버튼이 없습니다. 아래는 바꿔도 아무 일이 없고 저장을 눌러야 합니다. 한 화면에 섞으면 무엇이 저장됐는지 알 수 없어 하나만 고르는 것이 규칙입니다.

2 이름부르는 말이 여러 개다

한국어스위치, 토글, 토글 스위치, 온오프
영어switch, toggle
같이 쓰는 말움직이는 동그라미를 손잡이(knob·thumb), 바탕 알약을 트랙이라 합니다. 옆에 적는 '켬/끔'은 상태 글자.
자주 잘못 부름체크박스 — 가장 잦은 혼동입니다. 저장 버튼이 있으면 스위치를 쓰면 안 됩니다.
토글 — 넓게는 맞지만, 토글은 켜고 끄는 모든 것을 가리켜 토글 버튼·세그먼티드까지 섞입니다.
슬라이더 — 손잡이가 움직인다고 슬라이더가 아닙니다. 슬라이더는 범위에서 고릅니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 누르는 즉시 적용되는 설정 — 알림, 다크 모드, 공개 여부
  • 결과가 바로 보이는 것 — 켜면 뭔가 달라지는 게 눈에 보일 때
  • 되돌리기 쉬운 것 — 다시 누르면 끝나는 일

이럴 때는 안 쓴다

  • 저장 버튼이 있는 폼 안 → 체크박스를 씁니다
  • 약관 동의 — 동의는 보낼 때 확정되는 것이라 즉시 적용이 아닙니다
  • 둘 중 하나를 고르는 것 → 켜고 끄기가 아니라 선택이면 라디오나 세그먼티드
  • 되돌리기 어려운 일 — 즉시 적용은 확인할 틈이 없습니다

대신 이걸 — 저장을 눌러야 하면 체크박스, 둘 중 하나를 고르면 세그먼티드나 라디오, 되돌릴 틈이 필요하면 되돌리기 토스트.

8 최소 마크업과 키보드이 부품의 계약서

네이티브 스위치는 없습니다. <button role="switch">로 만드는 쪽이 체크박스를 꾸미는 쪽보다 뜻이 분명합니다.

<button role="switch" aria-checked="true"
        aria-label="멘션과 답글 알림"></button>

// 1) 바로 바꾼다  2) 보낸다  3) 거절당하면 되돌린다
btn.setAttribute('aria-checked', String(!was));
try { await api.set(!was); }
catch {
  btn.setAttribute('aria-checked', String(was));
  toast('바꾸지 못해 되돌렸습니다');
}

9 서버 쪽으로 치면백엔드 감각으로 번역

스위치 = 즉시 쓰기누를 때마다 요청이 한 번 갑니다. 연타하면 요청이 쌓이니 마지막 것만 반영하고, 멱등 키를 붙입니다.
되돌림이 설계의 전부낙관적 UI와 같은 구조입니다. 되돌릴 수 없는 일이면 스위치를 쓰면 안 됩니다.
저장 시점이 다르다체크박스는 폼을 보낼 때 한 번, 스위치는 누를 때마다. API 모양이 아예 달라집니다 — 한 번의 PUT 과 여러 번의 PATCH.
기본값과 상속'시스템 설정 따르기' 같은 제3의 상태가 필요하면 스위치로는 못 담습니다. 그때는 선택지가 셋인 라디오입니다.
