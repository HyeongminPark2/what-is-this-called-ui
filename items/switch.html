스위치

Switch · Toggle

스위치는 손잡이를 좌우로 옮겨 설정을 켜고 끄는 부품입니다. 체크박스와는 생김새만 다른 것이 아니라, 누르는 즉시 적용된다는 약속이 다릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 설정을 두 방식으로 만들어 두었습니다. 위쪽 스위치는 누르는 즉시 적용되고 저장 버튼이 없습니다. 반면 아래쪽 체크박스는 바꿔도 아무 일이 일어나지 않고 저장을 눌러야 적용됩니다. 두 방식을 한 화면에 섞으면 무엇이 이미 저장됐는지 알 수 없으므로 화면마다 한 가지 방식만 쓰는 것이 규칙입니다.
세 번째 스위치는 서버가 요청을 거절해서 원래대로 되돌아갑니다. 즉시 적용 방식을 쓰려면 이렇게 실패했을 때 되돌리고 이유를 알리는 처리까지 만들어야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어스위치, 토글, 토글 스위치, 온오프
영어switch, toggle
같이 쓰는 말움직이는 동그라미는 손잡이(knob·thumb), 바탕의 알약 모양은 트랙이라고 부릅니다. 옆에 적는 '켬/끔'은 상태 글자라고 합니다.
자주 잘못 부르는 이름체크박스 — 스위치와 특히 자주 혼동합니다. 저장 버튼이 있는 화면이면 스위치가 아니라 체크박스를 씁니다.
토글 — 넓은 뜻으로는 맞는 말이지만, 토글은 켜고 끄는 모든 것을 가리키기 때문에 토글 버튼이나 세그먼티드 컨트롤까지 함께 섞입니다.
슬라이더 — 손잡이가 움직인다고 모두 슬라이더는 아닙니다. 슬라이더는 범위 안에서 값을 고르는 부품입니다.

스위치를 한 줄로 정리하면 — 스위치는 누르는 즉시 적용됩니다. 그래서 저장 버튼이 있는 화면에 스위치를 두면 사용자는 무엇이 이미 저장됐는지 알 수 없습니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

멘션과 답글 누가 나를 부르면 바로 알립니다 켬
보안 경고
  1. 항목 이름 label켜면 무엇이 되는지 적습니다. '알림 끄기'처럼 부정형으로 적으면 스위치를 켰을 때 알림이 꺼지는 셈이라 뜻이 헷갈립니다
  2. 보조 설명 description언제, 얼마나 자주 적용되는지 적습니다. 스위치는 누르는 즉시 적용되어 다시 확인을 물을 자리가 없으므로, 필요한 설명을 여기에 다 적어야 합니다
  3. 상태 글자 state label켬/끔을 글자로도 적습니다. 색과 손잡이 위치만으로는 색각 이상이 있는 사람에게 상태가 잘 전해지지 않습니다
  4. 트랙 track알약 모양의 바탕이며, 켜지면 색이 바뀝니다
  5. 손잡이 knob · thumb좌우로 움직이며, 이 움직임으로 상태가 방금 바뀌었다는 것을 알립니다
  6. 비활성 스위치 disabled바꿀 수 없는 스위치입니다. 흐리게만 두지 말고 이유를 적습니다

스위치에는 중간 상태가 없다는 점도 체크박스와 다릅니다. 그래서 '일부만 켜짐'을 나타내야 하는 자리에는 스위치를 쓸 수 없습니다.

6 쓸 때 / 안 쓸 때

스위치를 쓰는 경우

  • 알림, 다크 모드, 공개 여부처럼 누르는 즉시 적용되는 설정을 바꿀 때
  • 켜자마자 무언가 달라지는 것이 바로 눈에 보일 때
  • 다시 한 번 누르면 원래대로 돌아가는, 되돌리기 쉬운 설정일 때

스위치를 쓰지 않는 경우

  • 저장 버튼이 있는 폼 안에 둘 때. 체크박스를 씁니다
  • 약관 동의를 받을 때. 동의는 폼을 보낼 때 확정되므로 즉시 적용되는 일이 아닙니다
  • 켜고 끄는 것이 아니라 둘 중 하나를 고를 때. 라디오나 세그먼티드 컨트롤을 씁니다
  • 되돌리기 어려운 일을 할 때. 즉시 적용되므로 사용자가 다시 확인할 기회가 없습니다

스위치 대신 다른 것을 써야 하는 경우 — 저장을 눌러야 적용되는 폼이면 체크박스를 쓰고, 켜고 끄는 것이 아니라 둘 중 하나를 고르는 값이면 세그먼티드 컨트롤이나 라디오를 씁니다. 잘못 눌렀을 때 되돌릴 틈이 필요하면 되돌리기 토스트를 함께 띄웁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

HTML 에는 네이티브 스위치가 없습니다. 체크박스를 스위치 모양으로 꾸미는 것보다 <button role="switch">로 만드는 편이 스위치라는 뜻을 더 분명하게 전합니다.

<button role="switch" aria-checked="true"
        aria-label="멘션과 답글 알림"></button>

// 1) 바로 바꾼다  2) 보낸다  3) 거절당하면 되돌린다
btn.setAttribute('aria-checked', String(!was));
try { await api.set(!was); }
catch {
  btn.setAttribute('aria-checked', String(was));
  toast('바꾸지 못해 되돌렸습니다');
}

되돌릴 때라이브 리전으로 되돌린 이유를 알립니다. 손잡이만 되돌리면 화면에서 눈을 뗀 사람은 되돌아간 줄 모릅니다
라벨을 붙일 때aria-label이나 연결된 라벨 글자가 꼭 있어야 합니다. 손잡이와 트랙만으로는 무엇을 켜는 스위치인지 알 수 없습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

누를 때마다 바로 저장하는 요청스위치는 누를 때마다 요청을 한 번씩 보냅니다. 여러 번 빠르게 누르면 요청이 쌓이므로 마지막 요청만 반영하고, 요청마다 멱등 키를 붙입니다.
거절당했을 때 되돌리는 처리낙관적 UI와 같은 구조로, 화면을 먼저 바꾸고 서버가 거절하면 되돌립니다. 그래서 되돌릴 수 없는 일에는 스위치를 쓰면 안 됩니다.
체크박스와 다른 저장 시점체크박스는 폼을 보낼 때 한 번 저장하고, 스위치는 누를 때마다 저장합니다. 그래서 체크박스는 PUT 한 번, 스위치는 PATCH 여러 번이 되어 API 형태가 아예 달라집니다.
켬과 끔 말고 세 번째 상태가 필요할 때'시스템 설정 따르기'처럼 켬과 끔 말고 세 번째 상태가 필요하면 스위치로는 나타낼 수 없습니다. 이때는 선택지가 셋인 라디오를 씁니다.
