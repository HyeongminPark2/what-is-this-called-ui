웹폰트

Web font · font loading

글꼴 파일을 받아 와서 쓰는 것. 받는 동안 글을 어떻게 보여 줄지까지 정해야 끝납니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

버튼을 눌러 느린 네트워크를 흉내 내 보세요. 위 칸은 글이 아예 안 보이고(FOIT), 아래 칸은 기본 글꼴로 먼저 보이다 바뀝니다(FOUT).
못 읽은 시간과, 글꼴이 바뀌며 레이아웃이 밀린 폭을 재서 알려 줍니다 — 둘 다 실제 사용자가 겪는 것이고, 둘 중 하나는 반드시 고르게 됩니다.

2 이름부르는 말이 여러 개다

한국어웹폰트, 글꼴 파일, 폰트 로딩
영어web font, font loading, FOIT, FOUT, subsetting
같이 쓰는 말받는 동안 글이 안 보이는 것을 FOIT(Flash of Invisible Text), 기본 글꼴로 보이다 바뀌는 것을 FOUT(Flash of Unstyled Text)라 합니다. 필요한 글자만 추려 파일을 줄이는 것은 서브셋(subsetting), 조각으로 나눠 쓰는 글자만 받는 것은 동적 서브셋입니다.
자주 잘못 부름폰트와 서체 — 엄밀히는 서체(typeface)가 디자인이고 폰트(font)가 파일입니다. 실무에서는 섞어 씁니다.
시스템 폰트 — 기기에 이미 있는 글꼴입니다. 받을 게 없어 이 문제가 통째로 없습니다.
woff 와 woff2 — 지금은 woff2 하나면 충분합니다.

3 가르는 기준형제들과 비교하는 네 축

글자를 다루는 것들은 '값 하나가 글 전체에 걸린다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 바꾸나한글에서 다른 점안 지키면고르는 단위
글자 굵기글자의 두께쓸 수 있는 굵기가 적다단이 다 비슷해 보인다400·500·700
행간줄 사이받침 때문에 더 넓게글이 한 덩어리로 뭉친다배수(1.6~1.8)
자간글자 사이조금만 벌려도 흩어진다글자가 닿거나 흩어진다em
한글 조판줄바꿈 규칙이 항목이 통째로 한글 문제어절이 한가운데서 쪼개진다속성
숫자 꼴숫자의 너비기능 없는 글꼴이 많다자릿수가 흔들린다켜고 끔
말줄임넘친 글의 끝같다뒷말이 그냥 사라진다줄 수
웹폰트글꼴 파일파일이 수십 배 크다글이 늦게 뜨거나 튄다굵기당 한 벌
글자 위계읽는 순서같다어디부터 읽을지 모른다크기·굵기·색
대소문자영어 글자의 꼴한국어에는 없다줄 안에서 결이 어긋난다자리마다
아이콘 글꼴그림을 글자 자리에같다 — 글꼴 문제다못 받으면 네모가 남는다묶음째

한 줄로 — 웹폰트는 '받는 동안 어떻게 보일지'까지가 한 세트입니다. 그걸 안 정하면 브라우저가 대신 정합니다.

4 상태받는 동안 무엇이 보이나

5 해부도부분 이름이 제일 안 알려진 지식

@font-face { font-family: "Pretendard" }
font-display: swap — 먼저 보여 주기
unicode-range — 쪼개서 필요한 조각만
woff2 — 압축 형식. 이것만 쓰면 된다
<link rel="preload"> — 먼저 받기
size-adjust — 바뀔 때 밀리는 것을 줄인다
  1. 글꼴 선언 @font-face이름·굵기·파일 위치를 적는다. 굵기마다 한 벌
  2. 받는 동안 font-display: swap먼저 보여 주기. 요즘의 기본 선택
  3. 쪼개기 unicode-range글자 범위별로 파일을 나눠 쓰는 조각만 받게 한다
  4. 파일 형식 woff2가장 작다. 이것만 적으면 된다 — 옛 형식은 이제 필요 없다
  5. 먼저 받기 preload중요한 한 벌만. 많이 걸면 다른 것이 밀린다
  6. 밀림 줄이기 size-adjust · ascent-override대체 글꼴의 크기를 맞춰 둬 바뀔 때 덜 흔들리게

한글 폰트는 영문의 수십 배입니다. 영문은 대소문자·숫자·기호 해서 수백 자면 끝나지만, 한글은 완성형만 1만 1172자입니다. 그대로 받으면 한 벌에 1~2MB 라 첫 화면이 그만큼 늦어집니다. 그래서 글자 범위별로 100여 조각으로 쪼개 두고, 화면에 실제로 쓰인 글자가 든 조각만 받게 하는 방식(동적 서브셋)이 한국어 사이트의 사실상 표준이 됐습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 브랜드 글꼴이 정해져 있을 때
  • 시스템 글꼴로는 굵기가 모자랄 때
  • 여러 OS 에서 똑같이 보여야 할 때

이럴 때는 안 쓴다

  • 굵기를 다섯 벌 이상 받는 것 — 한글은 한 벌이 1MB 급입니다
  • font-display를 안 정하는 것 — 브라우저가 대신 정합니다(보통 최대 3초 숨김)
  • 본문 글꼴을 바꾸려고 웹폰트를 쓰는 것 — 시스템 글꼴로 충분한 경우가 많습니다
  • 서브셋 없이 한글 전체를 받는 것

대신 이걸 — 굵기 수를 줄이려면 글자 굵기, 글꼴이 바뀌어도 숫자가 안 흔들리게 하려면 숫자 꼴, 로딩 중 화면은 스켈레톤.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 글꼴의 계약서

@font-face 한 덩어리와 <link> 한 줄입니다.

@font-face {
  font-family: "Pretendard";
  font-weight: 400;
  font-display: swap;                 /* 먼저 보여 준다 */
  src: url("pretendard-400.woff2") format("woff2");
  unicode-range: U+AC00-D7A3;          /* 한글 음절만 */
}

/* 대체 글꼴 크기를 맞춰 두면 바뀔 때 덜 밀린다 */
@font-face {
  font-family: "Pretendard-fallback";
  src: local("Apple SD Gothic Neo");
  size-adjust: 96%;
}

<link rel="preload" as="font" type="font/woff2"
      href="pretendard-400.woff2" crossorigin>
규칙지켜야 하는 것
font-display: swap안 정하면 브라우저가 최대 3초 숨깁니다
woff2만지금은 이것만 적으면 된다. 옛 형식은 파일만 늘린다
서브셋을 쓴다한글은 쪼개서 쓰는 조각만 받는다. 직접 호스팅할 때도 마찬가지
굵기를 줄인다한 벌이 수백 KB~1MB. 400·700만으로 시작한다
preload는 한둘만많이 걸면 다른 자원이 밀린다
crossorigin을 잊지 않는다폰트 preload 에는 꼭 필요하다. 없으면 두 번 받는다

9 서버 쪽으로 치면백엔드 감각으로 번역

어디서 받아 오나외부 CDN 은 편하지만 그 도메인에 또 연결해야 합니다. 직접 호스팅하면 연결이 하나로 줄어 보통 더 빠릅니다.
캐시글꼴은 거의 안 바뀌므로 아주 길게 캐시합니다(1년). 바꿀 때는 파일 이름에 해시를 넣습니다.
라이선스웹폰트는 웹 전용 라이선스가 따로입니다. 앱이나 이미지에 쓰려면 범위를 확인해야 합니다.
서버 렌더링첫 HTML 에 @font-face가 늦게 오면 그만큼 늦게 받기 시작합니다. CSS 를 인라인으로 넣는 선택을 하기도 합니다.
측정'글이 처음 보인 시각'과 '레이아웃이 밀린 정도'는 각각 FCP와 CLS로 잽니다. 둘 다 웹폰트가 크게 움직입니다.

글꼴을 앱에 넣어 배포합니다. 받는 동안이 없어 FOIT·FOUT 가 없습니다.
안드로이드앱 번들 · Downloadable Fonts

Downloadable Fonts
역시 앱에 넣습니다. 받아 쓰는 방식도 있지만 첫 화면에는 잘 안 씁니다.

자주 생기는 사고 — 앱에는 이 문제가 통째로 없습니다 — 글꼴이 앱 안에 들어 있으니까요. 그래서 "글꼴 바꿔 주세요"가 앱에서는 용량 몇 MB 늘어나는 일이고, 웹에서는 첫 화면 속도와 레이아웃 밀림 이야기가 됩니다. 같은 요청인데 걱정하는 지점이 다릅니다.
