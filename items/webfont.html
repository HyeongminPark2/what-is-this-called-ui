웹폰트

Web font · font loading

웹폰트는 글꼴 파일을 서버에서 받아 와서 쓰는 방식입니다. 파일을 받는 데 시간이 걸리기 때문에, 받는 동안 글을 어떻게 보여 줄지까지 정해야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

버튼을 눌러 느린 네트워크를 흉내 내 보세요. 위 칸은 글이 아예 보이지 않고(FOIT), 아래 칸은 기본 글꼴로 먼저 보이다가 바뀝니다(FOUT).
글을 읽지 못한 시간과, 글꼴이 바뀌면서 레이아웃이 밀린 폭을 재서 알려 줍니다. 두 현상 모두 실제 사용자가 겪는 일이고, 웹폰트를 쓰면 둘 중 하나는 반드시 골라야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어웹폰트, 글꼴 파일, 폰트 로딩
영어web font, font loading, FOIT, FOUT, subsetting
같이 쓰는 말글꼴을 받는 동안 글이 보이지 않는 현상을 FOIT(Flash of Invisible Text), 기본 글꼴로 보이다가 바뀌는 현상을 FOUT(Flash of Unstyled Text)라고 합니다. 필요한 글자만 추려 파일을 줄이는 작업은 서브셋(subsetting), 글꼴을 여러 조각으로 나눠 두고 화면에 쓰인 글자가 든 조각만 받는 방식은 동적 서브셋이라고 부릅니다.
자주 잘못 부르는 이름폰트와 서체 — 엄밀히 말하면 서체(typeface)는 글자의 디자인이고 폰트(font)는 그 디자인을 담은 파일이지만, 실무에서는 섞어 씁니다.
시스템 폰트 — 기기에 이미 깔려 있는 글꼴입니다. 받을 파일이 없어서 웹폰트의 로딩 문제가 아예 생기지 않습니다.
woff와 woff2 — 지금은 woff2 하나만 준비해도 충분합니다.

4 글꼴을 받는 동안의 상태받는 동안 화면에 보이는 것

5 해부도부분마다 붙은 이름

@font-face { font-family: "Pretendard" }
font-display: swap 글을 먼저 보여 주기
unicode-range 필요한 조각만 나눠 받기
woff2 이것 하나면 되는 압축 형식
<link rel="preload"> 미리 받아 두기
size-adjust 글꼴이 바뀔 때 밀림을 줄임
  1. 글꼴 선언 @font-face글꼴 이름과 굵기, 파일 위치를 적습니다. 굵기마다 한 벌씩 적습니다
  2. 받는 동안의 표시 방식 font-display: swap글을 대체 글꼴로 먼저 보여 줍니다. 요즘 가장 많이 쓰는 기본 선택입니다
  3. 쪼개기 unicode-range글자 범위별로 파일을 나눠서 화면에 쓰인 조각만 받게 합니다
  4. 파일 형식 woff2압축률이 가장 높은 형식이라 이것만 적으면 됩니다. 옛 형식은 이제 필요 없습니다
  5. 먼저 받기 preload중요한 한 벌에만 겁니다. 많이 걸면 다른 자원을 받는 순서가 뒤로 밀립니다
  6. 밀림 줄이기 size-adjust · ascent-override대체 글꼴의 크기를 웹폰트에 맞춰 두어 글꼴이 바뀔 때 덜 흔들리게 합니다

한글 폰트 파일은 영문의 수십 배입니다. 영문은 대소문자와 숫자, 기호를 합쳐 수백 자면 충분하지만, 한글은 완성형만 1만 1172자입니다. 이 글자를 모두 받으면 한 벌에 1~2MB라서 첫 화면이 그만큼 늦게 뜹니다. 그래서 글꼴을 글자 범위별로 100여 조각으로 나눠 두고, 화면에 실제로 쓰인 글자가 든 조각만 받게 하는 방식(동적 서브셋)이 한국어 사이트에서 사실상 표준으로 자리 잡았습니다.

6 쓸 때 / 안 쓸 때

웹폰트를 쓰는 경우

  • 브랜드 글꼴이 정해져 있을 때
  • 시스템 글꼴로는 필요한 굵기가 모자랄 때
  • 여러 OS에서 글자가 똑같이 보여야 할 때

웹폰트를 쓰지 않는 경우

  • 굵기를 다섯 벌 이상 받을 때. 한글 글꼴은 한 벌이 1MB 가까이 됩니다
  • font-display를 정하지 않을 때. 브라우저가 대신 정하는데, 보통 최대 3초 동안 글을 숨깁니다
  • 본문 글꼴을 바꾸려고 웹폰트를 쓸 때. 본문은 시스템 글꼴로 충분한 경우가 많습니다
  • 서브셋 없이 한글 글꼴 전체를 받을 때. 첫 화면이 그만큼 늦게 뜹니다

웹폰트와 이어지는 주제를 다루는 항목 — 받아 올 굵기 수를 줄이는 방법은 글자 굵기에서, 글꼴이 바뀌어도 숫자 자리가 흔들리지 않게 하는 방법은 숫자 꼴에서 다룹니다. 내용을 불러오는 동안 화면 자리를 잡아 두는 방법은 스켈레톤을 보세요.

8 최소 코드와 규칙글꼴 선언과 받아 오기 규칙

웹폰트 설정은 @font-face 한 덩어리와 <link> 한 줄로 이루어집니다.

@font-face {
  font-family: "Pretendard";
  font-weight: 400;
  font-display: swap;                 /* 먼저 보여 준다 */
  src: url("pretendard-400.woff2") format("woff2");
  unicode-range: U+AC00-D7A3;          /* 한글 음절만 */
}

/* 대체 글꼴 크기를 맞춰 두면 바뀔 때 덜 밀린다 */
@font-face {
  font-family: "Pretendard-fallback";
  src: local("Apple SD Gothic Neo");
  size-adjust: 96%;
}

<link rel="preload" as="font" type="font/woff2"
      href="pretendard-400.woff2" crossorigin>
지킬 규칙지키는 방법
font-display: swap 적기정하지 않으면 브라우저가 글을 최대 3초 동안 숨깁니다
woff2 형식만 준비하기지금은 woff2만 적으면 됩니다. 옛 형식을 함께 적으면 준비할 파일만 늘어납니다
서브셋으로 나눠 받기한글은 글꼴을 쪼개서 화면에 쓰인 조각만 받습니다. 직접 호스팅할 때도 마찬가지입니다
받아 올 굵기 줄이기한 벌이 수백 KB에서 1MB나 되므로 400·700 두 굵기로 시작합니다
preload는 한두 벌에만 걸기많이 걸면 다른 자원을 받는 순서가 뒤로 밀립니다
crossorigin 빠뜨리지 않기폰트를 preload할 때는 꼭 필요합니다. 빠뜨리면 같은 파일을 두 번 받습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

글꼴 파일을 받아 오는 곳외부 CDN은 편하지만 브라우저가 그 도메인에 따로 연결해야 합니다. 직접 호스팅하면 연결이 하나로 줄어서 보통 더 빠릅니다.
글꼴 파일의 캐시 기간글꼴 파일은 거의 바뀌지 않으므로 아주 길게(1년) 캐시합니다. 글꼴을 바꿀 때는 파일 이름에 해시를 넣어 새 파일을 받게 합니다.
웹 전용 라이선스웹폰트에는 웹 전용 라이선스가 따로 있습니다. 같은 글꼴을 앱이나 이미지에 쓰려면 라이선스 범위를 확인해야 합니다.
서버 렌더링에서 글꼴 선언 읽히기첫 HTML에서 @font-face를 늦게 읽으면 글꼴도 그만큼 늦게 받기 시작합니다. 그래서 CSS를 HTML 안에 인라인으로 넣기도 합니다.
글꼴 로딩을 재는 지표'글이 처음 보인 시각'은 FCP로, '레이아웃이 밀린 정도'는 CLS로 잽니다. 두 지표 모두 웹폰트 설정에 따라 크게 달라집니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

앱은 글꼴을 앱 안에 넣어 배포하기 때문에 글꼴 로딩 문제가 거의 없습니다.

웹@font-face
정산 확정
woff2 + swap
글꼴을 받아 오는 동안 글을 어떻게 보여 줄지 직접 정해야 합니다. 특히 한글은 파일 크기를 줄이는 일이 큰 과제입니다.
iOS앱 번들
Info.plist
UIAppFonts
.custom("…", size:)
글꼴을 앱에 넣어 배포합니다. 글꼴을 받는 시간이 없으므로 FOIT나 FOUT도 생기지 않습니다.
안드로이드앱 번들 · Downloadable Fonts
res/font/
Downloadable Fonts
안드로이드도 글꼴을 앱에 넣습니다. 글꼴을 내려받아 쓰는 방식도 있지만 첫 화면에는 잘 쓰지 않습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 앱은 글꼴이 앱 안에 들어 있어서 글꼴 로딩 문제가 아예 없습니다. 그래서 "글꼴 바꿔 주세요"라는 요청이 앱에서는 앱 용량이 몇 MB 늘어나는 일이지만, 웹에서는 첫 화면 속도와 레이아웃 밀림을 따져야 하는 일이 됩니다. 같은 요청이라도 플랫폼마다 걱정하는 지점이 다릅니다.
