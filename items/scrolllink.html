스크롤 연동

Scroll-linked animation

스크롤 연동은 사용자가 스크롤하는 만큼에 맞춰 요소를 움직이는 것입니다. 같은 이름 아래에 쓸모 있는 것과 멀미를 일으키는 것이 섞여 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

스크롤해 보세요. 읽은 만큼 막대와 붙박이 머리말은 사용자가 글의 어디쯤에 있는지 알려 주기 때문에 쓸모가 분명합니다.
스크롤 가로채기를 고르고 스크롤해 보면 스크롤한 만큼 내려가지 않아서, 기기가 고장 난 것 같은 느낌이 어떤 것인지 바로 알 수 있습니다. 모션 줄이기를 켜면 연출만 멈춥니다.

2 이름같은 것을 부르는 여러 이름

한국어스크롤 연동, 시차 스크롤, 스크롤 애니메이션, 스크롤 가로채기
영어scroll-linked animation, parallax, scroll-driven animation, scrolljacking
같이 쓰는 말배경이 앞의 내용과 다른 속도로 움직이는 것을 패럴랙스(parallax), 스크롤 위치에 맞춰 재생되는 애니메이션을 스크롤 드리븐이라고 합니다. 스크롤 입력을 가로채서 사용자가 스크롤한 양과 다르게 움직이게 하는 것은 스크롤재킹이라고 하는데, 대부분 나쁜 뜻으로 씁니다. 요소가 화면에 들어왔는지 알려 주는 API는 IntersectionObserver입니다.
자주 잘못 부르는 이름스티키 — 스티키는 화면에 붙어 있는 것이지 움직이는 것이 아닙니다.
무한 스크롤 — 무한 스크롤은 스크롤이 끝에 닿으면 자료를 더 받아오는 기능입니다.
애니메이션 — 시간에 따라 재생되는 애니메이션과 스크롤 위치에 따라 움직이는 것은 다릅니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

움직임은 화면에서 무엇이 바뀌었는지 사용자에게 알려 주는 역할을 합니다. 아래 네 가지를 따져 보면 움직임을 다루는 항목들을 서로 구별할 수 있습니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다
지속 시간얼마나 걸리나거리와 크기기다리게 된다짧게 하거나 0

스프링지나쳤다 돌아오는 정도손으로 민 느낌어지럽다튕김을 0으로

제스처손가락을 따라가는 규칙내가 조작한다실수로 닫힌다그대로 둔다

공유 요소 전환두 화면의 같은 것어디서 왔나자리가 어긋나면 더 헷갈린다자리 이동 없이
스크롤 연동굴림에 맞춰 움직이기내가 어디쯤인가멀미를 부른다연출만 끈다

스크롤 연동을 한 줄로 정리하면 — 스크롤은 사용자가 직접 하는 조작입니다. 스크롤 위치에 맞춰 무언가를 움직이는 것은 괜찮지만, 스크롤한 만큼 화면이 움직이지 않도록 가로채면 안 됩니다.

4 네 가지쓸모 있는 것과 아닌 것

5 해부도부분마다 붙은 이름

읽은 만큼 막대 — 내가 어디쯤인가
붙박이 머리말 — position: sticky
시차 배경 — 배경이 다른 속도로
스크롤 가로채기 — 굴린 만큼 안 간다
scroll-timeline · IntersectionObserver
모션 줄이기에서 연출만 끄고 막대는 남긴다
  1. 읽은 만큼 막대 진행 비율자리 이동이 없어서 가장 안전합니다
  2. 붙박이 position: sticky지금 어느 묶음을 보고 있는지 알려 줍니다. 자세한 내용은 스티키에 있습니다
  3. 시차 다른 속도크게 움직이면 멀미를 일으키므로 모션 줄이기에서 끕니다
  4. 가로채기 굴린 만큼 안 감쓰지 않습니다. 사용자가 스크롤한 만큼 화면이 움직이지 않기 때문입니다
  5. 재는 법 scroll-timelineCSS로도 만들 수 있고 IntersectionObserver로도 만들 수 있습니다
  6. 줄이기 연출만 끈다막대와 붙박이 머리말은 남깁니다

스크롤은 사용자가 화면을 직접 다루는 몇 안 되는 조작입니다. 사용자는 화면이 어떻게 생겼든 스크롤한 만큼 내려간다고 기대하기 때문에, 스크롤한 만큼 움직이지 않으면 기기가 고장 난 것처럼 느낍니다. 스크롤 가로채기를 사용자들이 특히 싫어하는 이유도 여기에 있습니다. 보기 좋은 연출 하나를 위해 스크롤한 만큼 움직인다는 기본 동작을 바꾸기 때문입니다. 스크롤 위치에 맞춰 무언가를 움직이는 것은 괜찮지만, 스크롤 자체를 가로채는 것은 안 됩니다.

6 쓸 때 / 안 쓸 때

스크롤 연동을 쓰는 경우

  • 긴 글에 읽은 만큼 막대를 달 때
  • 묶음이 있는 목록에 붙박이 머리말을 둘 때
  • 요소가 화면에 들어올 때 한 번 나타나게 할 때

스크롤 연동을 쓰지 않는 경우

  • 스크롤 가로채기를 쓸 때. 사용자 대부분이 불편해합니다
  • 시차를 크게 줄 때. 멀미를 일으킵니다
  • 스크롤할 때마다 다시 나타나게 할 때. 두 번째부터는 방해가 됩니다
  • 스크롤해야 나타나는 요소에 읽는 데 꼭 필요한 정보를 담을 때

스크롤 연동 대신 다른 것을 써야 하는 경우 — 화면에 붙어 있기만 하면 스티키, 자료를 더 받아오면 무한 스크롤, 작업 진행을 알리면 프로그레스 바.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙구현할 때 지킬 최소 규칙

CSS로 애니메이션을 스크롤 위치에 연결하고, 연출은 모션 줄이기에서 끕니다.

/* 읽은 만큼 막대 — CSS 만으로 */
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }
.progress {
  transform-origin: left;
  animation: grow linear;
  animation-timeline: scroll();   /* 시간이 아니라 굴림에 매단다 */
}

/* 화면에 들어올 때 한 번 */
const io = new IntersectionObserver(es => es.forEach(e => {
  if (e.isIntersecting) { e.target.classList.add('in'); io.unobserve(e.target); }
}), { threshold: .2 });

/* 줄이기에서는 연출만 끈다 — 막대는 남긴다 */
@media (prefers-reduced-motion: reduce) {
  .parallax { transform: none !important; }
  .reveal   { opacity: 1; transform: none; }
}
키와 동작그때 일어나야 하는 일
굴림을 가로채지 않는다preventDefault로 스크롤을 막으면 키보드로 하는 스크롤까지 막힙니다
animation-timeline: scroll()CSS만으로 애니메이션을 스크롤 위치에 연결합니다. 자바스크립트로 만들 때보다 매끄럽습니다
IntersectionObserverscroll 이벤트를 매번 받아 처리하는 것보다 가볍습니다
한 번만한 번 나타난 뒤에는 unobserve로 관찰을 끊습니다. 스크롤할 때마다 나타나면 읽기를 방해합니다
모션 줄이기시차는 끄고 막대와 붙박이 머리말은 남깁니다
읽는 데 필요한 것은 매달지 않는다스크롤해야 나타나는 글은 스크린 리더에서도 나타나지 않을 수 있습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

굴림으로 더 받을 때무한 스크롤과 함께 쓰면 문서 높이가 계속 바뀌어서 읽은 만큼 막대가 갑자기 줄어듭니다.
들어올 때 받기화면에 들어온 것만 받으면 가볍지만, 빠르게 스크롤하면 요청이 한꺼번에 몰립니다. 그래서 디바운스를 겁니다.
검색 엔진스크롤해야 나타나는 내용은 검색 엔진에 보이지 않을 수 있습니다. 중요한 글은 처음부터 화면에 둡니다.

스크롤 연동은 웹에서 가장 흔하고, 웹에서 가장 자주 지나치게 쓰입니다.

웹scroll-timeline · IO

플랫폼 차이 때문에 자주 생기는 문제 — "스크롤하면 뭔가 움직이게 해 주세요"라는 요청은 대개 예전에 본 홍보 사이트를 떠올리며 하는 말입니다. 제품 화면에서 쓸모 있는 것은 읽은 만큼 막대와 붙박이 머리말 두 가지가 거의 전부이고, 나머지는 멀미와 성능 저하를 감수하는 것에 비해 얻는 것이 적습니다. 이런 요청을 받으면 "이 움직임으로 무엇을 알려 주려는 건가요?"라고 한 번 물어보는 편이 좋습니다.
