스크롤 연동

Scroll-linked animation

굴림에 맞춰 움직이는 것들. 쓸모 있는 것과 멀미를 부르는 것이 한 이름 아래 섞여 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

굴려 보세요. 읽은 만큼 막대와 붙박이 머리말은 '내가 어디쯤인지'를 알려 줘 쓸모가 분명합니다.
스크롤 가로채기를 골라 굴려 보면 굴린 만큼 안 갑니다 — 기기가 고장 난 느낌이 어떤 것인지 바로 알 수 있습니다. 모션 줄이기를 켜면 연출 쪽만 멎습니다.

2 이름부르는 말이 여러 개다

한국어스크롤 연동, 시차 스크롤, 스크롤 애니메이션, 스크롤 가로채기
영어scroll-linked animation, parallax, scroll-driven animation, scrolljacking
같이 쓰는 말배경이 다른 속도로 움직이는 것이 패럴랙스(parallax), 굴림에 맞춰 재생되는 애니메이션이 스크롤 드리븐입니다. 굴린 양과 다르게 움직이게 가로채는 것을 스크롤재킹이라 하고 거의 늘 나쁜 뜻으로 씁니다. 요소가 화면에 들어온 것을 아는 장치가 IntersectionObserver입니다.
자주 잘못 부름스티키 — 스티키는 붙어 있는 것이지 움직이는 것이 아닙니다.
무한 스크롤 — 무한 스크롤은 더 받아오는 일입니다.
애니메이션 — 시간에 따라 도는 것과 굴림에 매인 것은 다릅니다.

3 가르는 기준형제들과 비교하는 네 축

움직임은 장식이 아니라 말입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다

한 줄로 — 굴림은 사용자의 것입니다. 거기에 매달 수는 있어도 빼앗으면 안 됩니다.

4 네 가지쓸모 있는 것과 아닌 것

5 해부도부분 이름이 제일 안 알려진 지식

읽은 만큼 막대 — 내가 어디쯤인가
붙박이 머리말 — position: sticky
시차 배경 — 배경이 다른 속도로
스크롤 가로채기 — 굴린 만큼 안 간다
scroll-timeline · IntersectionObserver
모션 줄이기에서 연출만 끄고 막대는 남긴다
  1. 읽은 만큼 막대 진행 비율자리 이동이 없다. 가장 안전하다
  2. 붙박이 position: sticky지금 어느 묶음인지 — 스티키
  3. 시차 다른 속도크게 쓰면 멀미. 줄이기에서 끈다
  4. 가로채기 굴린 만큼 안 감쓰지 않는다. 손맛을 빼앗는다
  5. 재는 법 scroll-timelineCSS 로도 되고 IntersectionObserver로도 된다
  6. 줄이기 연출만 끈다막대·붙박이는 남긴다

굴림은 사용자가 쥔 몇 안 되는 손잡이입니다. 화면이 어떻게 생겼든 굴리면 그만큼 내려간다는 것이 모두가 믿고 있는 약속이라, 그걸 깨면 기기가 고장 난 것처럼 느껴집니다. 가로채기가 유독 미움받는 이유가 이것입니다 — 예뻐 보이는 연출 하나를 위해 가장 기본적인 약속을 깨기 때문입니다. 굴림에 매다는 것은 괜찮고, 빼앗는 것은 안 됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 긴 글에 읽은 만큼 막대
  • 묶음이 있는 목록에 붙박이 머리말
  • 화면에 들어올 때 한 번 나타나게

이럴 때는 안 쓴다

  • 스크롤 가로채기 — 거의 늘 미움받는다
  • 크게 움직이는 시차 — 멀미를 부른다
  • 굴릴 때마다 다시 나타나기 — 두 번째부터는 방해다
  • 굴림에 매단 것을 읽는 데 꼭 필요한 정보로 두기

대신 이걸 — 붙어 있기만 하면 스티키, 더 받아오면 무한 스크롤, 진행을 알리면 프로그레스 바.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 연출의 계약서

CSS 로 굴림에 매달고, 줄이기에서는 끕니다.

/* 읽은 만큼 막대 — CSS 만으로 */
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }
.progress {
  transform-origin: left;
  animation: grow linear;
  animation-timeline: scroll();   /* 시간이 아니라 굴림에 매단다 */
}

/* 화면에 들어올 때 한 번 */
const io = new IntersectionObserver(es => es.forEach(e => {
  if (e.isIntersecting) { e.target.classList.add('in'); io.unobserve(e.target); }
}), { threshold: .2 });

/* 줄이기에서는 연출만 끈다 — 막대는 남긴다 */
@media (prefers-reduced-motion: reduce) {
  .parallax { transform: none !important; }
  .reveal   { opacity: 1; transform: none; }
}
키일어나야 하는 일
굴림을 가로채지 않는다preventDefault로 막으면 키보드 굴림까지 막힌다
animation-timeline: scroll()CSS 로 매단다. 자바스크립트보다 매끄럽다
IntersectionObserverscroll 이벤트를 매번 듣는 것보다 가볍다
한 번만unobserve로 끊는다. 굴릴 때마다면 읽기를 방해한다
모션 줄이기시차는 끄고 막대·붙박이는 남긴다
읽는 데 필요한 것은 매달지 않는다굴려야 나타나는 글은 스크린 리더에서도 안 나타날 수 있다

9 서버 쪽으로 치면백엔드 감각으로 번역

굴림으로 더 받을 때무한 스크롤과 섞이면 높이가 계속 변해 막대가 튑니다.
들어올 때 받기화면에 들어온 것만 받으면 가볍지만, 빨리 굴리면 요청이 몰립니다. 디바운스를 겁니다.
검색 엔진굴려야 나타나는 내용은 안 보일 수 있습니다. 중요한 글은 처음부터 둡니다.

자주 생기는 사고 — "스크롤하면 뭔가 움직이게"라는 요청은 대개 홍보 사이트의 기억에서 옵니다. 제품 화면에서는 읽은 만큼 막대와 붙박이 머리말 둘이 거의 전부이고, 나머지는 멀미와 성능을 사면서 얻는 것이 적습니다. 요청을 받으면 "무엇을 알려 주려는 건가요"를 한 번 물어보는 편이 좋습니다.
