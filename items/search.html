검색

Search

검색은 사용자가 글자를 자유롭게 입력해 원하는 것을 찾는 장치입니다. 입력칸을 만드는 일보다 요청을 언제 보내고 어떤 응답을 버릴지 정하는 일이 더 까다롭습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

글자를 빠르게 쳐 보세요. 디바운스를 끄면 글자를 칠 때마다 요청이 나갑니다. 늦은 응답 버리기를 끄면 먼저 보낸 요청의 응답이 늦게 도착해 지금 입력한 글자와 다른 결과가 남는데, 입력칸에는 '모란'이 적혀 있는데 목록은 '모'로 찾은 결과인 상태입니다. 실제 서비스에서 가장 자주 생기는 검색 버그입니다.

2 이름같은 것을 부르는 여러 이름

한국어검색, 검색창, 찾기, 자동완성
영어search, search field, typeahead, autocomplete
같이 쓰는 말글자를 치는 대로 입력칸 아래에 후보가 뜨는 것은 타입어헤드(typeahead)·자동완성이라고 하고, 결과 페이지로 넘어가는 것은 그냥 검색이라고 합니다. 입력이 멈출 때까지 기다렸다가 요청을 보내는 것은 디바운스(debounce), 일정한 간격으로만 요청을 보내는 것은 스로틀(throttle)이라고 부릅니다.
자주 잘못 부르는 이름필터 — 필터는 정해진 값 가운데서 고르는 방식이고, 검색은 글자를 직접 입력하는 방식입니다.
콤보박스 — 셀렉트에 글자 입력이 붙은 콤보박스는 값 하나를 고르는 입력이고, 검색은 입력한 글자에 따라 목록을 바꿉니다.
명령 팔레트 — Ctrl+K로 여는 창은 데이터 검색이 아니라 기능을 찾는 도구입니다.

검색을 한 줄로 정리하면 — 검색에서 가장 중요한 일은 지금 입력한 글자와 지금 보이는 결과를 서로 맞게 유지하는 것입니다. 둘이 어긋나면 사용자는 화면의 결과가 어떤 글자로 찾은 것인지 알 수 없어서 결과를 믿지 못하게 됩니다.

  1. 입력칸 type="search"돋보기와 ✕ 버튼을 함께 둡니다. 레이블은 화면에서 숨기더라도 마크업에는 있어야 합니다
  2. 디바운스 300ms입력이 멈춘 뒤에 요청을 보냅니다. 글자마다 보내면 열 글자를 칠 때 요청이 열 번 나갑니다
  3. 늦은 응답 버리기 순번 비교지금 입력한 글자에 대한 응답이 아니면 버립니다. 버리지 않으면 이전 글자의 결과가 섞여 보입니다
  4. 결과 listbox / list일치한 글자를 굵게 표시해서 왜 검색되었는지 보여 줍니다
  5. 건수 알림 role=status화면을 보지 않고 스크린 리더로 듣는 사람에게 결과가 바뀐 것을 알립니다
  6. 주소 ?q=결과 화면이면 검색어를 주소에 담고, 자동완성이면 담지 않습니다

검색을 구현할 때 손이 많이 가는 부분이 늦게 온 응답을 버리는 일입니다. '모'와 '모란'을 연달아 보내면 네트워크 사정에 따라 '모'의 응답이 나중에 도착할 수 있고, 그러면 입력칸에는 '모란'이 적혀 있는데 목록은 '모'로 찾은 결과가 됩니다. 이를 막으려면 요청마다 번호를 붙여 마지막 번호의 응답만 반영하거나, AbortController로 이전 요청을 취소해야 합니다.

6 쓸 때 / 안 쓸 때

검색을 쓰는 경우

  • 이름, 번호, 메모처럼 찾을 값이 정해져 있지 않을 때
  • 목록이 길어서 눈으로 훑어서는 찾기 어려울 때
  • 찾는 대상이 무엇인지 사용자가 이미 알고 있을 때

검색을 쓰지 않는 경우

  • 고를 값이 정해져 있을 때. 필터가 낫습니다
  • 항목이 열 개 남짓일 때. 검색칸을 두지 말고 전부 보여 줍니다
  • 글자를 칠 때마다 요청을 보낼 때. 디바운스를 겁니다
  • 찾는 동안 이전 결과를 지울 때. 화면만 깜빡이고 얻는 것이 없습니다

검색 대신 다른 것을 써야 하는 경우 — 고를 값이 미리 정해져 있으면 필터를 쓰고, 값 하나를 골라 넣는 입력이면 셀렉트가 맞습니다. 데이터가 아니라 기능을 찾게 하려면 명령 팔레트를 둡니다.

let seq = 0;
async function run(q) {
  const my = ++seq;

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

LIKE '%모란%'가 색인을 못 쓰는 문제검색어 앞에 %가 붙으면 색인을 쓰지 못해 테이블 전체를 훑습니다. 그래서 건수가 늘어나는 만큼 검색도 느려집니다.
한국어 검색어를 쪼개 색인하는 방법'모란상회'를 '모란'으로 찾으려면 글자를 형태소나 n-gram 단위로 쪼개 색인해야 합니다. 띄어쓰기를 기준으로 쪼개면 '모란상회'가 한 덩어리로 색인되어 '모란'으로는 찾을 수 없습니다.
너무 짧은 검색어 막기검색어가 한두 자이면 거의 모든 데이터가 결과로 나옵니다. 그래서 두 자 이상일 때부터 요청을 보내거나, 서버에서 짧은 검색어를 거릅니다.
같은 검색 요청이 몰릴 때디바운스를 걸지 않으면 한 사람이 10자를 칠 때 요청이 10번 옵니다. 같은 검색어 요청이 몰릴 때를 대비해 서버에도 짧은 캐시를 둡니다.
관련도순으로 순위 매기기'관련도순'으로 정렬하려면 따로 할 일이 많습니다. 검색어가 어느 필드의 어디에서 일치했는지 따져 점수를 매겨야 하는데, 이 단계부터는 데이터베이스만으로 버거워 검색 엔진이 필요해집니다.

🔍 검색

플랫폼 차이 때문에 자주 생기는 문제 — "검색 넣어 주세요"라는 요청을 받으면 자동완성을 말하는지 결과 화면을 말하는지부터 가려야 합니다. 자동완성은 후보를 고르면 끝나므로 검색어를 주소에 담지 않고, 결과 화면은 공유와 뒤로가기가 되어야 하므로 주소에 담습니다. 두 방식을 섞어 만들면 뒤로가기를 눌렀을 때 돌아갈 화면이 없어집니다.
