앵커 내비

Anchor navigation · on-page nav

같은 문서 안에서만 움직입니다. 화면을 갈아 치우지 않고 굴려서 데려다 줍니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

목차를 눌러 보세요. 고정 머리가 있는 문서에서는 앵커로 뛰면 제목이 머리 밑으로 숨습니다 — 데모가 뛴 뒤 제목의 자리를 재서 적습니다. scroll-margin-top 을 주면 머리 높이만큼 미리 떼어 놓아 제목이 보입니다.
목차는 지금 보는 절을 밝혀 줘야 길잡이가 됩니다. 끄면 어디쯤인지 알 수 없습니다 — 긴 문서에서 목차가 있으나 마나 해지는 이유입니다.

2 이름부르는 말이 여러 개다

한국어앵커 내비, 목차, 페이지 내 목차, 스크롤 목차
영어anchor navigation, on-page nav, table of contents, scrollspy
같이 쓰는 말지금 보는 절을 저절로 밝혀 주는 동작을 스크롤스파이(scrollspy)라 부릅니다. 글 안에 심는 목차는 TOC(table of contents), 오른쪽에 붙어 따라오는 꼴은 sticky TOC 라고 합니다. 뛰어가는 자리를 가리키는 id 를 앵커(anchor)라 부릅니다.
자주 잘못 부름탭 — 탭은 내용을 갈아 끼우고, 앵커 내비는 굴릴 뿐입니다.
사이드바 — 사이드바는 다른 화면으로 데려갑니다.
브레드크럼 — 브레드크럼은 위로 가는 길입니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

<nav aria-label="이 문서 안에서">
href="#s3" — 같은 문서 안의 자리
aria-current="true" — 지금 보는 절
scroll-margin-top — 고정 머리만큼 떼기
position: sticky — 굴려도 따라온다
IntersectionObserver — 보는 절을 고른다
  1. <nav> 이름을 붙인다화면에 nav 가 여럿이라 구별이 필요하다
  2. href="#s3" 같은 문서주소에 남아 공유할 수 있다
  3. aria-current 보는 절색 말고 소리로도
  4. scroll-margin-top 머리만큼 떼기한 줄로 고쳐진다
  5. sticky 따라온다굴려도 목차가 안 사라진다
  6. 관찰자 보는 절 고르기IntersectionObserver

제목이 머리 밑에 숨는 것은 고정 머리를 쓰는 사이트라면 거의 다 겪습니다. 예전에는 보이지 않는 빈 상자를 제목 위에 끼워 넣어 밀어내곤 했는데, 지금은 scroll-margin-top 한 줄이면 끝납니다. 값은 머리 높이와 같게 두되, 머리 높이가 바뀌는 화면이라면 var(--header-h) 같은 변수로 묶어 둡니다.
지금 보는 절을 고를 때는 '화면 위쪽 어디에 걸렸는가'를 기준으로 삼습니다 — 가운데를 기준으로 삼으면 짧은 절에서 영영 안 밝아집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • scroll-margin-top 을 머리 높이만큼 주기
  • 지금 보는 절을 밝히고 aria-current 도 같이 붙이기
  • 항목을 다섯에서 열둘 사이로 두기 — 넘으면 절을 묶는다

이럴 때는 안 쓴다

  • 항목마다 깊이를 세 단까지 두기 — 목차가 본문보다 길어진다
  • scrollIntoView 로만 가고 주소를 안 바꾸기 — 공유가 안 된다
  • behavior: smooth 를 늘 켜 두기 — 모션 줄이기를 켠 사람에게는 끈다
  • 목차를 본문 폭 안에 끼워 넣기 — 폰에서는 접어 둔다

대신 이걸 — 다른 화면으로 가면 사이드바, 내용을 갈아 끼우면 탭, 위로 가면 브레드크럼, 따라붙는 동작은 스티키.

8 최소 마크업과 키보드이 부품의 계약서

평범한 링크입니다. 두 줄의 CSS 가 나머지를 합니다.

<nav aria-label="이 문서 안에서">
  <a href="#fee" aria-current="true">수수료</a>
  <a href="#tax">세금계산서</a>
</nav>

<section id="fee"><h2>수수료</h2>…</section>

/* 고정 머리에 안 가리게 — 이 한 줄이 핵심이다 */
:target, section[id] { scroll-margin-top: var(--header-h); }

/* 모션 줄이기를 켠 사람에게는 부드럽게를 끈다 */
@media (prefers-reduced-motion: no-preference) {
  html { scroll-behavior: smooth; }
}
키일어나야 하는 일
Tab · Enter평범한 링크다 — 따로 붙일 것이 없다
뛴 뒤 초점브라우저가 그 절로 초점도 옮긴다 — 키보드 사용자의 다음 Tab 이 거기서 이어진다
tabindex="-1"제목이 초점을 못 받으면 붙여 둔다
aria-current="true"보는 절. page 가 아니라 true
:target뛰어간 절을 CSS 로 잠깐 밝힐 수 있다
확인하는 법뛴 다음 Tab 을 한 번 눌러 어디로 가는지 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버와는 상관없다# 뒤는 서버로 가지 않습니다. 전부 브라우저 안의 일입니다.
절 id 를 고정문서를 다시 낼 때마다 id 가 바뀌면 남이 공유한 링크가 깨집니다 — 제목 글자가 아니라 안 바뀌는 열쇠로 만듭니다.
긴 문서절마다 따로 받아 오는 구조라면 뛰기 전에 그 절이 와 있는지 확인해야 합니다.
