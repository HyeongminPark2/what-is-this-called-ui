세이프 에어리어

Safe area · safe area insets

화면에서 무엇을 놓아도 안전한 영역. 그 바깥은 노치와 홈 막대가 가져가서, 글자나 버튼을 두면 가려지거나 안 눌립니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

빨간 띠가 못 쓰는 자리입니다. 체크를 켜 보세요 — 상단 바 글자가 노치 아래로 내려오고 탭바가 홈 인디케이터 위로 올라옵니다.
웹에서는 env(safe-area-inset-top) 같은 값으로 읽는데, viewport-fit=cover를 안 적으면 이 값이 늘 0입니다 — "env 가 안 먹어요"의 대부분이 이것입니다.

2 이름부르는 말이 여러 개다

한국어세이프 에어리어, 안전 영역
영어safe area, safe area insets, notch, display cutout
같이 쓰는 말위쪽 카메라 자리는 노치(notch) 또는 다이내믹 아일랜드, 구멍 모양은 펀치홀(punch hole · display cutout), 아래 막대는 홈 인디케이터(home indicator)입니다. 안전 영역의 두께를 인셋(inset)이라 하고, 화면 끝까지 그리는 것을 엣지 투 엣지(edge-to-edge)라 합니다.
자주 잘못 부름상태 바 — 시계·배터리가 있는 띠는 상태 바이고, 세이프 에어리어는 그것까지 포함한 '쓰면 안 되는 범위'입니다.
패딩 — 그냥 padding-top: 44px로 못 박으면 기기마다 틀립니다. 값을 물어봐야 합니다.
뷰포트 — 화면 크기와 안전 영역은 다릅니다. 화면은 넓고 안전 영역은 그 안쪽입니다.

3 가르는 기준형제들과 비교하는 네 축

뼈대를 다루는 것들은 '눈에 안 보이는데 자리를 정한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나방향넘치면누가 값을 정하나
박스 모델상자 한 개의 크기해당 없음밖으로 삐져나온다내가
플렉스한 줄에 늘어놓기한 방향줄을 넘기거나 삐져나온다나 + 내용
그리드판을 칸으로 나누기두 방향칸끼리 자리를 빼앗는다나 + 내용
가운데 맞추기자식의 자리두 방향해당 없음나
넘침넘친 것을 어떻게 할지해당 없음이게 그 답이다나
스티키굴릴 때의 자리세로(보통)부모 밖으로는 못 간다나
컨테이너와 최대 폭내용의 최대 폭가로양옆 여백만 남는다나
세이프 에어리어쓰면 안 되는 가장자리네 방향가려지거나 안 눌린다OS 가

한 줄로 — 세이프 에어리어는 내가 정하는 값이 아니라 OS 에게 물어보는 값입니다. 숫자를 못 박는 순간 어느 기기에선가 깨집니다.

4 갈래기기와 방향마다 다르다

5 해부도부분 이름이 제일 안 알려진 지식

모란상회 홈정산
위 — 노치가 가져가는 두께
아래 — 홈 막대가 가져가는 두께
env(safe-area-inset-top)
env(safe-area-inset-bottom)
viewport-fit=cover — 없으면 값이 늘 0
  1. 화면 전체 viewport기기의 물리적 화면. 여기까지 그릴 수는 있다
  2. 위 인셋 safe-area-inset-top노치·상태 바가 차지하는 두께. 기기마다 다르다
  3. 아래 인셋 safe-area-inset-bottom홈 인디케이터 자리. 버튼을 두면 안 눌린다
  4. 위 값 읽기 env(safe-area-inset-top)숫자를 못 박지 않고 OS 에게 물어본다
  5. 아래 값 읽기 env(safe-area-inset-bottom)홈 막대가 없는 기기에서는 0 이 온다 — 그래서 max()와 함께 쓴다
  6. viewport-fit=cover meta viewport이게 없으면 env 값이 늘 0이다. 'env 가 안 먹어요'의 정답

인셋 값은 0 일 수도 있습니다 — 노치 없는 기기, 데스크톱 브라우저가 그렇습니다. 그래서 padding-bottom: env(safe-area-inset-bottom)만 적으면 그런 기기에서 패딩이 아예 사라집니다. max(16px, env(…))처럼 적어서 '최소한 이만큼은'을 함께 정해 두는 것이 정석입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 화면 끝까지 그리는 앱·웹앱(엣지 투 엣지)
  • 화면 아래 붙박이 버튼이나 탭바가 있을 때
  • 노치 쪽까지 사진·배경을 보낼 때 — 배경은 끝까지, 글자는 안쪽으로
  • 가로 화면을 지원할 때 — 좌우 인셋도 챙깁니다

이럴 때는 안 쓴다

  • 숫자를 못 박는 것 — padding-top: 44px은 다음 기기에서 틀립니다
  • env()만 쓰고 최소값을 안 주는 것 — 노치 없는 기기에서 여백이 0이 됩니다
  • 바의 배경까지 안쪽으로 미는 것 — 가장자리에 흰 띠가 남습니다
  • viewport-fit=cover 없이 env()를 기대하는 것

대신 이걸 — 아래 붙박이 줄 자체는 바텀 탭바, 위는 앱바, 굴릴 때 붙이는 일은 스티키.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙두 줄이면 끝난다

<meta> 한 줄과 padding 한 줄입니다. 메타가 먼저입니다.

<!-- 이게 없으면 env( ) 가 늘 0 이다 -->
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover">

/* 바 배경은 끝까지, 내용만 안쪽으로 */
.bottom-nav {
  padding-bottom: max(12px, env(safe-area-inset-bottom));
}                   /* ↑ 노치 없는 기기에서도 최소 12px */

.app-bar {
  padding-top: max(12px, env(safe-area-inset-top));
}

/* 가로 화면 — 좌우도 잊지 않는다 */
.page {
  padding-inline: max(16px, env(safe-area-inset-left));
}
규칙지켜야 하는 것
viewport-fit=cover 먼저이 한 줄이 없으면 env()가 전부 0이다. 1번 원인
max()와 함께 쓴다노치 없는 기기에서 0 이 와도 최소 여백이 남게
배경은 끝까지바의 배경은 화면 끝까지, 안의 내용만 민다. 안 그러면 가장자리에 띠가 생긴다
좌우도 챙긴다가로로 돌리면 left·right에 값이 생긴다
숫자를 못 박지 않는다44px·34px 같은 값은 그 기기에서만 맞다
터치 자리로 확인한다눈에 안 가려 보여도 안 눌리는 경우가 있다. 실기기로 눌러 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버가 할 일은 없다순수하게 화면의 일입니다. 다만 웹앱을 홈 화면에 설치해 쓰는 경우라면 매니페스트의 display: standalone과 함께 생각해야 합니다.
기기 목록으로 테스트노치 있는 기기 · 없는 기기 · 가로 화면 세 가지가 최소 조합입니다. 브라우저 개발자 도구의 기기 흉내로도 상당 부분 잡힙니다.
키보드가 올라올 때입력칸에 포커스가 가면 화면이 줄어듭니다. 아래 붙박이 버튼은 키보드 위로 올라오게 따로 다뤄야 합니다.
스크린샷 자동 검사글자 상자가 인셋 영역과 겹치는지는 좌표로 잴 수 있습니다. 실기기 없이도 회귀를 막을 수 있습니다.

자주 생기는 사고 — 기본값이 정반대입니다. iOS 는 안전 영역 '안'이 기본이라 안 챙기면 안전하고, 웹과 최신 안드로이드는 '끝까지'가 기본이라 안 챙기면 겹칩니다. 같은 시안을 세 쪽에 넘길 때 "끝까지 그릴지"를 먼저 정해 두면 서로 다른 버그를 안 만듭니다.
