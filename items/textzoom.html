확대와 글자 크기

Zoom & text resize

사용자는 글자를 키울 수 있습니다. 저시력인 사람에게는 이게 유일한 길입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 끌어 글자를 키워 보세요. OS·브라우저 설정으로 사용자가 직접 키울 수 있습니다.
px 로 박아 두기를 켜면 안 커지고, 상자 높이까지 박으면 글이 잘립니다 — 설정을 켠 사람만 겪는 사고라 우리 화면에서는 안 보입니다.

2 이름부르는 말이 여러 개다

한국어확대, 글자 크기 조절, 글자 키우기, 텍스트 리사이즈
영어zoom, text resize, text spacing, dynamic type
같이 쓰는 말화면 전체를 키우는 것이 브라우저 확대(zoom), 글자만 키우는 것이 글자 크기 설정입니다. iOS 는 다이내믹 타입, 안드로이드는 글꼴 크기라 부릅니다. WCAG 에는 200%까지 확대(1.4.4)와 글자 간격을 늘려도 안 깨질 것(1.4.12)이 따로 적혀 있습니다.
자주 잘못 부름반응형 — 폭이 달라지는 것과 글자가 커지는 것은 다릅니다. 다만 결과가 비슷해 섞입니다.
핀치 줌 — 손가락으로 벌리는 것도 확대지만, 막아 두는 코드가 흔해 따로 짚어야 합니다.
화면 밀도 — 화면 밀도는 기기의 성질이고, 이쪽은 사용자의 선택입니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 따로 붙이는 것이 아니라 빠뜨리지 않는 것입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다
대체 텍스트그림의 뜻안 보인다눈으로 안 보는 사람이미지를 끄고 읽어 본다
확대와 글자 크기키웠을 때도 쓰이나안 보인다저시력 사용자200%로 키워 본다

한 줄로 — 크기는 rem 으로, 높이는 박지 마세요. 그러면 설정을 켠 사람에게도 그대로 쓰입니다.

4 키웠을 때무엇이 깨지나

5 해부도부분 이름이 제일 안 알려진 지식

rem · em — 사용자 설정을 따라간다
px 로 박으면 설정을 켜도 안 커진다
높이까지 px 로 박으면 글이 잘린다
200%까지 키워도 내용과 기능을 잃지 않을 것
user-scalable=no 를 쓰지 않는다
글자만 키우는 설정과 화면 전체 확대는 다르다
  1. rem 설정을 따라간다뿌리 글자 크기의 배수다
  2. px 안 커진다설정이 아무 일도 안 한다
  3. 높이 박지 않는다내용이 밀고 늘어나게 둔다
  4. 200% 지켜야 하는 선여기까지 내용과 기능을 잃지 않아야 한다
  5. user-scalable=no 쓰지 않는다핀치 줌을 막는 것은 위반이다
  6. 두 가지 설정 글자만 / 화면 전체따로 켜지므로 둘 다 봐야 한다

깨지는 자리는 글자 크기가 아니라 '박아 둔 높이'입니다. font-size를 rem으로 두어도 상자에 height: 40px이 박혀 있으면 글이 잘립니다. 버튼·칩·표 줄처럼 높이를 맞춰 예쁘게 만든 곳이 특히 그렇습니다. min-height로 바꾸고 overflow를 열어 두면 대부분 해결되고, 그러면 번역해서 글이 길어질 때도 같이 버팁니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 글자 크기를 rem으로 두기
  • 높이는 min-height로, 박지 않기
  • 200%로 키워 한 번 열어 보기

이럴 때는 안 쓴다

  • user-scalable=no·maximum-scale=1 — 위반이다
  • font-size를 px 로 박기
  • 상자 높이를 px 로 박고 overflow:hidden
  • 키우면 기능이 사라지게 두기 — 버튼이 밖으로 밀려나는 식

대신 이걸 — 기기의 배율은 화면 밀도, 폭에 따른 배치는 브레이크포인트, 글줄 길이는 컨테이너.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 크기의 계약서

rem으로 두고 높이를 열어 둡니다.

<meta name="viewport"
      content="width=device-width, initial-scale=1">
<!-- user-scalable=no · maximum-scale=1 을 넣지 않는다 -->

html { font-size: 100%; }        /* 브라우저·OS 설정을 그대로 받는다 */
body { font-size: 1rem; }

.btn  { min-height: 44px; }   /* height 가 아니다 */
.card { min-height: 0; overflow: visible; }

/* 큰 글자에서 한 줄에 다 안 들어가면 접히게 */
.row { display: flex; flex-wrap: wrap; gap: var(--s2); }
키일어나야 하는 일
rem으로뿌리 크기의 배수라 설정을 그대로 따라간다
html에 px 을 박지 않는다font-size: 16px을 뿌리에 적으면 설정이 무시된다
min-height터치 타깃을 지키면서 글이 커지면 같이 늘어난다
flex-wrap: wrap큰 글자에서 한 줄에 안 들어가면 접히게 둔다
user-scalable=no쓰지 않는다. WCAG 1.4.4 위반이다
확인하는 법브라우저를 200%로, 폰은 글자 크기 최대로 두고 열어 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버는 설정을 모른다글자 크기 설정은 요청에 안 담겨 옵니다. 화면에서 CSS 로만 다룹니다.
글이 길어지는 것과 같은 문제번역해서 길어질 때 깨지는 자리와 거의 같습니다. 한 번 고치면 둘 다 해결됩니다.
