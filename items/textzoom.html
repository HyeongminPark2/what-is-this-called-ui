확대와 글자 크기

Zoom & text resize

사용자는 브라우저나 OS 설정으로 글자를 키울 수 있습니다. 저시력인 사람은 이 설정으로 글자를 키워야 화면을 읽을 수 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

막대를 끌어 글자를 키워 보세요. 실제로는 사용자가 OS나 브라우저 설정으로 직접 글자를 키웁니다.
글자 크기를 px로 고정하기를 켜면 막대를 끌어도 글자가 커지지 않고, 상자 높이까지 px로 고정하면 글이 잘립니다. 이 사고는 글자 크기 설정을 켠 사람만 겪기 때문에 개발하는 사람의 화면에서는 드러나지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어확대, 글자 크기 조절, 글자 키우기, 텍스트 리사이즈
영어zoom, text resize, text spacing, dynamic type
같이 쓰는 말화면 전체를 키우는 것은 브라우저 확대(zoom), 글자만 키우는 것은 글자 크기 설정이라고 합니다. 글자 크기 설정을 iOS에서는 다이내믹 타입, 안드로이드에서는 글꼴 크기라고 부릅니다. WCAG에는 200%까지 확대해도 쓸 수 있어야 한다는 기준(1.4.4)과 글자 간격을 늘려도 화면이 깨지지 않아야 한다는 기준(1.4.12)이 따로 있습니다.
자주 잘못 부르는 이름반응형 — 반응형은 화면 폭이 달라질 때를 다루고, 이 항목은 글자가 커질 때를 다룹니다. 다만 화면이 바뀌는 결과가 비슷해서 자주 섞어 부릅니다.
핀치 줌 — 두 손가락을 벌려 키우는 것도 확대에 속하지만, 핀치 줌을 막아 두는 코드가 흔해서 따로 짚어야 합니다.
화면 밀도 — 화면 밀도는 기기가 원래 가진 성질이고, 글자 크기는 사용자가 고르는 설정입니다.

3 글자를 키웠을 때의 모습배율과 단위에 따라 무엇이 깨지는지

4 해부도부분마다 붙은 이름

rem · em — 사용자 설정을 따라감
px로 고정하면 설정을 켜도 커지지 않음
높이까지 px로 고정하면 글이 잘림
200%까지 키워도 내용과 기능을 잃지 않을 것
user-scalable=no는 쓰지 않음
글자 크기 설정과 화면 전체 확대는 서로 다른 설정
  1. rem 설정을 따라감뿌리 요소(html)의 글자 크기에 곱하는 배수입니다
  2. px 커지지 않음px로 고정하면 글자 크기 설정을 바꿔도 반영되지 않습니다
  3. 상자 높이 고정하지 않음높이를 고정하지 않고, 내용이 커지는 만큼 상자도 늘어나게 둡니다
  4. 200% 지켜야 하는 선200%까지 키워도 내용과 기능을 잃지 않아야 합니다
  5. user-scalable=no 쓰지 않음핀치 줌을 막는 것은 접근성 기준 위반입니다
  6. 두 가지 설정 글자만 / 화면 전체두 설정은 따로 켜지므로 둘 다 확인해야 합니다

글자를 키웠을 때 화면이 깨지는 원인은 대개 px로 고정해 둔 상자 높이입니다. font-size를 rem으로 두어도 상자에 height: 40px이 고정되어 있으면 커진 글이 잘립니다. 버튼, 칩, 표의 줄처럼 높이를 딱 맞춰 정돈한 곳에서 특히 이런 일이 생깁니다. height를 min-height로 바꾸고 overflow를 열어 두면 대부분 해결되고, 그렇게 고쳐 두면 번역해서 글이 길어질 때도 화면이 깨지지 않습니다.

5 쓸 때 / 안 쓸 때

글자 크기 설정에 대비해야 하는 경우

  • 글자 크기를 정할 때. rem 단위로 정합니다
  • 상자 높이를 정할 때. 높이를 고정하지 말고 min-height로 정합니다
  • 화면을 다 만든 뒤 점검할 때. 글자를 200%로 키워서 한 번 열어 봅니다

글자를 키울 수 없게 만드는 실수

  • user-scalable=no나 maximum-scale=1로 확대를 막을 때. 접근성 기준 위반입니다
  • font-size를 px로 고정할 때
  • 상자 높이를 px로 고정하고 overflow:hidden을 걸 때
  • 글자를 키우면 버튼이 화면 밖으로 밀려나는 식으로 기능이 사라질 때

글자 크기와 이어지는 주제는 다른 항목에서 다룹니다 — 기기가 원래 가진 배율은 화면 밀도에서, 화면 폭에 따라 배치를 바꾸는 방법은 브레이크포인트에서 다룹니다. 한 줄에 들어가는 글의 길이는 컨테이너를 보세요.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙구현할 때 지킬 최소 규칙

글자 크기는 rem으로 정하고, 상자 높이는 고정하지 않고 열어 둡니다.

<meta name="viewport"
      content="width=device-width, initial-scale=1">
<!-- user-scalable=no · maximum-scale=1 을 넣지 않는다 -->

html { font-size: 100%; }        /* 브라우저·OS 설정을 그대로 받는다 */
body { font-size: 1rem; }

.btn  { min-height: 44px; }   /* height 가 아니다 */
.card { min-height: 0; overflow: visible; }

/* 글자가 커져 한 줄에 다 들어가지 않으면 다음 줄로 넘긴다 */
.row { display: flex; flex-wrap: wrap; gap: var(--s2); }
지킬 규칙지키는 방법
글자 크기는 rem으로뿌리 요소의 글자 크기에 곱하는 배수라서 사용자 설정을 그대로 따라갑니다
html에 px을 고정하지 않기뿌리 요소에 font-size: 16px을 적으면 사용자의 글자 크기 설정이 무시됩니다
높이는 min-height로터치 타깃 최소 크기를 지키면서도, 글이 커지면 상자가 같이 늘어납니다
flex-wrap: wrap으로 줄 넘기기글자가 커져 한 줄에 들어가지 않으면 다음 줄로 넘어가게 둡니다
user-scalable=no 쓰지 않기확대를 막으면 WCAG 1.4.4 위반입니다
확인하는 방법브라우저는 200%로 확대하고, 폰은 글자 크기를 최대로 두고 화면을 열어 봅니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버로 전달되지 않는 설정사용자의 글자 크기 설정은 서버로 오는 요청에 담기지 않으므로, 화면 쪽에서 CSS로만 다룹니다.
번역으로 글이 길어질 때와 같은 문제글자를 키웠을 때 깨지는 자리는 번역해서 글이 길어질 때 깨지는 자리와 거의 같아서, 한 번 고치면 두 문제가 함께 해결됩니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

웹, iOS, 안드로이드 모두 글자 크기는 사용자가 직접 켜는 설정입니다.

웹rem · 브라우저 확대
모란상회11월 1일 ~ 7일 정산이 승인되었습니다. 수수료를 뺀 금액이 들어갑니다.
브라우저 확대와 글자 크기 설정이 따로 있어서 둘 다 확인해야 합니다.
iOSDynamic Type
모란상회
시스템 글자 스타일을 쓰면 사용자 설정을 자동으로 따라갑니다. 접근성 설정에서는 글자를 훨씬 더 크게 키울 수도 있습니다.
안드로이드sp 단위
모란상회
글자 크기는 sp, 나머지 크기는 dp로 적습니다. 글자를 sp로 적어야 사용자 설정을 따라갑니다.

플랫폼 차이 때문에 자주 생기는 문제 — 이 항목의 문제는 개발하는 사람이 글자 크기 설정을 켜 두지 않는 한 개발 화면에서는 드러나지 않습니다. 그래서 일부러 브라우저는 200%로 확대하고, 폰은 글자 크기를 최대로 둔 채 화면을 한 번 열어 봐야 합니다. 그렇게 한 번만 열어 봐도 높이를 고정해 둔 자리가 대부분 드러납니다.
