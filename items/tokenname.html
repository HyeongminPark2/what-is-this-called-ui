토큰 이름 짓기

Token naming

토큰 이름은 값이 아니라 쓰임을 적습니다. --blue는 어두운 모드가 오는 순간 거짓말이 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

이름을 규칙 셋으로 매깁니다 — ①값이 이름에 박혀 있나 ②무엇에 쓰는지가 있나 ③어느 층인가. 직접 넣어 보면 그 자리에서 매겨 줍니다.
'어두운 모드로'를 켜면 --blue 의 실제 값이 나옵니다. 파랑이라고 적혀 있는데 파랑이 아닙니다 — 값을 이름에 박으면 벌어지는 일입니다.

2 이름부르는 말이 여러 개다

한국어토큰 이름 짓기, 네이밍 규칙, 토큰 체계
영어token naming, design token taxonomy
같이 쓰는 말값에 붙인 이름이 원시(primitive · global · core), 쓰임에 붙인 이름이 의미(semantic · alias), 한 부품만 쓰는 이름이 부품(component)입니다. 의미 토큰이 원시를 가리키는 구조를 별칭(alias)이라 부릅니다.
자주 잘못 부름변수 — CSS 변수는 담는 그릇이고, 토큰은 그 안의 약속입니다. 토큰을 변수로 옮겨 담을 뿐입니다.
테마 — 테마는 값 한 벌이고, 이름은 테마가 바뀌어도 그대로여야 합니다.
클래스 이름 — BEM 같은 규칙은 마크업의 이름이고 이건 값의 이름입니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보인다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선하다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 안 읽히고 z-index 가 안 먹는다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 안 맞는다
상태 색성공 · 주의 · 오류 · 정보4가지 × 3자리알림 · 배지 · 입력 오류색을 못 보면 상태를 못 읽는다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 아무도 못 고친다

한 줄로 — 이름만 보고 어디에 쓰는지 알 수 있으면 됩니다. 값이 적혀 있으면 이미 틀렸습니다.

4 층이름이 가리키는 것이 다르다

5 해부도부분 이름이 제일 안 알려진 지식

--blue-500 ← 원시 : 값에 붙인 이름
--color-text-danger ← 의미 : 쓰임에 붙인 이름
--btn-bg ← 부품 : 한 부품만의 이름
화면에서는 의미 층만 쓴다
--blue 를 어두운 모드에 쓰면 이름이 거짓
갈래-쓰임-자리-상태 ← 이름의 차례
  1. 원시 --blue-500값에 붙인 이름
  2. 의미 --color-text-danger쓰임에 붙인 이름
  3. 부품 --btn-bg한 부품만의 이름
  4. 쓰는 층 의미만화면 코드에는 의미 층만 나온다
  5. 거짓 이름 --blue어두운 모드에서 파랑이 아니다
  6. 차례 갈래-쓰임-자리-상태color-text-danger-hover

세 층을 두는 이유는 바꿀 자리를 한 곳으로 모으기 위해서입니다. 브랜드 파랑이 바뀌면 원시 한 줄만 고치면 되고, '오류 글자색을 더 진하게'는 의미 한 줄만 고치면 됩니다.
대신 층을 섞어 쓰면 이 이점이 통째로 사라집니다. 화면 코드에 --blue-500이 한 번이라도 나오면 그 자리는 어두운 모드를 따라오지 않습니다. 규칙은 하나입니다 — 화면에서는 의미 층만.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 이름에 쓰임을 적기 — text·bg·border
  • 차례를 갈래-쓰임-자리-상태로 고정하기
  • 화면 코드에서는 의미 층만 쓰기

이럴 때는 안 쓴다

  • --blue·--red — 어두운 모드에서 이름이 거짓이 된다
  • --font-14 — 값을 바꾸는 순간 이름이 거짓이 된다
  • --color-primary 하나로 버티기 — 글자인지 바탕인지 모른다
  • 부품 토큰을 먼저 만들기 — 의미 층이 비어 버린다

대신 이걸 — 값 자체는 색 토큰, 두 벌로 두는 법은 다크 모드, 크기 단은 타입 스케일·간격 체계.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 이름의 계약서

원시를 깔고, 의미가 그것을 가리키고, 화면은 의미만 씁니다.

/* 1층 원시 — 값에 붙인 이름. 화면에서 직접 안 쓴다 */
:root {
  --blue-500: #1f6feb;
  --red-500: #cf222e;
  --gray-200: #e4e6eb;
}

/* 2층 의미 — 쓰임에 붙인 이름. 테마가 바뀌면 여기만 갈아 끼운다 */
:root {
  --color-text-danger: var(--red-500);
  --color-border-muted: var(--gray-200);
}
[data-theme="dark"] {
  --color-text-danger: #ff7b72;   /* 이름은 그대로다 */
}

/* 화면은 의미 층만 쓴다 */
.field-error { color: var(--color-text-danger); }

/* ✕ 어두운 모드를 안 따라온다 */
.field-error { color: var(--red-500); }
키일어나야 하는 일
갈래color·space·radius·shadow
쓰임text·bg·border·icon
자리danger·muted·brand
상태hover·active·disabled — 맨 뒤
찾는 법--color- 로 시작하면 자동완성이 묶어 준다
확인하는 법화면 코드에서 --blue·-500 을 검색해 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버와는 상관없다토큰은 화면 안의 약속입니다. 다만 이름 짓는 버릇은 그대로 통합니다.
같은 원리status 를 red 가 아니라 failed 로 보내는 것과 같은 이야기입니다 — 값이 아니라 뜻을 이름으로 둡니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

웹CSS 변수

자산 묶음에 이름을 두고 밝은·어두운 값을 같이 담습니다 — 구조가 의미 층과 같습니다.
안드로이드Material 역할
primary·onPrimary·surface 처럼 역할 이름이 아예 정해져 있습니다.

자주 생기는 사고 — Material 의 역할 이름은 의미 층을 OS 가 미리 정해 준 것입니다 — 고민할 거리가 줄지만 그 틀 밖으로 나가기 어렵습니다. 웹은 반대로 전부 직접 지어야 해서 자유롭고 또 쉽게 엉킵니다. 그래서 이름의 차례를 한 줄로 적어 두고(갈래-쓰임-자리-상태) 새 토큰을 만들 때마다 그 줄에 맞춰 보는 것이, 규칙을 길게 쓰는 것보다 잘 지켜집니다.
