토큰 이름 짓기

Token naming

토큰 이름에는 값이 아니라 쓰임을 적습니다. 예를 들어 --blue라는 이름은 어두운 모드에서 값이 다른 색으로 바뀌면 실제 색과 맞지 않게 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

데모는 토큰 이름을 세 가지 규칙으로 따져 봅니다. ①이름에 값이 들어 있는지, ②무엇에 쓰는지가 드러나는지, ③어느 층의 이름인지를 보고, 이름을 직접 넣어 보면 그 자리에서 판정해 줍니다.
'어두운 모드로 바꾸기'를 켜면 --blue의 실제 값이 나오는데, 이름은 파랑인데 실제 색은 파랑이 아닙니다. 이름에 값을 넣으면 이런 일이 생깁니다.

2 이름같은 것을 부르는 여러 이름

한국어토큰 이름 짓기, 네이밍 규칙, 토큰 체계
영어token naming, design token taxonomy
같이 쓰는 말값에 붙인 이름은 원시(primitive · global · core), 쓰임에 붙인 이름은 의미(semantic · alias), 한 부품에서만 쓰는 이름은 부품(component) 토큰입니다. 의미 토큰이 원시 토큰을 가리키는 구조는 별칭(alias)이라고 부릅니다.
자주 잘못 부르는 이름변수 — CSS 변수는 값을 저장하는 수단이고, 토큰은 그 값을 어디에 쓸지 정한 규칙입니다. CSS 변수는 토큰을 코드로 옮길 때 쓰는 방법 가운데 하나입니다.
테마 — 테마는 토큰에 넣을 값 한 벌이고, 토큰 이름은 테마가 바뀌어도 그대로여야 합니다.
클래스 이름 — BEM 같은 규칙은 마크업에 붙이는 이름이고, 토큰 이름은 값에 붙이는 이름입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하는가몇 단으로 두면 좋은가값을 바꾸면 어디가 바뀌는가잘못 정했을 때 나타나는 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌, 고대비까지 두면 3벌화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지, 색마다 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

토큰 이름 짓기를 한 줄로 정리하면 — 좋은 토큰 이름은 이름만 보고 어디에 쓰는지 알 수 있는 이름입니다. 이름에 값이 적혀 있다면 이미 잘못 지은 것입니다.

4 토큰의 세 층과 잘못 지은 이름층마다 이름이 가리키는 것

5 해부도부분마다 붙은 이름

--blue-500 ← 원시 층, 값에 붙인 이름
--color-text-danger ← 의미 층, 쓰임에 붙인 이름
--btn-bg ← 부품 층, 한 부품만의 이름
화면에서는 의미 층만 씀
--blue는 어두운 모드에서 이름과 색이 어긋남
갈래-쓰임-자리-상태 ← 이름의 차례
  1. 원시 --blue-500값에 붙인 이름입니다
  2. 의미 --color-text-danger쓰임에 붙인 이름입니다
  3. 부품 --btn-bg한 부품에서만 쓰는 이름입니다
  4. 쓰는 층 의미만화면 코드에는 의미 층만 나와야 합니다
  5. 색 이름이 든 토큰 --blue어두운 모드에서는 실제 색이 파랑이 아닙니다
  6. 차례 갈래-쓰임-자리-상태color-text-danger-hover처럼 짓습니다

토큰을 세 층으로 나누는 이유는 바꿀 자리를 한 곳으로 모으기 위해서입니다. 브랜드 파랑이 바뀌면 원시 토큰 한 줄만 고치면 되고, 오류 글자색을 더 진하게 하고 싶으면 의미 토큰 한 줄만 고치면 됩니다.
하지만 층을 섞어 쓰면 이 이점이 모두 사라집니다. 화면 코드에 --blue-500이 한 번이라도 나오면 그 자리는 어두운 모드로 바꿔도 색이 바뀌지 않습니다. 그래서 지킬 규칙은 화면 코드에서는 의미 층만 쓴다는 것 하나입니다.

6 쓸 때 / 안 쓸 때

토큰 이름을 지을 때 지킬 것

  • 이름에 text·bg·border 같은 쓰임을 적기
  • 차례를 갈래-쓰임-자리-상태로 고정하기
  • 화면 코드에서는 의미 층만 쓰기

토큰 이름을 지을 때 피할 것

  • --blue·--red처럼 색 이름 쓰기. 어두운 모드에서 이름과 실제 색이 어긋납니다
  • --font-14처럼 값 넣기. 값을 바꾸면 이름과 값이 어긋납니다
  • --color-primary 하나로 여러 자리를 채우기. 글자색인지 바탕색인지 알 수 없습니다
  • 부품 토큰을 먼저 만들기. 부품마다 값을 따로 정하게 되어 의미 층이 비게 됩니다

함께 보면 좋은 항목 — 토큰에 넣을 색 값은 색 토큰 항목에서, 값을 두 벌로 두는 방법은 다크 모드 항목에서 다룹니다. 크기의 단은 타입 스케일 항목과 간격 체계 항목에서 설명합니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 지킬 규칙이름을 코드로 옮기는 방법

원시 토큰을 먼저 정의하고 의미 토큰이 원시 토큰을 가리키게 한 뒤, 화면 코드에서는 의미 토큰만 씁니다.

/* 1층 원시. 값에 붙인 이름이라 화면에서 직접 쓰지 않는다 */
:root {
  --blue-500: #1f6feb;
  --red-500: #cf222e;
  --gray-200: #e4e6eb;
}

/* 2층 의미. 쓰임에 붙인 이름이고, 테마가 바뀌면 여기만 바꾼다 */
:root {
  --color-text-danger: var(--red-500);
  --color-border-muted: var(--gray-200);
}
[data-theme="dark"] {
  --color-text-danger: #ff7b72;   /* 이름은 그대로다 */
}

/* 화면은 의미 층만 쓴다 */
.field-error { color: var(--color-text-danger); }

/* ✕ 어두운 모드를 안 따라온다 */
.field-error { color: var(--red-500); }
이름의 부분과 점검 방법들어가는 낱말과 설명
첫째, 갈래color·space·radius·shadow
둘째, 쓰임text·bg·border·icon
셋째, 자리danger·muted·brand
넷째, 상태hover·active·disabled. 이름의 맨 뒤에 붙입니다
토큰을 찾는 방법이름이 --color-로 시작하면 편집기 자동완성에서 색 토큰끼리 묶여 나옵니다
확인하는 방법화면 코드에서 --blue나 -500을 검색해 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

화면 쪽에서 쓰는 규칙토큰은 화면 쪽에서 쓰는 규칙입니다. 다만 이름 짓는 원칙은 서버에도 그대로 들어맞습니다.
서버 상태 이름과 같은 원리서버가 status를 red가 아니라 failed로 보내는 것과 같은 원리로, 값이 아니라 뜻을 이름으로 삼습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

토큰을 층으로 나누는 생각은 세 플랫폼이 같습니다.

웹CSS 변수
--color-text-danger의미

안드로이드Material 역할
primary·onPrimary·surface처럼 역할 이름이 규격에 미리 정해져 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — Material의 역할 이름은 의미 층을 OS가 미리 정해 준 것입니다. 그래서 이름을 고민할 일은 줄지만, 정해진 역할 밖의 이름을 만들기는 어렵습니다. 반대로 웹에서는 이름을 전부 직접 지어야 해서 자유로운 대신 이름이 쉽게 엉킵니다. 그러므로 이름의 차례를 갈래-쓰임-자리-상태처럼 한 줄로 적어 두고 새 토큰을 만들 때마다 그 차례에 맞춰 보는 편이, 규칙을 길게 써 두는 것보다 잘 지켜집니다.
