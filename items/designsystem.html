디자인 시스템

Design system

토큰 · 부품 · 패턴 · 문서 네 겹입니다. 넷 중 하나라도 빠지면 다른 이름으로 불러야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

색을 바꿔 보세요 — 토큰 하나를 고치면 부품도 패턴도 따라옵니다. 이게 디자인 시스템이 하는 일의 거의 전부입니다.
색을 부품마다 박아 두기를 켜면 연결이 끊깁니다. 색을 바꿔도 몇 개는 안 따라오고, 어느 것이 안 따라왔는지는 눈으로 찾아야 합니다.

2 이름부르는 말이 여러 개다

한국어디자인 시스템, 디자인 언어, 컴포넌트 라이브러리, 스타일 가이드
영어design system, design language, component library, style guide
같이 쓰는 말값에 이름을 붙인 것이 디자인 토큰, 그 값을 쓰는 조각이 컴포넌트, 조각을 모은 화면 단위가 패턴입니다. 색·글꼴 규칙만 적은 문서는 스타일 가이드, 쓸 수 있는 코드 묶음은 컴포넌트 라이브러리입니다. 넷이 다 있고 지켜지는 것을 디자인 시스템이라 부릅니다.
자주 잘못 부름스타일 가이드 — 규칙만 적은 문서입니다. 쓸 수 있는 부품이 없으면 지켜지지 않습니다.
컴포넌트 라이브러리 — 부품은 있는데 언제 쓰는지가 없으면 아무거나 쓰게 됩니다.
UI 킷 — 시안 파일만 가리키는 일이 많습니다. 코드가 따라오지 않으면 반쪽입니다.

3 가르는 기준형제들과 비교하는 네 축

현장 용어는 말이 아니라 일하는 단계를 가리킵니다. 이 네 가지만 물어보면 갈립니다.

무엇을 가리키나언제 나오나개발 쪽 대응물잘못 알아들으면
와이어프레임과 목업과 시안얼마나 진짜 같은 그림인가기획 ~ 디자인마크업 구조 ~ 완성 화면엉뚱한 리뷰가 돌아온다
디자인 시스템규칙 + 부품 + 문서프로젝트 내내토큰 + 컴포넌트 라이브러리스타일 가이드와 섞인다
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀐다
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞인다
오토 레이아웃자동 배치시안 작업flexbox‘여백이 자동’을 못 알아듣는다
프로토타입눌리는 시안리뷰 · 사용자 시험아직 코드가 아니다다 된 줄 안다
핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받는다
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배만 받아 뭉갠다

한 줄로 — 시안과 코드가 같은 토큰을 보고 있나가 전부입니다. 아니면 그림과 화면이 조금씩 멀어집니다.

4 네 겹무엇이 빠지면 무엇이 안 되나

5 해부도부분 이름이 제일 안 알려진 지식

토큰 — --accent: #2f6df6. 이름 붙인 값
부품 — 토큰을 쓰는 버튼 · 칩 · 입력칸
패턴 — 부품을 모은 카드 · 폼 · 표
문서 — 언제 쓰고 언제 안 쓰나
시안과 코드가 같은 토큰을 본다
색을 부품마다 박으면 연결이 끊긴다
  1. 토큰 이름 붙인 값--accent·--space-3. 값을 직접 안 쓴다
  2. 부품 토큰을 쓰는 조각버튼·칩·입력칸
  3. 패턴 부품을 모은 것카드·폼·표
  4. 문서 언제 쓰나이게 시스템과 라이브러리를 가른다
  5. 한 뿌리 시안 = 코드둘이 같은 토큰을 봐야 안 멀어진다
  6. 박아 두기 연결 끊김고칠 때 어느 것이 안 따라왔는지 모른다

디자인 시스템이 실패하는 가장 흔한 이유는 만들지 않아서가 아니라 지켜지지 않아서입니다. 부품을 아무리 잘 만들어도 '이럴 때는 어떤 걸 쓰나'가 없으면 급한 사람은 새로 만듭니다 — 그래서 문서가 네 번째가 아니라 사실은 첫 번째입니다. 그리고 문서는 길 필요가 없습니다. 부품마다 '언제 쓴다 / 언제 안 쓴다' 두 줄이면 대부분 해결됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 같은 부품이 여러 화면에 나올 때
  • 사람이 늘어 손으로 맞추기 어려워질 때
  • 브랜드·테마를 통째로 바꿀 일이 있을 때

이럴 때는 안 쓴다

  • 화면이 다섯 장인데 시스템부터 만들기 — 과하다
  • 값을 부품마다 박아 두기 — 토큰을 쓸 이유가 없어진다
  • 문서 없이 부품만 — 아무거나 쓰게 된다
  • 쓰는 사람 없이 혼자 만들기 — 안 쓰이면 없는 것이다

대신 이걸 — 값 하나하나는 색 토큰·간격 체계, 부품의 변형은 배리언트, 넘기는 일은 핸드오프.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 구조와 규칙이 시스템의 계약서

토큰은 한 곳에 두고, 부품은 값이 아니라 이름을 씁니다.

:root {
  /* ① 토큰 — 값에 이름을 붙인다 */
  --accent: #2f6df6;
  --space-3: 12px;
  --radius-1: 6px;
}

/* ② 부품 — 값이 아니라 이름을 쓴다 */
.btn {
  background: var(--accent);      /* ○ */
  padding: var(--space-3);
  border-radius: var(--radius-1);
}
.btn--bad { background: #2f6df6; }   /* ✕ 박아 두면 끊긴다 */

/* ③ 패턴 — 부품을 모은다 */
.store-card { display: grid; gap: var(--space-3); }
키일어나야 하는 일
토큰은 한 곳에흩어지면 '진짜 값'이 어디인지 아무도 모른다
이름은 쓰임으로--blue-500보다 --accent. 다크 모드에서 파랑이 아닐 수 있다
접근성은 부품에role·키보드를 부품에 넣어 두면 쓰는 사람이 공짜로 얻는다
다크 모드토큰이 있으면 값만 바꾸면 된다 — 없으면 전수 조사다
대비비토큰 단계에서 한 번 재 두면 부품마다 안 재도 된다
버전부품을 고치면 쓰는 쪽이 전부 바뀐다. 무엇이 바뀌는지 적어 둔다

9 서버 쪽으로 치면백엔드 감각으로 번역

토큰을 한 벌로 뽑는다시안 도구의 변수를 CSS 변수·JSON 으로 내보내 쓰면 손으로 옮기다 틀릴 일이 없습니다.
부품을 패키지로여러 저장소가 쓰면 버전이 필요합니다. 고칠 때마다 쓰는 쪽이 다 바뀝니다.
쓰이는지 센다어느 부품이 어디서 몇 번 쓰이는지를 세어 보면 버릴 것이 보입니다.
손으로 만든 것 찾기#2f6df6 같은 값을 코드에서 검색하면 끊긴 연결이 바로 나옵니다.
