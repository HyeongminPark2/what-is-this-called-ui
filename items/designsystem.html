디자인 시스템

Design system

디자인 시스템은 토큰과 부품, 패턴, 문서가 네 겹으로 쌓인 묶음입니다. 넷 중 하나라도 빠지면 스타일 가이드나 컴포넌트 라이브러리처럼 다른 이름으로 불러야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

색을 바꿔 보세요. 토큰 하나를 고치면 그 토큰을 참조하는 부품과 패턴의 색이 함께 바뀌는데, 디자인 시스템이 하는 일은 대부분 이것입니다.
색을 부품마다 박아 두기를 켜면 부품이 토큰 대신 색 값을 직접 쓰게 되어 연결이 끊깁니다. 그러면 색을 바꿔도 몇 개는 바뀌지 않고, 어느 것이 바뀌지 않았는지는 눈으로 하나씩 찾아야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어디자인 시스템, 디자인 언어, 컴포넌트 라이브러리, 스타일 가이드
영어design system, design language, component library, style guide
같이 쓰는 말색이나 간격 같은 값에 이름을 붙인 것을 디자인 토큰, 그 토큰을 가져다 쓰는 화면 조각을 컴포넌트, 조각 여러 개를 모은 화면 단위를 패턴이라고 합니다. 색과 글꼴 규칙만 적은 문서는 스타일 가이드, 가져다 쓸 수 있는 코드 묶음은 컴포넌트 라이브러리입니다. 토큰과 부품, 패턴, 문서가 모두 갖춰져 있고 실제로 지켜지는 것을 디자인 시스템이라고 부릅니다.
자주 잘못 부르는 이름스타일 가이드 — 규칙만 적은 문서입니다. 규칙대로 만든 가져다 쓸 수 있는 부품이 함께 없으면 매번 손으로 만들어야 해서 규칙이 잘 지켜지지 않습니다.
컴포넌트 라이브러리 — 부품은 있어도 각 부품을 언제 쓰는지 적은 문서가 없으면 사람마다 아무 부품이나 골라 쓰게 됩니다.
UI 킷 — 대개 시안 파일만 가리킵니다. 같은 부품이 코드로 함께 있지 않으면 디자인 쪽에서만 쓸 수 있는 묶음에 그칩니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

15부에서 다루는 현장 용어는 화면 부품의 이름 대신 디자인과 개발이 함께 일하는 단계를 가리킵니다. 아래 네 가지를 물어보면 이 용어들을 서로 구별할 수 있습니다.

무엇을 가리키는가어느 작업 단계에서 나오는가개발 쪽에서 대응하는 것잘못 알아들으면 생기는 일
와이어프레임과 목업과 시안그림이 얼마나 진짜 같은지기획 ~ 디자인마크업 구조 ~ 완성 화면묻는 것과 어긋난 리뷰가 돌아옴
디자인 시스템규칙과 부품과 문서프로젝트 내내토큰과 컴포넌트 라이브러리스타일 가이드와 섞어 부름
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀜
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞어 부름

핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받음
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배 파일만 받아 그림이 뭉개짐
디자인 리뷰고칠 거리를 만드는 말단계마다코드 리뷰의견이 너무 이르거나 늦음
버전 관리어느 것이 지금 것인지 가리기프로젝트 내내커밋 메시지final 사슬이 생김

디자인 시스템을 한 줄로 정리하면 — 디자인 시스템에서 가장 먼저 확인할 것은 시안과 코드가 같은 토큰을 참조하고 있는지입니다. 서로 다른 값을 쓰고 있으면 고칠 때마다 시안과 실제 화면이 조금씩 달라집니다.

4 디자인 시스템의 네 겹한 겹이 빠지면 생기는 문제

5 해부도부분마다 붙은 이름

토큰은 --accent: #2f6df6처럼 이름 붙인 값
부품은 토큰을 쓰는 버튼 · 칩 · 입력칸
패턴은 부품을 모은 카드 · 폼 · 표
문서에는 언제 쓰고 언제 안 쓰는지 적음
시안과 코드가 같은 토큰을 참조함
색을 부품마다 박으면 연결이 끊김
  1. 토큰 이름 붙인 값--accent·--space-3처럼 이름을 붙여 두고, 부품에는 값을 직접 쓰지 않습니다
  2. 부품 토큰을 쓰는 조각버튼, 칩, 입력칸 같은 조각입니다
  3. 패턴 부품을 모은 것카드, 폼, 표 같은 화면 단위입니다
  4. 문서 언제 쓰는지문서가 있느냐 없느냐로 디자인 시스템과 컴포넌트 라이브러리가 갈립니다
  5. 같은 토큰 참조 시안과 코드시안과 코드가 같은 토큰을 참조해야 둘이 서로 달라지지 않습니다
  6. 값 박아 두기 hard-coding값을 고친 뒤 어느 부품이 바뀌지 않았는지 알 수 없습니다

디자인 시스템이 실패하는 가장 흔한 이유는 만들어 둔 규칙과 부품이 지켜지지 않아서입니다. 부품을 잘 만들어 두어도 '이럴 때는 어떤 부품을 쓰나'가 적혀 있지 않으면 급한 사람은 부품을 새로 만들어 버립니다. 그래서 문서는 그림에서 네 번째 칸에 있지만 가장 먼저 챙겨야 할 겹입니다. 문서가 길 필요는 없고, 부품마다 '언제 쓴다 / 언제 안 쓴다' 두 줄만 적어 두어도 대부분의 문제가 해결됩니다.

6 쓸 때 / 안 쓸 때

디자인 시스템이 필요한 경우

  • 같은 부품이 여러 화면에 나올 때
  • 사람이 늘어 손으로 맞추기 어려워질 때
  • 브랜드·테마를 통째로 바꿀 일이 있을 때

디자인 시스템을 만들 때 피할 것

  • 화면이 다섯 장뿐인데 시스템부터 만들 때. 화면 수에 비해 일이 과합니다
  • 값을 부품마다 박아 둘 때. 토큰을 고쳐도 부품이 바뀌지 않으니 토큰을 둔 의미가 없어집니다
  • 문서 없이 부품만 만들 때. 사람마다 아무 부품이나 골라 쓰게 됩니다
  • 쓸 사람과 상의하지 않고 혼자 만들 때. 아무도 쓰지 않으면 만든 효과가 없습니다

관련 주제는 다른 항목에서 다룹니다 — 값 하나하나를 정하는 방법은 색 토큰과 간격 체계에서, 부품의 변형은 배리언트에서, 시안을 개발 쪽에 넘기는 일은 핸드오프에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 구조와 규칙토큰과 부품을 나눠 두는 법

토큰은 한 곳에 모아 두고, 부품에서는 값 대신 토큰 이름을 씁니다.

:root {
  /* ① 토큰 — 값에 이름을 붙인다 */
  --accent: #2f6df6;
  --space-3: 12px;
  --radius-1: 6px;
}

/* ② 부품 — 값이 아니라 이름을 쓴다 */
.btn {
  background: var(--accent);      /* ○ */
  padding: var(--space-3);
  border-radius: var(--radius-1);
}
.btn--bad { background: #2f6df6; }   /* ✕ 박아 두면 끊긴다 */

/* ③ 패턴 — 부품을 모은다 */
.store-card { display: grid; gap: var(--space-3); }
지킬 규칙그렇게 하는 이유
토큰은 한 곳에 모으기토큰이 여러 파일에 흩어지면 어느 쪽이 '진짜 값'인지 알 수 없게 됩니다
이름은 쓰임에 따라 짓기--blue-500보다 --accent처럼 쓰임을 이름으로 붙입니다. 다크 모드에서는 강조색이 파랑이 아닐 수도 있기 때문입니다
접근성은 부품에 넣어 두기role과 키보드 동작을 부품에 넣어 두면 그 부품을 쓰는 사람은 따로 손대지 않아도 접근성을 갖추게 됩니다
다크 모드 대응토큰이 있으면 토큰의 값만 바꾸면 되지만, 없으면 색을 쓴 곳을 모두 찾아 고쳐야 합니다
대비비 확인토큰 단계에서 색 조합의 대비비를 한 번 재 두면 부품마다 따로 재지 않아도 됩니다
부품 버전 기록부품을 고치면 그 부품을 쓰는 화면이 모두 바뀌므로 무엇이 바뀌는지 적어 둡니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

토큰을 코드로 한 벌 내보내기시안 도구에 정의한 변수를 CSS 변수나 JSON으로 내보내 코드에서 그대로 쓰면, 값을 손으로 옮겨 적다가 틀리는 일이 없습니다.
부품을 패키지로 묶어 버전 붙이기여러 저장소가 같은 부품 패키지를 쓰면 버전을 붙여 관리해야 합니다. 버전 없이 부품을 고치면 그 패키지를 쓰는 저장소가 모두 한꺼번에 바뀌기 때문입니다.
부품이 쓰인 횟수 세기어느 부품이 어디서 몇 번 쓰이는지 세어 보면 거의 쓰이지 않아 정리해도 되는 부품을 찾을 수 있습니다.
토큰 대신 값을 직접 쓴 곳 찾기#2f6df6 같은 색 값을 코드에서 검색하면 토큰 대신 값을 직접 써서 연결이 끊긴 곳을 바로 찾을 수 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "디자인 시스템 만들어 주세요"라는 요청은 범위를 얼마나 크게 잡느냐에 따라 하루면 끝나는 일도, 반년이 걸리는 일도 됩니다. 가장 적은 품으로 시작하는 방법은 토큰 열 개와 부품 다섯 개를 먼저 만드는 것이고, 부품마다 '언제 쓴다' 두 줄씩만 붙여도 시안과 화면이 어긋나는 일이 대부분 사라집니다. 처음부터 범위를 크게 잡으면 완성되기 전까지는 아무도 그 시스템을 쓰지 않습니다.
