숫자 입력

Number input

type="number" 는 쉬워 보이지만 함정이 많습니다 — 휠로 값이 바뀌고 쉼표를 삼킵니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

데모가 지금 칸의 읽히는 값을 그대로 적습니다 — type="number" 에 쉼표를 넣으면 빈 문자열이 됩니다.
그래서 돈·전화번호처럼 세어서 쓰지 않는 숫자는 text 에 inputmode="numeric" 을 두는 편이 안전합니다 — 폰에서 숫자 자판이 뜨는 것은 똑같습니다.
단위는 칸 밖에 두어야 값만 깨끗하게 남습니다.

type="number" 가 아주 쓸모없는 것은 아닙니다 — 수량이나 나이처럼 세어서 쓰는 작은 수에는 화살표와 범위 검사가 편합니다. 문제는 돈·전화번호·카드번호처럼 '숫자로 생겼지만 계산하지 않는 값'에 쓸 때입니다. 그런 값에는 쉼표·하이픈이 들어가고, 앞의 0 이 뜻을 가지며, 자릿수가 깁니다 — 전부 number 가 잘 못 다루는 것들입니다.
가르는 질문은 하나입니다 — 이 값을 더하거나 뺄 일이 있나. 없으면 text 입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 세어 쓰지 않는 숫자는 text + inputmode="numeric"
  • 단위는 칸 밖에 두기
  • 오른쪽 맞춤 + tabular-nums 로 자릿수 맞추기

이럴 때는 안 쓴다

  • 돈에 type="number" 쓰기 — 쉼표가 값을 지운다
  • 전화번호에 type="number" 쓰기 — 앞의 0이 사라진다
  • 단위를 칸 안에 넣기
  • 휠로 값이 바뀌게 두기 — 굴리다 틀어진다

대신 이걸 — − ＋ 가 붙으면 수량 스테퍼, 하이픈이 들어가면 자동 서식 입력, 범위면 슬라이더, 적는 꼴은 숫자와 단위 쓰기.

9 서버 쪽으로 치면백엔드 감각으로 번역

숫자만 받는다"1,284,000" 이 아니라 1284000 으로 보냅니다 — 서식은 화면의 일입니다.
돈은 정수로소수점 실수로 다루면 반올림 오차가 생깁니다 — 원 단위 정수나 문자열이 안전합니다.
범위min·max 를 서버가 주면 화면이 미리 막을 수 있습니다.
