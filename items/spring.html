스프링

Spring

스프링은 정해진 곡선이 아니라 용수철의 움직임을 계산해서 만드는 애니메이션입니다. 손으로 민 것 같은 느낌을 낼 수 있지만, 끝나는 시점이 미리 정해져 있지 않습니다.

튕김을 0으로 내리면 두 움직임이 거의 같아지고, 끝까지 올리면 글자를 읽기 전에 또 움직입니다. 오른쪽 그래프의 점선이 목표이고, 선이 점선을 넘었다가 돌아오는 모양이 스프링의 특징입니다.

2 이름같은 것을 부르는 여러 이름

한국어스프링, 용수철, 물리 기반 애니메이션
영어spring animation, physics-based animation
같이 쓰는 말목표 쪽으로 세게 당기는 정도를 뻣뻣함(stiffness·tension), 흔들림이 잦아드는 정도를 감쇠(damping·friction), 움직이는 물체의 무게를 질량(mass)이라고 합니다. 목표를 지나치는 것은 오버슈트(overshoot), 흔들림이 잦아들며 자리 잡는 것은 세틀링이라고 부릅니다. 목표를 지나치지 않도록 감쇠를 딱 맞춘 상태는 임계 감쇠(critically damped)입니다.
자주 잘못 부르는 이름바운스 — 튕기는 느낌을 내는 이징 곡선도 있지만, 그건 스프링이 아니라 길이가 정해진 곡선입니다.
이징 — 스프링은 미리 그려 둔 곡선이 아니라 매 프레임 계산해서 움직입니다. cubic-bezier로는 비슷하게 흉내만 낼 수 있습니다.
관성 스크롤 — 손을 뗀 뒤에도 미끄러지듯 계속 움직이는 것은 제스처에서 다룹니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

움직임은 무엇이 바뀌었는지 알려 주는 수단입니다. 아래 네 가지로 서로 가릅니다.

이 항목이 정하는 것사용자가 움직임에서 읽어 내는 것지나치게 쓰면 생기는 일모션 줄이기를 켰을 때
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보임그대로 둠
지속 시간얼마나 걸리는지거리와 크기사용자를 기다리게 함짧게 줄이거나 0으로
진입과 퇴장들고 나는 방식어디서 왔는지닫힐 때까지 붙잡혀 기다림퇴장 시간을 거의 0으로
무엇을 움직이나어떤 속성을 바꾸는지움직임이 매끄러운지화면이 버벅임해당 없음
스프링지나쳤다 돌아오는 정도손으로 민 듯한 느낌어지러움튕김을 0으로
차례로 들어오기줄과 줄 사이의 지연순서와 묶음마지막 줄이 늦게 나타남한꺼번에 띄움
제스처손가락을 따라가는 규칙내가 조작하고 있다는 느낌실수로 닫히기 쉬움그대로 둠
모션 줄이기무엇을 끄는지배려받고 있다는 느낌다 꺼 버려 무엇이 바뀌었는지 알 수 없음이 항목이 그 기준
공유 요소 전환두 화면에 함께 있는 같은 요소어디서 왔는지자리가 어긋나면 오히려 헷갈림자리 이동 없이 전환
스크롤 연동스크롤에 맞춰 움직이는 방식지금 어디쯤 읽고 있는지멀미를 일으킴연출만 끔

스프링을 한 줄로 정리하면 — 끌어서 다루는 것에는 스프링을, 순서대로 이어지는 연출에는 곡선을 씁니다. 끝나는 시점을 알아야 하는 곳에는 스프링이 맞지 않습니다.

4 튕김 정도에 따른 차이튕김에 따라 목표를 지나치는 정도

5 해부도부분마다 붙은 이름

점선인 목표를 한 번 지나침
뻣뻣함(stiffness)은 당기는 힘의 세기
감쇠(damping)는 흔들림이 잦아드는 빠르기
끌던 속도를 그대로 이어받음
끝나는 때가 정해져 있지 않음
  1. 곡선 감쇠 진동목표를 지나쳤다가 돌아옵니다. 용수철이 움직이는 모양입니다
  2. 목표선 1.0점선으로 표시합니다. 이 선에서 바로 멈추지 않고 이 선을 중심으로 흔들리다 멈춥니다
  3. 뻣뻣함 stiffness값이 클수록 목표 쪽으로 빨리 당겨지고, 작으면 느리게 늘어집니다
  4. 감쇠 damping값이 클수록 흔들림이 빨리 잦아들고, 작으면 오래 흔들립니다
  5. 이어받는 속도 initial velocity끌던 손가락의 속도를 그대로 이어받습니다. 스프링을 쓰는 가장 큰 이유입니다
  6. 끝나는 때 정해져 있지 않음목표에 충분히 가까워지면 계산을 멈춥니다. 그래서 몇 ms가 걸릴지 미리 알 수 없습니다

스프링을 쓰는 이유는 보기 좋아서라기보다 끌던 속도를 이어받을 수 있기 때문입니다. 손가락으로 시트를 빠르게 튕기면 시트가 그 속도 그대로 움직이고, 천천히 밀면 천천히 자리를 잡습니다. 손의 속도와 화면의 움직임을 이렇게 이어 주는 일은 길이가 정해진 곡선으로는 할 수 없습니다. 반대로 끝나는 시점을 알아야 하는 곳에는 스프링이 맞지 않습니다. '애니메이션이 끝나면 다음 애니메이션 시작'처럼 이어 붙이는 연출은 길이가 정해진 곡선으로 만드는 편이 쉽습니다.

6 쓸 때 / 안 쓸 때

스프링을 쓰는 경우

  • 시트, 카드 넘기기, 당겨서 새로고침처럼 끌어서 다루는 것을 만들 때
  • 손을 뗀 뒤에 이어지는 움직임을 만들 때
  • 버튼이 살짝 눌렸다 돌아오는 것처럼 작고 자주 보는 누르는 느낌을 낼 때

스프링을 쓰지 않는 경우

  • 읽을 글이 들어 있는 요소에 쓸 때. 글을 읽으려는데 또 움직여서 읽기를 방해합니다
  • 순서대로 이어 붙이는 연출에 쓸 때. 끝나는 시점을 알 수 없어서 다음 연출을 시작할 때를 잡기 어렵습니다
  • 세 번 넘게 흔들리게 할 때. 대부분 과합니다
  • 모션 줄이기를 켠 사람에게 보여 줄 때. 움직임 가운데 흔들림이 가장 어지럽습니다

스프링 대신 쓰거나 함께 볼 것 — 움직임이 끝나는 시점을 알아야 하면 이징 곡선을 씁니다. 손가락을 따라가는 규칙은 제스처에서, 여러 줄이 차례로 들어오게 하는 방법은 차례로 들어오기에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙구현할 때 지킬 최소 규칙

웹에는 표준 스프링이 없어서 매 프레임 직접 계산하거나 라이브러리를 씁니다.

// 감쇠 진동: 목표를 지나쳤다 돌아온다
function spring(el, to, v0) {
  const k = 180, c = 22, m = 1;     // 뻣뻣함 · 감쇠 · 질량
  let x = 0, v = v0 || 0, last = performance.now();

  (function step(now) {
    const dt = Math.min((now - last) / 1000, 0.032); last = now;
    const a = (-k * (x - to) - c * v) / m;
    v += a * dt; x += v * dt;
    el.style.transform = `translateY(${x.toFixed(2)}px)`;
    // 충분히 가까워지고 느려지면 끊는다
    if (Math.abs(x - to) > 0.4 || Math.abs(v) > 0.4) requestAnimationFrame(step);
    else el.style.transform = `translateY(${to}px)`;
  })(last);
}
알아 둘 규칙자세한 내용
웹 표준에 스프링이 없는 점CSS에는 스프링이 없습니다. 대신 linear()로 스프링 곡선을 점으로 찍어 옮기는 방법이 생겼습니다
계산을 멈추는 조건목표까지 거리와 속도가 둘 다 작아졌을 때 멈춥니다. 하나만 보면 제대로 멈추지 않습니다
dt에 상한 두기탭을 다시 열면 dt가 몇 초로 커져서 요소가 한 번에 멀리 튀어 나갑니다
이어받을 속도 구하기pointerup 직전 몇 프레임의 평균 속도를 씁니다. 마지막 한 프레임만 쓰면 값이 튀기 쉽습니다
prefers-reduced-motion목표를 지나치지 않게 튕김을 0으로 내리거나, 움직임 없이 바로 끝 값으로 보냅니다
초점을 옮기는 때스프링이 끝나기를 기다렸다가 초점을 옮기지 않습니다. 언제 끝날지 알 수 없기 때문입니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

화면 쪽에서만 하는 계산모두 화면 쪽에서 계산합니다. 다만 매 프레임 실행되는 코드라서 느린 기기에서는 다른 작업이 늦어집니다.
멈추기를 기다려 요청하지 않기끝나는 시점이 정해져 있지 않기 때문에, 움직임이 멈추기를 기다렸다가 저장하면 저장이 언제 시작될지 알 수 없습니다.
배경 탭에서 멈추는 계산requestAnimationFrame은 배경 탭에서 멈춥니다. 그래서 탭으로 돌아오면 요소를 끝 값으로 바로 보냅니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

앱 플랫폼에서는 스프링이 기본이고, 웹에서만 직접 만들어야 합니다.

웹직접 또는 라이브러리
표준이 없어서 라이브러리(Motion, React Spring)를 쓰거나 직접 계산합니다. linear()로 곡선을 옮겨 넣기도 합니다.
iOSUISpringTimingParameters
시스템 애니메이션 대부분이 스프링입니다. SwiftUI에서는 .spring(response:dampingFraction:)으로 적습니다.
안드로이드SpringAnimation
DynamicAnimation과 Compose의 spring()을 씁니다. 뻣뻣함과 감쇠에는 이름 붙은 기본값이 몇 가지 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "아이폰처럼 자연스럽게 해 주세요"라는 요청은 상당 부분 스프링을 말하는 것입니다. iOS는 시스템 애니메이션 대부분이 스프링이라서 웹에서 곡선만 쓰면 어딘가 다르게 느껴집니다. 다만 웹에는 표준이 없어서 라이브러리를 들이거나 직접 계산해야 하므로, 그만큼 일이 늘어난다는 점을 미리 말해 두는 편이 낫습니다.
