전체 화면 레이어

Full-screen layer

화면처럼 보이지만 화면이 아닙니다 — 뒤에 하던 일이 그대로 있고, 닫으면 돌아옵니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 '새 가게 등록'이라도 넓은 화면에서는 모달, 좁은 화면에서는 전체 화면이 맞습니다 — 390px 에 뜬 모달은 가장자리 여백만 남기고 내용 칸을 더 좁힙니다. 데모가 내용이 쓸 수 있는 폭을 재서 둘을 견줍니다.
전체 화면 레이어는 닫기(✕)이지 뒤로가기가 아니고, 제목 줄에 무엇을 하는 중인지를 적어야 합니다. 기록에 넣어 두면 시스템 백으로도 닫힙니다.

2 이름부르는 말이 여러 개다

한국어전체 화면 레이어, 풀스크린 모달, 전체 화면 시트
영어full-screen layer, full-screen modal, full-screen dialog, modal page
같이 쓰는 말안드로이드에서는 풀스크린 다이얼로그, iOS 에서는 모달 프레젠테이션(fullScreenCover)이라 부릅니다. 폭에 따라 모달과 전체 화면을 바꿔 쓰는 것을 반응형 모달이라 하고, 아래에서 전체 높이까지 올라오는 꼴은 풀 시트입니다.
자주 잘못 부름모달 — 모달은 가림막 위에 작게 뜹니다.
새 화면 — 진짜 화면 전환은 주소가 바뀌고 뒤가 사라집니다.
바텀시트 — 바텀시트는 아래에서 올라오고 보통 덜 덮습니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

화면을 다 덮는다 — 가림막이 안 보인다
닫기(✕)이지 뒤로가기가 아니다
제목 — 무엇을 하는 중인지
주 동작은 오른쪽 위 — 저장 · 완료
기록에 넣으면 시스템 백으로도 닫힌다
화면처럼 보이지만 화면이 아니다 — 뒤가 남아 있다
  1. 다 덮음 가림막 없음뒤가 안 보인다
  2. 닫기 ✕뒤로가 아니다
  3. 제목 무엇을 하는 중'새 가게 등록'
  4. 주 동작 오른쪽 위저장 · 완료
  5. 기록 넣어 두기시스템 백으로도 닫힌다
  6. 화면 아님 뒤가 남음닫으면 돌아온다

✕ 와 ‹ 중 무엇을 둘지가 자주 헷갈립니다 — 전체 화면 레이어는 덮고 올라온 것이니 ✕(닫기) 가 맞습니다. ‹(뒤로) 는 계층을 타고 내려갔을 때 쓰는 표시라, 덮고 올라온 것에 쓰면 '어디로 돌아가는지'가 모호해집니다.
폰에서는 시스템 백으로도 닫히는 것이 기본 기대입니다 — 안 그러면 시스템 백이 레이어를 지나쳐 그 뒤 화면까지 날려 버립니다. 기록에 한 칸을 넣어 두면 그 문제가 통째로 사라집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 좁으면 전체 화면, 넓으면 모달로 바꾸기
  • ✕(닫기) 를 쓰고 주 동작은 오른쪽 위에
  • 기록에 넣어 시스템 백으로도 닫히게 하기

이럴 때는 안 쓴다

  • 폰에서 모달로 띄우기 — 내용 칸이 더 좁아진다
  • ‹(뒤로) 를 쓰기 — 어디로 가는지 모호하다
  • 기록에 안 넣기 — 시스템 백이 뒤 화면까지 지운다
  • 안에서 또 전체 화면을 띄우기 — 겹치면 나올 길이 복잡해진다

대신 이걸 — 가림막 위에 작게 뜨면 모달, 아래에서 올라오면 바텀시트, 진짜 화면 전환이면 주소를 바꾸고, 뒤로가기 처리는 시스템 백.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

같은 <dialog> 를 쓰고 CSS 로만 모양을 바꿉니다.

<dialog id="editor" aria-label="새 가게 등록">
  <header>
    <button aria-label="닫기">✕</button>
    <h2>새 가게 등록</h2>
    <button class="primary">저장</button>
  </header>
  …
</dialog>

/* 좁으면 전체 화면, 넓으면 모달 — 마크업은 하나다 */
dialog { width: min(520px, calc(100% - 48px)); border-radius: var(--radius-4); }
@media (max-width: 480px) {
  dialog { width: 100%; max-width: none; height: 100dvh;
    max-height: none; margin: 0; border-radius: 0; }
}
키일어나야 하는 일
Esc닫는다 — 저장은 안 된다
Tab레이어 안에 갇힌다
초점열면 닫기나 첫 칸, 닫으면 부른 자리로
aria-modal="true"뒤가 안 읽힌다고 알린다
100dvh폰 주소창이 숨어도 안 흔들린다
확인하는 법폰 폭에서 열고 시스템 백을 눌러 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

초안 저장긴 폼이면 중간 저장을 두어 닫혀도 안 날아가게 합니다.
닫을 때 확인적은 것이 있으면 그냥 닫지 않고 한 번 묻습니다 — 위험한 동작과 같은 생각입니다.

Material 에 정식 부품으로 있습니다 — 왼쪽 ✕, 오른쪽 저장이 규격입니다.

자주 생기는 사고 — Material 의 풀스크린 다이얼로그는 머리 줄 규격까지 정해 두었습니다 — 왼쪽에 ✕, 가운데 제목, 오른쪽에 저장. 웹에서 그대로 따라도 어색하지 않고, 무엇을 하는 중이고 어떻게 빠져나가는지가 한 줄에 다 들어갑니다. 이 꼴을 쓰면 '이게 화면인가 레이어인가'를 사용자가 헷갈릴 일도 줄어듭니다.
