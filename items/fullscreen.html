전체 화면 레이어

Full-screen layer

전체 화면 레이어는 화면 전체를 덮기 때문에 새 화면처럼 보이지만 실제로 화면이 바뀐 것은 아닙니다. 뒤에 하던 화면이 그대로 남아 있어서, 레이어를 닫으면 그 화면으로 돌아옵니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 '새 가게 등록'이라도 넓은 화면에서는 모달로, 좁은 화면에서는 전체 화면으로 띄우는 것이 맞습니다. 390px 폭에 모달을 띄우면 모달 둘레에 여백이 생기는 만큼 내용을 담을 칸이 더 좁아지기 때문입니다. 데모는 두 방식에서 내용이 쓸 수 있는 폭을 재서 비교합니다.
전체 화면 레이어에는 뒤로가기(‹)가 아니라 닫기(✕) 단추를 두고, 제목 줄에는 무엇을 하는 중인지 적어야 합니다. 또 레이어를 열 때 기록에 한 칸을 넣어 두면 시스템 백으로도 닫힙니다.

2 이름같은 것을 부르는 여러 이름

한국어전체 화면 레이어, 풀스크린 모달, 전체 화면 시트
영어full-screen layer, full-screen modal, full-screen dialog, modal page
같이 쓰는 말안드로이드에서는 풀스크린 다이얼로그, iOS에서는 모달 프레젠테이션(fullScreenCover)이라고 부릅니다. 화면 폭에 따라 모달과 전체 화면을 바꿔 쓰는 방식은 반응형 모달이라고 하고, 아래에서 화면 높이 끝까지 올라오는 모양은 풀 시트라고 합니다.
자주 잘못 부르는 이름모달 — 화면을 다 덮지 않고 가림막 위에 작게 뜨면 모달입니다.
새 화면 — 실제로 화면이 바뀌면 주소가 바뀌고 앞의 화면은 사라집니다. 전체 화면 레이어는 뒤의 화면이 남아 있다는 점이 다릅니다.
바텀시트 — 화면 아래에서 올라오고 보통 화면을 다 덮지 않으면 바텀시트입니다.

5 해부도부분마다 붙은 이름

화면을 다 덮어 가림막이 보이지 않음
뒤로가기가 아니라 닫기(✕)를 둠
제목으로 무엇을 하는 중인지 알림
저장 · 완료 같은 주 동작은 오른쪽 위에
기록에 넣으면 시스템 백으로도 닫힘
새 화면처럼 보여도 뒤 화면이 남아 있음
  1. 덮는 범위 화면 전체, 가림막 없음화면을 다 덮어서 뒤의 화면이 보이지 않습니다
  2. 닫기 ✕뒤로가기(‹)가 아니라 닫기 단추(✕)를 둡니다
  3. 제목 무엇을 하는 중인지'새 가게 등록'처럼 지금 무엇을 하는 중인지 적습니다
  4. 주 동작 오른쪽 위저장이나 완료 같은 주 동작은 오른쪽 위에 둡니다
  5. 기록 기록에 넣어 두기열 때 기록에 한 칸을 넣어 두면 시스템 백으로도 닫힙니다
  6. 뒤에 남은 화면 닫으면 돌아옴뒤의 화면이 그대로 남아 있어서 닫으면 그 화면으로 돌아옵니다

✕와 ‹ 중 무엇을 둘지 자주 헷갈리는데, 전체 화면 레이어는 지금 화면 위를 덮고 올라온 것이므로 ✕(닫기)가 맞습니다. ‹(뒤로)는 계층을 따라 한 단계 아래 화면으로 들어갔을 때 쓰는 표시입니다. 그래서 덮고 올라온 레이어에 ‹를 쓰면 누를 때 어디로 돌아가는지 알기 어려워집니다.
폰 사용자는 시스템 백을 눌러도 레이어가 닫히기를 기대합니다. 그런데 레이어를 기록에 넣지 않으면 시스템 백이 레이어를 닫는 대신 그 뒤의 화면까지 벗어나 버립니다. 레이어를 열 때 기록에 한 칸을 넣어 두면 시스템 백이 레이어만 닫기 때문에 이 문제가 생기지 않습니다.

6 쓸 때 / 안 쓸 때

전체 화면 레이어를 만들 때 지킬 것

  • 화면이 좁으면 전체 화면, 넓으면 모달로 바꾸기
  • ✕(닫기)를 쓰고 주 동작은 오른쪽 위에 두기
  • 기록에 넣어 시스템 백으로도 닫히게 하기

전체 화면 레이어를 만들 때 피할 것

  • 폰에서 모달로 띄우기. 둘레 여백 때문에 내용 칸이 더 좁아집니다
  • ‹(뒤로)를 쓰기. 누르면 어디로 가는지 알기 어렵습니다
  • 기록에 넣지 않기. 시스템 백을 누르면 뒤의 화면까지 벗어납니다
  • 레이어 안에서 전체 화면을 또 띄우기. 레이어가 겹치면 빠져나오는 길이 복잡해집니다

전체 화면 레이어 대신 다른 것을 써야 하는 경우 — 가림막 위에 작게 띄우려면 모달을 쓰고, 화면 아래에서 올라오게 하려면 바텀시트가 맞습니다. 실제로 화면을 바꾸는 것이라면 레이어 대신 주소를 바꾸고, 뒤로가기 처리는 시스템 백에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

마크업은 <dialog> 하나를 그대로 쓰고, 화면 폭에 따라 CSS로만 모양을 바꿉니다.

<dialog id="editor" aria-label="새 가게 등록">
  <header>
    <button aria-label="닫기">✕</button>
    <h2>새 가게 등록</h2>
    <button class="primary">저장</button>
  </header>
  …
</dialog>

/* 좁으면 전체 화면, 넓으면 모달. 마크업은 하나로 둔다 */
dialog { width: min(520px, calc(100% - 48px)); border-radius: var(--radius-4); }
@media (max-width: 480px) {
  dialog { width: 100%; max-width: none; height: 100dvh;
    max-height: none; margin: 0; border-radius: 0; }
}
키와 마크업그때 일어나야 하는 일
Esc레이어를 닫습니다. 이때 적던 내용은 저장되지 않습니다
Tab초점이 레이어 밖으로 나가지 않고 안에서만 돕니다
열고 닫을 때의 초점열면 초점을 닫기 단추나 첫 입력 칸으로 옮기고, 닫으면 레이어를 부른 자리로 돌려놓습니다
aria-modal="true"보조 기술에 뒤의 화면은 읽히지 않는다고 알립니다
100dvh폰에서 주소창이 숨어도 레이어 높이가 흔들리지 않습니다
확인하는 방법폰 폭에서 레이어를 열고 시스템 백을 눌러 레이어만 닫히는지 확인합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

적던 내용을 초안으로 저장하기폼이 길면 중간 저장을 두어, 레이어가 닫혀도 적던 내용이 사라지지 않게 합니다.
닫기 전에 한 번 묻기사용자가 적은 내용이 있으면 그냥 닫지 않고 닫을지 한 번 묻습니다. 위험한 동작을 확인받는 것과 같은 이유입니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

폰에서는 모달보다 전체 화면 레이어가 기본입니다.

웹<dialog> + 미디어 쿼리
✕새 가게 등록저장

✕
아래로 쓸어 닫는 시트가 기본이고, 화면을 완전히 덮는 방식도 따로 있습니다.
안드로이드Full-screen dialog

저장
Material에 정식 부품으로 있고, 머리 줄 왼쪽에 ✕, 오른쪽에 저장을 두는 것이 규격입니다.

플랫폼 차이 때문에 자주 생기는 문제 — Material의 풀스크린 다이얼로그는 머리 줄 규격까지 정해 두었는데, 왼쪽에 ✕, 가운데에 제목, 오른쪽에 저장을 둡니다. 이 배치는 웹에서 그대로 따라 써도 어색하지 않고, 무엇을 하는 중이고 어떻게 빠져나가는지를 머리 줄 한 줄에 모두 보여 줍니다. 그래서 이 배치를 쓰면 지금 보는 것이 새 화면인지 레이어인지 사용자가 헷갈릴 일도 줄어듭니다.
