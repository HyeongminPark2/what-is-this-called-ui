폰 키보드

Software keyboard

폰 키보드는 올라오면 화면의 절반쯤을 덮기 때문에, 그 자리에 있던 입력칸과 버튼은 모두 키보드에 가려집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

입력칸 누르기로 키보드를 올려 보세요. 한글 키보드는 자동완성 줄까지 더해 화면의 절반을 덮습니다.
기본 상태에서는 저장 버튼이 키보드 뒤에 가려져서, 글자를 다 쳐도 저장할 방법이 없습니다. visualViewport로 버튼을 키보드 위로 올리기를 켜면 바닥에 붙어 있던 버튼이 키보드 위로 올라옵니다.

2 이름같은 것을 부르는 여러 이름

한국어폰 키보드, 소프트 키보드, 가상 키보드, 화상 키보드
영어software keyboard, on-screen keyboard, virtual keyboard, IME
같이 쓰는 말브라우저 창 안에서 실제로 보이는 영역을 비주얼 뷰포트(visual viewport)라고 하며 window.visualViewport로 크기를 읽습니다. 한글이나 일본어처럼 글자를 조합해 넣는 장치는 IME(입력기)라고 하고, 조합이 시작되고 끝날 때 compositionstart와 compositionend 이벤트가 옵니다. 엔터 키에 적히는 말은 enterkeyhint 속성으로 정합니다.
자주 잘못 부르는 이름뷰포트 — 뷰포트 단위의 dvh에는 키보드가 덮은 높이가 반영되지 않으므로, 키보드는 뷰포트 단위와 따로 다뤄야 하는 문제입니다.
리사이즈 — 키보드가 올라와도 window.resize 이벤트가 오지 않는 기기가 있습니다.
키보드 조작 — 키보드 조작은 PC에서 Tab과 Enter로 화면을 다루는 이야기라서 이 항목과는 다른 주제입니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

PC와 폰은 기계보다 쓰는 전제가 다릅니다. 아래 네 가지로 두 환경을 견줍니다.

두 환경에서 다른 점폰에서는PC에서는챙기지 않으면 생기는 일
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 배치가 깨짐
터치 타깃누를 수 있는 넓이44px 이상24px도 괜찮음옆의 것이 눌림
호버가 없는 세계올려놓기가 되는지안 됨됨끝내 볼 수 없는 정보가 생김
시스템 백뒤로 가는 길OS가 제공함브라우저의 ← 버튼모달 대신 앱이 꺼짐

HIG와 Material의 차이OS마다 다른 관례OS마다 다름웹 관례를 따름어느 쪽에서도 어색함

폰 키보드를 한 줄로 정리하면 — 키보드가 올라와도 창 크기는 바뀌지 않습니다. 그래서 position: fixed로 바닥에 붙인 것은 제자리에 남은 채 키보드 뒤에 가려집니다.

4 키보드가 올라올 때 생기는 일키보드에 가려지는 것

5 해부도부분마다 붙은 이름

키보드가 화면의 절반을 덮음 (자동완성 줄 포함)
position: fixed로 붙인 것은 키보드 뒤에 가려짐
visualViewport.height는 지금 보이는 높이
바닥 버튼을 그만큼 올림
inputmode·enterkeyhint로 키보드 모양을 정함
포커스가 간 칸은 scrollIntoView로 끌어 올림
  1. 덮는 높이 화면의 45~55%한글 키보드는 위에 자동완성 줄이 붙어서 더 높습니다
  2. fixed로 붙인 요소 position: fixed키보드가 올라와도 창 크기가 바뀌지 않으므로 제자리에 남아 키보드 뒤에 가려집니다
  3. 지금 보이는 높이 visualViewport.height키보드에 덮이지 않고 보이는 높이를 알려 주는, 유일하게 믿을 만한 값입니다
  4. 올려 주기 bottom: 덮인 높이바닥에 붙은 것을 키보드가 덮은 높이만큼 올립니다
  5. 키보드 모양 inputmode · enterkeyhint숫자를 넣는 칸에 글자 키보드가 뜨면 사용자가 키보드를 직접 바꿔야 해서 번거롭습니다
  6. 포커스 따라가기 scrollIntoView키보드를 올려도 글자를 치고 있는 칸이 보이지 않으면 무엇을 쳤는지 확인할 수 없습니다

키보드가 올라올 때 화면이 어떻게 바뀌는지는 기기마다 다릅니다. 안드로이드 크롬은 기본적으로 창을 줄이고 resize 이벤트를 보내지만, iOS 사파리는 창 크기를 그대로 두고 보이는 영역만 밀어 올립니다. 그래서 window.innerHeight로 재면 iOS에서는 값이 바뀌지 않습니다. 두 브라우저에서 같은 답을 주는 것은 visualViewport뿐이고, 이 차이 때문에 "내 폰에서는 되는데"라는 말이 가장 자주 나옵니다.

6 쓸 때 / 안 쓸 때

폰 키보드를 챙겨야 하는 화면

  • 바닥에 버튼이 붙는 폼을 만들 때. 키보드에 버튼이 가려지는 일이 가장 자주 생깁니다
  • 채팅처럼 입력칸이 아래에 있는 화면을 만들 때
  • 긴 폼을 만들 때. 포커스가 간 칸을 보이는 자리로 끌어 올립니다

폰 키보드를 다룰 때 피할 것

  • 100dvh만 쓰면 해결된다고 여길 때. 키보드가 덮은 높이는 dvh에 반영되지 않습니다
  • window.resize 이벤트만 기다릴 때. iOS에서는 이 이벤트가 오지 않습니다
  • 숫자를 넣는 칸에 글자 키보드를 띄울 때. inputmode 한 줄이면 숫자 키보드가 뜹니다
  • 키보드를 강제로 내릴 때. 글자를 치려던 사용자가 다시 칸을 눌러야 합니다

관련 주제는 다른 항목에서 다룹니다 — 화면 높이를 다루는 법은 뷰포트 단위에서, 입력칸을 묶는 법은 폼 설계에서 설명합니다. 바닥에 고정하는 법은 스티키 항목을 봅니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 지킬 규칙빠뜨리기 쉬운 설정까지 담은 규칙

visualViewport로 키보드가 덮은 높이를 재고, 바닥에 붙은 것을 그만큼 올립니다.

<input inputmode="numeric" enterkeyhint="next"
       autocomplete="tel" name="phone">

// 키보드가 덮은 높이를 잰다. 두 OS에서 같은 값이 나온다
const vv = window.visualViewport;
function fit() {
  const covered = window.innerHeight - vv.height - vv.offsetTop;
  document.documentElement.style.setProperty('--kbd', Math.max(covered, 0) + 'px');
}
vv.addEventListener('resize', fit);
vv.addEventListener('scroll', fit);
fit();

/* 바닥 막대를 그만큼 올린다 */
.cta-bar { position: fixed; bottom: calc(var(--kbd, 0px) + env(safe-area-inset-bottom)); }
지킬 규칙지키는 방법과 까닭
inputmode로 키보드 모양 바꾸기numeric·tel·email·decimal 같은 값을 주며, 키보드 모양만 바꿉니다
type과 구분하기type="number"는 값까지 숫자로 다루기 때문에 맨 앞의 0이 사라집니다. 전화번호나 계좌번호에는 inputmode만 씁니다
enterkeyhint로 엔터 키 글자 바꾸기next·done·send 같은 값을 주면 엔터 키에 적히는 말이 바뀝니다
autocomplete 달기이름, 전화번호, 주소를 자동으로 채워 줍니다. 폰에서는 글자를 치기가 번거로워서 효과가 특히 큰 한 줄입니다
한글을 조합하는 동안compositionstart부터 compositionend까지는 input 이벤트마다 검사하지 않습니다. 검사하면 조합 중인 글자를 틀렸다고 표시하게 됩니다
env(safe-area-inset-bottom) 더하기키보드 높이에 함께 더합니다. 자세한 내용은 세이프 에어리어를 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버 확인 요청을 보내는 시점한글을 조합하는 도중에 서버로 확인 요청을 보내면 조합이 덜 된 글자가 전송됩니다. 요청은 compositionend 뒤에 보냅니다.
자동완성으로 채운 값 읽기브라우저가 자동으로 채운 값은 input 이벤트 없이 들어오기도 하므로, 값은 제출할 때 다시 읽습니다.
폰에서 짧아지는 입력폰 키보드는 치기가 불편해서 사용자가 글을 짧게 적습니다. 폰에서는 긴 메모 칸이 거의 빈 채로 들어오므로, 이런 칸은 필수로 두지 않습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

키보드가 화면을 덮는 방식이 OS마다 달라서, 같은 코드라도 OS에 따라 다르게 움직입니다.

웹visualViewport
키보드가 올라올 때 창 크기가 바뀌는지는 브라우저마다 다르고, visualViewport만 양쪽에서 같은 값을 줍니다.
iOS창을 줄이지 않음
창 크기는 그대로 두고 보이는 영역만 밀어 올리기 때문에, innerHeight 값은 바뀌지 않습니다.
안드로이드창을 줄임
기본적으로 창을 줄이고 resize 이벤트를 보냅니다. 앱에서는 windowSoftInputMode 설정으로 동작을 고릅니다.

플랫폼 차이 때문에 자주 생기는 문제 — "폰에서 저장 버튼이 안 보여요"라는 문제는 PC에서 재현되지 않고, 개발자 도구의 기기 흉내 모드에서도 키보드가 뜨지 않습니다. 입력칸이 있는 화면은 실제 폰에서 한 번 열어 보는 것 말고는 확인할 방법이 없지만, 그 한 번만으로도 문제를 대부분 찾을 수 있습니다.
