버튼 위계

Button hierarchy

버튼 위계는 화면에서 사용자의 눈이 어느 버튼으로 먼저 가는지를 정하는 일입니다. 진한 버튼이 둘이면 어느 쪽으로도 눈이 먼저 가지 않아서 둘 다 주 동작으로 읽히지 않습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

주 버튼 수를 늘려 보세요. 데모가 가장 진한 버튼이 몇 개인지 세어서, 둘을 넘으면 '어느 것이 주 동작인지 알 수 없다'고 적습니다.
위험한 동작을 주 버튼으로를 켜면 가장 눈에 띄는 자리에 '지우기'가 오는데, 그 자리는 실수로 누르기도 가장 쉬운 곳입니다.
주 동작을 왼쪽과 오른쪽 중 어느 쪽에 둘지는 한 서비스 안에서 한쪽으로 고정해야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어버튼 위계, 버튼 단계, 주 버튼 · 보조 버튼
영어button hierarchy, primary/secondary button, call to action
같이 쓰는 말가장 진한 버튼은 프라이머리, 테두리만 있는 버튼은 세컨더리·아웃라인, 바탕도 테두리도 없는 버튼은 텍스트 버튼·고스트라고 부릅니다. 되돌릴 수 없는 일에 쓰는 빨간 버튼은 데스트럭티브(destructive), 그 화면에서 사용자가 가장 해 주기를 바라는 동작은 CTA(call to action)라고 합니다.
자주 잘못 부르는 이름색 — 위계를 가르는 것은 색이 아니라 세기입니다. 같은 파랑이라도 바탕을 채우면 주 버튼, 테두리만 두르면 보조 버튼입니다.
크기 — 버튼 크기로 위계를 나누면 작은 버튼이 터치 타깃 기준에 못 미치게 됩니다.
링크 — 링크와 버튼은 세기가 아니라 뜻이 다릅니다.

4 해부도부분마다 붙은 이름

주 버튼은 한 화면에 하나만
보조 버튼은 테두리만 그림
텍스트 버튼은 가장 약하게 표시
위험한 동작은 빨갛게 하되 주 버튼으로 두지 않음
주 동작은 늘 같은 쪽에 둠
진한 버튼이 둘이면 주 동작을 알 수 없음
  1. 주 버튼 한 화면에 하나한 화면에 하나만 둡니다
  2. 보조 버튼 테두리만 그림주 동작과 함께 놓이는 동작에 씁니다
  3. 텍스트 버튼 가장 약한 단계덜 중요한 동작에 씁니다
  4. 위험한 동작 빨간색이지만 약한 세기주 버튼으로 두지 않습니다
  5. 주 동작의 자리 늘 같은 쪽화면마다 자리가 바뀌면 사용자가 헷갈립니다
  6. 진한 버튼이 둘일 때 주 동작이 드러나지 않음둘 중 하나를 보조 버튼으로 내립니다

'둘 다 중요하니 둘 다 진하게' 두는 것이 가장 흔한 실수입니다. 그런데 두 버튼이 똑같이 진하면 사용자의 눈이 어느 쪽으로도 먼저 가지 않아서, 결국 둘 다 평범한 버튼과 다를 바 없어집니다. 정말 둘 다 중요하다면 둘을 함께 진하게 두지 말고 화면을 나눠 화면마다 주 동작을 하나씩 두는 편이 낫습니다.
위험한 동작을 주 버튼으로 두는 경우도 자주 보는데, 그렇게 해도 되는 곳은 되묻는 창 안뿐입니다. 목록이나 상세 화면에서는 '지우기'가 가장 눈에 띄면 안 됩니다.

5 쓸 때 / 안 쓸 때

버튼 위계를 잡을 때 지킬 것

  • 한 화면에는 진한 버튼을 하나만 두기
  • 위험한 동작은 빨간색으로 하되 약하게 표시하기
  • 주 동작의 좌우 자리를 서비스 안에서 고정하기

버튼 위계를 잡을 때 피할 것

  • 진한 버튼을 둘 두기. 어느 쪽도 주 동작으로 읽히지 않습니다
  • 크기로 위계 나누기. 작은 버튼은 손가락으로 누르기 어렵습니다
  • '지우기'를 주 버튼으로 두기(확인 창 제외)
  • 화면마다 자리를 바꾸기

함께 보면 좋은 항목 — 이동과 동작처럼 뜻을 가르는 문제는 링크와 버튼에서, 버튼에 다른 동작 갈래가 붙는 경우는 분할 버튼에서 다룹니다. 되돌릴 수 없는 일을 다루는 방법은 위험한 동작, 버튼 색 자체를 정하는 기준은 상태 색 항목에 있습니다.

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

버튼의 세기는 클래스 하나로 나눕니다. 색을 버튼마다 따로 적지 않습니다.

<button class="btn btn--primary">저장</button>
<button class="btn">취소</button>
<button class="btn btn--text">도움말</button>
<button class="btn btn--danger">지우기</button>

.btn { background: var(--color-bg-surface); color: var(--color-text);
  border: 1px solid var(--color-border); min-height: 44px; }
.btn--primary { background: var(--color-bg-brand); color: var(--color-text-onbrand);
  border-color: transparent; }
.btn--text    { background: none; border-color: transparent; color: var(--color-text-brand); }
.btn--danger  { color: var(--color-text-danger); border-color: var(--color-border-danger); }
키와 마크업그때 일어나야 하는 일
Tab세기와 상관없이 마크업 순서대로 멈춥니다
Enter · Space버튼을 누릅니다. <button> 요소라면 따로 만들지 않아도 저절로 동작합니다
type="button"폼 안에서는 꼭 적어 둡니다. 적지 않으면 버튼을 눌렀을 때 폼이 제출됩니다
autofocus쓰지 않습니다. 사용자가 보던 곳에서 초점을 가져가 버립니다
44px세기를 낮춰도 크기는 줄이지 않습니다
위계를 확인하는 방법화면을 흑백으로 바꿔도 어느 것이 주 버튼인지 보인다면 위계를 잘 나눈 것입니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

사용자에게 권한이 있는지사용자에게 권한이 없으면 단추를 아예 지웁니다. 흐리게만 두면 사용자가 '왜 안 되나'를 묻게 됩니다.
두 번 눌리지 않게 막기주 버튼은 요청을 보내는 동안 잠가 두어 두 번 눌리지 않게 합니다. 이 처리는 성공 확인과 함께 설계합니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼이 달라도 버튼의 세기를 나누는 방식은 같고, 단계의 이름만 다릅니다.

웹CSS 클래스로 구분
저장취소
표준으로 정해진 이름이 없어서 팀마다 다르게 부르므로, 팀 안에서 이름을 먼저 정해 두는 편이 낫습니다.
iOSborderedProminent 등
.borderedProminent · .bordered · .plain 세 단계가 있습니다.
안드로이드Filled · Outlined · Text
Material 지침이 Filled · Tonal · Outlined · Text · Elevated 다섯 단계를 정해 두었습니다.

플랫폼 차이 때문에 자주 생기는 문제 — Material 의 다섯 단계는 많아 보이지만, 그 가운데 토널(연한 바탕) 버튼은 실제로 쓸모가 큽니다. 주 버튼만큼 세지 않으면서도 테두리만 있는 버튼보다는 눈에 잘 띄기 때문입니다. 웹에서도 단계를 하나 더 둔다면 토널 버튼이 가장 쓸 만합니다. 다만 단계가 늘수록 어느 것을 쓸지 고민도 늘어나므로, 세 단계로 시작해 모자랄 때 늘리는 편이 좋습니다.
