일괄 선택

Bulk selection

일괄 선택은 여러 건을 골라 한꺼번에 처리하는 장치입니다. 일괄 선택에서 생기는 사고는 대부분 '전체'가 어디까지를 뜻하는지 사용자와 화면이 서로 다르게 이해해서 일어납니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

줄을 일부만 골라 보세요. 맨 위 체크박스가 반쯤 켜진 모양(indeterminate)이 되는데, 체크박스에 켜짐·꺼짐 말고 세 번째 상태가 있다는 것을 알아야 만들 수 있는 모양입니다.
맨 위 체크박스로 전체를 고르면 '이 쪽 5건'과 '조건에 맞는 128건' 가운데 어느 쪽인지 묻는 줄이 뜹니다. 이 질문이 없으면 사용자는 실제로 128건을 지우고도 5건만 지웠다고 알고 넘어갈 수 있습니다.

2 이름같은 것을 부르는 여러 이름

한국어일괄 선택, 다중 선택, 묶음 처리
영어bulk selection, multi-select, batch action
같이 쓰는 말줄을 고른 뒤 뜨는 막대는 벌크 액션 바·선택 툴바·컨텍스추얼 액션 바라고 부릅니다. 맨 위 체크박스는 전체 선택(select all), 일부만 골랐을 때 맨 위 체크박스가 반쯤 켜진 상태는 인디터미닛(indeterminate)이라고 합니다.
자주 잘못 부르는 이름체크박스 — 체크박스는 부품 하나이고, 일괄 선택은 체크박스와 동작 막대가 여러 줄에 걸쳐 함께 움직이는 장치입니다.
필터 — 필터는 화면에 보이는 건을 줄이고, 일괄 선택은 처리할 건을 고릅니다. 필터로 걸러 놓고 전체 선택을 하면 두 기능을 함께 쓰게 됩니다.
멀티 셀렉트 — 입력 부품에서 여러 값을 고르는 멀티 셀렉트와는 다른 장치입니다.

일괄 선택을 한 줄로 정리하면 — 만들기 전에 '전체 선택'이 지금 쪽만인지, 조건에 맞는 전부인지부터 정하세요. 이것을 정하지 않으면 사용자가 생각보다 훨씬 많은 건을 지우거나 바꾸는 일이 생기고, 그 결과는 되돌리기 어렵습니다.

4 상태맨 위 체크박스의 세 가지 상태

5 해부도부분마다 붙은 이름

가맹점
indeterminate는 일부만 골랐을 때의 세 번째 모양
5건 선택됨승인내보내기
'이 쪽 5건'과 '조건에 맞는 128건'은 범위가 다름
쪽을 넘길 때 선택을 풀지 먼저 정함
처리가 끝나면 "5건 승인됨 · 되돌리기"
  1. 맨 위 체크박스 select all지금 보이는 쪽만 고릅니다. 조건에 맞는 전부를 고르는 것이 아닙니다
  2. 반쯤 켜진 모양 indeterminateel.indeterminate = true처럼 HTML 속성이 아니라 자바스크립트로만 켤 수 있습니다
  3. 동작 막대 bulk action bar고른 것이 있을 때만 띄우고, 고른 건수를 적습니다
  4. 범위를 묻는 줄 this page / all'이 쪽 5건'과 '조건에 맞는 128건'은 범위가 다르므로 어느 쪽인지 묻습니다
  5. 쪽을 넘길 때 선택 유지 여부선택을 유지하면 화면에 보이지 않는 선택이 생기고, 풀면 지금까지 고른 것이 사라집니다. 어느 쪽으로 할지 정해서 화면에 적어 둡니다
  6. 결과와 되돌리기 undo묶음 처리는 되돌릴 수 있어야 사용자가 안심하고 씁니다

일괄 선택을 설계할 때 가장 주의할 점은 '전체 선택'이 두 가지 뜻으로 읽힌다는 것입니다. 맨 위 체크박스는 거의 언제나 지금 보이는 쪽만 고르는데, 사용자는 이것을 조건에 맞는 전부를 고른 것으로 받아들입니다. 그래서 지메일과 깃허브 같은 서비스는 모두 전체를 켠 뒤 "조건에 맞는 128건 모두 고르기"라는 줄을 따로 띄웁니다. 묻지 않고 범위를 넓히면 사용자는 128건을 지우고도 5건만 지웠다고 생각합니다.

6 쓸 때 / 안 쓸 때

일괄 선택을 쓰는 경우

  • 승인, 내보내기, 태그 달기처럼 같은 동작을 여러 건에 되풀이할 때
  • 건수가 많아서 하나씩 누르기에는 너무 번거로울 때
  • 되돌릴 수 있는 동작일 때. 되돌리기가 없으면 범위를 더 좁게 묻습니다

일괄 선택을 쓰지 않는 경우

  • 건수가 서너 개일 때. 줄마다 버튼을 두는 편이 더 빠릅니다
  • 되돌릴 수 없는 삭제에 '전체 선택'을 붙일 때. 적어도 사용자가 건수를 직접 입력하게 합니다
  • 고른 것이 없는데 동작 막대를 띄울 때
  • 쪽을 넘겼을 때 선택이 아무 안내 없이 풀릴 때

일괄 선택 대신 다른 것을 써야 하는 경우 — 한 건씩만 처리하면 되는 경우에는 줄 안의 카드나 메뉴 버튼으로 충분하고, 목록을 거르기만 하려면 필터를 씁니다. 처리하기 전에 사용자의 확인을 받아야 하면 다이얼로그를 띄웁니다.

8 최소 마크업과 키보드일괄 선택을 만들 때 꼭 갖출 것

indeterminate는 HTML 속성이 아니라 자바스크립트 프로퍼티입니다.

<input type="checkbox" id="all" aria-label="이 쪽 전체 선택">
…
<div role="status">5건 선택됨</div>

// 세 번째 상태는 속성으로 못 켠다
const n = rows.filter(r => r.checked).length;
all.checked = n === rows.length;
all.indeterminate = n > 0 && n < rows.length;

// 범위를 넓힐 때는 묻는다
if (all.checked && total > rows.length) showScopeBanner(total);
키와 마크업그때 일어나야 하는 일
Space체크박스를 켭니다. <input type="checkbox">를 쓰면 따로 만들지 않아도 됩니다
Shift+클릭마지막으로 누른 줄과 지금 누른 줄 사이를 전부 고릅니다. 긴 목록에서는 거의 반드시 있어야 하는 기능입니다
indeterminate스크린 리더는 'mixed'로 읽습니다. 자바스크립트로만 켤 수 있고, 사용자가 체크박스를 누르면 사라집니다
aria-label맨 위 체크박스에 답니다. 글자 없이 빈 칸만 있으면 무엇을 고르는 체크박스인지 알 수 없습니다
role="status"'5건 선택됨'처럼 알립니다. 동작 막대가 떠도 화면을 보지 않는 사람은 알아챌 수 없기 때문입니다
막대가 떠도 포커스는 그대로 두기포커스가 고르던 자리에 그대로 있어야 다음 줄을 이어서 고를 수 있습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

'전체'는 ID 목록 대신 조건으로 보내기128건의 ID를 전부 담아 보내면 건수가 늘수록 요청이 지나치게 커집니다. {"filter":{"status":"pending"}}처럼 조건을 보내고 대상은 서버가 고르게 합니다.
일부만 성공했을 때 알려 주기128건 가운데 3건이 실패하면 어느 건이 실패했는지 돌려줘야 합니다. 일부 실패를 허용할지, 전부 성공하거나 전부 실패하도록 묶을지도 미리 정해야 합니다.
오래 걸리는 묶음 처리수천 건이면 요청 하나가 끝나기를 기다릴 수 없습니다. 서버가 작업 번호를 먼저 돌려주고, 화면은 그 번호로 진행률을 따로 묻게 합니다.
되돌리기를 위한 기록묶음 처리를 되돌리려면 처리 전 상태를 기록해 두어야 합니다. 기록 없이 처리한 뒤에는 되돌리기 기능을 붙이기가 거의 불가능합니다.
버튼이 두 번 눌리는 문제동작 막대의 버튼도 두 번 눌릴 수 있습니다. 폼에서처럼 요청마다 고유 키를 붙입니다.

플랫폼 차이 때문에 자주 생기는 문제 — "여러 개 골라서 한 번에 처리"하는 기능을 요청받으면 되돌리기가 되는지부터 물어보세요. 되돌릴 수 있으면 선택 범위를 넓게 열어 줘도 되지만, 되돌릴 수 없으면 '조건에 맞는 전부'를 아예 막거나 건수를 직접 입력하게 하는 편이 낫습니다. 되돌리기는 처리 전 상태를 기록하는 구조가 필요해서 나중에 덧붙이기가 가장 어려운 기능입니다.
