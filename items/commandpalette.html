커맨드 팔레트

Command palette

커맨드 팔레트는 글자를 쳐서 기능을 찾는 메뉴입니다. 기능이 수십 개를 넘어가면 메뉴를 하나씩 여는 것보다 빠르지만, 팔레트가 있는 줄 모르는 사람은 그 안의 기능을 쓸 수 없습니다.

① 실물② 이름③ 상태④ 해부도⑤ 쓸 때⑥ 사례⑦ 마크업⑧ 백엔드 메모⑨ 플랫폼

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

팔레트를 열고 정내처럼 글자를 띄엄띄엄 쳐 보세요. '띄엄띄엄 쳐도 찾기'를 켜 두면 정산 내역 내보내기가 목록에 잡히고, 끄면 잡히지 않습니다. 데모는 두 방식으로 찾은 개수를 모두 세어 보여 줍니다.
아무것도 치지 않았을 때 목록에 무엇이 보이는지도 중요합니다. 최근 쓴 것을 먼저 보여 주면 대부분은 글자를 치지 않고도 원하는 명령을 고르고, 이 기능을 끄면 빈 목록이 뜹니다.

2 이름같은 것을 부르는 여러 이름

한국어커맨드 팔레트, 명령 팔레트, 빠른 실행
영어command palette, quick open, spotlight, omnibox
같이 쓰는 말VS Code가 널리 퍼뜨린 이름입니다. 맥의 스포트라이트, Slack의 퀵 스위처, Notion·Linear의 Cmd+K가 모두 같은 부품입니다. 띄엄띄엄 친 글자로 찾는 방식은 퍼지 검색(fuzzy search)이라고 부릅니다.
자주 잘못 부르는 이름검색 — 검색은 내용을 찾는 반면, 팔레트는 기능을 찾습니다.
콤보박스 — 콤보박스는 목록에서 값을 골라 칸을 채우는 부품이고, 팔레트는 고른 명령을 실행합니다.
모달 — 팔레트도 모달의 한 종류이지만, 기능을 찾아 실행하는 일로 쓰임이 아주 좁게 정해져 있습니다.

3 상태상태마다 달라지는 모습

4 해부도부분마다 붙은 이름

Ctrl/⌘ + K로 어디서나 열림
치기 전에는 최근 쓴 것을 먼저 보임
띄엄띄엄 쳐도 찾아 줌
단축키를 오른쪽에 적어 알려 줌
role="combobox"와 listbox로 스크린 리더 지원
여기에만 있는 기능은 두지 않음
  1. Ctrl/⌘ + K 어디서나 여는 키어느 화면에서든 한 손으로 누를 수 있습니다
  2. 최근 쓴 것 치기 전에 보임대부분은 글자를 치지 않고 여기서 고릅니다
  3. 띄엄띄엄 찾기 퍼지 검색정내만 쳐도 정산 내역을 찾습니다
  4. 단축키 오른쪽에 적음단축키를 적어 두면 다음에는 팔레트를 열지 않아도 됩니다
  5. 역할 combobox + listbox역할을 붙여 스크린 리더로도 쓸 수 있게 합니다
  6. 다른 길 메뉴에도 두기팔레트가 있는 줄 모르는 사람은 여기에만 있는 기능을 쓸 수 없습니다

팔레트에서 가장 빠지기 쉬운 함정은 팔레트에만 있는 기능입니다. Ctrl+K를 모르는 사람은 그 기능을 찾을 방법이 없기 때문에, 팔레트는 늘 빠른 길로만 두고 같은 기능을 메뉴나 화면 어딘가에 반드시 하나 더 두어야 합니다.
단축키를 익히게 하려면 목록 오른쪽에 단축키를 적어 두는 방법이 가장 좋습니다. 팔레트로 같은 명령을 두어 번 실행하다 보면 옆에 적힌 단축키가 눈에 익고, 그 뒤로는 팔레트를 열지 않고 단축키로 바로 실행하게 됩니다.

5 쓸 때 / 안 쓸 때

커맨드 팔레트를 만들 때 지킬 것

  • 아무것도 치지 않았을 때 최근 쓴 것을 먼저 보여 주기
  • 글자를 띄엄띄엄 쳐도 찾게 하기
  • 같은 기능을 메뉴에도 두기

커맨드 팔레트를 만들 때 피할 것

  • 팔레트에만 있는 기능 두기
  • 열자마자 빈 목록 보여 주기
  • 결과가 0건일 때 '없습니다'만 적기. 다음에 해 볼 일을 함께 보여 줍니다
  • <div>로만 만들기. 역할이 없으면 스크린 리더로는 쓸 수 없습니다

커맨드 팔레트 대신 다른 것을 써야 하는 경우 — 기능이 아니라 내용을 찾게 하려면 검색을 쓰고, 입력칸에서 값을 고르게 하려면 콤보박스가 맞습니다. 단추 옆에 목록을 띄우려면 드롭다운 메뉴를 쓰고, 처음 쓰는 사람에게 기능을 알려 주려면 코치마크를 씁니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

콤보박스 패턴을 그대로 씁니다. 입력칸에 aria-controls를 달아 아래 목록과 연결합니다.

<div role="dialog" aria-modal="true" aria-label="명령 찾기">
  <input role="combobox" aria-expanded="true"
         aria-controls="cmds" aria-activedescendant="c-2"
         aria-autocomplete="list" placeholder="무엇을 할까요">
  <ul id="cmds" role="listbox">
    <li id="c-2" role="option" aria-selected="true">
      정산 내역 내보내기 <kbd>⌘E</kbd>
    </li>
  </ul>
</div>

// 띄엄띄엄 친 글자가 차례대로 들어 있으면 맞는 것으로 본다
const fuzzy = (name, q) => {
  let i = 0;
  for (const ch of name) if (ch === q[i]) i++;
  return i === q.length;
};
키와 마크업그때 일어나야 하는 일
Ctrl/⌘ + K팔레트를 엽니다. 다른 입력칸에 커서가 있을 때도 열리게 할지 미리 정해 둡니다
↑ ↓초점은 입력칸에 둔 채 고른 줄만 옮깁니다
Enter고른 명령을 실행합니다
Esc팔레트를 닫으면 초점이 열기 전 자리로 돌아갑니다
aria-activedescendant초점을 옮기지 않고도 스크린 리더에 지금 고른 줄을 알립니다
확인하는 방법화면을 끄고 스크린 리더 소리만 들으며 명령 하나를 실행해 봅니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

명령 목록을 내려 주는 곳명령 목록은 화면 쪽 코드에 두어도 되지만, 사용자 권한에 따라 보여 줄 명령이 달라진다면 서버가 걸러서 내려 줍니다.
데이터도 함께 찾을 때가게·주문처럼 내용까지 함께 찾으려면 검색 API를 같이 씁니다. 이때는 검색에서 다루는 디바운스 규칙이 그대로 필요합니다.
최근 쓴 명령을 저장하는 곳최근 쓴 명령을 기기에만 저장하면 기기마다 목록이 달라지므로, 계정에 저장해 두면 어느 기기에서나 같은 목록이 보입니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

커맨드 팔레트는 PC 화면의 부품입니다. 폰에는 키보드 단축키를 누를 방법이 없기 때문입니다.

웹직접 만듦
정내정산 내역 내보내기⌘E
라이브러리가 많지만, 어떤 것을 쓰든 역할과 키보드 조작은 직접 챙겨야 합니다.
iOS따로 없고 검색이 대신함
앱 안에 두는 경우는 드물고, OS의 스포트라이트가 같은 일을 맡습니다.
안드로이드따로 없고 검색이 대신함
안드로이드 앱에서도 드물고, 앱 안의 검색 바가 같은 일을 대신합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 팔레트가 폰에 없는 것은 Ctrl+K를 누를 키보드가 없기 때문입니다. 폰에서는 검색 바가 같은 일을 맡아 기능과 내용을 함께 찾게 합니다. 그래서 웹에서도 팔레트와 검색을 입력칸 하나로 묶어 두면 PC와 폰에서 같은 방식으로 찾을 수 있고, 실제로 그렇게 만드는 서비스가 늘고 있습니다.
