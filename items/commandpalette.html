Command palette

쳐서 찾는 메뉴입니다. 기능이 수십 개를 넘어가면 메뉴보다 빠르지만, 있는 줄 모르면 없는 것과 같습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

팔레트를 열고 정내 처럼 띄엄띄엄 쳐 보세요 — '띄엄띄엄 쳐도 찾기'를 켜면 정산 내역 내보내기가 잡히고, 끄면 안 잡힙니다. 데모가 찾은 개수를 둘 다 세서 적습니다.
목록이 비어 있을 때 보이는 것이 중요합니다 — 최근 쓴 것을 먼저 보여 주면 대부분 치지 않고도 고릅니다. 끄면 아무것도 없는 목록이 뜹니다.

2 이름부르는 말이 여러 개다

한국어커맨드 팔레트, 명령 팔레트, 빠른 실행
영어command palette, quick open, spotlight, omnibox
같이 쓰는 말VS Code 가 퍼뜨린 이름입니다. 맥의 스포트라이트, Slack 의 퀵 스위처, Notion·Linear 의 Cmd+K 가 모두 같은 것입니다. 띄엄띄엄 친 글자로 찾는 방식을 퍼지 검색(fuzzy search)이라 합니다.
자주 잘못 부름검색 — 검색은 내용을 찾고, 팔레트는 기능을 찾습니다.
콤보박스 — 콤보박스는 값을 고르는 칸입니다.
모달 — 모달의 한 종류이긴 하지만, 쓰임이 아주 좁게 정해져 있습니다.

5 해부도부분 이름이 제일 안 알려진 지식

Ctrl/⌘ + K — 어디서나 열린다
안 쳤을 때 — 최근 쓴 것을 먼저 보인다
띄엄띄엄 쳐도 찾는다
단축키를 오른쪽에 적어 가르친다
role="combobox" + listbox — 소리로도 쓸 수 있게
여기에만 있는 기능을 두지 않는다
  1. Ctrl/⌘ + K 어디서나한 손으로 눌린다
  2. 최근 쓴 것 안 쳤을 때대부분 치지 않고 고른다
  3. 띄엄띄엄 퍼지 검색정내 → 정산 내역
  4. 단축키 오른쪽에다음엔 안 열어도 되게
  5. 역할 combobox + listbox소리로도 쓸 수 있게
  6. 유일한 길 금지 메뉴에도 두기있는 줄 모르면 없는 것

팔레트의 가장 큰 함정은 여기에만 있는 기능입니다 — Ctrl+K 를 모르는 사람에게는 그 기능이 없는 것과 같습니다. 그래서 팔레트는 늘 빠른 길로만 두고, 같은 기능을 메뉴나 화면 어딘가에 반드시 또 두어야 합니다.
익히게 하는 가장 좋은 방법은 단축키를 목록 오른쪽에 적어 두는 것입니다 — 팔레트로 두어 번 쓰다 보면 손이 단축키를 외웁니다. 그 순간 팔레트는 자기 할 일을 한 셈입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 안 쳤을 때 최근 쓴 것을 먼저 보이기
  • 띄엄띄엄 쳐도 찾게 하기
  • 같은 기능을 메뉴에도 두기

이럴 때는 안 쓴다

  • 여기에만 있는 기능 두기
  • 열자마자 빈 목록 보이기
  • 결과 0건에 '없습니다'만 적기 — 다음 길을 준다
  • <div> 로만 만들기 — 소리로는 못 쓴다

대신 이걸 — 내용을 찾으면 검색, 값을 고르는 칸이면 콤보박스, 단추 옆 목록이면 드롭다운 메뉴, 처음 쓰는 사람에게는 코치마크.

8 최소 마크업과 키보드이 부품의 계약서

콤보박스 패턴을 그대로 씁니다 — 입력칸이 목록을 가리킵니다.

<div role="dialog" aria-modal="true" aria-label="명령 찾기">
  <input role="combobox" aria-expanded="true"
         aria-controls="cmds" aria-activedescendant="c-2"
         aria-autocomplete="list" placeholder="무엇을 할까요">
  <ul id="cmds" role="listbox">
    <li id="c-2" role="option" aria-selected="true">
      정산 내역 내보내기 <kbd>⌘E</kbd>
    </li>
  </ul>
</div>

// 띄엄띄엄 친 글자가 차례대로 들어 있으면 맞는 것으로 본다
const fuzzy = (name, q) => {
  let i = 0;
  for (const ch of name) if (ch === q[i]) i++;
  return i === q.length;
};

9 서버 쪽으로 치면백엔드 감각으로 번역

명령 목록화면이 들고 있어도 되지만, 권한에 따라 보일 명령이 다르면 서버가 걸러 줍니다.
데이터도 섞을 때가게·주문처럼 내용까지 찾으려면 검색 API 와 같이 씁니다 — 검색의 디바운스 규칙이 그대로 필요합니다.
최근 쓴 것기기마다 다를 수 있으니 계정에 저장하면 어디서나 같습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

PC 의 부품입니다. 폰에는 키보드 단축키가 없습니다.

웹직접 만듦
정내정산 내역 내보내기⌘E
라이브러리도 많지만 역할과 키보드는 직접 챙겨야 합니다.
iOS없다 — 검색
앱 안에는 드뭅니다. OS 의 스포트라이트가 같은 자리를 맡습니다.
안드로이드없다 — 검색
역시 드뭅니다. 검색 바가 그 자리를 대신합니다.

자주 생기는 사고 — 팔레트가 폰에 없는 이유는 단순합니다 — Ctrl+K 를 누를 키보드가 없기 때문입니다. 폰에서는 같은 일을 검색 바가 맡고, 기능과 내용을 함께 찾게 둡니다. 그래서 웹에서도 팔레트와 검색을 한 입구로 묶으면 PC·폰 양쪽에서 같은 길이 됩니다 — 실제로 그렇게 만든 서비스가 늘고 있습니다.
