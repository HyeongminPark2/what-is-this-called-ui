범위 슬라이더

Range slider

손잡이가 둘이라 슬라이더의 문제가 전부 두 배가 됩니다 — 특히 서로 지나칠 때.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

손잡이를 서로 지나치게 두면 최소가 최대보다 큰 값이 만들어집니다 — 체크를 끄고 끌어 보면 데모가 뒤집힌 상태를 잡아 적습니다.
슬라이더만으로는 정확한 값을 못 넣습니다. 눈금을 50만원으로 키우면 데모가 끌어서 넣을 수 있는 값의 가짓수를 세서 보여 줍니다. 숫자 칸은 눈금에 없는 값도 넣을 수 있습니다.

2 이름부르는 말이 여러 개다

한국어범위 슬라이더, 구간 슬라이더, 두 손잡이 슬라이더
영어range slider, dual slider, two-thumb slider
같이 쓰는 말손잡이를 섬(thumb), 칠해진 구간을 트랙 필이라 합니다. 두 손잡이가 서로 못 넘어가게 막는 것을 크로싱 방지, 둘이 겹쳤을 때 어느 쪽을 잡을지 정하는 것을 핸들 우선순위라 부릅니다.
자주 잘못 부름슬라이더 — 슬라이더는 손잡이가 하나입니다.
날짜 범위 — 날짜 범위는 날짜를 다룹니다.
필터 — 필터와 패싯은 화면 전체의 설계입니다.

5 해부도부분 이름이 제일 안 알려진 지식

손잡이 둘 — 최소와 최대
서로 지나치면 최소가 최대보다 커진다
숫자 칸 — 눈금에 없는 값도 넣는다
눈금 — 넣을 수 있는 값의 가짓수를 정한다
두 손잡이가 겹치면 어느 쪽인지 모른다
Tab 으로 둘을 갈라서 다룬다
  1. 손잡이 둘 최소 · 최대문제가 두 배
  2. 지나침 뒤집힘밀어내거나 막는다
  3. 숫자 칸 정확한 값눈금에 없는 값도
  4. 눈금 가짓수클수록 못 넣는 값이 는다
  5. 겹침 모호함어느 쪽을 잡았는지
  6. Tab 둘을 갈라서키보드는 따로 다룬다

범위 슬라이더는 손가락으로 대충 정할 때 좋고, 정확한 값을 넣을 때 나쁩니다 — 둘 다 필요한 경우가 대부분이라 숫자 칸을 같이 두는 것이 거의 늘 답입니다.
두 손잡이가 겹쳤을 때도 정해 둬야 합니다 — 겹친 자리에서 오른쪽으로 끌면 어느 손잡이가 따라올지를 정하지 않으면 사용자가 원하는 쪽이 안 움직입니다. 보통 끄는 방향 쪽 손잡이를 잡는 것이 덜 놀랍습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 숫자 칸을 같이 두기
  • 두 손잡이가 서로 못 넘게 하거나 밀어내게 하기
  • 각 손잡이에 이름 붙이기 — '최소 금액' · '최대 금액'

이럴 때는 안 쓴다

  • 슬라이더만 두기 — 정확한 값을 못 넣는다
  • 뒤집힌 값을 그대로 보내기
  • 눈금을 너무 크게 두기 — 원하는 값이 없어진다
  • 손잡이에 이름을 안 붙이기 — 소리로는 둘이 구별이 안 된다

대신 이걸 — 손잡이가 하나면 슬라이더, 날짜면 날짜 범위, 칸으로만 받으면 숫자 입력, 거르기 화면은 필터와 패싯.

8 최소 마크업과 키보드이 부품의 계약서

<input type="range"> 둘을 겹쳐 쓰고, 숫자 칸을 같이 둡니다.

<div class="range">
  <input type="range" id="lo" min="0" max="500"
         value="100" aria-label="최소 금액">
  <input type="range" id="hi" min="0" max="500"
         value="300" aria-label="최대 금액">
</div>
<input inputmode="numeric" aria-label="최소 금액(만원)"> ~
<input inputmode="numeric" aria-label="최대 금액(만원)">

/* 겹쳐 놓고 손잡이만 눌리게 한다 */
.range input { position: absolute; width: 100%; pointer-events: none; }
.range input::-webkit-slider-thumb { pointer-events: auto; }
키일어나야 하는 일
← →값을 한 눈금씩 옮긴다
Home · End최소 · 최대로 보낸다
Tab두 손잡이를 갈라서 다룬다 — 겹쳐 있어도 된다
aria-label손잡이마다 이름을 준다
aria-valuetext'100만원'처럼 단위까지 읽히게 한다
확인하는 법키보드만으로 두 손잡이를 모두 움직여 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

두 값으로{min: 100, max: 300} — 뒤집힌 값이 와도 서버가 바로잡는 편이 안전합니다.
열린 범위'300만원 이상'처럼 한쪽이 없는 경우를 null 로 표현해 둡니다.
분포값의 분포를 주면 막대로 그려 어디에 많은지 보일 수 있습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

기본 부품이 없어 직접 만듭니다.

웹range 둘을 겹쳐
100~300만원
input[type=range] 가 하나짜리뿐이라 둘을 겹쳐 만듭니다.
iOS없다 — 직접
Slider 는 하나짜리뿐입니다 — 범위는 직접 만듭니다.
안드로이드RangeSlider
Material 에 RangeSlider 가 정식으로 있습니다 — 드문 경우입니다.

자주 생기는 사고 — Material 의 RangeSlider 는 세 플랫폼 가운데 유일한 정식 부품인데, 거기서도 끌어서 정확한 값을 넣는 문제는 그대로입니다. 그래서 Material 지침조차 값을 숫자로 보여 주라고 적어 둡니다. 웹에서 만들 때도 '칸을 같이 둘지'가 아니라 '어디에 둘지'를 고민하는 편이 맞습니다.
