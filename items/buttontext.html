버튼 문구

Button label

버튼 글자는 누르면 무슨 일이 일어나는지를 버튼만 보고도 알 수 있게 적어야 합니다. 앞뒤 설명을 읽어야 뜻이 통하는 버튼은, 버튼 글자만 따로 읽히는 상황에서 무엇을 하는지 알 수 없기 때문입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

버튼만 보고 맞히기를 켜 보세요. 앞뒤 설명이 사라지면 확인·제출 같은 버튼만으로는 무슨 일이 일어날지 전혀 알 수 없다는 것이 드러납니다.
판정 기준은 동사가 있는가, 두세 어절 안인가, 빈 말이 아닌가 세 가지입니다. 아래 칸에 버튼 문구를 직접 써 보면 이 기준으로 바로 판정해 줍니다.

2 이름같은 것을 부르는 여러 이름

한국어버튼 문구, 버튼 라벨, 레이블
영어button label, call to action (CTA), action label
같이 쓰는 말사용자가 다음 행동을 하도록 이끄는 주 버튼은 CTA(call to action)라고 부릅니다. 화면 안의 짧은 글 전체는 마이크로카피(microcopy)라고 하고, 그 가운데 버튼·레이블·힌트를 묶어 UX 라이팅이라고 합니다.
자주 잘못 부르는 이름레이블 — 입력 필드의 칸 이름도 레이블이라고 불러서 자주 섞이지만, 이 항목에서 다루는 것은 버튼에 적힌 글자입니다.
이름 붙이기 — 접근성의 이름은 스크린 리더 같은 보조기기가 읽는 이름이라서, 눈에 보이는 버튼 글자와 다를 수 있습니다.
카피 — 광고 문구를 가리킬 때도 쓰는 말이라서, 화면 안의 글은 UX 라이팅이라고 따로 부르는 편이 낫습니다.

3 흔한 버튼 문구와 고친 문구버튼 글자만 보고 뜻을 알 수 있는지 견주기

4 해부도부분마다 붙은 이름

누르면 무슨 일이 나는지 동사로 적음
두세 어절을 넘으면 버튼이 아니라 문장이 됨
조사 없이 ‘정산을 내보내기’ 대신 ‘내보내기’
취소 쪽은 색과 무게를 약하게 해 구별함
마침표는 찍지 않음
‘확인’만으로는 무엇을 확인하는지 알 수 없음
  1. 동사 무슨 일이 나나'저장'·'삭제'·'보내기'처럼 누르면 일어나는 일을 동사로 적습니다. 버튼 문구에서 가장 중요한 부분입니다
  2. 길이 두세 어절두세 어절을 넘기면 설명은 버튼 밖으로 빼고 버튼은 짧게 둡니다
  3. 조사 없이 ‘내보내기’'정산을 내보내기'처럼 조사를 붙이지 않습니다. 버튼 문구는 문장이 아니기 때문입니다
  4. 약한 쪽 취소색과 무게로 주 동작과 구별하고, 두 버튼을 같은 무게로 두지 않습니다
  5. 마침표 찍지 않음버튼 문구는 문장이 아니므로 마침표를 찍지 않습니다
  6. 빈 말 확인 · 제출누르면 무엇을 하는지 알려 주지 않습니다. 가장 흔한 실수입니다

'확인'도 앞 문장과 함께 보면 뜻이 통합니다. 그래서 화면을 만드는 사람 눈에는 문제가 잘 보이지 않습니다. 문제는 버튼 글자만 따로 읽히는 곳에서 드러나는데, 스크린 리더가 버튼 목록을 읽어 줄 때, 키보드로 버튼만 훑어 갈 때, 알림에 버튼 두 개만 뜰 때가 그렇습니다. 버튼 문구의 기준을 '앞 문장 없이도 뜻이 통하는가'로 잡으면 이런 경우를 모두 함께 막을 수 있습니다.

5 쓸 때 / 안 쓸 때

버튼 문구를 쓸 때 지킬 것

  • 누르면 무슨 일이 나는지 동사로 적기
  • 같은 화면에 비슷한 버튼이 있으면 대상까지 적기
  • 주 동작과 취소를 무게로 가르기

버튼 문구에서 피할 것

  • ‘확인 / 취소’ · ‘예 / 아니오’로 적을 때. 앞 문장을 읽어야만 뜻이 통하는 문구입니다
  • ‘제출’로 적을 때. 사용자가 실제로 무엇을 하는지를 적습니다
  • 버튼에 문장을 쓸 때. 설명은 버튼 위에 따로 둡니다
  • 마침표를 찍을 때

버튼 문구와 함께 보면 좋은 항목 — 설명이 길어져 버튼에 담기 어려우면 다이얼로그 본문에 적습니다. 보조기기가 읽는 이름은 이름 붙이기에서, 지우기처럼 위험한 동작에 붙일 문구는 위험한 동작에서 다룹니다.

7 최소 마크업과 규칙코드로 옮길 때 지킬 것

버튼에 보이는 글자가 그대로 접근성 이름이 되도록 적습니다.

<!-- 좋음: 글자만 읽어도 뜻이 통한다 -->
<button>내보내기</button>
<button class="ghost">취소</button>

<!-- 아이콘만 있을 때는 이름을 따로 -->
<button aria-label="정산 내보내기">
  <svg aria-hidden="true">…</svg>
</button>

<!-- 같은 글자가 여럿일 때: 보이는 글자는 짧게, 이름은 길게 -->
<button aria-label="모란상회 삭제">삭제</button>
지킬 규칙과 마크업지키는 방법과 이유
보이는 글자를 이름으로 쓰기aria-label에 보이는 글자와 전혀 다른 말을 넣으면, 음성 명령으로 화면을 다루는 사용자가 보이는 글자를 말해도 버튼을 누를 수 없습니다
아이콘만 있는 버튼aria-label로 이름을 반드시 붙여야 합니다(이름 붙이기)
같은 글자의 버튼이 여럿일 때표에 '삭제' 버튼이 스무 개 있으면 어느 줄의 버튼인지 알 수 없으므로, 접근성 이름에 대상까지 적습니다
<button>으로 만들기<div onclick>으로 만든 버튼은 키보드로 누를 수 없습니다(시맨틱 태그)
글자가 길어질 때글자가 길어지면 버튼 폭도 늘어나므로, min-width로 최소 폭을 잡고 줄바꿈을 허용합니다
다른 언어로 옮길 때영어 문구는 짧고 한국어 문구는 길어지기 쉬워서, 영어 기준으로 폭을 잡으면 한국어 글자가 버튼 밖으로 넘칩니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

문구를 코드 곳곳에 적지 않기버튼 글자는 화면에서 가장 자주 바뀌는 부분이라서, 코드 곳곳에 적지 않고 한곳에 모아 두면 고치기 쉽습니다.
같은 동작에는 같은 말 쓰기서버 응답 메시지와 버튼 글자가 ‘발송’과 ‘보내기’처럼 서로 다르면, 사용자에게는 같은 동작이 다른 기능처럼 보입니다.
분석 로그의 이벤트 이름 따로 두기분석 로그의 이벤트 이름은 버튼 글자와 따로 둡니다. 버튼 글자를 이벤트 이름으로 쓰면 문구를 고칠 때마다 이벤트 이름도 바뀌어서 지표가 끊기기 때문입니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 버튼을 글자만으로 그리는지, 배경을 칠해 그리는지가 다릅니다.

웹<button>
내보내기 취소
주 동작은 배경을 칠하고 취소는 테두리만 그립니다. 버튼 문구를 동사로 적는 관례는 다른 플랫폼과 같습니다.
iOS글자 버튼
취소 저장
배경을 칠하지 않고 글자에 색만 입힌 버튼이 많습니다. 모양으로 구별할 단서가 적은 만큼 문구가 더 중요합니다.
안드로이드Material 3
저장 취소
다이얼로그 버튼은 글자만으로 그립니다. Material 지침도 '확인'보다 동사를 쓰라고 권합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 시안에 '확인 / 취소'라고 적혀 오면 그대로 옮겨 넣기 쉽습니다. 하지만 이런 문구는 디자이너가 고민해서 고른 말이라기보다 아직 문구를 정하지 않고 채워 둔 자리인 경우가 많습니다. 시안을 받을 때 "이 버튼을 누르면 무슨 일이 납니까"라고 한 번 물어보면 대개 그 자리에서 더 나은 문구가 나옵니다.
