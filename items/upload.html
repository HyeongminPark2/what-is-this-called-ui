파일 올리기

File upload

올리기의 핵심은 언제 실패를 알려 주느냐입니다. 다 올린 뒤에 거절하면 기다린 시간이 통째로 버려집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

10MB 가 넘거나 받지 않는 형식이면 보내기 전에 그 자리에서 알려 줘야 합니다 — 데모가 헛되이 올린 양(MB)을 재서 적습니다. 미리 거르기를 끄면 그 숫자가 올라갑니다.
파일마다 따로 처리해야 합니다. 한 장이 실패했다고 나머지까지 되돌리면 멀쩡한 네 장을 다시 올려야 합니다 — '파일마다 따로 처리'를 끄면 그렇게 동작합니다.
실패한 줄에는 왜 실패했는지와 다시 시도가 같이 있어야 합니다.

2 이름부르는 말이 여러 개다

한국어파일 올리기, 업로드, 첨부, 파일 첨부
영어file upload, attachment, drag and drop upload
같이 쓰는 말끌어다 놓는 자리를 드롭존(dropzone), 큰 파일을 토막 내 보내는 방식을 청크 업로드(chunked), 끊겼다가 이어 보내는 것을 이어 올리기(resumable)라 합니다. 서버를 거치지 않고 저장소로 바로 보내는 길은 프리사인 URL(presigned URL)입니다.
자주 잘못 부름드롭존 — 드롭존은 끌어다 놓는 자리일 뿐, 올리기 전체가 아닙니다.
내보내기 — 내보내기는 반대 방향입니다.
프로그레스 바 — 프로그레스 바는 그 안에 들어가는 부품입니다.

4 상태실패까지 다 만들어야 한다

5 해부도부분 이름이 제일 안 알려진 지식

받는 조건을 미리 적는다 — 형식 · 크기
보내기 전에 거른다 — 헛되이 올리지 않는다
파일마다 줄 하나 — 이름 · 진척 · 상태
한 장이 실패해도 나머지는 살린다
실패한 줄에 이유와 '다시 시도'
끌어다 놓기 말고 고르기 단추도 둔다
  1. 받는 조건 미리 적기형식 · 크기 · 장수
  2. 미리 거르기 보내기 전브라우저가 이미 안다
  3. 줄마다 이름·진척·상태파일 단위로 본다
  4. 따로 처리 나머지 살리기한 장 실패가 전부를 망치지 않게
  5. 실패한 줄 이유 + 다시 시도무엇을 고쳐야 하는지
  6. 고르기 단추 같이 두기끌어다 놓기만으로는 키보드가 못 쓴다

끌어다 놓기만 만들어 두는 실수가 흔합니다. 마우스가 없는 사람은 파일을 올릴 길이 없어집니다 — 드롭존 안에 '파일 고르기' 단추를 같이 두면 그 길이 생기고, 만드는 품도 거의 안 듭니다(원래 있던 <input type="file"> 입니다).
그리고 올리는 중에는 떠나지 못하게 하기보다 떠나면 어떻게 되는지를 알려 주는 편이 낫습니다 — '올리는 중입니다. 지금 나가면 멈춥니다' 한 줄이면 충분합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 형식·크기·장수를 드롭존에 적어 두기
  • 보내기 전에 거르고 그 자리에서 이유 말하기
  • 드롭존 안에 '파일 고르기' 단추 같이 두기

이럴 때는 안 쓴다

  • 다 올린 뒤에 거절하기 — 기다린 시간이 버려진다
  • 한 장이 실패했다고 전부 되돌리기
  • 끌어다 놓기만 만들기 — 키보드로는 못 올린다
  • 진척을 전체 합계로만 보여 주기 — 어느 파일이 문제인지 모른다

대신 이걸 — 반대 방향은 내보내기, 진척 막대 자체는 프로그레스 바, 칸 검사 규칙은 입력 검증, 오류 문구는 오류 문구.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 화면의 계약서

원래 있는 <input type="file"> 이 뼈대입니다. 끌어다 놓기는 그 위에 얹습니다.

<label for="f">영수증 올리기</label>
<input id="f" type="file" multiple
       accept="image/jpeg,image/png,application/pdf"
       aria-describedby="rule">
<p id="rule">JPG · PNG · PDF · 한 장 10MB 까지</p>

<ul aria-live="polite">…올린 파일 목록…</ul>

// 보내기 전에 거른다 — 브라우저가 이미 크기와 형식을 안다
for (const f of input.files) {
  if (f.size > 10 * 1024 * 1024) { reject(f, '10MB 가 넘습니다'); continue; }
  upload(f);                       // 파일마다 따로 보낸다
}
키일어나야 하는 일
Tab · Enter<input type="file"> 가 원래 키보드로 열린다
accept고르기 창에서 미리 걸러 보여 준다 — 검사는 따로 해야 한다
aria-describedby받는 조건을 칸에 묶어 읽히게 한다
aria-live="polite"올린 결과를 소리로 알린다 — 진척은 넣지 않는다
드롭존dragover 에서 preventDefault() 를 해야 놓을 수 있다
확인하는 법마우스를 안 쓰고 Tab 만으로 파일을 올려 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

두 번 검사브라우저에서 거르는 것은 친절이고, 서버 검사가 진짜입니다 — 둘 다 필요합니다.
저장소로 바로서버를 거치지 않고 올리려면 프리사인 URL 을 내려 줍니다 — 서버 대역폭이 크게 줍니다.
큰 파일100MB 를 넘으면 토막 내어 보내고 끊기면 이어 올립니다.
바이러스·내용 검사올린 뒤 검사가 더 있으면 '검사 중' 상태를 따로 둬야 합니다 — 완료와 다릅니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

고르는 창을 누가 띄우느냐가 다릅니다.

웹input[type=file]
끌어다 놓거나 고르기영수증_01.jpg완료
끌어다 놓기가 자연스러운 유일한 자리입니다. 데스크톱에서는 기본으로 둡니다.
iOS포토 피커 · 파일 앱
PHPickerViewController 는 앱에 사진 권한을 안 주고도 고른 것만 건넵니다.
안드로이드Photo Picker · SAF
Photo Picker 와 SAF 가 같은 일을 합니다 — 역시 권한 없이 고른 것만 건넵니다.

자주 생기는 사고 — 앱 쪽이 권한 없이 고른 것만 건네는 길을 만들어 둔 것은 그대로 본받을 만한 생각입니다 — 사진 전체를 열어 주는 대신 필요한 것만 받습니다. 웹의 <input type="file"> 이 원래 그렇게 동작하고 있어서, 웹에서는 이 부분을 공짜로 얻습니다. 대신 웹에는 끌어다 놓기가 있는데, 폰에는 놓을 자리가 없으니 단추를 늘 같이 두는 것이 안전합니다.
