파일 올리기

File upload

파일 올리기에서 가장 중요한 것은 실패를 언제 알려 주느냐입니다. 파일을 다 올린 뒤에야 거절하면 사용자가 기다린 시간이 모두 헛수고가 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

10MB가 넘거나 받지 않는 형식이면 보내기 전에 그 자리에서 알려 줘야 합니다. 데모는 헛되이 올린 양(MB)을 재서 적는데, 미리 거르기를 끄면 그 숫자가 올라갑니다.
또 파일은 하나씩 따로 처리해야 합니다. 한 장이 실패했다고 나머지까지 되돌리면 멀쩡한 네 장을 다시 올려야 하는데, '파일마다 따로 처리'를 끄면 데모가 그렇게 동작합니다.
실패한 줄에는 왜 실패했는지와 다시 시도 버튼이 함께 있어야 합니다.

2 이름같은 것을 부르는 여러 이름

한국어파일 올리기, 업로드, 첨부, 파일 첨부
영어file upload, attachment, drag and drop upload
같이 쓰는 말파일을 끌어다 놓는 자리를 드롭존(dropzone)이라 하고, 큰 파일을 여러 토막으로 나눠 보내는 방식을 청크 업로드(chunked), 끊긴 곳부터 이어 보내는 방식을 이어 올리기(resumable)라고 합니다. 서버를 거치지 않고 저장소로 바로 보내도록 발급하는 주소는 프리사인 URL(presigned URL)이라고 합니다.
자주 잘못 부르는 이름드롭존 — 드롭존은 파일을 끌어다 놓는 자리이고, 파일 올리기 흐름 전체를 가리키는 말이 아닙니다.
내보내기 — 내보내기는 데이터가 반대 방향으로 나가는 일입니다.
프로그레스 바 — 프로그레스 바는 올리기 화면 안에 들어가는 부품입니다.

4 파일 올리기의 상태실패한 경우까지 모두 만들어야 하는 상태

5 해부도부분마다 붙은 이름

형식 · 크기 같은 받는 조건을 미리 적음
보내기 전에 걸러 헛되이 올리지 않음
파일마다 이름 · 진척 · 상태를 한 줄로
한 장이 실패해도 나머지는 그대로 올림
실패한 줄에 이유와 '다시 시도'를 표시
끌어다 놓기와 함께 고르기 단추도 둠
  1. 받는 조건 미리 적기형식 · 크기 · 장수를 미리 적어 둡니다
  2. 미리 거르기 보내기 전크기와 형식은 브라우저가 이미 알고 있으므로 보내기 전에 거릅니다
  3. 파일별 줄 이름·진척·상태진척과 상태를 파일 단위로 보여 줍니다
  4. 따로 처리 나머지는 그대로 올리기한 장이 실패해도 나머지는 그대로 올라가게 합니다
  5. 실패한 줄 이유 + 다시 시도무엇을 고쳐야 하는지 알려 주고 다시 시도할 수 있게 합니다
  6. 고르기 단추 드롭존과 같이 두기끌어다 놓기만 있으면 키보드로는 올릴 수 없습니다

끌어다 놓기만 만들어 두는 실수가 흔한데, 그러면 마우스를 쓰지 않는 사람은 파일을 올릴 방법이 없습니다. 드롭존 안에 '파일 고르기' 단추를 같이 두면 키보드로도 올릴 수 있고, 원래 있던 <input type="file">을 쓰면 되므로 만드는 품도 거의 들지 않습니다.
또 올리는 중에는 사용자가 떠나지 못하게 막기보다 떠나면 어떻게 되는지 알려 주는 편이 낫습니다. '올리는 중입니다. 지금 나가면 멈춥니다' 한 줄이면 충분합니다.

6 쓸 때 / 안 쓸 때

파일 올리기 화면을 만들 때 할 일

  • 받는 형식·크기·장수를 드롭존에 적어 둘 때
  • 보내기 전에 거르고 그 자리에서 이유를 알려 줄 때
  • 드롭존 안에 '파일 고르기' 단추를 같이 둘 때

파일 올리기를 잘못 만드는 경우

  • 다 올린 뒤에야 거절할 때. 사용자가 기다린 시간이 헛수고가 됩니다
  • 한 장이 실패했다고 전부 되돌릴 때
  • 끌어다 놓기만 만들 때. 키보드로는 올릴 수 없습니다
  • 진척을 전체 합계로만 보여 줄 때. 어느 파일이 문제인지 알 수 없습니다

함께 보면 좋은 항목 — 데이터가 반대 방향으로 나가는 일은 내보내기에서, 진척 막대 부품은 프로그레스 바에서 다룹니다. 입력값을 검사하는 규칙은 입력 검증에서, 오류를 알리는 문장은 오류 문구에서 설명합니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

원래 있는 <input type="file">을 기본으로 두고, 끌어다 놓기는 그 위에 덧붙입니다.

<label for="f">영수증 올리기</label>
<input id="f" type="file" multiple
       accept="image/jpeg,image/png,application/pdf"
       aria-describedby="rule">
<p id="rule">JPG · PNG · PDF · 한 장 10MB 까지</p>

<ul aria-live="polite">…올린 파일 목록…</ul>

// 브라우저가 이미 크기와 형식을 아니까 보내기 전에 거른다
for (const f of input.files) {
  if (f.size > 10 * 1024 * 1024) { reject(f, '10MB 가 넘습니다'); continue; }
  upload(f);                       // 파일마다 따로 보낸다
}
키와 마크업처리하는 방법
Tab · Enter<input type="file">은 따로 만들지 않아도 키보드로 열립니다
accept파일 고르기 창에서 맞는 형식만 미리 걸러 보여 줍니다. 다만 사용자가 다른 파일을 고를 수도 있으므로 검사는 따로 해야 합니다
aria-describedby받는 조건을 입력 칸과 연결해 함께 읽히게 합니다
aria-live="polite"올린 결과를 스크린 리더로 소리 내어 알립니다. 진척률은 계속 바뀌므로 넣지 않습니다
드롭존에 파일을 놓게 하기dragover에서 preventDefault()를 불러야 파일을 놓을 수 있습니다
확인하는 방법마우스를 쓰지 않고 Tab만으로 파일을 올려 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

브라우저와 서버에서 두 번 검사하기브라우저에서 거르는 것은 사용자를 위한 안내이고, 실제로 막는 것은 서버 검사입니다. 브라우저 검사는 우회할 수 있으므로 둘 다 필요합니다.
저장소로 바로 보내기파일이 서버를 거치지 않고 저장소로 바로 가게 하려면 프리사인 URL을 내려 줍니다. 그러면 서버가 쓰는 대역폭이 크게 줄어듭니다.
큰 파일은 나눠 보내기100MB를 넘는 파일은 토막으로 나눠 보내고, 중간에 끊기면 끊긴 곳부터 이어 올립니다.
올린 뒤 바이러스·내용 검사하기올린 뒤에 검사가 더 있다면 '검사 중' 상태를 따로 둬야 합니다. 검사 중인 파일은 아직 완료된 것이 아니기 때문입니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

플랫폼마다 파일을 고르는 창을 누가 띄우는지가 다릅니다.

웹input[type=file]
끌어다 놓거나 고르기영수증_01.jpg완료
세 플랫폼 가운데 끌어다 놓기가 자연스럽게 쓰이는 곳은 웹뿐이라서, 데스크톱에서는 기본으로 둡니다.
iOS포토 피커 · 파일 앱
PHPickerViewController는 앱에 사진 권한을 주지 않고도 사용자가 고른 사진만 앱에 건넵니다.
안드로이드Photo Picker · SAF
Photo Picker와 SAF가 같은 일을 하며, 마찬가지로 권한 없이 사용자가 고른 파일만 건넵니다.

플랫폼 차이 때문에 자주 생기는 문제 — 모바일 OS가 권한 없이 고른 것만 건네는 방식을 만들어 둔 것은 그대로 본받을 만합니다. 사진 전체에 접근하게 하는 대신 필요한 파일만 받기 때문입니다. 웹의 <input type="file">은 원래 이렇게 동작하므로, 웹에서는 따로 애쓰지 않아도 같은 효과를 얻습니다. 대신 웹에는 끌어다 놓기가 있는데, 폰에서는 파일을 끌어다 놓을 수 없으니 고르기 단추를 늘 같이 두는 것이 안전합니다.
