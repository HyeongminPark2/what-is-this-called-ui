바텀시트

Bottom sheet · Sheet

바텀시트는 화면 아래에서 올라오는 판으로, 손가락이 쉽게 닿는 자리에 선택지를 두려고 씁니다. 좁은 화면에서는 모달도 가운데 대신 이 모양으로 띄우는 경우가 많습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

핸들을 아래로 끌어 보세요. 끌어서 닫는 조작은 시트에만 있고 모달에는 없습니다. Esc를 누르거나 시트 바깥을 눌러도 닫힙니다. 폭을 넓게로 바꾸면 같은 시트가 화면 가운데로 옮겨 가는데, 넓은 화면에서는 손가락이 닿는 자리를 따질 필요가 없어 아래에 붙여 둘 이유가 없기 때문입니다.

2 이름같은 것을 부르는 여러 이름

한국어바텀시트, 시트, 하단 시트
영어bottom sheet, sheet
같이 쓰는 말뒤쪽 화면을 막는 것은 모달 시트, 막지 않고 내용 위에 걸쳐 있는 것은 스탠더드 시트라고 나눠 부릅니다. 시트가 위로 조금만 올라와 있는 상태는 엿보기(peek)라고 합니다.
자주 잘못 부르는 이름하단 팝업 — 실무에서 많이 쓰는 말이지만 표준 용어는 아닙니다.
모달 — 좁은 화면에서 모달이 시트 모양으로 바뀌는 것은 맞지만, 두 이름은 가리키는 것이 다릅니다. 시트는 어디서 뜨는가를, 모달은 뒤를 막는가를 가리킵니다.
액션 시트 — iOS에서 선택지를 늘어놓는 시트만 가리키는 좁은 말이라, 바텀시트 전체를 부르는 이름으로 쓰면 범위가 맞지 않습니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품은 생김새로는 가르기 어렵습니다. 아래 네 가지로 가릅니다.

토스트안 막음안 가둠그대로 움직임구석에 떴다 저절로 사라짐

바텀시트를 한 줄로 정리하면 — 시트인지 아닌지는 아래에서 올라오느냐로 정해집니다. 뒤쪽 화면을 막는지는 이와 따로 정하기 때문에, 뒤를 막는 시트와 막지 않는 시트가 모두 있습니다.

취소
  1. 스크림 scrim · backdrop뒤를 막는 시트에만 있습니다. 스크림이 없으면 뒤쪽 화면을 누를 수 있습니다
  2. 시트 몸통 sheet · surface아래쪽은 화면 끝에 붙어 있으므로 위쪽 모서리만 둥글게 깎습니다
  3. 그래브 핸들 grab handle · drag handle끌어서 크기를 바꿀 수 있다는 것을 알려 주는 표시로, 어포던스의 한 예입니다
  4. 헤더 header무엇에 대한 시트인지 알려 줍니다. 내용이 길면 헤더만 고정하고 그 아래를 스크롤합니다
  5. 내용 content이 영역만 스크롤합니다. 시트 전체가 스크롤되면 끌어서 닫는 동작과 부딪칩니다
  6. 액션 영역 action area폰에서는 버튼을 가로로 길게 늘려 세로로 쌓습니다
  7. 세이프 에어리어 여백 safe area inset홈 인디케이터가 버튼을 가리지 않도록 아래에 더 비워 두는 자리입니다

6 쓸 때 / 안 쓸 때

바텀시트를 쓰는 경우

  • 손가락으로 고를 선택지가 여럿일 때
  • 지도나 영상처럼 뒤쪽 화면을 계속 보여 주면서 조작해야 할 때. 이때는 뒤를 막지 않는 시트를 씁니다
  • 좁은 화면에서 모달 대신 쓸 때. 손가락이 닿기 쉽고, 키보드가 올라와도 가리지 않습니다

바텀시트를 쓰지 않는 경우

  • 넓은 데스크톱 화면일 때. 손가락이 닿는 자리를 따질 필요가 없어서 아래에 붙여 둘 이유가 없습니다
  • 입력 칸이 많은 폼을 담을 때. 키보드가 올라오면 시트에 남는 높이가 너무 작아집니다
  • 단계가 여럿인 작업일 때. 별도 페이지로 보냅니다
  • 끌어서 닫기와 안쪽 스크롤이 같은 자리에서 겹칠 때. 둘 다 세로로 끄는 제스처라 서로 부딪칩니다

바텀시트 대신 다른 것을 써야 하는 경우 — 넓은 화면에서는 가운데 뜨는 모달을 쓰고, 화면 옆에서 밀려 나와야 하면 드로어를 씁니다. 결과를 알리기만 하면 된다면 토스트로 충분합니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

<dialog> 요소를 화면 아래에 붙이면 바텀시트가 됩니다. 가운데 뜨는 모달과 코드에서 다른 곳은 margin을 정하는 한 줄뿐입니다.

<dialog class="sheet" aria-labelledby="t">
  <span class="grab"></span>
  <h2 id="t">해질녘 공원</h2>
  …
</dialog>

/* 가운데가 아니라 아래에 붙인다. 모달과 시트는 이 한 줄만 다르다 */
dialog.sheet { margin: auto auto 0; width: 100%; }

// 끌어 내려 닫기. 일정 거리를 넘길 때만 닫는다
if (dy > 70) dlg.close();

// 홈 인디케이터에 버튼이 가리지 않게
padding-bottom: calc(16px + env(safe-area-inset-bottom));
키와 마크업그때 일어나야 하는 일
Esc뒤를 막는 시트든 막지 않는 시트든 닫힙니다
Tab뒤를 막는 시트에서는 포커스가 시트 안에서만 돕니다
시트를 아래로 끌 때일정 거리를 넘겨 끌면 닫히고, 넘기지 않으면 제자리로 돌아갑니다
시트가 열릴 때포커스를 시트 안으로 옮깁니다. 삭제처럼 되돌릴 수 없는 선택지가 있으면 그 선택지에는 포커스를 두지 않습니다
시트가 닫힐 때포커스가 시트를 열었던 버튼으로 돌아갑니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

스냅 포인트는 상태 머신과 같은 구조엿보기·반 열림·전체는 세 가지 상태이고, 상태 사이를 오가는 규칙이 정해져 있습니다. 시트를 끌다가 손을 떼면 가장 가까운 상태로 맞춰 멈춥니다. 상태 수가 늘어날수록 오가는 규칙은 빠르게 복잡해집니다.
뒤를 막는 시트는 블로킹 호출과 같음뒤를 막는 시트는 사용자의 답이 올 때까지 기다리는 블로킹 호출과 같습니다. 반면 뒤를 막지 않는 시트는 비동기 호출에 가깝습니다.
데이터를 나눠 불러오기에 잘 맞음엿보기 상태에서는 요약만 보여 주고, 사용자가 끌어 올리면 상세 데이터를 더 가져옵니다. 필요한 만큼 이어서 받는다는 점에서 커서 페이지네이션과 구조가 같습니다.
세이프 에어리어는 미리 떼어 둔 영역화면 전체 크기와 실제로 그려도 되는 영역의 크기가 다릅니다. 패킷 전체 크기에서 헤더 크기를 빼고 페이로드 크기를 계산하는 것과 같습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

바텀시트는 iOS와 안드로이드가 서로 다른 이름 체계로 부르고, 웹은 두 쪽 이름을 섞어 씁니다.

시트(Sheet) · 시트가 멈출 높이를 디텐트(detent, medium과 large)로 정합니다. 선택지만 늘어놓는 시트는 액션 시트라고 따로 부릅니다.
안드로이드Material 3
해질녘 공원공유하기내려받기
바텀시트(Bottom sheet) · 뒤를 막는 Modal, 막지 않는 Standard, 그리고 Expanding으로 나눠 부릅니다. 바텀시트라는 이름은 Material에서 굳어졌습니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS에서는 "시트 띄워 주세요"라는 말이 화면 전환 방식을 뜻할 수 있습니다. iOS의 시트는 모달 프레젠테이션의 한 형태여서, 웹에서 떠올리는 '아래에서 올라오는 작은 판'보다 가리키는 범위가 넓기 때문입니다. 그래서 무엇을 하는 판인지 역할을 함께 말해야 오해가 없습니다.
