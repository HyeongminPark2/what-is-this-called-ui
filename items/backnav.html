뒤로가기

Back · up navigation

뒤로가기 단추는 겉보기에는 하나지만 실제로는 두 가지입니다. 하나는 들어온 길을 따라 되돌아가는 '뒤로'이고, 다른 하나는 어디서 들어왔든 늘 상위 화면으로 가는 '위로'입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 화면이라도 어떻게 들어왔는지에 따라 '뒤로'를 눌렀을 때 가는 곳이 달라집니다. 받은 링크로 바로 들어오면 방문 기록에 앞 화면이 없어서 돌아갈 곳이 없습니다. 데모는 방문 기록을 따로 저장해 두었다가 이런 경우를 표시해 줍니다.
반면 위로는 방문 기록과 상관없이 늘 상위 화면으로 가기 때문에, 링크로 들어온 사람도 갈 곳이 있습니다. 두 동작을 섞어 쓰면 사용자는 뒤로를 눌렀는데 예상과 다른 화면에 도착하게 됩니다.

2 이름같은 것을 부르는 여러 이름

한국어뒤로가기, 뒤로 단추, 위로 가기, 상위로
영어back, up navigation, back link, ancestor navigation
같이 쓰는 말브라우저나 OS의 방문 기록을 한 칸 되돌리는 것은 뒤로(back), 계층에서 부모 화면으로 올라가는 것은 위로(up)라고 합니다. 안드로이드는 이 둘을 지침에 명시적으로 나눠 적어 두었는데, 시스템 백이 뒤로이고 앱바 왼쪽의 ←가 위로입니다.
자주 잘못 부르는 이름닫기 — 닫기는 모달처럼 위에 뜬 그 부품만 없애고, 아래 화면은 바꾸지 않습니다.
시스템 백 — 시스템 백은 OS가 처리하는 동작이고, 뒤로가기는 화면 안에 둔 단추입니다.
취소 — 취소는 화면을 옮기는 것이 아니라 하던 일을 없던 일로 되돌리는 동작입니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

길 안내 부품은 모두 누르면 다른 곳으로 옮겨 갑니다. 아래 네 가지로 서로 가릅니다.

화면에 놓이는 자리누르면 데려가는 곳지금 위치를 알리는 방법담을 수 있는 항목 수
앱바 · 헤더화면 위전역 또는 상위 화면제목으로해당 없음
사이드바 내비게이션화면 옆전역항목 강조로10~20
바텀 탭바화면 아래전역아이콘 강조로3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위 단계계층 전체를 보여 줌3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록의 다음 묶음보여 주지 않음제한 없음
스테퍼내용 위 · 옆같은 흐름의 다음 단계번호와 완료 표시로3~5단계
트리뷰화면 옆계층 아래로펼친 가지로깊이 3단까지
앵커 내비내용 옆같은 문서 안보는 절을 강조해5~12
뒤로가기화면 왼쪽 위바로 앞 화면보여 주지 않음하나
메가 메뉴앱바 아래전역, 여러 분류열린 분류로20~60

뒤로가기를 한 줄로 정리하면 — 단추 하나에는 동작 하나만 맡기세요. '뒤로'라고 적었으면 방문 기록대로 돌아가고, '목록으로'라고 적었으면 늘 목록으로 가야 합니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

뒤로(기록)는 history.back()으로 왔던 길로
위로(상위)는 늘 부모 화면으로 감
링크로 바로 들어오면 기록에 앞 화면이 없음
'‹ 주문 목록'처럼 이름을 적음
<a href>로 두면 새 탭으로도 열림
뜻이 다른 닫기와 섞지 않음
  1. 뒤로(기록) history.back()들어온 길을 따라 되돌아갑니다
  2. 위로(상위) 부모 화면어디서 들어왔든 늘 같은 곳으로 갑니다
  3. 기록이 빈 경우 링크로 들어옴뒤로를 눌러도 갈 곳이 없습니다
  4. 이름 적기 '‹ 주문 목록'누르기 전에 어디로 가는지 미리 알려 줍니다
  5. <a href> 링크로 두기새 탭으로 열기와 마우스 가운데 버튼 클릭을 따로 구현하지 않아도 그대로 쓸 수 있습니다
  6. 닫기와 구별 뜻이 다름두 동작을 섞어 쓰면 사용자는 어느 단추가 무엇을 할지 예측할 수 없습니다

실무에서 가장 안전한 선택은 위로입니다. 방문 기록이 어떻든 늘 같은 곳으로 가고, 링크로 들어온 사람에게도 갈 곳이 있기 때문입니다. 여기에 '‹ 주문 목록'처럼 어디로 가는지 이름을 적어 두면 사용자가 누르기 전에 도착할 곳을 알 수 있어서 예상과 결과가 어긋나지 않습니다.
history.back()을 쓸 거라면 방문 기록이 비었을 때 갈 곳을 꼭 정해 두세요. 예를 들어 document.referrer가 우리 도메인이 아니면 상위 화면으로 보내는 식입니다. 이 처리를 빠뜨리면 눌러도 아무 일도 일어나지 않는 단추가 됩니다.

6 쓸 때 / 안 쓸 때

뒤로가기를 쓰는 경우

  • '‹ 주문 목록'처럼 어디로 가는지 이름을 적을 때
  • <a href>로 둘 때. 새 탭으로도 열 수 있습니다
  • 방문 기록이 비었을 때 갈 기본 화면을 정해 둘 때

뒤로가기를 쓰지 않는 경우

  • history.back()만 쓰고 방문 기록이 빈 경우를 챙기지 않을 때
  • '뒤로'라고 적어 두고 상위 화면으로 보낼 때. 단추 하나는 두 동작 중 하나만 합니다
  • 닫기 자리에 뒤로를 둘 때. 사용자는 누르면 모달만 사라질 거라고 생각합니다
  • 폰에서 시스템 백과 다른 곳으로 보낼 때

뒤로가기 대신 다른 것을 써야 하는 경우 — OS가 처리하는 뒤로 동작은 시스템 백 항목에서 다루고, 계층 전체를 보여 주려면 브레드크럼을 씁니다. 위에 뜬 부품만 치우려면 모달의 닫기 단추를 두고, 하던 일을 되돌리는 방법은 위험한 동작 항목에서 다룹니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

대부분은 링크로 두는 것이 맞습니다. history.back()으로 방문 기록을 쓸 때만 기록이 빈 경우를 따로 처리합니다.

<!-- 대부분 이 방식이 맞다. 새 탭으로도 열리고, 기록이 비어도 간다 -->
<a class="backlink" href="/orders">
  <span aria-hidden="true">‹</span> 주문 목록
</a>

// 기록을 쓸 거라면 빈 기록일 때 갈 곳을 정해 둔다
function goBack() {
  const sameSite = document.referrer.startsWith(location.origin);
  if (history.length > 1 && sameSite) history.back();
  else location.href = '/orders';   // 상위 화면
}
키와 마크업그때 일어나야 하는 일
Tab · Enter평범한 링크이므로 키보드 조작을 위해 따로 붙일 것이 없습니다
Alt + ←브라우저의 뒤로입니다. 화면 안 단추와 같은 곳으로 가야 사용자가 덜 헷갈립니다
aria-hidden‹ 같은 기호는 읽지 않게 하고 '주문 목록'만 읽게 합니다
Esc뒤로가 아니라 닫기 동작에 연결합니다
rel="up"링크의 뜻을 적어 두는 표시일 뿐이라서 동작은 바뀌지 않습니다
제대로 됐는지 확인하는 방법새 탭에서 상세 화면 주소를 직접 연 뒤 단추를 눌러 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

상위 주소를 응답에 함께 담기응답에 parent_url이나 category_id가 있으면 화면이 위로 단추를 만들 수 있습니다. 이 값이 없으면 화면이 상위 화면을 짐작해야 합니다.
들어온 길을 주소에 남기기주소에 ?from=search 같은 표시를 붙여 두면 돌아갈 곳을 정확히 알 수 있습니다. 다만 그만큼 주소가 길고 복잡해집니다.
돌아갈 목록의 상태 되살리기목록으로 되돌아갈 때 쪽 번호와 필터, 스크롤 위치를 되살리려면 이 상태가 주소에 들어 있어야 합니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS처럼 ‹ 옆에 앞 화면 이름을 붙이는 방식은 웹에서도 그대로 따라 할 만합니다. 누르기 전에 어디로 가는지 알 수 있어서 예상과 결과가 어긋나지 않기 때문입니다. 안드로이드처럼 뒤로와 위로를 나누는 방식은 더 엄밀하지만, 웹에서는 브라우저의 뒤로 버튼이 이미 '뒤로'를 맡고 있으므로 화면 안 단추는 위로로 두는 편이 역할이 겹치지 않습니다.
