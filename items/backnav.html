뒤로가기

Back · up navigation

같은 단추처럼 보이지만 둘입니다 — 들어온 길로 되돌아가는 '뒤로'와 늘 상위로 가는 '위로'.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

같은 화면이라도 어떻게 들어왔는지에 따라 '뒤로'가 데려가는 곳이 달라집니다. 받은 링크로 바로 들어오면 기록에 앞 화면이 없어 갈 데가 없습니다 — 데모가 기록을 들고 있다가 그 경우를 짚어 줍니다.
위로는 다릅니다. 기록과 상관없이 늘 상위 화면으로 가서, 링크로 들어온 사람에게도 갈 곳이 있습니다. 둘을 섞으면 '뒤로를 눌렀는데 엉뚱한 데로 간다'가 됩니다.

2 이름부르는 말이 여러 개다

한국어뒤로가기, 뒤로 단추, 위로 가기, 상위로
영어back, up navigation, back link, ancestor navigation
같이 쓰는 말브라우저·OS 의 기록을 되감는 것이 뒤로(back), 계층에서 부모로 올라가는 것이 위로(up)입니다. 안드로이드가 이 둘을 명시적으로 나눠 지침에 적어 두었습니다 — 시스템 백은 뒤로, 앱바 왼쪽의 ← 는 위로입니다.
자주 잘못 부름닫기 — 닫기는 그 부품만 치웁니다. 화면을 안 바꿉니다.
시스템 백 — 시스템 백은 OS 가 쥔 동작이고 이건 화면 안의 단추입니다.
취소 — 취소는 하던 일을 무르는 것이지 자리 이동이 아닙니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

뒤로(기록) — history.back(), 들어온 길로
위로(상위) — 늘 부모 화면으로
링크로 바로 들어오면 기록에 앞이 없다
이름을 적는다 — '‹ 주문 목록'
<a href> 로 둔다 — 새 탭으로도 열린다
닫기와 섞지 않는다 — 뜻이 다르다
  1. 뒤로(기록) history.back()들어온 길로
  2. 위로(상위) 부모 화면늘 같은 곳으로
  3. 기록이 빈 경우 링크로 들어옴뒤로는 갈 데가 없다
  4. 이름을 적는다 '‹ 주문 목록'어디로 가는지 미리 알린다
  5. <a href> 링크로새 탭·마우스 가운데 버튼이 그냥 된다
  6. 닫기와 구별 뜻이 다름섞으면 둘 다 못 믿는다

실무에서 가장 안전한 선택은 위로입니다 — 기록이 어떻든 늘 같은 곳으로 가고, 링크로 들어온 사람에게도 갈 곳이 있습니다. 그리고 어디로 가는지 이름을 적어 두면('‹ 주문 목록') 누르기 전에 알 수 있어 기대와 결과가 어긋나지 않습니다.
history.back() 을 쓸 거라면 기록이 비었을 때의 길을 꼭 정해 두세요 — document.referrer 가 우리 도메인이 아니면 상위 화면으로 보내는 식입니다. 이걸 안 하면 아무 일도 안 일어나는 단추가 됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 어디로 가는지 이름을 적기 — '‹ 주문 목록'
  • <a href> 로 두기 — 새 탭으로도 열린다
  • 기록이 비었을 때 갈 기본 자리를 정해 두기

이럴 때는 안 쓴다

  • history.back() 만 쓰고 빈 기록을 안 챙기기
  • '뒤로'라고 적고 상위로 보내기 — 둘 중 하나만 한다
  • 닫기 자리에 뒤로를 두기 — 모달이 사라지는 줄 안다
  • 폰에서 시스템 백과 다른 곳으로 보내기

대신 이걸 — OS 쪽 동작은 시스템 백, 계층 전체를 보이려면 브레드크럼, 부품만 치우는 것은 모달의 닫기, 되돌리기는 위험한 동작.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

링크로 두는 것이 거의 늘 맞습니다. 기록을 쓸 때만 빈 기록을 챙깁니다.

<!-- 거의 늘 이쪽 — 새 탭으로도 열리고, 기록이 비어도 간다 -->
<a class="backlink" href="/orders">
  <span aria-hidden="true">‹</span> 주문 목록
</a>

// 기록을 쓸 거라면 빈 기록일 때 갈 곳을 정해 둔다
function goBack() {
  const sameSite = document.referrer.startsWith(location.origin);
  if (history.length > 1 && sameSite) history.back();
  else location.href = '/orders';   // 상위 화면
}
키일어나야 하는 일
Tab · Enter링크다 — 따로 붙일 것이 없다
Alt + ←브라우저의 뒤로. 화면 안 단추와 같은 곳으로 가야 덜 헷갈린다
aria-hidden‹ 같은 기호는 안 읽게 하고 '주문 목록'만 읽힌다
Esc뒤로가 아니라 닫기에 묶는다
rel="up"뜻을 적어 두는 표시. 동작은 안 바뀐다
확인하는 법새 탭에서 상세 주소를 직접 열고 단추를 눌러 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

상위 주소를 같이응답에 parent_url 이나 category_id 가 있으면 위로를 만들 수 있습니다 — 없으면 화면이 짐작해야 합니다.
들어온 길?from=search 같은 표시를 붙여 두면 돌아갈 곳을 정확히 알 수 있습니다. 다만 주소가 지저분해집니다.
목록 상태되돌아갈 때 쪽·필터·굴린 자리를 살리려면 그 상태가 주소에 있어야 합니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

안드로이드가 뒤로와 위로를 나눠 둔 것이 이 항목의 출발점입니다.

앱바의 ← 는 위로, 시스템 백은 뒤로입니다. 둘이 다른 곳으로 가도 됩니다.

자주 생기는 사고 — iOS 의 ‹ 에 앞 화면 이름이 붙는 것은 그대로 베낄 만합니다 — 누르기 전에 어디로 가는지 알 수 있어 기대와 결과가 어긋나지 않습니다. 안드로이드가 둘을 나눠 둔 것은 더 엄밀하지만, 웹에서는 브라우저 뒤로가 이미 '뒤로'를 맡고 있으니 화면 안 단추는 위로로 두는 쪽이 겹치지 않습니다.
