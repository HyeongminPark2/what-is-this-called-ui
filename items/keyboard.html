키보드 조작

Keyboard operability

마우스 없이도 전부 되어야 한다는 것. 손을 못 쓰는 사람뿐 아니라 마우스가 고장 난 사람에게도 해당합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 가지가 똑같아 보이는데 키보드로는 전혀 다릅니다. 마우스를 쓰지 말고 Tab·Enter·Space로만 해 보세요.
<div>는 Tab 이 아예 지나가고, tabindex를 더하면 갈 수는 있는데 Enter·Space 가 안 먹습니다. 기록에 '아무 일도 안 일어남'이 찍히는 것이 그 순간입니다.

2 이름부르는 말이 여러 개다

한국어키보드 조작, 키보드 접근성, 키보드만으로
영어keyboard operability, keyboard accessibility, keyboard trap
같이 쓰는 말빠져나올 수 없게 갇히는 것을 키보드 트랩(keyboard trap)이라 하고 — 포커스 트랩과 달리 나쁜 뜻입니다. 부품마다 정해진 키 약속을 키보드 인터랙션 패턴(ARIA Authoring Practices)이라 합니다.
자주 잘못 부름단축키 — 단축키는 빠르게 하는 것이고, 키보드 조작은 되기는 하는가입니다.
포커스 — 포커스는 '어디 있는가', 키보드 조작은 '거기서 뭘 할 수 있는가'입니다.
키보드 트랩 — 못 빠져나오는 사고입니다. 모달의 포커스 트랩과 헷갈리면 안 됩니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다
대체 텍스트그림의 뜻안 보인다눈으로 안 보는 사람이미지를 끄고 읽어 본다
확대와 글자 크기키웠을 때도 쓰이나안 보인다저시력 사용자200%로 키워 본다

한 줄로 — 규칙은 하나입니다 — 누를 것은 <button>, 이동은 <a href>. div 로 만들면 다섯 가지를 직접 짜야 합니다.

4 갈래같은 모양, 다른 속

5 해부도부분 이름이 제일 안 알려진 지식

저장하기
<button> — 포커스·Enter·Space 가 공짜
<div onclick> — 키보드로 아예 못 간다
tabindex="0" + role="button" — 갈 수는 있다
keydown: Enter · Space — 직접 짜야 한다
화살표 · Esc · Home/End — 부품마다 약속이 있다
  1. 누를 것 button원래 태그를 쓰면 아래 다섯 줄이 전부 공짜다
  2. 태그가 주는 것 <button>포커스 순서 · Enter · Space · 역할 · 비활성 처리
  3. div 로 만들면 <div onclick>Tab 이 아예 안 간다. 마우스 전용이 된다
  4. 순서에 넣기 tabindex="0" + role갈 수는 있게 된다. 아직 눌리지는 않는다
  5. 키 처리 keydownEnter 와 Space 를 직접 받아 click 을 만들어야 한다
  6. 부품별 약속 화살표 · Esc · Home/End탭·라디오·메뉴마다 정해진 키가 있다

<div>로 버튼을 만들면 챙길 것이 다섯 가지입니다 — tabindex · role · Enter · Space · 비활성 처리. 거기에 Space 는 기본으로 화면을 스크롤하므로 preventDefault()도 필요합니다. 전부 맞춰도 <button> 한 글자보다 나은 점이 없습니다 — 그래서 이 항목의 결론은 언제나 "원래 태그를 쓰세요"입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 모든 화면 — 마우스를 치우고 한 번 끝까지 해 봅니다
  • 부품을 새로 만들 때 — 원래 태그가 있는지 먼저 찾습니다
  • 탭·메뉴·라디오처럼 화살표로 도는 부품을 만들 때

이럴 때는 안 쓴다

  • <div>·<span>에 onclick만 거는 것
  • 빠져나올 수 없게 만드는 것(키보드 트랩) — 가장 심각한 사고입니다
  • 마우스 전용 동작만 두는 것 — 호버로만 열리는 메뉴, 드래그로만 되는 정렬
  • tabindex에 1 이상을 주는 것

대신 이걸 — 어디 있는지 보이게 하려면 포커스, 모달 안에 가두려면 포커스 트랩, 태그 고르기는 시맨틱 태그.

8 최소 마크업과 키보드원래 태그를 쓰면 공짜

가장 짧은 답은 태그를 바꾸는 것입니다. 굳이 div 로 만들 때 필요한 줄들을 아래에 적어 뒀습니다.

<!-- 이 한 줄이면 끝난다 -->
<button type="button">저장하기</button>

<!-- 굳이 div 로 만든다면 이만큼이 필요하다 -->
<div role="button" tabindex="0"
     aria-disabled="false">저장하기</div>

el.addEventListener('keydown', (e) => {
  if (e.key === 'Enter' || e.key === ' ') {
    e.preventDefault();      // Space 는 기본이 '화면 스크롤'이다
    el.click();
  }
});
키일어나야 하는 일

Space버튼·체크박스를 누른다. 기본은 화면 스크롤이라 막아야 한다

9 서버 쪽으로 치면백엔드 감각으로 번역

테스트가 가장 쉽다접근성 항목 중 직접 해 보기가 가장 쉽습니다 — 마우스를 치우고 화면을 끝까지 써 보면 됩니다. 도구도 지식도 필요 없습니다.
자동 검사Playwright 로 Tab을 눌러 가며 activeElement를 기록하면 '누를 수 있는데 Tab 이 안 가는 것'을 CI 에서 잡을 수 있습니다.
컴포넌트 라이브러리직접 만들기 전에 키 약속이 구현된 라이브러리를 찾는 편이 거의 늘 낫습니다. 콤보박스 하나에만 키 처리가 열 줄 넘게 들어갑니다.
드래그로만 되는 것순서 바꾸기를 드래그로만 만들면 키보드로는 아예 못 합니다. '위로/아래로' 버튼을 함께 둡니다.
