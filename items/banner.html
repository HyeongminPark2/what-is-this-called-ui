배너

Banner

배너는 화면 꼭대기에 뜨는 알림으로, 토스트와 달리 저절로 사라지지 않습니다. 사용자가 닫을 때까지 남아 있기 때문에 다 읽은 뒤에는 치울 수 있어야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

배너가 여러 개 쌓이면 그만큼 화면 자리를 차지합니다. 배너 수를 늘려 보면 데모가 배너가 화면의 몇 %를 차지하는지 재서 적어 줍니다.
배너를 닫을 수 있게 하기를 끄면 배너를 치울 방법이 없어 계속 남습니다. 또 닫은 배너를 기억하지 않으면 새로 고칠 때마다 다시 뜨는데, 데모가 그렇게 다시 뜬 개수를 세어 보여 줍니다.
배너는 화면 전체에 해당하는 사정을 알리는 데 씁니다. 입력 칸 하나의 오류는 인라인 얼럿으로 알립니다.

2 이름같은 것을 부르는 여러 이름

한국어배너, 상단 알림, 공지 띠
영어banner, message bar, notification banner
같이 쓰는 말앱 전체에 해당하는 것은 앱 배너, 한 화면에만 해당하는 것은 페이지 배너라고 나눠 부릅니다. 브라우저 화면에 뜨는 쿠키 동의 띠나 알림 허용 요청 띠도 배너라고 부릅니다. Material에는 M2 때 Banner라는 이름의 부품이 있었지만, M3에서는 다른 방법을 쓰라고 권합니다.
자주 잘못 부르는 이름토스트 — 토스트는 저절로 사라지지만, 배너는 사용자가 닫을 때까지 남습니다.
인라인 얼럿 — 인라인 얼럿은 화면 전체가 아니라 그 자리에 해당하는 사정을 알립니다.
광고 배너 — 같은 낱말을 쓰지만 알림 배너와는 전혀 다른 것입니다.

3 상태상태마다 달라지는 모습

4 해부도부분마다 붙은 이름

화면 꼭대기에 떠 있지 않고 자리를 차지함
읽고 치울 때까지 사라지지 않음
'갱신하기' 같은 할 일 하나를 붙임
닫을 수 있고, 닫은 배너는 기억해 둠
쌓이면 내용보다 알림이 더 커짐
화면 전체의 사정만, 칸 하나는 인라인 얼럿으로
  1. 자리 화면 꼭대기화면 위에 떠 있지 않고 본문 위쪽 자리를 차지합니다
  2. 남아 있는 시간 치울 때까지저절로 사라지는 토스트와 반대입니다
  3. 할 일 하나만 붙임'갱신하기'처럼 할 일 하나를 붙입니다
  4. 닫기 꼭 둠사용자가 닫은 배너는 기억해 둡니다
  5. 쌓임 읽지 않게 됨두 개가 쌓이면 둘 다 읽지 않습니다
  6. 범위 화면 전체입력 칸 하나의 사정은 인라인 얼럿으로 알립니다

배너는 대개 비슷한 과정을 거쳐 늘어납니다. 누군가 중요한 공지를 하나 올리고, 다음 달에 또 하나가 붙다 보면, 반 년 뒤에는 본문보다 배너 띠가 더 큰 화면이 됩니다. 그래서 배너를 만들 때 언제 내릴지를 처음부터 정해 두는 것이 좋습니다. 예를 들어 점검 안내라면 점검이 끝나는 시각에 저절로 내려가게 합니다.
닫은 배너를 기억하지 않으면 사용자는 같은 배너를 들어올 때마다 닫아야 합니다. 그러면 사용자에게 닫기 버튼은 '읽었다'는 표시가 아니라 '또 떴네' 하며 치우는 버튼이 됩니다.

5 쓸 때 / 안 쓸 때

배너를 알맞게 쓰는 경우

  • 한 번에 하나만 띄울 때
  • 닫을 수 있게 하고, 닫은 배너를 기억해 둘 때
  • 언제 내릴지를 처음부터 정해 둘 때

배너를 잘못 쓰는 경우

  • 배너를 여러 개 쌓을 때. 두 개가 쌓이면 사용자는 둘 다 읽지 않습니다
  • 닫기 버튼을 두지 않을 때(서비스가 멈춘 경우는 예외)
  • 입력 칸 하나의 오류를 배너로 알릴 때. 오류는 그 칸 옆에 적습니다
  • 성공을 배너로 알릴 때. 성공은 토스트나 작업한 자리에서 알립니다

배너 대신 다른 것을 써야 하는 경우 — 저절로 사라져도 되는 알림이면 토스트, 특정 자리에 해당하는 사정이면 인라인 얼럿, 하던 일을 막아야 하면 모달, 나중에 모아 보는 알림이면 알림 센터를 씁니다.

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

role="status"로 스크린 리더에 알리고 닫기 버튼을 답니다. 배너는 본문 위쪽 자리를 차지하므로 화면 위에 떠 있게 만들지 않습니다.

<div class="banner banner--warn" role="status">
  <span aria-hidden="true">!</span>
  <p>사업자 정보가 만료되어 갱신이 필요합니다.</p>
  <a href="/settings/business">갱신하기</a>
  <button aria-label="이 알림 닫기">✕</button>
</div>

// 닫은 배너는 기억해 둔다. 기억하지 않으면 매번 다시 뜬다
closeBtn.onclick = () => {
  localStorage.setItem('banner:biz-expiry', 'dismissed');
  banner.remove();
};
키와 마크업그때 일어나야 하는 일
role="status"배너가 뜨면 스크린 리더가 읽던 말을 마친 뒤 배너를 읽어 줍니다
Tab배너 안의 링크와 닫기 버튼으로 포커스를 옮길 수 있어야 합니다
aria-label✕ 버튼에 무엇을 닫는지 적습니다
배너가 뜰 때의 초점배너가 떠도 초점을 옮기지 않습니다. 초점이 옮겨 가면 하던 일이 끊깁니다
마크업 안에서의 차례마크업에서 본문보다 먼저 둬야 스크린 리더도 배너를 먼저 읽습니다
확인하는 방법배너를 닫고 새로 고침한 뒤 다시 뜨는지 봅니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

언제까지 띄울지 정하기expires_at 값을 두면 그 시각에 배너가 저절로 내려가기 때문에, 누군가 잊지 않고 직접 지울 필요가 없습니다.
누구에게 띄울지 정하기'사업자 정보 만료' 같은 배너는 해당하는 사용자에게만 띄웁니다. 모두에게 띄우면 대부분의 사용자에게는 쓸모없는 띠가 됩니다.
닫은 기록을 계정별로 저장하기닫은 기록을 계정별로 저장하면 다른 기기에서도 그 배너가 다시 뜨지 않습니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

배너는 웹에서 가장 흔하게 쓰고, 앱 쪽 지침은 배너를 줄이는 추세입니다.

웹직접 만듦
점검 안내✕
쿠키 동의 띠와 공지 띠로 익숙한 부품입니다. 웹에서는 배너가 쉽게 쌓이는 편입니다.
iOS정식 부품 없음
정식 부품이 없습니다. 중요한 사정은 화면 내용 안에 섞어 넣는 방식을 권합니다.
안드로이드M2 Banner (M3에서 뺌)
M2에 있던 Banner가 M3에서는 빠졌습니다. 남용되기 쉬운 부품이기 때문입니다.

플랫폼 차이 때문에 자주 생기는 문제 — Material이 배너를 지침에서 뺀 이유를 볼 만합니다. 배너는 만들기 쉬워서 자꾸 늘어나는데, 늘어날수록 사용자가 읽지 않게 되기 때문입니다. Material은 배너 대신 알릴 내용을 화면 안에 섞어 넣는 방식을 권합니다. 웹에서도 배너를 하나 더 올리고 싶을 때 그 내용을 본문 어디에 적을 수 있는지 먼저 찾아보면 배너가 늘어나는 것을 막을 수 있습니다.
