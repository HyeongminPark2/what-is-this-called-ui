숫자 꼴

Numerals · tabular figures

숫자의 너비. 세로로 쌓이는 표나 1초마다 바뀌는 값에서 자릿수가 흔들리면 읽을 수 없습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

가운데 표가 글꼴마다 직접 재서 알려 줍니다 — '원래 고름'인지, '켜니 고르게 됨'인지, '켜도 안 바뀜 — 기능 없음'인지.
tabular-nums는 글꼴에 그 기능이 있을 때만 먹습니다. 세리프 계열에는 대개 없어서 켜도 아무 일이 일어나지 않습니다. 위의 큰 숫자에서 흔들린 폭이 실시간으로 쌓이는 것도 보세요.

2 이름부르는 말이 여러 개다

한국어숫자 꼴, 등폭 숫자, 고정폭 숫자
영어tabular figures, tabular-nums, lining figures, oldstyle figures
같이 쓰는 말너비가 다 같은 숫자를 등폭 숫자(tabular figures), 글자마다 다른 것을 비례 숫자(proportional figures)라 합니다. 높이가 들쭉날쭉한 옛 스타일 숫자는 올드스타일(oldstyle · text figures), 키가 고른 것은 라이닝(lining)입니다. 글꼴 안의 기능 이름은 tnum·pnum입니다.
자주 잘못 부름등폭 글꼴 — 모든 글자가 같은 너비인 글꼴(코드용)과, 숫자만 같은 너비인 기능은 다릅니다.
text-align: right — 오른쪽 맞춤은 자릿수를 끝에서 맞출 뿐, 너비 자체는 안 바꿉니다.
천 단위 쉼표 — 자릿수 읽기를 돕지만 흔들림은 못 막습니다.

한 줄로 — tabular-nums는 글꼴이 지원할 때만 먹습니다. 중요한 자리라면 켜 놓고 끝내지 말고 재 보고 정해야 합니다.

4 갈래글꼴마다 사정이 다르다

5 해부도부분 이름이 제일 안 알려진 지식

₩1,284,000
font-variant-numeric: tabular-nums
글꼴에 tnum 기능이 없으면 안 먹는다
text-align: right — 자릿수를 오른쪽에 맞춘다
toLocaleString('ko-KR') — 천 단위 쉼표
등폭 글꼴 — 기능 없는 글꼴의 대안
  1. 바뀌는 숫자 value금액·시간·카운트다운. 값이 바뀌어도 자리가 안 흔들려야 한다
  2. 등폭 켜기 tabular-nums숫자마다 같은 너비를 쓰게 한다
  3. 글꼴 지원 tnum feature글꼴에 이 기능이 없으면 아무 일도 안 일어난다. 한글 글꼴에 특히 흔하다
  4. 오른쪽 맞춤 text-align: right자릿수를 끝에서 맞춘다. 등폭과 둘 다 있어야 표가 읽힌다
  5. 천 단위 쉼표 toLocaleString읽기를 돕는다. 통화·소수점 규칙도 이걸로 맞춘다
  6. 등폭 글꼴 monospace기능이 없는 글꼴을 만났을 때의 확실한 대안

tabular-nums를 켜 두고 된 줄 아는 것이 가장 흔한 실수입니다. 이 속성은 글꼴 안의 기능을 켜는 스위치일 뿐이라, 그 기능이 없는 글꼴에서는 아무 일도 일어나지 않고 경고도 없습니다. 글꼴을 바꾸는 날 조용히 깨지는 자리이기도 합니다 — 개발자 도구에서 숫자 너비를 재 보는 것이 유일한 확인 방법입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 세로로 쌓이는 숫자 — 표의 금액 열, 목록의 값
  • 자주 바뀌는 숫자 — 타이머, 카운트다운, 실시간 집계
  • 자릿수가 같은 값들을 비교해야 할 때

이럴 때는 안 쓴다

  • 읽는 문장 속 숫자 — 비례 숫자가 더 자연스럽습니다
  • 켜 놓고 확인 안 하는 것 — 글꼴이 지원하는지 재 봐야 합니다
  • 오른쪽 맞춤 없이 등폭만 — 자릿수가 다르면 여전히 어긋납니다
  • 숫자만 다른 글꼴로 바꾸는 것 — 글자와 숫자의 높이가 안 맞을 수 있습니다

대신 이걸 — 표 전체의 짜임은 데이터 테이블(10부), 큰 숫자 하나는 스탯 타일, 글꼴 파일 문제는 웹폰트.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙켜고 나서 재 본다

한 줄로 켜고, 정말 먹었는지 재 보는 한 줄을 더 둡니다.

/* 표·타이머처럼 자릿수가 맞아야 하는 곳 */
.amount, .timer, td {
  font-variant-numeric: tabular-nums;
  text-align: right;      /* 둘 다 있어야 읽힌다 */
}

// 천 단위 쉼표와 통화는 로케일에 맡긴다
new Intl.NumberFormat('ko-KR',
  { style: 'currency', currency: 'KRW' }).format(1284000);

// 글꼴이 정말 지원하는지 재 본다
const p = document.createElement('span');
p.style.cssText = 'position:absolute;visibility:hidden;font-variant-numeric:tabular-nums';
document.body.append(p);
p.textContent = '1111'; const a = p.offsetWidth;
p.textContent = '0000'; const ok = (a === p.offsetWidth);
규칙지켜야 하는 것
표와 타이머에 켠다세로로 쌓이거나 자주 바뀌는 숫자
오른쪽 맞춤과 함께등폭만으로는 자릿수가 다른 값이 안 맞는다
정말 먹는지 재 본다글꼴에 기능이 없으면 조용히 아무 일도 안 일어난다
안 되면 등폭 글꼴숫자만 font-family를 바꾸는 방법도 있다
문장 속 숫자는 그대로읽는 글에서는 비례 숫자가 더 자연스럽다
쉼표는 Intl로통화 기호·소수점·자릿수 규칙이 나라마다 다르다

9 서버 쪽으로 치면백엔드 감각으로 번역

서식은 어디서 하나1284000을 내려주고 화면에서 서식을 입히는 쪽이 낫습니다. 서버가 '₩1,284,000' 문자열을 보내면 정렬도 계산도 못 합니다.
소수점과 반올림금액은 정수로 다루고 화면에서만 나눕니다. 부동소수점으로 돈을 세면 1원이 사라집니다.
통화와 로케일Intl.NumberFormat이 통화 기호 위치·쉼표·소수 자릿수를 한 번에 맞춰 줍니다.
큰 수 줄이기'₩12.8억'처럼 줄일지는 화면이 정합니다. 어디서 반올림할지를 한 군데에 모아 두지 않으면 화면마다 숫자가 달라집니다.
