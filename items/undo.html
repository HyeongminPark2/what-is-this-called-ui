되돌리기

Undo

되묻기는 할 때마다 멈춰 세웁니다. 되돌리기는 안 멈추는 대신 몇 초 안에만 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

되묻기는 매번 멈춰 세웁니다 — 데모가 지우는 동안 몇 번 멈춰 세웠는지 셉니다. 열 번 지우면 열 번 멈춥니다.
되돌리기는 안 멈추는 대신 시간이 지나면 끝입니다. 창이 닫힌 뒤에 눌러 보면 데모가 너무 늦은 되돌리기를 셉니다. 그래서 되돌릴 수 있는 시간은 5초 안팎이 보통이고, 정말 되돌릴 수 없는 일에는 되묻기를 씁니다.

2 이름부르는 말이 여러 개다

한국어되돌리기, 실행 취소, 언두
영어undo, undo toast, undo snackbar
같이 쓰는 말지운 뒤 잠깐 뜨는 띠를 언두 스낵바(undo snackbar)라 부릅니다. 지운 것을 바로 없애지 않고 일정 기간 두는 것을 소프트 삭제(soft delete), 그 기간을 유예 기간(grace period)이라 합니다. 여러 단계를 되돌리는 것은 되돌리기 기록(undo stack)입니다.
자주 잘못 부름취소 — 취소는 하기 전에 그만두는 것입니다. 되돌리기는 한 뒤에입니다.
되묻기 — 위험한 동작의 확인은 막아 세우는 쪽입니다.
휴지통 — 휴지통은 며칠 두는 유예 기간이고, 되돌리기는 몇 초입니다.

3 가르는 기준형제들과 비교하는 네 축

되돌릴 수 없는 일을 다루는 방법들입니다. 이 네 가지만 물어보면 갈립니다.

언제 멈추나되돌릴 수 있나몇 번 멈추나되돌릴 수 없는 일에
되돌리기안 멈춘다몇 초 안에 가능0번안 맞는다
되묻기하기 전에되묻는 순간에만할 때마다맞는다
이름 적어 확인하기 전에아니오를 고르면할 때마다가장 센 확인
유예 기간안 멈춘다며칠 동안0번계정 삭제 같은 일

한 줄로 — 되돌릴 수 있으면 묻지 마세요. 묻는 것이 맞는 일은 되돌릴 수 없는 일뿐입니다.

4 상태시간이 지나면 끝난다

5 해부도부분 이름이 제일 안 알려진 지식

무엇을 했는지 — '영수증을 지웠습니다'
되돌리기 — 한 번 누르면 끝
남은 시간 — 5초 안팎
창이 닫히면 되돌릴 수 없다
role="status" — 소리로도 알린다
되돌릴 수 없는 일에는 되묻기를 쓴다
  1. 무엇을 했는지 한 줄'영수증을 지웠습니다'
  2. 되돌리기 한 번두 단계로 만들지 않는다
  3. 남은 시간 5초 안팎보여 주면 덜 불안하다
  4. 창이 닫힘 끝그 뒤에는 방법이 없다
  5. role="status" 소리로띠가 떴다는 것을 알린다
  6. 되묻기 되돌릴 수 없을 때그때만 쓴다

되묻기를 기본으로 두면 사람이 그것을 안 읽게 됩니다 — 매번 뜨는 창은 몇 번 지나면 '예'를 누르는 동작이 되어 버려 정작 막아야 할 때 못 막습니다. 그래서 되돌릴 수 있는 일은 묻지 않고, 되묻기는 정말 되돌릴 수 없는 일에 아껴 둡니다.
키보드만 쓰는 사람에게는 5초가 짧습니다 — 띠가 떴다는 것을 알고, Tab 으로 가서, 누르기까지의 시간입니다. 띠에 초점을 옮기거나(알림이라면), 적어도 role="status" 로 떴다는 것을 알려야 합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 되돌릴 수 있는 일은 묻지 않기
  • 남은 시간을 보여 주기
  • 여러 개를 지우면 띠를 하나로 묶기

이럴 때는 안 쓴다

  • 모든 삭제에 되묻기 붙이기 — 읽지 않게 된다
  • 되돌리기를 두 단계로 만들기 — 한 번이면 된다
  • 띠를 쌓기 — 셋을 지우면 셋이 떠 화면을 덮는다
  • 소리로 안 알리기 — 띠가 떴는지도 모른다

대신 이걸 — 되돌릴 수 없는 일은 위험한 동작, 띠 부품 자체는 토스트, 며칠 두는 것은 휴지통(소프트 삭제), 보내기 전 확인은 다이얼로그.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 띠의 계약서

띠는 role="status" 로 알리고, 되돌리기는 평범한 버튼입니다.

<div class="undo-bar" role="status">
  <span>영수증_2411_01.jpg 을 지웠습니다</span>
  <button>되돌리기</button>
  <span class="left">5초</span>
</div>

// 서버에는 바로 보내되, 되돌릴 수 있게 둔다
const id = await api.softDelete(fileId);   // 표시만 지움
const t = setTimeout(() => api.purge(id), 5000);

undoBtn.onclick = async () => {
  clearTimeout(t);
  await api.restore(id);
  announce('영수증이 돌아왔습니다');
};
키일어나야 하는 일
role="status"띠가 떴다고 하던 말이 끝난 뒤 읽어 준다
Tab띠의 되돌리기로 갈 수 있어야 한다
초점 옮기기띠로 초점을 뺏지는 않는다 — 하던 일이 끊긴다
Ctrl + Z글 편집기라면 같이 묶어 둔다
시간5초는 키보드 사용자에게 짧다 — 멈춤 단추를 두거나 늘린다
확인하는 법마우스를 안 쓰고 Tab 만으로 되돌려 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

바로 지우지 않는다표시만 지우고 몇 초 뒤에 정말 지웁니다 — 그 사이에 되돌리기가 옵니다.
되돌리기 열쇠지울 때 undo_token 을 돌려주면 무엇을 되살릴지가 분명해집니다.
여러 개묶어서 지웠으면 묶음 단위로 되살려야 합니다 — 하나씩이면 순서가 꼬입니다.
유예 기간계정·프로젝트처럼 큰 것은 며칠을 둡니다. 그동안은 목록에서만 숨깁니다.

Material 이 스낵바 + UNDO 를 표준으로 못박아, 목록에서 되묻기를 거의 안 씁니다.

자주 생기는 사고 — 안드로이드가 '지우고 되돌리기'를 표준으로 삼은 덕에 그쪽 앱에서는 삭제 확인 창이 드뭅니다 — 쓰다 보면 훨씬 덜 거슬립니다. iOS 는 반대로 되묻기를 더 쓰는데, 흔들어 취소라는 숨은 기능이 있어 글 편집에서는 되돌리기가 됩니다. 웹에서는 둘 다 직접 만들어야 하니 어느 쪽을 기본으로 삼을지를 팀에서 한 번 정해 두면 화면마다 다르게 되는 일이 없습니다.
