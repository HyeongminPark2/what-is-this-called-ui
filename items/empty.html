빈 상태

Empty state

보여 줄 것이 아무것도 없을 때의 화면. 비어 있는 이유가 저마다 달라서, 해야 할 말도 전부 다릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 가지를 번갈아 눌러 보세요. 모두 "아무것도 없는 화면"이지만 할 말이 전혀 다릅니다. 처음이면 첫 걸음을, 검색 결과가 없으면 조건을 푸는 길을, 다 지운 뒤면 잘 끝냈다고 말합니다. 셋을 같은 "데이터가 없습니다"로 때우면 세 번 다 쓸모가 없어집니다.

2 이름부르는 말이 여러 개다

한국어빈 상태, 빈 화면, 공백 상태
영어empty state, blank state, zero state
같이 쓰는 말처음 쓰는 사람에게 보이는 것을 제로 스테이트나 온보딩 빈 상태라 따로 부르기도 합니다. 가짜 데이터를 흐리게 깔아 두는 기법은 고스트 콘텐츠.
자주 잘못 부름404 — 404는 없는 주소를 뜻합니다. 주소는 맞는데 안에 든 것이 없는 상태가 빈 상태입니다.
에러 — 비어 있는 것은 잘못된 상태가 아닙니다. 빨갛게 칠하면 안 됩니다.
로딩 — 아직 안 온 것과 원래 없는 것은 다릅니다. 불러오는 중에 빈 상태를 띄우면 사용자를 속이는 셈입니다.

3 가르는 기준형제들과 비교하는 네 축

겹쳐 뜨는 부품들은 모양으로는 구별이 안 됩니다. 이 네 가지만 물어보면 갈립니다.

왜 비었나해야 할 말버튼그림
처음아직 아무것도 안 만들었다첫 걸음을 알려 준다만들기 · 가져오기밝게, 기대감
검색 결과 없음조건이 너무 좁다조건을 푸는 길조건 지우기 · 다시 찾기조용하게
다 지움잘 끝냈다수고했다고 말한다처리한 것 보기 (선택)성공 색
권한 없음볼 자격이 없다누구에게 요청할지관리자에게 요청잠금 느낌

한 줄로 — 빈 상태의 핵심은 '비었다'가 아니라 왜 비었고 이제 뭘 하면 되는가입니다. 그 말이 없으면 그냥 막다른 길입니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

＋
아직 프로젝트가 없습니다
첫 프로젝트를 만들면 팀원을 부르고
지표를 모을 수 있습니다.
프로젝트 만들기 가져오기
  1. 자리 container목록이 들어올 그 자리에 그대로 둔다. 다른 화면으로 보내지 않는다
  2. 그림 illustration · icon분위기를 정한다. 처음이면 밝게, 검색 결과 없음이면 조용하게
  3. 제목 title왜 비었는지 한 줄. '없습니다'로 끝내지 않는다
  4. 설명 description다음에 뭘 하면 되는지. 두 줄을 넘기지 않는다
  5. 주 행동 primary action딱 하나. 여기서 할 수 있는 가장 자연스러운 일
  6. 보조 행동 secondary action다른 길. 없어도 되고, 있으면 하나까지

그림은 없어도 됩니다. 관리 도구처럼 자주 보는 화면에서는 큰 그림이 오히려 성가십니다. 반대로 처음 쓰는 사람이 보는 화면이라면 공들일 값어치가 큽니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 처음 쓰는 사람에게 첫 걸음을 알려 줄 때 — 이 화면 하나가 제품의 첫인상입니다
  • 검색·필터 결과가 없을 때 무엇으로 찾았는지와 푸는 길을 보여 줄 때
  • 할 일을 다 끝냈을 때 — 비어 있는 것이 성취인 경우

이럴 때는 안 쓴다

  • 셋을 같은 문구로 때우기 — "데이터가 없습니다"는 세 번 다 쓸모없습니다
  • 에러처럼 빨갛게 칠하기 — 비어 있는 것은 잘못이 아닙니다
  • 불러오는 중에 띄우기 → 그건 스켈레톤이나 스피너 자리입니다
  • 큰 그림만 두고 할 일을 안 주기 — 예쁜 막다른 길이 됩니다

대신 이걸 — 아직 불러오는 중이면 스켈레톤, 불러오다 실패했으면 에러 상태, 방금 비운 것을 되돌릴 수 있으면 되돌리기 토스트.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

어려운 건 마크업이 아니라 세 가지(또는 네 가지) 경우를 가려내는 일입니다. 불러오는 중과 비어 있는 것을 같은 분기로 다루면 반드시 틀립니다.

// 상태를 하나로 뭉치지 않는다 — 이 분기가 이 항목의 전부다
if (loading) return <Skeleton />;
if (error)   return <ErrorState … />;
if (!items.length) return hasFilters
  ? <Empty kind="noResult" query={q} onClear={clear} />
  : <Empty kind="first" onCreate={create} />;
return <List items={items} />;

<!-- 비어 있는 것은 에러가 아니다. role="alert" 를 붙이지 않는다 -->
<div class="empty">
  <img alt="">  <!-- 장식 그림은 alt 를 비운다 -->
  <h3>아직 프로젝트가 없습니다</h3>
</div>
키일어나야 하는 일
Tab주 행동으로 바로 닿아야 한다. 빈 화면에서 누를 것이 그것뿐이다
스크린 리더제목을 h2·h3로 두면 건너뛰기 목록에 잡힌다
장식 그림alt=""로 비운다. 뜻을 담은 그림이면 설명을 적는다
role경고가 아니다. role="alert"나 status를 붙이지 않는다
검색 결과 없음찾은 말을 제목에 넣어 읽히게 한다 — "'환불 대기'에 맞는 것이 없습니다"

9 서버 쪽으로 치면백엔드 감각으로 번역

빈 응답 ≠ 에러200에 빈 배열은 정상입니다. 빈 목록을 404로 돌려주면 화면이 엉뚱하게 에러로 갈립니다. 자주 나는 실수입니다.
왜 비었는지도 응답에필터 때문인지 원래 없는 건지는 서버가 더 잘 압니다. total과 filteredTotal을 같이 주면 화면이 가려낼 수 있습니다.
권한으로 빈 것403을 빈 목록으로 뭉개면 사용자는 영문도 모른 채 빈 화면을 봅니다. 이유를 구분해 내려 줍니다.
첫 사용자 지표처음 빈 상태는 가입 직후 거의 모두가 보는 화면입니다. 여기서 빠져나가는 비율이 제품 전체 이탈에 바로 반영됩니다.
