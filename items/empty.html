빈 상태

Empty state

빈 상태는 목록이나 화면에 보여 줄 것이 하나도 없을 때 띄우는 화면입니다. 비어 있는 이유가 경우마다 다르기 때문에 사용자에게 해야 할 말도 경우마다 다릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 가지를 번갈아 눌러 보세요. 셋 다 "아무것도 없는 화면"이지만 사용자에게 하는 말은 전혀 다릅니다. 처음 쓰는 사람에게는 첫 걸음을, 검색 결과가 없을 때는 조건을 푸는 방법을 알려 주고, 할 일을 다 지운 뒤에는 잘 끝냈다고 말합니다. 세 경우를 모두 "데이터가 없습니다" 한 줄로 처리하면 어느 경우에도 사용자에게 도움이 되지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어빈 상태, 빈 화면, 공백 상태
영어empty state, blank state, zero state
같이 쓰는 말처음 쓰는 사람에게 보이는 빈 상태는 제로 스테이트나 온보딩 빈 상태라고 따로 부르기도 합니다. 가짜 데이터를 흐리게 깔아 두는 기법은 고스트 콘텐츠라고 합니다.
자주 잘못 부르는 이름404 — 404는 주소 자체가 없다는 뜻입니다. 반면 빈 상태는 주소는 맞는데 그 안에 든 것이 없는 상태입니다.
에러 — 비어 있다고 해서 무언가 잘못된 것은 아니므로 에러처럼 빨갛게 칠하면 안 됩니다.
로딩 — 데이터가 아직 도착하지 않은 것과 원래 없는 것은 다릅니다. 불러오는 중에 빈 상태를 띄우면 사용자에게 사실과 다른 정보를 주게 됩니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품은 생김새로는 가르기 어렵습니다. 아래 네 가지로 가릅니다.

화면이 비어 있는 이유사용자에게 해야 할 말두어야 할 버튼그림의 분위기
처음 쓸 때아직 아무것도 만들지 않음첫 걸음을 알려 줌만들기 · 가져오기밝고 기대감 있게
검색 결과가 없을 때검색 조건이 너무 좁음조건을 푸는 방법을 알려 줌조건 지우기 · 다시 찾기차분하게
할 일을 다 끝냈을 때일을 다 끝냄수고했다고 말해 줌처리한 것 보기 (선택)성공을 뜻하는 색으로
볼 권한이 없을 때볼 권한이 없음누구에게 요청할지 알려 줌관리자에게 요청잠금을 나타내는 그림으로

빈 상태를 한 줄로 정리하면 — 빈 상태에서 알려 줘야 할 것은 화면이 비었다는 사실보다 왜 비었고 이제 무엇을 하면 되는지입니다. 이 안내가 없으면 사용자는 그 화면에서 더 할 수 있는 일이 없습니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

＋
아직 프로젝트가 없습니다
첫 프로젝트를 만들면 팀원을 부르고
지표를 모을 수 있습니다.
프로젝트 만들기 가져오기
  1. 자리 container목록이 들어올 자리에 그대로 둡니다. 사용자를 다른 화면으로 보내지 않습니다
  2. 그림 illustration · icon화면의 분위기를 정합니다. 처음 쓰는 사람에게는 밝게, 검색 결과가 없을 때는 차분하게 그립니다
  3. 제목 title왜 비었는지 한 줄로 적습니다. '없습니다'로 끝내지 않습니다
  4. 설명 description다음에 무엇을 하면 되는지 적습니다. 두 줄을 넘기지 않습니다
  5. 주 행동 primary action하나만 둡니다. 이 화면에서 사용자가 가장 자연스럽게 이어 할 일을 고릅니다
  6. 보조 행동 secondary action주 행동 말고 다른 선택지입니다. 없어도 되고, 둔다면 하나까지만 둡니다

그림은 없어도 됩니다. 관리 도구처럼 자주 보는 화면에서는 큰 그림이 볼 때마다 자리를 차지해 오히려 성가십니다. 반대로 처음 쓰는 사람이 보는 화면이라면 그림에 공들일 만한 가치가 큽니다.

6 쓸 때 / 안 쓸 때

빈 상태를 쓰는 경우

  • 처음 쓰는 사람에게 첫 걸음을 알려 줄 때. 처음 빈 상태는 사용자가 제품을 처음 접하는 화면입니다
  • 검색이나 필터 결과가 없을 때 무엇으로 찾았는지와 조건을 푸는 방법을 보여 줄 때
  • 할 일을 다 끝내서 목록이 비었을 때. 비어 있다는 것이 곧 일을 다 끝냈다는 뜻입니다

빈 상태를 쓰지 않는 경우

  • 세 경우를 같은 문구로 처리할 때. "데이터가 없습니다"는 어느 경우에도 도움이 되지 않습니다
  • 에러처럼 빨갛게 칠할 때. 비어 있다고 해서 잘못된 것은 아닙니다
  • 아직 불러오는 중일 때. 불러오는 동안에는 스켈레톤이나 스피너를 띄웁니다
  • 큰 그림만 두고 다음에 할 일을 알려 주지 않을 때. 보기에는 좋아도 사용자가 그 화면에서 할 수 있는 일이 없습니다

빈 상태 대신 다른 것을 써야 하는 경우 — 아직 불러오는 중이면 스켈레톤을 띄우고, 불러오다 실패했으면 에러 상태를 보여 줍니다. 사용자가 방금 비운 것을 되돌릴 수 있다면 되돌리기 토스트로 알립니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

마크업은 간단하고, 손이 가는 부분은 세 가지(또는 네 가지) 경우를 가려내는 일입니다. 불러오는 중인 상태와 비어 있는 상태를 같은 분기로 처리하면 불러오는 동안 빈 상태가 잘못 뜹니다.

// 상태를 하나로 뭉치지 않고 경우마다 따로 분기한다
if (loading) return <Skeleton />;
if (error)   return <ErrorState … />;
if (!items.length) return hasFilters
  ? <Empty kind="noResult" query={q} onClear={clear} />
  : <Empty kind="first" onCreate={create} />;
return <List items={items} />;

<!-- 비어 있는 것은 에러가 아니다. role="alert" 를 붙이지 않는다 -->
<div class="empty">
  <img alt="">  <!-- 장식 그림은 alt 를 비운다 -->
  <h3>아직 프로젝트가 없습니다</h3>
</div>
상황그때 일어나야 하는 일
Tab주 행동 버튼에 바로 닿아야 합니다. 빈 화면에서 누를 수 있는 것은 사실상 그 버튼뿐입니다
스크린 리더로 읽을 때제목을 h2나 h3로 두면 스크린 리더의 제목 목록에 나타나 바로 건너갈 수 있습니다
장식용 그림을 넣을 때alt=""로 비웁니다. 뜻을 담은 그림이라면 설명을 적습니다
role 속성을 붙일지빈 상태는 경고가 아니므로 role="alert"나 status를 붙이지 않습니다
검색 결과가 없을 때"'환불 대기'에 맞는 것이 없습니다"처럼 검색한 말을 제목에 넣어 함께 읽히게 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

빈 목록을 에러로 돌려주지 않기200과 빈 배열을 돌려주는 것이 정상입니다. 빈 목록을 404로 돌려주면 화면이 빈 상태 대신 에러 화면을 띄웁니다. 자주 하는 실수입니다.
비어 있는 이유도 응답에 담기필터 때문에 비었는지 원래 없는지는 서버가 더 잘 압니다. 응답에 total과 filteredTotal을 함께 주면 화면에서 두 경우를 가려낼 수 있습니다.
권한이 없어 비어 보이는 경우403을 빈 목록으로 바꿔 돌려주면 사용자는 이유도 모른 채 빈 화면을 봅니다. 비어 있는 이유를 구분해서 응답에 담아 줍니다.
첫 사용자 이탈률에 주는 영향처음 빈 상태는 가입 직후 거의 모든 사용자가 보는 화면입니다. 그래서 이 화면에서 떠나는 사용자의 비율이 제품 전체 이탈률에 바로 반영됩니다.

플랫폼 차이 때문에 자주 생기는 문제 — "빈 화면 하나 만들어 주세요"라는 요청에는 보통 네 가지 경우가 한데 섞여 있습니다. 처음·검색 결과 없음·다 지움·권한 없음 가운데 어느 경우인지를 먼저 가려야 문구와 버튼을 정할 수 있습니다. 경우를 가리지 않으면 "데이터가 없습니다" 한 줄로 끝나기 쉽습니다.
