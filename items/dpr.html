화면 밀도

Device pixel ratio

CSS 의 1px 은 길이 단위이지 화소가 아닙니다. 배율 3배 화면에서는 화소 세 개로 그려집니다.

배율을 바꾸면 캔버스의 실제 화소 수가 함께 바뀝니다.
1배짜리 그림은 3배 화면에서 세 배로 늘어나 뭉개지고, 배율만큼 받은 그림과 SVG는 그대로입니다. 아래 두 줄은 1px 선과 화소 하나짜리 선의 차이입니다 — 배율이 높을수록 화소 하나는 가늘어집니다. 위에 이 화면의 실제 배율도 나옵니다.

2 이름부르는 말이 여러 개다

한국어화면 밀도, 픽셀 배율, 고해상도 화면
영어device pixel ratio (DPR), pixel density, Retina / HiDPI
같이 쓰는 말브라우저가 알려 주는 값이 window.devicePixelRatio이고, 애플은 레티나, 일반적으로는 HiDPI라 부릅니다. 그림을 배율별로 주는 것이 srcset의 1x · 2x · 3x이고, 화소 하나 굵기의 선을 헤어라인(hairline)이라 합니다. 안드로이드의 길이 단위 dp, 애플의 pt가 CSS 의 px 과 같은 자리입니다.
자주 잘못 부름해상도 — '1920×1080'은 화소 수이고, 밀도는 그 화소가 얼마나 빽빽한가입니다.
화면 크기 — 브레이크포인트가 보는 폭은 CSS px이라 밀도와 무관합니다.
DPI — 인쇄의 단위입니다. 화면에서는 배율로 다룹니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다
HIG와 Material의 차이OS 의 말투각자 다르다웹 관례어느 쪽에서도 어색하다

한 줄로 — 선은 저절로 맞고, 그림은 저절로 안 맞습니다. 밀도 때문에 할 일은 거의 전부 그림에 관한 것입니다.

4 배율에 따라무엇이 바뀌고 무엇이 안 바뀌나

5 해부도부분 이름이 제일 안 알려진 지식

CSS 1px — 길이 단위다. 화소가 아니다
devicePixelRatio = 3 — 기기 화소 3개가 CSS 1px
그림은 CSS 크기 × 배율 만큼의 화소가 필요하다
srcset · 2x · 3x — 그 배율에 맞는 것을 받는다
SVG · 글자는 배율과 상관없다
머리카락 선 = 1 ÷ 배율 px
  1. CSS px 길이 단위어느 화면에서나 눈에 같은 크기로 보이게 정한 단위
  2. 배율 devicePixelRatioCSS 1px 을 기기 화소 몇 개로 그리는가
  3. 그림에 필요한 화소 CSS 크기 × 배율100px 자리에 3배면 300화소짜리가 필요하다
  4. 배율별로 주기 srcset 1x 2x 3x브라우저가 자기 배율에 맞는 것만 받는다
  5. 배율과 무관한 것 SVG · 글자그릴 때마다 다시 계산한다. 늘 선명하다
  6. 머리카락 선 1 ÷ 배율 px3배에서 0.33px이면 정확히 화소 하나

반대 방향의 실수도 흔합니다 — 어디서나 선명하라고 모든 그림을 3배짜리로만 주는 것입니다. 그러면 1배 모니터에서도 아홉 배 큰 파일을 받게 되고, 화면에 뿌릴 때 줄이느라 오히려 느려집니다. srcset을 적어 두면 브라우저가 자기 배율과 통신 사정을 보고 알아서 고릅니다 — 골라 주는 일을 브라우저에 넘기는 것이 요점입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 사진·비트맵 아이콘에 srcset 적기
  • 아이콘은 되도록 SVG나 글꼴로
  • 캔버스로 그릴 때 배율만큼 크게 잡고 축소해 쓰기

이럴 때는 안 쓴다

  • 모든 그림을 3배짜리로만 주기 — 1배 기기가 손해를 본다
  • devicePixelRatio로 기기를 짐작하기 — 같은 값이 여럿이다
  • 선 굵기를 배율로 계산하기 — 1px 은 이미 맞는다
  • 글자 크기를 배율로 바꾸기 — 바꿀 필요가 없다

대신 이걸 — 폭에 따른 배치는 브레이크포인트, 그림이 무거우면 포맷(WebP·AVIF)을 바꾸기, 아이콘이면 SVG 로.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 밀도의 계약서

그림은 배율별로 주고, 캔버스는 직접 맞춥니다.

<img src="logo.png"
     srcset="logo@2x.png 2x, logo@3x.png 3x"
     width="120" height="40" alt="이름표">

/* 폭까지 다를 때는 sizes 와 w 서술자로 */
<img srcset="c-400.jpg 400w, c-800.jpg 800w, c-1200.jpg 1200w"
     sizes="(min-width: 900px) 33vw, 100vw" src="c-800.jpg">

// 캔버스는 직접 맞춘다
const dpr = window.devicePixelRatio || 1;
cv.width = w * dpr; cv.height = h * dpr;      // 그리는 화소 수
cv.style.width = w + 'px';                  // 보이는 크기
ctx.scale(dpr, dpr);
키일어나야 하는 일
width·height를 적는다밀도와 별개로 자리를 미리 잡아 글이 덜컥거리지 않게 한다
srcset의 2x와 800w배율만 다르면 x, 폭도 다르면 w + sizes
alt밀도와 무관하지만 같이 빠지기 쉽다. 이름 붙이기
image-rendering: pixelated일부러 도트를 살릴 때만. 사진에 쓰면 더 나빠진다
0.5px 테두리1배 화면에서는 반올림돼 사라지거나 흐려질 수 있다. 질의로 가린다
배율로 기기를 짐작하지 않는다같은 값이 폰에도 노트북에도 있다. 입력 방식은 포인터 질의로 묻는다

9 서버 쪽으로 치면백엔드 감각으로 번역

이미지 변환은 서버에서원본 하나를 올려 두고 필요한 크기로 잘라 내려주는 쪽이 파일을 따로 관리하는 것보다 쌉니다.
캐시가 갈라진다같은 주소가 기기마다 다른 그림을 주면 CDN 캐시가 어긋납니다. 주소를 크기마다 따로 두는 편이 안전합니다.
포맷이 더 큰 몫같은 그림이라도 WebP·AVIF 로 바꾸면 절반 아래로 떨어집니다. 배율보다 먼저 볼 일입니다.
업로드한 사진요즘 폰 사진은 4000px 이 넘습니다. 받자마자 쓸 크기로 줄여 저장해 두지 않으면 목록 화면이 통째로 느려집니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

세 곳 모두 길이와 화소를 갈라 둡니다. 이름만 다릅니다.

웹CSS px · DPR
CSS px
px이 길이이고 devicePixelRatio가 배율입니다. 그림은 srcset으로 갈라 줍니다.
iOSpt · @2x @3x
icon@2x
icon@3x
길이는 pt이고 파일 이름에 @2x·@3x를 붙여 둡니다. 구분선은 화소 하나가 관례입니다.
안드로이드dp · mdpi~xxxhdpi
drawable-xhdpi
drawable-xxhdpi
길이는 dp이고 폴더 이름으로 배율을 가릅니다. 벡터 드로어블을 쓰면 한 벌로 끝납니다.

자주 생기는 사고 — "로고가 흐릿해요"는 거의 늘 이것입니다. 그리고 디자이너의 화면과 개발자의 화면이 둘 다 2배라서 못 보고 지나가는 일이 잦습니다. 시안을 받을 때 2배·3배 파일을 함께 달라고 하거나, 아예 SVG 로 받아 두면 이 왕복이 사라집니다.
