화면 밀도

Device pixel ratio

CSS의 1px은 화소가 아니라 길이 단위입니다. 그래서 배율이 3배인 화면에서는 CSS 1px 길이를 기기 화소 세 개로 그립니다.

배율을 바꾸면 캔버스의 실제 화소 수가 함께 바뀝니다.
1배짜리 그림은 3배 화면에서 세 배로 늘어나 뭉개지지만, 배율만큼 크게 받은 그림과 SVG는 선명하게 그대로 보입니다. 아래 두 줄은 1px 선과 화소 하나짜리 선을 비교한 것으로, 배율이 높을수록 화소 하나짜리 선이 가늘어집니다. 위쪽에는 지금 보는 화면의 실제 배율도 나옵니다.

2 이름같은 것을 부르는 여러 이름

한국어화면 밀도, 픽셀 배율, 고해상도 화면
영어device pixel ratio (DPR), pixel density, Retina / HiDPI
같이 쓰는 말브라우저는 배율을 window.devicePixelRatio 값으로 알려 줍니다. 배율이 높은 화면을 애플은 레티나라고 부르고, 일반적으로는 HiDPI라고 부릅니다. 그림을 배율별로 나눠 줄 때는 srcset에 1x · 2x · 3x를 적고, 화소 하나 굵기로 그은 선은 헤어라인(hairline)이라고 합니다. 안드로이드의 길이 단위 dp와 애플의 pt는 CSS의 px과 같은 역할을 합니다.
자주 잘못 부르는 이름해상도 — '1920×1080'은 화면 전체의 화소 수이고, 밀도는 화소가 얼마나 빽빽하게 들어 있는가를 가리킵니다.
화면 크기 — 브레이크포인트가 기준으로 삼는 폭은 CSS px로 재기 때문에 밀도와 상관이 없습니다.
DPI — 인쇄에서 쓰는 단위이고, 화면에서는 밀도를 배율로 다룹니다.

3 배율에 따라 달라지는 것배율에 따라 바뀌는 것과 바뀌지 않는 것

4 해부도부분마다 붙은 이름

CSS 1px은 화소가 아닌 길이 단위
devicePixelRatio가 3이면 기기 화소 3개가 CSS 1px
그림에는 CSS 크기 × 배율만큼의 화소가 필요함
srcset의 2x·3x로 배율에 맞는 그림을 받음
SVG와 글자는 배율과 상관없음
머리카락 선의 굵기는 1 ÷ 배율 px
  1. CSS px 길이 단위어느 화면에서나 눈에 같은 크기로 보이도록 정한 길이 단위입니다
  2. 배율 devicePixelRatioCSS 1px을 기기 화소 몇 개로 그리는지 나타내는 값입니다
  3. 그림에 필요한 화소 CSS 크기 × 배율폭 100px 자리에 배율 3배라면 폭 300화소짜리 그림이 필요합니다
  4. 배율별로 주기 srcset 1x 2x 3x브라우저가 화면 배율에 맞는 그림 하나만 골라 받습니다
  5. 배율과 무관한 것 SVG · 글자그릴 때마다 배율에 맞춰 다시 계산하기 때문에 늘 선명합니다
  6. 머리카락 선 1 ÷ 배율 px배율 3배 화면에서는 0.33px이 정확히 화소 하나입니다

어디서나 선명하게 보이도록 모든 그림을 3배짜리로만 주는 반대 방향의 실수도 흔합니다. 그러면 1배 모니터에서도 화소 수가 아홉 배인 그림을 받게 되고, 화면에 그릴 때 크기를 줄이는 작업까지 더해져 오히려 느려집니다. srcset에 여러 크기를 적어 두면 브라우저가 화면 배율과 통신 사정을 보고 알맞은 것을 고르므로, 어떤 그림을 받을지는 브라우저에 맡기는 편이 낫습니다.

5 쓸 때 / 안 쓸 때

화면 밀도를 챙겨야 하는 경우

  • 사진이나 비트맵 아이콘을 넣을 때. srcset을 적습니다
  • 아이콘을 넣을 때. 되도록 SVG나 아이콘 글꼴을 씁니다
  • 캔버스로 그릴 때. 캔버스를 배율만큼 크게 잡고 줄여서 보여 줍니다

화면 밀도를 잘못 다루는 경우

  • 모든 그림을 3배짜리로만 줄 때. 1배 기기가 필요 없이 큰 파일을 받습니다
  • devicePixelRatio로 기기를 짐작할 때. 서로 다른 기기가 같은 값을 냅니다
  • 선 굵기를 배율로 계산할 때. 1px 선은 브라우저가 이미 맞춰 그립니다
  • 글자 크기를 배율에 따라 바꿀 때. 글자는 배율과 상관없이 선명하므로 바꿀 필요가 없습니다

함께 살펴볼 것 — 화면 폭에 따라 배치를 바꾸는 일은 브레이크포인트에서 다룹니다. 그림이 무거우면 배율보다 먼저 포맷(WebP·AVIF)을 바꿔 보고, 아이콘은 처음부터 SVG로 만듭니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 지킬 규칙빠뜨리기 쉬운 설정까지 담은 규칙

그림은 srcset으로 배율별 파일을 주고, 캔버스는 배율을 읽어 화소 수를 직접 맞춥니다.

<img src="logo.png"
     srcset="logo@2x.png 2x, logo@3x.png 3x"
     width="120" height="40" alt="이름표">

/* 폭까지 다를 때는 sizes 와 w 서술자로 */
<img srcset="c-400.jpg 400w, c-800.jpg 800w, c-1200.jpg 1200w"
     sizes="(min-width: 900px) 33vw, 100vw" src="c-800.jpg">

// 캔버스는 직접 맞춘다
const dpr = window.devicePixelRatio || 1;
cv.width = w * dpr; cv.height = h * dpr;      // 그리는 화소 수
cv.style.width = w + 'px';                  // 보이는 크기
ctx.scale(dpr, dpr);
지킬 규칙지키는 방법과 까닭
width·height 적기밀도와는 별개로, 그림이 들어갈 자리를 미리 잡아 그림이 늦게 뜰 때 글이 밀려 움직이지 않게 합니다
srcset의 2x와 800w 구분하기배율만 다르면 x를 쓰고, 표시 폭도 달라지면 w와 sizes를 함께 씁니다
alt 함께 적기밀도와는 상관없지만 그림을 넣을 때 함께 빠뜨리기 쉽습니다. 이름 붙이기를 참고합니다
image-rendering: pixelated도트 그림처럼 화소를 일부러 살릴 때만 씁니다. 사진에 쓰면 오히려 거칠어집니다
0.5px 테두리1배 화면에서는 굵기가 반올림되어 사라지거나 흐려질 수 있으므로, 배율을 묻는 미디어 쿼리로 배율이 높은 화면에만 적용합니다
배율로 기기를 짐작하지 않기같은 배율 값이 폰에도 노트북에도 있습니다. 입력 방식이 궁금하면 포인터 질의로 묻습니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

그림 크기 변환은 서버에서 하기원본 하나만 올려 두고 서버가 필요한 크기로 줄여 내려주게 하면, 크기별 파일을 따로 관리하는 것보다 비용이 적게 듭니다.
기기별 그림과 CDN 캐시같은 주소에서 기기마다 다른 그림을 내려주면 CDN 캐시가 엉뚱한 그림을 돌려줄 수 있습니다. 그래서 크기마다 주소를 따로 두는 편이 안전합니다.
배율보다 먼저 살펴볼 그림 포맷같은 그림이라도 WebP나 AVIF로 바꾸면 파일 크기가 절반 아래로 줄어듭니다. 그래서 그림이 무거우면 배율보다 포맷을 먼저 살펴봅니다.
업로드한 사진은 줄여서 저장하기요즘 폰으로 찍은 사진은 폭이 4000px을 넘습니다. 업로드를 받자마자 화면에 쓸 크기로 줄여 저장해 두지 않으면, 사진이 여러 장 뜨는 목록 화면 전체가 느려집니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

세 플랫폼 모두 길이 단위와 기기 화소를 나눠 다루고, 부르는 이름만 다릅니다.

웹CSS px · DPR
CSS px
px이 길이 단위이고 devicePixelRatio가 배율입니다. 그림은 srcset으로 배율별로 나눠 줍니다.
iOSpt · @2x @3x
icon@2x
icon@3x
길이 단위는 pt이고, 배율별 그림은 파일 이름에 @2x·@3x를 붙여 구분합니다. 구분선은 화소 하나 굵기로 긋는 것이 관례입니다.
안드로이드dp · mdpi~xxxhdpi
drawable-xhdpi
drawable-xxhdpi
길이 단위는 dp이고, 배율별 그림은 폴더 이름으로 구분합니다. 벡터 드로어블을 쓰면 그림 한 벌로 모든 배율을 처리할 수 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "로고가 흐릿해요"라는 문의는 거의 늘 배율에 맞는 그림을 주지 않아서 생깁니다. 게다가 디자이너와 개발자의 화면이 둘 다 2배인 경우가 많아서, 만드는 동안에는 문제를 못 보고 지나가기 쉽습니다. 시안을 받을 때 2배·3배 파일을 함께 달라고 하거나 처음부터 SVG로 받아 두면, 나중에 파일을 다시 주고받을 일이 없어집니다.
