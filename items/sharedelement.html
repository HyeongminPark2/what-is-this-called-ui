2 이름부르는 말이 여러 개다

한국어공유 요소 전환, 이어지는 전환, 확대 전환
영어shared element transition, shared axis, hero animation, container transform
같이 쓰는 말안드로이드에서는 셰어드 엘리먼트, Material 3 에서는 컨테이너 트랜스폼이라 부릅니다. 플러터 쪽에서는 히어로 애니메이션입니다. 웹에는 뷰 트랜지션(View Transitions API)이 생겨 view-transition-name으로 같은 것임을 알려 줍니다.
자주 잘못 부름페이지 전환 — 화면이 통째로 바뀌는 것이고, 이쪽은 한 조각이 이어지는 것입니다.
확대 애니메이션 — 그냥 커지는 것과 두 화면을 잇는 것은 다릅니다.
모프 — 모양이 변형되는 연출을 가리키기도 해 자주 섞입니다.

4 이어지는 네 토막같은 것이 자란다

5 해부도부분 이름이 제일 안 알려진 지식

두 화면에 같은 것이 있다 — 그걸 코드가 알아야 한다
출발 자리와 도착 자리를 잰다
그 사이를 이어서 움직인다 — 240~320ms
나머지는 투명도로 바꿔치기
돌아갈 때도 같은 길 — 왔던 자리로
자리를 못 찾으면 그냥 페이드로 떨어뜨린다
  1. 같은 것 이름을 붙인다코드가 알아야 이을 수 있다
  2. 자리 재기 출발과 도착두 자리를 재서 그 사이를 움직인다
  3. 길이 240~320ms짧으면 안 보이고 길면 기다린다 — 지속 시간
  4. 나머지 투명도이어지는 것 말고는 바꿔치기한다
  5. 돌아오기 같은 길왔던 자리로. 안 그러면 더 헷갈린다
  6. 못 찾으면 페이드로떨어뜨릴 길을 반드시 둔다

떨어뜨릴 길이 가장 중요합니다. 목록에서 한참 굴려 내려간 뒤 들어갔다 나오면 출발 자리가 화면 밖일 수 있고, 필터가 바뀌어 그 줄이 아예 사라졌을 수도 있습니다. 그럴 때 억지로 이으면 화면 밖에서 날아오는 이상한 연출이 됩니다. 자리를 못 찾으면 그냥 페이드로 물러나게 해 두면, 되는 때만 예쁘고 안 되는 때도 멀쩡합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 목록 → 상세처럼 같은 것이 양쪽에 있을 때
  • 사진·카드처럼 눈에 띄는 한 조각이 이어질 때
  • 돌아올 때도 같은 길을 둘 수 있을 때

이럴 때는 안 쓴다

  • 이어지는 것이 작고 안 눈에 띌 때 — 값을 못 한다
  • 출발 자리가 화면 밖인데 억지로 잇기
  • 글자처럼 크기가 많이 다른 것을 억지로 모프하기
  • 떨어뜨릴 길 없이 — 안 되는 때가 반드시 온다

대신 이걸 — 그냥 들고 나는 것은 진입과 퇴장, 곡선은 이징, 줄이 차례로면 차례로 들어오기.

8 최소 코드와 규칙이 전환의 계약서

같은 것에 같은 이름을 붙이면 브라우저가 이어 줍니다.

/* 두 화면의 같은 것에 같은 이름을 붙인다 */
.list .thumb[data-id="42"] { view-transition-name: store-42; }
.detail .hero                { view-transition-name: store-42; }

// 화면을 바꾸는 일을 감싸면 그 사이를 이어 준다
if (!document.startViewTransition) { render(); }   // 안 되면 그냥 바꾼다
else document.startViewTransition(() => render());

/* 모션 줄이기에서는 잇지 않는다 */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*) { animation-duration: 1ms; }
}
키일어나야 하는 일
이름은 한 화면에 하나같은 view-transition-name이 둘이면 전환이 통째로 멎는다
안 되는 브라우저startViewTransition이 없으면 그냥 바꾼다. 기능은 그대로여야 한다
초점은 기다리지 않는다연출 중에도 초점은 바로 옮긴다 — 진입과 퇴장
모션 줄이기큰 거리를 지나가는 연출이라 줄이기에서 끈다
읽는 순서연출은 눈에만 있다. DOM 순서는 그대로여야 한다
긴 목록가상 스크롤이면 출발 요소가 아예 없을 수 있다

9 서버 쪽으로 치면백엔드 감각으로 번역

자료가 양쪽에 있어야상세를 새로 받아야 한다면 그 사이에 빈 화면이 생깁니다. 목록이 가진 값으로 먼저 그려 두면 매끄럽습니다.
그림을 미리 받아 둔다큰 그림이 늦게 오면 자라다 멈춘 자리가 비어 보입니다.
주소가 바뀌는 전환뒤로가기로 돌아올 때도 같은 길을 쓰려면 어디서 왔는지를 알아야 합니다 — 시스템 백.

10 플랫폼마다 다른 이름같은 부품, 다른 말

앱에서 먼저 흔해졌고 웹은 최근에 따라왔습니다.

웹View Transitions
view-transition-name으로 같은 것임을 알립니다. 최근 브라우저에서만 됩니다.
iOSmatchedGeometryEffect
SwiftUI 에서 matchedGeometryEffect로 잇습니다. 같은 id를 주면 됩니다.
안드로이드Container transform
Material 3 의 컨테이너 트랜스폼이 규격입니다. 네 가지 전환 가운데 하나로 정리돼 있습니다.

자주 생기는 사고 — 시안에서 가장 멋있어 보이는 연출이지만, 되는 경우와 안 되는 경우를 함께 정해야 합니다 — 목록을 한참 굴려 내려간 뒤, 필터가 바뀐 뒤, 검색으로 바로 들어온 뒤. 받을 때 "자리를 못 찾으면 어떻게 합니까"를 한 번 물어보면 떨어뜨릴 길이 함께 정해집니다.
