공유 요소 전환

Shared element transition

공유 요소 전환은 두 화면에 있는 같은 요소를 이어서 움직이는 전환입니다. 두 화면이 어떤 관계인지 설명하는 글 없이 움직임으로 보여 줍니다.

목록의 작은 그림이 상세 화면의 큰 그림으로 이어서 커집니다.
이어서 움직이기를 끄면 목록이 사라진 뒤 상세 화면이 따로 나타나는데, 같은 자료인데도 두 화면의 관계가 보이지 않아서 상세 화면이 어디서 왔는지 잠깐 헷갈립니다.

2 이름같은 것을 부르는 여러 이름

한국어공유 요소 전환, 이어지는 전환, 확대 전환
영어shared element transition, shared axis, hero animation, container transform
같이 쓰는 말안드로이드에서는 셰어드 엘리먼트, Material 3에서는 컨테이너 트랜스폼이라고 부르고, 플러터에서는 히어로 애니메이션이라고 부릅니다. 웹에는 뷰 트랜지션(View Transitions API)이 생겨서 view-transition-name으로 두 요소가 같은 것임을 브라우저에 알려 줍니다.
자주 잘못 부르는 이름페이지 전환 — 페이지 전환은 화면이 통째로 바뀌는 것이고, 공유 요소 전환은 그 가운데 한 요소가 두 화면을 이어 움직이는 것입니다.
확대 애니메이션 — 요소가 그냥 커지는 것과 두 화면을 이어 주는 것은 다릅니다.
모프 — 모프는 모양이 변형되는 연출을 가리키기도 해서 공유 요소 전환과 자주 섞어 부릅니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

움직임은 화면에서 무엇이 바뀌었는지 사용자에게 알려 주는 역할을 합니다. 아래 네 가지를 따져 보면 움직임을 다루는 항목들을 서로 구별할 수 있습니다.

이 항목이 정하는 것사용자가 움직임에서 읽어 내는 것지나치게 쓰면 생기는 일모션 줄이기를 켰을 때
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보임그대로 둠
지속 시간얼마나 걸리는지거리와 크기사용자를 기다리게 함짧게 줄이거나 0으로
진입과 퇴장들고 나는 방식어디서 왔는지닫힐 때까지 붙잡혀 기다림퇴장 시간을 거의 0으로
무엇을 움직이나어떤 속성을 바꾸는지움직임이 매끄러운지화면이 버벅임해당 없음
스프링지나쳤다 돌아오는 정도손으로 민 듯한 느낌어지러움튕김을 0으로
차례로 들어오기줄과 줄 사이의 지연순서와 묶음마지막 줄이 늦게 나타남한꺼번에 띄움
제스처손가락을 따라가는 규칙내가 조작하고 있다는 느낌실수로 닫히기 쉬움그대로 둠
모션 줄이기무엇을 끄는지배려받고 있다는 느낌다 꺼 버려 무엇이 바뀌었는지 알 수 없음이 항목이 그 기준
공유 요소 전환두 화면에 함께 있는 같은 요소어디서 왔는지자리가 어긋나면 오히려 헷갈림자리 이동 없이 전환
스크롤 연동스크롤에 맞춰 움직이는 방식지금 어디쯤 읽고 있는지멀미를 일으킴연출만 끔

공유 요소 전환을 한 줄로 정리하면 — 공유 요소 전환은 두 화면의 요소가 같은 것이라는 사실을 코드가 알아야 만들 수 있습니다. 그만한 구현 비용을 들일 만한 자리인지 먼저 따져 보세요.

4 이어지는 전환의 단계같은 그림이 목록에서 상세 화면으로 커지는 과정

5 해부도부분마다 붙은 이름

두 화면의 같은 요소를 코드가 알아야 함
출발 자리와 도착 자리를 잼
그 사이를 240~320ms 동안 이어서 움직임
나머지는 투명도로 바꿔치기
돌아갈 때도 같은 길로 왔던 자리에
자리를 못 찾으면 그냥 페이드로 바꿈
  1. 같은 요소 이름 붙이기두 요소가 같다는 것을 코드가 알아야 이을 수 있습니다
  2. 자리 재기 출발과 도착출발 자리와 도착 자리를 재서 그 사이를 움직입니다
  3. 길이 240~320ms짧으면 움직임이 보이지 않고 길면 기다리게 됩니다. 자세한 내용은 지속 시간에 있습니다
  4. 나머지 투명도이어지는 요소를 뺀 나머지는 투명도로 바꿔치기합니다
  5. 돌아오기 같은 길돌아갈 때도 왔던 자리로 움직입니다. 다른 자리로 가면 더 헷갈립니다
  6. 자리를 못 찾을 때 페이드로이을 수 없을 때 대신할 방법(폴백)을 반드시 둡니다

공유 요소 전환에서 특히 중요한 것은 이을 수 없을 때 대신할 방법입니다. 목록을 한참 스크롤해 내려간 뒤 상세에 들어갔다 나오면 출발 자리가 화면 밖에 있을 수 있고, 필터가 바뀌어서 그 줄이 아예 사라졌을 수도 있습니다. 이럴 때 억지로 이으면 요소가 화면 밖에서 날아 들어오는 이상한 연출이 됩니다. 그래서 자리를 못 찾으면 그냥 페이드로 바꿔 보여 주도록 해 두면, 이을 수 있을 때는 이어서 움직이고 이을 수 없을 때도 화면이 어색해지지 않습니다.

6 쓸 때 / 안 쓸 때

공유 요소 전환을 쓰는 경우

  • 목록과 상세 화면처럼 같은 요소가 양쪽 화면에 있을 때
  • 사진이나 카드처럼 눈에 띄는 요소 하나가 이어질 때
  • 돌아올 때도 같은 경로로 움직이게 할 수 있을 때

공유 요소 전환을 쓰지 않는 경우

  • 이어지는 요소가 작아서 눈에 잘 띄지 않을 때. 들인 비용만큼 효과가 없습니다
  • 출발 자리가 화면 밖에 있는데 억지로 이을 때
  • 글자처럼 두 화면에서 크기가 많이 다른 것을 억지로 모프할 때
  • 이을 수 없을 때 대신할 방법을 두지 않을 때. 이을 수 없는 경우는 반드시 생깁니다

공유 요소 전환 대신 쓰거나 함께 볼 것 — 요소가 다른 화면과 이어지지 않고 그냥 들어오고 나가기만 하면 진입과 퇴장으로 충분합니다. 곡선은 이징에서, 여러 줄이 차례로 들어오게 하는 방법은 차례로 들어오기에서 다룹니다.

8 최소 코드와 규칙구현할 때 지킬 최소 규칙

두 화면의 같은 요소에 같은 이름을 붙이면 브라우저가 둘 사이를 이어 줍니다.

/* 두 화면의 같은 것에 같은 이름을 붙인다 */
.list .thumb[data-id="42"] { view-transition-name: store-42; }
.detail .hero                { view-transition-name: store-42; }

// 화면을 바꾸는 일을 감싸면 그 사이를 이어 준다
if (!document.startViewTransition) { render(); }   // 안 되면 그냥 바꾼다
else document.startViewTransition(() => render());

/* 모션 줄이기에서는 잇지 않는다 */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*) { animation-duration: 1ms; }
}
알아 둘 규칙자세한 내용
한 화면에 같은 이름은 하나만 쓰기같은 view-transition-name이 한 화면에 둘 있으면 전환 전체가 동작하지 않습니다
지원하지 않는 브라우저에서startViewTransition이 없으면 연출 없이 그냥 화면을 바꿉니다. 기능은 그대로 동작해야 합니다
초점은 연출을 기다리지 않고 옮기기연출 중에도 초점은 바로 옮깁니다. 자세한 내용은 진입과 퇴장에 있습니다
모션 줄이기를 켰을 때큰 거리를 지나가는 연출이라서 모션 줄이기에서는 끕니다
읽는 순서 그대로 두기연출은 화면에서만 일어나는 일이므로 DOM 순서는 그대로 둬야 합니다
긴 목록에서 출발 요소가 없을 때가상 스크롤을 쓰면 출발 요소가 DOM에 아예 없을 수 있습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

목록이 가진 값으로 상세 화면 먼저 그리기상세 자료를 새로 받아야 한다면 받는 동안 빈 화면이 생깁니다. 목록이 이미 가진 값으로 먼저 그려 두면 전환이 매끄럽습니다.
큰 그림을 미리 받아 두기큰 그림이 늦게 오면 커지는 연출이 끝난 자리가 비어 보입니다. 그래서 큰 그림은 미리 받아 둡니다.
주소가 바뀌는 전환뒤로가기로 돌아올 때도 같은 경로로 움직이려면 상세 화면이 어느 줄에서 왔는지 알아야 합니다. 자세한 내용은 시스템 백에 있습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

공유 요소 전환은 앱에서 먼저 흔해졌고, 웹에서는 최근에야 쓸 수 있게 되었습니다.

웹View Transitions
view-transition-name으로 두 요소가 같은 것임을 알립니다. 최근 브라우저에서만 동작합니다.
iOSmatchedGeometryEffect
SwiftUI에서는 matchedGeometryEffect로 두 요소를 잇고, 두 요소에 같은 id를 주면 됩니다.
안드로이드Container transform
Material 3에는 컨테이너 트랜스폼이라는 규격이 있고, 네 가지 전환 패턴 가운데 하나로 정리되어 있습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 공유 요소 전환은 시안에서 가장 멋있어 보이는 연출이지만, 이을 수 있는 경우와 없는 경우를 함께 정해야 합니다. 목록을 한참 스크롤해 내려간 뒤, 필터가 바뀐 뒤, 검색으로 상세 화면에 바로 들어온 뒤가 이을 수 없는 대표적인 경우입니다. 시안을 받을 때 "출발 자리를 못 찾으면 어떻게 하나요?"라고 한 번 물어보면 대신할 방법도 함께 정해집니다.
