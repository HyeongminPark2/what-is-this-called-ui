콤보박스

Combobox · Autocomplete

타이핑으로 선택지를 좁혀 고르는 칸. 입력칸과 목록을 붙여 놓은 것이라, 선택지가 수십·수백 개일 때 유일하게 쓸 만한 방법입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

↓↑로 옮기고 Enter로 고르고 Esc로 닫습니다 — 손을 키보드에서 떼지 않아도 됩니다.
위의 체크를 켜면 목록에 없는 값도 받습니다. 끄면 목록 안에서만 고를 수 있습니다. 이 하나가 '검색되는 셀렉트'와 '자동완성이 붙은 입력칸'을 가릅니다.

2 이름부르는 말이 여러 개다

한국어콤보박스, 자동완성, 검색 선택
영어combobox, autocomplete, typeahead
같이 쓰는 말입력에 맞춰 걸러 주는 동작을 타입어헤드, 키보드로 짚고 있는 항목을 활성 항목(active descendant), 맞은 글자를 굵게 하는 것을 하이라이트라 합니다.
자주 잘못 부름셀렉트 — 타이핑으로 걸러지면 콤보박스입니다.
검색창 — 검색창은 결과 화면으로 넘어가고, 콤보박스는 값 하나를 그 자리에서 정합니다.
드롭다운 — 너무 뭉뚱그린 말이라 셀렉트·메뉴·콤보박스가 전부 섞입니다.

3 가르는 기준형제들과 비교하는 네 축

조작 부품은 모두 '값을 받는다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

고르는 개수선택지가 보이나바로 적용되나타이핑
텍스트 필드자유 입력해당 없음저장 눌러야된다
셀렉트하나펼쳐야 보인다저장 눌러야안 된다
콤보박스하나펼치고 걸러진다저장 눌러야된다
체크박스여럿다 보인다저장 눌러야안 된다
라디오 그룹하나다 보인다저장 눌러야안 된다
스위치켬 · 끔해당 없음바로안 된다
세그먼티드 컨트롤하나다 보인다보통 바로안 된다
슬라이더범위에서 하나범위가 보인다보통 바로안 된다

한 줄로 — 콤보박스는 타이핑으로 좁힐 수 있는 셀렉트입니다. 목록에 없는 값을 받을지 말지는 따로 정해야 하고, 그게 성격을 완전히 바꿉니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

블루보틀
블루보틀 성수 5호 M1004
229개 중 2개
  1. 입력칸 combobox inputrole="combobox". 열림 여부를 aria-expanded로 알린다
  2. 입력한 글자 query이게 걸러내는 기준이다. 지우면 다시 전체가 된다
  3. 목록 listbox입력칸 바로 아래. 화면 밖으로 나가면 위로 뒤집는다
  4. 활성 항목 active option키보드가 짚고 있는 것. aria-activedescendant로 알린다 — 포커스는 입력칸에 그대로 둔다
  5. 보조 정보 secondary text같은 이름이 여럿일 때 가르는 열쇠. 코드·지역·날짜
  6. 결과 수 result count몇 개로 좁혀졌는지. 라이브 리전으로 읽히게 하면 더 좋다

그림에 없는 가장 중요한 결정이 목록에 없는 값을 받을 것인가입니다. 받으면 자유 입력에 자동완성이 붙은 것이고, 안 받으면 검색되는 셀렉트입니다 — 서버가 받는 값의 모양부터 달라집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 선택지가 수십 개 넘게 있을 때 — 가맹점, 도시, 사용자
  • 이름을 아는 상태에서 고를 때 — 타이핑이 가장 빠릅니다
  • 목록이 서버에 있어 한 번에 다 못 받을 때

이럴 때는 안 쓴다

  • 선택지가 열 개 안팎 → 셀렉트가 더 단순합니다
  • 이름을 모르고 둘러봐야 할 때 → 걸러낼 말을 모르면 쓸 수 없습니다
  • 결과 없음을 막다른 길로 두기 — 그대로 쓰기나 다시 찾을 길을 줍니다
  • 포커스를 목록으로 옮기기 — 그러면 계속 타이핑할 수 없습니다

대신 이걸 — 열 개 안팎이면 셀렉트, 자유롭게 적으면 텍스트 필드, 여럿 고르면 체크박스나 태그 입력.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

브라우저가 주는 부품이 없어서 직접 만들어야 합니다. 그래서 키보드와 스크린 리더 처리를 빠뜨리기 쉽습니다.

<input role="combobox" aria-expanded="false"
       aria-controls="list" aria-autocomplete="list"
       autocomplete="off">
<ul id="list" role="listbox" hidden>
  <li role="option" id="o0" aria-selected="true">…</li>
</ul>

// 포커스는 입력칸에 두고, 짚고 있는 항목만 가리킨다
input.setAttribute('aria-activedescendant', 'o0');

// 서버에서 찾을 때는 한 글자마다 부르지 않는다
clearTimeout(t); t = setTimeout(search, 250);
키일어나야 하는 일
↓↑항목을 옮긴다. 닫혀 있으면 연다. 포커스는 입력칸에 그대로
Enter짚고 있는 것을 고른다. 없는 값 허용 모드면 적은 글자를 그대로 쓴다
Esc고르지 않고 닫는다. 한 번 더 누르면 적은 글자도 지운다
HomeEnd글자의 처음·끝으로. 목록이 아니라 입력칸이 받는다
스크린 리더aria-activedescendant로 짚은 항목을 읽히고, 결과 수를 라이브 리전으로 알린다

9 서버 쪽으로 치면백엔드 감각으로 번역

걸러내기를 어디서 하나목록이 작으면 화면에서, 크면 서버에서 합니다. 서버면 디바운스(250ms쯤)로 한 글자마다 부르지 않습니다.
응답 순서 뒤섞임'블'·'블루'·'블루보'의 응답이 거꾸로 올 수 있습니다. 마지막 질의의 결과만 반영합니다 — 안 그러면 엉뚱한 목록이 남습니다.
값과 라벨고른 뒤 보내야 하는 건 보이는 이름이 아니라 코드입니다. 이름만 보내면 동명이인·동명 가맹점에서 바로 깨집니다.
없는 값 허용 = 다른 계약받으면 서버가 새 값을 만들 수 있어야 하고, 안 받으면 목록에 있는지 다시 검증해야 합니다. 화면 설정 하나가 API 모양을 바꿉니다.
