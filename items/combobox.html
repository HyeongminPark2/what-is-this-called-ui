콤보박스

Combobox · Autocomplete

콤보박스는 글자를 입력해 선택지를 좁힌 뒤 고르는 칸입니다. 입력칸과 목록을 붙여 놓은 부품이라서, 선택지가 수십·수백 개일 때는 사실상 콤보박스 말고는 쓸 만한 방법이 없습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

↓↑로 항목을 옮기고 Enter로 고르고 Esc로 목록을 닫을 수 있어서, 키보드에서 손을 떼지 않고도 끝까지 고를 수 있습니다.
위의 체크를 켜면 목록에 없는 값도 받고, 끄면 목록 안에서만 고를 수 있습니다. 이 설정 하나에 따라 콤보박스는 '검색되는 셀렉트'가 되기도 하고 '자동완성이 붙은 입력칸'이 되기도 합니다.

2 이름같은 것을 부르는 여러 이름

한국어콤보박스, 자동완성, 검색 선택
영어combobox, autocomplete, typeahead
같이 쓰는 말입력한 글자에 맞춰 선택지를 걸러 주는 동작은 타입어헤드, 키보드로 짚고 있는 항목은 활성 항목(active descendant), 입력한 글자와 맞는 부분을 굵게 표시하는 것은 하이라이트라고 부릅니다.
자주 잘못 부르는 이름셀렉트 — 글자를 입력해 선택지를 걸러 낼 수 있으면 셀렉트가 아니라 콤보박스입니다.
검색창 — 검색창은 검색 결과 화면으로 넘어가지만, 콤보박스는 그 자리에서 값 하나를 정합니다.
드롭다운 — 아래로 펼쳐지는 것을 두루 가리키는 말이라서, 이렇게 부르면 셀렉트와 메뉴, 콤보박스를 구별할 수 없습니다.

6 쓸 때 / 안 쓸 때

콤보박스를 쓰는 경우

  • 가맹점, 도시, 사용자처럼 선택지가 수십 개 넘게 있을 때
  • 찾는 항목의 이름을 이미 알고 있을 때. 이름을 입력하는 쪽이 목록을 훑는 것보다 빠릅니다
  • 목록이 서버에 있어 한 번에 다 못 받을 때

콤보박스를 쓰지 않는 경우

  • 선택지가 열 개 안팎일 때. 셀렉트가 더 단순합니다
  • 이름을 모르고 둘러보며 골라야 할 때. 무엇을 입력해 걸러야 할지 모르면 쓸 수 없습니다
  • 결과가 없을 때 '없음'만 띄우고 끝낼 때. 입력한 값을 그대로 쓰거나 다시 찾을 방법을 줍니다
  • 포커스를 목록으로 옮길 때. 포커스가 입력칸을 떠나면 이어서 입력할 수 없습니다

콤보박스 대신 다른 것을 써야 하는 경우 — 열 개 안팎이면 셀렉트, 자유롭게 적으면 텍스트 필드, 여럿 고르면 체크박스나 태그 입력.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

콤보박스는 브라우저가 제공하는 부품이 없어서 직접 만들어야 합니다. 그래서 키보드 조작과 스크린 리더 처리를 빠뜨리기 쉽습니다.

<input role="combobox" aria-expanded="false"
       aria-controls="list" aria-autocomplete="list"
       autocomplete="off">
<ul id="list" role="listbox" hidden>
  <li role="option" id="o0" aria-selected="true">…</li>
</ul>

// 포커스는 입력칸에 두고, 짚고 있는 항목만 가리킨다
input.setAttribute('aria-activedescendant', 'o0');

// 서버에서 찾을 때는 한 글자마다 부르지 않는다
clearTimeout(t); t = setTimeout(search, 250);
키와 동작그때 일어나야 하는 일
↓↑항목을 옮기고, 목록이 닫혀 있으면 엽니다. 이때도 포커스는 입력칸에 그대로 둡니다
Enter짚고 있는 항목을 고릅니다. 목록에 없는 값을 받는 설정이면 입력한 글자를 그대로 값으로 씁니다
Esc고르지 않고 목록을 닫습니다. 한 번 더 누르면 입력한 글자도 지웁니다
HomeEnd입력한 글자의 처음이나 끝으로 커서를 옮깁니다. 이 키는 목록이 아니라 입력칸이 받습니다
스크린 리더aria-activedescendant로 짚은 항목을 읽어 주고, 결과 수는 라이브 리전으로 알립니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

걸러내기를 어디서 하나목록이 작으면 화면에서 거르고, 크면 서버에서 거릅니다. 서버에서 거를 때는 디바운스를 250ms쯤 걸어 글자 하나 칠 때마다 요청을 보내지 않게 합니다.
응답 순서 뒤섞임'블', '블루', '블루보'를 차례로 보냈어도 응답은 거꾸로 올 수 있습니다. 그래서 마지막으로 보낸 질의의 결과만 반영해야 하고, 그렇지 않으면 지금 입력한 글자와 맞지 않는 목록이 남습니다.
값과 라벨고른 뒤 서버에 보내야 하는 값은 화면에 보이는 이름이 아니라 코드입니다. 이름만 보내면 이름이 같은 사람이나 가맹점이 있을 때 어느 쪽인지 구별할 수 없습니다.
없는 값 허용 = 다른 계약목록에 없는 값을 받으면 서버가 새 값을 만들 수 있어야 하고, 받지 않으면 서버가 그 값이 목록에 있는지 다시 검증해야 합니다. 화면의 설정 하나에 따라 API의 형태가 달라집니다.
