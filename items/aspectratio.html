종횡비

Aspect ratio

폭이 정해지면 높이가 따라오게 하는 값. 비를 지키는 것보다 자리를 미리 잡는 쓸모가 큽니다.

1 실물 — 직접 만져 보기

폭이 서로 다른 세 상자가 같은 비를 지킵니다 — 아래에 실제로 잰 값이 나옵니다.
비를 안 정하고 높이만 주기를 켜면 폭마다 비가 달라집니다. 반응형에서 바로 드러나는 차이입니다.

2 이름부르는 말이 여러 개다

한국어종횡비, 가로세로비, 비율
영어aspect ratio, intrinsic ratio
같이 쓰는 말CSS 속성 이름이 그대로 aspect-ratio입니다. 이 속성이 없던 시절 padding-top: 56.25%로 흉내 내던 것을 패딩 트릭이라 불렀습니다. 안을 어떻게 채울지는 object-fit이고, cover는 잘라 채우고 contain은 다 보이게 넣습니다. 그림이 늦게 와 글이 밀리는 것을 레이아웃 시프트(CLS)라 합니다.
자주 잘못 부름해상도 — 화소 수와 비는 다릅니다. 1920×1080 과 1280×720 은 같은 16:9 입니다.
크롭 — 잘라내는 것은 object-fit의 일입니다. 비는 상자의 모양입니다.
스케일 — 키우는 것과 비를 유지하는 것은 다릅니다.

4 비별로같은 폭, 다른 높이

5 해부도부분 이름이 제일 안 알려진 지식

aspect-ratio: 16 / 9 — 폭이 정해지면 높이가 따라온다
폭이 바뀌어도 비가 유지된다
그림이 오기 전에 자리를 잡는다 — 글이 안 덜컥거린다
object-fit: cover — 잘라서 채운다
img 에는 width · height 속성도 함께 적는다
높이가 따로 정해지면 비가 무시된다
  1. 비 16 / 9폭이 정해지면 높이가 따라온다
  2. 반응형 비가 유지된다칸 폭이 바뀌어도 모양이 같다
  3. 자리 잡기 오기 전에그림이 늦게 와도 글이 안 밀린다
  4. 채우기 object-fit: cover잘라서 채운다. contain 은 다 보이게
  5. <img> width · height 속성속성만 적어도 비가 생긴다
  6. 안 먹을 때 높이가 따로 박힘height가 있으면 비가 진다

그림에 width·height 속성을 적는 것만으로 브라우저가 비를 계산해 자리를 미리 잡아 줍니다 — CSS 로 width: 100%를 주어도 그 비는 그대로 쓰입니다. 오래된 조언('HTML 에 크기를 적지 마라')이 지금은 정반대가 된 자리라, 옛 습관대로 속성을 지워 두면 그림이 뜰 때마다 글이 밀립니다. 비가 저마다 다른 사진이라면 서버가 가로·세로를 함께 내려주는 것이 이 문제를 가장 싸게 해결합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 그림·영상 자리에 거의 늘
  • 목록 썸네일 — 모양이 같아야 줄이 선다
  • <img>에는 width·height 속성도 함께

이럴 때는 안 쓴다

  • 비와 height를 같이 주기 — 비가 진다
  • 글이 든 상자에 비를 박기 — 글이 넘친다
  • 패딩 트릭을 새로 쓰기 — 이제 속성이 있다
  • object-fit 없이 그림 넣기 — 찌그러진다

대신 이걸 — 크기 자체는 크기 정하기, 넘치는 처리는 넘침, 오기 전 자리는 스켈레톤.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙이 비의 계약서

상자에는 aspect-ratio, 그림에는 크기 속성을 적습니다.

/* 상자 — 폭이 정해지면 높이가 따라온다 */
.thumb {
  aspect-ratio: 16 / 9;
  width: 100%;
  overflow: hidden;
  border-radius: var(--radius-1);
}
.thumb img { width: 100%; height: 100%; object-fit: cover; }

<!-- 그림 자체 — 속성만 적어도 비가 생긴다 -->
<img src="store.jpg" width="800" height="450"
     style="width:100%;height:auto" alt="모란상회 매장">
키일어나야 하는 일
width·height 속성지우지 않는다. 브라우저가 비를 계산해 자리를 잡는다
height: autoCSS 로 폭만 주면 속성의 비가 쓰인다
object-fit: cover없으면 찌그러진다
alt자리만 잡고 뜻은 따로다 — 대체 텍스트
글이 든 상자비를 박으면 글이 넘친다. 글에는 min-height를 쓴다
SVGviewBox가 이미 비를 가진다. preserveAspectRatio를 none으로 두면 찌그러진다

9 서버 쪽으로 치면백엔드 감각으로 번역

가로·세로를 함께 보낸다{"w":800,"h":450}가 있으면 화면이 자리를 미리 잡습니다.
사진마다 비가 다르다사용자가 올린 사진은 제각각입니다. 한 비로 잘라 저장하거나 비를 함께 보냅니다.
썸네일을 만들어 둔다원본을 줄여 쓰면 느립니다 — 화면 밀도·에셋 내보내기.

10 플랫폼마다 다른 이름같은 부품, 다른 말

비로 자리를 잡는다는 생각은 같습니다.

웹aspect-ratio
16/9
2021년부터 속성 하나로 됩니다. 전에는 패딩 트릭을 썼습니다.
iOSaspectRatio
.aspectRatio(16/9, contentMode:). fill이 cover 자리입니다.
안드로이드aspectRatio

자주 생기는 사고 — "그림이 뜨면 글이 밀려요"는 비를 안 적어서 생깁니다. 고치는 값이 아주 싸고(<img> 속성 두 개) 효과는 바로 보여서, 목록 화면을 만들 때 가장 먼저 챙기면 좋은 한 줄입니다.
