차례로 들어오기

Stagger

여러 줄을 조금씩 늦게 들여보내는 것. 멋있어 보이지만 마지막 줄까지 세어 봐야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

간격과 줄 수를 바꿔 보세요. 아래에 마지막 줄이 다 보이기까지 걸리는 시간이 계산됩니다.
간격 160ms × 스무 줄이면 3초가 넘습니다 — 그 사이 사용자는 이미 스크롤하고 있습니다. 한 줄은 200ms 인데 전체는 3초인 상황이 어떻게 생기는지 숫자로 보입니다.

2 이름부르는 말이 여러 개다

한국어차례로 들어오기, 시차 등장, 순차 등장
영어stagger, staggered animation, cascade
같이 쓰는 말줄마다 시작을 늦추는 값이 딜레이(delay)이고, 그 간격을 스태거라 부릅니다. 애니메이션 도구에서는 stagger·offset·cascade로 나옵니다. CSS 만으로 하려면 --i 같은 사용자 변수에 번호를 넣어 곱합니다.
자주 잘못 부름지속 시간 — 길이는 한 줄이 걸리는 시간, 스태거는 줄 사이의 틈입니다.
스크롤 등장 — 화면에 들어올 때 나타나는 것은 관찰(IntersectionObserver)이고 스태거와는 다릅니다.
타이핑 효과 — 글자가 한 자씩 찍히는 것도 시차지만 읽기를 막는 쪽이라 성격이 다릅니다.

움직임은 장식이 아니라 말입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다
지속 시간얼마나 걸리나거리와 크기기다리게 된다짧게 하거나 0
진입과 퇴장들고 나는 방식어디서 왔나닫는 데 붙잡힌다퇴장은 거의 0

스프링지나쳤다 돌아오는 정도손으로 민 느낌어지럽다튕김을 0으로

한 줄로 — 간격은 20~50ms, 차례로 넣는 줄은 앞 대여섯 줄까지. 나머지는 한꺼번에 띄웁니다.

4 간격과 줄 수마지막 줄까지 세어 본다

5 해부도부분 이름이 제일 안 알려진 지식

모란상회
한빛아웃도어
새벽상사
대림유통
transition-delay: 번호 × 40ms
한 줄의 길이는 그대로 200ms
위에서 아래로 — 읽는 방향과 같게
마지막 줄 = (줄 수 − 1) × 간격 + 길이
앞 여섯 줄만 차례로, 나머지는 한꺼번에
  1. 줄들 같은 연출길이와 곡선은 모두 같다. 다른 것은 시작 시각뿐
  2. 간격 delay = i × 40ms번호에 곱한다. 이게 스태거의 전부다
  3. 한 줄 길이 200ms간격과 따로 정한다. 둘을 섞으면 셈이 안 맞는다
  4. 방향 위 → 아래읽는 방향과 같게. 거꾸로면 어색하다
  5. 마지막 줄 (n−1)×간격 + 길이이 숫자가 사용자가 기다리는 시간이다
  6. 자르기 앞 여섯 줄만나머지는 한꺼번에. 안 그러면 긴 목록이 지옥이 된다

셈법이 전부입니다 — (줄 수 − 1) × 간격 + 한 줄 길이. 한 줄이 200ms 라도 간격 160ms 에 스무 줄이면 3,240ms입니다. 디자인 시안은 보통 네댓 줄로 만들기 때문에 이 숫자가 안 드러나고, 실제 데이터가 들어오고 나서야 문제가 보입니다. 시안을 받을 때 '줄이 스무 개면?'을 한 번 물어보는 것으로 대부분 막힙니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 처음 한 번 그려지는 목록 — 빈 화면에서 내용이 들어올 때
  • 줄이 대여섯일 때 — 카드 묶음, 메뉴 항목
  • 묶음끼리 순서가 있다고 말하고 싶을 때

이럴 때는 안 쓴다

  • 긴 목록 전체에 — 마지막 줄이 몇 초 뒤가 된다
  • 줄이 바뀔 때마다 — 필터를 누를 때마다 춤추면 못 쓴다
  • 스크롤할 때마다 다시 — 두 번째부터는 방해다
  • 간격을 100ms 넘게 — 거의 늘 과하다

대신 이걸 — 한 줄의 길이는 지속 시간, 들고 나는 짝은 진입과 퇴장, 아직 데이터가 없으면 스켈레톤.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 시차의 계약서

번호를 CSS 변수로 넘기고 곱합니다. 앞 몇 줄까지만 늦춥니다.

<li style="--i:0">…</li>
<li style="--i:1">…</li>

li {
  opacity: 0; transform: translateY(8px);
  transition: opacity 200ms var(--ease-out), transform 200ms var(--ease-out);
  transition-delay: calc(min(var(--i), 5) * 40ms);   /* 앞 6줄까지만 */
}
li.in { opacity: 1; transform: none; }

@media (prefers-reduced-motion: reduce) {
  li { transition-delay: 0s; transform: none; }
}
키일어나야 하는 일
min()으로 자른다min(var(--i), 5) — 일곱 번째부터는 더 안 늦어진다
읽는 순서는 안 바뀐다시각적으로 늦게 나타나도 DOM 순서는 그대로다. 스크린 리더는 기다리지 않는다
transition-delay vs animation-delay상태를 오가면 transition, 한 번 재생이면 animation
초점을 뺏지 않는다아직 투명한 줄에 초점이 가면 안 보이는 곳에 커서가 있는 셈이 된다
prefers-reduced-motion간격을 0 으로. 시차는 줄이기에서 가장 먼저 끄는 것 중 하나다
다시 그릴 때 끈다필터를 누를 때마다 춤추지 않게 첫 그리기에만 클래스를 붙인다

9 서버 쪽으로 치면백엔드 감각으로 번역

데이터가 늦게 오면 두 번 기다린다응답 600ms + 시차 1,200ms = 1.8초입니다. 사용자는 둘을 구분하지 못합니다.
쪽을 더 받을 때무한 스크롤로 다음 묶음이 올 때마다 시차를 다시 주면 스크롤할 때마다 춤춥니다. 새로 온 줄만 짧게.
줄 수가 들쭉날쭉서버가 한 번에 100건을 주면 시차가 10초가 됩니다. 자르는 상한이 화면 쪽에 반드시 있어야 합니다.
