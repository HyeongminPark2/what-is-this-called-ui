탭

Tabs

같은 대상의 다른 면을 번갈아 보여 주는 줄. 화면을 떠나지 않고 내용 묶음만 바뀝니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

Tab으로 탭 줄에 들어온 뒤 ←→로 옮기고, 한 번 더 Tab을 누르면 내용으로 넘어갑니다 — 탭 다섯 개를 Tab 다섯 번으로 지나지 않습니다(로빙 탭인덱스).
여기서는 전부 '모란상회' 이야기이고 위의 이름이 안 바뀝니다. 이름까지 바뀐다면 그건 화면 이동입니다.

2 이름부르는 말이 여러 개다

한국어탭, 탭 메뉴, 탭 바
영어tabs, tab list
같이 쓰는 말탭 줄 전체가 탭 리스트, 칸 하나가 탭, 내용이 탭 패널입니다. 넘치면 가로로 미는 것을 스크롤 가능 탭이라 합니다.
자주 잘못 부름세그먼티드 컨트롤 — 세그먼티드는 값을 고르고 탭은 내용 묶음을 바꿉니다. 가장 잦은 혼동입니다.
바텀 탭바 — 이름은 닮았지만 탭바는 앱 전체를 오갑니다. 이 탭은 한 화면 안입니다.
아코디언 — 아코디언은 여러 개를 동시에 펼칠 수 있습니다.

3 가르는 기준형제들과 비교하는 네 축

겹쳐 뜨는 부품들은 모양으로는 구별이 안 됩니다. 이 네 가지만 물어보면 갈립니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음

한 줄로 — 탭은 한 화면 안의 전환입니다. 누른 뒤에도 제목·주소·빵부스러기가 그대로면 탭이고, 바뀌면 화면 이동입니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

개요 거래 문의 3
고른 탭의 내용이 여기 나옵니다 — 위의 가맹점 이름은 안 바뀝니다
  1. 탭 리스트 tablist줄 전체가 하나의 부품이다. role="tablist"
  2. 고른 탭 selected tab밑줄과 색. 늘 하나는 골라져 있다 — 아무것도 안 고른 상태가 없다
  3. 안 고른 탭 tab읽히되 눌러도 된다는 느낌이 있어야 한다
  4. 배지 badge처리할 것이 몇 건인지. 없으면 안 둔다
  5. 탭 패널 tabpanel고른 탭의 내용. 이것만 바뀐다

탭은 다섯 개쯤이 한계입니다. 그 이상이면 가로로 밀어야 하고, 밀어야 하는 탭은 끝에 있는 것이 거의 안 눌립니다. 여섯 개가 넘으면 사이드바나 묶음을 다시 생각할 때입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 같은 대상의 여러 면을 번갈아 볼 때 — 가맹점의 개요·거래·정산
  • 내용이 서로 독립이고 동시에 볼 필요가 없을 때
  • 묶음이 2~5개일 때

이럴 때는 안 쓴다

  • 내용을 나란히 비교해야 할 때 — 탭은 한 번에 하나만 보입니다
  • 같은 목록을 거를 때 → 세그먼티드 컨트롤
  • 아예 다른 화면으로 갈 때 → 사이드바나 탭바
  • 탭 안에 또 탭 — 어디 있는지 금세 알 수 없게 됩니다

대신 이걸 — 같은 목록을 거르면 세그먼티드, 화면을 옮기면 사이드바·바텀 탭바, 동시에 펼쳐야 하면 아코디언(2부).

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

로빙 탭인덱스가 핵심입니다 — 탭 줄 전체가 Tab 한 번이고, 안에서는 화살표로 움직입니다.

<div role="tablist" aria-label="가맹점 상세">
  <button role="tab" id="t1" aria-controls="p1"
          aria-selected="true" tabindex="0">개요</button>
  <button role="tab" … aria-selected="false" tabindex="-1">거래</button>
</div>
<div role="tabpanel" id="p1" aria-labelledby="t1" tabindex="0">…</div>

// 고른 탭만 tabindex=0 — 탭 줄 전체가 Tab 한 번이 된다
tabs.forEach(t => t.tabIndex = (t === sel) ? 0 : -1);
키일어나야 하는 일
Tab탭 줄 전체를 한 번에 지난다. 한 번 더 누르면 내용으로 간다
←→탭을 옮기고 옮기는 즉시 내용이 바뀐다
HomeEnd첫 탭·마지막 탭으로
aria-controls탭과 내용을 이어 둔다. 스크린 리더가 '탭 2/5'로 읽는다
패널tabindex="0"을 줘서 내용으로 포커스가 들어갈 수 있게 한다

9 서버 쪽으로 치면백엔드 감각으로 번역

탭 = 같은 리소스의 다른 표현보통 같은 ID 의 다른 필드입니다. 한 번에 다 받아 두면 전환이 즉시 되고, 따로 받으면 첫 화면이 가볍습니다 — 어느 쪽이 나은지는 탭 수와 크기로 정합니다.
주소에 담을 것인가/merchant/12?tab=tx로 두면 공유와 뒤로가기가 됩니다. 안 담으면 새로고침 때 늘 첫 탭으로 돌아갑니다.
지연 로드안 열어 본 탭은 안 부르는 것이 기본입니다. 다만 한 번 연 탭은 기억해 두면 오갈 때 빨라집니다.
배지 숫자탭마다 개수를 보여 주려면 열지 않은 탭의 수도 알아야 합니다. 요약 하나로 묶어 받는 편이 요청 수를 줄입니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

웹과 안드로이드는 '한 화면 안의 탭'이 또렷하고, iOS 는 그 자리에 다른 부품을 씁니다.

웹표준 부품 없음 · ARIA 패턴
개요거래
탭 · 부품은 없고 ARIA 패턴이 정해져 있습니다. 밑줄 꼴이 가장 흔합니다.
iOSApple HIG
개요거래
화면 안 전환은 세그먼티드 컨트롤로 합니다. iOS 에서 '탭'은 화면 아래 탭 바를 뜻합니다 — 뜻이 아예 다릅니다.
안드로이드Material 3
개요거래
탭(Tabs) · Primary(화면 위)와 Secondary(그 안쪽) 두 층으로 정리돼 있고, 넘치면 미는 스크롤 가능 탭도 표준입니다.

자주 생기는 사고 — iOS 에서 "탭"은 화면 아래 탭 바를 뜻합니다. 화면 안에서 내용을 바꾸는 것은 세그먼티드 컨트롤이라 부릅니다. "여기 탭으로 나눠 주세요"가 iOS 쪽에는 "앱 전체 구조를 바꾸자"로 들릴 수 있습니다.
