링크와 버튼

Link vs button

링크와 버튼은 누른 결과가 다른 곳으로 이동하는지, 그 자리에서 동작하는지로 가릅니다. 생김새는 자유롭게 꾸며도 되지만 태그는 이 뜻을 따라야 합니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

누른 뒤 주소가 바뀌면 링크(<a href>)이고, 그 자리에서 일이 일어나면 버튼(<button>)입니다.
div 에 onclick 을 달아 만들면 보기에는 똑같지만 Tab 이 멈추지 않고 Enter 로도 눌리지 않습니다. 'Tab 으로 훑어보기'를 누르면 초점이 몇 군데에서 멈추는지 세어 줍니다.
링크와 버튼을 서로 바꿔서 만들면 겉으로 티가 덜 나서 문제를 더 늦게 알아챕니다. 링크로 만든 '저장'은 새 탭으로 열리고, 버튼으로 만든 '상세 보기'는 가운데 버튼·복사·공유가 되지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어링크와 버튼, 앵커와 버튼
영어link vs button, anchor vs button
같이 쓰는 말링크처럼 보이는 버튼은 링크 버튼·텍스트 버튼, 버튼처럼 보이는 링크는 버튼 링크라고 부르는데, 둘 다 태그가 아니라 생김새를 가리키는 이름입니다. 태그 이름으로는 <a>를 앵커라고 하고, <button>은 그대로 버튼이라고 합니다.
자주 잘못 부르는 이름버튼 위계 — 버튼 위계는 버튼의 세기를 나누는 일이고, 링크와 버튼은 뜻을 가르는 일입니다.
CTA — CTA 는 화면에서 맡는 역할을 가리키는 이름이고, 태그 이름은 아닙니다.
링크 색 — 링크를 파란 밑줄로 그리는 것은 관습이고, 꼭 지켜야 하는 규칙은 아닙니다.

링크와 버튼을 한 줄로 정리하면 — 누른 뒤 주소가 바뀌면 링크, 그렇지 않으면 버튼을 씁니다. 링크와 버튼을 가르는 기준은 이것 하나입니다.

4 만드는 방식어떤 태그로 만드느냐에 따라 달라지는 동작

5 해부도부분마다 붙은 이름

주소가 바뀌는 이동이면 <a href>
그 자리에서 일어나는 동작이면 <button>
링크는 새 탭 열기 · 복사 · 공유가 됨
버튼은 Space 로도 눌리고 링크는 Enter 로만 열림
div + onclick 은 Tab 도 Enter 도 받지 못함
생김새는 자유롭게, 뜻은 태그로 지킴
  1. 이동 <a href>누르면 주소가 바뀝니다
  2. 동작 <button>그 자리에서 일이 일어납니다
  3. 링크만 되는 것 새 탭 · 복사링크는 오른쪽 클릭 메뉴가 버튼과 다릅니다
  4. 버튼만 받는 키 SpaceSpace 는 버튼만 누르고, 링크는 Enter 로만 열립니다
  5. div로 만든 줄 키보드로 쓸 수 없음Tab 도 멈추지 않고 Enter 로도 눌리지 않습니다
  6. 생김새 자유롭게 꾸밈생김새는 자유롭게 하고 뜻만 지킵니다

링크와 버튼을 서로 바꿔 쓰는 실수는 div 로 만드는 것보다 더 흔하고, 겉으로 드러나지 않아서 더 늦게 발견됩니다. 예를 들어 링크로 만든 '저장'은 가운데 버튼으로 누르면 새 탭에서 열리고, 그 탭에서 저장이 한 번 더 일어납니다. 버튼으로 만든 '상세 보기'는 링크 주소를 복사할 수도, 새 탭으로 열 수도 없습니다. 두 문제 모두 평소에는 드러나지 않아서 고쳐지지 않은 채 오래 남습니다.
어느 쪽인지 판단하기 애매하면 주소창을 보세요. 누른 뒤 주소가 바뀐다면 링크입니다. 모달을 열 때 주소를 바꾸기도 하는데, 그럴 때는 라이트박스처럼 링크로 두는 편이 공유도 되고 뒤로가기도 됩니다.

6 쓸 때 / 안 쓸 때

링크와 버튼을 고를 때 지킬 것

  • 주소가 바뀌면 링크, 그렇지 않으면 버튼으로 만들기
  • 폼 안의 버튼에는 type="button" 적기
  • div 에 onclick 을 달지 않기

링크와 버튼을 만들 때 피할 것

  • 저장을 링크로 만들기. 새 탭에서 한 번 더 저장됩니다
  • 상세 보기를 버튼으로 만들기. 주소 복사와 새 탭 열기가 되지 않습니다
  • <a href="#"> 에 onclick 달기. 누를 때마다 주소 끝에 #이 붙습니다
  • role="button" 만 붙이고 키보드를 안 붙이기

함께 보면 좋은 항목 — 버튼의 세기를 나누는 일은 버튼 위계에서, 버튼에 다른 동작 갈래가 붙는 경우는 분할 버튼에서 다룹니다. 버튼에 적을 문구는 버튼 문구, 초점이 멈추는 차례는 보이는 순서와 읽는 순서 항목에 있습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

생김새는 클래스로 정하고 뜻은 태그로 정해서, 둘을 따로 다룹니다.

<!-- 이동. 버튼처럼 보여도 링크다 -->
<a class="btn btn--primary" href="/orders/2411">주문 상세 보기</a>

<!-- 동작. 링크처럼 보여도 버튼이다 -->
<button class="btn btn--text" type="button">도움말 보기</button>

/* 둘을 같은 모양으로 만든다. 생김새는 클래스가 정한다 */
.btn { display: inline-flex; align-items: center; justify-content: center;
  min-height: 44px; text-decoration: none; font: inherit; cursor: pointer; }

/* ✕ 이건 둘 다 아니다 */
<div onclick="save()">저장</div>
키와 마크업그때 일어나야 하는 일
Enter링크와 버튼 둘 다 눌립니다
Space버튼만 눌립니다. 링크에서 누르면 페이지가 스크롤됩니다
⌘ · Ctrl + 클릭링크만 새 탭으로 열립니다
type="button"폼 안에서 적지 않으면 누를 때 폼이 제출됩니다
role="button"이 속성을 붙였다면 Enter·Space 처리도 직접 만들어 붙여야 합니다
제대로 만들었는지 확인하는 방법Tab 으로 화면을 훑으며 초점이 멈추지 않는 자리가 있는지 봅니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

이동이면 응답에 주소 담기응답에 url 을 담아 주면 화면이 그 주소로 바로 링크를 만들 수 있습니다. 반면 id 만 주면 화면이 주소를 직접 조립해야 합니다.
동작이면 바뀐 결과 돌려주기버튼이 부르는 API 가 무엇이 바뀌었는지 돌려줘야 화면이 부분 로딩으로 바뀐 곳만 다시 그릴 수 있습니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

링크와 버튼은 웹에만 있는 구분입니다. 앱 화면에는 주소가 없기 때문입니다.

웹<a> vs <button>
상세 보기a저장button
웹은 화면마다 주소가 있어서 공유·새 탭·뒤로가기를 따로 만들지 않아도 쓸 수 있습니다.
iOSNavigationLink vs Button
›
NavigationLink 는 이동, Button 은 동작을 맡아서 웹과 같은 구분이 있습니다.
안드로이드Navigation vs Button
코드에서 화면 이동은 내비게이션으로, 동작은 버튼으로 나눠 처리합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 앱에도 이동과 동작이라는 구분은 똑같이 있지만 웹만큼 차이가 드러나지 않습니다. 앱 화면에는 주소가 없어서 '새 탭으로 열기'나 '링크 복사'가 처음부터 없기 때문입니다. 반면 웹에서 이 구분을 지키면 공유할 수 있는 주소, 뒤로가기, 가운데 버튼, 검색 엔진처럼 따로 만들지 않고도 얻는 것이 많습니다. 앱을 만들다 웹으로 온 사람들이 특히 자주 놓치는 부분이기도 합니다.
