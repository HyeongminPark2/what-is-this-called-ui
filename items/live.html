라이브 리전

Live region

화면이 저절로 바뀐 것을 소리로 알리는 자리. 눈으로는 보이지만 소리로는 안 들리는 틈을 메웁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 버튼을 눌러 보세요. 조용히 바꾸기는 화면 숫자만 바뀌고 아래 기록은 그대로입니다 — 화면을 못 보는 사람에게는 아무 일도 없던 것입니다.
status는 하던 말이 끝난 뒤, alert는 말을 끊고 알립니다. 기록의 '[기다렸다가]'와 '[말을 끊고]'가 그 차이입니다.

2 이름부르는 말이 여러 개다

한국어라이브 리전, 실시간 알림 영역
영어live region, aria-live, polite, assertive
같이 쓰는 말기다렸다 읽는 것을 polite, 말을 끊고 읽는 것을 assertive라 합니다. role="status"는 polite 의, role="alert"는 assertive 의 짧은 이름입니다. 여러 번 바뀔 때 다 읽을지 정하는 것은 aria-atomic·aria-relevant 입니다.
자주 잘못 부름토스트 — 토스트는 부품이고 라이브 리전은 읽히게 하는 장치입니다. 토스트를 띄워도 리전이 없으면 안 읽힙니다.
알림(notification) — 브라우저 알림은 다른 기능입니다.
alert() — 자바스크립트의 그 함수와는 아무 상관이 없습니다.

3 가르는 기준형제들과 비교하는 네 축

접근성은 '눈으로는 안 보이는 것을 챙기는 일'입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 돕나눈으로 보이나안 하면 누가 막히나어떻게 확인하나
포커스지금 어디인지보여야 한다키보드만 쓰는 사람Tab 을 눌러 본다
포커스 트랩모달 안에 가두기안 보인다키보드·스크린 리더모달에서 Tab 을 돌려 본다
키보드 조작마우스 없이 전부안 보인다마우스를 못 쓰는 사람마우스를 치우고 해 본다
이름 붙이기뭐라고 부르나안 보인다화면을 못 보는 사람접근성 트리를 본다
스크린 리더가 읽는 것역할 · 이름 · 상태안 보인다화면을 못 보는 사람실제로 읽혀 본다
라이브 리전저절로 바뀐 것안 보인다화면을 못 보는 사람바꿔 놓고 들어 본다
대비비글자가 읽히나보인다저시력 · 밝은 곳 · 싼 화면재 본다(숫자로 나온다)
시맨틱 태그화면의 구조안 보인다거의 모두구역 목록을 열어 본다

한 줄로 — 라이브 리전은 미리 비워 둔 채로 있어야 합니다. 알릴 때 통째로 만들면 읽지 않습니다 — 가장 흔한 실수입니다.

4 갈래언제 어떻게 알리나

5 해부도부분 이름이 제일 안 알려진 지식

정산이 3건 추가되었습니다
role="status" = aria-live="polite"
role="alert" = aria-live="assertive" (말을 끊는다)
리전은 미리 비워 둔 채로 있어야 한다
내용만 바꾼다 — 통째로 새로 만들면 안 읽는다
aria-busy — 다 바뀐 뒤에 한 번만 읽히게
  1. 알릴 말 message저절로 바뀐 것. 사용자가 누른 결과거나 서버가 보낸 것
  2. 기다렸다 알리기 role="status"하던 말을 마치고 읽는다. 대부분 이것으로 충분
  3. 끊고 알리기 role="alert"말을 끊는다. 오류·연결 끊김처럼 급한 것에만
  4. 미리 두기 빈 리전알릴 때 만들면 안 읽는다. 처음부터 비워 둔 채로 있어야 한다
  5. 내용만 바꾸기 textContent리전을 지웠다 다시 만들면 새 리전이라 안 읽힌다
  6. 다 바뀐 뒤에 aria-busy여러 줄을 고칠 때 true로 묶었다가 끝나면 false

리전을 알릴 때 만들면 안 읽힙니다. 스크린 리더는 '이미 있던 리전의 내용이 바뀐 것'을 감시하기 때문입니다. 그래서 토스트를 띄울 때마다 <div role="status">를 새로 붙이면 아무 소리도 안 납니다 — 빈 리전을 화면 어딘가에 미리 두고 그 안의 글만 바꾸는 것이 정석입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 사용자가 누른 뒤 저절로 바뀌는 것 — 저장됨, 삭제됨, N건 추가됨
  • 검색 결과 개수처럼 입력에 따라 바뀌는 숫자
  • 폼 오류 — 제출을 막았으면 alert
  • 연결 끊김·세션 만료

이럴 때는 안 쓴다

  • 1초마다 바뀌는 것에 거는 것 — 계속 읽어 시끄럽습니다
  • 모든 것에 alert를 쓰는 것 — 끊는 것은 거슬립니다
  • 리전을 알릴 때 만드는 것 — 안 읽힙니다
  • 화면에 안 보이는데 소리로만 알리는 것 — 둘 다 있어야 합니다

대신 이걸 — 부품 자체는 토스트·에러 상태, 상태 속성은 스크린 리더가 읽는 것.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 규칙미리 두고 내용만 바꾼다

빈 리전을 미리 두고, 알릴 때는 그 안의 글만 바꿉니다.

<!-- 화면 어딘가에 미리 — 비어 있는 채로 -->
<div id="status" role="status" class="sr-only"></div>
<div id="errors" role="alert" class="sr-only"></div>

// 알릴 때는 '내용만' 바꾼다
status.textContent = '정산을 확정했습니다';

// 같은 말을 또 알려야 하면 한 번 비웠다 넣는다
status.textContent = '';
requestAnimationFrame(() => status.textContent = msg);

/* 보이지 않게 두는 표준 방법 — display:none 은 안 읽힌다 */
.sr-only { position: absolute; width: 1px; height: 1px;
           overflow: hidden; clip: rect(0 0 0 0); }
규칙지켜야 하는 것
리전을 미리 둔다비어 있는 채로. 알릴 때 만들면 안 읽힌다
내용만 바꾼다요소를 갈아 끼우지 않는다
status를 기본으로alert는 말을 끊으니 정말 급한 것에만
display:none으로 숨기지 않는다안 읽힌다. .sr-only 방식으로 숨긴다
같은 말을 또 알릴 때한 번 비웠다가 다시 넣어야 바뀐 것으로 친다
자주 바뀌면 묶는다aria-busy로 묶었다가 끝나고 한 번만 읽히게

9 서버 쪽으로 치면백엔드 감각으로 번역

무엇을 알릴지 정한다서버 응답이 올 때마다 다 알리면 시끄럽습니다. 사용자가 한 행동의 결과만 알리는 것이 기준입니다.
실시간 밀어 주기웹소켓으로 남이 바꾼 것까지 알리면 끝없이 말합니다. 내 행동과 남의 행동을 나눠 다룹니다.
문구는 짧게소리로 듣는 글입니다. '정산 요청 #4821이(가) 정상적으로 처리 완료되었습니다' 보다 '정산을 확정했습니다'가 낫습니다.
검사자동 도구는 리전이 있는지는 보지만 실제로 읽히는지는 못 봅니다. VoiceOver 를 켜고 한 번 해 보는 수밖에 없습니다.
