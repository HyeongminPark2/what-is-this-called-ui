라이브 리전

Live region

라이브 리전은 화면 내용이 저절로 바뀌었을 때 스크린 리더가 그 내용을 소리로 읽어 주게 하는 영역입니다. 화면에 새로 뜬 내용은 눈으로는 바로 보이지만, 라이브 리전이 없으면 스크린 리더는 아무것도 읽지 않습니다.

세 버튼을 눌러 보세요. 조용히 바꾸기를 누르면 화면의 숫자만 바뀌고 아래 기록에는 아무것도 남지 않습니다. 화면을 보지 못하는 사람은 무엇이 바뀌었는지 전혀 알 수 없습니다.
status는 스크린 리더가 읽던 말을 마친 뒤 알리고, alert는 읽던 말을 끊고 바로 알립니다. 기록에 찍히는 '[기다렸다가]'와 '[말을 끊고]'가 이 차이를 보여 줍니다.

2 이름같은 것을 부르는 여러 이름

한국어라이브 리전, 실시간 알림 영역
영어live region, aria-live, polite, assertive
같이 쓰는 말읽던 말을 마칠 때까지 기다렸다가 읽는 방식은 polite, 읽던 말을 끊고 바로 읽는 방식은 assertive라고 합니다. role="status"는 polite 리전을, role="alert"는 assertive 리전을 짧게 쓰는 방법입니다. 내용이 바뀔 때 무엇을 읽을지는 aria-atomic과 aria-relevant로 정합니다.
자주 잘못 부르는 이름토스트 — 토스트는 화면에 뜨는 부품이고, 라이브 리전은 그 내용을 스크린 리더가 읽게 하는 장치입니다. 그래서 토스트를 띄워도 라이브 리전이 없으면 스크린 리더는 읽지 않습니다.
알림(notification) — 브라우저가 띄우는 알림은 라이브 리전과 다른 기능입니다.
alert() — role="alert"는 자바스크립트의 alert() 함수와 아무 상관이 없습니다.

라이브 리전을 한 줄로 정리하면 — 라이브 리전은 처음부터 빈 채로 화면에 두어야 합니다. 알릴 때가 되어서야 리전을 새로 만들면 스크린 리더가 읽지 않는데, 이것이 가장 흔한 실수입니다.

4 알리는 방식바뀐 내용을 언제 어떻게 알리는지

5 해부도부분마다 붙은 이름

정산이 3건 추가되었습니다
role="status" — aria-live="polite"와 같음
role="alert" — aria-live="assertive"와 같음(말을 끊음)
리전은 빈 채로 미리 두어야 함
통째로 새로 만들면 읽지 않으니 내용만 바꿈
aria-busy — 다 바뀐 뒤에 한 번만 읽히게 함
  1. 알릴 말 message저절로 바뀐 내용입니다. 사용자가 누른 버튼의 결과일 수도 있고, 서버가 보낸 소식일 수도 있습니다
  2. 기다렸다 알리기 role="status"읽던 말을 마친 뒤에 읽습니다. 대부분은 이 방식으로 충분합니다
  3. 끊고 알리기 role="alert"읽던 말을 끊고 바로 읽습니다. 오류나 연결 끊김처럼 급한 내용에만 씁니다
  4. 리전을 미리 두기 빈 리전알릴 때 리전을 만들면 읽지 않으므로, 처음부터 빈 리전을 두어야 합니다
  5. 내용만 바꾸기 textContent리전을 지웠다가 다시 만들면 스크린 리더가 새 리전으로 보고 읽지 않습니다
  6. 다 바뀐 뒤에 읽히기 aria-busy여러 줄을 한꺼번에 고칠 때 true로 두었다가, 다 고친 뒤 false로 바꿉니다

알릴 때가 되어서 리전을 만들면 스크린 리더가 읽지 않습니다. 스크린 리더는 이미 있던 리전의 내용이 바뀌는 것만 지켜보기 때문입니다. 그래서 토스트를 띄울 때마다 <div role="status">를 새로 붙이면 아무 소리도 나지 않습니다. 빈 리전을 화면 어딘가에 미리 두고 그 안의 글만 바꾸는 것이 표준적인 방법입니다.

6 쓸 때 / 안 쓸 때

라이브 리전을 쓰는 경우

  • 저장됨, 삭제됨, N건 추가됨처럼 사용자가 버튼을 누른 뒤 저절로 바뀌는 내용을 알릴 때
  • 검색 결과 개수처럼 입력에 따라 바뀌는 숫자를 알릴 때
  • 폼 오류를 알릴 때. 오류 때문에 제출을 막았다면 alert로 알립니다
  • 연결이 끊기거나 세션이 만료되었을 때

라이브 리전을 쓰지 않거나 잘못 쓰는 경우

  • 1초마다 바뀌는 내용에 걸 때. 스크린 리더가 쉬지 않고 읽어서 시끄럽습니다
  • 모든 알림에 alert를 쓸 때. 읽던 말이 자꾸 끊기면 사용자가 불편합니다
  • 리전을 알릴 때 새로 만들 때. 스크린 리더가 읽지 않습니다
  • 화면에는 보이지 않고 소리로만 알릴 때. 화면 표시와 소리 둘 다 있어야 합니다

라이브 리전과 이어지는 주제는 다른 항목에서 다룹니다 — 화면에 뜨는 부품 자체는 토스트와 에러 상태 항목에서, 요소의 상태를 알리는 속성은 스크린 리더가 읽는 것에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 규칙리전을 미리 두고 내용만 바꾸는 방법

빈 리전을 미리 만들어 두고, 알릴 때는 리전 안의 글만 바꿉니다.

<!-- 화면 어딘가에 빈 채로 미리 둔다 -->
<div id="status" role="status" class="sr-only"></div>
<div id="errors" role="alert" class="sr-only"></div>

// 알릴 때는 '내용만' 바꾼다
status.textContent = '정산을 확정했습니다';

// 같은 말을 또 알려야 하면 한 번 비웠다 넣는다
status.textContent = '';
requestAnimationFrame(() => status.textContent = msg);

/* 보이지 않게 두는 표준 방법. display:none 으로 숨기면 읽히지 않는다 */
.sr-only { position: absolute; width: 1px; height: 1px;
           overflow: hidden; clip: rect(0 0 0 0); }
지킬 규칙지키는 방법
리전을 미리 두기빈 채로 미리 둡니다. 알릴 때 만들면 읽히지 않습니다
리전의 내용만 바꾸기리전 요소를 새 요소로 바꾸지 않고 안의 글만 바꿉니다
status를 기본으로 쓰기alert는 읽던 말을 끊기 때문에 정말 급한 내용에만 씁니다
display:none으로 숨기지 않기display:none으로 숨기면 읽히지 않으므로 .sr-only 방식으로 숨깁니다
같은 말을 또 알릴 때리전을 한 번 비웠다가 다시 넣어야 스크린 리더가 내용이 바뀐 것으로 봅니다
자주 바뀌는 내용은 묶어서 알리기aria-busy로 묶어 두었다가 바뀌는 일이 끝난 뒤 한 번만 읽히게 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

무엇을 알릴지 정하기서버 응답이 올 때마다 모두 알리면 시끄럽기 때문에, 사용자가 한 행동의 결과만 알리는 것을 기준으로 삼습니다.
실시간으로 받은 변경 알리기웹소켓으로 받은 다른 사람의 변경까지 모두 알리면 스크린 리더가 쉬지 않고 읽습니다. 그래서 내가 한 행동의 결과와 다른 사람이 바꾼 내용을 나눠서 다룹니다.
알리는 문구를 짧게 쓰기라이브 리전의 문구는 소리로 듣는 글이므로 짧을수록 좋습니다. '정산 요청 #4821이(가) 정상적으로 처리 완료되었습니다' 보다 '정산을 확정했습니다'가 낫습니다.
실제로 읽히는지 검사하기자동 검사 도구는 리전이 있는지는 확인하지만 실제로 읽히는지는 확인하지 못합니다. 그래서 VoiceOver를 켜고 직접 한 번 들어 봐야 합니다.
