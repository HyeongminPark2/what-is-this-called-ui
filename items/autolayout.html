오토 레이아웃

Auto layout

오토 레이아웃은 플렉스박스입니다. 이름만 다를 뿐 같은 것이라, 대응표 하나면 대화가 짧아집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

조작기를 움직이면 아래에 그대로 CSS 가 나옵니다 — 이름만 다를 뿐 같은 것입니다.
이 대응표를 알고 있으면 “여백이 자동이에요”가 gap 이고 “채우기로 해 주세요”가 flex: 1 이라는 것이 바로 들립니다.

2 이름부르는 말이 여러 개다

한국어오토 레이아웃, 자동 배치, 스택
영어auto layout, stack, frame
같이 쓰는 말자식을 한 방향으로 줄 세우는 상자가 오토 레이아웃 프레임입니다. 남은 자리를 다 쓰는 것이 채우기(Fill), 내용만큼만 차지하는 것이 감싸기(Hug), 값을 박는 것이 고정(Fixed)입니다. 다른 도구에서는 스택(Stack)이라 부르고, SwiftUI 의 HStack·VStack도 같은 생각입니다.
자주 잘못 부름그리드 — CSS 그리드는 두 방향입니다. 오토 레이아웃은 한 방향이라 플렉스에 가깝습니다.
프레임 — 그냥 상자를 뜻하기도 하고 오토 레이아웃이 걸린 상자를 뜻하기도 합니다.
레이아웃 그리드 — 화면을 세로로 나눈 안내선입니다. 전혀 다른 것입니다.

3 가르는 기준형제들과 비교하는 네 축

현장 용어는 말이 아니라 일하는 단계를 가리킵니다. 이 네 가지만 물어보면 갈립니다.

무엇을 가리키나언제 나오나개발 쪽 대응물잘못 알아들으면
와이어프레임과 목업과 시안얼마나 진짜 같은 그림인가기획 ~ 디자인마크업 구조 ~ 완성 화면엉뚱한 리뷰가 돌아온다
디자인 시스템규칙 + 부품 + 문서프로젝트 내내토큰 + 컴포넌트 라이브러리스타일 가이드와 섞인다
컴포넌트와 인스턴스원본과 복제본시안 작업컴포넌트 정의와 사용원본을 고쳐 전체가 바뀐다
배리언트와 프롭같은 부품의 정해진 변형시안 작업props상태와 섞인다
오토 레이아웃자동 배치시안 작업flexbox‘여백이 자동’을 못 알아듣는다
프로토타입눌리는 시안리뷰 · 사용자 시험아직 코드가 아니다다 된 줄 안다
핸드오프넘기는 일개발 시작 전스펙 읽기그림만 받고 규칙은 못 받는다
에셋 내보내기그림 파일 넘기기개발 중srcset · SVG1배만 받아 뭉갠다

한 줄로 — 대응표 한 장이면 통역이 끝납니다. 채우기 = flex: 1, 감싸기 = fit-content, 간격 = gap.

4 설정별로CSS 로는 무엇인가

5 해부도부분 이름이 제일 안 알려진 지식

오토 레이아웃 = display: flex
가로 · 세로 = flex-direction: row · column
간격 = gap · 패딩 = padding
채우기(Fill) = flex: 1
감싸기(Hug) = width: fit-content
절대 위치 = position: absolute — 흐름에서 뺀다
  1. 오토 레이아웃 display: flex자식을 한 방향으로 줄 세운다
  2. 방향 row · column가로냐 세로냐
  3. 간격 · 패딩 gap · padding사이 빈틈과 안쪽 여백
  4. 채우기 flex: 1남은 자리를 다 쓴다. 가장 자주 오가는 말
  5. 감싸기 fit-content내용만큼만
  6. 절대 위치 position: absolute흐름에서 빼낸다 — 배지·뱃지 같은 것

시안의 오토 레이아웃이 곧 마크업 구조라는 점이 숨은 쓸모입니다. 시안에서 상자를 어떻게 묶었는지가 <div> 를 어떻게 묶을지와 거의 그대로 겹칩니다. 그래서 시안이 오토 레이아웃으로 잘 짜여 있으면 마크업이 빨라지고, 절대 위치로 늘어놓은 시안은 구조를 다시 생각해서 만들어야 합니다 — "이 시안 오토 레이아웃으로 되어 있나요"가 일정을 가늠하는 질문이 되는 이유입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 시안의 묶음을 그대로 마크업으로 옮기기
  • 대응표를 손에 두고 대화하기
  • 채우기·감싸기·고정 가운데 무엇인지 물어보기

이럴 때는 안 쓴다

  • 절대 위치로 늘어놓은 시안을 그대로 흉내 내기
  • 오토 레이아웃을 그리드와 섞어 부르기
  • 간격을 margin으로 — gap 이 더 안 깨진다
  • '알아서 되게' 로 넘기기 — Fill 인지 Hug 인지 물어본다

대신 이걸 — 두 방향이 필요하면 그리드, 한 방향이면 플렉스, 간격 값은 간격 체계.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 대응표이 말의 계약서

시안에서 부르는 말과 CSS 를 짝지어 둡니다.

/* 오토 레이아웃 = 플렉스 */
.frame {
  display: flex;                 /* 오토 레이아웃 */
  flex-direction: row;          /* 가로 · 세로 */
  gap: 12px;                    /* 간격 */
  padding: 16px;                /* 패딩 */
  align-items: center;          /* 맞춤 (세로축) */
  justify-content: space-between; /* 맞춤 (가로축) */
  flex-wrap: wrap;              /* 줄바꿈 */
}

.child-fill { flex: 1; min-width: 0; }   /* 채우기 (Fill) */
.child-hug  { width: fit-content; }      /* 감싸기 (Hug) */
.child-fix  { width: 120px; }           /* 고정 (Fixed) */
.badge      { position: absolute; }       /* 절대 위치 */
키일어나야 하는 일
min-width: 0을 잊지 않는다Fill 로 둔 칸에 긴 글이 들어가면 넘친다 — 플렉스
gap이 margin보다 낫다첫·마지막 칸의 예외가 없고, 줄바꿈에서도 안 깨진다
순서가 곧 읽는 순서order나 row-reverse로 눈에만 바꾸면 키보드 순서와 어긋난다
position: absolute흐름에서 빠지므로 자리를 안 차지한다. 배지·닫기 버튼에
터치 타깃간격을 좁게 잡으면 손가락이 겹친다
반응형같은 오토 레이아웃이라도 폭에 따라 방향이 바뀌어야 할 때가 있다 — 브레이크포인트

9 서버 쪽으로 치면백엔드 감각으로 번역

구조가 곧 마크업시안의 묶음이 <div> 묶음과 겹칩니다. 오토 레이아웃으로 짜인 시안이 개발을 빠르게 합니다.
데이터 길이시안은 짧은 글로 그려집니다. 실제 길이로 한 번 채워 보면 Fill·Hug 선택이 드러납니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

한 방향으로 줄 세우기라는 생각이 어디에나 있습니다.

웹flexbox
display: flex
gap·flex: 1. 시안의 말과 거의 1대1로 대응합니다.
iOSHStack · VStack
HStack(spacing: 12)
HStack·VStack·Spacer(). Spacer 가 justify-content 자리입니다.
안드로이드Row · Column
Row(horizontalArrangement = …)
Compose 의 Row·Column·weight(1f). weight 가 flex: 1 입니다.

자주 생기는 사고 — "오토 레이아웃이 뭐예요"는 디자이너와 개발자가 같은 것을 다른 이름으로 부르고 있다는 신호입니다. 대응표를 한 번 맞춰 두면 '여백 자동'·'채우기'·'감싸기' 같은 말이 바로 코드로 옮겨지고, 시안 리뷰에서 구조 이야기를 할 수 있게 됩니다.
