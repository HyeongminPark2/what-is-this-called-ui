오토 레이아웃

Auto layout

오토 레이아웃은 플렉스박스입니다. 시안 도구와 CSS에서 부르는 이름만 다를 뿐 같은 개념이라서, 두 이름을 짝지은 대응표 하나만 있으면 디자이너와 개발자의 대화가 짧아집니다.

2 이름같은 것을 부르는 여러 이름

한국어오토 레이아웃, 자동 배치, 스택
영어auto layout, stack, frame
같이 쓰는 말자식 요소를 한 방향으로 줄 세우는 상자를 오토 레이아웃 프레임이라고 합니다. 자식이 남은 자리를 모두 쓰게 하는 설정은 채우기(Fill), 내용만큼만 차지하게 하는 설정은 감싸기(Hug), 크기를 값으로 정해 두는 설정은 고정(Fixed)입니다. 다른 도구에서는 스택(Stack)이라고 부르며, SwiftUI의 HStack·VStack도 같은 개념입니다.
자주 잘못 부르는 이름그리드 — CSS 그리드는 가로와 세로 두 방향으로 배치하지만, 오토 레이아웃은 한 방향으로 배치하므로 그리드가 아니라 플렉스에 가깝습니다.
프레임 — 그냥 상자를 뜻하기도 하고, 오토 레이아웃을 적용한 상자를 뜻하기도 합니다.
레이아웃 그리드 — 화면을 세로 단으로 나눠 보여 주는 안내선이라서 오토 레이아웃과는 전혀 다른 기능입니다.

오토 레이아웃을 한 줄로 정리하면 — 대응표 한 장만 있으면 시안의 말을 CSS로 바로 옮길 수 있습니다. 채우기는 flex: 1, 감싸기는 fit-content, 간격은 gap입니다.

5 해부도부분마다 붙은 이름

오토 레이아웃은 display: flex
가로 · 세로는 flex-direction: row · column
간격은 gap, 패딩은 padding
채우기(Fill)는 flex: 1
감싸기(Hug)는 width: fit-content
절대 위치는 position: absolute로 흐름에서 뺌
  1. 오토 레이아웃 display: flex자식 요소를 한 방향으로 줄 세웁니다
  2. 방향 row · column가로로 늘어놓을지 세로로 쌓을지 정합니다
  3. 간격 · 패딩 gap · padding간격은 자식 사이의 빈틈, 패딩은 상자 안쪽의 여백입니다
  4. 채우기 flex: 1남은 자리를 모두 씁니다. 디자이너와 개발자 사이에서 가장 자주 오가는 말입니다
  5. 감싸기 fit-content내용만큼만 자리를 차지합니다
  6. 절대 위치 position: absolute배치 흐름에서 빼내어 겹쳐 놓습니다. 배지·뱃지 같은 것에 씁니다

잘 드러나지 않는 쓸모는 시안의 오토 레이아웃이 그대로 마크업 구조가 된다는 점입니다. 시안에서 상자를 묶은 방식이 코드에서 <div>를 묶을 방식과 거의 그대로 겹치기 때문입니다. 그래서 시안이 오토 레이아웃으로 잘 짜여 있으면 마크업을 빨리 만들 수 있지만, 절대 위치로 늘어놓은 시안은 개발자가 구조를 다시 생각해서 만들어야 합니다. "이 시안 오토 레이아웃으로 되어 있나요"라는 질문으로 개발 일정을 가늠할 수 있는 것도 이 때문입니다.

6 쓸 때 / 안 쓸 때

오토 레이아웃 대응표가 쓸모 있는 경우

  • 시안의 묶음을 그대로 마크업으로 옮길 때
  • 대응표를 옆에 두고 디자이너와 이야기할 때
  • 채우기, 감싸기, 고정 가운데 무엇인지 물어볼 때

오토 레이아웃을 코드로 옮길 때 피할 것

  • 절대 위치로 늘어놓은 시안을 코드에서도 그대로 흉내 낼 때
  • 오토 레이아웃을 그리드와 섞어 부를 때
  • 간격을 margin으로 줄 때. gap을 써야 배치가 덜 깨집니다
  • '알아서 되게' 해 달라는 말로 넘어갈 때. Fill인지 Hug인지 물어봐야 합니다

관련 주제는 다른 항목에서 다룹니다 — 가로와 세로 두 방향으로 배치해야 하면 그리드를, 한 방향이면 플렉스 항목을 보세요. 간격 값을 정하는 방법은 간격 체계에서 다룹니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 시안과 CSS 대응표시안의 말과 CSS 짝짓기

시안 도구에서 부르는 이름과 CSS 속성을 짝지어 두면 다음과 같습니다.

/* 오토 레이아웃 = 플렉스 */
.frame {
  display: flex;                 /* 오토 레이아웃 */
  flex-direction: row;          /* 가로 · 세로 */
  gap: 12px;                    /* 간격 */
  padding: 16px;                /* 패딩 */
  align-items: center;          /* 맞춤 (세로축) */
  justify-content: space-between; /* 맞춤 (가로축) */
  flex-wrap: wrap;              /* 줄바꿈 */
}

.child-fill { flex: 1; min-width: 0; }   /* 채우기 (Fill) */
.child-hug  { width: fit-content; }      /* 감싸기 (Hug) */
.child-fix  { width: 120px; }           /* 고정 (Fixed) */
.badge      { position: absolute; }       /* 절대 위치 */
지킬 규칙그렇게 하는 이유
Fill 칸에 min-width: 0 넣기Fill로 둔 칸에 min-width: 0이 없으면 긴 글이 들어갔을 때 칸 밖으로 넘칩니다(플렉스 참고)
margin 대신 gap 쓰기첫 칸과 마지막 칸을 따로 처리할 필요가 없고, 줄바꿈이 일어나도 간격이 깨지지 않습니다
보이는 순서와 읽는 순서 맞추기order나 row-reverse로 보이는 순서만 바꾸면 키보드로 옮겨 가는 순서와 어긋납니다
position: absolute배치 흐름에서 빠지므로 자리를 차지하지 않습니다. 배지나 닫기 버튼에 씁니다
터치 타깃 넓이 지키기간격을 좁게 잡으면 손가락이 옆 버튼까지 누르게 됩니다
화면 폭에 따라 방향 바꾸기같은 오토 레이아웃이라도 화면 폭에 따라 방향이 바뀌어야 할 때가 있습니다(브레이크포인트 참고)

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

시안 구조를 마크업으로 옮기기시안에서 상자를 묶은 방식이 코드의 <div> 묶음과 겹치기 때문에, 오토 레이아웃으로 짜인 시안을 받으면 개발이 빨라집니다.
실제 데이터 길이로 채워 보기시안은 대개 짧은 글로 그려져 있습니다. 실제 데이터의 길이로 한 번 채워 보면 어느 칸을 Fill로, 어느 칸을 Hug로 둬야 하는지 드러납니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

자식을 한 방향으로 줄 세우는 배치 방식은 어느 플랫폼에나 있습니다.

웹flexbox
display: flex
gap과 flex: 1 같은 속성이 시안의 설정과 거의 1대1로 대응합니다.
iOSHStack · VStack
HStack(spacing: 12)
HStack·VStack·Spacer()를 쓰며, Spacer가 justify-content 역할을 합니다.
안드로이드Row · Column
Row(horizontalArrangement = …)
Compose의 Row·Column·weight(1f)를 쓰며, weight가 flex: 1에 해당합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 개발자가 "오토 레이아웃이 뭐예요"라고 묻는다면 디자이너와 개발자가 같은 것을 다른 이름으로 부르고 있다는 뜻입니다. 대응표를 한 번 맞춰 두면 '여백 자동', '채우기', '감싸기' 같은 말을 바로 코드로 옮길 수 있고, 시안 리뷰에서도 구조 이야기를 할 수 있게 됩니다.
