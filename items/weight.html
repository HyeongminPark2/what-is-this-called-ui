글자 굵기

Font weight

글자 굵기는 글자 획의 두께입니다. 굵기를 쓰면 크기를 키우지 않고도 강조할 수 있고, 굵기를 바꿔도 줄 높이는 그대로라서 레이아웃이 흔들리지 않습니다.

체크를 풀어 아홉 단을 모두 펼쳐 보세요. 그러면 아래에 실제로 다르게 보이는 단이 몇 개인지 재서 알려 줍니다. 받아 온 파일이 없는 단은 브라우저가 흉내 내서 그리거나 옆 단과 똑같이 그리기 때문에, 아홉 단이 모두 다르게 보이지는 않습니다.
이 화면의 글꼴에서 몇 단이 진짜인지는 글꼴마다 다릅니다. 시안에 '세미볼드'라고 적혀 있어도 그 굵기의 파일을 받아 오지 않았다면 화면에서는 볼드와 구별되지 않습니다.

2 이름같은 것을 부르는 여러 이름

한국어글자 굵기, 굵기, 웨이트
영어font weight, weight, bold, regular
같이 쓰는 말100~900 사이의 숫자로 나타낸 굵기를 웨이트라고 하며, 이름으로 부르면 가는 것부터 Thin · Light · Regular · Medium · SemiBold · Bold · Black 순입니다. 글꼴 파일이 없어서 브라우저가 만들어 내는 굵기는 가짜 굵게(synthetic bold · faux bold), 파일 하나로 모든 굵기를 내는 글꼴은 가변 글꼴(variable font)이라고 부릅니다.
자주 잘못 부르는 이름<b>와 <strong> — 굵기는 생김새일 뿐이지만 strong은 중요하다는 뜻을 나타내기 때문에 스크린 리더가 둘을 다르게 읽습니다.
볼드 — 보통 700을 가리키지만, 글꼴에 따라서는 600을 '볼드'라고 부르기도 합니다.
굵기와 크기 — 둘 다 강조 수단이지만, 크기와 달리 굵기는 바꿔도 줄 높이가 그대로입니다.

  1. 400 Regular font-weight: 400본문에 쓰는 기본값으로, 글의 대부분이 이 굵기입니다
  2. 500 Medium font-weight: 500줄 제목이나 라벨처럼 살짝 강조할 곳에 씁니다
  3. 700 Bold font-weight: 700제목과 버튼에 씁니다. <b>와 <strong>도 기본으로 이 굵기입니다
  4. 파일 한 벌 @font-face굵기 하나마다 파일이 하나씩 필요해서, 굵기를 늘리면 그만큼 더 내려받아야 합니다
  5. 가짜 굵게 synthetic bold파일이 없으면 브라우저가 획을 부풀려 만들어 내기 때문에 글자가 뭉개져 보입니다
  6. 가변 글꼴 variable font파일 하나로 100~900을 모두 냅니다. 요즘은 한글 글꼴도 가변 글꼴로 나옵니다

한글에서는 가짜 굵게가 특히 나쁘게 보입니다. 한글은 획이 많아서 브라우저가 획을 부풀리면 자음 안쪽의 빈 공간이 메워지고, 글자가 덩어리처럼 뭉개집니다. 영문은 가짜 굵게로 그려도 어느 정도 읽을 만하지만 한글은 바로 티가 나기 때문에, 쓸 굵기의 파일은 반드시 받아 와야 합니다.

5 쓸 때 / 안 쓸 때

글자 굵기를 쓰는 경우

  • 크기를 바꾸지 않고 강조할 때. 굵기만 바꾸면 줄 높이가 그대로라 레이아웃이 흔들리지 않습니다
  • 표의 머리글이나 줄 제목, 버튼 글자를 본문과 구별할 때
  • 같은 글자 크기 안에서 위계를 한 단계 더 만들고 싶을 때

글자 굵기를 쓰지 않는 경우

  • 굵기를 다섯 단 넘게 둘 때. 내려받을 파일만 늘고, 화면에서는 단끼리 구별되지 않습니다
  • 본문 전체를 300(Light)으로 쓸 때. 작은 글자에서는 획이 흐려 보여 읽기 힘듭니다
  • 중요한 내용을 <b>로 굵게만 할 때. 중요하다는 뜻을 담으려면 <strong>을 씁니다
  • 받아 오지 않는 굵기를 시안에 적을 때. 화면에서는 그 굵기가 가짜 굵게로 그려집니다

글자 굵기 대신 다른 것을 써야 하는 경우 — 글자 크기의 차이로 위계를 만들려면 타입 스케일을 쓰고, 크기·굵기·색을 함께 써서 읽는 순서를 정하려면 글자 위계를 봅니다. 굵기별 글꼴 파일을 받아 오는 문제는 웹폰트에서 다룹니다.

7 최소 코드와 규칙굵기를 적고 받아 오는 규칙

굵기는 숫자로 적습니다. bold는 700을 가리키는 다른 이름이라서 500이나 600 같은 중간 단은 나타낼 수 없습니다.

/* 받아 올 굵기만 적는다. 굵기 하나에 파일 하나가 필요하다 */
@font-face {
  font-family: "Pretendard";
  font-weight: 400;
  src: url("pretendard-400.woff2") format("woff2");
}
@font-face { font-weight: 700; src: url("pretendard-700.woff2"); … }

/* 가변 글꼴이면 한 벌로 끝난다 */
@font-face {
  font-weight: 100 900;          /* 범위로 적는다 */
  src: url("pretendard-var.woff2") format("woff2-variations");
}

/* 브라우저가 가짜 굵게를 만들지 못하게 막을 수도 있다 */
body { font-synthesis: none; }
지킬 규칙지키는 방법
굵기는 숫자로 적기700처럼 숫자로 씁니다. bold로는 중간 단을 가리킬 수 없기 때문입니다
쓸 굵기의 파일만 받아 오기굵기 하나마다 파일이 하나씩 필요하고, 한글 글꼴은 한 벌이 수백 KB나 됩니다
가변 글꼴을 쓸 수 있는지 보기파일 하나로 모든 굵기를 낼 수 있으면 굵기를 늘려도 내려받을 파일이 늘지 않습니다
<strong>은 뜻을 담을 때만굵게 보이게만 하려면 CSS로 굵기를 주고, 중요하다는 뜻을 담을 때만 strong을 씁니다
가짜 굵게가 생기는지 확인하기파일이 없는 굵기를 쓰면 한글이 뭉개지므로, 화면에서 직접 눈으로 확인합니다
세 단으로 시작하기400·500·700 세 단으로 시작하고, 단을 늘리기 전에 화면에서 정말 구별되는지 확인합니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

굵기 수만큼 늘어나는 글꼴 파일굵기를 하나 늘리면 내려받을 글꼴 파일도 한 벌 늘어납니다. 한글 글꼴은 한 벌이 수백 KB나 되기 때문에, 굵기를 늘릴수록 첫 화면이 뜨는 속도가 느려집니다.
가변 글꼴이 이득이 되는 경우가변 글꼴은 파일 하나로 모든 굵기를 내지만, 굵기 하나짜리 파일보다 파일 자체가 더 큽니다. 그래서 굵기를 셋 이상 쓸 때부터 이득입니다.
시안과 실제 화면의 차이디자인 도구에서는 글꼴의 모든 굵기를 고를 수 있지만, 웹 화면에는 받아 온 굵기만 제대로 나옵니다. 실제로 받아 오는 굵기 목록을 디자이너와 먼저 합의해 두면 '세미볼드가 안 나와요' 같은 일이 생기지 않습니다.
메일과 PDF에서 쓸 수 있는 굵기메일이나 PDF처럼 웹폰트를 쓸 수 없는 곳에서는 굵기 두 단(400·700)만 제대로 나온다고 보고 화면을 짭니다.

이름과 숫자를 모두 씁니다. 기기에 없는 단은 안드로이드도 흉내 내서 그리므로, 쓸 굵기의 폰트 파일을 앱에 함께 넣습니다.

플랫폼 차이 때문에 자주 생기는 문제 — "굵기를 하나 더 쓰면 파일도 하나 더 받아야 한다"는 비용은 웹에서만 눈에 띕니다. 두 모바일 OS는 시스템 글꼴에 단이 모두 들어 있어서 "세미볼드로 해 주세요"라는 요청에 따로 드는 비용이 없습니다. 그래서 같은 요청이라도 웹에서는 화면이 뜨는 속도까지 함께 따져야 합니다.
