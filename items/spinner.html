스피너

Spinner · Loading indicator

얼마나 걸릴지 모르는 기다림을 알리는 돌아가는 고리. 아는 게 '지금 뭔가 하고 있다' 뿐일 때 씁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

빠르게를 눌러 보세요. 스피너가 아예 안 뜹니다. 0.3초 안에 끝나는 일에 스피너를 띄우면 깜빡이고 사라져서 오히려 더 느리게 느껴집니다. 느리게는 띄우되, 한번 띄웠으면 최소 0.5초는 유지합니다 — 이 두 숫자가 스피너의 거의 전부입니다.

2 이름부르는 말이 여러 개다

한국어스피너, 로딩 아이콘, 로딩 표시
영어spinner, loading indicator, busy indicator, throbber
같이 쓰는 말연한 고리를 트랙, 도는 진한 부분을 인디케이터라 합니다. 끝을 모르는 표시라 비결정형(indeterminate)으로 분류합니다.
자주 잘못 부름프로그레스 바 — 둘 다 기다림을 알리지만, 프로그레스 바는 끝나는 때를 압니다. 모르면서 퍼센트를 지어내면 안 됩니다.
로딩 — '로딩 띄워 주세요'는 스피너인지 스켈레톤인지 가려지지 않습니다.
버퍼링 — 영상이 잠깐 끊길 때만 쓰는 말입니다.

3 가르는 기준형제들과 비교하는 네 축

겹쳐 뜨는 부품들은 모양으로는 구별이 안 됩니다. 이 네 가지만 물어보면 갈립니다.

끝나는 때를 아나들어올 자리를 잡나사용자가 기다리나화면이 덜컥거리나
스피너모른다안 잡는다기다린다덜컥거린다
스켈레톤모른다잡는다기다린다안 덜컥거린다
프로그레스 바안다잡기도 한다기다린다안 덜컥거린다
낙관적 UI해당 없음잡는다안 기다린다안 덜컥거린다

한 줄로 — 스피너는 아는 게 없을 때 씁니다. 들어올 모양을 알면 스켈레톤, 끝나는 때를 알면 프로그레스 바가 더 나은 답입니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

불러오는 중…
  1. 자리 container끝나면 여기에 내용이 들어온다. 스피너가 차지한 높이와 실제 내용의 높이가 다르면 덜컥거린다
  2. 트랙 track연한 고리. 없는 디자인도 많다
  3. 인디케이터 indicator도는 진한 부분. 이것만으로는 얼마나 남았는지 알 수 없다
  4. 안내 문구 label무엇을 기다리는지. aria-label로도 같이 알린다

그림에 없는 두 숫자가 사실 이 부품의 전부입니다 — 지연(0.3초 전에는 안 띄운다)과 최소 표시 시간(띄웠으면 0.5초는 둔다). 둘 다 깜빡임을 없애려는 장치입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 얼마나 걸릴지 정말로 모를 때
  • 들어올 내용의 모양도 모를 때 (검색 결과 첫 조회 등)
  • 버튼 하나의 처리처럼 자리가 작을 때

이럴 때는 안 쓴다

  • 0.3초 안에 끝나는 일 — 깜빡임만 남깁니다
  • 들어올 모양을 아는 목록·카드 → 스켈레톤이 낫습니다
  • 퍼센트를 알 수 있는 업로드 → 프로그레스 바
  • 화면 전체를 스피너로 덮기 — 자리를 안 잡아 두면 내용이 들어올 때 덜컥거립니다

대신 이걸 — 들어올 모양을 알면 스켈레톤, 끝나는 때를 알면 프로그레스 바, 기다림 자체를 없앨 수 있으면 낙관적 UI.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

돌아가는 모양은 CSS 한 줄이고, 어려운 건 언제 띄우고 언제 치우느냐입니다.

<div id="panel" aria-busy="true">
  <span class="spn" role="status" aria-label="불러오는 중"></span>
</div>

// 0.3초를 넘길 때만 띄운다
const t = setTimeout(show, 300);

// 빨리 끝나면 아예 안 띄운 채로 끝낸다
await load(); clearTimeout(t);

// 이미 띄웠으면 최소 0.5초는 둔다 — 깜빡임 방지
if (shown) await wait(500 - (Date.now() - shownAt));

/* 움직임을 줄여 달라는 설정은 지킨다 */
@media (prefers-reduced-motion: reduce) { .spn { animation-duration: 2.4s; } }
키일어나야 하는 일
포커스스피너는 포커스를 뺏지 않는다. 하던 입력이 끊긴다
스크린 리더aria-busy="true"를 바뀌는 영역에 걸고, 안내는 role="status"로 알린다
끝났을 때aria-busy를 지우고, 바뀐 내용 쪽으로 포커스를 옮길지 따로 정한다
움직임 줄이기prefers-reduced-motion이 켜져 있으면 천천히 돌리거나 정적인 표시로 바꾼다
실패돌다가 멈추는 것이 아니라 실패 화면으로 바뀌어야 한다

9 서버 쪽으로 치면백엔드 감각으로 번역

스피너 = 진행률 없는 폴링응답이 올 때까지 아무 정보도 없는 상태입니다. 서버가 진행률을 줄 수 있으면 그걸 받아 프로그레스 바로 바꾸는 쪽이 언제나 낫습니다.
지연 = 디바운스0.3초 안에 끝날 일에 표시를 띄우지 않는 것은, 짧은 요청에 로그를 안 남기는 것과 같은 절약입니다.
최소 표시 시간 = 안정화깜빡임을 막으려고 일부러 늦추는 것입니다. 지표가 요동칠 때 창을 두고 평균 내는 것과 같습니다.
타임아웃스피너는 영원히 돌 수 있지만 요청에는 상한이 있어야 합니다. 상한이 없으면 사용자는 멈춘 화면을 봅니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

이 부품은 플랫폼마다 모양이 다르고 이름도 다릅니다.

웹표준 지침 없음
스피너 · 고리 모양이 가장 흔합니다. 브라우저가 주는 기본 부품은 없어서 직접 그립니다.

액티비티 인디케이터(Activity indicator) · 고리가 아니라 돌아가는 막대입니다. 이름도 '스피너'가 아닙니다.
안드로이드Material 3
비결정형 프로그레스 인디케이터(Indeterminate progress indicator) · 원형과 띠 두 가지가 있고, 프로그레스와 같은 부품의 한 모드로 봅니다.

자주 생기는 사고 — 안드로이드에서는 스피너와 프로그레스 바가 같은 부품의 두 모드입니다(결정형 / 비결정형). 더 헷갈리는 건, 안드로이드에 Spinner 라는 전혀 다른 부품이 따로 있다는 것입니다 — 그건 셀렉트(드롭다운)입니다. "스피너 넣어 주세요"가 거기서는 선택 상자가 됩니다.
