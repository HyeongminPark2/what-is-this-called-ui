스피너

Spinner · Loading indicator

스피너는 얼마나 걸릴지 모르는 기다림을 알리려고 띄우는, 빙글빙글 도는 고리입니다. 화면이 알려 줄 수 있는 것이 '지금 무언가를 처리하고 있다'는 사실 하나뿐일 때 씁니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

빠르게를 눌러 보면 스피너가 아예 뜨지 않습니다. 0.3초 안에 끝나는 일에 스피너를 띄우면 잠깐 깜빡이고 사라지는데, 이 깜빡임 때문에 오히려 더 느리게 느껴지기 때문입니다. 느리게를 누르면 스피너를 띄우고, 한번 띄운 스피너는 최소 0.5초 동안 그대로 둡니다. 스피너를 다룰 때 정해야 할 것은 대부분 이 두 시간입니다.

2 이름같은 것을 부르는 여러 이름

한국어스피너, 로딩 아이콘, 로딩 표시
영어spinner, loading indicator, busy indicator, throbber
같이 쓰는 말바탕에 깔린 연한 고리는 트랙, 그 위에서 도는 진한 부분은 인디케이터라고 부릅니다. 언제 끝날지 모르는 상태를 나타내는 표시라서 비결정형(indeterminate)으로 분류합니다.
자주 잘못 부르는 이름프로그레스 바 — 둘 다 기다림을 알리지만, 프로그레스 바는 끝나는 때를 알 때 씁니다. 진행률을 모르는데 퍼센트를 지어내 보여 주면 안 됩니다.
로딩 — '로딩 띄워 주세요'라고만 하면 스피너를 말하는지 스켈레톤을 말하는지 알 수 없습니다.
버퍼링 — 영상 재생이 잠깐 끊겼을 때만 쓰는 말입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품들은 모양만 보고는 구별하기 어렵지만, 아래 네 가지를 따져 보면 어느 부품인지 가려낼 수 있습니다.

끝나는 때를 아는가들어올 내용의 자리를 미리 잡는가사용자가 기다려야 하는가내용이 들어올 때 화면이 덜컥거리는가
스피너모름잡지 않음기다림덜컥거림
스켈레톤모름잡아 둠기다림덜컥거리지 않음
프로그레스 바알고 있음잡기도 함기다림덜컥거리지 않음
낙관적 UI해당 없음잡아 둠기다리지 않음덜컥거리지 않음

스피너를 한 줄로 정리하면 — 스피너는 기다리는 동안 알려 줄 정보가 없을 때 씁니다. 들어올 내용의 모양을 알면 스켈레톤이, 끝나는 때를 알면 프로그레스 바가 더 알맞습니다.

4 상태상태마다 달라지는 모습

5 해부도부분마다 붙은 이름

불러오는 중…
  1. 자리 container로딩이 끝나면 이 자리에 내용이 들어옵니다. 스피너가 차지한 높이와 실제 내용의 높이가 다르면 화면이 덜컥거립니다
  2. 트랙 track바탕의 연한 고리입니다. 트랙을 그리지 않는 디자인도 많습니다
  3. 인디케이터 indicator도는 진한 부분입니다. 계속 돌기만 하므로 얼마나 남았는지는 알 수 없습니다
  4. 안내 문구 label무엇을 기다리는지 적습니다. 같은 내용을 aria-label로도 알립니다

그림에는 보이지 않지만 스피너에서 특히 중요한 값이 두 가지 있습니다. 0.3초가 지나기 전에는 띄우지 않는 지연과, 한번 띄우면 0.5초는 두는 최소 표시 시간입니다. 두 값 모두 스피너가 잠깐 떴다 사라지는 깜빡임을 없애려고 둡니다.

6 쓸 때 / 안 쓸 때

스피너를 쓰는 경우

  • 얼마나 걸릴지 정말로 모를 때
  • 들어올 내용의 모양도 모를 때(검색 결과를 처음 조회할 때 등)
  • 버튼 하나의 처리처럼 자리가 작을 때

스피너를 쓰지 않는 경우

  • 0.3초 안에 끝나는 일을 기다릴 때. 스피너가 깜빡이기만 하고 사라집니다
  • 들어올 모양을 아는 목록이나 카드를 불러올 때. 스켈레톤이 더 알맞습니다
  • 퍼센트를 알 수 있는 업로드를 기다릴 때. 프로그레스 바를 씁니다
  • 화면 전체를 스피너로 덮을 때. 내용이 들어올 자리를 잡아 두지 않았기 때문에 내용이 들어오는 순간 화면이 덜컥거립니다

스피너 대신 다른 것을 써야 하는 경우 — 들어올 내용의 모양을 알면 스켈레톤을 쓰고, 끝나는 때를 알면 프로그레스 바를 씁니다. 기다림 자체를 없앨 수 있다면 낙관적 UI가 더 낫습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

도는 모양은 CSS 한 줄로 만들 수 있습니다. 정작 신경 써야 하는 부분은 언제 띄우고 언제 치울지입니다.

<div id="panel" aria-busy="true">
  <span class="spn" role="status" aria-label="불러오는 중"></span>
</div>

// 0.3초를 넘길 때만 띄운다
const t = setTimeout(show, 300);

// 빨리 끝나면 아예 안 띄운 채로 끝낸다
await load(); clearTimeout(t);

// 이미 띄웠으면 깜빡이지 않도록 최소 0.5초는 둔다
if (shown) await wait(500 - (Date.now() - shownAt));

/* 움직임을 줄여 달라는 설정은 지킨다 */
@media (prefers-reduced-motion: reduce) { .spn { animation-duration: 2.4s; } }
상황그때 일어나야 하는 일
포커스를 다룰 때스피너가 포커스를 가져가지 않게 합니다. 포커스를 가져가면 사용자가 하던 입력이 끊깁니다
스크린 리더로 읽을 때aria-busy="true"를 내용이 바뀌는 영역에 걸고, 안내 문구는 role="status"로 알립니다
끝났을 때aria-busy를 지웁니다. 바뀐 내용 쪽으로 포커스를 옮길지는 화면에 맞게 따로 정합니다
움직임 줄이기 설정이 켜져 있을 때prefers-reduced-motion이 켜져 있으면 천천히 돌리거나 움직이지 않는 표시로 바꿉니다
불러오기에 실패했을 때스피너가 돌다가 그대로 멈추면 안 되고, 실패 화면으로 바뀌어야 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

진행률 없이 응답만 기다리는 상태스피너는 응답이 올 때까지 진행 정보를 하나도 받지 못한 상태를 나타냅니다. 서버가 진행률을 알려 줄 수 있다면 그 값을 받아 프로그레스 바로 바꾸는 편이 언제나 낫습니다.
지연은 디바운스와 같은 원리0.3초 안에 끝날 일에는 표시를 띄우지 않습니다. 짧은 요청까지 일일이 로그로 남기지 않는 것처럼, 금방 끝나는 일에는 표시를 아끼는 셈입니다.
최소 표시 시간으로 깜빡임 막기깜빡임을 막으려고 스피너를 치우는 시점을 일부러 늦춥니다. 지표가 요동칠 때 일정한 시간 창을 두고 평균을 내서 값을 안정시키는 것과 같은 방법입니다.
요청 쪽에 시간 상한 두기스피너 자체는 끝없이 돌 수 있기 때문에 요청 쪽에 시간 상한을 두어야 합니다. 상한이 없으면 응답이 오지 않을 때 사용자는 멈춘 화면을 계속 보게 됩니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

스피너는 플랫폼마다 모양도 다르고 부르는 이름도 다릅니다.

웹표준 지침 없음
스피너 · 고리 모양이 가장 흔합니다. 브라우저가 기본으로 주는 부품이 없어서 직접 그립니다.
iOSApple HIG
액티비티 인디케이터(Activity indicator) · 고리가 아니라 여러 개의 막대가 둥글게 돌아가는 모양이고, 이름도 '스피너'가 아닙니다.
안드로이드Material 3
비결정형 프로그레스 인디케이터(Indeterminate progress indicator) · 원형과 띠 두 가지 모양이 있고, 프로그레스 바와 같은 부품의 한 모드로 다룹니다.

플랫폼 차이 때문에 자주 생기는 문제 — 안드로이드에서는 스피너와 프로그레스 바가 같은 부품의 두 모드(결정형과 비결정형)입니다. 게다가 안드로이드에는 Spinner라는 이름의 전혀 다른 부품이 따로 있는데, 이 부품은 셀렉트(드롭다운)입니다. 그래서 안드로이드에서 "스피너 넣어 주세요"라고 하면 선택 상자를 넣어 달라는 말로 알아듣습니다.
