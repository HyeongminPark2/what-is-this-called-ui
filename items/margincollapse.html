여백 붕괴

Margin collapse

맞닿은 세로 여백은 더해지지 않고 겹칩니다. 그래서 24px과 16px이 맞닿으면 간격은 40px이 아니라 큰 쪽인 24px이 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

여백을 주는 방법을 바꿔 가며 실제 간격을 잰 값을 보세요. 두 값을 더하면 40px이지만 margin으로 붙이면 24px로 나옵니다.
flex 안에서는 여백이 겹치지 않아 40px이 그대로 나오고, 부모에 padding이 생겨도 붕괴가 멈춥니다. 코드를 건드리지 않은 것 같은데 간격이 바뀌는 일은 흔히 이 때문에 생깁니다.

2 이름같은 것을 부르는 여러 이름

한국어여백 붕괴, 마진 겹침, 마진 상쇄
영어margin collapsing, collapsing margins
같이 쓰는 말맞닿은 두 형제 사이에서 여백이 겹치는 것은 인접 형제 붕괴, 첫 자식의 margin-top이 부모 밖으로 빠져나가는 것은 부모-자식 붕괴라고 부릅니다. 붕괴가 멈추는 상태는 새 블록 서식 문맥(BFC)이 생겼다고 말하는데, overflow: hidden이나 display: flow-root를 주면 새 블록 서식 문맥이 생깁니다.
자주 잘못 부르는 이름간격 체계 — 간격 체계는 간격을 얼마로 할지 정하는 규칙이고, 여백 붕괴는 여백이 어떻게 계산되는지에 관한 규칙입니다.
패딩 — 패딩은 안쪽 여백이라서 겹치지 않습니다.
gap — gap은 마진과 다른 방식으로 간격을 만들기 때문에 겹치지 않습니다.

3 여백이 겹치는 경우와 겹치지 않는 경우적은 값이 그대로 나오는지 비교

4 해부도부분마다 붙은 이름

위 24와 아래 16이 만나면 40이 아닌 24
세로만 겹치고 가로는 더해짐
flex·grid 안에서는 겹치지 않음
부모에 padding·테두리가 생기면 멈춤
첫 자식의 margin이 부모 밖으로 빠지기도 함
gap을 쓰면 적은 값이 그대로 나옴
  1. 형제끼리 큰 쪽만 남음24px과 16px이 맞닿으면 24px만 남습니다
  2. 세로 방향 가로는 더해짐좌우 여백은 겹치지 않습니다
  3. flex · grid 겹치지 않음여백이 겹치지 않기 때문에 gap으로 준 간격은 예측할 수 있습니다
  4. 멈추는 조건 padding · 테두리padding이나 테두리가 생기면 붕괴가 그 자리에서 멈춥니다
  5. 부모-자식 밖으로 빠짐첫 자식의 여백이 부모를 밀어냅니다
  6. 해결 방법 gap적은 값이 그대로 나옵니다

여백 붕괴는 '건드리지도 않았는데 간격이 바뀌었다'는 문제의 흔한 원인입니다. 부모에 padding이나 테두리를 1px만 더해도 붕괴가 멈춰서 간격이 갑자기 늘어납니다. 반대로 패딩을 지우면 자식 여백이 부모 밖으로 빠져나가면서 엉뚱한 자리가 벌어집니다. 원인과 결과가 멀리 떨어져 있어 찾기 어렵지만, 간격을 gap으로 주는 습관을 들이면 이런 문제가 아예 생기지 않습니다.

5 쓸 때 / 안 쓸 때

여백 붕괴를 피해 간격을 주는 방법

  • 요소 사이 간격을 줄 때. gap으로 줍니다
  • 꼭 margin을 써야 할 때. 한 방향만(아래쪽만) 씁니다
  • 붕괴를 막고 싶을 때. display: flow-root를 씁니다

여백을 줄 때 피할 것

  • 위아래 margin을 둘 다 줄 때. 여백이 겹쳐서 계산이 어긋납니다
  • 간격을 맞추려고 padding을 1px 더할 때. 붕괴가 멈춰서 옆 간격까지 바뀝니다
  • overflow: hidden으로 붕괴를 막을 때. 그림자와 툴팁이 잘립니다
  • margin과 gap을 섞어 간격을 줄 때. 섞으면 간격을 추적하기 어려우니, margin은 가운데 맞추기에만 쓰고 나머지는 gap으로 줍니다

여백 붕괴와 함께 보면 좋은 항목 — 간격을 얼마로 할지는 간격 체계에서, 안쪽 여백인 패딩은 박스 모델에서 다룹니다. 요소를 한 줄로 세우면서 gap으로 띄우는 방법은 플렉스에서 봅니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 규칙여백을 줄 때 지킬 것

gap을 기본으로 두고, 꼭 필요할 때만 flow-root로 막습니다.

/* 대부분 이쪽. 겹칠 일이 없다 */
.stack { display: flex; flex-direction: column; gap: var(--space-4); }

/* margin을 쓴다면 한 방향만 */
.prose > * + * { margin-top: var(--space-4); }

/* 붕괴만 막는다. overflow:hidden과 달리 잘리지 않는다 */
.card { display: flow-root; }

/* ✕ 이렇게 하면 계산이 어긋난다 */
.a { margin-bottom: 24px; }
.b { margin-top: 16px; }    /* 합 40 이 아니라 24 */
지킬 규칙지키는 방법
세로 여백만 겹친다는 점 기억하기좌우 여백은 그대로 더해집니다
붕괴는 display: flow-root로 막기붕괴만 막습니다. 반면 overflow:hidden은 그림자와 툴팁까지 자릅니다
gap은 flex·grid 안에서만 쓰기일반 블록 흐름에는 아직 적용되지 않습니다
* + *로 한 방향 여백 주기첫 요소만 빼고 여백을 붙입니다. 한 방향 규칙을 적용하는 흔한 방법입니다
빈 요소의 여백도 겹친다는 점 기억하기내용이 없는 상자는 자기 위아래 여백끼리도 겹칩니다
개발자 도구로 실제 여백 확인하기개발자 도구에서 요소를 선택하면 실제 여백이 주황색으로 표시됩니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

CSS 안에서만 계산되는 규칙여백 붕괴는 모두 CSS 안에서 계산됩니다. 다만 데이터가 없어 내용이 비었을 때 간격이 달라져서 화면이 어색해지는 일이 있습니다.
목록이 비었을 때목록에 줄이 하나도 없으면 여백만 남아 이상한 빈칸이 생기므로 빈 상태 문구를 둡니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

여백 붕괴는 웹에만 있는 규칙입니다.

웹margin collapsing
위 상자24px아래 상자
CSS 초기부터 있던 규칙입니다. 글 문서를 위해 만든 규칙이라서 UI에서는 자주 방해가 됩니다.
iOS여백 붕괴 없음
VStack(spacing:)으로 사이 간격을 직접 주기 때문에 겹칠 일이 없습니다.
안드로이드여백 붕괴 없음
Arrangement.spacedBy()로 같은 일을 하며, 여기서도 여백이 겹치지 않습니다.

플랫폼 차이 때문에 자주 생기는 문제 — 앱을 만들다 웹으로 온 사람들이 가장 먼저 당황하는 규칙입니다. CSS에 적은 값이 그대로 나오지 않기 때문입니다. 다행히 요즘은 gap이 널리 쓰여서 이 규칙과 마주칠 일이 줄었습니다. 간격은 gap으로 준다는 것을 팀 규칙으로 적어 두면 여백 붕괴는 알고만 있으면 되는 지식이 됩니다.
