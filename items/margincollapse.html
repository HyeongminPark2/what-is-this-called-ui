여백 붕괴

Margin collapse

세로 여백은 더해지지 않고 겹칩니다. 24 + 16 이 40 이 아니라 24가 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

붙이는 법을 바꿔 가며 실제 간격을 잰 값을 보세요 — 적은 값 40px 이 margin에서는 24px로 나옵니다.
flex 안에서는 안 겹쳐 40px 이 그대로 나오고, 부모에 padding이 생겨도 붕괴가 멈춥니다 — 예고 없이 간격이 바뀌는 흔한 원인입니다.

2 이름부르는 말이 여러 개다

한국어여백 붕괴, 마진 겹침, 마진 상쇄
영어margin collapsing, collapsing margins
같이 쓰는 말맞닿은 두 형제 사이에서 겹치는 것이 인접 형제 붕괴, 첫 자식의 margin-top이 부모 밖으로 새는 것이 부모-자식 붕괴입니다. 붕괴가 멈추는 상태를 새 블록 서식 문맥(BFC)이 생겼다고 말합니다. overflow: hidden·display: flow-root가 그걸 만듭니다.
자주 잘못 부름간격 체계 — 간격 체계는 얼마를 쓸지의 규칙이고, 이건 어떻게 계산되는지입니다.
패딩 — 패딩은 안쪽 여백이라 겹치지 않습니다.
gap — gap은 아예 다른 장치입니다. 그래서 안 겹칩니다.

한 줄로 — 간격은 gap으로 주세요. 그러면 적은 값이 그대로 나오고, 첫·마지막 예외도 없습니다.

4 언제 겹치나적은 값이 그대로 나오나

5 해부도부분 이름이 제일 안 알려진 지식

위 24 + 아래 16 = 40 이 아니라 24
세로만 겹친다 — 가로는 더해진다
flex · grid 안에서는 안 겹친다
부모의 padding · 테두리가 생기면 멈춘다
첫 자식의 margin 이 부모 밖으로 새기도 한다
gap 을 쓰면 적은 값이 그대로 나온다
  1. 형제끼리 큰 쪽만24 와 16 이면 24
  2. 세로만 가로는 더해짐좌우 여백은 겹치지 않는다
  3. flex · grid 안 겹친다그래서 gap이 예측 가능하다
  4. 멈추는 조건 padding · 테두리생기면 붕괴가 그 자리에서 멈춘다
  5. 부모-자식 밖으로 샌다첫 자식의 여백이 부모를 밀어낸다
  6. 해법 gap적은 값이 그대로 나온다

'건드리지도 않았는데 간격이 바뀌었다'의 흔한 원인입니다. 부모에 padding이나 테두리를 1px만 더해도 붕괴가 멈춰 간격이 갑자기 늘어납니다. 반대로 패딩을 지우면 자식 여백이 부모 밖으로 새면서 엉뚱한 자리가 벌어집니다. 원인과 결과가 멀리 떨어져 있어 찾기 어려운데, 간격을 gap으로 주는 습관 하나면 이 종류가 통째로 사라집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 간격은 gap으로 주기
  • 꼭 margin 을 쓴다면 한 방향만(아래쪽만) 쓰기
  • 붕괴를 막고 싶으면 display: flow-root

이럴 때는 안 쓴다

  • 위·아래 margin 을 둘 다 주기 — 계산이 어긋난다
  • 간격을 맞추려고 padding을 1px 더하기 — 옆 간격까지 바뀐다
  • overflow: hidden으로 붕괴 막기 — 그림자·툴팁이 잘린다
  • margin 으로 가운데 맞추기 말고는 다 gap 으로 — 섞으면 추적이 어렵다

대신 이걸 — 간격 값 자체는 간격 체계, 안쪽 여백은 박스 모델, 줄 세우기는 플렉스.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 여백의 계약서

gap을 기본으로 두고, 꼭 필요할 때만 flow-root로 막습니다.

/* 거의 늘 이쪽 — 겹칠 일이 없다 */
.stack { display: flex; flex-direction: column; gap: var(--space-4); }

/* margin 을 쓴다면 한 방향만 */
.prose > * + * { margin-top: var(--space-4); }

/* 붕괴만 막는다 — overflow:hidden 과 달리 잘리지 않는다 */
.card { display: flow-root; }

/* ✕ 이렇게 하면 계산이 어긋난다 */
.a { margin-bottom: 24px; }
.b { margin-top: 16px; }    /* 합 40 이 아니라 24 */
키일어나야 하는 일
세로만 겹친다좌우 여백은 그대로 더해진다
display: flow-root붕괴만 막는다. overflow:hidden은 그림자·툴팁까지 자른다
gap은 flex·grid 에서만블록 흐름에는 아직 안 먹는다
* + *첫 요소에만 여백이 안 붙는다 — 한 방향 규칙의 흔한 꼴
빈 요소내용이 없는 상자는 자기 위아래 여백끼리도 겹친다
확인하는 법개발자 도구에서 요소를 짚으면 실제 여백이 주황색으로 보인다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버와는 상관없다전부 CSS 계산입니다. 다만 내용이 비었을 때 간격이 달라져 화면이 어색해지는 일이 있습니다.
빈 목록줄이 하나도 없으면 여백만 남아 이상한 빈칸이 생깁니다 — 빈 상태 문구를 둡니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

웹에만 있는 규칙입니다.

웹margin collapsing
위 상자24px아래 상자
CSS 초기부터 있던 규칙입니다. 글 문서를 위해 만든 것이라 UI 에서는 자주 거슬립니다.
iOS없다
VStack(spacing:)으로 사이 간격을 직접 줍니다. 겹칠 일이 없습니다.
안드로이드없다
Arrangement.spacedBy()가 같은 자리입니다. 역시 겹침이 없습니다.

자주 생기는 사고 — 앱 쪽에서 오신 분들이 웹에서 가장 먼저 당황하는 규칙입니다 — 적은 값이 안 나오기 때문입니다. 다행히 요즘은 gap이 널리 쓰여 마주칠 일이 줄었고, 간격은 gap 으로를 팀 규칙으로 적어 두면 이 항목은 '알고만 있으면 되는' 지식으로 내려갑니다.
