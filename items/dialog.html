다이얼로그

Dialog (modeless · modal)

다이얼로그는 사용자에게 무언가를 묻거나 입력을 받으려고 화면 위에 띄우는 대화 상자입니다. 뒤쪽 화면을 막으면 모달, 막지 않으면 비모달이라고 부르기 때문에 모달은 다이얼로그의 한 종류입니다.

새 탭에서 열기 ↗

찾기를 열어 둔 채 뒤쪽 글을 읽어 보세요. 비모달이라서 뒤쪽 글을 스크롤할 수도 있고 글자를 선택할 수도 있습니다. 옆의 나가기 확인은 같은 <dialog> 요소를 showModal()로 연 것인데, 이렇게 열면 뒤쪽 화면이 막히고 Tab으로 옮기는 포커스도 다이얼로그 안에서만 돕니다. 모달과 비모달은 어느 메서드로 여느냐로만 갈립니다.

2 이름같은 것을 부르는 여러 이름

한국어다이얼로그, 대화 상자
영어dialog
같이 쓰는 말뒤쪽 화면을 막는 것은 모달 다이얼로그, 막지 않는 것은 비모달(modeless·non-modal)이라고 부릅니다. 답 하나를 받으려고 띄우는 작은 모달은 얼럿 다이얼로그라고 합니다.
자주 잘못 부르는 이름모달 — 모달은 다이얼로그의 한 종류일 뿐이어서, 뒤를 막지 않는 다이얼로그를 모달이라고 부르면 틀립니다.
팝업 — 브라우저가 새로 여는 팝업 창과 이름이 겹쳐서 헷갈립니다.
창 — 운영체제의 윈도와 헷갈립니다. 다이얼로그는 별도의 창이 아니라 페이지 안에 그려집니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품은 생김새로는 가르기 어렵습니다. 아래 네 가지로 가릅니다.

다이얼로그를 한 줄로 정리하면 — 다이얼로그는 모달과 비모달을 함께 이르는 상위 개념이고, 뒤쪽 화면을 막느냐에 따라 둘로 나뉩니다. 코드에서는 showModal()로 여느냐 show()로 여느냐만 다릅니다.

2 / 4곳 다음
  1. 뒤쪽 내용 background content어두워지지 않습니다. 스크림이 없다는 점이 비모달과 모달을 가르는 가장 큰 차이입니다
  2. 다이얼로그 dialog surface모달보다 작고 그림자도 약하며, 화면 구석에 붙여 두는 경우가 많습니다
  3. 제목 줄 title bar무엇을 하는 다이얼로그인지 알려 주고, 끌어서 옮기는 손잡이 역할도 합니다
  4. 닫기 close비모달은 사용자가 닫을 때까지 계속 떠 있기 때문에 모달보다 닫기 버튼이 더 중요합니다
  5. 내용 content뒤쪽 화면을 보면서 쓰는 것이라 작고 단순하게 만듭니다
  6. 액션 영역 actions'다음 찾기'처럼 여러 번 누르는 버튼이 놓입니다. 모달에서는 버튼을 한 번 누르면 다이얼로그가 닫힙니다

모달의 해부도(모달 ⑤칸)와 비교해 보면 스크림이 없다는 점만 다릅니다. 하지만 스크림이 없으면 뒤쪽 화면을 계속 쓸 수 있으므로, 포커스를 가두지 않고 배경 스크롤도 잠그지 않으며 다른 창과의 겹침 순서도 따로 정해야 합니다.

6 쓸 때 / 안 쓸 때

다이얼로그를 쓰는 경우

  • 찾기·바꾸기처럼 뒤쪽 화면을 보면서 일할 때
  • 도구 창이나 속성 패널처럼 열어 둔 채 여러 번 쓸 때
  • 보조 정보를 오래 띄워 두고 참고할 때

다이얼로그를 쓰지 않는 경우

  • 꼭 답을 받아야 할 때. 비모달은 사용자가 무시하고 지나갈 수 있으니 모달을 씁니다
  • 되돌릴 수 없는 작업을 확인받을 때. 이때도 모달을 씁니다
  • 화면이 좁을 때. 다이얼로그를 띄우면 뒤쪽을 볼 자리가 남지 않아서 비모달로 둘 이유가 없습니다
  • 비모달을 여러 개 띄우면서 겹침 순서를 정하지 않을 때

다이얼로그 대신 다른 것을 써야 하는 경우 — 사용자의 답을 꼭 받아야 하면 모달을 쓰고, 누른 요소 바로 옆에 붙어 떠야 하면 팝오버가 맞습니다. 화면 옆에 길게 열어 두고 쓸 것이라면 드로어를, 결과를 알리기만 하면 된다면 토스트를 씁니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

모달과 비모달은 같은 <dialog> 요소를 어느 메서드로 여느냐만 다릅니다. 아래 코드의 show()와 showModal() 두 줄이 그 차이입니다.

<dialog id="dlg" aria-labelledby="t">…</dialog>

// 비모달. 뒤를 막지 않고 포커스도 가두지 않는다
dlg.show();

// 모달. 뒤가 inert 가 되고 포커스가 안에 갇힌다
dlg.showModal();

// 지금 어느 쪽으로 열려 있는지 물어볼 수 있다
dlg.matches(':modal');   // showModal() 로 열었으면 true

// 비모달은 자리를 직접 잡아 줘야 한다 (모달처럼 가운데로 안 온다)
dialog.dlg { position: fixed; top: 72px; right: 20px; margin: 0; }
키와 마크업그때 일어나야 하는 일
Esc모달과 비모달 모두 닫힙니다. <dialog> 요소가 알아서 처리합니다
Tab모달에서만 포커스가 안에 갇히고, 비모달에서는 뒤쪽 화면으로 이어집니다
뒤쪽 화면의 스크롤모달일 때만 잠급니다. 비모달은 뒤쪽 화면을 쓰려고 띄우는 것이라 그대로 둡니다
다이얼로그가 열릴 때포커스를 첫 입력 칸으로 옮깁니다. 비모달은 사용자가 뒤쪽에서 하던 일이 있으니 포커스를 옮길지 더 신중하게 정합니다
다이얼로그가 닫힐 때포커스를 다이얼로그를 열었던 요소로 돌려보냅니다. 모달과 비모달 모두 이 처리를 직접 해야 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

show()는 비동기 호출, showModal()은 동기 호출비모달은 띄워 놓고 다른 일을 계속하는 반면, 모달은 사용자의 답이 올 때까지 흐름을 멈춥니다. 비동기 호출에 await를 붙이느냐 붙이지 않느냐를 고르는 것과 같습니다.
여러 비모달은 동시에 열린 세션과 같음비모달은 여러 개가 동시에 떠 있을 수 있어서 겹침 순서와 포커스를 관리해야 합니다. 모달은 한 번에 하나만 띄우므로 이런 관리가 필요 없습니다.
뒤쪽 화면의 상태와 묶여 있음찾기 다이얼로그는 뒤쪽 문서의 내용을 계속 읽어 와야 합니다. 그래서 다이얼로그를 띄우면서 뒤쪽 화면의 상태 갱신을 멈추면 찾기 기능이 동작하지 않습니다.
무시할 수 있어 처리를 보장하지 않음비모달은 사용자가 응답하지 않고 지나칠 수 있기 때문에 반드시 처리돼야 하는 일은 비모달에 담지 않습니다.
