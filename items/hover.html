호버가 없는 세계

No hover

손가락에는 '올려놓기'가 없습니다. 호버로만 되는 일은 폰에서 영영 안 됩니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

왼쪽 넷은 마우스를 올려야 보이는 정보입니다. 손가락으로 쓰는 기기로 보기를 켜면 그 순간 영영 볼 수 없는 정보가 됩니다.
오른쪽 둘은 같은 정보를 처음부터 보이게 하거나 눌러서 보게 고친 것입니다 — 켜도 그대로 쓸 수 있습니다. 위에 이 기기의 실제 설정도 나옵니다.

2 이름부르는 말이 여러 개다

한국어호버, 마우스 올리기, 포인터 없는 기기
영어hover, pointer, hover-capable device
같이 쓰는 말CSS 로는 :hover이고, 기기를 가리는 질의가 @media (hover: hover)·(pointer: fine)입니다. 손가락으로 한 번 눌렀을 때 호버만 걸리고 클릭이 안 되는 현상을 더블 탭 문제라 부릅니다. 손가락이 닿기 전에 미리 알 수 없다는 뜻으로 호버 없는 입력이라고도 합니다.
자주 잘못 부름마우스 오버 — 옛 이벤트 이름(onmouseover)이고 지금은 포인터 이벤트로 묶여 있습니다.
툴팁 — 툴팁은 호버로 띄우는 한 부품이고, 이쪽은 그 전제에 대한 이야기입니다.
모바일 대응 — 폭의 문제가 아닙니다. 입력 방식의 문제라 큰 태블릿에서도 똑같습니다.

3 가르는 기준형제들과 비교하는 네 축

PC와 폰은 다른 기계가 아니라 다른 전제입니다. 이 네 가지만 물어보면 갈립니다.

무엇이 다른가폰에서는PC에서는안 챙기면
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 깨진다
터치 타깃누를 수 있는 넓이44px 이상24px도 된다옆 것이 눌린다
호버가 없는 세계올려놓기가 되나없다있다영영 못 보는 정보가 생긴다
시스템 백뒤로 가는 길OS가 준다브라우저 버튼모달 대신 앱이 나간다
화면 밀도1px 의 실제 화소 수2~3배1~2배그림이 뭉갠다
뷰포트 단위100vh 가 가리키는 높이주소창 때문에 흔들린다고정바닥 버튼이 잘린다
폰 키보드올라오는 자리화면 절반없다입력칸이 가려진다
HIG와 Material의 차이OS 의 말투각자 다르다웹 관례어느 쪽에서도 어색하다

한 줄로 — 호버는 덤이어야 합니다. 호버로 되는 일은 반드시 눌러서도 되어야 하고, 그러면 키보드 사용자도 같이 구제됩니다.

4 호버가 없으면무엇이 사라지나

5 해부도부분 이름이 제일 안 알려진 지식

@media (hover: hover) — 올려놓기가 되는 기기
(pointer: fine) — 마우스처럼 뾰족한 포인터
(pointer: coarse) — 손가락
모란상회✕
호버는 덤 — 호버로만 되는 일을 두지 않는다
:hover 만 쓰면 키보드 사용자도 같은 처지가 된다
  1. 기기를 묻는 질의 @media (hover: hover)올려놓기가 되는 기기에만 호버 규칙을 준다
  2. 뾰족한 포인터 (pointer: fine)마우스·펜. 작은 것도 정확히 누른다
  3. 뭉툭한 포인터 (pointer: coarse)손가락. 터치 타깃을 키워야 한다
  4. 늘 보이는 길 버튼·메뉴호버로 되는 일은 눌러서도 되게 둔다
  5. 호버는 덤 progressive없어도 쓸 수 있고, 있으면 조금 더 편한 것
  6. 키보드도 같은 처지 :focus-visible:hover만 쓰면 Tab 으로 온 사람도 못 본다

기기는 한 가지가 아닙니다. 노트북에 터치스크린이 달려 있고, 아이패드에 마우스를 붙이고, 폰을 모니터에 연결해 씁니다. 그래서 (hover: hover)가 참이어도 손가락으로 만질 수 있고, 거짓이어도 키보드로 다닐 수 있습니다. '폰이냐 PC냐'로 갈라 두면 그 중간이 전부 깨집니다 — 호버는 덤으로 두고 나머지는 모두에게 주는 쪽이 결국 더 적게 일합니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 호버를 미리보기·강조로 쓰기 — 없어도 되는 것
  • @media (hover: hover) 안에만 호버 규칙 두기
  • 같은 일을 버튼이나 메뉴로도 할 수 있게

이럴 때는 안 쓴다

  • 호버에만 있는 동작 — 삭제·편집·하위 메뉴
  • 호버에만 있는 정보 — 가격, 아이콘 뜻, 전체 글
  • :hover만 쓰고 :focus-visible을 빼먹기
  • 폭으로 가르기 — 큰 태블릿도 손가락이다

대신 이걸 — 설명이면 눌러서 펼치는 팝오버, 동작이면 ⋯ 메뉴나 줄 안의 버튼, 미리보기면 없어도 되게.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 전제의 계약서

호버 규칙은 되는 기기에만 주고, 키보드를 같이 적습니다.

/* 늘 되는 길 — 모두에게 준다 */
.row .del { opacity: 1; }

/* 덤 — 올려놓기가 되는 기기에서만 숨겼다 보여 준다 */
@media (hover: hover) and (pointer: fine) {
  .row .del { opacity: 0; transition: opacity 120ms; }
  .row:hover .del,
  .row:focus-within .del { opacity: 1; }   /* 키보드도 같이 */
}

// 자바스크립트에서 물어볼 때
if (matchMedia('(hover: none)').matches) showActionsAlways();
키일어나야 하는 일
:focus-within을 짝으로:hover를 쓸 때마다 함께 적는다. 한 줄로 키보드가 구제된다
@media (hover: hover)손가락 기기는 이 블록을 아예 안 읽는다. 숨기는 코드가 안 들어간다
(pointer: fine)과 함께펜·마우스. 둘을 같이 걸면 터치 노트북에서 덜 어긋난다
:hover가 손가락에서 남는다한 번 누른 뒤 호버 상태가 그대로 붙어 있을 수 있다. 질의로 가두면 안 생긴다
title 속성호버로만 뜨고 손가락에서는 안 보인다. 설명을 title 에만 두지 않는다
툴팁호버와 초점 둘 다로 떠야 한다. 초점으로 안 뜨면 키보드에서 없는 것과 같다

9 서버 쪽으로 치면백엔드 감각으로 번역

미리 받아 두는 것호버할 때 미리 데이터를 받는 방식은 손가락 기기에서 아무 효과가 없습니다. 그쪽에는 다른 전략이 필요합니다.
쓰임이 다르게 찍힌다같은 기능이 폰에서만 거의 안 쓰인다면 호버에 숨어 있어서일 수 있습니다. 숫자만 보고 '안 쓰는 기능'으로 지우면 틀립니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

오버플로 메뉴(⋮)가 관례입니다. 숨길 동작은 거기 모읍니다.

자주 생기는 사고 — "줄에 올리면 삭제 버튼이 나오게"는 PC 시안에서 가장 깔끔해 보이는 안이고, 폰에서 기능이 통째로 사라지는 안이기도 합니다. 받을 때 "폰에서는 어떻게 지웁니까"를 한 번 물어보면, 대개 ⋯ 메뉴나 쓸어넘기기로 정리됩니다.
