호버가 없는 세계

No hover

손가락으로 쓰는 화면에는 마우스처럼 '올려놓기'가 없습니다. 그래서 호버로만 할 수 있게 만든 일은 폰에서는 할 방법이 없습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

왼쪽 넷은 마우스를 올려야 보이는 정보입니다. 손가락으로 쓰는 기기로 보기를 켜면 이 정보는 볼 방법이 없는 정보가 됩니다.
오른쪽 둘은 같은 정보를 처음부터 보이게 하거나 눌러서 보게 고친 것이라서, 켜도 그대로 쓸 수 있습니다. 위쪽에는 지금 보는 기기의 실제 설정도 나옵니다.

2 이름같은 것을 부르는 여러 이름

한국어호버, 마우스 올리기, 포인터 없는 기기
영어hover, pointer, hover-capable device
같이 쓰는 말CSS에서는 :hover로 적고, 호버가 되는 기기인지 묻는 미디어 쿼리는 @media (hover: hover)와 (pointer: fine)입니다. 손가락으로 한 번 눌렀을 때 호버 상태만 걸리고 클릭은 되지 않는 현상을 더블 탭 문제라고 부릅니다. 손가락이 화면에 닿기 전에는 어디를 가리키는지 미리 알 수 없다는 뜻으로 호버 없는 입력이라고도 합니다.
자주 잘못 부르는 이름마우스 오버 — 옛 이벤트 이름(onmouseover)에서 온 말이고, 지금은 마우스·펜·손가락 입력이 포인터 이벤트로 묶여 있습니다.
툴팁 — 툴팁은 호버로 띄우는 부품 하나이고, 이 항목은 호버라는 전제 자체를 다룹니다.
모바일 대응 — 호버가 없는 것은 화면 폭이 아니라 입력 방식의 문제라서, 화면이 큰 태블릿에서도 똑같이 일어납니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

PC와 폰은 기계보다 쓰는 전제가 다릅니다. 아래 네 가지로 두 환경을 견줍니다.

두 환경에서 다른 점폰에서는PC에서는챙기지 않으면 생기는 일
브레이크포인트폭에 따른 배치한 단여러 단중간 폭에서 배치가 깨짐
터치 타깃누를 수 있는 넓이44px 이상24px도 괜찮음옆의 것이 눌림
호버가 없는 세계올려놓기가 되는지안 됨됨끝내 볼 수 없는 정보가 생김
시스템 백뒤로 가는 길OS가 제공함브라우저의 ← 버튼모달 대신 앱이 꺼짐
화면 밀도1px의 실제 화소 수2~3배1~2배그림이 뭉개짐
뷰포트 단위100vh가 가리키는 높이주소창 때문에 달라짐하나로 정해짐바닥 버튼이 잘림
폰 키보드키보드가 올라와 덮는 자리화면의 절반덮지 않음입력칸이 가려짐
HIG와 Material의 차이OS마다 다른 관례OS마다 다름웹 관례를 따름어느 쪽에서도 어색함

호버가 없는 세계를 한 줄로 정리하면 — 호버는 없어도 되는 부가 기능으로 두어야 합니다. 호버로 되는 일은 반드시 눌러서도 할 수 있어야 하고, 그렇게 만들면 키보드 사용자도 같은 기능을 쓸 수 있게 됩니다.

4 호버가 없을 때 달라지는 것사라지는 것과 고친 모습

5 해부도부분마다 붙은 이름

@media (hover: hover)는 올려놓기가 되는 기기
(pointer: fine)은 마우스처럼 뾰족한 포인터
(pointer: coarse)는 손가락 입력
모란상회✕
호버는 부가 기능이라 호버로만 되는 일은 없앰
:hover만 쓰면 키보드 사용자도 볼 수 없음
  1. 기기를 묻는 질의 @media (hover: hover)올려놓기가 되는 기기에만 호버 규칙을 적용합니다
  2. 뾰족한 포인터 (pointer: fine)마우스나 펜처럼 작은 것도 정확히 누를 수 있는 입력입니다
  3. 뭉툭한 포인터 (pointer: coarse)손가락 입력입니다. 터치 타깃을 키워야 합니다
  4. 늘 보이는 버튼 버튼·메뉴호버로 되는 일은 눌러서도 할 수 있게 둡니다
  5. 호버는 부가 기능 progressive호버가 없어도 쓸 수 있고, 있으면 조금 더 편해지는 정도로 둡니다
  6. 키보드 포커스 :focus-visible:hover만 쓰면 Tab으로 포커스를 옮긴 사용자도 볼 수 없습니다

실제 기기에는 입력 방식이 섞여 있습니다. 터치스크린이 달린 노트북도 있고, 아이패드에 마우스를 붙이거나 폰을 모니터에 연결해 쓰기도 합니다. 그래서 (hover: hover)가 참이어도 사용자가 손가락으로 화면을 만질 수 있고, 거짓이어도 키보드로 화면을 옮겨 다닐 수 있습니다. '폰이냐 PC냐'로만 갈라 두면 이렇게 섞인 기기에서 화면이 깨지기 때문에, 호버는 부가 기능으로 두고 나머지 기능은 모든 기기에 똑같이 주는 편이 결국 손이 덜 갑니다.

6 쓸 때 / 안 쓸 때

호버를 써도 되는 경우

  • 호버를 미리보기나 강조처럼 없어도 되는 효과에 쓸 때
  • 호버 규칙을 @media (hover: hover) 안에만 둘 때
  • 호버로 하는 일을 버튼이나 메뉴로도 할 수 있게 해 둘 때

호버에 기대면 안 되는 경우

  • 삭제, 편집, 하위 메뉴 같은 동작을 호버에만 둘 때
  • 가격, 아이콘의 뜻, 잘린 글의 전체 같은 정보를 호버에만 둘 때
  • :hover만 쓰고 :focus-visible을 빼먹을 때
  • 화면 폭으로 호버 여부를 가를 때. 화면이 큰 태블릿도 손가락으로 씁니다

호버 대신 쓸 수 있는 방법 — 설명을 보여 줘야 하면 눌러서 펼치는 팝오버를 쓰고, 동작이라면 ⋯ 메뉴나 줄 안의 버튼으로 꺼내 둡니다. 미리보기는 없어도 쓰는 데 지장이 없게 만듭니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 지킬 규칙빠뜨리기 쉬운 설정까지 담은 규칙

호버 규칙은 호버가 되는 기기에만 적용하고, 키보드 포커스 규칙을 함께 적습니다.

/* 늘 보이는 길은 모든 기기에 준다 */
.row .del { opacity: 1; }

/* 올려놓기가 되는 기기에서만 숨겼다가 보여 준다 */
@media (hover: hover) and (pointer: fine) {
  .row .del { opacity: 0; transition: opacity 120ms; }
  .row:hover .del,
  .row:focus-within .del { opacity: 1; }   /* 키보드도 같이 */
}

// 자바스크립트에서 물어볼 때
if (matchMedia('(hover: none)').matches) showActionsAlways();
지킬 규칙지키는 방법과 까닭
:focus-within을 짝으로 적기:hover를 쓸 때마다 함께 적습니다. 이 한 줄로 키보드 사용자도 같은 것을 볼 수 있습니다
@media (hover: hover) 안에 두기손가락으로 쓰는 기기는 이 블록을 적용하지 않으므로 숨기는 규칙이 아예 걸리지 않습니다
(pointer: fine)과 함께 걸기펜이나 마우스를 가리킵니다. 두 조건을 같이 걸면 터치 노트북에서 덜 어긋납니다
손가락으로 누른 뒤 남는 :hover손가락으로 한 번 누른 뒤 호버 상태가 풀리지 않고 남아 있을 수 있습니다. 호버 규칙을 미디어 쿼리 안에 두면 이 문제가 생기지 않습니다
title 속성으로 띄운 설명호버로만 뜨기 때문에 손가락으로 쓰는 기기에서는 보이지 않습니다. 설명을 title에만 두지 않습니다
툴팁을 띄우는 조건호버와 포커스 양쪽에서 떠야 합니다. 포커스로 뜨지 않으면 키보드 사용자는 툴팁을 볼 수 없습니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

호버할 때 데이터를 미리 받아 두기마우스를 올렸을 때 다음 화면의 데이터를 미리 받아 두는 방식은 손가락으로 쓰는 기기에서 아무 효과가 없습니다. 이런 기기를 위해서는 다른 시점에 미리 받는 방법이 필요합니다.
폰에서만 사용량이 낮게 나올 때같은 기능이 폰에서만 거의 쓰이지 않는다면, 그 기능이 호버로만 보이게 숨어 있어서일 수 있습니다. 사용량 숫자만 보고 '안 쓰는 기능'으로 판단해 지우면 잘못된 결정이 됩니다.

10 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

호버가 없는 것은 기기가 아니라 입력 방식의 문제라서, 세 플랫폼 모두 사정이 같습니다.

웹hover · pointer 질의
모란상회✕
브라우저가 hover·pointer 미디어 쿼리로 입력 방식을 물어볼 방법을 줍니다. 다만 입력 방식이 섞인 기기가 많아서 참과 거짓이 늘 명확하지는 않습니다.
iOS호버가 없는 환경
길게 눌러 열기
숨겨 둔 동작은 길게 누르기나 쓸어넘기기로 꺼냅니다. 아이패드에 마우스를 연결하면 호버도 쓸 수 있습니다.
안드로이드호버가 없는 환경
⋮
숨길 동작은 오버플로 메뉴(⋮)에 모으는 것이 관례입니다.

플랫폼 차이 때문에 자주 생기는 문제 — "줄에 마우스를 올리면 삭제 버튼이 나오게" 해 달라는 안은 PC 시안에서는 깔끔해 보이지만, 폰에서는 삭제 기능이 통째로 사라집니다. 이런 요청을 받으면 "폰에서는 어떻게 지웁니까"를 한 번 물어보세요. 대개 ⋯ 메뉴나 쓸어넘기기로 정리됩니다.
