타입 스케일

Type scale · typographic scale

글자 크기를 비율로 쌓아 만든 사다리. 17·19·23을 그때그때 고르지 않고, 정해 둔 단 중에서 고릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

비율을 바꾸면 모든 단이 같이 움직입니다 — 기준 16px 에 비율을 거듭 곱한 값이기 때문입니다. 규칙 없이를 켜면 17·19·23처럼 손으로 고른 값이 됩니다. 각각은 멀쩡한데 나란히 놓으면 어느 쪽이 더 중요한지가 안 읽힙니다.

2 이름부르는 말이 여러 개다

한국어타입 스케일, 글자 크기 체계, 폰트 스케일
영어type scale, typographic scale, modular scale
같이 쓰는 말곱하는 값을 비율(ratio · 1.125·1.25·1.333), 기준이 되는 크기를 기준 크기(base) 라고 합니다. 단 하나를 스텝(step) 또는 타입 토큰이라 하고, 크기·행간·굵기를 묶은 것을 텍스트 스타일(text style · type style)이라 합니다.
자주 잘못 부름폰트 크기 — 크기 하나만 가리키는 말입니다. 스케일은 단들 사이의 관계입니다.
헤딩 레벨 — h1~h6은 문서의 구조이고 크기와는 별개입니다. h2를 작게 쓰는 화면도 정상입니다.
모듈러 스케일 — 같은 뜻으로 쓰이지만, 엄밀히는 비율을 거듭 곱해 만든 것만 가리킵니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다

한 줄로 — 타입 스케일은 크기 목록이 아니라 비율입니다. 두 단을 나란히 놓았을 때 차이가 늘 같은 몫이면 스케일이고, 들쭉날쭉하면 그냥 값 모음입니다.

  1. 크기 font-size사다리에서 고른 단. 이것 하나만 토큰이 아니다
  2. 행간 line-height줄 사이. 큰 글자는 좁게(1.2), 본문은 넓게(1.6~1.8). 한국어는 영문보다 더 넓게 본다
  3. 자간 letter-spacing글자 사이. 큰 제목은 좁히고(-0.02em), 작은 대문자 라벨은 넓힌다
  4. 굵기 font-weight400·500·700 세 단이면 보통 충분하다. 굵기로 주는 강조가 크기보다 조용하다
  5. 숫자 꼴 tabular-nums금액을 세로로 쌓을 때 자릿수가 맞게. 표에서 거의 필수인데 가장 안 알려져 있다

타입 토큰은 크기 하나가 아니라 다섯 개의 묶음입니다. 크기만 바꾸고 행간을 그대로 두면 제목이 답답해지고 본문이 흩어집니다. 그래서 디자인 시스템은 text-lg 한 이름 안에 크기와 행간을 함께 담아 둡니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 제목·본문·보조 글의 위계를 눈으로 알게 하고 싶을 때
  • 여러 사람이 화면을 만들 때 — 매번 고르지 않아도 됩니다
  • 글이 많은 화면 — 문서, 기사, 설명

이럴 때는 안 쓴다

  • 단을 열 개 넘게 두는 것 — 고를 수 없게 되고 결국 아무 값이나 쓰게 됩니다
  • 비율을 크게(1.5 이상) 잡고 단을 많이 두는 것 — 가운데가 비어 쓸 단이 없어집니다
  • 본문 크기를 14px 아래로 — 한국어는 획이 많아 같은 크기라도 더 작게 보입니다
  • 크기만으로 모든 위계를 주는 것 — 굵기와 색이 더 조용하고 잘 듣습니다

대신 이걸 — 줄 간격과 묶음 간격은 간격 체계가 맡고, 글자색의 위계는 색 토큰이 맡습니다.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 사다리의 계약서

단마다 크기와 행간을 한 묶음으로 둡니다. 크기만 토큰으로 두면 쓰는 쪽에서 행간을 매번 다시 고르게 됩니다.

:root {
  /* 16px 에 1.25 를 거듭 곱한다 */
  --text-sm: 12.8px;   --lh-sm: 1.7;
  --text-base: 16px;   --lh-base: 1.65;
  --text-lg: 20px;     --lh-lg: 1.4;
  --text-xl: 25px;     --lh-xl: 1.25;
}

.card-title {
  font-size: var(--text-lg);
  line-height: var(--lh-lg);
  word-break: keep-all;   /* 한국어는 어절로 끊는다 */
}

/* 폰에서 본문이 16px 아래면 입력 중 화면이 확대된다 */
input, select, textarea { font-size: 16px; }
규칙지켜야 하는 것
기준과 비율을 먼저기준 16px, 비율 1.2~1.333 사이. 두 수만 정하면 나머지는 계산이다
크기와 행간을 함께--text-lg 하나를 쓰면 행간도 따라오게 묶어 둔다
단은 6~8개열 개가 넘으면 고를 수 없고, 넷 이하면 위계가 모자란다
한국어는 한 단 크게같은 px 이라도 한글은 획이 많아 작아 보인다. 영문 기준 시안을 그대로 쓰면 빽빽해진다
rem으로 적는다사용자가 브라우저 글자 크기를 키웠을 때 같이 커진다. px로 박으면 안 커진다
입력창은 16px 이상iOS 사파리는 그보다 작으면 입력할 때 화면을 확대한다

9 서버 쪽으로 치면백엔드 감각으로 번역

스케일 = 상수 테이블매직 넘버를 상수로 뽑은 것과 같습니다. 다른 점은 값들 사이에 계산식이 있다는 것이라, 기준 하나를 바꾸면 전부 따라 움직입니다.
글자 길이는 데이터가 정한다'상품명'이 12자일 때와 60자일 때 화면이 다릅니다. 가장 긴 값으로 한 번 그려 보지 않으면 제목 칸이 터집니다.
다국어같은 문장이 독일어에서 1.3배, 한국어에서 0.8배가 됩니다. 크기를 줄여 맞추지 말고 줄바꿈과 말줄임을 준비합니다.
폰트 파일굵기 하나가 파일 하나입니다. 400·700만 쓰면 두 벌, 거기에 500을 더하면 세 벌을 더 받습니다 — 굵기를 늘리는 것은 공짜가 아닙니다.
