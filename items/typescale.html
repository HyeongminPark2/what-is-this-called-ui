타입 스케일

Type scale · typographic scale

타입 스케일은 기준 글자 크기에 일정한 비율을 거듭 곱해 만든 크기 단계입니다. 글자 크기가 필요할 때마다 17, 19, 23처럼 그때그때 고르지 않고, 미리 정해 둔 단 가운데서 고릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

비율을 바꾸면 모든 단이 함께 바뀝니다. 각 단이 기준 16px에 비율을 거듭 곱한 값이기 때문입니다. 규칙 없이를 켜면 17, 19, 23처럼 손으로 고른 값으로 바뀌는데, 값 하나하나는 문제가 없어도 나란히 놓으면 단 사이의 차이가 들쭉날쭉해서 어느 쪽이 더 중요한지 알아보기 어렵습니다.

2 이름같은 것을 부르는 여러 이름

한국어타입 스케일, 글자 크기 체계, 폰트 스케일
영어type scale, typographic scale, modular scale
같이 쓰는 말거듭 곱하는 값은 비율(ratio · 1.125·1.25·1.333), 출발점이 되는 크기는 기준 크기(base)라고 합니다. 단 하나하나는 스텝(step) 또는 타입 토큰이라 부르고, 크기와 행간, 굵기를 한데 묶은 것은 텍스트 스타일(text style · type style)이라고 부릅니다.
자주 잘못 부르는 이름폰트 크기 — 폰트 크기는 글자 크기 값 하나를 가리키는 말이고, 스케일은 단과 단 사이의 관계까지 정한 것입니다.
헤딩 레벨 — h1~h6은 문서의 구조를 나타낼 뿐 글자 크기와는 별개입니다. 그래서 h2를 작은 글자로 보여 주는 화면도 잘못된 것이 아닙니다.
모듈러 스케일 — 타입 스케일과 같은 뜻으로 쓰이기도 하지만, 엄밀히는 비율을 거듭 곱해 만든 스케일만 가리킵니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하는가몇 단으로 두면 좋은가값을 바꾸면 어디가 바뀌는가잘못 정했을 때 나타나는 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌, 고대비까지 두면 3벌화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지, 색마다 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

타입 스케일을 한 줄로 정리하면 — 타입 스케일의 핵심은 크기 목록이 아니라 비율입니다. 이웃한 두 단을 나란히 놓았을 때 큰 쪽이 늘 작은 쪽의 같은 배수라면 스케일이고, 배수가 들쭉날쭉하면 스케일이 아니라 크기 값을 모아 둔 목록입니다.

  1. 크기 font-size스케일에서 고른 단입니다. 다만 크기 하나만으로 타입 토큰이 되지는 않습니다
  2. 행간 line-height줄과 줄 사이의 간격입니다. 큰 글자는 좁게(1.2), 본문은 넓게(1.6~1.8) 두고, 한국어는 영문보다 더 넓게 잡습니다
  3. 자간 letter-spacing글자와 글자 사이의 간격입니다. 큰 제목은 좁히고(-0.02em), 작은 대문자 라벨은 넓힙니다
  4. 굵기 font-weight보통 400·500·700 세 단이면 충분합니다. 굵기로 주는 강조는 크기를 키우는 것보다 덜 두드러집니다
  5. 숫자 꼴 tabular-nums금액을 세로로 늘어놓을 때 자릿수가 맞도록 숫자 폭을 고르게 합니다. 표에서는 거의 필수인데도 잘 알려져 있지 않습니다

타입 토큰은 크기 하나가 아니라 위의 다섯 가지 값을 한데 묶은 것입니다. 크기만 바꾸고 행간을 그대로 두면 제목은 답답해 보이고 본문은 줄이 흩어져 보입니다. 그래서 디자인 시스템은 text-lg 같은 이름 하나에 크기와 행간을 함께 담아 둡니다.

6 쓸 때 / 안 쓸 때

타입 스케일을 쓰는 경우

  • 제목과 본문, 보조 글의 위계가 눈으로 바로 드러나게 하고 싶을 때
  • 여러 사람이 화면을 만들 때. 정해 둔 단에서 고르면 되므로 사람마다 크기를 따로 정하지 않아도 됩니다
  • 문서나 기사, 설명처럼 글이 많은 화면일 때

타입 스케일을 쓰지 않는 경우

  • 단을 열 개 넘게 둘 때. 어느 단을 골라야 할지 정할 수 없어서 결국 아무 값이나 쓰게 됩니다
  • 비율을 1.5 이상으로 크게 잡고 단을 많이 둘 때. 이웃한 단의 차이가 너무 커서 자주 쓰는 중간 크기에 맞는 단이 없어집니다
  • 본문 크기를 14px보다 작게 잡을 때. 한국어는 획이 많아서 같은 크기라도 더 작게 보입니다
  • 크기만으로 모든 위계를 나타낼 때. 굵기와 색으로 위계를 주면 크기를 키우는 것보다 덜 요란하면서도 차이가 잘 드러납니다

타입 스케일과 함께 정하는 규칙 — 글줄과 글줄 묶음 사이의 간격은 간격 체계에서 정하고, 글자색으로 주는 위계는 색 토큰에서 정합니다.

8 최소 코드와 지킬 규칙스케일을 코드로 옮기는 방법

단마다 크기와 행간을 한 묶음으로 둡니다. 크기만 토큰으로 두면 쓰는 쪽에서 행간을 매번 다시 고르게 됩니다.

:root {
  /* 16px 에 1.25 를 거듭 곱한다 */
  --text-sm: 12.8px;   --lh-sm: 1.7;
  --text-base: 16px;   --lh-base: 1.65;
  --text-lg: 20px;     --lh-lg: 1.4;
  --text-xl: 25px;     --lh-xl: 1.25;
}

.card-title {
  font-size: var(--text-lg);
  line-height: var(--lh-lg);
  word-break: keep-all;   /* 한국어는 어절로 끊는다 */
}

/* 폰에서 본문이 16px 아래면 입력 중 화면이 확대된다 */
input, select, textarea { font-size: 16px; }
지킬 규칙지키는 방법과 이유
기준 크기와 비율부터 정하기기준은 16px, 비율은 1.2~1.333 사이에서 고릅니다. 이 두 수만 정하면 나머지 단은 계산으로 나옵니다
크기와 행간을 한 토큰으로 묶기--text-lg 하나만 쓰면 행간도 함께 적용되도록 묶어 둡니다
단은 6~8개로 두기열 개가 넘으면 어느 단을 써야 할지 고르기 어렵고, 넷 이하이면 위계를 나타내기에 단이 모자랍니다
한국어는 한 단 크게 잡기같은 px이라도 한글은 획이 많아 작아 보이기 때문에, 영문 기준으로 만든 시안을 그대로 쓰면 글자가 빽빽해 보입니다
rem 단위로 적기rem으로 적으면 사용자가 브라우저 글자 크기를 키웠을 때 함께 커지지만, px로 적으면 커지지 않습니다
입력창 글자는 16px 이상으로 두기iOS 사파리는 입력창 글자가 16px보다 작으면 입력할 때 화면을 확대합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

상수 테이블과 같은 역할코드의 매직 넘버를 상수로 뽑아 두는 것과 같은 일입니다. 다만 타입 스케일은 값들 사이에 계산식이 있어서, 기준 크기 하나를 바꾸면 모든 단이 함께 바뀝니다.
데이터에 따라 달라지는 글자 길이같은 '상품명' 칸이라도 12자일 때와 60자일 때 화면이 달라집니다. 그래서 들어올 수 있는 가장 긴 값으로 한 번 그려 보지 않으면 제목 칸이 넘쳐 레이아웃이 깨집니다.
언어마다 달라지는 글자 길이같은 문장이라도 언어에 따라 길이가 달라서 독일어에서는 1.3배, 한국어에서는 0.8배가 됩니다. 길어진 글을 글자 크기를 줄여 맞추지 말고 줄바꿈과 말줄임을 준비해 둡니다.
굵기마다 늘어나는 폰트 파일웹 폰트는 굵기 하나가 파일 하나입니다. 400과 700만 쓰면 파일 두 벌을 받고, 거기에 500을 더하면 세 벌을 받아야 합니다. 이처럼 굵기를 하나 늘릴 때마다 내려받을 파일도 늘어납니다.

플랫폼 차이 때문에 자주 생기는 문제 — iOS와 안드로이드 모두 사용자가 시스템 글자 크기를 키울 수 있습니다. 이 설정을 무시하고 글자 크기를 px로 고정해 두면 접근성 심사에서 걸리고, 실제로 글자를 키워 쓰는 사람에게는 앱 화면이 깨진 것처럼 보입니다. 그래서 시안에 "16px"이라고만 적혀 있다면, 그 값이 기본 설정일 때의 크기라는 뜻인지 확인하세요.
