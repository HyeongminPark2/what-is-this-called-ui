팝오버

Popover · Flyout

누른 것 옆에 붙어서 뜨는 작은 판. 뒤를 막지 않고, 안에 누를 것이 들어 있습니다 — 이 점이 툴팁과 다릅니다.

열어 둔 채로 아래 목록을 읽어 보세요. 뒤가 안 막힙니다. 오른쪽 끝 '내 계정'은 화면 밖으로 나가지 않으려고 반대쪽으로 뒤집혀 열립니다 — 이걸 플립이라 부르고, 팝오버를 직접 만들 때 가장 자주 빠뜨리는 부분입니다.

2 이름부르는 말이 여러 개다

한국어팝오버, 팝업 메뉴, 플라이아웃
영어popover, flyout
같이 쓰는 말안에 든 것이 메뉴 항목뿐이면 드롭다운 메뉴라 따로 부릅니다. 폼이나 설정이 들어가면 팝오버입니다. 붙는 기준이 되는 요소는 앵커(anchor).
자주 잘못 부름툴팁 — 설명만 하면 툴팁, 누를 것이 있으면 팝오버입니다. 가장 흔한 혼동입니다.
모달 — 팝오버는 뒤를 안 막습니다.
팝업 — 브라우저가 띄우는 새 창과 섞입니다.

적용
  1. 앵커 · 트리거 anchor · trigger팝오버가 붙는 기준. 열려 있는 동안 눌린 상태로 보여 준다
  2. 오프셋 offset앵커와 판 사이의 빈 자리. 보통 8~12px
  3. 꼬리 tail · arrow · caret어디서 나온 것인지 가리킨다. 없는 디자인도 많다
  4. 패널 panel · surface모달보다 그림자를 약하게 준다. 덜 떠 있어야 한다
  5. 헤더 header짧게. 길면 팝오버에 담을 내용이 아니다
  6. 내용 content한눈에 들어오는 분량만. 스크롤이 생기면 다시 생각할 때다
  7. 액션 영역 footer적용·초기화. 바로 반영되는 설계면 아예 없어도 된다

여기 안 보이는 두 가지가 더 있습니다 — 플립(화면 밖으로 나갈 것 같으면 반대쪽으로 뒤집기)과 시프트(꼬리는 둔 채 판만 안으로 밀기). 둘 다 자리 계산 규칙이라 그림에 테두리가 없습니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 추가 설정·필터 — 화면을 떠나지 않고 조건만 바꿀 때
  • 한두 칸짜리 빠른 편집
  • 보조 정보 더 보기 — 사용자 카드, 미리보기

이럴 때는 안 쓴다

  • 꼭 답해야 하는 것 → 모달. 팝오버는 바깥을 누르면 사라집니다
  • 긴 폼이나 여러 단계 → 페이지나 드로어
  • 모바일에서 손가락으로 쓰기 어려운 크기 → 바텀시트로 바꿉니다
  • 팝오버 안에서 또 팝오버 — 바깥 클릭 처리가 바로 엉킵니다

대신 이걸 — 꼭 답을 받아야 하면 모달, 설명만이면 툴팁, 폰에서는 바텀시트, 긴 작업이면 드로어.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

스크림이 없으니 바깥 클릭과 Esc를 직접 처리해야 합니다. 모달이 공짜로 주던 것을 여기서는 손으로 만듭니다.

<button aria-expanded="false" aria-controls="p1">필터 ▾</button>
<div id="p1" role="dialog" aria-label="필터" hidden>…</div>

// 바깥을 누르면 닫는다 — 스크림이 없으니 직접
pop.addEventListener('click', e => e.stopPropagation());
document.addEventListener('click', closeAll);

// Esc 로 닫고 포커스를 앵커로 돌려준다
document.addEventListener('keydown', e => {
  if (e.key === 'Escape') { close(); btn.focus(); }
});
키일어나야 하는 일
Esc닫히고 포커스가 앵커로 돌아간다
Tab팝오버 안을 지나 뒤쪽으로 이어진다. 메뉴형이면 가두고 화살표로 움직인다
바깥 누름닫힌다. 안쪽 클릭은 전파를 멈춰 안 닫히게 한다
열릴 때포커스가 첫 요소로. aria-expanded 가 true 가 된다
스크롤앵커가 화면 밖으로 나가면 같이 닫는다. 안 그러면 허공에 뜬다

9 서버 쪽으로 치면백엔드 감각으로 번역

열 때 가져오기팝오버 내용은 열기 전에는 필요 없습니다. 지연 로드하면 첫 화면이 가벼워집니다. 열 때마다 또 부르지 않게 캐시를 둡니다.
바깥 클릭 = 전파 차단문서 전체에 걸린 닫기 처리와 안쪽 클릭이 부딪칩니다. stopPropagation 은 이벤트 버스에서 소비 표시를 하는 것과 같습니다.
플립·시프트 = 경계 검사'화면 밖으로 나가는가'를 매번 계산합니다. 범위를 벗어나면 되접는 clamp 와 같은 일입니다.
낙관적 적용체크를 바꾸자마자 목록을 걸러 보여 주고 서버 응답은 나중에 맞춰도 됩니다. 팝오버는 되돌리기 비용이 싸서 낙관적 처리가 잘 맞습니다.
