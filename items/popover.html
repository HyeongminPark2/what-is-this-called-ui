팝오버

Popover · Flyout

팝오버는 사용자가 누른 요소 옆에 붙어서 뜨는 작은 판입니다. 뒤쪽 화면을 막지 않으며, 툴팁과 달리 안에 누를 수 있는 것이 들어 있습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

팝오버를 열어 둔 채로 아래 목록을 읽어 보세요. 팝오버는 뒤쪽 화면을 막지 않습니다. 오른쪽 끝의 '내 계정'은 그대로 열면 화면 밖으로 나가기 때문에 반대쪽으로 뒤집혀 열립니다. 이 동작을 플립이라고 부르는데, 팝오버를 직접 만들 때 가장 자주 빠뜨리는 부분입니다.

2 이름같은 것을 부르는 여러 이름

한국어팝오버, 팝업 메뉴, 플라이아웃
영어popover, flyout
같이 쓰는 말안에 든 것이 메뉴 항목뿐이면 드롭다운 메뉴라고 따로 부르고, 폼이나 설정이 들어가면 팝오버라고 부릅니다. 팝오버가 붙는 기준 요소는 앵커(anchor)라고 합니다.
자주 잘못 부르는 이름툴팁 — 설명만 담으면 툴팁이고, 누를 것이 들어 있으면 툴팁이 아니라 팝오버입니다. 팝오버를 두고 가장 흔히 헷갈리는 이름입니다.
모달 — 모달은 뒤쪽 화면을 막지만 팝오버는 막지 않습니다.
팝업 — 브라우저가 새로 띄우는 팝업 창과 이름이 겹쳐서 헷갈립니다.

3 상태상태마다 달라지는 모습

4 해부도부분마다 붙은 이름

적용
  1. 앵커 · 트리거 anchor · trigger팝오버가 붙는 기준 요소입니다. 팝오버가 열려 있는 동안에는 눌린 상태로 보여 줍니다
  2. 오프셋 offset앵커와 판 사이의 빈 자리로, 보통 8~12px을 둡니다
  3. 꼬리 tail · arrow · caret팝오버가 어느 앵커에서 나왔는지 가리킵니다. 꼬리를 두지 않는 디자인도 많습니다
  4. 패널 panel · surface모달보다 화면에서 덜 떠 보이도록 그림자를 약하게 줍니다
  5. 헤더 header짧게 씁니다. 헤더가 길어질 만큼 내용이 많으면 팝오버에 담기에 너무 많은 것입니다
  6. 내용 content한눈에 들어오는 분량만 담습니다. 스크롤이 생기면 팝오버가 맞는 부품인지 다시 따져 봅니다
  7. 액션 영역 footer적용·초기화 버튼을 둡니다. 바꾸는 즉시 반영되도록 설계했다면 액션 영역을 아예 두지 않아도 됩니다

그림에는 보이지 않는 요소가 두 가지 더 있습니다. 화면 밖으로 나갈 것 같으면 반대쪽으로 뒤집어 여는 플립과, 꼬리는 그대로 둔 채 판만 화면 안쪽으로 옮기는 시프트입니다. 둘 다 팝오버를 놓을 자리를 계산하는 규칙이라 그림에 따로 표시할 테두리가 없습니다.

5 쓸 때 / 안 쓸 때

팝오버를 쓰는 경우

  • 추가 설정이나 필터처럼 화면을 떠나지 않고 조건만 바꿀 때
  • 입력 칸 한두 개로 끝나는 빠른 편집을 할 때
  • 사용자 카드나 미리보기처럼 보조 정보를 더 보여 줄 때

팝오버를 쓰지 않는 경우

  • 사용자가 꼭 답해야 할 때. 팝오버는 바깥을 누르면 사라지므로 모달을 씁니다
  • 폼이 길거나 단계가 여럿일 때. 페이지나 드로어를 씁니다
  • 모바일에서 손가락으로 누르기 어려울 만큼 작을 때. 바텀시트로 바꿉니다
  • 팝오버 안에서 팝오버를 또 열 때. 어느 팝오버의 바깥을 눌렀는지 가리는 처리가 금방 엉킵니다

팝오버 대신 다른 것을 써야 하는 경우 — 사용자의 답을 꼭 받아야 하면 모달을 쓰고, 누를 것 없이 설명만 보여 주면 되면 툴팁으로 충분합니다. 폰에서는 바텀시트로 바꾸고, 작업이 길면 드로어에 담습니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 마크업과 키보드구현할 때 지킬 최소 규칙

팝오버에는 스크림이 없기 때문에 바깥 클릭과 Esc를 직접 처리해야 합니다. 모달에서는 <dialog> 요소가 알아서 해 주던 일을 여기서는 코드로 직접 만듭니다.

<button aria-expanded="false" aria-controls="p1">필터 ▾</button>
<div id="p1" role="dialog" aria-label="필터" hidden>…</div>

// 바깥을 누르면 닫는다. 스크림이 없으니 직접 처리한다
pop.addEventListener('click', e => e.stopPropagation());
document.addEventListener('click', closeAll);

// Esc 로 닫고 포커스를 앵커로 돌려준다
document.addEventListener('keydown', e => {
  if (e.key === 'Escape') { close(); btn.focus(); }
});
키와 마크업그때 일어나야 하는 일
Esc팝오버가 닫히고 포커스가 앵커로 돌아갑니다
Tab포커스가 팝오버 안을 지나 뒤쪽 화면으로 이어집니다. 메뉴 항목만 든 팝오버라면 포커스를 안에 가두고 화살표 키로 옮깁니다
바깥을 눌렀을 때팝오버가 닫힙니다. 팝오버 안쪽을 누를 때는 이벤트 전파를 멈춰서 닫히지 않게 합니다
팝오버가 열릴 때포커스가 팝오버의 첫 요소로 옮겨 가고, 앵커의 aria-expanded 값이 true로 바뀝니다
화면을 스크롤할 때앵커가 화면 밖으로 나가면 팝오버도 함께 닫습니다. 닫지 않으면 팝오버만 가리킬 대상 없이 화면에 남습니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

열 때 내용 가져오기팝오버 내용은 팝오버를 열기 전에는 필요하지 않으므로, 열 때 가져오는 지연 로드를 쓰면 첫 화면이 가벼워집니다. 다만 열 때마다 서버를 다시 부르지 않도록 받아 온 내용은 캐시에 둡니다.
바깥 클릭 처리는 이벤트 전파 차단팝오버 안쪽을 눌러도 문서 전체에 걸어 둔 닫기 처리가 함께 실행되어 팝오버가 닫혀 버립니다. 그래서 안쪽 클릭에서 stopPropagation을 부르는데, 이벤트 버스에서 이벤트에 처리 완료 표시를 해서 더 퍼지지 않게 하는 것과 같습니다.
플립과 시프트는 경계 검사팝오버를 띄울 때마다 '화면 밖으로 나가는가'를 계산합니다. 값이 범위를 벗어나면 범위 안으로 되돌리는 clamp와 같은 일입니다.
바꾼 값을 먼저 반영하는 낙관적 적용체크를 바꾸자마자 목록을 걸러 보여 주고, 서버 응답은 나중에 받아 맞춰도 됩니다. 팝오버에서 바꾸는 필터 같은 값은 틀렸을 때 되돌리기 쉬워서 낙관적 처리가 잘 맞습니다.
