무한 스크롤

Infinite scroll

목록 끝에 닿으면 저절로 다음 묶음을 이어 붙이는 방식. 읽기만 하는 피드에는 편하지만, 돌아올 자리와 끝이 사라집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

끝까지 스크롤하면 저절로 더 불러옵니다. 대신 푸터에 닿을 수 없고 전부 몇 건인지도 알 수 없습니다 — 아래 숫자가 계속 늘어날 뿐입니다.
위의 체크를 켜면 더 보기 버튼으로 바뀝니다. 멈출 자리를 사용자가 정할 수 있어 푸터에 닿고 키보드로도 쓸 수 있습니다. 대부분의 경우 이쪽이 더 안전합니다.

2 이름부르는 말이 여러 개다

한국어무한 스크롤, 끝없는 스크롤, 자동 불러오기
영어infinite scroll, endless scroll, infinite loading
같이 쓰는 말끝을 감시하는 보이지 않는 표식을 센티널(sentinel), 사용자가 눌러 불러오는 꼴을 더 보기(load more), 끝에 닿았다는 표시를 끝 표시라 합니다.
자주 잘못 부름페이지네이션 — 쪽 번호가 있는 쪽입니다. 지금 어디인지와 전체를 알 수 있습니다.
가상 스크롤 — 가상 스크롤은 그리는 양을 줄이는 기법이고, 무한 스크롤은 불러오는 방식입니다. 같이 쓰기도 합니다.
지연 로딩 — 지연 로딩은 이미지처럼 개별 자원을 늦게 받는 것입니다.

3 가르는 기준형제들과 비교하는 네 축

길 안내 부품은 모두 '누르면 어디론가 간다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

자리데려가는 곳지금 위치감당하는 개수
앱바 · 헤더화면 위전역 · 상위제목으로해당 없음
사이드바 내비게이션화면 옆전역강조로10~20
바텀 탭바화면 아래전역아이콘 강조3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위로계층 전체3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록 이어서안 보여 준다제한 없음

한 줄로 — 무한 스크롤은 끝과 위치를 버리고 흐름을 얻습니다. 찾아서 돌아와야 하는 목록에는 맞지 않습니다.

4 상태그림 한 장으로는 못 배운다

5 해부도부분 이름이 제일 안 알려진 지식

… 앞서 불러온 48건
더 불러오는 중…
여기까지입니다
  1. 목록 list묶음이 계속 뒤에 붙는다. 앞의 것은 그대로 남는다
  2. 앞서 불러온 것 loaded items길어질수록 메모리와 그리는 양이 늘어난다 — 가상 스크롤과 묶어 쓰는 이유
  3. 센티널 sentinel보이지 않는 표식. 이게 화면에 들어오면 다음 묶음을 부른다
  4. 불러오는 표시 loading indicator목록 끝에만 둔다. 화면 전체를 덮지 않는다
  5. 안내 문구 status라이브 리전으로 '12건 더 불러왔습니다'를 알린다
  6. 끝 표시 end marker반드시 둔다. 끝났다는 말이 없으면 계속 기다린다

센티널을 목록 끝에서 조금 위에 두면(rootMargin) 사용자가 닿기 전에 미리 불러와 끊김이 없습니다. 너무 위에 두면 안 볼 것까지 받아 데이터만 축냅니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 둘러보는 피드 — 소셜, 사진, 추천
  • 순서가 시간순이고 돌아올 일이 적은 목록
  • 폰에서 손가락으로 계속 넘기는 화면

이럴 때는 안 쓴다

  • 찾아서 돌아와야 하는 목록 → 페이지네이션. 뒤로가면 자리가 사라집니다
  • 푸터에 중요한 것이 있을 때 — 영영 못 닿습니다
  • 전체가 몇 건인지 알아야 할 때
  • 표나 관리 도구 — 비교하고 건너뛰어야 하는 화면

대신 이걸 — 돌아와야 하면 페이지네이션, 멈출 자리를 주려면 더 보기 버튼, 그리는 양이 문제면 가상 스크롤(10부), 결과가 없으면 빈 상태.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 마크업과 키보드이 부품의 계약서

IntersectionObserver로 센티널을 지켜봅니다. 스크롤 이벤트를 세는 것보다 가볍고 정확합니다.

<ul id="list">…</ul>
<div id="sentinel"></div>
<p role="status" aria-live="polite">12건 더 불러왔습니다</p>

// 닿기 전에 미리 부른다 (rootMargin)
new IntersectionObserver(es => {
  if (es[0].isIntersecting) loadMore();
}, { rootMargin: '200px' }).observe(sentinel);

// 두 번 부르지 않게 잠근다 — 가장 흔한 버그
if (busy || done) return;

aria-live'12건 더 불러왔습니다'를 알린다. 안 알리면 화면이 바뀐 줄 모른다

9 서버 쪽으로 치면백엔드 감각으로 번역

커서가 거의 필수오프셋으로 이어 붙이면 그 사이 새 항목이 들어올 때 같은 항목이 두 번 보입니다. 커서(마지막 ID·시각)를 쓰면 그 문제가 없습니다.
중복 요청 잠금스크롤이 빠르면 센티널이 여러 번 걸립니다. busy 플래그가 없으면 같은 묶음을 서너 번 부릅니다 — 가장 흔한 버그입니다.
끝을 어떻게 아나응답에 hasMore를 담습니다. '받은 수 < 요청 수'로 추측하면 경계에서 틀립니다.
쌓이는 비용1,000건을 이어 붙이면 DOM 도 메모리도 그만큼 커집니다. 가상 스크롤로 보이는 만큼만 그리거나, 앞쪽을 버리는 창 방식을 씁니다.
돌아올 자리뒤로 왔을 때 보던 자리를 되살리려면 받아 둔 묶음과 스크롤 위치를 함께 저장해야 합니다. 페이지네이션이 주소 한 줄로 푸는 일을 여기서는 직접 해야 합니다.
