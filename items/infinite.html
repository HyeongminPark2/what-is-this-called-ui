무한 스크롤

Infinite scroll

무한 스크롤은 목록 끝에 닿으면 저절로 다음 묶음을 불러와 이어 붙이는 방식입니다. 읽기만 하는 피드에서는 편하지만, 보던 자리로 돌아오기 어렵고 목록이 어디서 끝나는지도 알 수 없습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

끝까지 스크롤하면 저절로 더 불러옵니다. 대신 푸터까지 내려갈 수 없고 전부 몇 건인지도 알 수 없어서, 아래에 보이는 숫자는 불러온 만큼 계속 늘어나기만 합니다.
위의 체크를 켜면 더 보기 버튼 방식으로 바뀝니다. 언제 더 불러올지를 사용자가 정하기 때문에 푸터까지 내려갈 수 있고 키보드로도 쓸 수 있습니다. 대부분의 경우 더 보기 버튼이 더 안전합니다.

2 이름같은 것을 부르는 여러 이름

한국어무한 스크롤, 끝없는 스크롤, 자동 불러오기
영어infinite scroll, endless scroll, infinite loading
같이 쓰는 말목록 끝에 두어 스크롤이 닿았는지 감지하는 보이지 않는 요소는 센티널(sentinel), 사용자가 버튼을 눌러 불러오는 형태는 더 보기(load more), 목록이 끝났다는 표시는 끝 표시라고 부릅니다.
자주 잘못 부르는 이름페이지네이션 — 페이지네이션은 쪽 번호가 있어서 지금 몇 쪽인지와 전체가 얼마인지를 알 수 있습니다.
가상 스크롤 — 가상 스크롤은 화면에 그리는 양을 줄이는 기법이고, 무한 스크롤은 데이터를 불러오는 방식입니다. 둘을 함께 쓰기도 합니다.
지연 로딩 — 지연 로딩은 이미지처럼 개별 자원을 필요할 때 늦게 받는 기법이고, 목록의 다음 묶음을 불러오는 무한 스크롤과는 다릅니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

겹쳐 뜨는 부품들은 모양만 보고는 구별하기 어렵지만, 아래 네 가지를 따져 보면 어느 부품인지 가려낼 수 있습니다.

화면에 놓이는 자리누르면 데려가는 곳지금 위치를 알리는 방법담을 수 있는 항목 수
앱바 · 헤더화면 위전역 또는 상위 화면제목으로해당 없음
사이드바 내비게이션화면 옆전역항목 강조로10~20
바텀 탭바화면 아래전역아이콘 강조로3~5
탭내용 위같은 화면 안밑줄로2~6
브레드크럼내용 위상위 단계계층 전체를 보여 줌3~5단계
페이지네이션목록 아래같은 목록의 다른 쪽쪽 번호로제한 없음
무한 스크롤목록 끝같은 목록의 다음 묶음보여 주지 않음제한 없음
스테퍼내용 위 · 옆같은 흐름의 다음 단계번호와 완료 표시로3~5단계

메가 메뉴앱바 아래전역, 여러 분류열린 분류로20~60

무한 스크롤을 한 줄로 정리하면 — 무한 스크롤을 쓰면 멈추지 않고 계속 내려 볼 수 있는 대신, 목록의 끝과 지금 위치를 알 수 없게 됩니다. 그래서 항목을 찾아서 다시 돌아와야 하는 목록에는 맞지 않습니다.

여기까지입니다
  1. 목록 list새 묶음이 계속 뒤에 붙고, 앞에 불러온 항목은 그대로 남습니다
  2. 앞서 불러온 것 loaded items목록이 길어질수록 메모리와 화면에 그리는 양이 늘어납니다. 그래서 가상 스크롤과 함께 쓰는 경우가 많습니다
  3. 센티널 sentinel목록 끝에 둔 보이지 않는 요소입니다. 센티널이 화면에 들어오면 다음 묶음을 요청합니다
  4. 불러오는 표시 loading indicator목록 끝에만 두고, 화면 전체를 덮지 않습니다
  5. 안내 문구 status라이브 리전으로 '12건 더 불러왔습니다'처럼 알립니다
  6. 끝 표시 end marker반드시 둡니다. 끝났다는 표시가 없으면 사용자는 더 나올 것을 계속 기다립니다

센티널을 목록 끝보다 조금 위에서 감지하게 하면(rootMargin) 사용자가 끝에 닿기 전에 다음 묶음을 미리 받아 두므로 스크롤이 멈추지 않고 이어집니다. 다만 너무 위에서 감지하게 하면 사용자가 보지도 않을 항목까지 받아서 데이터를 낭비합니다.

6 쓸 때 / 안 쓸 때

무한 스크롤을 쓰는 경우

  • 소셜, 사진, 추천처럼 훑어보는 피드일 때
  • 시간순으로 늘어놓았고 다시 돌아올 일이 적은 목록일 때
  • 폰에서 손가락으로 계속 넘겨 보는 화면일 때

무한 스크롤을 쓰지 않는 경우

  • 항목을 찾아서 다시 돌아와야 하는 목록일 때. 뒤로가기로 돌아오면 보던 자리를 잃으므로 페이지네이션을 씁니다
  • 푸터에 중요한 내용이 있을 때. 사용자가 푸터까지 내려갈 수 없습니다
  • 전체가 몇 건인지 알아야 할 때
  • 항목을 비교하거나 원하는 위치로 건너뛰어야 하는 표나 관리 도구일 때

무한 스크롤 대신 다른 것을 써야 하는 경우 — 항목을 찾아 다시 돌아와야 하는 목록이면 페이지네이션을 쓰고, 사용자에게 멈출 자리를 주려면 더 보기 버튼을 둡니다. 화면에 그리는 양이 문제라면 가상 스크롤(10부)을 함께 쓰고, 결과가 하나도 없으면 빈 상태를 보여 줍니다.

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

IntersectionObserver로 센티널이 화면에 들어오는지 감지합니다. 스크롤 이벤트마다 위치를 계산하는 방식보다 가볍고 정확합니다.

<ul id="list">…</ul>
<div id="sentinel"></div>
<p role="status" aria-live="polite">12건 더 불러왔습니다</p>

// 끝에 닿기 전에 미리 부른다 (rootMargin)
new IntersectionObserver(es => {
  if (es[0].isIntersecting) loadMore();
}, { rootMargin: '200px' }).observe(sentinel);

// 두 번 부르지 않게 잠근다. 이걸 빠뜨리는 버그가 가장 흔하다
if (busy || done) return;

Tab자동 로드는 키보드 사용자에게 불리합니다. 목록 끝을 지나 그 아래로 갈 방법이 없는데, 더 보기 버튼을 두면 이 문제가 해결됩니다
aria-live'12건 더 불러왔습니다'처럼 알립니다. 알리지 않으면 스크린 리더 사용자는 목록이 늘어난 것을 모릅니다
더 보기 버튼을 눌렀을 때버튼을 누른 뒤 새로 들어온 첫 항목으로 포커스를 옮기면 이어서 읽을 수 있습니다
목록 끝에 닿았을 때'여기까지입니다'처럼 글로 끝을 알립니다
prefers-reduced-motion이 설정이 켜져 있으면 새 묶음이 나타나는 애니메이션을 끕니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

오프셋 대신 커서로 이어 붙이기오프셋으로 이어 붙이면 묶음을 받는 사이에 새 항목이 들어왔을 때 같은 항목이 두 번 보입니다. 마지막으로 받은 항목의 ID나 시각을 커서로 넘기면 이 문제가 생기지 않습니다.
같은 묶음을 두 번 요청하지 않게 잠그기스크롤이 빠르면 센티널이 짧은 사이에 여러 번 감지됩니다. 요청 중임을 나타내는 busy 플래그가 없으면 같은 묶음을 서너 번 요청하게 되는데, 무한 스크롤에서 가장 흔한 버그입니다.
끝을 어떻게 아나응답에 hasMore를 담아 더 있는지 알려 줍니다. '받은 수 < 요청 수'로 끝을 추측하면 남은 항목 수가 묶음 크기와 정확히 맞아떨어질 때 틀립니다.
이어 붙일수록 쌓이는 비용1,000건을 이어 붙이면 DOM과 메모리도 그만큼 커집니다. 그래서 가상 스크롤로 화면에 보이는 만큼만 그리거나, 앞쪽 항목을 버리고 일정 개수만 유지하는 창(window) 방식을 씁니다.
돌아왔을 때 보던 자리 되살리기뒤로가기로 돌아왔을 때 보던 자리를 되살리려면 받아 둔 묶음과 스크롤 위치를 함께 저장해야 합니다. 페이지네이션은 주소에 쪽 번호만 담으면 되지만, 무한 스크롤에서는 이 일을 직접 구현해야 합니다.
