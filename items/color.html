색 토큰

Color tokens · semantic color

색을 값이 아니라 쓰임으로 부르는 약속. 화면은 #2f6df6을 모르고 --accent만 압니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

1단은 색 이름표(blue-500), 2단은 쓰임표(--accent), 3단은 부품표(button-bg)입니다. 어두운 화면으로를 켜면 2단의 화살표만 다른 색을 가리키게 바뀝니다 — 1단의 색은 그대로이고 3단은 손대지 않았는데 버튼 색이 따라옵니다. 이것이 토큰을 쓰는 이유 전부입니다.

2 이름부르는 말이 여러 개다

한국어색 토큰, 시맨틱 색, 의미 색
영어color token, semantic color, design token
같이 쓰는 말원시 토큰(raw · primitive · global)은 blue-500처럼 색 그 자체이고, 시맨틱 토큰(semantic · alias)은 --accent처럼 쓰임입니다. 컴포넌트 토큰(component)은 button-bg처럼 부품 전용입니다. 색을 가로로 늘어놓은 10단 묶음을 색 램프(ramp · scale)라고 합니다.
자주 잘못 부름테마 — 테마는 토큰 한 벌을 가리키는 말이고, 토큰은 그 안의 항목 하나입니다.
CSS 변수 — 변수는 담는 그릇이고 토큰은 그 안에 담긴 약속입니다. 변수를 쓴다고 토큰이 되지는 않습니다.
팔레트 — 팔레트는 쓸 수 있는 색의 목록, 토큰은 어디에 쓸지까지 정한 것입니다.

3 가르는 기준형제들과 비교하는 네 축

토큰은 눈에 보이는 부품이 아니라 값의 약속입니다. 이 네 가지만 물어보면 어떤 약속인지 갈립니다.

무엇을 정하나몇 단이 좋나바꾸면 어디가 바뀌나틀렸을 때 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다르다
다크 모드두 벌의 값2벌(+고대비)화면 전체의 바탕과 글자흰 상자 하나가 혼자 남아 눈을 찌른다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기뭐가 더 중요한지 안 읽힌다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격뭐라 집어 말하기 어려운데 어수선하다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 안 보인다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 안 보인다

한 줄로 — 색 토큰은 '이 색을 어디에 쓰는가'에 이름을 붙인 것입니다. 이름에 blue가 들어가면 아직 쓰임이 아닙니다.

4 쓰임색은 예쁘라고 고르는 것이 아니다

5 해부도부분 이름이 제일 안 알려진 지식

검토 중
  1. 면 surface카드의 바탕. 페이지 바탕(--bg)과 한 단계 다르게 둔다
  2. 본문 글 fg · text-primary가장 진한 글. 바탕과 대비비 4.5:1 이상
  3. 보조 글 fg-muted · text-secondary덜 중요한 글. 흐리게 하다 대비를 놓치기 가장 쉬운 자리
  4. 위험 글 danger · text-error빨강 하나로 알리지 않는다 — 글로도 말한다
  5. 주요 버튼 accent · primary한 화면에 하나. 둘이 되면 둘 다 안 눌린다
  6. 약한 강조 accent-soft · subtle같은 강조색의 연한 짝. 배지·선택된 줄에 쓴다

쓰임 하나에 색 하나가 아니라 짝으로 갑니다 — 강조색에는 글자색(on-accent)과 연한 바탕(accent-soft)이 함께 있어야 합니다. 이 짝을 안 만들어 두면 결국 화면에서 rgba(…, .1) 같은 것을 손으로 섞게 되고, 다크 모드에서 그게 전부 깨집니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 색을 두 번 이상 쓸 때 — 한 번 쓰는 색은 토큰이 아닙니다
  • 다크 모드나 고대비 모드를 할 생각이 있을 때
  • 브랜드 색이 바뀔 수 있을 때 — 1단만 고치면 끝납니다
  • 여러 사람이 같은 화면을 만들 때

이럴 때는 안 쓴다

  • 일러스트나 그래프 색 — 의미가 아니라 구별이 목적이라 규칙이 다릅니다
  • 토큰 이름에 색 이름을 넣는 것 — --blue-button은 다크 모드에서 파랗지 않게 됩니다
  • 쓰임이 겹치는 토큰을 자꾸 늘리는 것 — --accent2가 생기면 이미 무너진 것입니다

대신 이걸 — 밝고 어두운 두 벌이 필요하면 다크 모드, 떠 있는 느낌은 색이 아니라 고도로 냅니다.

8 최소 코드와 이름 규칙이 토큰의 계약서

CSS 변수 세 겹으로 그대로 옮겨집니다. 화면은 2단·3단만 봅니다.

/* 1단 — 색 그 자체. 쓰임을 모른다 */
:root {
  --blue-500: #2f6df6;
  --blue-300: #6f9bff;
  --gray-900: #14161a;

  /* 2단 — 쓰임. 화면이 보는 것은 여기부터 */
  --accent: var(--blue-500);
  --on-accent: #fff;
  --fg: var(--gray-900);
}

/* 어두운 모드 — 2단의 연결만 갈아 끼운다 */
:root[data-theme="dark"] {
  --accent: var(--blue-300);
  --fg: #e8ebf0;
}

.btn { background: var(--accent); color: var(--on-accent); }
규칙지켜야 하는 것
이름에 색을 넣지 않는다--brand-blue ✗ → --accent ✓. 색이 바뀌어도 이름이 안 거짓말하게
쓰임 + 자리 + 강도--text-danger-strong처럼 무엇에 / 어디에 / 얼마나 순으로 읽히게 짓는다
짝을 함께 만든다바탕색에는 늘 그 위 글자색(--on-*)을 같이 정의한다
화면에서 1단 금지var(--blue-500)을 컴포넌트에서 쓰면 다크 모드가 거기서 깨진다
대비비를 값으로 못 박는다본문 4.5:1, 큰 글자·아이콘 3:1. 토큰을 고칠 때마다 다시 잰다

9 서버 쪽으로 치면백엔드 감각으로 번역

토큰 = 설정 파일의 상수코드 여기저기 박힌 매직 넘버를 config로 뺀 것과 같은 일입니다. 다른 점은 값이 여러 벌(밝게·어둡게)이라는 것뿐입니다.
어디에 저장하나보통 JSON 한 벌을 원본으로 두고(W3C Design Tokens 형식) 거기서 CSS·iOS·안드로이드 파일을 생성합니다. 손으로 세 군데 고치면 반드시 어긋납니다.
바꿀 때 영향 범위2단 하나를 고치면 그것을 가리키는 모든 3단이 따라 바뀝니다. 그래서 2단은 적게 두고 뜻을 또렷하게 지어야 합니다.
서버가 색을 보내는 경우상태 코드(APPROVED)를 보내고 색은 화면이 고릅니다. 서버가 #1f8a4c를 보내면 다크 모드에서 고칠 방법이 없습니다.
