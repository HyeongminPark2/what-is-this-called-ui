색 토큰

Color tokens · semantic color

색 토큰은 색을 값 대신 쓰임의 이름으로 부르기로 정해 둔 것입니다. 화면 코드에는 #2f6df6 같은 값을 적지 않고 --accent 같은 이름만 적습니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

1단은 색 자체의 이름(blue-500), 2단은 쓰임의 이름(--accent), 3단은 부품 전용 이름(button-bg)입니다. 어두운 화면으로를 켜면 2단의 화살표만 다른 색을 가리키도록 바뀝니다. 1단의 색은 그대로이고 3단도 손대지 않았지만, 3단이 2단을 가리키고 있기 때문에 버튼 색이 함께 바뀝니다. 한 곳만 고쳐서 화면 전체의 색을 바꿀 수 있다는 점이 토큰을 쓰는 이유입니다.

2 이름같은 것을 부르는 여러 이름

한국어색 토큰, 시맨틱 색, 의미 색
영어color token, semantic color, design token
같이 쓰는 말원시 토큰(raw · primitive · global)은 blue-500처럼 색 그 자체를 가리키고, 시맨틱 토큰(semantic · alias)은 --accent처럼 쓰임을 가리킵니다. 컴포넌트 토큰(component)은 button-bg처럼 한 부품에만 쓰는 토큰입니다. 같은 색을 10단으로 늘어놓은 묶음은 색 램프(ramp · scale)라고 부릅니다.
자주 잘못 부르는 이름테마 — 테마는 토큰 한 벌 전체를 가리키는 말이고, 토큰은 그 안의 항목 하나입니다.
CSS 변수 — CSS 변수는 값을 저장하는 수단이고, 토큰은 그 값을 어디에 쓸지 정한 규칙입니다. 그래서 CSS 변수를 쓴다고 해서 저절로 토큰이 되지는 않습니다.
팔레트 — 팔레트는 쓸 수 있는 색을 모아 둔 목록이고, 토큰은 그 색을 어디에 쓸지까지 정한 것입니다.

3 가르는 기준헷갈리는 형제 부품과 견주는 네 가지 기준

토큰은 눈에 보이는 부품이 아니라 값을 어떻게 쓸지 정해 둔 규칙입니다. 그래서 생김새 대신 아래 네 가지를 물어보면 토큰끼리 무엇이 다른지 가려집니다.

무엇을 정하는가몇 단으로 두면 좋은가값을 바꾸면 어디가 바뀌는가잘못 정했을 때 나타나는 증상
색 토큰색의 쓰임쓰임 10여 개브랜드 색 전체같은 파랑이 화면마다 조금씩 다릅니다
다크 모드두 벌의 값2벌, 고대비까지 두면 3벌화면 전체의 바탕과 글자어두운 화면에 흰 상자 하나만 남아 눈이 부십니다
타입 스케일글자 크기 단계6~8단제목과 본문의 크기무엇이 더 중요한지 알아보기 어렵습니다
간격 체계여백의 단위6~8단(4·8의 배수)모든 패딩과 줄 간격딱 집어 말하기 어렵지만 어수선해 보입니다
고도그림자의 세기4~5단떠 있는 부품들무엇이 위에 있는지 알 수 없습니다
z-index쌓이는 순서5~6층겹치는 것들의 앞뒤토스트가 모달에 가려 보이지 않습니다
모서리둥근 정도4~6단카드 · 버튼 · 입력칸 전부안팎 곡선이 어긋나 안쪽이 네모져 보입니다
테두리와 구분선가르는 선선 1~2종목록 · 카드 · 표선이 두 겹이 되고 화면이 어수선해집니다
불투명도흐린 정도2~3단비활성 · 가림막 · 흐린 글글이 잘 읽히지 않고 z-index가 적용되지 않습니다
아이콘 크기그림의 크기3~4단(16·20·24)버튼 · 목록 · 앱바선이 흐리고 글자와 가운데가 맞지 않습니다
상태 색성공 · 주의 · 오류 · 정보4가지, 색마다 3자리알림 · 배지 · 입력 오류색을 구별하지 못하면 상태를 알 수 없습니다
토큰 이름 짓기이름의 규칙층 3겹토큰 전부이름과 값이 어긋나 어느 토큰을 고쳐야 할지 알 수 없습니다

색 토큰을 한 줄로 정리하면 — 색 토큰은 '이 색을 어디에 쓰는가'에 이름을 붙인 것입니다. 그래서 이름에 blue 같은 색 이름이 들어 있다면 아직 쓰임으로 이름을 짓지 않은 것입니다.

검토 중
  1. 면 surface카드의 바탕색입니다. 페이지 바탕(--bg)과 한 단계 다른 색으로 둡니다
  2. 본문 글 fg · text-primary가장 진한 글자색입니다. 바탕과의 대비비가 4.5:1 이상이어야 합니다
  3. 보조 글 fg-muted · text-secondary덜 중요한 글에 씁니다. 글자를 흐리게 만들다 보면 대비비 기준을 놓치기 쉬운 자리입니다
  4. 위험 글 danger · text-error빨간색만으로 알리지 않고, 무엇이 문제인지 글로도 적습니다
  5. 주요 버튼 accent · primary한 화면에 하나만 둡니다. 두 개가 되면 어느 쪽이 주요 동작인지 알기 어려워집니다
  6. 약한 강조 accent-soft · subtle강조색과 짝을 이루는 연한 색입니다. 배지나 선택된 줄에 씁니다

색 토큰은 쓰임 하나에 색 하나씩 정하지 않고 여러 색을 짝으로 묶어 정합니다. 예를 들어 강조색에는 그 위에 올릴 글자색(on-accent)과 연한 바탕색(accent-soft)이 함께 있어야 합니다. 이 짝을 미리 만들어 두지 않으면 화면을 만들 때마다 rgba(…, .1) 같은 색을 손으로 섞게 되는데, 이렇게 섞은 색은 토큰을 거치지 않아서 다크 모드로 바꿔도 따라 바뀌지 않습니다.

6 쓸 때 / 안 쓸 때

색 토큰을 쓰는 경우

  • 같은 색을 두 번 이상 쓸 때. 한 번만 쓰는 색은 토큰으로 만들 필요가 없습니다
  • 다크 모드나 고대비 모드를 지원할 계획이 있을 때
  • 브랜드 색이 바뀔 수 있을 때. 토큰을 쓰면 1단의 값만 고치면 됩니다
  • 여러 사람이 같은 화면을 만들 때

색 토큰을 쓰지 않는 경우

  • 일러스트나 그래프 색을 정할 때. 이런 색은 의미를 전하기보다 서로 구별되는 것이 목적이라 규칙이 다릅니다
  • 토큰 이름에 색 이름을 넣을 때. --blue-button은 다크 모드에서 파란색이 아니게 될 수 있어 이름과 실제 색이 어긋납니다
  • 쓰임이 겹치는 토큰을 자꾸 늘릴 때. --accent2 같은 이름이 생겼다면 이미 쓰임의 구분이 흐려졌다는 뜻입니다

색 토큰과 함께 보면 좋은 항목 — 밝은 화면과 어두운 화면에 쓸 값을 두 벌 마련해야 하면 다크 모드 항목을 함께 봅니다. 부품이 떠 있는 느낌은 색을 바꿔서 내지 않고 고도로 표현합니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 이름 규칙코드로 옮기는 법과 지킬 규칙

세 단의 토큰은 CSS 변수 세 겹으로 그대로 옮길 수 있습니다. 화면 코드에서는 2단과 3단만 씁니다.

/* 1단. 색 그 자체이고 쓰임은 정하지 않는다 */
:root {
  --blue-500: #2f6df6;
  --blue-300: #6f9bff;
  --gray-900: #14161a;

  /* 2단. 쓰임을 정한다. 화면은 여기부터 쓴다 */
  --accent: var(--blue-500);
  --on-accent: #fff;
  --fg: var(--gray-900);
}

/* 어두운 모드에서는 2단의 연결만 바꾼다 */
:root[data-theme="dark"] {
  --accent: var(--blue-300);
  --fg: #e8ebf0;
}

.btn { background: var(--accent); color: var(--on-accent); }
지킬 규칙지키는 방법과 이유
이름에 색 이름을 넣지 않기--brand-blue(✗) 대신 --accent(✓)처럼 짓습니다. 이렇게 지어야 색이 바뀌어도 이름과 실제 색이 어긋나지 않습니다
쓰임, 자리, 강도 순서로 짓기--text-danger-strong처럼 무엇에 / 어디에 / 얼마나 순서로 읽히도록 짓습니다
짝이 되는 색을 함께 만들기바탕색을 정할 때는 그 위에 올릴 글자색(--on-*)도 늘 함께 정의합니다
화면 코드에서 1단 토큰을 쓰지 않기컴포넌트에서 var(--blue-500)을 직접 쓰면 그 자리만 다크 모드에서 색이 바뀌지 않습니다
토큰 값마다 대비비 확인하기본문은 4.5:1, 큰 글자와 아이콘은 3:1 이상이어야 하고, 토큰 값을 고칠 때마다 대비비를 다시 잽니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

설정 파일의 상수와 같은 역할코드 여기저기에 직접 적힌 매직 넘버를 config로 빼내는 것과 같은 일입니다. 다만 토큰은 밝은 화면용과 어두운 화면용처럼 값이 여러 벌이라는 점이 다릅니다.
토큰 원본을 저장하는 곳보통 W3C Design Tokens 형식의 JSON 한 벌을 원본으로 두고, 거기서 CSS와 iOS, 안드로이드용 파일을 생성합니다. 세 플랫폼의 파일을 손으로 따로 고치면 결국 값이 서로 어긋나기 때문입니다.
토큰 하나를 바꿀 때 영향이 미치는 범위2단 토큰 하나를 고치면 그 토큰을 가리키는 3단 토큰이 모두 함께 바뀝니다. 그래서 2단은 개수를 적게 두고 이름의 뜻을 또렷하게 지어야 합니다.
서버가 색 값을 보내면 생기는 문제서버는 APPROVED 같은 상태 코드만 보내고, 색은 화면 쪽에서 고릅니다. 서버가 #1f8a4c 같은 색 값을 직접 보내면 화면에서는 다크 모드에 맞게 색을 바꿀 방법이 없습니다.
