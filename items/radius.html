모서리

Border radius · corner scale

모서리 둥글기는 몇 가지 단으로 정해 두고 그 단만 씁니다. 자리마다 8px 같은 값을 직접 적기 시작하면 화면마다 둥글기가 조금씩 어긋납니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

겹친 상자의 안쪽 모서리는 바깥 모서리보다 여백만큼 작아야 두 곡선이 나란히 이어집니다. 식으로 쓰면 안쪽 = 바깥 − 여백입니다. 공식을 끄면 모서리에서 두 곡선 사이가 벌어져 안쪽이 네모져 보입니다.
둥근 카드 안에 그림을 꽉 채울 때는 overflow: hidden이 있어야 그림이 카드 모양대로 잘립니다. 이 설정을 끄면 네모난 그림이 둥근 모서리를 덮는데, 데모는 그 자리를 실제로 찍어서 그림이 튀어나왔는지 확인합니다.

2 이름같은 것을 부르는 여러 이름

한국어모서리, 모서리 둥글기, 라운드, 코너 반경
영어border radius, corner radius, rounding
같이 쓰는 말양 끝을 완전히 둥글린 모양은 알약(pill), 정사각형을 동그랗게 만든 것은 원형이라고 합니다. 애플이 쓰는 매끈한 곡선은 연속 곡률(continuous · squircle)이라고 부르는데, CSS의 border-radius는 원호(circular)로 그리기 때문에 모양이 미세하게 다릅니다.
자주 잘못 부르는 이름테두리 — 테두리는 선이고 모서리는 모양입니다. CSS 속성 이름에 둘 다 border가 들어갈 뿐 서로 다른 값입니다.
그림자 — 모서리는 고도와 함께 쓰이는 일이 많지만, 둘은 따로 정하는 값입니다.
50% — 50%를 주면 정사각형에서만 동그라미가 되고, 직사각형에서는 타원이 됩니다.

3 모서리 단계별 쓰는 부품단마다 그 둥글기를 주는 부품

4 해부도부분마다 붙은 이름

--radius-1: 4px ← 칩 · 배지
--radius-2: 8px ← 버튼 · 입력칸
--radius-3: 12px ← 카드
--radius-4: 16px ← 시트 · 모달
--radius-full: 999px ← 알약 · 동그라미
안쪽 = 바깥 − 여백 ← 겹칠 때의 공식
  1. 1단 4px 칩 · 배지작은 부품에는 작은 값을 줍니다
  2. 2단 8px 버튼 · 입력칸가장 자주 씁니다
  3. 3단 12px 카드내용 덩어리를 한 장으로 묶어 보이게 합니다
  4. 4단 16px 시트 · 모달큰 면일수록 크게 줍니다
  5. 999px 알약 · 원50%를 주면 직사각형에서 타원이 되므로 999px을 씁니다
  6. 공식 안쪽 = 바깥 − 여백겹친 상자에서 지켜야 할 유일한 규칙입니다

모서리 값은 큰 면일수록 크게, 작은 면일수록 작게 주는 것이 원칙입니다. 16px짜리 배지에 12px 모서리를 주면 거의 알약 모양이 되고, 반대로 큰 시트에 4px을 주면 둥근지 알아보기 어렵습니다. 알약을 만들 때 50% 대신 999px을 쓰는 데에도 이유가 있습니다. 50%는 가로세로 비율을 따라가서 타원이 되지만, 999px은 짧은 변의 절반에서 더 커지지 않으므로 비율과 상관없이 알약 모양이 됩니다.

5 쓸 때 / 안 쓸 때

모서리 값을 정할 때 지킬 것

  • 둥글기를 토큰 네댓 개로 정해 두고 그 토큰만 쓰기
  • 겹친 상자는 안쪽 = 바깥 − 여백으로 계산하기
  • 알약은 999px로, 동그라미는 정사각형에 50%로 만들기

모서리 값을 정할 때 피할 것

  • 자리마다 6px·7px을 직접 적기. 화면마다 둥글기가 조금씩 달라집니다
  • 둥근 카드 안에 그림을 넣고 overflow를 걸지 않기. 그림이 모서리 밖으로 튀어나옵니다
  • 직사각형에 50% 주기. 알약이 아니라 타원이 됩니다
  • 겹친 상자 안팎에 같은 값 주기. 모서리에서 두 곡선 사이가 벌어져 안쪽이 네모져 보입니다

모서리와 함께 보면 좋은 항목 — 선을 긋는 방법은 테두리와 구분선 항목에서, 떠 있는 느낌을 내는 방법은 고도 항목에서 다룹니다. 모서리 토큰의 이름을 정하는 방법은 토큰 이름 짓기 항목을 봅니다.

6 자주 보는 모습구조만 따라 그린 재현 그림

7 최소 코드와 지킬 규칙모서리를 코드로 옮기는 방법

단은 토큰으로 정해 두고, 상자가 겹칠 때만 공식으로 안쪽 값을 구합니다.

/* 네댓 단이면 화면 전체에 충분하다 */
:root {
  --radius-1: 4px;    /* 칩 · 배지 */
  --radius-2: 8px;    /* 버튼 · 입력칸 */
  --radius-3: 12px;   /* 카드 */
  --radius-4: 16px;   /* 시트 · 모달 */
  --radius-full: 999px;
}

/* 겹치면 안쪽은 여백만큼 작게 */
.card { border-radius: var(--radius-3); padding: 8px; overflow: hidden; }
.card > .thumb { border-radius: calc(var(--radius-3) - 8px); }

/* ✕ 직사각형에서는 타원이 된다 */
.pill { border-radius: 50%; }
값과 속성쓰면 일어나는 일
999px짧은 변의 절반에서 더 커지지 않으므로, 가로세로 비율과 상관없이 알약 모양이 됩니다
50%가로세로 비율을 따라가므로 정사각형에서만 원이 됩니다
overflow: hidden자식을 카드 모양대로 자릅니다. 대신 카드 밖으로 나가는 그림자와 툴팁도 함께 잘립니다
네 모서리 값을 따로 주기16px 16px 0 0처럼 네 값을 따로 주면 위쪽 두 모서리만 둥글립니다
calc()안쪽 값은 손으로 적지 말고 바깥 값에서 여백을 빼서 구합니다
확인하는 방법개발자 도구에서 두 모서리를 함께 확대해 곡선이 나란한지 봅니다

8 서버 쪽으로 치면백엔드 개념과 짝지어 보기

서버와 관계없는 CSS 값모서리는 전부 CSS 값입니다. 다만 이미지 자체를 둥글게 잘라 보내 달라는 요청이 가끔 오는데, 모양은 화면 쪽에서 정하는 편이 낫습니다.
아바타 이미지를 자르는 쪽서버는 이미지를 정사각형으로 잘라 주고, 화면에서 동그랗게 만듭니다. 그래야 같은 이미지를 자리마다 다른 모양으로 쓸 수 있습니다.

9 플랫폼마다 다른 이름웹 · iOS · 안드로이드에서 부르는 이름

곡선의 모양이 플랫폼마다 조금씩 다릅니다.

웹border-radius
원호
모서리를 원호로 그립니다. 그래서 곡선과 직선이 만나는 곳에서 곡률이 한 번에 바뀝니다.
iOScontinuous
연속 곡률을 씁니다. 같은 값이라도 더 부드럽게 보이기 때문에, 같은 값을 웹에 옮기면 살짝 각져 보입니다.
안드로이드Shape
Material 3는 모서리 값을 크게(12~28dp) 쓰고, 버튼은 알약 모양이 기본입니다.

플랫폼 차이 때문에 자주 생기는 문제 — 곡선을 그리는 방식이 다르기 때문에 같은 12px이라도 iOS 쪽이 더 둥글어 보입니다. 그래서 디자인 도구에서 'continuous'로 그린 시안을 웹에 옮기면 각져 보인다는 말을 듣는데, 값이 틀린 것이 아니라 곡선을 그리는 방식이 다른 것입니다. 모양을 맞추려면 웹 쪽 값을 1~2px 키우거나, 값은 그대로 두고 플랫폼마다 기본 곡선을 따르는 편이 낫습니다.
