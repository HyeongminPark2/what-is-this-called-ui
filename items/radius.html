모서리

Border radius · corner scale

둥글기를 단으로 정해 두고 그 단만 씁니다. 아무 데나 8px을 적기 시작하면 화면이 조금씩 어긋납니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

겹친 상자의 안쪽 모서리는 바깥보다 여백만큼 작아야 두 곡선이 나란히 돕니다 — 안쪽 = 바깥 − 여백입니다. 공식을 끄면 사이가 벌어져 안쪽이 네모져 보입니다.
둥근 카드 안에 그림을 꽉 채우면 overflow: hidden이 있어야 모양대로 잘립니다. 끄면 네모난 그림이 모서리를 덮는데, 데모는 그 자리를 실제로 찍어서 확인합니다.

2 이름부르는 말이 여러 개다

한국어모서리, 모서리 둥글기, 라운드, 코너 반경
영어border radius, corner radius, rounding
같이 쓰는 말완전히 둥근 양 끝은 알약(pill), 정사각형을 동그랗게 만든 것은 원형입니다. 애플이 쓰는 매끈한 곡선은 연속 곡률(continuous · squircle)이라 부르고, CSS 의 border-radius는 원호(circular)라 미세하게 다릅니다.
자주 잘못 부름테두리 — 테두리는 선이고 모서리는 모양입니다. 이름만 같이 붙어 있습니다.
그림자 — 고도와 함께 다니지만 따로 정하는 값입니다.
50% — 정사각형에만 동그라미가 되고, 직사각형에서는 타원이 됩니다.

4 단단마다 맡은 부품이 있다

5 해부도부분 이름이 제일 안 알려진 지식

--radius-1: 4px ← 칩 · 배지
--radius-2: 8px ← 버튼 · 입력칸
--radius-3: 12px ← 카드
--radius-4: 16px ← 시트 · 모달
--radius-full: 999px ← 알약 · 동그라미
안쪽 = 바깥 − 여백 ← 겹칠 때의 공식
  1. 1단 4px 칩 · 배지작은 것은 작게
  2. 2단 8px 버튼 · 입력칸가장 자주 쓴다
  3. 3단 12px 카드덩어리를 한 장으로 묶는다
  4. 4단 16px 시트 · 모달큰 면일수록 크게
  5. 999px 알약 · 원50% 는 직사각형에서 타원이 된다
  6. 공식 안쪽 = 바깥 − 여백겹친 상자의 유일한 규칙

큰 면일수록 크게, 작은 면일수록 작게가 원칙입니다. 16px 짜리 배지에 12px 모서리를 주면 거의 알약이 되고, 반대로 큰 시트에 4px 을 주면 둥근 줄도 모릅니다. 알약을 만들 때 50% 대신 999px을 쓰는 이유도 같습니다 — 50% 는 가로세로 비를 따라 타원이 되지만, 999px 은 짧은 변의 절반에서 멈춰 어떤 비에서도 알약이 됩니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 둥글기를 토큰 네댓 개로 두고 그것만 쓰기
  • 겹친 상자는 안쪽 = 바깥 − 여백으로 계산하기
  • 알약은 999px, 동그라미는 정사각형 + 50%

이럴 때는 안 쓴다

  • 자리마다 6px·7px을 직접 적기 — 조금씩 다른 화면이 된다
  • 둥근 카드 안에 그림을 넣고 overflow를 안 걸기
  • 직사각형에 50% 주기 — 타원이 된다
  • 안팎에 같은 값 주기 — 사이가 벌어져 안쪽이 네모져 보인다

대신 이걸 — 선 자체는 테두리와 구분선, 떠 있는 느낌은 고도, 값 이름은 토큰 이름 짓기.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 단의 계약서

단을 토큰으로 두고, 겹칠 때만 공식을 씁니다.

/* 네댓 단이면 화면 전체가 덮인다 */
:root {
  --radius-1: 4px;    /* 칩 · 배지 */
  --radius-2: 8px;    /* 버튼 · 입력칸 */
  --radius-3: 12px;   /* 카드 */
  --radius-4: 16px;   /* 시트 · 모달 */
  --radius-full: 999px;
}

/* 겹치면 안쪽은 여백만큼 작게 */
.card { border-radius: var(--radius-3); padding: 8px; overflow: hidden; }
.card > .thumb { border-radius: calc(var(--radius-3) - 8px); }

/* ✕ 직사각형에서는 타원이 된다 */
.pill { border-radius: 50%; }
키일어나야 하는 일
999px짧은 변의 절반에서 멈춘다 — 어떤 비에서도 알약
50%가로세로 비를 따라간다 — 정사각형에서만 원
overflow: hidden자식을 모양대로 자른다. 대신 그림자·툴팁도 잘린다
네 값 따로16px 16px 0 0 — 위 둘만 둥글린다
calc()안쪽 값은 손으로 적지 말고 바깥에서 빼서 쓴다
확인하는 법개발자 도구에서 두 모서리를 같이 확대해 곡선이 나란한지 본다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버와는 상관없다전부 CSS 값입니다. 다만 이미지 자체를 둥글게 잘라 보내 달라는 요청이 가끔 오는데, 모양은 화면에서 정하는 편이 낫습니다.
아바타서버는 정사각형으로 잘라 주고 화면이 동그랗게 만듭니다 — 자리마다 다른 모양을 쓸 수 있습니다.

10 플랫폼마다 다른 이름같은 부품, 다른 말

곡선의 모양이 플랫폼마다 조금씩 다릅니다.

웹border-radius
원호
원호입니다. 모서리와 직선이 만나는 곳에서 곡률이 한 번에 꺾입니다.
iOScontinuous
연속 곡률을 씁니다. 같은 값이라도 더 부드럽게 보여, 웹에서 흉내 내면 살짝 각져 보입니다.
안드로이드Shape
Material 3 이 모서리를 크게 씁니다(12~28dp). 버튼은 아예 알약이 기본입니다.

자주 생기는 사고 — 같은 12px이라도 iOS 쪽이 더 둥글어 보입니다 — 곡선을 그리는 방식이 다르기 때문입니다. 디자인 도구에서 'continuous' 로 그린 시안을 웹에 옮기면 각져 보인다는 말을 듣는데, 값이 틀린 게 아니라 곡선이 다른 것입니다. 맞추려면 값을 1~2px 키우거나, 그대로 두고 플랫폼의 기본을 따르는 편이 낫습니다.
