말줄임

Truncation · line clamp

말줄임은 칸을 넘친 글의 끝을 …으로 줄여 보여 주는 방식입니다. 잘린 부분은 화면에서 보이지 않게 되므로, '어디서 자를지'보다 '전체를 어떻게 보게 할지'를 먼저 정해야 합니다.

새 탭에서 열기 ↗

한 줄, 여러 줄, 흐려서 끊기, 세 가지 방식을 나란히 두었습니다. 줄 수 막대를 움직이면 상자 높이가 따라 바뀝니다.
아래에는 scrollWidth·scrollHeight 값을 재서 지금 글이 잘렸는지를 보여 줍니다. 이 값을 쓰면 잘렸을 때만 툴팁을 붙일 수 있습니다. 잘리지 않은 글에 툴팁이 뜨면 같은 내용을 한 번 더 보여 주는 셈이라 거슬립니다.

2 이름같은 것을 부르는 여러 이름

한국어말줄임, 줄임표, 생략, 더보기
영어truncation, ellipsis, line clamp, text overflow
같이 쓰는 말한 줄로 줄이는 것을 엘립시스(ellipsis), 정한 줄 수까지만 보여 주는 것을 라인 클램프(line clamp)라고 합니다. 끝을 흐리게 지우는 방식은 페이드 아웃, 뒷부분을 눌러서 펼치게 하는 방식은 더 보기(read more)라고 부릅니다. … 글자 자체의 이름은 줄임표(horizontal ellipsis)입니다.
자주 잘못 부르는 이름overflow: hidden — 이 속성만 쓰면 글이 … 없이 그냥 잘립니다. …이 나오려면 세 속성이 모두 있어야 합니다.
글자 수로 자르기 — slice(0, 20)은 화면 폭과 상관없이 자르기 때문에, 넓은 화면에서도 똑같이 잘립니다.
text-overflow — 이 속성 하나만으로는 아무 변화도 일어나지 않습니다.

말줄임을 한 줄로 정리하면 — 한 줄 말줄임에는 세 속성이 한 세트로 필요합니다. 그보다 더 중요한 것은 잘린 글의 전체를 볼 방법을 남겨 두는 것입니다.

4 갈래자르는 방법마다 주는 느낌이 다르다

5 해부도부분마다 붙은 이름

환불 확인 요청 — 카드 승인 취소가 늦어져 고객이 두 번 문의했고
overflow: hidden
text-overflow: ellipsis
white-space: nowrap
-webkit-line-clamp: 2 — 여러 줄
scrollWidth > clientWidth — 잘렸는지 아는 법
  1. 잘린 글 truncated text줄 수가 정해진 상자 안에 들어가는 글입니다
  2. 넘침 숨기기 overflow: hidden혼자 쓰면 글이 그냥 잘리고 … 은 붙지 않습니다
  3. 줄임표 text-overflow: ellipsis잘린 끝에 …을 붙입니다. 이 속성 하나만으로는 아무 변화도 없습니다
  4. 줄바꿈 막기 white-space: nowrap한 줄 말줄임에만 씁니다. 줄바꿈을 막아야 글이 가로로 넘치면서 … 이 생깁니다
  5. 줄 수 묶기 -webkit-line-clamp여러 줄 말줄임에 씁니다. 이름에 -webkit-이 붙었지만 모든 브라우저가 지원합니다
  6. 잘렸는지 알기 scrollWidth > clientWidth이 비교 결과로 툴팁을 붙일지 말지를 정합니다

플렉스·그리드 자식에서는 세 속성을 모두 써도 말줄임이 적용되지 않습니다. 자식의 자동 최소 너비가 '내용 길이만큼'으로 잡혀서, 상자가 글 길이에 맞춰 늘어나기 때문입니다. 그래서 min-width: 0 한 줄을 더 적어야 합니다. 이 도감에서 가장 자주 다루는 실수이고, 플렉스·넘침 항목에서도 같은 내용을 설명합니다.

6 쓸 때 / 안 쓸 때

말줄임을 쓰는 경우

  • 목록의 제목이나 보조 글처럼 줄 높이가 일정해야 할 때
  • 카드 설명처럼 두세 줄까지만 보여 줘야 할 때
  • 툴팁이나 상세 화면, 더 보기처럼 전체를 볼 방법이 있을 때

말줄임을 쓰지 않는 경우

  • 전체를 볼 방법 없이 자를 때. 잘린 정보를 사용자가 볼 수 없게 됩니다
  • 글자 수로 자를 때. 화면 폭과 상관없이 똑같이 잘립니다
  • 잘리지 않은 글에 툴팁을 붙일 때. 이미 보이는 내용이 한 번 더 떠서 거슬립니다
  • 중요한 정보의 끝을 자를 때. 파일명이나 코드는 끝부분이 중요합니다

말줄임 대신 다른 것을 써야 하는 경우 — 넘침 자체의 처리는 넘침, 줄이 안 줄어들면 플렉스의 min-width: 0, 전체를 띄우려면 툴팁.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 코드와 규칙세 속성이 한 세트

한 줄 말줄임에는 세 속성이 필요하고 플렉스 자식이면 한 줄을 더 적습니다. 여러 줄 말줄임에는 네 속성이 필요합니다.

/* 한 줄 */
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  min-width: 0;        /* 플렉스·그리드 자식이면 */
}

/* 여러 줄 */
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

// 잘렸을 때만 툴팁을 붙인다
if (el.scrollWidth > el.clientWidth) el.title = el.textContent;
규칙지켜야 하는 것
세 속성이 한 세트하나라도 빠지면 …이 나오지 않습니다
min-width: 0플렉스·그리드 자식에서는 이 줄이 없으면 말줄임이 적용되지 않습니다
잘렸을 때만 툴팁scrollWidth > clientWidth로 잘렸는지 확인한 뒤에 붙입니다
전체를 볼 길을 준다툴팁, 상세 화면, 더 보기 가운데 하나는 둡니다. 그런 방법이 없으면 잘린 정보는 아무도 볼 수 없습니다
글자 수로 자르지 않는다어디서 자를지는 화면 폭에 맡깁니다. 서버에서 글자 수로 자르면 넓은 화면에서도 글이 짧게 잘립니다
끝이 중요하면 가운데를파일명이나 코드는 앞뒤를 남기고 가운데를 지웁니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

자르기는 화면에서서버가 글을 미리 자르면 툴팁에도 전체를 보여 줄 수 없습니다. 그래서 전체를 보내고 화면에서 줄이는 편이 낫고, 서버에서는 글이 아주 길 때만 자릅니다.
가장 긴 값으로 테스트개발 중에 쓰는 짧은 더미 데이터로는 말줄임 문제가 드러나지 않습니다. 그래서 운영 데이터에서 가장 긴 값으로 화면을 한 번 그려 봅니다.
검색 결과 하이라이트글을 자른 뒤에 하이라이트를 넣으면 찾은 낱말이 잘린 부분에 들어가 보이지 않을 수 있습니다. 그래서 찾은 자리 앞뒤를 남기고 자르는 처리가 따로 필요합니다.
접근성화면에서 잘린 글도 DOM에는 전체가 들어 있어서 스크린 리더는 전체를 읽습니다. 그래서 같은 내용을 title로 한 번 더 붙이면 두 번 읽힙니다.

한 줄 말줄임은 세 속성이 한 세트이고, 여러 줄은 -webkit-line-clamp로 처리합니다.

플랫폼 차이 때문에 자주 생기는 문제 — 두 OS에는 가운데를 지우는 모드가 기본으로 들어 있어서 파일명이나 코드를 자를 때 바로 쓸 수 있습니다. 반면 웹에는 이런 기능이 없어 직접 만들어야 하므로, "파일명 가운데를 … 으로 줄여 주세요"라는 요청이 웹에서는 손이 많이 가는 작업이 됩니다.
