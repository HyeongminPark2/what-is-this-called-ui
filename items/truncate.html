말줄임

Truncation · line clamp

넘친 글의 끝을 …으로 줄이는 것. 정보를 지우는 일이라 '어디서 자를지'보다 '전체를 어떻게 보게 할지'가 먼저입니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

세 가지를 나란히 뒀습니다 — 한 줄, 여러 줄, 흐려서 끊기. 줄 수 막대를 움직이면 상자 높이가 따라 바뀝니다.
아래에 scrollWidth·scrollHeight 값을 재서 지금 잘렸는지를 보여 줍니다. 이걸 쓰면 잘렸을 때만 툴팁을 붙일 수 있습니다 — 안 잘렸는데 툴팁이 뜨면 거슬립니다.

2 이름부르는 말이 여러 개다

한국어말줄임, 줄임표, 생략, 더보기
영어truncation, ellipsis, line clamp, text overflow
같이 쓰는 말한 줄로 줄이는 것을 엘립시스(ellipsis), 여러 줄로 묶는 것을 라인 클램프(line clamp)라 합니다. 끝을 흐리게 지우는 방식은 페이드 아웃, 뒷부분을 눌러서 펼치는 것은 더 보기(read more)입니다. … 글자 자체는 줄임표(horizontal ellipsis)입니다.
자주 잘못 부름overflow: hidden — 그것만으로는 그냥 잘립니다. …이 나오려면 세 속성이 다 있어야 합니다.
글자 수로 자르기 — slice(0, 20)은 폭과 상관없이 자릅니다. 넓은 화면에서도 똑같이 잘립니다.
text-overflow — 혼자서는 아무 일도 안 합니다.

한 줄로 — 말줄임은 세 속성이 한 세트이고, 그보다 중요한 것은 전체를 볼 길을 남기는 것입니다.

4 갈래자르는 방법마다 주는 느낌이 다르다

5 해부도부분 이름이 제일 안 알려진 지식

환불 확인 요청 — 카드 승인 취소가 늦어져 고객이 두 번 문의했고
overflow: hidden
text-overflow: ellipsis
white-space: nowrap
-webkit-line-clamp: 2 — 여러 줄
scrollWidth > clientWidth — 잘렸는지 아는 법
  1. 잘린 글 truncated text줄 수가 정해진 상자 안의 글
  2. 넘침 숨기기 overflow: hidden혼자 쓰면 그냥 잘린다 — … 이 안 붙는다
  3. 줄임표 text-overflow: ellipsis끝에 …을 붙인다. 혼자서는 아무 일도 안 한다
  4. 줄바꿈 막기 white-space: nowrap한 줄짜리에만. 이게 있어야 가로로 넘쳐 … 이 생긴다
  5. 줄 수 묶기 -webkit-line-clamp여러 줄용. 이름에 -webkit-이 붙었지만 모든 브라우저가 지원한다
  6. 잘렸는지 알기 scrollWidth > clientWidth툴팁을 붙일지 말지를 이걸로 정한다

플렉스·그리드 자식에서는 세 속성을 다 써도 말줄임이 안 걸립니다. 자식의 자동 최소 너비가 '내용만큼'이라 상자가 글에 밀려 늘어나기 때문입니다 — min-width: 0 한 줄이 더 필요합니다. 이 도감에서 가장 자주 나오는 사고이고, 플렉스·넘침에서도 같은 이야기가 나옵니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 줄 높이가 일정해야 하는 목록 — 제목, 보조 글
  • 카드 설명처럼 두세 줄로 묶어야 할 때
  • 전체를 볼 길(툴팁·상세·더 보기)이 있을 때

이럴 때는 안 쓴다

  • 전체를 볼 길 없이 자르는 것 — 정보가 그냥 사라집니다
  • 글자 수로 자르는 것 — 화면 폭과 상관없이 똑같이 잘립니다
  • 안 잘렸는데 툴팁을 붙이는 것 — 거슬립니다
  • 중요한 정보의 끝을 자르는 것 — 파일명·코드는 끝이 중요합니다

대신 이걸 — 넘침 자체의 처리는 넘침, 줄이 안 줄어들면 플렉스의 min-width: 0, 전체를 띄우려면 툴팁.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙세 속성이 한 세트

한 줄은 세 속성(+ 플렉스면 한 줄 더), 여러 줄은 네 속성입니다.

/* 한 줄 */
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  min-width: 0;        /* 플렉스·그리드 자식이면 */
}

/* 여러 줄 */
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

// 잘렸을 때만 툴팁을 붙인다
if (el.scrollWidth > el.clientWidth) el.title = el.textContent;
규칙지켜야 하는 것
세 속성이 한 세트하나라도 빠지면 …이 안 나온다
min-width: 0플렉스·그리드 자식이면 이게 없으면 영영 안 걸린다
잘렸을 때만 툴팁scrollWidth > clientWidth로 확인하고 붙인다
전체를 볼 길을 준다툴팁·상세·더 보기 중 하나. 없으면 정보를 지운 것이다
글자 수로 자르지 않는다폭이 정하게 둔다. 서버에서 자르면 넓은 화면에서도 짧다
끝이 중요하면 가운데를파일명·코드는 앞뒤를 남기고 가운데를 지운다

9 서버 쪽으로 치면백엔드 감각으로 번역

자르기는 화면에서서버가 미리 자르면 툴팁에도 전체가 없습니다. 전체를 보내고 화면이 줄이는 쪽이 낫습니다 — 글이 아주 길 때만 서버에서 자릅니다.
가장 긴 값으로 테스트개발 중의 짧은 더미 데이터로는 평생 안 드러납니다. 운영 데이터의 최댓값으로 한 번 그려 봅니다.
검색 결과 하이라이트자른 뒤에 하이라이트를 넣으면 찾은 낱말이 잘려 안 보일 수 있습니다. 찾은 자리 앞뒤를 남기고 자르는 처리가 따로 필요합니다.
접근성잘린 글도 스크린 리더에는 전체가 읽힙니다(DOM 에는 다 있으므로). 그래서 title을 중복으로 붙이면 두 번 읽힙니다.
