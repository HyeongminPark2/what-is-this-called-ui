1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

줄 수를 바꿔 보고, 자르지 말고 접기를 켜 보세요. 글이 다 보이는 대신 줄 높이가 제각각이 됩니다. 목록은 보통 자르는 쪽을 고릅니다 — 높이가 일정해야 눈이 세로로 미끄러지고, 가상 스크롤도 그때만 쓸 수 있습니다.

2 이름부르는 말이 여러 개다

한국어리스트 아이템, 목록 항목, 줄, 행
영어list item, row, list row, cell(iOS)
같이 쓰는 말앞의 아이콘·아바타 자리를 리딩(leading), 뒤의 값·꺾쇠 자리를 트레일링(trailing)이라 합니다. 줄 사이를 나누는 선은 디바이더(divider · separator), 묶음의 머리글은 섹션 헤더입니다. 글이 몇 줄이냐로 한 줄·두 줄·세 줄(one/two/three-line)이라 부릅니다.
자주 잘못 부름카드 — 가로형 카드와 거의 같아 보입니다. 가르는 것은 생김새가 아니라 어떻게 모이느냐입니다.
테이블 행 — 표의 행은 열이 정해져 있고 정렬·선택이 따릅니다. 리스트 아이템은 자유로운 세 자리뿐입니다.
메뉴 아이템 — 메뉴는 눌러서 사라지는 선택지입니다. 리스트는 내용 그 자체입니다.

3 가르는 기준형제들과 비교하는 네 축

표시 부품은 '보여 주기만 한다'는 점이 같습니다. 이 네 가지만 물어보면 갈립니다.

무엇을 담나전체가 눌리나어떻게 모이나내용이 길어지면
카드한 덩어리보통 눌린다그리드로높이가 늘어난다
리스트 아이템한 건보통 눌린다세로 목록으로말줄임한다
아바타사람·조직 하나안 눌린다겹쳐 쌓는다고정 — 넘치면 +N
배지숫자나 한 낱말안 눌린다혼자 안 선다 — 붙는다고정 — 넘치면 99+
칩한 낱말눌린다가로로 줄바꿈말줄임하거나 줄을 넘긴다
스탯 타일숫자 하나가끔 눌린다가로 한 줄로단위를 줄인다(1.2만)
타임라인사건들의 순서항목만세로로 꿴다아래로 길어진다
별점점수 하나읽기용은 안 눌린다줄 안에 들어간다고정 — 별 다섯

한 줄로 — 리스트 아이템은 세로로 비교하라고 줄을 맞춘 것입니다. 줄 높이가 제각각이면 이미 리스트의 일을 못 하고 있습니다.

5 해부도부분 이름이 제일 안 알려진 지식

길동 정산 요청 #4821 11월 1일 ~ 11월 7일 ₩1,245,480 ›
줄 하나가 통째로 하나의 누를 것이다
길동 앞자리 — 폭이 고정
가운데 — 여기만 늘어난다
이번 주
  1. 목록 list줄들을 감싸는 상자. <ul>이라야 '모두 몇 건'이 읽힌다
  2. 줄 list item · row한 건 전체가 하나의 누를 것이다 — 제목만 링크로 두지 않는다
  3. 앞자리 leading아바타·아이콘·체크박스. 폭이 고정이라야 줄끼리 세로로 맞는다
  4. 가운데 primary · secondary text제목과 보조 글. 여기만 늘어난다(flex:1; min-width:0)
  5. 구분선 divider줄 사이. 아바타가 있으면 보통 앞자리만큼 들여 긋는다
  6. 섹션 헤더 section header'이번 주'처럼 줄들을 묶는 머리글. 스크롤해도 붙어 있게 만들기도 한다

가운데 자리에 min-width: 0을 안 주면 말줄임이 영영 안 걸립니다. 플렉스·그리드 자식의 기본 최소 너비가 '내용만큼'이라, 글이 길면 칸을 밀어내고 뒤쪽의 값과 꺾쇠를 화면 밖으로 쫓아냅니다. 리스트에서 가장 자주 나는 레이아웃 사고입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 건이 많고 같은 모양으로 반복될 때
  • 세로로 훑으며 찾거나 비교할 때
  • 좁은 화면 — 카드보다 한 화면에 훨씬 많이 들어갑니다
  • 설정처럼 이름과 값의 짝이 늘어설 때

이럴 때는 안 쓴다

  • 사진이 고르는 데 결정적일 때 → 카드가 낫습니다
  • 열을 정렬하거나 여러 값을 비교해야 할 때 → 데이터 테이블
  • 줄마다 보여 줄 것이 너무 많을 때 — 세 자리에 다 안 들어가면 줄이 아니라 카드입니다

대신 이걸 — 사진이 중요하면 카드, 열로 다루면 데이터 테이블(10부), 눌러서 사라지는 선택지면 메뉴(6부).

8 최소 마크업과 키보드이 부품의 계약서

      </span>
      <span class="li__end">₩1,245,480</span>

  </li>
</ul>

.li__main { flex: 1; min-width: 0; }
.li__t { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }

9 서버 쪽으로 치면백엔드 감각으로 번역

줄 하나 = 레코드 하나목록 API 의 한 행이 줄 하나입니다. 줄에 보이는 값은 그 행 안에 다 있어야 합니다 — 줄마다 이름을 따로 조회하면 N+1 입니다.
높이가 일정해야 하는 이유줄 높이가 같으면 가상 스크롤을 쓸 수 있어 수만 줄도 그립니다. 높이가 제각각이면 매 줄을 재야 해서 스크롤이 튑니다.
커서 페이징무한 스크롤로 이어 붙일 때 offset을 쓰면 새 글이 끼어들며 같은 줄이 두 번 나옵니다. 마지막 줄의 커서를 넘기는 쪽이 안전합니다.
빈 목록0건일 때 빈 줄 하나를 돌려주지 말고 빈 배열을 주고, 화면에서 빈 상태를 그립니다.
