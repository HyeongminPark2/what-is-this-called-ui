리스트 아이템

List item · row

리스트 아이템은 목록에서 한 줄에 한 건을 담는 부품입니다. 담는 내용은 카드와 같지만, 여러 건을 세로로 훑어 비교하기 좋도록 줄을 가지런히 맞춰 둔다는 점이 다릅니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

줄 수를 바꿔 보고, 긴 글을 자르지 말고 접기를 켜 보세요. 글이 모두 보이는 대신 줄마다 높이가 달라집니다. 목록에서는 보통 자르는 쪽을 고릅니다. 줄 높이가 일정해야 세로로 훑어 읽기 쉽고, 가상 스크롤도 높이가 일정할 때만 쓸 수 있기 때문입니다.

2 이름같은 것을 부르는 여러 이름

한국어리스트 아이템, 목록 항목, 줄, 행
영어list item, row, list row, cell(iOS)
같이 쓰는 말줄 앞쪽의 아이콘이나 아바타 자리는 리딩(leading), 뒤쪽의 값이나 꺾쇠 자리는 트레일링(trailing)이라고 부릅니다. 줄 사이를 나누는 선은 디바이더(divider · separator), 여러 줄을 묶는 머리글은 섹션 헤더라고 합니다. 글이 몇 줄 들어가느냐에 따라 한 줄·두 줄·세 줄(one/two/three-line) 리스트 아이템으로 나눠 부릅니다.
자주 잘못 부르는 이름카드 — 가로형 카드와는 생김새가 거의 같아서, 둘을 가르는 기준은 생김새가 아니라 여러 건이 어떻게 모이느냐입니다.
테이블 행 — 표의 행은 열이 정해져 있고 정렬과 선택 기능이 따라옵니다. 반면 리스트 아이템에는 내용을 자유롭게 넣는 세 자리만 있습니다.
메뉴 아이템 — 메뉴는 하나를 누르면 메뉴째 닫히는 선택지 모음입니다. 리스트는 선택지가 아니라 화면에 보여 줄 내용 자체입니다.

3 가르는 기준형제 부품과 견주는 네 가지 기준

표시 부품은 모두 보여 주기만 합니다. 아래 네 가지로 서로 가릅니다.

무엇을 담는가부품 전체를 누를 수 있는가여러 개가 어떻게 모이는가내용이 길어지면 어떻게 하는가
카드한 덩어리보통 눌림그리드로 늘어섬높이가 늘어남
리스트 아이템한 건보통 눌림세로 목록으로 쌓임말줄임함
아바타사람·조직 하나눌리지 않음겹쳐 쌓음크기는 고정하고 넘치면 +N으로 줄임
배지숫자나 한 낱말눌리지 않음혼자 놓이지 않고 다른 요소에 붙음크기는 고정하고 넘치면 99+로 줄임
칩한 낱말눌림가로로 늘어서다 줄을 바꿈말줄임하거나 줄을 넘김
스탯 타일숫자 하나가끔 눌림가로 한 줄로 늘어섬단위를 줄인다(1.2만)
타임라인사건들의 순서항목만 눌림세로 선으로 이음아래로 길어짐
별점점수 하나읽기용은 눌리지 않음줄 안에 들어감별 다섯 개로 고정됨
아이콘뜻 하나혼자서는 눌리지 않음글자 옆에 붙음아이콘은 그대로 두고 옆 글자가 길어짐
썸네일그림 하나보통 눌림격자로 늘어섬칸은 고정하고 사진을 자르거나 여백을 남김
테이블 행한 건의 여러 값행 전체나 주 열만 눌림세로로 쌓임말줄임함
키-값 목록이름과 값의 짝눌리지 않음세로로 쌓임값이 먼저 잘림
미디어 오브젝트그림과 글보통 눌림세로 목록으로 쌓임글 쪽만 늘어남
접히는 글제목과 본문제목이 눌림세로로 쌓음접어 둠
태그한 낱말눌리지 않음가로로 늘어서다 줄을 바꿈말줄임하거나 +N으로 접음

리스트 아이템을 한 줄로 정리하면 — 리스트 아이템은 여러 건을 세로로 비교하기 쉽도록 줄을 맞춘 것입니다. 그래서 줄 높이가 제각각이면 세로로 훑어 비교하기 어려워져 리스트를 쓰는 의미가 줄어듭니다.

5 해부도부분마다 붙은 이름

줄 하나 전체가 하나의 누를 것임
길동 앞자리는 폭이 고정됨
가운데는 이 자리만 늘어남
이번 주
  1. 목록 list줄들을 감싸는 상자입니다. <ul>로 만들어야 스크린 리더가 모두 몇 건인지 읽어 줍니다
  2. 줄 list item · row한 건 전체를 하나의 누를 것으로 만듭니다. 제목만 링크로 두지 않습니다
  3. 앞자리 leading아바타, 아이콘, 체크박스가 들어갑니다. 폭을 고정해야 줄끼리 세로로 가지런히 맞습니다
  4. 가운데 primary · secondary text제목과 보조 글이 들어갑니다. 세 자리 가운데 여기만 늘어납니다(flex:1; min-width:0)
  5. 구분선 divider줄 사이를 나누는 선입니다. 아바타가 있으면 보통 앞자리 폭만큼 들여서 긋습니다
  6. 섹션 헤더 section header'이번 주'처럼 여러 줄을 묶는 머리글입니다. 스크롤해도 화면 위쪽에 붙어 있게 만들기도 합니다

가운데 자리에 min-width: 0을 주지 않으면 말줄임이 끝내 적용되지 않습니다. 플렉스나 그리드 자식의 기본 최소 너비가 '내용 길이만큼'이라서, 글이 길면 가운데 칸이 계속 넓어지면서 뒤쪽의 값과 꺾쇠를 화면 밖으로 밀어내기 때문입니다. 리스트에서 특히 자주 생기는 레이아웃 오류입니다.

6 쓸 때 / 안 쓸 때

리스트 아이템을 쓰는 경우

  • 건이 많고 같은 모양으로 반복될 때
  • 세로로 훑으며 찾거나 비교할 때
  • 화면이 좁을 때. 카드보다 한 화면에 훨씬 많은 건이 들어갑니다
  • 설정처럼 이름과 값의 짝이 늘어설 때

리스트 아이템을 쓰지 않는 경우

  • 사진을 보고 골라야 할 때. 카드가 더 낫습니다
  • 열을 기준으로 정렬하거나 여러 값을 비교해야 할 때. 데이터 테이블을 씁니다
  • 줄마다 보여 줄 것이 너무 많을 때. 세 자리에 다 들어가지 않으면 리스트 아이템이 아니라 카드로 만듭니다

리스트 아이템 대신 다른 것을 써야 하는 경우 — 사진을 보고 골라야 하면 카드를 쓰고, 열을 기준으로 정렬하거나 비교해야 하면 데이터 테이블(10부)을 씁니다. 누르면 닫히는 선택지 모음이라면 메뉴(6부)가 맞습니다.

7 자주 보는 모습구조만 따라 그린 재현 그림

8 최소 마크업과 키보드구현할 때 지킬 최소 규칙

목록은 <ul>과 <li>로 만듭니다. 그래야 스크린 리더가 '목록, 항목 3개 중 1번'처럼 몇 번째 건인지 읽어 줍니다.

<ul class="list">
  <li>
    <a href="/settle/4821" class="li">
      <span class="av" aria-hidden="true">길동</span>
      <span class="li__main">
        <span class="li__t">정산 요청 #4821</span>
        <span class="li__s">11월 1일 ~ 11월 7일</span>
      </span>
      <span class="li__end">₩1,245,480</span>
    </a>
  </li>
</ul>

/* min-width: 0 이 없으면 말줄임이 적용되지 않는다 */
.li__main { flex: 1; min-width: 0; }
.li__t { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
키와 마크업그때 일어나야 하는 일
Tab포커스가 줄마다 한 번 멈춥니다. 줄 안에 누를 것이 둘이면 두 번 멈춥니다
Enter포커스가 있는 줄을 엽니다
<ul>로 감쌌을 때스크린 리더가 '목록, 항목 12개'라고 읽어 줍니다. <div>만 쌓으면 몇 건인지 알 수 없습니다
앞자리에 아바타가 있을 때aria-hidden="true"을 붙입니다. 바로 옆에 이름이 또 있어서 아바타까지 읽으면 이름을 두 번 듣게 됩니다
뒤에 스위치가 있을 때줄 전체를 누르는 동작과 겹치지 않게 합니다. 보통 줄은 눌리지 않게 두고 스위치만 누르게 합니다

9 서버 쪽으로 치면백엔드 개념과 짝지어 보기

줄 하나는 레코드 하나목록 API가 돌려주는 한 행이 줄 하나가 됩니다. 줄에 보이는 값은 그 행 안에 모두 들어 있어야 하는데, 줄마다 이름을 따로 조회하면 N+1 문제(목록 1번에 줄 수만큼 추가 조회)가 생기기 때문입니다.
높이가 일정해야 하는 이유줄 높이가 같으면 화면에 보이는 줄만 그리는 가상 스크롤을 쓸 수 있어서 수만 줄도 그릴 수 있습니다. 반면 높이가 제각각이면 줄마다 높이를 재야 해서 스크롤 위치가 갑자기 건너뜁니다.
무한 스크롤에는 커서 페이징무한 스크롤로 목록을 이어 붙일 때 offset을 쓰면, 그사이 새 글이 앞에 끼어들어 같은 줄이 두 번 나옵니다. 그래서 마지막 줄의 커서를 넘겨 다음 묶음을 받는 쪽이 안전합니다.
결과가 없을 때 돌려줄 값결과가 0건이면 빈 줄 하나를 돌려주지 말고 빈 배열을 돌려준 뒤, 화면에서 빈 상태를 그립니다.
