이징 곡선

Easing

속도를 어떻게 나눠 쓸지를 정하는 곡선. 거리도 시간도 같은데 느낌만 달라집니다.

1 실물 — 직접 만져 보기

새 탭에서 열기 ↗

네 공이 같은 거리를 같은 시간에 달립니다. 다른 것은 속도를 나눠 쓰는 방식뿐인데 느낌은 완전히 다릅니다.
줄 이름을 누르면 오른쪽에 그 곡선이 그려집니다 — 가로가 시간, 세로가 간 거리입니다. 대각선이 linear고, 거기서 멀어질수록 '밀고 당기는' 느낌이 생깁니다.

2 이름부르는 말이 여러 개다

한국어이징, 가속 곡선, 완급
영어easing, timing function, easing curve
같이 쓰는 말CSS 에서는 transition-timing-function·animation-timing-function입니다. 곡선을 네 숫자로 적는 것이 큐빅 베지에(cubic-bezier), 뚝뚝 끊어 가는 것이 스텝(steps)입니다. 디자인 도구에서는 이즈 인/아웃이라 부르고 그래프로 보여 줍니다.
자주 잘못 부름지속 시간 — 지속 시간은 '얼마나', 이징은 '어떻게'입니다. 둘은 따로 정합니다.
딜레이 — 시작을 늦추는 것은 차례로 들어오기에서 씁니다.
스프링 — 스프링은 곡선이 아니라 물리 계산이라 끝나는 때가 정해져 있지 않습니다.

3 가르는 기준형제들과 비교하는 네 축

움직임은 장식이 아니라 말입니다. 이 네 가지만 물어보면 갈립니다.

무엇을 정하나사람이 읽는 뜻과하면모션 줄이기에서
이징 곡선속도를 나눠 쓰는 방식무게와 재질끈적해 보인다그대로 둔다
지속 시간얼마나 걸리나거리와 크기기다리게 된다짧게 하거나 0
진입과 퇴장들고 나는 방식어디서 왔나닫는 데 붙잡힌다퇴장은 거의 0
무엇을 움직이나어떤 속성을 바꾸나매끄러움 그 자체버벅인다해당 없음
스프링지나쳤다 돌아오는 정도손으로 민 느낌어지럽다튕김을 0으로
차례로 들어오기줄 사이 지연순서와 묶음마지막이 늦는다한꺼번에 띄운다
제스처손가락을 따라가는 규칙내가 조작한다실수로 닫힌다그대로 둔다
모션 줄이기무엇을 끄나배려받고 있다다 꺼서 변화를 못 읽는다이게 그 기준이다

한 줄로 — 들어오는 것은 ease-out, 나가는 것은 ease-in. 이 한 줄만 지켜도 대부분의 화면이 자연스러워집니다.

4 곡선 여섯대각선에서 얼마나 벗어났나

5 해부도부분 이름이 제일 안 알려진 지식

가로 = 시간 0 → 1
세로 = 간 거리 0 → 1
가파른 곳 = 빠른 구간
cubic-bezier(.22, .9, .3, 1)
대각선 = linear — 기계가 미는 움직임
  1. 곡선 timing function가로가 시간, 세로가 간 거리. 이 한 줄만 알면 그래프가 읽힌다
  2. 가로축 0 → 1움직임이 시작해서 끝날 때까지. 길이와는 상관없다
  3. 세로축 0 → 1출발점에서 도착점까지. 1을 넘으면 지나쳤다 돌아온다
  4. 가파른 구간 빠른 구간곡선이 가파른 곳에서 빨리 움직인다
  5. 네 숫자 cubic-bezier손잡이 두 개의 좌표. 첫 둘이 출발, 뒤 둘이 도착 쪽이다
  6. 대각선 linear속도가 안 변한다. 물체가 아니라 기계처럼 보인다

현실의 물체는 갑자기 멈추지 않습니다. 그래서 linear가 어색합니다 — 속도가 끝에서 뚝 끊기는 움직임은 물체가 아니라 기계의 움직임으로 읽힙니다. 반대로 끝없이 도는 것(스피너)과 진행 막대는 linear가 맞습니다. 속도가 바뀌면 '뭔가 되고 있다'가 아니라 '막혔다 풀렸다'로 읽히기 때문입니다.

6 쓸 때 / 안 쓸 때

이럴 때 쓴다

  • 자리·크기·투명도가 바뀌는 모든 것 — 기본값을 한 번 정해 둔다
  • 들어오는 것에 ease-out, 나가는 것에 ease-in
  • 제자리로 돌아오는 것에 ease-in-out

이럴 때는 안 쓴다

  • linear를 기본으로 두는 것 — 도는 것과 진행 막대에만
  • 항목마다 다른 곡선 — 토큰으로 두셋만 정해 둔다
  • 튀는 곡선을 본문·목록에 — 읽으려는데 또 움직인다
  • 들어오는 데 ease-in — 굼떠 보인다. 가장 흔한 실수다

대신 이걸 — 끝을 안 정하고 손맛을 내려면 스프링, 얼마나 걸릴지는 지속 시간, 들고 나는 짝은 진입과 퇴장.

7 자주 보는 모습구조만 흉내 낸 재현 그림

8 최소 코드와 규칙이 곡선의 계약서

곡선을 이름 붙인 토큰으로 두고, 들고 나는 쪽에 짝지어 씁니다.

:root {
  --ease-out: cubic-bezier(.22, .9, .3, 1);   /* 들어올 때 */
  --ease-in:  cubic-bezier(.7, 0, .84, 0);    /* 나갈 때 */
  --ease-both: cubic-bezier(.4, 0, .2, 1);    /* 제자리로 */
}

.sheet            { transition: transform 180ms var(--ease-in); }
.sheet[data-open] { transition: transform 260ms var(--ease-out); }

/* 도는 것만 linear */
.spinner { animation: spin 1s linear infinite; }
키일어나야 하는 일
기본값은 easetransition: transform 200ms라고만 쓰면 ease가 붙는다
cubic-bezier의 네 숫자x1 y1 x2 y2. x 는 0~1 을 벗어날 수 없고, y 는 벗어나도 된다 — 그게 '지나침'이다
steps(n)뚝뚝 끊어 간다. 스프라이트 애니메이션·숫자 카운터에
곡선은 속성마다 따로transition: transform 260ms var(--ease-out), opacity 180ms linear
linear는 도는 것에만스피너·진행 막대. 그 밖에는 거의 늘 틀린 선택이다
모션 줄이기에서곡선은 그대로 둬도 된다. 줄여야 하는 것은 거리와 길이다

9 서버 쪽으로 치면백엔드 감각으로 번역

서버는 곡선을 모른다이징은 전부 화면 쪽 일입니다. 다만 움직임이 끝나기를 기다렸다 요청을 보내면 응답이 그만큼 늦습니다 — 요청은 먼저 보냅니다.
응답이 먼저 와도데이터가 50ms 에 와도 애니메이션이 400ms 면 사용자는 400ms 를 기다립니다. 느린 건 서버가 아닐 수 있습니다.
측정에 섞인다'화면이 뜨기까지'를 재는 지표(LCP 등)에 애니메이션 시간이 들어갑니다. 늦게 나타나는 연출은 점수를 깎습니다.
