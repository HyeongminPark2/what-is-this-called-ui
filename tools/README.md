## 무엇을 보나

기능(모달이 열리나 닫히나)뿐 아니라 **레이아웃이 무너졌는지**를 본다. 기능 검사만
돌리면 해부도가 세로로 한 글자씩 쌓여 칸 높이가 10,000px가 돼도 통과한다.

- 글이 세로로 쌓였는지 (폭 46px 미만인데 높이 170px 초과)
- 그림이 칸 밖으로 잘렸는지
- 390px에서 가로로 넘치는지
- 페이지 전체 높이가 터무니없이 긴지
- 폭 토글이 실제로 390 / 768을 만드는지
- 좁은 폭에서 모달이 바텀시트가 되는지
- 포커스가 **배경의 누를 수 있는 것에 닿지 않는지**, 배경이 정말 비활성인지,
  닫은 뒤 포커스가 부른 버튼으로 돌아오는지

항목 카드는 **백열네 장 전부** 같은 틀인지 본다 — 칸이 10개인가, 해부도 번호가
목록과 1대1로 맞고 1부터 이어지는가, 빈 태그(`<hr>` 등)에 번호를 붙여 안 그려지는
곳은 없는가, 형제 링크가 같은 부에서 자기만 뺀 것인가, 해부도 번호가 잘리거나 서로 겹치거나
찌그러지지 않았는가.

**번호가 '한 칸 밀려' 있지 않은가**도 본다. 번호끼리 겹치면 자동으로 비키는데, 예전에는
아래로 비켰다. 그러면 겹치지도 잘리지도 않은 채 **옆 줄을 가리키는** 번호가 생긴다 —
눈으로도 검사로도 안 잡히던 사고다. 지금은 `card.js`가 **같은 줄에 두고 바깥으로만** 밀고,
검사는 번호의 세로 중심이 자기 부품 상자 안에 있는지를 본다(이 검사를 넣자마자 6부
네 장에서 여덟 개가 걸렸다). 해부도를 한 겹의 세로 줄로 그리고 **번호를 중첩해 넣지 않는 것**이
애초에 이 문제를 막는 방법이다.

데모 백열네 장도 실제로 눌러 본다 — 토스트가 쌓이고 되돌려지고 저절로 사라지는가,
시트가 아래에 붙는가, 드로어가 높이를 다 쓰는가, 팝오버가 가장자리에서 뒤집히는가,
툴팁이 지연 뒤에 뜨고 마우스를 안 받는가, `show()`와 `showModal()`이 정말 다른가.

2부 토큰 데모는 **보여주려는 실패가 아직 실패하는지**도 본다 — 색을 박아 둔 카드가
어두운 모드를 안 따라오는가, 비율을 끄면 단 사이 비가 정말 들쭉날쭉해지는가,
9999를 쓰면 모달이 가림막에 덮이는가. 이 쪽이 고쳐지면 데모가 설명을 잃는다.

10부 데모도 같은 방식이다 — 디바운스를 끄면 글자마다 요청이 나가는가, 일부만 고른
머리글 체크박스가 중간 상태가 되는가, 가상 스크롤을 끄면 천 개가 정말 다 만들어지는가,
제출했을 때 첫 틀린 칸으로 포커스가 가는가, 질문을 바꾸면 맞는 차트도 바뀌는가.

9부 데모는 **움직임 자체**를 잰다 — 같은 시간에 달리는 네 곡선이 정말 같은 시간인가,
`left`로 움직이는 쪽이 `transform`보다 실제로 프레임 시간을 더 쓰는가(한 프레임을 만들고
재서 숫자로 비교한다), 시차 간격을 키우면 마지막 줄이 3초를 넘는가, 모션 줄이기를 켜면
큰 이동은 멎고 **투명도 바뀜은 남는가**. 마지막 것은 '전부 끄기'로 때운 코드를 잡는 검사다.

11부 데모는 **PC에서는 안 보이는 사고**를 흉내 내서 잰다 — 기기 폭으로 끊으면 390px에서
가게 이름이 정말 두 줄로 접히는가(접힌 칸을 센다), 보이는 24px과 눌리는 44px이 따로 노는가,
모달을 기록에 안 넣으면 뒤로가 엉뚱한 화면을 지우는가, 키보드가 올라오면 바닥 버튼이
덮이는가. 전부 실제 폰이 없어도 걸리게 만든 검사다.

13부 데모는 **화면이 아니라 흐름**을 잰다 — 오류 문구를 자세히 말하면 계정이 있는지
새어 나가는가, 단계를 넷에서 여섯으로 늘리면 끝내는 사람이 절반 아래로 떨어지는가,
결과에서 들어갔다 돌아오면 질의와 굴린 자리가 살아나는가, 결제를 두 번 눌렀을 때
주문이 둘 생기는가, 권한 앞선 설명에서 '나중에'를 고르면 OS 창이 아껴지는가.

14부 데모는 **문구를 규칙으로 매긴다** — 동사가 있나, 두세 어절인가, '확인·제출' 같은 빈 말인가.
사람이 읽고 판단하는 대신 규칙을 돌리니 검사도 같은 눈으로 본다. 받침을 보고 조사를 고르는
것도 마찬가지다 — '모란상회'는 '를', '대림유통'은 '을', 'Starbucks'는 **모른다고 답해야** 통과다.

15부 데모는 **시안 도구의 동작을 흉내 내서** 잰다 — 토큰 하나를 바꾸면 부품이 따라오는가,
떼어낸(디태치) 하나만 옛 모습에 굳는가, 축을 하나 더하면 칸이 18에서 54가 되는가,
오토 레이아웃 조작기와 그 아래 CSS 가 같이 움직이는가. 마지막 것은 두 말이 같은 것임을
보이려고 만든 데모라, **상자의 computed style 과 적힌 CSS 를 둘 다** 확인한다.

포커스 갇힘은 iframe 밖에서만 검사할 수 있어서 `demos/modal.html`을 직접 연다.

**단정문이 전부 통과해도 스크린샷을 눈으로 본다.**
