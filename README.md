# 이름표 (what-is-this-called-ui)

화면 속 그게 뭔지 알려주는 프론트엔드 UI/UX 도감.

백엔드를 하던 사람이 프론트엔드 화면을 볼 때 막히는 건 개념이 아니라 **이름**이다.
이름을 모르면 디자이너와 말이 안 통하고 검색도 못 한다.
그래서 이 도감은 이름순 색인을 맨 뒤로 밀고, 입구에 **화면 지도**를 뒀다.
보이는 자리를 눌러 들어가면 그게 뭐라고 불리는지 나온다.

👉 **<https://hyeongminpark2.github.io/what-is-this-called-ui/>**

## 항목 하나는 열 칸으로 쓴다

틀이 똑같아야 100번째 항목에서도 어디를 볼지 안다.

| 칸 | 내용 |

| ③ 가르는 기준 | 형제 부품들과 비교하는 축 |
| ④ 상태 | 기본 · 진입 · 열림 · 처리 중 · 에러 · 닫힌 뒤를 나란히 |
| ⑤ 해부도 | 부분마다 번호와 이름 |

## 화면 지도

이름을 적은 빈 상자를 늘어놓으면 이름은 알려 주지만 **그게 어떻게 생겼는지**는
못 알려 준다. 그래서 진짜 앱처럼 내용을 채운 화면(결제 관리자 PC 화면과 폰 화면)을
그리고, 이름표는 바깥에 두고 지시선으로 각 부분을 가리킨다.

- **선을 늘 그어 두지 않는다.** 이름표 열다섯 개에서 선이 뻗으면 그림이 어지러워진다.
  기본은 조용한 번호 배지와 아래 목록이고, 짚은 것 하나만 지시선을 긋는다.
- **어느 쪽을 짚어도 된다.** 목록의 이름에 올리면 화면에서 그 부분이 밝아지고,
  화면의 부품에 올리면 목록에서 이름이 밝아진다. 겹쳐 있으면 안쪽 것이 이긴다.
- 지시선 좌표는 JS가 매번 계산한다. 손으로 박으면 폭이 바뀔 때마다 어긋난다.
- 번호 배지는 가리키는 것을 덮으면 안 된다. 낮은 부품은 왼쪽 바깥으로, 오른쪽 끝에
  붙은 작은 부품은 오른쪽 바깥으로 뺀다. 검사가 덮는 넓이를 재서 막는다.
- 좁은 화면에서는 지시선을 접고 번호로만 잇는다. PC 화면은 옆으로 밀어 본다.

## 지금 상태

- 0부 찾아가는 길 — 화면 지도 2장 (PC 관리 도구, 폰)
- 6부 겹치는 것들 — **모달** 1항목 완성 (열 칸 견본)
- 나머지 14부는 목차만

전체 계획은 약 185항목, 15부.

## 구조

```
index.html          입구 — 화면 지도 · 혼동 쌍 · 목차
tools/check.js      브라우저 검사 (tools/README.md 참고)
items/modal.html    항목 카드
demos/modal.html    ①칸 iframe에 들어가는 실물 예시
assets/base.css     디자인 토큰과 도감 껍데기
assets/card.css     항목 카드 열 칸 틀
assets/demo.css     예시 안에서 쓰는 UI 부품
assets/map.css      가짜 앱 화면과 이름표
assets/map.js       지시선 긋기
assets/card.js      폭 토글
```

빌드 도구가 없다. `index.html`을 그냥 열면 된다.

## 원칙

- **상태를 안 보여주면 그림은 반쪽이다.** 버튼 그림 한 장으로는 버튼을 못 배운다.
- **종이가 아니라 돌아가는 HTML로.** 호버도 포커스도 애니메이션도 캡처로는 안 전해진다.
- **PC와 폰을 같은 항목 안에서.** 폭 토글로 같은 부품이 어떻게 모습을 바꾸는지 직접 끌어 본다.
- **남의 화면 캡처를 쓰지 않는다.** 모든 그림은 색과 로고를 뺀 재현이다. 설명 목적에는 오히려 군더더기가 없다.
